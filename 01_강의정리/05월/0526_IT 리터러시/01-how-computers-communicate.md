# 컴퓨터와 소통하는 법 — 0과 1에서 운영체제까지

> 컴퓨터는 우리말도 영어도 모릅니다. 오직 "켜짐(1)"과 "꺼짐(0)" 두 글자만 압니다. 그런데 어떻게 우리는 한국어로 명령하고, 컴퓨터는 그걸 알아들을까요?

`기계어` · `프로그래밍언어` · `컴파일러` · `인터프리터` · `고급언어` · `저급언어` · `운영체제`

## 핵심요약

- 컴퓨터가 직접 이해하는 언어는 0과 1로만 이루어진 **기계어**다.
- 사람이 0과 1로 일일이 명령하긴 어려워서, 사람이 읽기 쉬운 **프로그래밍 언어**를 만들었다.
- 우리가 쓴 코드는 **번역(컴파일러/인터프리터)** 과정을 거쳐 기계어로 바뀐 뒤 실행된다.
- 기계에 가까운 언어를 **저급 언어(Low level)**, 사람에 가까운 언어를 **고급 언어(High level)** 라고 부른다. "저급/고급"은 좋고 나쁨이 아니라 **기계와의 거리**를 뜻한다.
- 화면을 보여주는 쪽을 **클라이언트(프론트엔드)**, 뒤에서 처리하는 쪽을 **서버(백엔드)** 라고 한다.
- 복잡한 하드웨어를 사람이 쉽게 다루도록 도와주는 시스템 소프트웨어가 **운영체제(OS)** 다.

## 개념별 정리

### 기계어 (0과 1)

**1. 정의**
컴퓨터가 직접 알아듣는 유일한 언어로, 0과 1의 조합으로만 이루어져 있습니다. 전기가 흐르면 1, 안 흐르면 0이라고 생각하면 됩니다.

**2. 왜 필요한가?**
TV·컴퓨터·에어컨의 전원 On/Off가 결국 1/0이듯, 모든 디지털 기기는 내부적으로 0과 1로만 동작합니다. 이 사실을 알아야 "코드가 결국 어떻게 실행되는가"를 이해할 수 있습니다.

**3. 예시**
같은 명령도 기계어로 보면 이렇게 0과 1의 나열입니다.

```text
0000 1001 1100 0110 1010 1111 0101 1000
1010 1001 1100 0110 1010 1111 0101 1000
1100 0110 1010 1111 0101 1000 0000 1001
```

**4. 헷갈리기 쉬운 점**
"기계어 = 어려운 외국어"가 아니라, **기계어는 컴퓨터의 모국어**입니다. 어려운 건 사람이 기계어로 직접 말하는 것이지, 컴퓨터에게는 가장 자연스러운 언어입니다.

**5. 한 줄 정리**
컴퓨터의 세계는 켜짐(1)과 꺼짐(0), 단 두 글자로 돌아간다.

> 비유: 모스 부호가 점·선 두 가지로 모든 문장을 표현하듯, 컴퓨터는 0·1 두 신호로 모든 작업을 표현합니다.

### 프로그래밍 언어와 번역(컴파일러·인터프리터)

**1. 정의**
사람이 읽고 쓰기 쉽게 만든 컴퓨터 명령용 언어가 **프로그래밍 언어**입니다. Python, Java, JavaScript, C, C++, Swift, Kotlin, Go, Rust 등 종류가 다양합니다. 사람이 쓴 이 코드를 기계어로 바꿔주는 번역기가 **컴파일러/인터프리터**입니다.

**2. 왜 필요한가?**
0과 1로 직접 프로그램을 짜는 건 사실상 불가능에 가깝습니다. 복잡한 기계어를 사람이 다루기 쉬운 형태로 감싸서, 더 많은 사람이 컴퓨터를 활용할 수 있게 하려고 만든 것입니다.

**3. 예시 — 코드가 실행되는 과정**

```text
[Code 작성]  →  [인터프리터/컴파일러]  →  [기계어 번역]  →  [컴퓨터 인식·실행]
   사람의 언어        번역기                   0과 1            동작
```

우리가 쓴 한 줄의 코드는 위 단계를 거쳐 결국 0과 1로 바뀐 뒤 컴퓨터에서 실행됩니다.

**4. 헷갈리기 쉬운 점**
"언어가 많은데 뭘 배워야 하지?"에서 막히기 쉽습니다. 언어마다 잘하는 분야가 다를 뿐(데이터 분석엔 Python, 웹엔 다양한 언어 등), 한 언어의 원리를 익히면 다른 언어로 옮겨가기는 훨씬 수월해집니다.

**5. 한 줄 정리**
프로그래밍 언어는 "사람의 말 ↔ 컴퓨터의 0과 1" 사이를 이어주는 번역 가능한 다리다.

> 비유: 통역사가 한국어를 영어로 옮기듯, 컴파일러/인터프리터는 사람의 코드를 기계어로 옮겨줍니다.

### 저급 언어 vs 고급 언어 (Low / High level)

**1. 정의**
기계(0과 1)에 더 가까운 언어를 **저급 언어(Low level)**, 사람의 말에 더 가까운 언어를 **고급 언어(High level)** 라고 합니다.

**2. 왜 필요한가?**
상황에 맞는 언어를 고르기 위해서입니다. 저급 언어일수록 기계를 직접 컨트롤할 수 있어 속도가 빠를 수 있지만, 작성이 어렵고 실수가 나기 쉽습니다.

**3. 예시**

| 구분 | 사람과의 거리 | 특징 |
| --- | --- | --- |
| 저급 언어(Low level) | 멀다(기계에 가깝다) | 속도 빠를 수 있음 · 작성 어려움 · 실수 위험 |
| 고급 언어(High level) | 가깝다(사람에 가깝다) | 작성 쉬움 · 생산성 높음 |

**4. 헷갈리기 쉬운 점**
"저급 = 나쁜 언어, 고급 = 좋은 언어"가 **아닙니다.** 여기서 급(level)은 품질이 아니라 **기계와 얼마나 가까운가(추상화 수준)** 를 뜻합니다.

**5. 한 줄 정리**
"저급/고급"은 우열이 아니라 기계와의 거리 차이일 뿐이다.

> 비유: 요리에 비유하면, 저급 언어는 불 세기를 직접 손으로 조절하는 가스레인지, 고급 언어는 버튼만 누르는 전기밥솥에 가깝습니다.

### 클라이언트와 서버 (프론트엔드와 백엔드)

**1. 정의**
사용자가 직접 보고 조작하는 쪽이 **클라이언트(Web에서는 프론트엔드)**, 요청을 받아 뒤에서 처리해 주는 쪽이 **서버(Web에서는 백엔드)** 입니다.

**2. 왜 필요한가?**
하나의 서비스는 "보여주는 일"과 "처리하는 일"로 나뉘어 협력합니다. 이 역할 분담을 알아야 어떤 기능이 어디서 동작하는지 감을 잡을 수 있습니다.

**3. 예시 — 배달앱과 서버**

```text
배달앱(클라이언트)  ── 배달음식 주문 ──▶  서버
배달앱(클라이언트)  ◀─ 주문완료/배달이동 ─  서버
```

내가 음식을 주문(요청)하면 서버가 받아 처리하고, 주문 완료와 배달 상황을 다시 보내줍니다(응답).

**4. 헷갈리기 쉬운 점**
"앱 화면 = 서비스 전부"가 아닙니다. 화면 뒤에는 항상 요청을 받아 처리하는 서버가 있습니다. 화면은 빙산의 일각이라고 생각하면 좋습니다.

**5. 한 줄 정리**
클라이언트는 보여주는 역할, 서버는 처리하는 역할로 나뉜 한 팀이다.

> 비유: 식당 홀의 직원(클라이언트)이 주문을 받아 주방(서버)에 전달하고, 주방이 만든 음식을 다시 손님에게 가져다줍니다.

### 운영체제 (OS)

**1. 정의**
복잡한 컴퓨팅 기계를 사람이 쉽게 다루도록 도와주는 **시스템 소프트웨어**입니다. Windows, MacOS, Linux, iOS, Android 등이 있습니다.

**2. 왜 필요한가?**
앱이 카메라·저장공간 같은 하드웨어를 쓰려면 권한과 통로가 필요합니다. 운영체제가 그 접근 권한과 코드를 제공해, 개발자가 매번 하드웨어를 바닥부터 다루지 않아도 되게 해줍니다.

**3. 예시 — 스마트폰에서 카메라를 쓰는 과정**

```text
스마트폰 공장 제작 → 운영체제 설치 → App 제작 → 사용자 활용
```

예를 들어 카메라로 길이를 재는 AR 앱은, "카메라 접근 권한"을 운영체제로부터 받아야 동작합니다. 운영체제가 카메라 접근 코드를 제공하고, 개발자는 그걸 활용해 앱을 만듭니다.

**4. 헷갈리기 쉬운 점**
운영체제와 앱을 같은 것으로 보기 쉽지만, **운영체제는 무대(바탕), 앱은 무대 위 공연**입니다. 같은 앱도 iOS와 Android에서 동작 방식이 다른 이유가 여기 있습니다.

**5. 한 줄 정리**
운영체제는 사람과 하드웨어 사이에서 통제권을 쉽게 넘겨주는 중간 관리자다.

> 비유: 운영체제는 건물의 관리사무소입니다. 입주민(앱)이 전기·수도(하드웨어)를 직접 끌어오지 않아도, 관리사무소가 알아서 연결해 줍니다.

## 코드로 보기 — 코드가 실행되기까지의 전체 흐름

이 글은 개념 중심이라, 코드 대신 "사람의 명령이 컴퓨터까지 닿는 과정"을 흐름도로 정리합니다.

```text
[1단계] 개발자가 프로그래밍 언어로 코드 작성
            예) print("Hello")
                │
[2단계] 컴파일러/인터프리터가 기계어로 번역
                │
[3단계] 0과 1로 이루어진 기계어
            예) 0100 1000 ...
                │
[4단계] 운영체제가 하드웨어에 전달
                │
[5단계] 컴퓨터가 실행 → 화면에 결과 표시
```

**무엇을 하기 위한 흐름인가**
"내가 쓴 코드 한 줄이 결국 어떻게 컴퓨터에서 돌아가는가"를 보여주기 위한 과정입니다.

**해석**
우리가 만지는 건 1단계(고급 언어)지만, 실제 실행은 3단계(0과 1)에서 일어납니다. 그 사이를 번역기(2단계)와 운영체제(4단계)가 메워줍니다.

**실무 연결**
- 같은 코드가 OS마다 다르게 동작할 수 있다는 걸 알면, "내 PC에선 되는데 왜 다른 데선 안 되지?" 류의 문제를 이해하기 쉬워집니다.
- 언어 선택(분석=Python 등)도 "기계와의 거리 vs 생산성"이라는 기준으로 판단할 수 있습니다.

## 헷갈리기 쉬운 포인트

- **저급 언어 vs 고급 언어**: 품질의 우열이 아니라 "기계에 가까움 vs 사람에 가까움"의 차이.
- **컴파일러 vs 인터프리터**: 둘 다 코드를 기계어로 번역하지만, 컴파일러는 대체로 미리 한꺼번에, 인터프리터는 실행하면서 한 줄씩 번역하는 방식으로 동작합니다.
- **클라이언트 vs 서버**: 보여주는 쪽 vs 처리하는 쪽. 한 서비스 안에서 역할이 다를 뿐 둘 다 필요합니다.
- **운영체제 vs 앱**: 바탕(무대) vs 그 위에서 도는 프로그램(공연).

**복습 질문 및 답변**

- (기본) 컴퓨터가 직접 이해하는 언어는?
  → 0과 1로 이루어진 기계어.
- (이해확인) 고급 언어가 저급 언어보다 "생산성"이 높은 이유는?
  → 사람의 말에 가까워 작성이 쉽고 실수가 줄기 때문. 다만 기계 제어의 직접성과 속도는 저급 언어가 유리할 수 있음.
- (응용) 같은 앱이 iOS와 Android에서 다르게 동작할 수 있는 이유를 운영체제 개념으로 설명한다면?
  → 앱은 운영체제가 제공하는 권한·코드 위에서 동작하는데, OS마다 그 제공 방식이 달라 동작도 달라질 수 있기 때문.

## 한 줄 정리

> 컴퓨터는 0과 1만 알지만, 프로그래밍 언어·번역기·운영체제가 그 사이를 메워주기에 우리는 사람의 말로 컴퓨터를 부릴 수 있다.
