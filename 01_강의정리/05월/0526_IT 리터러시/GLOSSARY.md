# GLOSSARY — IT 리터러시 용어집

이 강의에서 등장한 핵심 용어를 비전공자 눈높이로 정리했습니다. "관련 글"의 링크를 따라가면 더 자세한 설명을 볼 수 있습니다.

| 용어 | 쉬운 설명 | 관련 글 | 함께 보면 좋은 개념 |
| --- | --- | --- | --- |
| 기계어 | 컴퓨터가 직접 알아듣는 0과 1로만 된 언어 | 컴퓨터와 소통하는 법 | 이진수, 프로그래밍 언어 |
| 프로그래밍 언어 | 사람이 읽기 쉽게 만든 컴퓨터 명령용 언어 | 컴퓨터와 소통하는 법 | 컴파일러, 인터프리터 |
| 컴파일러 / 인터프리터 | 사람의 코드를 기계어로 바꿔주는 번역기 | 컴퓨터와 소통하는 법 | 기계어, 실행 |
| 저급 언어(Low level) | 기계(0·1)에 더 가까운 언어. "급"은 우열이 아님 | 컴퓨터와 소통하는 법 | 고급 언어, 추상화 |
| 고급 언어(High level) | 사람의 말에 더 가까워 작성이 쉬운 언어 | 컴퓨터와 소통하는 법 | 저급 언어, 생산성 |
| 클라이언트 | 사용자가 보고 조작하는 쪽(웹=프론트엔드) | 컴퓨터와 소통하는 법 | 서버, 프론트엔드 |
| 서버 | 요청을 받아 뒤에서 처리하는 쪽(웹=백엔드) | 컴퓨터와 소통하는 법 | 클라이언트, 백엔드 |
| 운영체제(OS) | 복잡한 하드웨어를 쉽게 다루게 돕는 시스템 소프트웨어 | 컴퓨터와 소통하는 법 | 하드웨어, 권한 |
| 통신(Communication) | 기기끼리 약속대로 정보를 주고받는 대화 | 웹·앱 서비스의 구조와 통신 | 요청/응답, HTTP |
| 요청(Request) / 응답(Response) | 보내는 쪽과 돌려주는 쪽. 1요청 1응답이 기본 | 웹·앱 서비스의 구조와 통신 | 통신, HTTP 메서드 |
| HTTP | 연결된 문자를 약속대로 주고받는 웹 통신 규칙 | 웹·앱 서비스의 구조와 통신 | 프로토콜, HTTPS |
| 프로토콜(Protocol) | 통신에서 미리 정한 규칙·약속 | 웹·앱 서비스의 구조와 통신 | HTTP |
| HyperText | 서로 연결된 문자(웹 문서의 바탕 개념) | 웹·앱 서비스의 구조와 통신 | HTTP, JSON/XML |
| JSON | 데이터를 약속된 형태로 담는 가벼운 그릇 | 웹·앱 서비스의 구조와 통신 | XML, 파싱 |
| XML | 태그 형태로 데이터를 담는 그릇 | 웹·앱 서비스의 구조와 통신 | JSON, 파싱 |
| 파싱(Parsing) | 받은 데이터를 풀어 필요한 부분을 꺼내는 일 | 웹·앱 서비스의 구조와 통신 | JSON, XML |
| WAS | 클라이언트→웹서버→백엔드→DB로 이어지는 처리 구조 | 웹·앱 서비스의 구조와 통신 | 서버, 데이터베이스 |
| Endpoint | 요청이 도착하는 정해진 주소 | 웹·앱 서비스의 구조와 통신 | URI, REST API |
| 동기(Synchronous) | 결과가 올 때까지 기다리며 함께 움직임 | 웹·앱 서비스의 구조와 통신 | 비동기 |
| 비동기(Asynchronous) | 결과와 상관없이 다른 일을 동시에 진행 | 웹·앱 서비스의 구조와 통신 | 동기, 콜백 |
| 프론트엔드 | 사용자가 만나는 화면과 통신 입구 | 프론트엔드·백엔드와 REST API | UI/UX, 클라이언트 |
| 백엔드 | 서버 측에서 비즈니스 로직을 처리하는 쪽 | 프론트엔드·백엔드와 REST API | 서버, 데이터베이스 |
| 비즈니스 로직 | 데이터를 생성·표시·저장·변경하는 처리 규칙 | 프론트엔드·백엔드와 REST API | 백엔드 |
| UI(User Interface) | 사용자가 보는 화면, 디자인 요소 | 프론트엔드·백엔드와 REST API | UX, GUI |
| UX(User Experience) | 서비스를 쓰는 전체 경험과 흐름 | 프론트엔드·백엔드와 REST API | UI |
| GUI | 그래픽 기반 화면. 흔히 UI와 같은 뜻으로 통용 | 프론트엔드·백엔드와 REST API | UI |
| 반응형 화면 | 다양한 크기의 화면을 하나로 커버하는 설계 | 프론트엔드·백엔드와 REST API | 그리드 시스템 |
| 그리드 시스템 | 화면을 일정 규칙으로 나눠 정렬하는 구조 | 프론트엔드·백엔드와 REST API | 반응형 |
| GET | 기존 정보·페이지를 읽어오는 메서드 | 프론트엔드·백엔드와 REST API | POST, CRUD |
| POST | 정보를 저장·전달하려고 서버에 보내는 메서드 | 프론트엔드·백엔드와 REST API | GET, CRUD |
| PUT / PATCH | 저장된 정보를 수정하는 메서드 | 프론트엔드·백엔드와 REST API | POST, CRUD |
| DELETE | 저장된 정보를 삭제하는 메서드 | 프론트엔드·백엔드와 REST API | 논리삭제, CRUD |
| CRUD | 생성·읽기·수정·삭제, 데이터의 네 가지 기본 동작 | 데이터베이스의 모든 것 | HTTP 메서드 |
| API | 프로그램끼리 대화하도록 돕는 기능 호출 | 프론트엔드·백엔드와 REST API | REST API, 라이브러리 |
| REST API | 약속된 주소(URI)에 기능을 매핑한 설계 방식 | 프론트엔드·백엔드와 REST API | API, URI |
| URI / URL | 자원 식별자(넓은 개념) / 흔히 쓰는 웹 주소 | 프론트엔드·백엔드와 REST API | Endpoint |
| Open API | 누구나 활용하도록 공개된 API | 프론트엔드·백엔드와 REST API | API |
| Analytics | 트래픽·방문자 등 사용자 행동을 측정·분석 | 프론트엔드·백엔드와 REST API | SEO, A/B 테스트 |
| SEO | 검색엔진이 내 페이지를 잘 찾게 최적화하는 것 | 프론트엔드·백엔드와 REST API | Analytics |
| 데이터베이스(DB) | 분류하기 좋게 저장한 데이터 창고 | 데이터베이스의 모든 것 | 테이블, 쿼리 |
| 테이블 | 데이터를 행·열로 정리해 저장한 표 | 데이터베이스의 모든 것 | 데이터 타입, 쿼리 |
| 데이터 타입 | 각 칸에 담길 값의 종류(숫자·문자·시간 등) | 데이터베이스의 모든 것 | 테이블 |
| Query(쿼리) | 데이터베이스에 내리는 명령어 | 데이터베이스의 모든 것 | 인덱싱, 성능 |
| 정렬 | 특정 값 기준으로 데이터 순서를 맞추는 것 | 데이터베이스의 모든 것 | 쿼리 |
| 논리삭제 | 실제로 지우지 않고 "삭제됨"으로 표시만 하는 방식 | 데이터베이스의 모든 것 | 물리삭제 |
| 트래픽 | 서버에 접속할 때 일어나는 통신량 | 데이터베이스의 모든 것 | 과부하, 성능 테스트 |
| DBMS | 데이터베이스를 운영·관리하는 소프트웨어 | 데이터베이스의 모든 것 | RDB, NoSQL |
| 관계형(RDB) | 키로 테이블을 연결해 관리하는 정형 DB | 데이터베이스의 모든 것 | Primary Key, NoSQL |
| NoSQL | 기록이 단순하고 대용량 처리에 유리한 비정형 DB | 데이터베이스의 모든 것 | RDB, Vector DB |
| Vector DB | LLM·검색(RAG)에 쓰이는 성장 단계의 DB | 데이터베이스의 모든 것 | NoSQL |
| Primary Key | 행을 구분하는 고유값. 테이블 연결에 사용 | 데이터베이스의 모든 것 | 관계형 |
| 웹(WWW) | 자료 공유를 위해 시작된, 연결된 문서들의 세계 | 라이브러리와 프레임워크 | HTML, HTTP |
| 라이브러리 | 자주 쓰는 코드를 모아 둔 도구 모음(=패키지) | 라이브러리와 프레임워크 | 프레임워크, API |
| 패키지 | 라이브러리를 부르는 또 다른 이름 | 라이브러리와 프레임워크 | 라이브러리 |
| 프레임워크 | 코드를 작성하기 위한 틀(구조)을 제시하는 도구 | 라이브러리와 프레임워크 | 라이브러리 |
| 버전 관리 | 도구의 버전 차이로 코드가 깨질 수 있어 확인하는 것 | 라이브러리와 프레임워크 | 의존성 |
