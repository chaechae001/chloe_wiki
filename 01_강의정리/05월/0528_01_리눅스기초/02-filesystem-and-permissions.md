# 파일 시스템과 권한 — 디렉토리·소유권·편집기

> 리눅스에는 "내 컴퓨터" 같은 C드라이브가 없다. 모든 것이 `/` 하나에서 가지를 뻗는 한 그루의 나무라면, 그 안에서 길을 찾는 법은?

`파일시스템` `디렉토리` `트리구조` `ls` `chmod` `소유권` `권한` `nano` `vi`

## 핵심요약

- 파일 시스템은 저장 장치에 데이터를 어떻게 저장·관리할지 정한 **약속(정책)** 이다.
- 리눅스의 모든 파일과 디렉토리는 최상위 루트(`/`) 아래 **계층적 트리 구조**로 놓인다.
- 디렉토리는 파일과 하위 디렉토리를 묶는 "이름 공간(폴더)"이고, 파일은 데이터의 집합이다.
- `pwd` `ls` `cd` `whoami` `mkdir` `touch` `cat` 같은 명령으로 위치를 파악하고 파일을 만든다.
- `ls -al`로 파일의 **속성**(유형·권한·소유자·크기·시간 등)을 한 줄에서 읽을 수 있다.
- 권한은 **소유자 / 그룹 / 그 외 사용자** 세 묶음으로, 읽기(4)·쓰기(2)·실행(1)의 합으로 표현하며 `chmod`로 바꾼다.
- 터미널 안에서 글을 편집할 때는 `nano`(쉬움)나 `vi`(강력) 같은 텍스트 편집기를 쓴다.

## 개념별 정리

### 파일 시스템과 디렉토리 트리

**1. 정의**
파일 시스템은 저장 장치 내에서 데이터를 읽고 쓰기 위해 미리 정한 **약속이자 관리 방법(정책)** 입니다. 리눅스 파일 시스템은 **디렉토리 + 파일** 형태로 구성되며, 최상위 루트(`/`)를 정점으로 모든 것이 아래로 뻗어 내려가는 **트리(tree) 구조**를 이룹니다.

**2. 왜 필요한가?**
수만 개의 파일을 한곳에 쏟아 두면 찾을 수 없습니다. 트리 구조는 "역할별로 방을 나눈 건물"처럼 파일을 분류해, 어디에 무엇이 있는지 경로(`/home/user/문서` 등)로 정확히 가리킬 수 있게 합니다.

**3. 예시**
```bash
# 현재 디렉토리에 무엇이 있는지 본다
ls
# bin   boot  dev   etc   home  lib   media  mnt  opt
# proc  root  run   sbin  srv   sys   tmp    usr  var ...

# 트리 구조로 한눈에 보기 (tree가 없으면 설치)
sudo apt install tree
tree
# .
# ├── 공개
# ├── 다운로드
# ├── 문서
# ├── 바탕화면
# └── ...
```
루트(`/`) 아래에 `bin`, `home`, `lib` 등이 있고, `home` 아래에 사용자 폴더, 그 안에 바탕화면·문서·다운로드가 가지처럼 이어집니다.

**4. 헷갈리기 쉬운 점**
윈도우의 `C:\`, `D:\`처럼 드라이브가 따로 있는 게 아니라, 리눅스는 **모든 것이 단 하나의 `/` 아래**에 통합됩니다. USB나 외장 디스크조차 트리의 한 폴더로 "연결(마운트)"되어 등장합니다.

**5. 한 줄 정리**
리눅스의 모든 파일은 루트(`/`)라는 한 뿌리에서 뻗은 나무의 잎이다.

> 비유: 루트(`/`)는 건물 1층 로비, 디렉토리는 층과 방, 파일은 방 안의 서류다. 경로는 "3층 302호" 같은 주소다.

### 기본 탐색·생성 명령어

**1. 정의**
터미널에서 위치를 확인하고 이동하며, 폴더와 파일을 만드는 기초 명령어들입니다.

**2. 왜 필요한가?**
GUI에서 더블클릭으로 하던 모든 일(어디에 있는지 보기, 들어가기, 새 폴더 만들기)을 CLI에서는 명령어로 합니다. 이 손가락 근육이 모든 리눅스 작업의 토대입니다.

**3. 예시**
```bash
pwd                 # 현재 내가 있는 경로 출력 (print working directory)
ls                  # 현재 위치의 파일/폴더 목록
ls -al              # 숨김 파일(.으로 시작)까지 + 상세 속성 포함
whoami              # 지금 로그인한 계정 이름
cd 문서             # '문서' 디렉토리로 이동
cd ..               # 한 단계 상위 폴더로 이동
mkdir project       # 'project' 폴더 생성
mkdir -p a/b/c      # 중첩 폴더(a 안에 b, 그 안에 c)를 한 번에 생성
touch hello.txt     # 비어 있는 파일 생성
cat hello.txt       # 파일 내용 출력
```

**4. 헷갈리기 쉬운 점**
- `whoami`(누구인가 = 계정)와 `pwd`(어디인가 = 경로)를 헷갈리기 쉽습니다. 하나는 "사람", 하나는 "위치"입니다.
- `mkdir a/b/c`는 `a`가 없으면 실패하지만, `mkdir -p a/b/c`는 없는 중간 폴더까지 한 번에 만들어 줍니다.

**5. 한 줄 정리**
`pwd`로 위치를 알고, `ls`로 둘러보고, `cd`로 이동하며, `mkdir`·`touch`로 만든다.

### 파일 속성과 ls -al

**1. 정의**
`ls -al`을 실행하면 각 파일마다 한 줄로 **속성**이 나옵니다. 이 한 줄에는 파일의 거의 모든 신상 정보가 담깁니다.

**2. 왜 필요한가?**
"이 파일을 누가 읽고 쓸 수 있는가? 언제 마지막으로 바뀌었나? 크기는?"을 알아야 권한 문제나 용량 문제를 진단할 수 있습니다. 서버 트러블슈팅의 출발점입니다.

**3. 예시**
```text
-rw-r--r-- 1 user user 8980 9월 16 09:35 sample.txt
```
이 한 줄은 다음과 같이 끊어 읽습니다.

| 항목 | 값 | 의미 |
| --- | --- | --- |
| 파일 유형 | `-` | 일반 파일(`-`), 디렉토리(`d`) |
| 파일 권한 | `rw-r--r--` | 소유자/그룹/그 외 사용자의 읽기·쓰기·실행 권한 |
| 링크 수 | `1` | 연결된 링크 개수 |
| 파일 소유자 | `user` | 이 파일의 주인 |
| 소유 그룹 | `user` | 파일이 속한 그룹 |
| 파일 크기 | `8980` | 바이트(Byte) 단위 크기 |
| 마지막 변경 시각 | `9월 16 09:35` | 마지막으로 수정된 시간 |
| 파일 이름 | `sample.txt` | 파일 이름 |

**4. 헷갈리기 쉬운 점**
맨 앞 글자가 `-`면 일반 파일, `d`면 디렉토리입니다. 그 뒤 9칸(`rw-r--r--`)은 3칸씩 끊어 **소유자 / 그룹 / 그 외 사용자** 순서로 읽어야 합니다.

**5. 한 줄 정리**
`ls -al`의 한 줄은 파일의 주민등록증이다 — 유형·권한·주인·크기·시각이 모두 담겨 있다.

### 소유권과 권한, 그리고 chmod

**1. 정의**
리눅스 파일 권한은 **읽기(read)·쓰기(write)·실행(execute)** 세 종류를, **소유자·그룹·그 외 사용자** 세 대상에게 각각 부여합니다. `chmod`는 이 권한을 바꾸는 명령어입니다.

**2. 왜 필요한가?**
여러 사람이 함께 쓰는 서버에서, 아무나 중요한 파일을 고치거나 지우면 안 됩니다. 권한 시스템은 "누가 이 파일을 읽고/쓰고/실행할 수 있는가"를 통제하는 보안의 기본 장치입니다.

**3. 예시 — 숫자로 권한 읽기**
권한은 읽기(4)·쓰기(2)·실행(1)의 합으로 표현합니다.

| 대상 | 권한 | 계산 | 숫자 |
| --- | --- | --- | --- |
| 소유자 | `rw-` | 4 + 2 + 0 | 6 |
| 그룹 | `r--` | 4 + 0 + 0 | 4 |
| 그 외 사용자 | `r--` | 4 + 0 + 0 | 4 |

→ `rw-r--r--` 는 곧 **644** 입니다.

```bash
# 모든 사용자에게 읽기·쓰기·실행 권한을 모두 부여 (7 = 4+2+1)
chmod 777 sample.txt
ls -al
# -rwxrwxrwx 1 user user 13 9월 16 09:35 sample.txt
```
`chmod [권한숫자] [대상 파일]` 형태이며, `777`은 "모든 사용자가 모든 권한을 가진다"는 뜻입니다.

**4. 헷갈리기 쉬운 점**
`777`은 편하지만 위험합니다. 누구나 쓰고 실행할 수 있다는 건 보안 구멍이 될 수 있어, 실무에서는 꼭 필요한 만큼만(예: 파일은 보통 `644`, 폴더는 `755`) 권한을 줍니다.

**5. 한 줄 정리**
권한은 (읽기4·쓰기2·실행1)을 (소유자·그룹·그외)별로 합산한 세 자리 숫자이며, `chmod`로 바꾼다.

> 비유: 권한은 사무실 문서함의 출입 권한표다. 어떤 서류는 본인만(600), 어떤 건 팀 전체가(640), 어떤 건 누구나(644) 열어 볼 수 있게 지정하는 것과 같다.

### 텍스트 편집기 — nano와 vi

**1. 정의**
터미널 안에서 파일 내용을 직접 작성·수정하는 도구입니다. **nano**는 가볍고 쉬운 편집기, **vi**는 더 강력하지만 진입 장벽이 있는 편집기입니다.

**2. 왜 필요한가?**
화면(GUI)이 없는 서버에서는 메모장 같은 프로그램을 띄울 수 없습니다. 설정 파일을 고치거나 스크립트를 작성하려면 터미널 안에서 동작하는 편집기가 반드시 필요합니다.

**3. 예시**
```bash
nano hello.txt      # nano로 파일 열기(없으면 새로 만들며 열림)
vi memo.txt         # vi로 파일 열기/생성
```
nano의 주요 단축키 (대문자로 입력하지 않아도 됩니다):

| 단축키 | 동작 | 단축키 | 동작 |
| --- | --- | --- | --- |
| `Ctrl + O` | 저장하기 | `Alt + 6` | 복사하기 |
| `Ctrl + X` | 종료하기 | `Ctrl + U` | 붙여넣기 |
| `Ctrl + W` | 검색하기 | `Ctrl + ^` | 여러 줄 선택 |

vi는 처음엔 "열고 빠져나오기"부터 익히면 충분합니다. `vi memo.txt`로 열고, 저장 없이 강제로 빠져나오려면 `:q!` 를 입력합니다.

**4. 헷갈리기 쉬운 점**
vi에 처음 들어가면 글자가 입력되지 않아 당황하기 쉽습니다. vi는 "명령 모드 / 입력 모드"가 나뉘어 있어, 입력하려면 먼저 `i`를 눌러 입력 모드로 들어가야 합니다. 일단 빠져나오는 안전한 탈출 명령(`:q!`)부터 외워 두면 좋습니다.

**5. 한 줄 정리**
nano는 입문용 쉬운 편집기, vi는 강력하지만 모드 개념을 익혀야 하는 편집기다.

## 코드로 보기 — 파일을 만들고 권한 확인·변경하기

```bash
# 1단계: 빈 파일을 만든다
touch sample.txt

# 2단계: 상세 속성으로 현재 권한을 확인한다
ls -al
# -rw-r--r-- 1 user user 0 9월 16 09:35 sample.txt   ← 644(소유자만 쓰기 가능)

# 3단계: 모든 사용자에게 모든 권한을 준다
chmod 777 sample.txt

# 4단계: 권한이 바뀌었는지 다시 확인한다
ls -al
# -rwxrwxrwx 1 user user 0 9월 16 09:35 sample.txt   ← 777(모두 읽기·쓰기·실행)
```

**코드목적**
파일을 만들고, 그 파일의 권한을 눈으로 확인한 뒤, `chmod`로 권한을 바꾸고 변화를 검증하는 한 사이클을 연습하기 위한 예제입니다.

**해석**
처음엔 권한이 `rw-r--r--`(644)로, 소유자만 수정할 수 있습니다. `chmod 777` 이후 `rwxrwxrwx`로 바뀌어 세 대상 모두 모든 권한을 갖게 됩니다. 권한 문자열이 어떻게 변하는지 직접 보는 것이 핵심입니다.

**실무 연결**
배포 스크립트에 실행 권한을 주거나(`chmod +x deploy.sh`), 웹 서버가 특정 폴더를 읽을 수 있게 권한을 조정하는 등, 권한 다루기는 서버 운영의 일상입니다. "권한 거부(Permission denied)" 오류의 90%는 이 개념으로 해결됩니다.

## 헷갈리기 쉬운 포인트

- **whoami vs pwd**: 누구(계정)인지 vs 어디(경로)인지.
- **파일 vs 디렉토리**: `ls -al` 맨 앞이 `-`면 파일, `d`면 디렉토리.
- **mkdir vs mkdir -p**: 중간 폴더가 없으면 전자는 실패, 후자는 알아서 만들어 준다.
- **nano vs vi**: 쉬움·즉시 사용 vs 강력함·모드 개념 학습 필요.

**복습 질문 및 답변**

- (기본) `mkdir -p`는 일반 `mkdir`과 무엇이 다른가요?
  - 존재하지 않는 중간 디렉토리까지 한 번에 만들어 줍니다.
- (이해확인) `rwxr-xr-x` 권한을 숫자로 바꾸면 얼마인가요?
  - 7(4+2+1) / 5(4+0+1) / 5(4+0+1) → **755** 입니다.
- (응용) 동료가 만든 스크립트를 실행하려는데 "Permission denied"가 뜹니다. 무엇을 의심하고 어떻게 해결할까요?
  - 실행 권한이 없을 가능성이 큽니다. `ls -al`로 권한을 확인하고 `chmod +x 파일명`으로 실행 권한을 부여합니다.

## 한 줄 정리

> 리눅스의 모든 것은 `/`에서 뻗은 트리이며, 그 위의 파일은 소유자·그룹·그 외 사용자별 권한(읽기4·쓰기2·실행1)으로 통제되고, `ls -al`과 `chmod`가 이를 읽고 바꾸는 핵심 도구다.
