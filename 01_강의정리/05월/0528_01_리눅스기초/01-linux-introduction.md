# 리눅스 입문 — 운영체제부터 패키지·권한까지

> 개발자들은 왜 다들 까만 화면에 글자를 치고 있을까? 그리고 그 화면 속 "리눅스"는 도대체 무엇일까?

`리눅스` `우분투` `배포판` `GUI` `CLI` `apt` `sudo` `root` `패키지관리자`

## 핵심요약

- 리눅스는 무료로 쓸 수 있고 자유롭게 고칠 수 있는 운영체제이며, 용도에 맞게 변형한 여러 **배포판**(우분투, CentOS 등)으로 나뉜다.
- 배포판은 크게 **레드햇 계열**(`.rpm`, `yum`)과 **데비안 계열**(`.deb`, `apt`)로 묶을 수 있다.
- **우분투**는 데비안 기반의 데스크탑용 배포판으로, 쉽고 사용자가 많아 입문용으로 널리 쓰인다.
- 컴퓨터를 다루는 방식에는 마우스 중심의 **GUI**와 문자 명령 중심의 **CLI**가 있고, 서버·개발 환경에서는 CLI가 표준이다.
- **apt**는 소프트웨어를 설치·삭제·업데이트해 주는 도구(패키지 관리자)로, `apt install`처럼 쓴다.
- **root**는 모든 권한을 가진 최고 관리자이며, 일반 사용자는 `sudo`를 앞에 붙여 잠깐 그 권한을 빌려 쓴다.

## 개념별 정리

### 리눅스와 배포판

**1. 정의**
리눅스는 컴퓨터의 자원(메모리, 저장장치, 네트워크 등)을 관리하는 운영체제입니다. 핵심 부분(커널)은 누구나 자유롭게 쓰고 수정할 수 있어, 이를 바탕으로 만든 다양한 완성형 묶음을 **배포판(Distribution)** 이라고 부릅니다.

**2. 왜 필요한가?**
서버, 라즈베리파이, 안드로이드, 네트워크 장비, 심지어 정밀 의료기기까지 — 우리가 의식하지 못하는 곳 대부분이 리눅스로 돌아갑니다. 개발·데이터·AI 작업의 실제 실행 환경이 거의 리눅스이기 때문에, 리눅스를 모르면 "내 코드가 돌아가는 곳"을 이해하지 못하는 셈입니다.

**3. 예시**
대표적인 배포판은 패키지 형식과 관리자에 따라 다음과 같이 나뉩니다.

| 계열 | 패키지 형식 | 패키지 관리자 | 대표 운영체제 |
| --- | --- | --- | --- |
| 레드햇 | `.rpm` | `yum` | CentOS, 페도라(Fedora) |
| 데비안 | `.deb` | `apt` | 우분투(Ubuntu), 리눅스 민트, 라즈비안 |
| 안드로이드 | `.apk` | Android Package Manager | 안드로이드 OS |

**4. 헷갈리기 쉬운 점**
"리눅스"와 "우분투"를 같은 것으로 착각하기 쉽습니다. 리눅스는 공통의 뿌리(커널)이고, 우분투는 그 뿌리에서 자란 하나의 나무(배포판)입니다. CentOS·우분투·민트는 모두 리눅스지만 패키지 관리 방식이 서로 다릅니다.

**5. 한 줄 정리**
리눅스는 공통의 엔진, 배포판은 그 엔진으로 만든 서로 다른 완성차다.

> 비유: 같은 밀가루(리눅스 커널)로 누구는 빵을, 누구는 국수를 만든다. 우분투·CentOS는 그렇게 만들어진 서로 다른 음식(배포판)이다.

### 우분투

**1. 정의**
데비안 GNU/Linux를 기반으로 만든, **데스크탑 환경에 친화적인 리눅스 배포판**입니다.

**2. 왜 필요한가?**
개인용 PC 환경에 최적화되어 있고, 간결하고 쉬우며, 사용자가 많아 막혔을 때 검색으로 해결책을 찾기 좋습니다. 약 6개월 단위로 꾸준히 업데이트되어 입문자에게 안정적입니다.

**3. 예시**
우분투라는 이름은 남아프리카 반투어의 "우분투"에서 왔으며, *사람들 간의 관계와 헌신을 중시하는 인본주의 사상*을 뜻합니다. 기본 그래픽 환경으로는 GNOME 인터페이스를 제공합니다.

**4. 헷갈리기 쉬운 점**
"우분투는 명령어만 쓰는 검은 화면"이라는 오해가 있는데, 우분투도 GUI(마우스로 쓰는 그래픽 환경)를 제공합니다. 다만 학습·서버 작업에서는 CLI(터미널)를 주로 다룹니다.

**5. 한 줄 정리**
우분투는 "쉽고 사용자 많은 데비안 계열 리눅스"로, 입문의 표준 선택지다.

### GUI와 CLI

**1. 정의**
- **GUI(Graphical User Interface)**: 아이콘·이미지 같은 그래픽으로 조작하는 인터페이스. (예: 윈도우, macOS 바탕화면)
- **CLI(Command Line Interface)**: 문자 명령으로 사용자와 컴퓨터가 상호작용하는 인터페이스. (예: 윈도우 CMD, macOS Terminal)

**2. 왜 필요한가?**
GUI는 직관적이지만, 같은 작업을 1,000번 반복하거나 화면이 없는 원격 서버를 다룰 때는 비효율적입니다. CLI는 명령 한 줄로 복잡하고 반복적인 작업을 자동화할 수 있어, 서버·개발 환경의 사실상 표준입니다.

**3. 예시**
```bash
# GUI라면 폴더를 더블클릭해 들어가지만, CLI에서는 한 줄로 처리한다
cd /home/user/문서
ls
```

**4. 헷갈리기 쉬운 점**
CLI가 GUI보다 "어려운 상위 버전"이 아니라, **목적이 다른 도구**입니다. 빠른 자동화·원격 작업엔 CLI가, 직관적 탐색엔 GUI가 유리합니다.

**5. 한 줄 정리**
GUI는 마우스로 가리키는 방식, CLI는 문자로 지시하는 방식이다.

> 비유: GUI는 메뉴판을 손가락으로 가리켜 주문하기, CLI는 점원에게 정확한 문장으로 주문하기다. 익숙해지면 후자가 훨씬 빠르다.

### 패키지 관리자 apt

**1. 정의**
apt(Advanced Packaging Tool)는 데비안 계열 배포판에서 소프트웨어를 **설치·제거·업데이트**해 주는 도구입니다.

**2. 왜 필요한가?**
프로그램을 일일이 웹에서 내려받아 설치하면 버전 충돌·의존성 문제가 생깁니다. apt는 필요한 부속 프로그램(의존성)까지 알아서 챙겨 설치해 주는, 일종의 "공식 앱스토어 + 자동 설치기"입니다.

**3. 예시**
과거에는 `apt-get`과 `apt-cache`를 나눠 썼지만, 최신 우분투에서는 이를 합친 `apt`를 제공합니다.

| 최신(`apt`) | 기존 명령어 |
| --- | --- |
| `apt install` | `apt-get install` |
| `apt remove` | `apt-get remove` |
| `apt update` | `apt-get update` |
| `apt search` | `apt-cache search` |
| `apt show` | `apt-cache show` |

**4. 헷갈리기 쉬운 점**
`apt update`와 `apt upgrade`를 혼동하기 쉽습니다. `update`는 "어떤 새 버전이 있는지 목록을 새로 받아오는 것", `upgrade`는 "실제로 최신 버전으로 갈아끼우는 것"입니다.

**5. 한 줄 정리**
apt는 리눅스용 자동 설치 도우미로, `apt install 패키지명` 형태로 쓴다.

### root와 sudo

**1. 정의**
- **root**: 리눅스에서 모든 권한을 가진 최고 관리자. 운영체제의 모든 것을 제어할 수 있습니다.
- **sudo**: 일반 사용자가 명령어 앞에 붙여 **잠깐 root 권한을 빌려 실행**하게 해 주는 키워드입니다.

**2. 왜 필요한가?**
소프트웨어 설치처럼 시스템 전체에 영향을 주는 작업은 아무나 못 하게 막혀 있습니다. 평소엔 안전한 일반 권한으로 작업하다가, 필요한 순간에만 `sudo`로 관리자 권한을 빌려 쓰면 실수로 시스템을 망가뜨릴 위험이 줄어듭니다.

**3. 예시**
```bash
# 권한 없이 설치 시도 → 거부됨
apt install nano
# E: Unable to acquire the dpkg frontend lock ..., are you root?

# sudo로 권한을 빌려 실행 → 비밀번호 입력 후 정상 동작
sudo apt install nano
```
`sudo`를 입력하면 우분투 설치 시 지정했던 비밀번호를 묻고, 맞으면 명령이 실행됩니다.

**4. 헷갈리기 쉬운 점**
"항상 sudo를 붙이면 편하다"는 생각은 위험합니다. 관리자 권한은 실수도 그대로 시스템에 반영되므로(예: 중요한 시스템 파일 삭제), 꼭 필요할 때만 사용하는 습관이 중요합니다.

**5. 한 줄 정리**
root는 모든 권한을 가진 관리자, sudo는 그 권한을 명령 한 줄 동안만 빌리는 열쇠다.

> 비유: root는 건물 마스터키를 가진 관리소장, sudo는 "이 문 한 번만 열게요" 하고 잠깐 키를 빌리는 것이다.

## 코드로 보기 — sudo로 패키지 설치하기

```bash
# 1단계: 권한 없이 설치를 시도하면 거부된다
apt install nano
# → are you root? (권한 부족)

# 2단계: sudo로 관리자 권한을 빌려 다시 실행
sudo apt install nano
# [sudo] 비밀번호 입력 ...
# 패키지 목록 / 의존성 트리 / 상태 정보 읽는 중 ... 완료
# nano 패키지는 이미 최신 버전입니다.
```

**코드목적**
권한이 필요한 작업(소프트웨어 설치)을 sudo로 어떻게 수행하는지, 그리고 권한이 없을 때 어떤 메시지가 뜨는지 직접 확인하기 위한 예제입니다.

**해석**
첫 번째 시도는 "관리자냐?"라고 되물으며 막힙니다. `sudo`를 붙이면 비밀번호 확인 후, apt가 패키지 목록과 의존성을 점검하고 설치(또는 "이미 최신"임을)를 알려 줍니다. 결과 메시지를 읽는 습관이 곧 리눅스 문해력입니다.

**실무 연결**
서버에 분석 도구(예: 데이터베이스 클라이언트), 웹 서버, 언어 런타임을 올릴 때 거의 항상 이 패턴(`sudo apt install ...`)을 씁니다. AI 서비스 배포 환경을 세팅하는 첫 단추이기도 합니다.

## 헷갈리기 쉬운 포인트

- **리눅스 vs 우분투**: 리눅스는 공통 뿌리(커널), 우분투는 그 위에 만든 하나의 배포판.
- **GUI vs CLI**: 마우스 그래픽 조작(GUI) vs 문자 명령 조작(CLI). 상하 관계가 아니라 용도 차이.
- **apt vs apt-get**: 같은 일을 하지만 `apt`가 더 새롭고 간결한 통합 명령.
- **root vs sudo**: root는 권한의 "주인", sudo는 그 권한을 잠깐 "빌리는" 행위.

> 리눅스는 세상의 서버를 떠받치는 공통 엔진이고, 우분투는 그 입문판이며, `apt`와 `sudo`는 그 환경을 만지기 위한 첫 두 도구다.
