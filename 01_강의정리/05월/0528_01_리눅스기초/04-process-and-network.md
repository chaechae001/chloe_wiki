# 프로세스와 네트워크 — ps·job·cron·ssh

> 지금 이 순간에도 컴퓨터 안에서는 수백 개의 프로그램이 동시에 살아 움직인다. 그들을 들여다보고, 멈추고, 미래에 깨우고, 멀리서 명령하는 법.

`프로세스` `PID` `ps` `job` `백그라운드` `cron` `crontab` `ssh`

## 핵심요약

- **프로세스**는 메모리에 올라와 실행 중인 프로그램이며, 저마다 고유 번호(**PID**)를 가진다.
- 프로세스는 부모-자식 관계를 이루고, 커널이 관리하며, 각자 소유자가 있다.
- `ps`로 실행 중인 프로세스 목록과 상세 정보를 본다.
- **job**은 작업을 화면 앞(포그라운드)이나 뒤(백그라운드, `&`)에서 실행·관리하는 개념이며, `jobs`·`kill %번호`로 다룬다.
- **cron**(crontab)은 명령을 정해진 시각에 자동·반복 실행하도록 예약하는 스케줄러다.
- **ssh**는 원격 컴퓨터에 **암호화된** 연결로 접속하는 방법이며, 우분투에서는 `openssh` 패키지로 구동한다.

## 개념별 정리

### 프로세스와 PID

**1. 정의**
**프로세스(Process)** 는 리눅스 시스템에서 메모리에 적재되어 실행되고 있는 모든 프로그램을 말합니다. 모든 프로세스에는 식별을 위한 고유 번호 **PID(Process ID)** 가 부여됩니다.

**2. 왜 필요한가?**
"어떤 프로그램이 CPU를 잡아먹는가", "멈춘 프로그램을 어떻게 끄는가"를 다루려면 프로세스 단위로 시스템을 봐야 합니다. 서버가 느려지거나 멎었을 때 원인을 찾는 출발점입니다.

**3. 예시 — 프로세스의 특징**
- 모든 프로그램은 실행될 때 하나 이상의 프로세스를 갖는다.
- 여러 프로세스가 병행적으로(동시에) 실행될 수 있다.
- 부모 프로세스와 자식 프로세스가 있다.
- 커널에 의해 관리되며, 각 프로세스에는 소유자가 있다.

PID에는 특별한 번호가 있습니다. **PID 1번은 `init` 프로세스**로 나머지 모든 시스템 프로세스의 부모이고, **2번은 `kthreadd` 프로세스**로 모든 커널 스레드의 부모입니다.

**4. 헷갈리기 쉬운 점**
"프로그램"과 "프로세스"는 다릅니다. 프로그램은 저장된 파일(설계도)이고, 프로세스는 그것이 메모리에 올라와 **실제로 실행되는 상태**(가동 중인 기계)입니다. 같은 프로그램을 두 번 실행하면 PID가 다른 두 개의 프로세스가 생깁니다.

**5. 한 줄 정리**
프로세스는 실행 중인 프로그램이고, PID는 그 프로세스의 주민번호다.

> 비유: 프로그램이 요리 레시피(종이)라면, 프로세스는 그 레시피로 지금 요리 중인 주방이다. 같은 레시피로 두 솥을 끓이면 주방(프로세스)은 둘이다.

### 프로세스의 메모리 구성

**1. 정의**
하나의 프로세스가 차지하는 메모리는 용도에 따라 여러 영역으로 나뉩니다.

| 영역 | 담는 것 |
| --- | --- |
| 코드 영역 | 프로그램 코드 |
| 데이터 영역 | 전역 변수와 정적 변수 |
| BSS 영역 | 초기화되지 않은 변수 |
| 힙(Heap) 영역 | 동적으로 할당되는 메모리 |
| 스택(Stack) 영역 | 함수 매개변수, 복귀 주소, 지역 변수 같은 임시 자료 |

**2. 왜 필요한가?**
메모리를 용도별로 나누면 관리가 쉽고, "메모리 누수", "스택 오버플로" 같은 문제의 원인을 영역 단위로 짚을 수 있습니다. 프로그래밍 언어가 변수를 어디에 두는지 이해하는 토대이기도 합니다.

**3. 예시**
함수 안에서 잠깐 쓰는 지역 변수는 **스택**에, 프로그램 내내 유지되는 전역 변수는 **데이터 영역**에, 실행 중에 크기를 모르고 동적으로 잡는 메모리는 **힙**에 놓입니다.

**4. 헷갈리기 쉬운 점**
힙과 스택을 혼동하기 쉽습니다. 스택은 함수 호출에 맞춰 자동으로 쌓였다 사라지는 임시 공간, 힙은 프로그램이 직접 요청해 할당하고 해제하는 동적 공간입니다.

**5. 한 줄 정리**
프로세스 메모리는 코드·데이터·BSS·힙·스택으로 나뉘며, 변수의 성격에 따라 자리가 정해진다.

### 프로세스 명령어 ps

**1. 정의**
`ps`는 현재 실행 중인 프로세스 목록을 보여 주는 명령어입니다.

**2. 왜 필요한가?**
무엇이 돌아가는지 봐야 끄거나 진단할 수 있습니다. 특정 프로세스의 PID를 알아내 종료하거나, 자원을 많이 쓰는 범인을 찾을 때 가장 먼저 쓰는 명령입니다.

**3. 예시**
```bash
ps [option]
# option
#   -e : 현재 실행 중인 모든 프로세스 정보 출력
#   -f : 모든 정보(전체 포맷) 확인
#   -a : 실행 중인 전체 사용자의 모든 프로세스 출력
#   -u : 프로세스를 실행한 사용자와 시작 시간 등을 출력
#   -x : 터미널 제어 없이 동작하는 프로세스 현황 보기

ps -ef       # 흔히 쓰는 조합: 모든 프로세스를 상세 포맷으로
```

**4. 헷갈리기 쉬운 점**
`ps`만 단독으로 치면 현재 터미널과 연결된 프로세스만 조금 보입니다. 시스템 전체를 보려면 `-e`(또는 `-ax`) 같은 옵션을 붙여야 합니다.

**5. 한 줄 정리**
`ps`는 "지금 무엇이 돌고 있나"를 보여 주는 시스템의 현황판이다.

### job — 포그라운드와 백그라운드

**1. 정의**
**job**은 셸에서 실행하는 작업의 실행 위치를 다루는 개념입니다.
- **포그라운드(Foreground)**: 작업이 끝날 때까지 터미널을 점유하는 일반 실행.
- **백그라운드(Background)**: 명령 끝에 `&`를 붙여, 터미널을 돌려받고 뒤에서 돌리는 실행.

**2. 왜 필요한가?**
오래 걸리는 작업(대용량 처리, 서버 실행)을 포그라운드로 돌리면 끝날 때까지 다른 일을 못 합니다. 백그라운드로 돌리면 같은 터미널에서 다른 작업을 이어 할 수 있어, 프로세스를 효율적으로 관리할 수 있습니다.

**3. 예시**
```bash
sleep 500 &     # 500초 대기 작업을 백그라운드로 실행
# [1] 2292      ← [작업번호] PID
sleep 700 &
# [2] 2293

jobs            # 현재 백그라운드 작업 목록 확인
# [1]-  실행중                 sleep 500 &
# [2]+  실행중                 sleep 700 &

kill %1         # 1번 작업 종료 (% + 작업번호)
jobs
# [1]-  종료됨                 sleep 500
# [2]+  실행중                 sleep 700 &
```
프로세스와 마찬가지로 `kill`로 종료할 수 있으며, `ps`로 PID를 알아내 `kill PID` 형태로 끄는 방법도 있습니다.

**4. 헷갈리기 쉬운 점**
`kill %1`의 `%1`은 PID가 아니라 **작업 번호(job number)** 입니다. PID로 끌 때는 `%` 없이 `kill 2292`처럼 씁니다. 둘을 헷갈리면 엉뚱한 프로세스를 끌 수 있으니 주의하세요.

**5. 한 줄 정리**
`&`로 작업을 뒤로 보내고, `jobs`로 목록을 보고, `kill %번호`로 정리한다.

> 비유: 포그라운드는 손에 들고 계속 봐야 하는 일, 백그라운드는 세탁기에 넣고 돌려둔 빨래다. 돌려두고 다른 일을 하다가 필요하면 멈출(`kill`) 수 있다.

### cron — 예약·반복 실행

**1. 정의**
**cron**은 명령을 정해진 시각에 자동으로 반복 실행해 주는 스케줄러이며, 그 일정을 등록·관리하는 명령이 **crontab**입니다.

**2. 왜 필요한가?**
"매일 새벽 3시에 백업", "매주 일요일에 리포트 생성"처럼 사람이 매번 챙길 수 없는 정기 작업을 자동화합니다. 서버 운영 자동화의 핵심 도구입니다.

**3. 예시**
```bash
crontab [옵션]
# option
#   -l : 현재 계정에 설정된 crontab 정보를 보여준다
#   -e : 현재 계정의 crontab 정보를 수정한다
#   -r : 현재 계정의 crontab 정보를 모두 삭제한다
#   -u : 특정 사용자의 crontab을 다룬다 (root 권한 필요)
```
등록 형식은 **분 시 일 월 요일 명령어** 순서입니다.
```text
분(0~59)  시(0~23)  일(1~31)  월(1~12)  요일(0~6)  수행할 명령어
# 요일: 0=일요일, 1=월요일, ... , 6=토요일
```
실제 등록 예 (`crontab -l`):
```bash
# 매월 1일 1시 10분에 test.sh 실행
10 1 1 * * /home/user/test.sh

# 일요일 1시, 1시 30분에 backup.sh 실행
0,30 1 * * 0 /home/user/backup.sh
```
`*`는 "모든 값(매번)"을 뜻하고, 콤마(`,`)를 쓰면 두 가지 이상의 시각을 한 번에 지정할 수 있습니다(위의 `0,30`은 0분과 30분 둘 다).

**4. 헷갈리기 쉬운 점**
필드 순서를 외우는 게 관건입니다. **분·시·일·월·요일** 순서이며, 맨 앞이 "분"이라는 점을 자주 헷갈립니다. 또 요일과 일을 동시에 지정하면 의도와 다르게 동작할 수 있어 주의가 필요합니다.

**5. 한 줄 정리**
cron은 "언제 무엇을 실행할지"를 분·시·일·월·요일 형식으로 예약하는 알람 시계다.

> 비유: crontab은 반복 알람 설정과 같다. "매주 일요일 오전 1시에 울려"처럼 시각을 정해 두면, 사람이 없어도 정해진 일이 저절로 실행된다.

### ssh — 안전한 원격 접속

**1. 정의**
**ssh(Secure Shell)** 는 멀리 있는 컴퓨터(서버)에 네트워크로 접속해 명령을 내릴 수 있게 해 주는 방법으로, 주고받는 데이터가 **암호화**됩니다.

**2. 왜 필요한가?**
서버는 보통 내 책상이 아니라 데이터센터에 있습니다. ssh로 접속하면 마치 그 컴퓨터 앞에 앉은 것처럼 원격 제어할 수 있습니다. 과거의 Telnet은 데이터가 암호화되지 않아 비밀번호 등이 그대로 노출될 위험이 있었지만, ssh는 이를 암호화해 안전하게 보호합니다.

**3. 예시**
```bash
# 1) 설치 여부 확인
dpkg -l | grep openssh
# openssh-client ... secure shell (SSH) client ...

# 2) 다른 컴퓨터가 접속해 오도록 서버 패키지 설치
sudo apt-get install openssh-server

# 3) ssh 서버 실행 및 상태 확인
sudo service ssh start
service --status-all | grep +

# 4) 열려 있는 포트 확인 (ssh 기본 포트 22)
sudo netstat -antp
# tcp  0  0 0.0.0.0:22  0.0.0.0:*  LISTEN  .../sshd

# 5) 원격 접속
ssh [서버아이디]@[아이피 또는 서버이름 또는 도메인]
```
우분투에는 `openssh-client`가 기본 설치되어 있지만, **다른 컴퓨터가 내게 접속**하게 하려면 `openssh-server`를 따로 설치해야 합니다.

**4. 헷갈리기 쉬운 점**
- **client vs server**: 내가 남에게 접속할 땐 client, 남이 내게 접속하게 하려면 server 패키지가 필요합니다. 역할이 반대입니다.
- ssh의 기본 포트는 **22번**입니다. `netstat`에서 `:22 ... LISTEN`이 보이면 ssh 서버가 접속을 기다리는 상태입니다.

**5. 한 줄 정리**
ssh는 암호화된 원격 접속 통로이며, 접속하려면 client·server 역할에 맞는 openssh 패키지가 필요하다.

> 비유: ssh는 멀리 있는 사무실로 연결된 보안 전용 회선이다. Telnet이 엽서(누구나 내용을 봄)라면, ssh는 밀봉된 등기우편(암호화)이다.

## 코드로 보기 — 백그라운드 작업 띄우고 관리하기

```bash
# 1단계: 오래 걸리는 작업 2개를 백그라운드로 실행
sleep 500 &
# [1] 2292
sleep 700 &
# [2] 2293

# 2단계: 현재 백그라운드 작업 목록 확인
jobs
# [1]-  실행중                 sleep 500 &
# [2]+  실행중                 sleep 700 &

# 3단계: 1번 작업을 작업 번호로 종료
kill %1

# 4단계: 결과 확인
jobs
# [1]-  종료됨                 sleep 500
# [2]+  실행중                 sleep 700 &
```

**코드목적**
시간이 오래 걸리는 작업을 백그라운드(`&`)로 띄워 터미널을 계속 쓰고, 작업 목록(`jobs`)을 확인하며 원하는 작업만 골라 종료(`kill %번호`)하는 흐름을 익히기 위한 예제입니다.

**해석**
`&`를 붙이면 `[작업번호] PID` 형식으로 즉시 제어권이 돌아옵니다. `jobs`로 보면 두 작업이 "실행중"입니다. `kill %1` 이후 1번은 "종료됨"으로, 2번은 여전히 "실행중"으로 남아 — 작업 단위로 정확히 제어되었음을 확인할 수 있습니다.

**실무 연결**
대용량 데이터 전처리, 모델 학습, 서버 프로세스 실행처럼 오래 걸리는 작업을 백그라운드로 돌려 두고 다른 일을 이어 하는 방식은 데이터·AI 작업의 표준입니다. 잘못 띄운 작업을 골라 끄는 능력도 필수입니다.

2. `sleep 300 &` → `jobs`로 작업번호 확인 → `kill %1`(작업번호) 또는 `kill PID`(예: `kill 2292`).
3. `0 9 * * * /home/user/script.sh` — 분(0) 시(9) 일(*) 월(*) 요일(*) 순서입니다.

## 헷갈리기 쉬운 포인트

- **프로그램 vs 프로세스**: 저장된 파일(설계도) vs 메모리에서 실행 중인 상태(가동 기계).
- **포그라운드 vs 백그라운드**: 터미널 점유 vs `&`로 뒤에서 실행.
- **`kill %1` vs `kill PID`**: 작업 번호로 끄기 vs 프로세스 번호로 끄기.
- **openssh-client vs openssh-server**: 내가 접속할 때 vs 남이 내게 접속할 때.
- **힙 vs 스택**: 직접 할당하는 동적 영역 vs 함수 호출에 따라 자동으로 쌓이는 임시 영역.

## 셀프 체크

- [ ] 프로세스와 PID의 개념을 설명할 수 있다.
- [ ] PID 1번(init)의 역할을 안다.
- [ ] `ps`로 프로세스를 확인하는 법을 안다.
- [ ] `&`로 백그라운드 실행하고 `kill %번호`로 종료할 수 있다.
- [ ] crontab의 "분 시 일 월 요일" 형식을 안다.
- [ ] ssh가 암호화 원격 접속이며 client/server 역할이 다름을 안다.

**복습 질문 및 답변**

- (기본) 백그라운드로 명령을 실행하려면 무엇을 붙이나요?
  - 명령 끝에 `&`를 붙입니다.
- (이해확인) crontab `0,30 1 * * 0`은 언제 실행되나요?
  - 매주 일요일(요일 0) 1시 0분과 1시 30분에 실행됩니다.
- (응용) 멀리 있는 우분투 서버에 내 노트북에서 접속하려 합니다. 서버 쪽과 내 쪽에는 각각 무엇이 필요할까요?
  - 서버 쪽은 `openssh-server`가 설치·실행되어 있어야 하고, 내 쪽은 `openssh-client`(우분투엔 기본 설치)가 있어야 합니다. 접속은 `ssh 아이디@주소`로 합니다.

## 한 줄 정리

> 프로세스는 실행 중인 프로그램(PID로 식별)이고, `ps`로 들여다보며 job(`&`·`kill`)으로 다루고, cron으로 미래에 예약 실행하며, ssh로 멀리 있는 서버까지 안전하게 손을 뻗는다.
