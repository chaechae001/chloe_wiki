# 텍스트 흐름 다루기 — 리다이렉션·파이프·검색

> 명령어 하나하나는 작은 부품이다. 그런데 이 부품들을 호스로 이어 붙이면? 로그 수만 줄에서 원하는 줄만 뽑아내는 한 줄짜리 마법이 만들어진다.

`표준입출력` `리다이렉션` `파이프` `grep` `정규표현식` `mount` `로그분석`

## 핵심요약

- 리눅스 명령어는 기본적으로 **입력(키보드) → 처리 → 출력(화면)** 의 흐름을 가진다.
- **리다이렉션**은 이 흐름의 방향을 바꿔, 출력을 화면 대신 파일로 보내거나(`>`, `>>`) 파일을 입력으로 끌어온다(`<`).
- `>`는 **덮어쓰기**(기존 내용 삭제), `>>`는 **이어쓰기**(뒤에 추가)로 결과가 완전히 다르다.
- 에러 메시지만 따로 저장할 때는 `2>`를 쓴다.
- **grep**은 텍스트에서 특정 패턴이 들어간 줄만 골라내는 검색 도구이며, **정규표현식**으로 패턴을 표현한다.
- **파이프(`|`)** 는 한 명령어의 출력을 다음 명령어의 입력으로 곧장 연결해, 명령어를 조립하게 해 준다.
- **mount**는 USB·디스크 같은 물리 저장 장치를 디렉토리에 연결해 사용할 수 있게 하는 작업이다.

## 개념별 정리

### 표준 입출력과 리다이렉션

**1. 정의**
명령어는 **표준 입력**(보통 키보드)으로 받아 **표준 출력**(보통 화면)으로 결과를 내보냅니다. **리다이렉션(Redirection)** 은 이 입출력의 방향을 바꾸는 기능입니다.

| 기호 | 의미 |
| --- | --- |
| `>` | 출력을 파일로 보내기(**덮어쓰기**) |
| `>>` | 출력을 파일에 **이어쓰기**(추가) |
| `<` | 파일을 명령어의 입력으로 가져오기 |
| `2>` | **에러** 메시지만 파일로 보내기 |

**2. 왜 필요한가?**
명령 결과를 화면으로만 보면 사라집니다. 결과를 파일로 저장해 두면 나중에 분석하거나 보고서로 쓸 수 있고, 에러만 따로 모아 로그로 남길 수도 있습니다. 자동화의 출발점입니다.

**3. 예시**
```bash
echo "hello"               # 화면에 hello 출력
echo "hello" > hello.txt   # 화면 대신 hello.txt에 저장(기존 내용 덮어씀)
echo "world" >> hello.txt  # hello.txt 끝에 world 한 줄 추가
cat hello.txt              # hello / world
```
에러만 따로 저장하는 예:
```bash
cd helloelice > err.txt
# bash: cd: helloelice: 그런 파일이나 디렉터리가 없습니다  ← 에러는 화면에 그대로
cat err.txt
#                                                           ← err.txt는 비어 있음

cd helloelice 2> err.txt   # 이번엔 에러를 err.txt로 보냄
cat err.txt
# bash: cd: helloelice: 그런 파일이나 디렉터리가 없습니다  ← 에러가 파일에 저장됨
```
입력과 출력을 동시에 바꾸는 예:
```bash
cat < hello.txt > result.txt
# 1. hello.txt의 내용을 cat의 입력 스트림으로 전송
# 2. cat은 받은 내용을 출력
# 3. 그 출력 스트림을 result.txt로 변경
# 4. 결과는 화면이 아닌 result.txt에 저장
```

**4. 헷갈리기 쉬운 점**
가장 중요한 함정은 `>`와 `>>`의 차이입니다. `>`는 **기존 내용을 통째로 지우고** 새로 씁니다. 중요한 설정 파일에 `>`를 잘못 쓰면 내용이 사라져 복구가 어려우니, 추가하려는 의도라면 반드시 `>>`를 써야 합니다. 또한 일반 출력(`>`)과 에러 출력(`2>`)은 다른 통로라는 점도 주의하세요.

**5. 한 줄 정리**
`>`는 출력 방향을 파일로 돌리는 화살표이며, 덮어쓰기(`>`)와 이어쓰기(`>>`)를 반드시 구분해야 한다.

> 비유: 출력은 수도꼭지에서 나오는 물이다. 기본은 싱크대(화면)로 흐르지만, 호스(`>`)를 연결하면 양동이(파일)로 받을 수 있다. `>`는 양동이를 비우고 새로 받기, `>>`는 기존 물 위에 더 붓기다.

### grep과 정규표현식

**1. 정의**
**grep**은 텍스트에서 특정 패턴이 포함된 **줄만 골라 출력**하는 검색 명령어입니다. 이때 "어떤 패턴을 찾을지"를 표현하는 규칙이 **정규표현식(Regular Expression)** 입니다.

**2. 왜 필요한가?**
로그가 수만 줄이어도, "에러가 난 줄", "특정 사용자가 등장한 줄", "숫자가 들어간 줄"만 즉시 뽑아낼 수 있습니다. 데이터에서 신호를 걸러내는 가장 빠른 거름망입니다.

**3. 예시**
```bash
grep [0-9] a.txt       # a.txt에서 '숫자(0~9)'가 포함된 줄만 출력
ls | grep user01       # 목록 중 'user01'이 이름에 들어간 항목만 출력
```
여기서 `[0-9]`는 정규표현식으로 "0부터 9까지의 숫자 한 글자"를 의미합니다. 즉 grep은 패턴에 맞는 줄을 통째로 추려 줍니다.

**4. 헷갈리기 쉬운 점**
grep은 **줄(line) 단위**로 결과를 내보냅니다. `[0-9]`에 맞는 "숫자만" 뽑는 게 아니라, 숫자가 하나라도 들어간 **줄 전체**를 출력한다는 점을 기억하세요.

**5. 한 줄 정리**
grep은 "이 패턴이 들어간 줄을 다 보여 줘"라고 시키는 검색 명령이며, 패턴 언어가 정규표현식이다.

> 비유: grep은 형광펜이다. 책 한 권에서 특정 단어가 나온 문장(줄)에 전부 형광펜을 그어 따로 모아 주는 셈이다.

### 파이프(Pipe)

**1. 정의**
**파이프(`|`)** 는 둘 이상의 명령어를 묶어, 앞 명령어의 **표준 출력**을 뒤 명령어의 **표준 입력**으로 곧장 연결하는 기능입니다.

**2. 왜 필요한가?**
"목록을 뽑고 → 그중 특정 항목만 거르고 → 그 결과를 파일로 저장"하는 복잡한 작업을, 중간 파일 없이 한 줄로 처리할 수 있습니다. 작은 명령어들을 레고처럼 조립해 강력한 한 줄을 만드는 것이 리눅스의 진짜 힘입니다.

**3. 예시**
```bash
head a.txt | grep [0-9]
# 1. head로 a.txt의 첫 10줄을 출력
# 2. 그 출력을 | 를 통해 grep으로 전달
# 3. grep이 숫자가 포함된 줄만 골라 최종 출력
# 결과 예:
# 3 * 3 is 9
# 20190903
# Welcome 2 Elice!
```

**4. 헷갈리기 쉬운 점**
파이프(`|`)와 리다이렉션(`>`)을 혼동하기 쉽습니다. `|`는 출력을 **다른 명령어**로 넘기고, `>`는 출력을 **파일**로 보냅니다. 둘은 함께 쓸 수 있습니다.

**5. 한 줄 정리**
파이프는 명령어와 명령어를 잇는 컨베이어 벨트로, 앞의 결과를 뒤의 재료로 흘려보낸다.

> 비유: 파이프는 공장의 컨베이어 벨트다. 1번 기계가 만든 반제품을 곧바로 2번 기계에 넘겨 가공하듯, `ls`의 결과를 `grep`에 넘겨 거른다.

### 파이프 + 리다이렉션 조합

**1. 정의**
파이프로 명령어를 잇고, 그 최종 출력을 리다이렉션으로 파일에 저장하는 조합입니다.

**2. 왜 필요한가?**
"걸러낸 결과를 영구 보관"하는 가장 흔한 패턴입니다. 로그에서 특정 사용자 기록만 추려 보고용 파일로 남기는 식의 작업이 한 줄로 끝납니다.

**3. 예시**
```bash
ls | grep user02 > output.txt
# 1. ls로 현재 디렉토리의 파일/폴더명을 출력
# 2. 그 결과를 grep으로 넘겨 'user02'가 든 항목만 거름
# 3. 거른 결과를 화면이 아닌 output.txt에 저장

cat output.txt
# user02_20190807
# user02_20190813
# user02_20190818
# user02_20190830
# user02_20190910
# user02_20190924
```

**4. 헷갈리기 쉬운 점**
명령은 왼쪽에서 오른쪽으로 흐릅니다. `ls | grep user02 > output.txt`에서 마지막 `>`는 **grep의 최종 출력**을 저장하는 것이지, `ls`나 중간 결과를 저장하는 게 아닙니다.

**5. 한 줄 정리**
`명령 | 거르기 > 파일`은 "뽑고 → 거르고 → 저장"을 한 줄에 담는 황금 패턴이다.

### mount(마운트)

**1. 정의**
**mount**는 물리적인 저장 장치(USB, 외장 하드 같은 보조기억장치)를 특정 디렉토리에 **연결**해, 그 폴더로 접근하면 장치 내용을 쓸 수 있게 만드는 작업입니다.

**2. 왜 필요한가?**
윈도우는 USB를 꽂으면 자동으로 드라이브로 잡힙니다(PnP, Plug and Play). 하지만 리눅스는 이 자동 연결이 기본 동작하지 않는 경우가 많아, **직접 mount 해야** 장치를 쓸 수 있습니다. 서버에 새 디스크를 붙일 때 반드시 거치는 과정입니다.

**3. 예시**
```bash
mount [option] [device] [directory]
# option
#   -a : /etc/fstab에 명시된 파일 시스템을 마운트할 때
#   -t : 파일 시스템 유형 지정 (생략 시 /etc/fstab 참조)
#   -o : 추가 설정 적용 (여러 조건은 콤마(,)로 구분)

umount [device 또는 directory]   # 연결 해제(마운트 취소)
df                               # 현재 mount된 디스크 정보 출력
```

**4. 헷갈리기 쉬운 점**
연결을 끊는 명령은 `mount`가 아니라 **`umount`**(unmount, 'n'이 빠진 철자)입니다. 또한 `df`는 "지금 무엇이 어디에 마운트되어 있고 용량은 얼마인지"를 확인하는 점검용 명령으로, 마운트 작업과 짝을 이룹니다.

**5. 한 줄 정리**
mount는 물리 장치를 폴더에 연결하는 작업이고, `umount`로 끊고 `df`로 현황을 본다.

> 비유: mount는 외부 창고(USB)를 사무실의 특정 방(디렉토리) 문에 연결하는 것이다. 문을 열면 창고 물건을 쓰고, `umount`로 연결을 끊으면 다시 분리된다.

## 코드로 보기 — 로그에서 원하는 줄만 뽑아 저장하기

```bash
# 목표: 현재 폴더의 파일 중 'user02'가 든 것만 골라 output.txt로 남긴다
ls | grep user02 > output.txt

# 저장된 결과 확인
cat output.txt
# user02_20190807
# user02_20190813
# user02_20190818
# user02_20190830
# user02_20190910
# user02_20190924
```

**코드목적**
파이프(`|`)로 `ls`의 출력을 `grep`에 넘겨 특정 패턴만 거르고, 리다이렉션(`>`)으로 그 결과를 파일에 저장하는 — 리눅스의 대표적인 "조립형 한 줄"을 익히기 위한 예제입니다.

**해석**
`ls`가 만든 전체 목록 중 `grep user02`가 'user02'를 포함한 줄만 통과시키고, `> output.txt`가 그 최종 결과를 파일에 담습니다. 화면에는 아무것도 안 나오지만, `cat`으로 열어 보면 걸러진 6줄이 그대로 저장되어 있습니다.

**실무 연결**
서버 접속 로그에서 특정 IP만 추리기, 거대한 CSV에서 특정 키워드 행만 뽑아 보고용 파일 만들기, 에러 로그만 모아 일별로 쌓기 등 — 데이터 분석·운영 자동화의 일상 업무가 거의 이 패턴의 변주입니다.

## 헷갈리기 쉬운 포인트

- **`>` vs `>>`**: 덮어쓰기(내용 삭제 후 기록) vs 이어쓰기(끝에 추가). 실수 시 데이터 손실 위험.
- **`>` vs `|`**: 출력을 파일로 보내기 vs 출력을 다음 명령어로 넘기기.
- **일반 출력 vs 에러 출력**: `>`는 정상 결과, `2>`는 에러 메시지. 통로가 다르다.
- **mount vs umount**: 장치 연결 vs 연결 해제. 끊을 땐 `n` 없는 `umount`.

## 한 줄 정리

> 리눅스의 명령어는 입출력 흐름을 가진 부품이며, 리다이렉션(`>` `>>` `<`)으로 방향을 바꾸고 파이프(`|`)로 이어 붙여, `grep` 같은 거름망과 조립하면 한 줄로 강력한 데이터 처리가 완성된다.
