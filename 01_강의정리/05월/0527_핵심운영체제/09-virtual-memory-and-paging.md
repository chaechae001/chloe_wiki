# 가상 메모리와 페이징 — 실제보다 큰 메모리를 쓰는 마법

> "메모리가 부족해서 못 켜요"라는 말을 요즘은 잘 안 듣습니다. 실제 메모리는 한정돼 있는데도 큰 프로그램이 척척 돌아가죠. 그 비밀이 가상 메모리입니다.

`가상메모리` `논리주소` `물리주소` `페이징` `페이지테이블` `스와핑` `요구페이징` `캐시` `세그멘테이션`

## 핵심요약

- 가상 메모리는 "실제 물리적 주소가 아닌, 가상의 주소(논리적 주소)를 프로세스가 사용"하게 하는 기술이다.
- 덕분에 모든 프로세스가 고정된 주소를 가질 수 있고, 실제 주소는 OS만 접근해 리소스를 보호한다.
- 보조 기억 장치 일부를 메모리처럼 쓸 수 있어, 실제 메모리보다 큰 작업도 가능하다.
- **페이징**은 메모리를 일정 크기(페이지)로 잘라, 페이지 테이블로 가상↔실제 주소를 매핑하는 방식이다.
- **스와핑**은 안 쓰는 프로세스를 잠시 하드 디스크에 내려두는 것, **요구 페이징**은 당장 필요한 페이지만 메모리에 두는 것이다.
- 페이징은 일정 크기로 잘라 내부 단편화가 생기고, **세그멘테이션**은 역할 단위로 잘라 외부 단편화가 생긴다.

## 개념별 정리

### 가상 메모리가 필요한 이유

**1. 정의**
프로세스가 실제 물리 주소 대신 가상의 논리 주소를 쓰게 하는 메모리 관리 기법입니다.

**2. 왜 필요한가?**
프로세스가 실제 물리 주소를 직접 다루면 두 가지 문제가 생깁니다. 첫째, 잘못된 주소에 데이터를 쓰면 다른 프로세스나 시스템 영역을 망가뜨릴 수 있습니다. 둘째, 실제 메모리가 좁으면 큰 프로세스를 올릴 수 없습니다("너무 좁은데…"). 가상 메모리는 이 둘을 해결합니다.

**3. 예시**
실제 메모리가 시스템 영역과 프로세스 A·B로 꽉 차 있을 때, 프로세스 C가 들어가려면 자리가 부족합니다. 가상 메모리는 보조 기억 장치를 빌려 마치 자리가 있는 것처럼 처리합니다.

**4. 헷갈리기 쉬운 점**
가상 메모리는 "메모리를 진짜로 늘리는 것"이 아닙니다. 보조 기억 장치를 빌려 **있는 것처럼 보이게** 하는 것이라, 너무 많이 쓰면 느려집니다.

**5. 한 줄 정리**
가상 메모리는 "실제보다 더 큰 메모리가 있는 것처럼" 보이게 하는 기술입니다.

### 논리 주소와 물리 주소 (바인딩)

**1. 정의**
- **논리 주소**: 프로세스가 보는 가상의 주소(프로세스 시점).
- **물리 주소**: 실제 메모리의 주소.
- **바인딩**: 논리 주소를 물리 주소에 연결하는 작업.

**2. 왜 필요한가?**
프로세스마다 "0번부터 시작하는 깔끔한 주소 공간"을 쓰게 해 주면 프로그래밍이 단순해집니다. 실제로 어디에 놓일지는 OS가 바인딩으로 알아서 연결합니다.

**3. 예시 (이상 vs 현실)**
프로세스는 "0번부터 차곡차곡 쌓인 스택/힙/데이터/코드"를 본다고 가정(이상)하지만, 실제 메모리에서는 여기저기 흩어져 있을 수 있습니다(현실). 가상 메모리가 이 둘을 매끄럽게 이어 줍니다.

**4. 헷갈리기 쉬운 점**
프로세스가 보는 주소(논리)와 실제 위치(물리)는 다릅니다. 모든 프로세스가 "고정된 주소를 가질 수 있게" 보이는 것은 논리 주소 덕분입니다.

**5. 한 줄 정리**
프로세스는 깔끔한 논리 주소를 보고, OS는 그걸 실제 물리 주소에 몰래 연결해 줍니다.

### 페이징(Paging)과 페이지 테이블

**1. 정의**
- **페이지(Page)**: 물리 메모리와 가상 주소를 연결하는 단위. 보통 4KB 또는 8KB 크기로, 메모리를 이 단위로 나눠 씁니다.
- **페이지 테이블(Page table)**: 가상 메모리의 페이지와 물리 메모리를 매핑하는 표.

**2. 왜 필요한가?**
메모리를 일정 크기로 잘라 페이지 테이블에 매핑해 두면, 가상 주소를 실제 주소로 빠르게 변환할 수 있고 불연속 공간도 활용할 수 있습니다.

**3. 예시**
프로세스 A의 페이지들이 페이지 테이블을 거쳐 실제 메모리의 흩어진 칸들과 연결됩니다. 가상에서는 연속처럼 보여도 실제로는 여기저기 흩어져 있을 수 있습니다.

```mermaid
flowchart LR
    A[프로세스 A<br/>가상 페이지] --> T[페이지 테이블<br/>매핑표]
    T --> M[실제 메모리<br/>흩어진 칸들]
```

**4. 헷갈리기 쉬운 점**
페이지 테이블은 "주소를 변환하는 전화번호부"입니다. 프로세스가 가상 페이지 번호로 물으면, 테이블이 실제 어느 칸인지 알려줍니다.

**5. 한 줄 정리**
페이징은 메모리를 일정 크기로 잘라, 표(페이지 테이블)로 가상↔실제 주소를 잇는 방식입니다.

### 스와핑·요구 페이징·캐시

**1. 정의**
- **스와핑(swapping)**: 안 쓰는 프로세스를 잠시 하드 디스크에 내려두는 것.
- **요구 페이징(demand paging)**: 페이지 단위로 스와핑하여, 당장 필요한 페이지만 메모리에 남겨 두는 방법.
- **캐시(cache)**: 데이터나 값을 미리 복사해 두는 임시 장소.

**2. 왜 필요한가?**
메모리가 부족할 때 안 쓰는 것을 잠시 디스크로 내리면 더 많은 프로세스를 돌릴 수 있습니다. 다만 프로세스 단위로 통째 옮기면 비효율적이고 단편화가 생길 수 있어, 페이지 단위(요구 페이징)로 잘게 옮기는 방식이 발전했습니다. 캐시는 오래 걸리는 계산 결과를 미리 복사해 두어 시간을 아낍니다.

**3. 예시**
- 스와핑: 새 프로세스 D를 실행하려고 안 쓰는 A를 하드 디스크로 내려보냅니다.
- 캐시 비유: "손바닥에 메모하기" — 빠르게 확인하고 쓰고 지울 수 있지만, 손바닥에 들어갈 정도의 적은 내용만 담을 수 있습니다. 모든 데이터를 캐시에 넣을 수는 없습니다.

**4. 헷갈리기 쉬운 점**
스와핑(프로세스 단위)과 요구 페이징(페이지 단위)을 헷갈립니다. 요구 페이징은 "필요한 조각만" 메모리에 두므로 훨씬 효율적입니다. 또 실제 물리 메모리를 하드 디스크의 캐시처럼 쓰는 관점도 있습니다.

**5. 한 줄 정리**
안 쓰는 건 디스크로 내리고(스와핑/요구 페이징), 자주 쓸 건 가까이 복사해 둡니다(캐시).

### 세그멘테이션(Segmentation)과 결합 방식

**1. 정의**
- **페이징의 문제점**: 부위(역할)에 상관없이 일정한 크기로 자르기 때문에, 할당받고도 안 쓰는 공간(내부 단편화)이 생깁니다.
- **세그멘테이션**: 논리적으로 같은 역할을 하는 부분끼리 잘라 저장하는 방법.
- **페이징 + 세그멘테이션**: 부위별로 먼저 나눈 다음, 각 부위를 일정 크기대로 자르는 방법.

**2. 왜 필요한가?**
페이징은 칸을 일정하게 잘라 단순하지만, 의미 단위를 무시해 내부 단편화가 생깁니다. 세그멘테이션은 중요한 부분과 아닌 부분을 분리해 효율적으로 저장하고 내부 단편화 문제를 해결합니다.

**3. 예시**
꽃 그림을 일정 격자로 자르면(페이징) 의미와 상관없이 조각이 나뉘고, 꽃잎·줄기·잎처럼 의미 단위로 자르면(세그멘테이션) 같은 역할끼리 묶입니다. 같은 코드 영역은 하나만 저장하고 같은 곳을 가리키게 하면 중복도 줄일 수 있습니다.

**4. 헷갈리기 쉬운 점**
세그멘테이션은 내부 단편화는 해결하지만, **크기가 제각각이라 외부 단편화가 발생**합니다. 일반적으로 외부 단편화가 내부 단편화보다 훨씬 큰 공간을 낭비합니다. 그래서 둘을 결합해, 부위별로 나눈 뒤 각 부위를 페이징으로 자르는 방식을 씁니다(단, 테이블을 두 번 거쳐 조금 느려질 수 있음).

**5. 한 줄 정리**
페이징은 "일정 크기로", 세그멘테이션은 "역할 단위로", 결합 방식은 "역할로 나눈 뒤 일정 크기로" 자릅니다.

## 코드로 보기 — 페이징 vs 세그멘테이션

| 구분 | 페이징 | 세그멘테이션 |
| --- | --- | --- |
| 자르는 기준 | 일정한 크기 | 논리적 역할 단위 |
| 단편화 | 내부 단편화 발생 | 외부 단편화 발생 |
| 장점 | 관리 단순, 외부 단편화 적음 | 의미 단위 분리, 내부 단편화 해결 |

**코드목적**
두 방식이 무엇을 기준으로 자르고, 그 결과 어떤 단편화가 생기는지 비교합니다.

**해석**
"어느 쪽도 완벽하지 않다"가 핵심입니다. 페이징은 내부 단편화, 세그멘테이션은 외부 단편화를 떠안습니다. 그래서 둘을 결합해 약점을 보완합니다.

**실무 연결**
가상 메모리·페이징은 OS가 알아서 처리하지만, "왜 메모리를 많이 쓰면 갑자기 느려지는가(스와핑 과다)"를 이해하면 서버·머신러닝 작업에서 성능 문제를 진단하는 데 도움이 됩니다.

## 헷갈리기 쉬운 포인트

- **논리 주소 vs 물리 주소**: 프로세스가 보는 가상 주소 vs 실제 메모리 주소.
- **스와핑 vs 요구 페이징**: 프로세스 통째로 vs 필요한 페이지만.
- **페이징 vs 세그멘테이션**: 일정 크기(내부 단편화) vs 역할 단위(외부 단편화).
- **가상 메모리 ≠ 진짜 메모리 증설**: 보조 기억 장치를 빌려 있는 것처럼 보이게 함.

- (응용) 메모리를 과도하게 쓰면 시스템이 갑자기 느려지는 이유를 가상 메모리로 설명하면?
  → 부족한 메모리를 보충하려 디스크로의 스와핑이 잦아지는데, 디스크는 메모리보다 훨씬 느려 전체 속도가 떨어진다.

## 한 줄 정리

> 가상 메모리는 보조 기억 장치를 빌려 실제보다 큰 메모리가 있는 것처럼 보이게 하고, 페이징·세그멘테이션은 그 공간을 자르는 서로 다른 전략이다.
