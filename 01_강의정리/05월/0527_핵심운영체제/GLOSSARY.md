# 용어집 (GLOSSARY)

> 이 단원(협업 도구 + 운영체제) 전체에서 등장한 핵심 용어를 한곳에 모았습니다. 비전공자 눈높이의 쉬운 설명과 함께, 어느 글에서 다뤘는지·무엇과 같이 보면 좋은지를 정리했습니다.

| 용어 | 쉬운 설명 | 관련 강의명 | 함께 보면 좋은 개념 |
| --- | --- | --- | --- |
| 버전 관리 (Version Control) | 코드의 변경 이력을 기록하고 원하는 시점으로 되돌릴 수 있게 해 주는 방식 | 01. 버전 관리와 Git | Git, 원격 저장소 |
| Git | 대표적인 버전 관리 도구. 코드의 '되돌리기'와 협업을 가능하게 함 | 01. 버전 관리와 Git | 버전 관리, GitHub |
| GitHub | Git으로 관리하는 코드를 온라인에 올려 함께 보고 협업하는 서비스 | 01. 버전 관리와 Git | Git, 오픈소스 |
| 플로우차트 (Flowchart) | 서비스나 프로그램의 흐름을 도형과 화살표로 그린 설계도 | 02. 기획과 플로우차트 | 핵심 로직, UX |
| UX (사용자 편의성) | 사용자가 서비스를 얼마나 편하게 쓰는가에 대한 경험 | 02. 기획과 플로우차트 | 플로우차트, 프로토타입 |
| 오픈소스 (Open Source) | 누구나 보고 쓰고 기여할 수 있도록 공개된 소스 코드 | 03. 오픈소스 | 라이선스, GitHub |
| 라이선스 (License) | 공개된 코드를 어떤 조건으로 쓸 수 있는지 정한 사용 약속 | 03. 오픈소스 | 오픈소스 |
| 클라우드 (Cloud) | 실물 서버를 사지 않고 인터넷으로 빌려 쓰는 컴퓨팅 자원 | 04. 클라우드와 SaaS | SaaS, 컨테이너 |
| SaaS | 설치 없이 인터넷으로 바로 쓰는 소프트웨어 서비스 | 04. 클라우드와 SaaS | 클라우드 |
| 컨테이너 (Container) | 프로그램과 실행 환경을 한 상자에 담아 어디서나 똑같이 돌리는 기술 | 04. 클라우드와 SaaS | 클라우드 |
| 운영체제 (OS) | 컴퓨터 자원을 제어하고 프로그램을 실행해 주는 시스템 소프트웨어 | 05. 운영체제의 개념과 기능 | 자원(리소스), 프로세스 |
| 자원 (Resource) | CPU, 메모리, 저장장치처럼 운영체제가 나눠 주는 컴퓨터의 자산 | 05. 운영체제의 개념과 기능 | 운영체제, 스케줄링 |
| 프로그램 (Program) | 디스크에 저장된, 아직 실행되지 않은 명령어 묶음 | 06. 프로세스와 스레드 | 프로세스 |
| 프로세스 (Process) | 실행 중인 프로그램. 자기만의 메모리 공간을 가짐 | 06. 프로세스와 스레드 | 프로그램, 스레드 |
| 스레드 (Thread) | 한 프로세스 안에서 일을 나눠 동시에 처리하는 실행 흐름 | 06. 프로세스와 스레드 | 프로세스, 멀티스레딩 |
| 코드 영역 | 프로세스 메모리 중 실행할 명령어가 저장되는 영역 | 06. 프로세스와 스레드 | 데이터 영역, 스택, 힙 |
| 데이터 영역 | 전역 변수 등 프로그램이 쓰는 데이터가 저장되는 영역 | 06. 프로세스와 스레드 | 코드 영역, 정적 할당 |
| 스택 (Stack) | 함수 호출·지역 변수가 쌓였다 사라지는, 자동으로 관리되는 영역 | 06. 프로세스와 스레드 | 힙, 정적 할당 |
| 힙 (Heap) | 프로그램이 실행 중에 필요할 때 직접 할당받는 메모리 영역 | 06. 프로세스와 스레드 | 스택, 동적 할당 |
| 정적/동적 할당 | 미리 정해 두고 쓰는 방식(정적) vs 실행 중 필요할 때 받는 방식(동적) | 06. 프로세스와 스레드 | 스택, 힙 |
| 프로세스 상태 | 프로세스가 거치는 단계: 생성·준비·실행·대기·종료 | 07. 프로세스 상태와 스케줄링 | 스케줄링 |
| 멀티프로세싱 | 여러 프로세스를 동시에 돌려 작업을 나누는 방식 | 07. 프로세스 상태와 스케줄링 | 멀티스레딩, IPC |
| 멀티스레딩 | 한 프로세스 안에서 여러 스레드로 일을 나누는 방식 | 06. 프로세스와 스레드 | 스레드, 멀티프로세싱 |
| IPC (프로세스 간 통신) | 서로 다른 프로세스가 데이터를 주고받는 방법 | 07. 프로세스 상태와 스케줄링 | 메시지 큐, 공유 메모리, 소켓 |
| 메시지 큐 | 메시지를 줄 세워 주고받는 프로세스 간 통신 방식 | 07. 프로세스 상태와 스케줄링 | IPC, 공유 메모리 |
| 공유 메모리 | 여러 프로세스가 같은 메모리 공간을 함께 써서 통신하는 방식 | 07. 프로세스 상태와 스케줄링 | IPC, 소켓 |
| 소켓 (Socket) | 네트워크를 통해 프로세스끼리 데이터를 주고받는 통로 | 07. 프로세스 상태와 스케줄링 | IPC |
| 스케줄링 (Scheduling) | 여러 작업에 CPU를 언제·얼마나 줄지 정하는 운영체제의 교통정리 | 07. 프로세스 상태와 스케줄링 | FCFS, SJF, RR |
| FCFS / SJF / RR | 먼저 온 순서(FCFS), 짧은 작업 먼저(SJF), 시간을 돌아가며 나눔(RR) | 07. 프로세스 상태와 스케줄링 | 스케줄링 |
| 교착상태 (Deadlock) | 서로 상대의 자원을 기다리며 아무도 못 나아가는 멈춤 상태 | 07. 프로세스 상태와 스케줄링 | 기아상태, 자원 |
| 기아상태 (Starvation) | 우선순위에 밀려 특정 작업이 계속 자원을 못 받는 상태 | 07. 프로세스 상태와 스케줄링 | 교착상태, 스케줄링 |
| 메모리 할당/해제 | 프로그램에 메모리 공간을 내어 주고, 다 쓰면 회수하는 작업 | 08. 메모리 관리와 단편화 | 연속/불연속 할당 |
| 연속/불연속 할당 | 한 덩어리로 붙여 배치 vs 흩어서 배치하는 방식 | 08. 메모리 관리와 단편화 | 단편화, 페이징 |
| 고정/가변 분할 | 메모리를 같은 크기로 미리 나눔 vs 필요에 맞게 나눔 | 08. 메모리 관리와 단편화 | 내부/외부 단편화 |
| 내부/외부 단편화 | 칸 안에 남는 빈틈(내부) vs 칸 사이에 생기는 빈틈(외부) | 08. 메모리 관리와 단편화 | 고정/가변 분할 |
| 가상 메모리 (Virtual Memory) | 실제 메모리보다 큰 공간을 쓰는 것처럼 보이게 하는 기술 | 09. 가상 메모리와 페이징 | 페이징, 스와핑 |
| 논리/물리 주소 | 프로그램이 보는 주소(논리) vs 실제 메모리 주소(물리) | 09. 가상 메모리와 페이징 | 가상 메모리, 페이지 테이블 |
| 페이징 (Paging) | 메모리를 일정 크기 페이지로 잘라 흩어 배치하는 방식 | 09. 가상 메모리와 페이징 | 페이지 테이블, 세그멘테이션 |
| 페이지 테이블 | 논리 주소(페이지)를 실제 위치로 연결해 주는 변환표 | 09. 가상 메모리와 페이징 | 페이징, 논리/물리 주소 |
| 스와핑 (Swapping) | 당장 안 쓰는 메모리 내용을 디스크로 잠시 옮겨 두는 동작 | 09. 가상 메모리와 페이징 | 가상 메모리, 요구 페이징 |
| 요구 페이징 (Demand Paging) | 실제로 필요해질 때 그 페이지만 메모리로 불러오는 방식 | 09. 가상 메모리와 페이징 | 페이징, 스와핑 |
| 캐시 (Cache) | 자주 쓰는 데이터를 더 빠른 곳에 미리 담아 두는 임시 저장소 | 09. 가상 메모리와 페이징 | 가상 메모리 |
| 세그멘테이션 (Segmentation) | 메모리를 의미 단위(코드·데이터 등)로 나누어 관리하는 방식 | 09. 가상 메모리와 페이징 | 페이징 |
| 파일 (File) | 컴퓨터에서 정보를 담는 논리적인 저장 단위 | 10. 파일 시스템과 디스크 할당 | 파일 시스템, 메타데이터 |
| 파일 시스템 (File System) | 파일을 쉽게 읽고 쓰도록 관리해 주는 체계 | 10. 파일 시스템과 디스크 할당 | 파일, 디렉터리 |
| 메타데이터 (Metadata) | 파일 이름·크기·권한·시간 등 파일을 관리하기 위한 정보 | 10. 파일 시스템과 디스크 할당 | 파일, inode |
| 디렉터리 (Directory) | 파일들의 정보를 담은 특수한 파일(흔히 '폴더') | 10. 파일 시스템과 디스크 할당 | 파일 시스템 |
| HDD / SSD | 회전·헤드로 읽는 기계식 디스크(HDD) vs 전기식이라 빠른 저장장치(SSD) | 10. 파일 시스템과 디스크 할당 | 트랙/섹터 |
| 트랙/섹터 | 하드 디스크의 띠 모양 영역(트랙)과 최소 기억 단위(섹터) | 10. 파일 시스템과 디스크 할당 | HDD/SSD |
| 연속 할당 | 파일을 디스크에 앞에서부터 붙여 저장하는 방식 | 10. 파일 시스템과 디스크 할당 | 연결 할당, 색인 할당 |
| 연결 할당 | 각 칸이 다음 칸을 가리키는 포인터로 이어 저장하는 방식 | 10. 파일 시스템과 디스크 할당 | FAT, 색인 할당 |
| FAT | 다음 칸을 가리키는 포인터들을 한 표에 모아 직접 접근을 가능케 한 방식 | 10. 파일 시스템과 디스크 할당 | 연결 할당 |
| 색인 할당 | 파일의 블록 번호들을 인덱스 블록 한 칸에 모아 두는 방식 | 10. 파일 시스템과 디스크 할당 | inode, FAT |
| inode | 파일의 모든 정보(유형·권한·시간·저장 위치)를 담은 고유 번호의 정보 칸 | 11. 링크와 마운트 | 색인 할당, 심볼릭/하드 링크 |
| 심볼릭 링크 (Symbolic link) | 원본의 '경로'를 가리키는 바로가기. 별도 inode를 가짐 | 11. 링크와 마운트 | 하드 링크, inode |
| 하드 링크 (Hard link) | 원본과 '같은 inode'를 공유하는 바로가기 | 11. 링크와 마운트 | 심볼릭 링크, inode |
| 마운트 (Mount) | 물리 저장 장치를 특정 디렉터리에 연결해 운영체제가 쓰게 하는 작업 | 11. 링크와 마운트 | 파일 시스템, 디렉터리 |
