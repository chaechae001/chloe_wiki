# 주요 프로토콜 한눈에 — DNS·DHCP·TCP/UDP·FTP·SMTP·SSH·SSL/TLS

> 도메인 이름을 IP로 바꾸고, 주소를 자동으로 나눠 주고, 파일·메일을 전송하고, 원격 서버에 안전하게 접속하는 일 — 인터넷의 보이지 않는 일꾼들이 각자 맡은 프로토콜로 처리합니다.

`DNS` `DHCP` `TCP` `UDP` `핸드셰이크` `FTP` `SMTP` `SSH` `SSL/TLS`

## 핵심요약
- **DNS**는 도메인 이름(`example.com`)을 IP 주소로 바꿔 주는 "인터넷 전화번호부"다.
- **DHCP**는 IP·게이트웨이·DNS 주소를 자동으로 할당해 주는 프로토콜이다.
- **TCP**는 신뢰성 있는 연결형, **UDP**는 빠른 비연결형 — 용도가 다르다.
- TCP는 연결을 맺을 때 **3-way handshake**, 끊을 때 **4-way handshake** 를 거친다.
- **FTP/SFTP**는 파일 전송, **SMTP/POP3/IMAP**는 메일, **SSH**는 안전한 원격 접속을 담당한다.
- **SSL/TLS**는 데이터를 암호화하고, 여기에 HTTP를 더한 것이 **HTTPS**다.

---

## 인터넷의 길잡이 — IP · DNS · DHCP

### IP(Internet Protocol)의 성격
IP는 네트워크에서 정보를 수신·송신하는 통신 규약입니다. 세 가지 성격을 기억해 둡니다.

- **비신뢰성**: 데이터가 송신지까지 정확히 전달되도록 **보장하지는 않음**(그 보장은 전송 계층의 TCP가 담당).
- **비연결형**: TCP와 달리 연결 설정 과정 없이 데이터를 보냄.
- **주소 지정·경로 설정**: 각 기기를 식별하고(IP), 그 IP를 통해 라우팅 경로도 정함.

### DNS(Domain Name System)
**1. 정의**
DNS는 사람이 읽기 쉬운 **도메인 이름을 컴퓨터가 쓰는 IP 주소로 변환**해 주는 시스템입니다. **인터넷의 전화번호부**에 비유됩니다.

**2. 왜 필요한가?**
우리는 `216.3.123.12` 같은 숫자가 아니라 `example.com` 같은 이름을 기억합니다. DNS가 그 이름을 IP로 바꿔 줘야 실제 접속이 됩니다.

**3. 예시 — DNS 조회 단계**
```text
1. 웹 브라우저에 도메인 이름으로 요청
2. DNS 서버에서 TLD 서버에 IP 주소 요청
3. TLD 서버에서 IP 주소를 응답
4. DNS 서버에서 (브라우저로) IP 주소를 응답
```
질의 방식은 두 가지입니다.
- **재귀적 질의**: Local DNS가 대신 위→아래로 끝까지 찾아 **최종 IP를 한 번에** 돌려줌.
- **반복적 질의**: Local DNS가 최상위부터 하나씩 직접 물어 가며 응답을 받음.

**4. 헷갈리기 쉬운 점**
"인터넷이 느린데 사이트는 IP로 치면 빨리 뜬다"면 DNS 조회 단계의 지연일 수 있습니다. DNS는 **접속 그 자체가 아니라 "이름 → 주소 변환"** 만 담당한다는 점을 기억하세요.

**5. 한 줄 정리**
DNS는 이름을 주소로 바꿔 주는 인터넷 전화번호부다.

> 비유: 친구 이름(도메인)을 누르면 저장된 전화번호(IP)로 연결되는 휴대폰 주소록과 같습니다.

---

### DHCP(Dynamic Host Configuration Protocol)
**1. 정의**
DHCP는 **IP 주소·게이트웨이·네임서버(DNS) 주소 등을 자동으로 할당**해 주는 프로토콜입니다.

**2. 왜 필요한가?**
새 기기마다 사람이 IP를 일일이 손으로 지정하면 번거롭고 충돌도 납니다. DHCP가 비어 있는 주소를 자동으로 빌려줘서 편리합니다.

**3. 예시 — DHCP 동작원리(4단계)**
```text
PC                          DHCP 서버
 │── DHCP Discover ───────▶  "DHCP 서버 있나요? 네트워크 정보가 필요합니다."
 │◀── DHCP Offer ──────────  "제가 드릴 수 있는 IP와 정보는 이겁니다."
 │── DHCP Request ────────▶  "그 네트워크 정보를 사용할게요."
 │◀── DHCP Ack ────────────  "네, 해당 정보로 사용하세요."
```
할당 방식은 수동(Manual)·자동(Automatic)·동적(Dynamic)이 있고, 그중 **동적 할당**은 제한된 수의 IP를 빌려주는 기간(lease) 동안만 쓰고 회수해 재활용합니다.

**4. 헷갈리기 쉬운 점**
DHCP가 IP를 "영구히 주는 것"이 아닙니다. 동적 할당은 임대 기간이 끝나면 주소를 회수합니다. 그래서 공유기를 재시작하면 기기의 IP가 바뀌기도 합니다.

**5. 한 줄 정리**
DHCP는 네트워크 접속에 필요한 주소들을 자동으로 빌려준다.

> 비유: 카페 자리(IP)를 손님이 올 때마다 자동 배정하고, 떠나면 비우는 안내원과 같습니다.

## 빠름이냐 신뢰냐 — TCP와 UDP

### TCP(Transmission Control Protocol)
**1. 정의**
TCP는 컴퓨터가 다른 컴퓨터와 **신뢰성 있는** 통신을 하기 위한 연결형 통신 규약입니다.

**2. 왜 필요한가?**
파일 다운로드·결제처럼 **한 글자도 틀리면 안 되는** 통신은, 빠짐없이·순서대로·오류 없이 도착해야 합니다. TCP가 이를 보장합니다.

**3. 예시 — 3-way / 4-way handshake**
```text
[연결 맺기 — 3-way handshake]
USER ── 1. SYN ─────▶ SERVER     "연결할래? 괜찮니?"
USER ◀── 2. SYN/ACK ─ SERVER     "응, 나도 괜찮아."
USER ── 3. ACK ─────▶ SERVER     "그럼 연결하자."

[연결 끊기 — 4-way handshake]
USER ── 1. FIN ─────▶ SERVER
USER ◀── 2. ACK ───── SERVER
USER ◀── 3. FIN ───── SERVER
USER ── 4. ACK ─────▶ SERVER
```

**4. 헷갈리기 쉬운 점**
연결을 맺을 땐 3번, 끊을 땐 4번 주고받습니다. 끊을 때 한 번 더 많은 이유는, 한쪽이 "끝낼게(FIN)"를 보내도 상대는 보내던 데이터를 마저 처리한 뒤 따로 "나도 끝(FIN)"을 보내야 하기 때문입니다.

**5. 한 줄 정리**
TCP는 악수(handshake)로 연결을 확실히 맺고 끊는, 신뢰의 프로토콜이다.

> 비유: 전화 통화 — "여보세요? 들려요? 네 들려요"로 연결을 확인하고 시작합니다.

### UDP(User Datagram Protocol)
**1. 정의**
UDP는 컴퓨터가 다른 컴퓨터와 **빠르게** 통신하기 위한 비연결형 통신 규약입니다.

**2. 왜 필요한가?**
실시간 스트리밍·게임·음성 통화처럼 **약간의 손실보다 지연이 더 치명적인** 통신은, 연결 확인 절차 없이 일단 빠르게 보내는 게 유리합니다.

**3. 예시 — TCP vs UDP**

| 구분 | TCP | UDP |
| --- | --- | --- |
| 연결 방식 | 연결형 | 비연결형 |
| 전송 순서 | 순서 보장 | 순서 보장 X |
| 수신 여부 확인 | O | X |
| 통신 방식 | 1:1 | 1:1, 1:N, N:N |
| 신뢰성 | 높다 | 낮다 |
| 속도 | 느리다 | 빠르다 |

**4. 헷갈리기 쉬운 점**
UDP가 "오류를 전혀 안 본다"는 아닙니다. UDP 헤더의 CheckSum 필드로 **최소한의 오류만** 검출합니다. 다만 재전송·순서 보장은 하지 않습니다.

**5. 한 줄 정리**
정확함이 중요하면 TCP, 빠름이 중요하면 UDP.

> 비유: TCP는 등기우편(수령 확인), UDP는 일반우편(빠르지만 확인 없음).

## 파일과 메일, 그리고 원격 접속

### FTP / SFTP — 파일 전송
**FTP(File Transfer Protocol)** 는 인터넷을 통해 한 컴퓨터에서 다른 컴퓨터로 파일을 전송하는 프로토콜입니다. TCP 기반이라 처음에 3-way handshake를 거치며, **21번 포트로 신호·명령 제어**를, **20번 포트로 실제 데이터 전송**을 합니다.

| 종류 | 특징 |
| --- | --- |
| FTP | ID·Password 인증, TCP로 데이터 송수신 |
| TFTP | 인증 없이 UDP 기반으로 빠르게 송수신, 69번 포트 |
| SFTP | 전송 구간을 암호화해 기밀성 제공 |

**SFTP(Secure File Transfer Protocol)** 는 **SSH(시큐어 셸)** 의 데이터 스트림을 통해 파일을 전송하는, 보안이 강화된 별도의 프로토콜입니다. FTP와 비교하면 보안성이 높고, 방화벽에 안정적이며, 단일 포트만 사용해 관리가 쉽습니다.

> FTP 모드도 알아 두면 좋습니다. **능동 모드(Active)** 는 서버가 능동적으로 연결을 시도하고, **수동 모드(Passive)** 는 서버가 듣기만 하고 클라이언트가 데이터·명령 채널을 모두 엽니다(방화벽 환경에서 유리).

### SMTP / POP3 / IMAP — 메일
**SMTP(Simple Mail Transfer Protocol)** 는 네트워크를 통해 **전자우편을 전송(보내기)** 하는 프로토콜입니다. 메일은 MUA(사용자 프로그램) → MSA → MTA → MDA → 수신자로 흐르며 전달됩니다.

| 프로토콜 | 역할 |
| --- | --- |
| **SMTP** | 이메일 클라이언트에서 서버로 메일을 **보내는** 데 사용 |
| **IMAP** | 수신 서버에서 메일을 **관리·검색**(원격 보관, 여러 기기 동기화) |
| **POP3** | 서버에서 클라이언트로 메일을 **내려받는** 방법 |

쉽게 나누면 **보낼 때 SMTP, 받을 때 IMAP/POP3**입니다. IMAP은 서버에 두고 여러 기기에서 보기, POP3는 내 PC로 내려받기에 가깝습니다.

### TELNET / SSH — 원격 접속
**TELNET**은 원격 컴퓨터에 접속해 서비스를 받는 인터넷 표준 프로토콜이지만 **암호화가 없어** 보안에 취약합니다. 그래서 오늘날엔 **SSH**를 씁니다.

**SSH(Secure Shell)** 는 원격 호스트에 접속하기 위한 **보안 프로토콜**입니다. 특징은 다음과 같습니다.
- 모든 데이터 암호화 보장, 트래픽 압축으로 더 빠른 전송 효율.
- **22번 포트** 사용.
- **Public Key(공개키)** 와 **Private Key(개인키)** 를 사용. 사용자와 서버가 각자 키를 보유하고, 이 키로 연결 상대를 인증하며 안전하게 데이터를 주고받습니다.

> 원격 서버를 다룰 때 가장 자주 쓰는 도구가 SSH입니다. 로컬(내 PC) ↔ 원격(서버)을 안전하게 잇는 통로라고 기억하면 됩니다. (맥/리눅스는 기본 ssh, 윈도우는 별도 클라이언트를 사용하기도 합니다.)

## 데이터를 잠그는 자물쇠 — SSL/TLS와 HTTPS

**SSL(Secure Sockets Layer)** 은 암호화 기반 인터넷 보안 프로토콜이고, **TLS(Transport Layer Security)** 는 그 **더 안전한 후속 버전**입니다(오늘날 실제로 쓰이는 건 대부분 TLS).

두 프로토콜의 공통 역할:
- 웹에서 전송되는 데이터를 **암호화**.
- 클라이언트와 서버 간 **핸드셰이크로 상대를 인증**.
- 데이터에 **디지털 서명**을 더해, 도착 전에 조작됐는지 **무결성**을 확인.

그리고 **HTTPS(HTTP Secure)** 는 한마디로 **HTTP + SSL/TLS** 입니다. 평문으로 오가던 HTTP에 암호화 한 겹을 씌워 데이터 유출을 막습니다.

```text
[ HTTPS = HTTP + SSL/TLS ]

Application Layer  │  HTTP
SSL/TLS Layer      │  Handshake / Record Layer (암호화·인증)
Transport Layer    │  TCP/IP
```

> 주소창의 `https`와 자물쇠 아이콘이 바로 이 TLS가 적용됐다는 표시입니다.

## 코드로 보기 — 도메인을 IP로, 그리고 안전한 원격 접속

```bash
# 1) DNS 조회: 도메인 → IP (이름을 주소로 바꾸는 일)
$ nslookup example.com
Name:    example.com
Address: 93.184.216.34        # ← DNS가 돌려준 IP

# 2) SSH: 원격 서버에 안전하게 접속 (22번 포트, 키 기반 인증)
$ ssh user@93.184.216.34
# → 공개키/개인키로 서로를 인증한 뒤, 암호화된 통로가 열림

# 3) SFTP: 그 보안 통로로 파일 전송
$ sftp user@93.184.216.34
sftp> put report.pdf          # 파일 업로드(암호화된 채로)
```

**코드목적**
"이름으로 주소를 찾고(DNS) → 그 주소의 서버에 안전하게 접속하고(SSH) → 파일을 보내는(SFTP)" 실무에서 매우 흔한 흐름을 한 화면에 모았습니다.

**해석**
`nslookup`은 DNS의 "이름 → IP 변환"을 직접 보여 줍니다. `ssh`는 키 기반 인증으로 암호화된 원격 셸을 열고, `sftp`는 그 SSH 통로 위에서 파일을 안전하게 옮깁니다. 일반 FTP였다면 평문이라 도청 위험이 있지만, SFTP는 암호화되어 안전합니다.

**실무 연결**
서버에 코드를 배포하거나 로그를 확인할 때 거의 매번 거치는 과정입니다. "왜 ftp가 아니라 sftp를 쓰는가?", "왜 22번 포트인가?"에 답할 수 있다면 인프라 기본기가 갖춰진 것입니다.

## 직접 해보기
1. 좋아하는 사이트 도메인을 `nslookup`(또는 온라인 DNS 조회 도구)으로 조회해 IP를 확인해 보기.
2. "실시간 게임의 위치 정보"와 "은행 이체"는 각각 TCP/UDP 중 무엇이 어울리는지 고르고 이유 적기.
3. SMTP·IMAP·POP3를 "보내기/받기" 기준으로 분류해 보기.

## 헷갈리기 쉬운 포인트
- **TCP vs UDP**: 신뢰·순서 보장(느림) vs 빠름(보장 약함).
- **3-way vs 4-way**: 연결 맺기(3번) vs 연결 끊기(4번).
- **DNS vs DHCP**: 이름→IP 변환 vs IP 자동 할당.
- **FTP vs SFTP**: 평문 전송(취약) vs SSH 기반 암호화(안전).
- **SMTP vs IMAP/POP3**: 보내기 vs 받기.
- **SSL vs TLS vs HTTPS**: 암호화 프로토콜 / 그 개선판 / HTTP에 그걸 씌운 것.

- [ ] DHCP의 4단계(Discover–Offer–Request–Ack)를 떠올릴 수 있다.
- [ ] TCP와 UDP의 차이를 3가지 이상 말할 수 있다.
- [ ] 3-way와 4-way handshake가 각각 언제 쓰이는지 안다.
- [ ] FTP와 SFTP, SMTP와 IMAP/POP3의 역할을 구분할 수 있다.
- [ ] SSL/TLS와 HTTPS의 관계를 설명할 수 있다.

**복습 질문 및 답변**

- (기본) 도메인 이름을 IP 주소로 바꿔 주는 프로토콜은 무엇인가요?
  - DNS(Domain Name System)입니다.
- (이해확인) TCP가 연결을 끊을 때 4-way handshake를 쓰는 이유는?
  - 한쪽이 종료(FIN)를 알려도 상대는 남은 데이터를 처리한 뒤 따로 종료(FIN)를 보내야 하므로, 확인(ACK)까지 합쳐 총 4번을 주고받습니다.
- (응용) 사내 서버에 파일을 올려야 하는데 보안이 중요합니다. FTP와 SFTP 중 무엇을, 왜 선택할까요?
  - SFTP. SSH 기반으로 전송 구간을 암호화해 도청·변조 위험이 낮고, 단일 포트로 방화벽 환경에서도 안정적이기 때문입니다.

## 한 줄 정리
> 인터넷은 DNS(이름→주소)·DHCP(주소 자동 배분)·TCP/UDP(신뢰 vs 속도)·FTP/SMTP/SSH(파일·메일·원격)·SSL/TLS(암호화)라는 일꾼들이 각자 맡은 일을 해내며 굴러간다.
