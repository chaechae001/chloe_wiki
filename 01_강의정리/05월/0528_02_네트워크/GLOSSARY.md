# 용어집 (GLOSSARY)

이 강의에서 처음 나오는 용어를 비전공자 눈높이로 정리했습니다. 글을 읽다 막히면 여기서 찾아보세요.

| 용어 | 쉬운 설명 | 관련 강의명 | 함께 보면 좋은 개념 |
| --- | --- | --- | --- |
| 네트워크(Network) | 두 대 이상의 컴퓨터를 이어 데이터를 주고받게 하는 통신망 | ① 네트워크의 기초 | 노드, 인터넷 |
| 노드(Node) | 통신에 참여하는 각각의 장치·지점(PC, 휴대폰 등) | ① 네트워크의 기초 | 네트워크, 토폴로지 |
| 토폴로지(Topology) | 노드를 어떤 모양으로 연결했는지의 구조(Star·Bus·Ring·Mesh) | ① 네트워크의 기초 | 노드, 라우터 |
| 광섬유 케이블 | 레이저로 통신해 구리선보다 장거리·고속인 유선 매체. 해저 케이블에 사용 | ① 네트워크의 기초 | 동축·이더넷 케이블 |
| 감쇠 현상 | 신호 에너지가 마찰·열 등으로 줄어드는 현상 | ① 네트워크의 기초 | 무선 통신, 마이크로파 |
| PAN/LAN/MAN/WAN | 연결 범위에 따른 네트워크 종류(개인→지역→도시→광역) | ① 네트워크의 기초 | 인터넷, 와이파이 |
| 유니/멀티/브로드캐스트 | 한 번에 1:1 / 1:N / 전체에게 보내는 통신 방식 | ① 네트워크의 기초 | MAC 주소, 프레임 |
| 라우터(Router) | 네트워크 간 최적 경로로 데이터를 전달하는 장치 | ① 네트워크의 기초 | 라우팅, 포워딩 |
| 라우팅 vs 포워딩 | 길을 정하는 과정(라우팅) vs 그 길로 실제 내보내는 동작(포워딩) | ① 네트워크의 기초 | 라우터, 패킷 |
| 패킷(Packet) | 네트워크가 전달하는, 데이터를 잘게 나눈 형식화된 블록 | ① 네트워크의 기초 | 캡슐화, IP |
| IP 주소 | 네트워크에서 쓰는 내 컴퓨터의 주소(논리 주소, 바뀔 수 있음) | ② IP 주소와 계층 모델 | MAC 주소, 서브넷 |
| MAC 주소 | 장치(랜카드)에 새겨진 물리적 고유 주소(잘 안 바뀜) | ② IP 주소와 계층 모델 | IP 주소, 프레임 |
| 네트워크 ID / 호스트 ID | IP에서 "어느 네트워크인가 / 그 안 어떤 기기인가"를 나눈 두 부분 | ② IP 주소와 계층 모델 | 서브넷 마스크 |
| 서브넷 마스크 | IP에서 어디까지가 네트워크 ID인지 표시해 주는 값 | ② IP 주소와 계층 모델 | 서브넷, CIDR |
| IPv4 / IPv6 | 32비트(약 43억 개) / 128비트 IP 주소 체계 | ② IP 주소와 계층 모델 | NAT, 사설 IP |
| 사설 IP / 공인 IP | 내부 통신용(중복 가능) / 인터넷용(중복 불가, ISP 할당) | ② IP 주소와 계층 모델 | NAT, ISP |
| NAT | 내부 사설 IP를 하나의 공인 IP로 바꿔 트래픽을 주고받는 기술 | ② IP 주소와 계층 모델 | 사설 IP, 보안 |
| OSI 7계층 | 통신 과정을 7단계로 나눈 표준 지도 | ② IP 주소와 계층 모델 | TCP/IP 4계층 |
| TCP/IP 4계층 | OSI를 실무에 맞게 4단계로 압축한 모델 | ② IP 주소와 계층 모델 | OSI 7계층 |
| 프로토콜(Protocol) | 통신에 필요한 형식·약속·규칙을 정의한 것 | ③ 인터넷과 HTTP | 네트워크 아키텍처 |
| 캡슐화 / 역캡슐화 | 보낼 때 계층마다 헤더를 덧붙임 / 받을 때 벗겨 냄 | ③ 인터넷과 HTTP | 계층 모델, 패킷 |
| HTTP | 웹에서 데이터를 주고받는 무상태·클라이언트–서버 프로토콜 | ③ 인터넷과 HTTP | 상태코드, 메서드 |
| 무상태(Stateless) | 서버가 이전 요청 상태(로그인 등)를 기억하지 않는 성질 | ③ 인터넷과 HTTP | 쿠키, 세션 |
| HTTP 메서드 | GET·POST·PUT·DELETE — 서버에 요청하는 동작 | ③ 인터넷과 HTTP | CRUD |
| CRUD | 데이터 처리의 기본 4동작: 생성·조회·수정·삭제 | ③ 인터넷과 HTTP | HTTP 메서드 |
| 상태코드(Status Code) | 응답 상태를 알리는 숫자(2xx 성공·4xx 클라이언트·5xx 서버 오류) | ③ 인터넷과 HTTP | HTTP, 요청/응답 |
| 출처(Origin) | 프로토콜+호스트+포트의 묶음. 세 가지가 같아야 같은 출처 | ③ 인터넷과 HTTP | SOP, CORS |
| SOP | 같은 출처에서만 요청·응답을 허용하는 기본 보안 정책 | ③ 인터넷과 HTTP | CORS, 출처 |
| CORS | 다른 출처 간에도 안전하게 요청을 허용하는 정책 | ③ 인터넷과 HTTP | SOP, Preflight |
| DNS | 도메인 이름을 IP 주소로 바꿔 주는 "인터넷 전화번호부" | ④ 주요 프로토콜 | 도메인, IP 주소 |
| DHCP | IP·게이트웨이·DNS 주소를 자동으로 할당해 주는 프로토콜 | ④ 주요 프로토콜 | IP 주소, 임대(lease) |
| TCP / UDP | 신뢰성 있는 연결형(느림) / 빠른 비연결형(보장 약함) | ④ 주요 프로토콜 | handshake, 포트 |
| 3-way / 4-way handshake | TCP 연결을 맺는(3번)·끊는(4번) 패킷 교환 절차 | ④ 주요 프로토콜 | TCP, SYN/ACK |
| FTP / SFTP | 파일 전송 프로토콜 / SSH 기반 암호화 파일 전송 | ④ 주요 프로토콜 | TCP, SSH |
| SMTP / POP3 / IMAP | 메일 보내기 / 내려받기 / 서버에서 관리·동기화 | ④ 주요 프로토콜 | 전자우편 |
| TELNET / SSH | 원격 접속(암호화 X) / 안전한 원격 접속(22번 포트) | ④ 주요 프로토콜 | 공개키·개인키 |
| SSL / TLS | 데이터를 암호화·인증하는 보안 프로토콜(TLS가 개선판) | ④ 주요 프로토콜 | HTTPS, 핸드셰이크 |
| HTTPS | HTTP + SSL/TLS. 암호화된 안전한 웹 통신 | ④ 주요 프로토콜 | HTTP, TLS |
| 인증(Authentication) | 사용자의 신원을 확인하는 과정("누구인가") | ⑤ 웹 보안과 인증 | 인가, 토큰 |
| 인가(Authorization) | 인증된 사용자의 접근 권한을 확인("무엇을 할 수 있나") | ⑤ 웹 보안과 인증 | 인증, 액세스 토큰 |
| 암호화 / 복호화 | 알아볼 수 없게 바꾸기 / 다시 되돌리기 | ⑤ 웹 보안과 인증 | 대칭키·공개키, 해시 |
| 해시(Hash) | 임의 길이 데이터를 고정 길이로 바꾸는 단방향(복원 불가) 변환 | ⑤ 웹 보안과 인증 | SHA, 무결성 |
| 단방향성 | 입력→해시값은 쉽지만, 해시값→입력은 불가능한 성질 | ⑤ 웹 보안과 인증 | 해시, 비밀번호 저장 |
| 무결성(Integrity) | 데이터가 전송 중 변조되지 않았음 | ⑤ 웹 보안과 인증 | 해시, 디지털 서명 |
| 쿠키(Cookie) | 서버가 브라우저에 저장하는 작은 데이터(클라이언트 저장) | ⑤ 웹 보안과 인증 | 세션, 무상태 |
| 세션(Session) | 사용자 정보를 서버에 저장하는 방식(고유 Session ID 부여) | ⑤ 웹 보안과 인증 | 쿠키, 오버헤드 |
| 오버헤드(Overhead) | 어떤 처리를 위해 추가로 드는 시간·메모리 등의 부담 | ⑤ 웹 보안과 인증 | 세션, 서버 자원 |
| 토큰(Token) | 클라이언트를 구별하기 위한 유니크한 암호화 데이터 | ⑤ 웹 보안과 인증 | JWT, 인증 |
| JWT | 권한용 토큰. Header·Payload·Signature 세 부분 구조 | ⑤ 웹 보안과 인증 | 토큰, Refresh Token |
| Access / Refresh Token | 짧은 만료의 접근 토큰 / 그것을 재발급해 주는 긴 만료 토큰 | ⑤ 웹 보안과 인증 | JWT, 보안 |
| 캐시(Cache) / 캐싱 | 자주 쓰는 데이터의 복사본을 가까운 곳에 두는 저장소·기법 | ⑤ 웹 보안과 인증 | CDN, 쿠키 |
| CDN | 전 세계 캐시 서버로 콘텐츠를 빠르고 안정적으로 전달하는 기술 | ⑤ 웹 보안과 인증 | 캐시, SPOF |
| SPOF(단일 장애점) | 한 곳이 고장 나면 전체가 멈추는 취약 지점 | ⑤ 웹 보안과 인증 | CDN, 이중화 |
