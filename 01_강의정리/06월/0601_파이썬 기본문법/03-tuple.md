# 튜플 — 바뀌면 안 되는 값 묶기

> 좌표 (위도, 경도)나 요일 번호처럼 "절대 바뀌면 안 되는" 값을 리스트에 담으면 누군가 실수로 고칠 수 있습니다. 한 번 만들면 잠기는 자료형이 튜플입니다.

`튜플` · `불변성` · `immutable` · `소괄호` · `시퀀스`

## 핵심요약

- 튜플은 여러 값을 묶는 자료형으로, 소괄호 `()`로 만든다.
- 가장 큰 특징은 **불변(immutable)**: 한 번 만들면 추가·삭제·수정이 불가능하다.
- 리스트와 공통점: 인덱싱·슬라이싱·`in`·`len`·`+`·`*`가 모두 가능하다(튜플도 시퀀스).
- 리스트와 차이점: 내용 변경이 안 되므로 `append`·`remove`·값 대입이 모두 에러.
- 원소가 1개인 튜플은 `(1,)`처럼 **쉼표를 반드시** 붙여야 한다.
- "값이 바뀌면 안 되는 데이터"를 안전하게 보관할 때 리스트 대신 튜플을 고른다.

## 개념 정리

### 튜플의 생성과 시퀀스 기능

**1. 정의**
소괄호로 여러 값을 묶은 자료형. 순서가 있으므로 리스트·문자열과 마찬가지로 인덱싱·슬라이싱이 되고, `in`·`len`·`+`·`*`도 그대로 동작한다.

**2. 왜 필요한가?**
"이 묶음은 처음부터 끝까지 변하지 않아야 한다"는 의도를 코드에 명확히 새길 수 있다. 실수로 값을 바꾸는 사고를 원천 차단하고, 읽는 사람에게 "이건 고정값"이라는 신호를 준다.

**3. 예시**
```python
tuple_zero   = ()
tuple_one    = (1,)           # 원소 1개 → 반드시 쉼표!
tuple_sample = (1, 2, 3, 4, 5)
print(tuple_sample)           # (1, 2, 3, 4, 5)
print(type(tuple_sample))     # <class 'tuple'>

my_tuple = ("A", "C", "E")
print(my_tuple[1])            # C        (인덱싱)
print(my_tuple[:2])           # ('A', 'C') (슬라이싱)
print("A" in my_tuple)        # True
print(len(my_tuple))          # 3
print(("G", "O") + ("O", "D"))  # ('G', 'O', 'O', 'D')
print(("G", "O") * 3)           # ('G', 'O', 'G', 'O', 'G', 'O')
```

**4. 헷갈리기 쉬운 점**
`(1)`은 튜플이 아니라 그냥 숫자 1이다(괄호는 계산 묶음으로 해석됨). 원소가 하나뿐인 튜플은 반드시 `(1,)`처럼 쉼표를 붙여야 한다.

**5. 한 줄 정리**
튜플은 리스트와 거의 같지만, 만든 뒤에는 못 바꾸는 묶음이다.

### 튜플의 불변성(immutable)

**1. 정의**
튜플은 새 원소 추가, 기존 원소 삭제·변경이 불가능하다. 시도하면 에러가 난다.

**2. 왜 필요한가?**
딕셔너리의 Key처럼 "변하면 안 되는 자리"에 쓸 수 있고, 여러 사람이 함께 쓰는 코드에서 데이터가 의도치 않게 바뀌는 것을 막는다.

**3. 예시**
```python
my_tuple = ("e", "l", "i", "c", "e")
try:
    my_tuple[1] = "ERROR"   # 튜플은 원소 변경 불가!
except TypeError as e:
    print("에러 발생:", e)
# 에러 발생: 'tuple' object does not support item assignment
```

리스트와 비교하면 차이가 분명하다.
```python
my_list  = [1, 2, 3]     # 리스트: 변경 가능(mutable)
my_tuple = (1, 2, 3)     # 튜플: 변경 불가(immutable)

my_list[0] = 99
print("리스트 변경 후:", my_list)   # [99, 2, 3]

try:
    my_tuple[0] = 99
except TypeError:
    print("튜플은 변경 불가!")
# 리스트 변경 후: [99, 2, 3]
# 튜플은 변경 불가!
```

**4. 헷갈리기 쉬운 점**
튜플을 "억지로" 바꾸려고 리스트로 바꿨다가 다시 튜플로 되돌리는 방식은 권장하지 않는다. 그렇게 자주 바꿔야 하는 데이터라면 애초에 리스트를 쓰는 게 맞다. 자료형 선택은 "이 값이 바뀔 것인가"라는 질문으로 결정한다.

**5. 한 줄 정리**
튜플의 불변성은 "한 번 정하면 못 고친다"는 안전장치다.

> 비유: 리스트가 연필로 쓴 메모(지우고 고침)라면, 튜플은 도장으로 찍은 인감(한 번 찍으면 고정).

## 코드로 보기 — 불변성 직접 확인하기

```python
my_list  = [1, 2, 3]     # 변경 가능
my_tuple = (1, 2, 3)     # 변경 불가

my_list[0] = 99
print("리스트 변경 후:", my_list)   # [99, 2, 3]

try:
    my_tuple[0] = 99
except TypeError:
    print("튜플은 변경 불가!")
# 리스트 변경 후: [99, 2, 3]
# 튜플은 변경 불가!
```

**코드목적**
같은 값을 리스트와 튜플에 각각 담고, 첫 원소를 바꿔 보며 두 자료형의 차이를 눈으로 확인한다.

**해석**
리스트는 `my_list[0] = 99`가 그대로 적용돼 `[99, 2, 3]`이 된다. 튜플은 같은 시도에서 `TypeError`가 발생하는데, `try/except`로 그 에러를 잡아 "튜플은 변경 불가!"를 대신 출력했다. 에러가 나는 것이 정상 동작임을 안전하게 보여 주는 코드다.

**실무 연결**
설정값, 좌표, RGB 색상값(255, 255, 255)처럼 "묶음이지만 절대 변하지 않아야 하는" 데이터를 다룰 때 튜플을 쓰면 버그를 사전에 막을 수 있다. 함수가 여러 값을 한 번에 돌려줄 때도 보통 튜플 형태로 반환된다.

## 헷갈리기 쉬운 포인트

- **리스트 vs 튜플**: 둘 다 순서 있는 묶음이지만 리스트는 `[]`·변경 가능, 튜플은 `()`·변경 불가. "바뀔 데이터면 리스트, 고정 데이터면 튜플".
- **`(1)` vs `(1,)`**: 앞은 그냥 숫자 1, 뒤는 원소 1개짜리 튜플. 쉼표 하나로 의미가 완전히 달라진다.
- **에러는 실패가 아니다**: 튜플 수정 시 나는 `TypeError`는 "이건 원래 안 되는 동작"이라는 정상적인 안내다.

## 연결되는 개념

- 먼저 알면 좋은 것: [리스트와 시퀀스 자료형 다루기](02-sequence-list.md). 튜플은 리스트와 거의 같고 불변성만 다르다.
- 다음으로 이어지는 것: [딕셔너리와 반복문 활용](04-dictionary.md). 딕셔너리의 Key로는 리스트는 못 쓰고 튜플은 쓸 수 있는데, 그 이유가 바로 불변성이다.
- 더 찾아볼 키워드: 언패킹(`a, b = (1, 2)`), 함수의 다중 반환값, named tuple.

## 셀프 체크

- [ ] 튜플을 만드는 괄호와 리스트를 만드는 괄호를 구분할 수 있다.
- [ ] 튜플에서 인덱싱·슬라이싱·`+`·`*`가 모두 된다는 것을 안다.
- [ ] 원소 1개 튜플에 쉼표가 필요한 이유를 설명할 수 있다.
- [ ] 튜플 수정 시 에러가 나는 것이 정상임을 이해한다.
- [ ] "리스트를 쓸지 튜플을 쓸지"를 판단하는 기준을 말할 수 있다.

**복습 질문 및 답변**

- (기본) 튜플은 어떤 괄호로 만드나요? → 소괄호 `()`로 만든다.
- (이해 확인) `my_tuple[1] = "x"`를 실행하면 왜 에러가 나나요? → 튜플은 불변이라 원소 변경(item assignment)을 지원하지 않기 때문이다.
- (응용) RGB 색상값처럼 절대 바뀌면 안 되는 세 숫자 묶음에는 리스트와 튜플 중 무엇이 더 적절할까요? → 튜플. 불변성이 실수로 인한 변경을 막아 준다.

## 한 줄 정리

> 튜플은 리스트와 거의 같은 시퀀스이지만 "한 번 만들면 못 바꾸는" 불변 자료형이라, 바뀌면 안 되는 값을 안전하게 묶을 때 쓴다.
