# 집계 함수와 LIMIT — 데이터를 요약하고, 일부만 잘라 보기

> 책이 몇 권인지, 점수 총합은 얼마인지, 1등은 누구인지. 표를 한 줄 한 줄 세지 않고 한 번에 알아내는 방법이 있을까?

`COUNT` `SUM` `AVG` `MAX` `MIN` `LIMIT` `집계함수` `NULL` `내장함수`

## 핵심요약

- 집계 함수는 **여러 행을 입력받아 하나의 대표값으로 압축**하는 내장함수다.
- `COUNT`는 개수, `SUM`은 합계, `AVG`는 평균, `MAX`는 최댓값, `MIN`은 최솟값을 구한다.
- `COUNT`를 비롯한 집계 함수는 **NULL(빈 값)을 계산에서 제외**한다.
- `COUNT(*)`는 행 전체의 개수, `COUNT(컬럼)`은 그 컬럼에 값이 있는 행의 개수를 센다.
- `MAX`와 `MIN`은 숫자뿐 아니라 문자(가나다·알파벳 순서)에도 쓸 수 있다.
- `LIMIT`은 집계 함수는 아니지만, **출력되는 행의 개수를 제한**할 때 쓴다.
- `LIMIT 시작위치, 개수` 형태로 "몇 번째부터 몇 개"를 지정할 수 있고, 시작 위치는 0부터 센다.

## 개념별 정리

### COUNT — 데이터가 몇 개인지

**1. 정의**
검색한 결과에서 데이터(행)의 개수를 세어 돌려주는 함수다.

**2. 왜 필요한가?**
"우리 도서관에 책이 모두 몇 권이지?", "이번 달 주문이 몇 건이지?" 같은 질문은 거의 모든 데이터 업무의 출발점이다. 사람이 행을 일일이 세는 대신 함수 하나로 즉시 답을 얻는다.

**3. 예시**

```sql
-- book 테이블의 id 컬럼 개수를 센다
SELECT COUNT(id) FROM book;

-- 모든 행의 개수를 센다
SELECT COUNT(*) FROM book;
```

**4. 헷갈리기 쉬운 점**
`COUNT(*)`와 `COUNT(컬럼)`은 다르다. `COUNT(*)`는 행이 몇 개인지 무조건 세지만, `COUNT(컬럼)`은 **그 컬럼이 NULL이 아닌 행만** 센다. 예를 들어 전체 10행 중 어떤 컬럼에 빈 값이 3개 있다면 `COUNT(그_컬럼)`의 결과는 7이다.

**5. 한 줄 정리**
COUNT는 "몇 개야?"라는 질문에 답하는 함수이며, 컬럼을 지정하면 빈 값은 빼고 센다.

> 비유: 출석부에서 이름이 적힌 칸만 세는 것이 `COUNT(이름)`, 줄 수 자체를 세는 것이 `COUNT(*)`다. 결석으로 비워 둔 칸은 `COUNT(이름)`에서 빠진다.

### SUM — 값을 모두 더하기

**1. 정의**
지정한 컬럼의 값을 모두 더해 총합을 구하는 함수다.

**2. 왜 필요한가?**
매출 총액, 시험 총점, 재고 총수량처럼 "다 합치면 얼마인가"를 구하는 거의 모든 상황에 쓴다.

**3. 예시**

```sql
SELECT SUM(math) FROM grade;
```

`grade` 테이블에 저장된 모든 학생의 수학 점수를 더한 값을 돌려준다.

**4. 헷갈리기 쉬운 점**
SUM은 **숫자형 컬럼**에만 의미가 있다. 문자 컬럼에 SUM을 쓰면 원하는 결과가 나오지 않는다. 또한 NULL은 더하기에서 제외되므로, 빈 값이 0으로 취급되어 합계가 줄어드는 것은 아니다(애초에 더해지지 않는다).

**5. 한 줄 정리**
SUM은 숫자 컬럼을 한 줄로 다 더한 결과를 준다.

### AVG — 평균 구하기

**1. 정의**
지정한 컬럼의 평균값을 구하는 함수다.

**2. 왜 필요한가?**
"반 평균", "평균 객단가", "평균 체류 시간"처럼 대표값을 볼 때 쓴다. `SUM`을 `COUNT`로 나누는 수고 없이 한 번에 평균을 얻는다.

**3. 예시**

```sql
SELECT AVG(korean), AVG(english), AVG(math) FROM grade;
```

국어·영어·수학 각각의 평균을 한 번에 구한다.

**4. 헷갈리기 쉬운 점**
AVG도 NULL을 제외하고 계산한다. 그래서 "비어 있는 칸을 0점으로 보고 평균을 내고 싶을 때"와 결과가 달라질 수 있다. 빈 값을 0으로 처리하려면 NULL을 0으로 바꾸는 별도 처리가 필요하다.

**5. 한 줄 정리**
AVG는 평균을 직접 구해 주며, 빈 값은 분자·분모 양쪽에서 모두 빠진다.

### MAX & MIN — 가장 크고 작은 값

**1. 정의**
`MAX`는 최댓값, `MIN`은 최솟값을 가져오는 함수다.

**2. 왜 필요한가?**
"1등 점수", "최저가", "가장 늦은 주문 시각"처럼 극단값을 찾을 때 쓴다.

**3. 예시**

```sql
-- 국어 점수 중 가장 높은 값
SELECT MAX(korean) FROM grade;

-- 영어 점수 중 가장 낮은 값
SELECT MIN(english) FROM grade;
```

**4. 헷갈리기 쉬운 점**
MAX·MIN은 **문자형에도 동작한다.** 문자에서는 사전 순서(가나다·알파벳)가 기준이 되어, `MAX(name)`은 가장 뒷순서의 이름을, `MIN(name)`은 가장 앞순서의 이름을 돌려준다. "최댓값=가장 큰 숫자"라고만 생각하면 이 동작이 낯설게 느껴질 수 있다.

**5. 한 줄 정리**
MAX·MIN은 가장 크고 작은 값을 뽑되, 문자는 사전 순서로 비교한다.

### LIMIT — 일부만 잘라 보기

**1. 정의**
출력되는 데이터의 개수를 제한하는 명령이다. 집계 함수가 아니라 "결과 제어" 명령으로 분류된다.

**2. 왜 필요한가?**
테이블에 수만 건이 있을 때 전부 출력하면 보기 어렵다. "상위 몇 개만", "다음 페이지" 같은 화면을 만들 때 LIMIT이 핵심이다.

**3. 예시**

```sql
-- book 테이블에서 5개만 가져오기
SELECT * FROM book LIMIT 5;

-- 2번째 데이터부터 5개를 가져오기
SELECT * FROM book LIMIT 1, 5;
```

`LIMIT 시작위치, 개수` 형태에서 시작 위치는 **0부터** 센다. 그래서 `LIMIT 1, 5`는 "0이 아닌 1번 위치, 즉 2번째 행부터 5개"를 의미한다.

**4. 헷갈리기 쉬운 점**
시작 위치가 1부터가 아니라 **0부터**라는 점에서 헷갈린다. "1번째부터"라고 생각해 `LIMIT 1, 5`를 쓰면 실제로는 2번째 행부터 나온다. 또한 LIMIT 문법은 DBMS마다 다르다. MySQL·SQLite는 위와 같지만, 일부 DBMS(예: Oracle)는 다른 문법을 쓴다.

**5. 한 줄 정리**
LIMIT은 출력 개수를 자르는 명령이며, 시작 위치는 0부터 센다.

> 비유: 검색 결과의 "1페이지에 10개씩" 같은 페이지네이션이 바로 LIMIT으로 만든 화면이다.

## 코드로 보기 — 한 테이블에서 요약값 한꺼번에 뽑기

아래처럼 작은 `grade` 테이블이 있다고 하자(설명을 위한 예시 데이터다).

| id | name | korean | english | math |
| --- | --- | --- | --- | --- |
| 1 | Alice | 90 | 80 | 100 |
| 2 | Bob | 70 | 90 | 60 |
| 3 | Carol | 80 | NULL | 80 |

```sql
SELECT
  COUNT(*)      AS 학생수,
  COUNT(english) AS 영어응시자수,
  SUM(math)     AS 수학총점,
  AVG(math)     AS 수학평균,
  MAX(korean)   AS 국어최고,
  MIN(korean)   AS 국어최저
FROM grade;
```

| 학생수 | 영어응시자수 | 수학총점 | 수학평균 | 국어최고 | 국어최저 |
| --- | --- | --- | --- | --- | --- |
| 3 | 2 | 240 | 80.0 | 90 | 70 |

**코드목적**
한 테이블의 여러 요약 지표(개수·합계·평균·최대·최소)를 한 번의 쿼리로 동시에 뽑아내는 것이 목적이다.

**해석**
학생은 3명인데 영어 응시자는 2명이다. Carol의 영어 점수가 NULL이라 `COUNT(english)`에서 빠졌기 때문이다. 같은 이유로 `MAX`·`MIN`·`AVG`도 NULL은 무시한다. 수학 평균이 정수가 아니라 `80.0`처럼 소수로 표시되는 것은 평균 계산 결과가 실수형이기 때문이다.

**실무 연결**
대시보드의 요약 카드("총 주문 수 / 총 매출 / 평균 객단가 / 최고 결제액")는 대부분 이런 한 줄짜리 집계 쿼리에서 나온다. 데이터 분석의 첫 화면을 만드는 가장 기본 도구다.

## 직접 해보기

1. `book` 테이블에서 전체 책 수와, `author` 컬럼에 값이 있는 책 수를 한 번에 조회해 보자. (두 값이 다르다면 무엇을 뜻할까?)
2. `grade` 테이블에서 영어 점수의 평균과 최고점·최저점을 한 쿼리로 구해 보자.
3. `book` 테이블에서 11번째 행부터 10개를 가져오는 `LIMIT` 구문을 작성해 보자. (시작 위치를 0부터 센다는 점에 주의)

<details>
<summary>예시 답안 보기</summary>

```sql
-- 1번
SELECT COUNT(*), COUNT(author) FROM book;

-- 2번
SELECT AVG(english), MAX(english), MIN(english) FROM grade;

-- 3번 (11번째 = 위치 10)
SELECT * FROM book LIMIT 10, 10;
```

</details>

## 헷갈리기 쉬운 포인트

- **COUNT(*) vs COUNT(컬럼)**: 전자는 행 수를 무조건 세고, 후자는 그 컬럼이 NULL이 아닌 행만 센다.
- **AVG vs SUM/COUNT 직접 계산**: AVG는 NULL을 빼고 평균을 내므로, 빈 값을 0으로 보고 직접 나눈 값과 다를 수 있다.
- **LIMIT의 시작 위치 0 vs 1**: `LIMIT 1, 5`는 1번째가 아니라 2번째 행부터다.

## 셀프 체크

- [ ] COUNT(*)와 COUNT(컬럼)의 차이를 한 문장으로 설명할 수 있다.
- [ ] 집계 함수가 NULL을 제외한다는 점을 예로 들 수 있다.
- [ ] SUM·AVG·MAX·MIN을 한 쿼리에 함께 쓸 수 있다.
- [ ] MAX·MIN이 문자형에도 동작한다는 것을 안다.
- [ ] LIMIT의 시작 위치가 0부터라는 것을 안다.

**복습 질문 및 답변**

*기본* — 전체 행 수를 세려면 어떤 함수를 써야 하나?
> `COUNT(*)`를 쓴다. 특정 컬럼의 값 있는 행만 세려면 `COUNT(컬럼명)`을 쓴다.

*이해 확인* — 10행짜리 테이블에서 어떤 컬럼에 NULL이 3개 있을 때 `COUNT(그_컬럼)`의 결과는?
> 7이다. 집계 함수는 NULL을 제외하고 세기 때문이다.

*응용* — `SELECT * FROM book LIMIT 5, 5;`는 어떤 데이터를 가져오나?
> 6번째 행부터 5개(즉 6~10번째)를 가져온다. 시작 위치 5는 0부터 셌을 때 6번째이기 때문이다.

## 한 줄 정리

> 집계 함수는 여러 행을 하나의 대표값으로 압축하고(개수·합계·평균·최대·최소), LIMIT은 그 결과 중 일부만 잘라 보여 준다. 둘 다 NULL과 시작 위치(0부터) 같은 사소해 보이는 규칙에서 실수가 갈린다.
