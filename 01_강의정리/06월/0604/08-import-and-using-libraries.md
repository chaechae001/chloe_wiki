# 라이브러리 불러오기와 200% 활용하기

> 설치는 끝났습니다. 그런데 이 라이브러리를 어떻게 내 프로그램에서 쓸까요? 그리고 처음 보는 라이브러리의 사용법은 어디서 익혀야 할까요? import부터 시작해, 공식 문서와 AI를 활용해 사용법을 빠르게 파악하는 방법까지 정리합니다.

`import` `네임스페이스` `LEGB` `alias` `from import` `dir` `help` `공식 문서`

## 핵심요약

- `import`는 특정 라이브러리의 코드를 현재 네임스페이스로 가져오라는 지시다.
- 가져온 뒤에는 점(`.`) 연산자로 그 안의 함수·속성에 접근한다.
- 네임스페이스는 이름이 저장되는 공간이고, 파이썬은 LEGB 순서로 이름을 찾는다.
- `from ... import ...`로 특정 함수만, `as`로 별칭을 지정해 가져올 수 있다.
- `버전 확인`, `dir()`, `help()`/`pydoc`로 라이브러리의 정보와 사용법을 파악한다.
- 사용법은 공식 문서·커뮤니티·생성형 AI를 함께 쓰되, 항상 검증한다.

## 개념별 정리

### import와 점(.) 연산자

**1. 정의**
`import`는 라이브러리의 코드를 현재 프로그램으로 불러오는 명령입니다. 불러온 뒤에는 `라이브러리.함수` 형태로 사용합니다.

**2. 왜 필요한가?**
설치만으로는 코드에서 바로 쓸 수 없습니다. import해야 파이썬 인터프리터가 그 코드를 현재 작업 공간으로 가져옵니다.

**3. 예시**

```python
import math
print(math.sqrt(9))   # 3.0
```

**4. 헷갈리기 쉬운 점**
점(`.`)은 "안에 있는 것에 접근"한다는 뜻입니다. `math.sqrt`는 "math 안의 sqrt"입니다. import만 하고 점 없이 `sqrt(9)`라고 쓰면 이름을 못 찾습니다(아래 `from import`는 예외).

**5. 한 줄 정리**
import로 데려오고, 점(`.`)으로 그 안의 기능을 꺼내 씁니다.

> 비유: import는 도서관에서 책을 대출해 오는 것, 점(`.`)은 그 책의 특정 챕터를 펼치는 것입니다.

### 네임스페이스와 LEGB

**1. 정의**
네임스페이스는 변수·함수·클래스 등의 이름이 저장되는 공간입니다. 파이썬은 이름을 찾을 때 **LEGB**(Local → Enclosed → Global → Built-in) 순서로 탐색합니다.

**2. 왜 필요한가?**
같은 이름이 여러 곳에 있을 수 있습니다. 파이썬이 "어느 이름을 쓸지" 정하는 규칙이 LEGB입니다. 이걸 알면 변수 충돌이나 예상 밖 값의 원인을 찾을 수 있습니다.

**3. 예시**

```python
x = '글로벌 x'

def test():
    x = '로컬 x'
    print(x)

test()      # 로컬 x   ← 함수 안에서는 로컬을 먼저 찾음
print(x)    # 글로벌 x  ← 함수 밖에서는 글로벌
```

**4. 헷갈리기 쉬운 점**
함수 안에서 만든 변수(로컬)는 함수 밖에 영향을 주지 않습니다. 같은 이름 `x`라도 함수 안의 것과 밖의 것은 다른 공간에 있습니다. import한 라이브러리는 글로벌 네임스페이스에 들어가 모듈 전체에서 통용됩니다.

**5. 한 줄 정리**
LEGB는 "가까운 데부터 차례로 이름을 찾는" 파이썬의 검색 순서입니다.

### from import와 alias(as)

**1. 정의**
- `from 라이브러리 import 함수`: 라이브러리 전체가 아니라 특정 기능만 가져오기
- `import 라이브러리 as 별칭`: 라이브러리에 짧은 별명을 붙여 가져오기

**2. 왜 필요한가?**
필요한 함수만 가져오면 코드가 짧아지고 가독성·메모리 효율이 좋아집니다. 별칭은 긴 이름을 줄여 주고, 관례적으로 굳어진 별칭은 협업 시 의사소통을 돕습니다.

**3. 예시**

```python
# 특정 함수만 가져오기
from math import sqrt, pow, fabs

sqrt_result = sqrt(9)     # 제곱근 → 3.0
pow_result  = pow(9, 2)   # 거듭제곱(9^2) → 81.0
fabs_result = fabs(-9)    # 절댓값 → 9.0

# 상수 가져오기
from math import pi
radius = 5
circumference = 2 * pi * radius
print(f"원의 반지름이 {radius}일 때, 원의 둘레는 {circumference}입니다.")
# 원의 반지름이 5일 때, 원의 둘레는 31.41592653589793입니다.
```

```python
# 별칭(as)으로 가져오기
import pandas as pd
pd.read_csv('data.csv')
```

자주 쓰는 관례 별칭:

| 라이브러리 | 별칭 |
| --- | --- |
| numpy | np |
| pandas | pd |
| matplotlib.pyplot | plt |
| seaborn | sns |
| tensorflow | tf |
| streamlit | st |

**4. 헷갈리기 쉬운 점**
`from math import sqrt`로 가져오면 `math.sqrt`가 아니라 그냥 `sqrt`로 씁니다. 반대로 `import math`만 했다면 반드시 `math.sqrt`로 써야 합니다. "어떻게 가져왔느냐"가 "어떻게 부르느냐"를 결정합니다.

**5. 한 줄 정리**
필요한 것만 콕 집으려면 `from import`, 이름을 줄이려면 `as`.

### 라이브러리 정보 확인하기 — 버전, dir(), help()

**1. 정의**
라이브러리가 올바르게 불려 왔는지, 무엇을 제공하는지 확인하는 방법들입니다.

**2. 왜 필요한가?**
문서를 보거나 질문할 때 **버전**이 중요합니다(버전마다 기능이 다를 수 있음). 또 라이브러리가 어떤 함수·속성을 갖는지 알아야 사용법을 익힐 수 있습니다.

**3. 예시**

```python
# 버전 확인
import pandas as pd
print(pd.__version__)        # 예: 2.2.1

# 어떤 이름들이 들어 있는지 목록 확인
import math
print(dir(math))
# ['acos', 'acosh', ..., 'pi', 'pow', 'sqrt', 'tan', ...]

# 도움말(설명서) 보기
help(pd)
```

터미널에서는 `pip show pandas`로 버전·홈페이지·라이선스·설치 위치·의존성을, `pydoc pandas`로 설명을 볼 수 있습니다.

**4. 헷갈리기 쉬운 점**
`dir()`은 "어떤 이름이 있는지" 목록만 보여 줍니다. 각 함수가 무엇을 하는지는 `help()`나 공식 문서를 봐야 합니다. 둘은 역할이 다릅니다.

**5. 한 줄 정리**
`dir()`로 "무엇이 있나"를, `help()`로 "어떻게 쓰나"를 확인합니다.

### 사용법 익히기 — 공식 문서·커뮤니티·AI

**1. 정의**
처음 보는 라이브러리의 사용법을 파악하는 세 갈래 경로입니다.

**2. 왜 필요한가?**
공식 문서는 가장 정확하지만 방대해서 원하는 정보를 빠르게 찾는 역량이 필요합니다. 그래서 AI와 커뮤니티로 빠르게 감을 잡고, 공식 문서에서 최종 검증하는 조합이 효율적입니다.

**3. 예시**
- **공식 문서(Documentation):** 라이브러리의 "사용 설명서". 소개·설치·튜토리얼·API 레퍼런스·FAQ·버전 히스토리가 담깁니다. 검색 기능으로 필요한 부분만 찾고, 영어 문서는 AI로 번역해 읽으면 됩니다.
- **커뮤니티(포럼·GitHub Issues 등):** 실제 사용자의 경험·노하우·예제를 얻습니다. GitHub Issue로 버그·기능 요청을 보거나 직접 남길 수 있습니다.
- **생성형 AI:** 원하는 기능을 질문하고, 이어지는 질문으로 좁혀 갑니다.

**4. 헷갈리기 쉬운 점 — AI의 두 가지 함정**
- **최신 정보 부족:** AI는 학습 시점 이후에 바뀌거나 새로 나온 기능을 모릅니다. 예전 버전 기준으로 답해 "없는 기능"을 안내할 수 있습니다.
- **할루시네이션:** AI가 사실이 아닌 정보를 그럴듯하게 지어낼 수 있습니다. 예를 들어 실제로 없는 함수를 있다고 답하면, 실행 시 `AttributeError` 같은 오류가 납니다.

그래서 AI·커뮤니티 답변은 반드시 공식 문서나 실제 실행으로 **검증**해야 합니다.

**5. 한 줄 정리**
AI·커뮤니티로 빠르게 찾고, 공식 문서로 정확히 확인합니다.

## 코드로 보기 — 새 라이브러리를 처음 만났을 때의 점검 순서

```python
# 1) 잘 불러와졌는지 + 버전 확인 (문서·질문의 기준)
import pandas as pd
print(pd.__version__)        # 2.2.1

# 2) 무엇이 들어 있는지 훑어보기
print([name for name in dir(pd) if name.startswith("read")])
# ['read_csv', 'read_excel', 'read_json', ...]

# 3) 특정 기능의 사용법 확인
help(pd.read_csv)            # 인자·반환값 설명 출력
```

**코드목적**
처음 쓰는 라이브러리를 "버전 확인 → 기능 목록 → 사용법" 순서로 빠르게 파악하는 흐름을 익히는 것이 목적입니다.

**해석**
먼저 버전을 확인해 문서·AI 답변의 기준을 맞춥니다. `dir()`로 어떤 기능이 있는지 큰 그림을 보고(여기선 데이터를 읽는 `read_` 계열만 추렸습니다), `help()`로 실제 사용법을 확인합니다. 이 순서면 공식 문서를 통째로 읽지 않아도 필요한 부분에 빠르게 도달합니다.

**실무 연결**
새 라이브러리 도입은 늘 "사용법 파악"에서 시간이 걸립니다. 이 점검 순서를 습관화하면 낯선 도구도 빠르게 손에 익힐 수 있습니다. 생성형 AI에게 "이 버전의 라이브러리로 ~를 하려면?"이라고 버전을 명시해 물으면 더 정확한 답을 얻습니다.

3. 좋아하는 라이브러리 하나를 `import ... as ...`로 별칭을 붙여 불러와 보세요.

## 헷갈리기 쉬운 포인트

- **`import math` vs `from math import sqrt`:** 전자는 `math.sqrt`, 후자는 `sqrt`로 호출합니다.
- **`dir()` vs `help()`:** 목록 보기 vs 사용법 보기.
- **AI 답변 vs 검증:** 최신성·할루시네이션 때문에 공식 문서·실행으로 확인이 필수입니다.

## 셀프 체크

- [ ] `import`와 점(`.`) 연산자의 관계를 안다.
- [ ] 네임스페이스와 LEGB 탐색 순서를 안다.
- [ ] `from import`와 `as`의 차이를 안다.
- [ ] 가져온 방식에 따라 호출법이 달라진다는 걸 안다.
- [ ] `dir()`과 `help()`의 역할을 구분한다.

**복습 질문 및 답변**

- (기본) import한 라이브러리의 함수는 어떻게 호출하나요? → `라이브러리.함수`처럼 점(`.`)으로 접근합니다.
- (이해 확인) `from math import sqrt` 후 `math.sqrt(9)`가 오류 나는 이유는? → `sqrt`만 가져왔으므로 `sqrt(9)`로 써야 합니다.
- (응용) 처음 보는 라이브러리의 사용법을 빠르게 파악하는 순서는? → 버전 확인 → `dir()`로 기능 목록 → `help()`/공식 문서로 사용법, AI는 보조로 쓰되 검증.

## 한 줄 정리

> `import`로 데려오고 점(`.`)으로 꺼내 쓰며, `from import`·`as`로 가져오는 방식을 조절하고, `dir()`·`help()`와 공식 문서·AI를 함께 써 사용법을 익히는 것이 라이브러리 활용의 전부입니다.
