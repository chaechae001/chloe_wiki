# EDA — 데이터를 그림으로 들여다보고, 관계를 읽고, 모델에 맞게 다듬기

> 깨끗하게 정리한 데이터도 표로만 보면 아무것도 안 보인다. EDA(탐색적 데이터 분석)는 데이터를 *그림으로 펼쳐* 숨은 패턴을 찾고, 변수들이 *어떻게 함께 움직이는지*(상관관계)를 읽고, 모델이 잘 학습하도록 *스케일과 특성을 다듬는* 과정이다. 이 글은 그 전 과정을 시각화 도구(Matplotlib·Seaborn)와 함께 따라간다.

`EDA` · `시각화` · `히스토그램` · `박스플롯` · `산점도` · `히트맵` · `상관계수` · `스케일링` · `전처리` · `특성엔지니어링`

## 핵심요약

- **EDA**는 수학자 존 튜키가 제안한, 데이터를 다양한 방법으로 확인하고 이해하는 과정으로, 여기서 얻은 지식이 이후 통계 분석·모델링의 토대가 된다.
- 시각화는 목적에 따라 도구가 다르다 — 분포는 **히스토그램**, 이상치·퍼짐은 **박스플롯**, 두 변수 관계는 **산점도**, 범주 비교는 **막대 차트**, 상관관계는 **히트맵**.
- **Matplotlib**은 파이썬의 기본 시각화 도구이고, **Seaborn**은 그 위에서 더 세련되고 간결하게 그려 주며 pandas와 잘 맞물린다.
- 두 변수가 함께 움직이는 정도는 **공분산**으로 재지만, 단위에 휘둘리는 단점이 있어 **상관계수**(−1~1)로 표준화해 본다.
- 상관관계는 **산점도·pairplot·히트맵**으로 시각화하면 한눈에 강도와 방향이 읽힌다.
- 변수마다 값의 범위가 다르면 큰 변수가 결과를 좌우하므로, **스케일링**(Min-Max·표준화·로버스트)으로 범위를 맞춘다.
- **전처리**(정제·결측 보간)와 **특성 엔지니어링**(기존 특성으로 새 특성 생성)으로 데이터를 모델이 학습하기 좋은 형태로 마무리한다.

## 개념별 정리

### 1. EDA란 무엇인가

**1. 정의**
EDA(Exploratory Data Analysis, 탐색적 데이터 분석)는 데이터를 다양한 방법으로 확인하고 이해하는 과정이다. 주로 시각화를 통해 자료를 직관적으로 바라보며, 여기서 도출된 지식이 이후 통계 분석이나 모델링에 사용된다.

**2. 왜 필요한가?**
숫자만 늘어놓은 표에서는 패턴이 보이지 않는다. "어느 구간에 몰려 있나, 튀는 값은 없나, 두 변수가 같이 움직이나" 같은 질문은 그림으로 봐야 답이 나온다. EDA는 본격 분석 전에 데이터의 성격을 파악하는 정찰 단계다.

**3. 예시 (흐름)**
EDA의 큰 흐름은 "데이터 시각화 → 패턴·관계 발견 → 전처리·특성 가공 → 이후 모델링"으로 이어진다. 이 글의 순서가 곧 그 흐름이다.

**4. 헷갈리기 쉬운 점**
EDA는 "정답을 내는 단계"가 아니라 "질문을 만드는 단계"다. 가설을 세우고 검증하는 확증적 분석(CDA)과 달리, EDA는 데이터를 열어 보며 *무엇을 물어야 할지*를 찾는 데 가깝다.

**5. 한 줄 정리**
EDA는 데이터를 그림으로 펼쳐 보며 패턴과 관계를 찾고, 이후 분석의 방향을 잡는 정찰 과정이다.

> 비유: EDA는 *낯선 도시에 도착해 지도를 펼치고 한 바퀴 둘러보는 것*이다. 어디에 뭐가 있는지 감을 잡아야 본격적인 일정을 짤 수 있다.

(EDA는 데이터 처리 편의 전처리 다음 단계로 이어진다 → [데이터 처리](03-data-processing.md))

### 2. 시각화의 무기고 — 어떤 그래프를 언제 쓰나

**1. 정의**
데이터 시각화는 그래프·차트·맵 같은 시각 요소로 데이터를 나타내는 과정이다. 수치만으로는 못 보던 패턴을 발견하게 돕는다.

**2. 왜 필요한가?**
"무엇을 보여 주고 싶은가"에 따라 알맞은 그래프가 다르다. 도구를 잘못 고르면 메시지가 묻힌다. 대표 그래프들의 쓰임을 알아 두면 데이터를 만났을 때 바로 손이 나간다.

**3. 예시 (대표 그래프와 쓰임)**
- **히스토그램**: 단일 수치형 변수의 *분포*를 본다(가로축=계급, 세로축=도수). 장점은 분포를 한눈에 보는 것, 한계는 원래 값이 가려지고 연속형에만 적합하다는 것.
- **박스 플롯**: *이상치*를 식별하고 *퍼짐(분산)*을 본다. 제1사분위(Q1, 25%), 중앙값, 제3사분위(Q3, 75%)를 상자로 그리고, 최대값(Q3+1.5×IQR)·최소값(Q1−1.5×IQR) 밖은 이상치로 점 찍는다.
- **산점도**: 두 수치형 변수 *사이의 관계*를 본다. 패턴·추세·이상치가 잘 드러나지만, 점이 너무 많으면 겹쳐 보기 어렵다.
- **막대 차트**: 범주형 변수의 *카테고리 비교*에 쓴다. 해석이 쉽지만 연속 데이터엔 부적합하다.
- **히트맵**: 변수 간 *상관관계*를 색으로 표현한다. 직관적이지만 색 척도를 잘못 고르면 해석이 흐려진다.

**4. 헷갈리기 쉬운 점**
히스토그램과 막대 차트는 모양이 비슷하지만 쓰임이 다르다. 히스토그램은 *연속형 값의 구간별 도수*(막대 사이가 붙음), 막대 차트는 *범주별 값 비교*(막대 사이가 떨어짐)다.

**5. 한 줄 정리**
"분포는 히스토그램, 퍼짐·이상치는 박스플롯, 관계는 산점도, 범주 비교는 막대, 상관은 히트맵"이 기본 공식이다.

> 비유: 그래프는 *공구함*이다. 같은 데이터라도 묻는 질문에 맞는 도구를 꺼내야 한다.

(박스플롯의 IQR·이상치는 데이터 처리 편에서도 다뤘다 → [데이터 처리](03-data-processing.md))

### 3. Matplotlib — 파이썬 기본 시각화

**1. 정의**
Matplotlib은 파이썬에서 널리 쓰이는 데이터 시각화 라이브러리다. 관례상 `import matplotlib.pyplot as plt`로 불러온다.

**2. 왜 필요한가?**
거의 모든 파이썬 시각화의 바탕이 되는 도구다. Seaborn 같은 고급 라이브러리도 내부적으로 Matplotlib 위에서 동작하므로, 기본기를 익혀 두면 어디서나 응용할 수 있다.

**3. 예시**
점을 찍고(`'ro'`는 빨간 원 마커), 축 범위를 정한다.

```python
import matplotlib.pyplot as plt

# 'ro' = red(빨강) + o(원형 마커)
plt.plot([1, 2, 3, 4], [3, 7, 9, 12], 'ro')
plt.axis([0, 5, 0, 15])   # [x최소, x최대, y최소, y최대]
plt.show()
```

여러 그래프를 한 번에 겹쳐 그릴 수도 있다.

```python
import numpy as np
import matplotlib.pyplot as plt

time = np.arange(0, 10, 0.5)
# (x, y, 스타일)을 묶어서 여러 개 전달
plt.plot(time, time, 'ro', time, time**2, 'b--', time, time**3, 'gs')
plt.show()
# 빨간 점(1차), 파란 점선(2차), 초록 사각형(3차)이 함께 그려진다
```

**4. 헷갈리기 쉬운 점**
스타일 문자열 `'ro'`, `'b--'`, `'gs'`는 *색 + 모양*의 조합이다(r=red, b=blue, g=green / o=원, --=점선, s=사각형). 또 Matplotlib은 강력하지만, Seaborn·Plotly 같은 최신 도구에 비해 기본 그래프가 다소 투박하다는 한계가 있다.

**5. 한 줄 정리**
Matplotlib은 점·선·도형을 직접 그리는 파이썬 시각화의 기본 도구다.

> 비유: Matplotlib은 *연필과 자*다. 무엇이든 그릴 수 있지만, 예쁘게 다듬는 건 손이 좀 더 간다.

### 4. Seaborn — 더 세련되고 간결한 시각화

**1. 정의**
Seaborn은 Matplotlib을 기반으로 기능을 확장한 시각화 라이브러리로, 관례상 `import seaborn as sns`로 불러온다.

**2. 왜 필요한가?**
같은 그래프라도 Seaborn은 더 적은 코드로, 더 세련되게 그린다. 무엇보다 pandas DataFrame과 잘 맞물려 `data=`, `x=`, `y=`만 지정하면 바로 그려지고, 고급 통계 플롯도 함수 한 줄로 만든다.

**3. 예시**
Seaborn은 자체 예제 데이터셋을 제공한다(여기서는 연도·월별 항공 승객 수를 담은 flights, 식당 팁 정보를 담은 tips).

```python
import matplotlib.pyplot as plt
import seaborn as sns

# 박스 플롯 — 연도별 승객 수 분포
flights = sns.load_dataset('flights')
plt.figure(figsize=(6, 6))
sns.boxplot(data=flights, x='year', y='passengers')
plt.show()

# 산점도 — total_bill vs tip, 색은 식사 시간(time)으로 구분
tips = sns.load_dataset("tips")
sns.scatterplot(data=tips, x="total_bill", y="tip", hue="time")
plt.show()
```

**4. 헷갈리기 쉬운 점**
Seaborn은 Matplotlib *위에서* 동작하므로 둘을 함께 쓴다 — 그래프는 `sns`로 그리고, 크기·제목·표시는 `plt.figure(...)`, `plt.title(...)`, `plt.show()`로 마무리하는 식이다. `hue=`는 "색으로 한 변수를 더 구분해 표현"하는 옵션이다.

**5. 한 줄 정리**
Seaborn은 Matplotlib 위에서 더 적은 코드로 더 예쁜 통계 그래프를 그려 주는 도구다.

> 비유: Matplotlib이 *맨손 요리*라면 Seaborn은 *밀키트*다. 같은 요리를 더 빠르고 깔끔하게 완성한다.

### 5. 데이터 비교 — 강조로 메시지 전하기

**1. 정의**
데이터 비교는 두 개 이상의 데이터 집합을 분석해 유사성·차이·추세·관계를 파악하는 과정이다. 범주형의 차이를 보는 질적 비교와, 수치의 상관·패턴을 보는 양적 비교로 나뉜다.

**2. 왜 필요한가?**
그냥 그린 그래프는 "다 비슷하게" 보인다. 보여 주고 싶은 대상을 *색으로 강조*하면 메시지가 또렷해진다. 분석 결과를 남에게 전달할 때 핵심 기술이다.

**3. 예시**
막대 그래프에서 특정 연도만 강조해 비교한다.

```python
import matplotlib.pyplot as plt
import seaborn as sns

# 연도 목록을 만들고, 1955·1958년만 파란색, 나머지는 회색으로
flights_years = sorted(list(set(flights['year'])))
color = ['lightgrey' if x not in [1955, 1958] else "#4472C4" for x in flights_years]
sns.barplot(data=flights, x="year", y="passengers", palette=color, ci=None)
plt.show()
```

선 그래프로 여러 연도의 월별 추세를 겹쳐 비교할 수도 있다.

```python
# 연도마다 월별 승객 변화를 선으로, 강조 연도만 진하게
for year in flights['year'].unique():
    one_year = flights[flights['year'] == year]
    line_color = '#4472C4' if year in (1955, 1958) else '#EFF3F9'
    plt.plot(one_year['month'], one_year['passengers'], color=line_color)
plt.show()
```

**4. 헷갈리기 쉬운 점**
강조 색을 만들 때 쓰는 `['색A' if 조건 else '색B' for x in 목록]`은 리스트 컴프리헨션이다 — "목록의 각 항목마다 조건을 따져 색을 정한 리스트"를 만든다. 이 색 리스트를 `palette=`에 넘기는 게 핵심이다.

**5. 한 줄 정리**
데이터 비교는 강조 색을 활용해 "보여 주고 싶은 대상"을 도드라지게 만드는 시각화 기술이다.

> 비유: 형광펜으로 *중요한 문장만 칠하는 것*과 같다. 나머지를 흐리게 두면 핵심이 튀어나온다.

### 6. 상관관계 — 공분산과 상관계수

**1. 정의**
상관관계 분석은 두 양적 변수 간 선형 관계의 강도와 방향을 평가하는 것이다. 공분산은 두 변수의 공동 변동성을, 상관계수는 그것을 −1~1로 표준화한 값을 나타낸다.

**2. 왜 필요한가?**
"키가 크면 몸무게도 큰가?"처럼 두 변수가 함께 움직이는지를 수치로 알면, 어떤 변수가 서로 관련 있는지(=모델에 함께 쓸지)를 판단할 수 있다.

**3. 예시**
공분산은 함께 커지면 양수, 반대로 움직이면 음수다.

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({'키':[158, 163, 170, 183, 180], '몸무게':[49, 52, 60, 80, 83]})
print(np.cov(df['키'], df['몸무게']))
# [[114.7 164.7]
#  [164.7 249.7]]   → 키-몸무게 공분산 164.7 (양수: 함께 증가)
```

그런데 공분산은 **단위에 휘둘린다**. 키를 cm 대신 m로 바꾸면 값이 확 달라진다. 그래서 −1~1로 표준화한 상관계수를 쓴다.

```python
# 키를 cm로 잰 데이터와 m로 잰 데이터
df_cm = pd.DataFrame({'키':[158, 163, 170, 183, 180], '몸무게':[49, 52, 60, 80, 83]})
df_m  = pd.DataFrame({'키':[1.58, 1.63, 1.70, 1.83, 1.80], '몸무게':[49, 52, 60, 80, 83]})

print(np.corrcoef(df_cm['키'], df_cm['몸무게'])[0][1])  # 0.9732011625327036
print(np.corrcoef(df_m['키'],  df_m['몸무게'])[0][1])   # 0.9732011625327038
# 단위가 달라도 상관계수는 거의 동일! (≈ 0.973)
```

상관계수는 −1(완전한 음의 관계), 0(독립), 1(완전한 양의 관계) 사이의 값을 가진다.

**4. 헷갈리기 쉬운 점**
공분산의 값이 크다고 "관계가 강하다"고 말할 수 없다 — 단위에 따라 값이 달라지기 때문이다. 강도를 비교하려면 반드시 *상관계수*를 봐야 한다. 또 상관관계는 "함께 움직임"일 뿐, *인과관계(원인-결과)는 아니다*.

**5. 한 줄 정리**
공분산은 함께 움직이는 방향을, 상관계수(−1~1)는 단위에 휘둘리지 않는 관계의 강도를 알려 준다.

> 비유: 공분산이 *나라마다 다른 화폐로 적힌 금액*이라면, 상관계수는 *공통 통화로 환산한 금액*이다. 그래야 서로 비교가 된다.

### 7. 상관관계 시각화 — 한눈에 관계 읽기

**1. 정의**
변수 간 관계를 그림으로 표현하는 방법으로, 산점도(두 변수), pairplot(여러 변수의 모든 조합), 히트맵(상관계수 행렬)이 대표적이다.

**2. 왜 필요한가?**
상관계수 숫자만 보면 감이 안 온다. 그림으로 보면 관계의 강도·방향은 물론, 직선 관계인지 곡선인지까지 한눈에 들어와 "어떤 특성을 쓸지" 고르는 데 큰 도움이 된다.

**3. 예시**
여기서는 회귀 연습에 자주 쓰는 당뇨병(diabetes) 데이터셋을 사용한다.

```python
import pandas as pd
from sklearn import datasets
import seaborn as sns
import matplotlib.pyplot as plt

data = datasets.load_diabetes()
df = pd.DataFrame(data['data'], columns=data['feature_names'])

# 여러 변수의 모든 짝을 산점도로 (대각선은 분포 히스토그램)
sns.pairplot(df[['age', 'bmi', 'bp']])
plt.show()

# 모든 변수 쌍의 상관계수를 색으로 — 히트맵
sns.heatmap(df.corr())
plt.title('Heatmap by sns.heatmap()')
plt.show()
```

**4. 헷갈리기 쉬운 점**
`df.corr()`는 모든 숫자 열 쌍의 상관계수를 표(행렬)로 만들어 준다. 히트맵은 그 표에 색을 입힌 것일 뿐이다 — 대각선은 자기 자신과의 상관이라 항상 1이다. pairplot의 대각선이 산점도가 아니라 *히스토그램*인 것도 같은 이유(자기 자신과의 관계)다.

**5. 한 줄 정리**
산점도·pairplot·히트맵은 변수 간 관계의 강도와 방향을 한눈에 읽게 해 주는 EDA의 핵심 그림이다.

> 비유: 히트맵은 *반 전체의 관계도를 색으로 칠한 좌석표*다. 누구와 누가 가까운지 색만 봐도 안다.

### 8. 데이터 스케일링 — 변수의 범위 맞추기

**1. 정의**
스케일링은 서로 다른 변수의 값 범위가 일치하도록 조정하는 작업이다.

**2. 왜 필요한가?**
주택 크기(수천)와 수영장 수(한 자리)가 한 데이터에 섞이면, 숫자가 큰 변수가 결과를 좌우해 버린다. 모든 변수를 비슷한 범위로 맞추면 공정하게 비교되고, 이상치 처리에도 효과적이다.

**3. 예시**
대표적인 세 가지 스케일링이 있다.

- **Min-Max 스케일링**: 최소값~최대값을 이용해 0~1 사이로 변환
- **표준화(Standard)**: 평균이 0, 표준편차가 1이 되도록 변환
- **로버스트(Robust)**: 중앙값이 0, 사분위범위(IQR)가 1이 되도록 변환(이상치에 덜 민감)

```python
from sklearn.datasets import load_breast_cancer
from sklearn.preprocessing import StandardScaler, MinMaxScaler, RobustScaler

X = load_breast_cancer().data

std = StandardScaler();   X_std = std.fit(X).transform(X)   # 평균0, 표준편차1
mms = MinMaxScaler();     X_mm  = mms.fit(X).transform(X)   # 0~1
rbs = RobustScaler();     X_rb  = rbs.fit(X).transform(X)   # 중앙값0, IQR1
```

**4. 헷갈리기 쉬운 점**
세 방법은 "어디에 맞추느냐"가 다르다 — Min-Max는 *범위(0~1)*에, 표준화는 *평균·표준편차*에, 로버스트는 *중앙값·IQR*에 맞춘다. 이상치가 많을 땐 평균·최댓값이 흔들리므로, 중앙값 기반의 로버스트가 더 안전하다. 또 `fit`은 "기준을 학습", `transform`은 "그 기준으로 변환"이라는 2단계임을 기억하자.

**5. 한 줄 정리**
스케일링은 변수마다 제각각인 값의 범위를 맞춰, 큰 변수가 결과를 독점하지 못하게 하는 작업이다.

> 비유: 스케일링은 *키·몸무게·시력을 모두 0~100점으로 환산하는 것*이다. 그래야 한 점수로 공정하게 비교된다.

### 9. 데이터 전처리와 특성 엔지니어링

**1. 정의**
전처리는 데이터를 분석에 효과적인 형식으로 정리·변환·구성하는 작업이고(정제·결측 처리·불균형 처리 등), 특성 엔지니어링은 기존 특성에서 새로운 특성을 선택·변환·생성해 모델 성능을 높이는 과정이다.

**2. 왜 필요한가?**
모델은 "좋은 입력"이 있어야 좋은 결과를 낸다. 누락·잡음을 정리하고, 의미 있는 새 특성을 만들어 주면 같은 모델도 훨씬 잘 학습한다.

**3. 예시**
전처리 — 결측이 많은 열은 버리고, 수치 결측은 선형보간으로 메운다.

```python
import seaborn as sns
titanic = sns.load_dataset('titanic')

titanic = titanic.drop(['deck'], axis=1)         # 결측 많은 열 제거
titanic['age'] = titanic['age'].interpolate()    # 선형보간으로 빈 나이 채움
```

특성 엔지니어링 — 범주를 0/1로 인코딩하고, 조건으로 새 특성을 만든다.

```python
import numpy as np

# 생존 여부(yes/no)를 1/0으로 인코딩
titanic['alive_1'] = np.where(titanic['alive'] == 'yes', 1, 0)
print(titanic[['fare', 'alive_1']].corr())   # 요금과 생존의 상관 ≈ 0.257

# 조건으로 새 특성 만들기
titanic['expensive'] = np.where(titanic['fare'] > 50, 1, 0)             # 비싼 표 여부
titanic['continent'] = np.where(titanic['embark_town'] == 'Queenstown', # 출발지로 대륙
                                'Oceania', 'Europe')
```

특성 엔지니어링 방법으로는 특성 결합(두 특성을 합쳐 새 특성), 범주형 변수 인코딩(수치로 변환), 비선형 변환(제곱·세제곱항 추가), 새로운 특성 생성 등이 있다.

**4. 헷갈리기 쉬운 점**
`interpolate()`(선형보간)와 `fillna(평균)`은 둘 다 결측을 채우지만 방식이 다르다. 보간은 *앞뒤 값을 잇는 직선 위의 값*으로 채우고(순서가 의미 있는 데이터에 적합), `fillna(평균)`은 *전체 평균*으로 채운다. 또 인코딩에 쓰는 `np.where(조건, 참값, 거짓값)`는 데이터 처리 편에서 본 것과 동일하다.

**5. 한 줄 정리**
전처리는 데이터를 깨끗하게 정리하고, 특성 엔지니어링은 의미 있는 새 변수를 만들어 모델이 잘 학습하도록 돕는다.

> 비유: 전처리가 *식재료 손질*이라면, 특성 엔지니어링은 *재료를 조합해 새로운 요리를 만드는 것*이다.

(`np.where`·`drop`·결측 처리는 데이터 처리 편과 이어진다 → [데이터 처리](03-data-processing.md))

## 코드로 보기 — 공분산 vs 상관계수, 단위의 함정

```python
import pandas as pd
import numpy as np

# 같은 사람들의 키를 cm로 잰 것과 m로 잰 것
df_cm = pd.DataFrame({'키':[158, 163, 170, 183, 180], '몸무게':[49, 52, 60, 80, 83]})
df_m  = pd.DataFrame({'키':[1.58, 1.63, 1.70, 1.83, 1.80], '몸무게':[49, 52, 60, 80, 83]})

# 공분산 — 단위가 바뀌면 값이 크게 달라진다
print(np.cov(df_cm['키'], df_cm['몸무게'])[0][1])  # 164.7
print(np.cov(df_m['키'],  df_m['몸무게'])[0][1])   # 1.647  ← 100배 차이!

# 상관계수 — 단위가 바뀌어도 거의 그대로
print(np.corrcoef(df_cm['키'], df_cm['몸무게'])[0][1])  # 0.9732011625327036
print(np.corrcoef(df_m['키'],  df_m['몸무게'])[0][1])   # 0.9732011625327038
```

**코드목적**
같은 데이터를 단위만 바꿔(cm ↔ m) 공분산과 상관계수를 비교해, "관계의 강도를 잴 땐 왜 상관계수를 써야 하는지"를 직접 확인한다.

**해석**
키를 cm에서 m로 바꾸자 **공분산은 164.7 → 1.647로 100배나 달라졌다**. 관계 자체는 그대로인데 단위 때문에 값이 출렁인 것이다. 반면 **상관계수는 0.973으로 거의 변하지 않았다**. 상관계수는 각 변수의 퍼짐으로 나눠 표준화하기 때문에 단위에 휘둘리지 않는다.

**실무 연결**
실제 데이터는 매출(만 원)·나이(세)·비율(%)처럼 단위가 제각각이다. "어떤 변수가 서로 관련 깊은가"를 판단할 때 공분산 값을 그대로 비교하면 단위가 큰 변수가 무조건 커 보이는 착시에 빠진다. 그래서 상관계수와 히트맵으로 강도를 비교하고, 관련 깊은 특성을 모델에 골라 넣는다.

## 헷갈리기 쉬운 포인트

- **히스토그램 vs 막대 차트** — 연속형의 구간별 도수(붙은 막대) / 범주별 값 비교(떨어진 막대).
- **Matplotlib vs Seaborn** — 기본·세밀 제어 / 그 위에서 더 간결·세련.
- **공분산 vs 상관계수** — 단위에 휘둘림 / −1~1로 표준화돼 강도 비교 가능.
- **상관관계 ≠ 인과관계** — 함께 움직인다고 원인-결과는 아니다.
- **Min-Max vs 표준화 vs 로버스트** — 0~1 범위 / 평균0·표준편차1 / 중앙값0·IQR1(이상치에 강함).
- **fit vs transform** — 기준 학습 / 그 기준으로 변환.
- **interpolate vs fillna(평균)** — 앞뒤 잇는 보간 / 전체 평균으로 채움.

**복습 질문 및 답변**

*기본* — 분포를 보고 싶을 때와 두 변수의 관계를 보고 싶을 때, 각각 어떤 그래프가 적합한가?
> 단일 변수의 분포는 히스토그램(또는 박스플롯), 두 수치 변수의 관계는 산점도가 적합하다. 여러 변수의 상관관계를 한눈에 보려면 히트맵을 쓴다.

*이해 확인* — 키를 cm에서 m로 바꿨더니 공분산은 100배 작아졌는데 상관계수는 그대로였다. 왜 그런가?
> 공분산은 각 변수의 단위가 그대로 곱해져 들어가므로 단위를 바꾸면 값이 크게 달라진다. 반면 상관계수는 공분산을 두 변수의 표준편차로 나눠 −1~1로 표준화하기 때문에, 단위가 바뀌어도 분자·분모가 같은 비율로 변해 값이 유지된다.

*응용* — 주택 크기(수천 단위)와 수영장 수(한 자리 단위)가 섞인 데이터로 모델을 만들려 한다. 무엇을 먼저 해야 하고 왜인가?
> 스케일링(예: 표준화 또는 Min-Max)을 먼저 해야 한다. 그대로 두면 숫자가 큰 '주택 크기'가 거리·가중치 계산을 지배해 '수영장 수'의 영향이 묻히기 때문이다. 모든 변수를 비슷한 범위로 맞춰야 각 변수가 공정하게 반영된다.

## 한 줄 정리

> EDA는 "데이터를 그림으로 탐색하고(시각화) → 변수들의 관계를 읽고(상관) → 모델에 맞게 다듬는(스케일링·전처리·특성 엔지니어링)" 과정이며, 여기서 얻은 통찰이 곧 이후 머신러닝 모델링의 출발점이 된다.
