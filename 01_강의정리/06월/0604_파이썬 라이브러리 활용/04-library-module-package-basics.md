# 라이브러리·모듈·패키지·프레임워크 기초

> 별 찍기와 자판기 프로그램은 만들 수 있는데, 멋진 그래프나 크롤링은 어떻게 만들까요? 정답은 "내가 다 만들지 않는다"입니다. 남이 잘 만들어 둔 코드를 가져다 쓰는 것 — 그 코드 뭉치를 부르는 이름이 라이브러리입니다.

`라이브러리` `모듈` `패키지` `프레임워크` `표준 라이브러리` `외부 라이브러리` `PyPI`

## 핵심요약

- 라이브러리는 "특정 작업을 수행하거나 기능을 제공하기 위해 미리 작성된 코드의 집합"이다.
- 모듈(파일) → 패키지(폴더) → 라이브러리(더 큰 배포 단위) 순으로 점점 커지는 코드 묶음이다.
- 패키지는 폴더에 `__init__.py`가 있어야 하나의 패키지로 인식된다.
- 프레임워크는 라이브러리보다 큰 "개발의 틀"이며, 차이의 핵심은 제어의 역전(IoC)이다.
- 표준 라이브러리는 설치 없이 바로 쓰고, 외부 라이브러리는 PyPI에서 설치해 쓴다.
- 기본 문법만으로는 한계가 있어, 시각화·크롤링·AI 등은 라이브러리 활용이 필수다.

## 개념별 정리

### 라이브러리란

**1. 정의**
재사용 가능한 코드의 집합으로, 개발자가 만들어 두면 사용자는 가져다 쓰기만 하면 되는 코드 묶음입니다. 함수·클래스·변수·상수 등을 포함합니다.

**2. 왜 필요한가?**
파이썬 기본 문법만으로는 데이터 시각화, 크롤링, AI 같은 고급 기능을 직접 구현하기가 너무 어렵습니다. 이미 검증된 코드를 가져다 쓰면 빠르고 안정적으로 원하는 결과를 얻습니다.

**3. 예시**

```python
import matplotlib.pyplot as plt
import pandas as pd
import seaborn as sns

df = pd.read_csv("data.csv")     # 데이터 불러오기

plt.figure(figsize=(12, 5))      # 그래프 옵션 설정
plt.xticks(rotation=45)
sns.boxplot(data=df, x="구", y="평당금액")   # 그래프 그리기
```

직접 짜면 수백 줄이 필요할 시각화를, 라이브러리 몇 줄로 해냅니다.

**4. 헷갈리기 쉬운 점**
라이브러리를 "import만 하면 끝"이라고 생각하기 쉽지만, 외부 라이브러리는 먼저 **설치**해야 import가 됩니다. "설치했는데 import가 안 된다"면 설치 위치(환경)가 다른 경우가 많습니다(가상환경 글에서 다룹니다).

**5. 한 줄 정리**
라이브러리는 "남이 잘 만들어 둔 코드를 가져다 쓰는" 재사용의 단위입니다.

> 비유: 도서관이에요. 필요한 책만 골라 빌리듯, 필요한 라이브러리만 골라 가져옵니다.

### 모듈 · 패키지 · 라이브러리

**1. 정의**
- **모듈(Module):** 함수·클래스·변수를 담은 하나의 파이썬 파일(`.py`)
- **패키지(Package):** 여러 모듈을 폴더로 묶은 것 (`__init__.py` 필요)
- **라이브러리(Library):** 하나 이상의 모듈이나 패키지를 포함하는 더 큰 코드 집합

**2. 왜 필요한가?**
코드가 커지면 한 파일에 다 넣을 수 없습니다. 관련된 기능을 파일(모듈)로 나누고, 파일들을 폴더(패키지)로 묶고, 그것을 배포 단위(라이브러리)로 포장하면 관리와 공유가 쉬워집니다.

**3. 예시**

모듈 — `math_utils.py` 파일 하나:

```python
# math_utils.py
def add(a, b):
    return a + b

def subtract(a, b):
    return a - b
```

```python
import math_utils
result = math_utils.add(5, 3)
print(result)   # 8
```

패키지 — 모듈들을 폴더로 묶음:

```
number_utils/
    __init__.py
    math_utils.py
    stats_utils.py
```

```python
from number_utils import math_utils
result = math_utils.subtract(10, 5)
print(result)   # 5
```

**4. 헷갈리기 쉬운 점**
세 단어는 별개가 아니라 "크기 순서"입니다. 모듈 < 패키지 < 라이브러리. 폴더에 `__init__.py`가 없으면 단순 폴더일 뿐 패키지로 인식되지 않을 수 있습니다(그래서 빈 파일이라도 넣어 둡니다).

**5. 한 줄 정리**
파일(모듈)을 모아 폴더(패키지)로, 폴더를 모아 배포 단위(라이브러리)로 — 모두 코드 재사용을 위한 개념입니다.

> 비유: 모듈은 한 권의 책, 패키지는 한 칸의 책장, 라이브러리는 도서관 전체입니다.

### 프레임워크 vs 라이브러리

**1. 정의**
프레임워크는 복잡한 문제를 해결하기 위한 "기본 구조·틀"입니다. 애플리케이션 개발의 뼈대를 제공하며, 라이브러리보다 크고 포괄적입니다.

**2. 왜 필요한가?**
큰 애플리케이션(웹 서비스 등)을 빠르고 일관되게 만들려면, 매번 구조를 새로 짜기보다 정해진 틀 위에서 살을 붙이는 편이 효율적입니다.

**3. 예시**
- 데이터/AI: Pandas, Matplotlib, PyTorch, TensorFlow, Scikit-learn
- 웹 개발 프레임워크: FastAPI, Django, Flask
- 자동화: Selenium, BeautifulSoup

**4. 헷갈리기 쉬운 점**
차이의 핵심은 **제어의 역전(Inversion of Control, IoC)**입니다. 라이브러리는 *내가* 필요할 때 불러서 씁니다(내가 흐름의 주인). 프레임워크는 *프레임워크가* 정한 흐름 안에 내 코드를 끼워 넣습니다(틀이 흐름의 주인). "내가 부르느냐, 불려 가느냐"로 기억하면 쉽습니다.

**5. 한 줄 정리**
라이브러리는 내가 골라 쓰는 도구, 프레임워크는 그 위에서 개발하는 무대입니다.

### 표준 라이브러리 vs 외부 라이브러리

**1. 정의**
- **표준 라이브러리:** 파이썬을 설치하면 함께 깔려 바로 쓸 수 있는 라이브러리
- **외부 라이브러리:** 별도 설치가 필요하며, 보통 PyPI를 통해 배포되는 라이브러리

**2. 왜 필요한가?**
모든 기능을 파이썬에 기본 포함하면 너무 무거워집니다. 그래서 자주 쓰는 기본 기능은 표준으로 제공하고, 특수한 기능은 필요한 사람만 설치하도록 외부로 둡니다.

**3. 예시**
표준 라이브러리에는 텍스트 처리(`string`, `re`), 수학·숫자(`math`, `random`, `statistics`), 파일 입출력(`os`, `csv`, `json`), 날짜·시간(`datetime`, `time`) 등이 있습니다. 외부 라이브러리(pandas, requests 등)는 PyPI에서 설치해 씁니다.

**4. 헷갈리기 쉬운 점**
`math`처럼 표준 라이브러리는 설치 없이 바로 `import`되지만, pandas 같은 외부 라이브러리는 설치하지 않으면 `import` 단계에서 오류가 납니다. import 오류가 나면 "표준인가, 설치가 필요한가"를 먼저 확인하세요.

**5. 한 줄 정리**
표준은 "기본 제공", 외부는 "PyPI에서 골라 설치".

## 코드로 보기 — PyPI라는 거대한 외부 라이브러리 창고

PyPI(Python Package Index)는 파이썬 패키지를 호스팅하고 배포하는 공식 저장소입니다. 등록된 프로젝트가 50만 개를 넘을 만큼 방대합니다. 외부 라이브러리는 대부분 여기를 통해 배포됩니다.

```python
# 표준 라이브러리: 설치 없이 바로 사용
import math
print(math.sqrt(9))   # 3.0

# 외부 라이브러리: PyPI에서 설치한 뒤에야 import 가능
import pandas as pd   # 미설치 시 ModuleNotFoundError
```

**코드목적**
"바로 되는 것"과 "설치가 필요한 것"의 경계를 코드로 확인하는 것이 목적입니다.

**해석**
`math`는 표준이라 어디서든 import됩니다. 반면 `pandas`는 설치돼 있지 않으면 `ModuleNotFoundError`가 납니다. 이 차이를 알면 "왜 어떤 import는 되고 어떤 건 안 되는지"를 스스로 진단할 수 있습니다.

**실무 연결**
새 프로젝트를 시작할 때 가장 먼저 "필요한 외부 라이브러리가 무엇이고, 어디서 설치하는가"를 따집니다. 그 출발점이 PyPI입니다.

## 헷갈리기 쉬운 포인트

- **모듈 vs 패키지:** 모듈은 파일 하나, 패키지는 `__init__.py`를 가진 폴더.
- **라이브러리 vs 프레임워크:** 제어권이 나에게 있으면 라이브러리, 틀에 있으면 프레임워크(IoC).
- **표준 vs 외부:** 표준은 설치 불필요, 외부는 PyPI 설치 필요.

## 셀프 체크

- [ ] 라이브러리의 정의를 한 문장으로 말할 수 있다.
- [ ] 모듈·패키지·라이브러리를 크기 순으로 구분할 수 있다.
- [ ] 패키지에 `__init__.py`가 필요한 이유를 안다.
- [ ] 라이브러리와 프레임워크의 차이(IoC)를 설명할 수 있다.
- [ ] 표준 라이브러리와 외부 라이브러리의 차이를 안다.
- [ ] PyPI가 무엇인지 안다.

**복습 질문 및 답변**

- (기본) 모듈은 무엇인가요? → 함수·클래스·변수를 담은 하나의 파이썬 파일입니다.
- (이해 확인) 라이브러리와 프레임워크의 핵심 차이는? → 제어의 역전(IoC). 라이브러리는 내가 부르고, 프레임워크는 내가 불려 갑니다.
- (응용) `import pandas`가 오류 나는 가장 흔한 이유는? → 외부 라이브러리라 설치가 안 됐거나, 설치된 환경이 달라서입니다.

## 한 줄 정리

> 모듈·패키지·라이브러리는 점점 커지는 코드 묶음이고, 프레임워크는 그 위의 개발 틀이며, 표준은 바로·외부는 PyPI에서 설치해 쓰는 것 — 이것이 라이브러리 세계의 지도입니다.
