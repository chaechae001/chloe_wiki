# 라이브러리 탐색·비교·선택하기

> "데이터 시각화 라이브러리"라고 검색하면 수십 개가 쏟아집니다. 이 중에 무엇을 써야 할까요? 아무거나 골랐다가 6개월 뒤 업데이트가 끊겨 있으면 곤란합니다. 믿을 만한 라이브러리를 고르는 데도 절차가 있습니다.

`필요 기능 정의` `키워드 선정` `GitHub` `PyPI` `Awesome Lists` `비교 평가` `유지보수성`

## 핵심요약

- 라이브러리 탐색은 즉흥이 아니라 "필요 기능 정의 → 키워드 선정 → 탐색 → 비교·평가 → 선택"의 흐름을 따른다.
- 먼저 프로젝트 목표와 필수/선택 기능을 정의하고 우선순위를 매긴다.
- 그 기능을 짧은 키워드로 요약하고, 영어 키워드도 함께 준비하면 검색 결과가 훨씬 풍부해진다.
- 검색 엔진·생성 AI·GitHub·PyPI 네 갈래로 탐색하되, 결과는 항상 검증한다.
- 비교 기준은 기능성·사용 용이성·커뮤니티·라이선스·호환성·유지보수성 여섯 가지다.
- 최종 선택은 "내 우선순위에 가장 잘 맞는" 라이브러리를 고르는 것이다.

## 개념별 정리

### 1단계 — 필요 기능 정의하기

**1. 정의**
무엇을 만들 것인지(목표)와, 그에 필요한 세부 기능을 목록으로 적고 우선순위를 정하는 단계입니다.

**2. 왜 필요한가?**
기능을 명확히 하지 않으면 "그럴듯해 보이는" 라이브러리에 끌려가기 쉽습니다. 먼저 필요한 것을 못 박아야 후보를 제대로 거를 수 있습니다.

**3. 예시**
- 목표: 매출 데이터를 분석한 보고서 작성
- (필수) 엑셀(`.xlsx`) 형태 데이터의 시각화
- (선택) 디자인이 예쁜 그래프, 상호작용 가능한 그래프, 결과를 자유롭게 공유

**4. 헷갈리기 쉬운 점**
"있으면 좋은 것"과 "없으면 안 되는 것"을 섞으면 선택이 어려워집니다. 필수와 선택을 분리하고, 정말 필요한 기능에 높은 우선순위를 줍니다.

**5. 한 줄 정리**
탐색의 출발점은 "내가 무엇이 필요한지"를 분명히 적는 것입니다.

### 2단계 — 키워드 선정하기

**1. 정의**
정의한 기능을 검색에 쓸 짧은 용어로 요약하는 단계입니다. 영어 키워드까지 준비합니다.

**2. 왜 필요한가?**
어떤 키워드를 넣느냐에 따라 검색 결과가 완전히 달라집니다. 좋은 키워드가 좋은 후보를 데려옵니다.

**3. 예시**
- 기본(한글): "파이썬 엑셀 데이터 분석 / 데이터 시각화"
- 추가: "디자인 예쁜, 상호작용, 공유"
- 영어: `python data visualization`, `xlsx file visualization library`, `how to visualize data with python`, `python interactive visualization`

**4. 헷갈리기 쉬운 점**
한글로만 검색하면 결과가 적습니다. 더 많은 자료를 얻으려면 영어 키워드 검색이 거의 필수입니다.

**5. 한 줄 정리**
기능을 키워드로 압축하되, 영어 키워드도 꼭 챙깁니다.

### 3단계 — 탐색하기 (네 갈래)

**1. 정의**
선정한 키워드로 실제 후보를 찾는 단계입니다.

**2. 왜 필요한가?**
같은 키워드라도 어디서 찾느냐에 따라 보이는 정보가 다릅니다. 여러 경로를 함께 쓰면 빈틈이 줄어듭니다.

**3. 예시**
- **검색 엔진(Google 등):** 가장 보편적. 영어 검색이 결과가 많음.
- **생성 AI(ChatGPT 등):** 후보를 빠르게 추리고, 이어지는 질문으로 좁혀 갈 수 있음.
- **GitHub:** 오픈소스 프로젝트의 코드·이슈·반응(star, fork)을 확인. "Awesome Lists"는 주제별로 정리된 커뮤니티 큐레이션 목록.
- **PyPI:** 파이썬 패키지 공식 저장소. 필터·정렬로 주제·라이선스·환경별로 좁히기.

**4. 헷갈리기 쉬운 점**
생성 AI는 편리하지만 **불확실한 정보를 줄 수 있어** 결과 검증이 필수입니다. AI가 알려 준 라이브러리가 실제로 존재하고 유지되는지 공식 출처에서 다시 확인하세요.

**5. 한 줄 정리**
검색 엔진·AI·GitHub·PyPI를 함께 쓰되, 답은 항상 한 번 더 검증합니다.

> 비유: 맛집을 찾을 때 검색·지인 추천·리뷰 앱을 함께 보고, 그래도 직접 가 보고 판단하는 것과 같습니다.

### 4단계 — 비교 및 평가하기

**1. 정의**
탐색으로 추린 후보들을 정해진 기준으로 견주어 보는 단계입니다.

**2. 왜 필요한가?**
"인기 있어 보인다"만으로는 부족합니다. 객관적 기준으로 비교해야 프로젝트에 맞는 선택을 할 수 있습니다.

**3. 예시 — 여섯 가지 평가 기준**
- **기능성:** 내가 필요한 기능을 제공하는가 (공식 문서 확인)
- **사용 용이성:** 문서·레퍼런스가 잘 돼 있는가
- **커뮤니티 및 지원:** GitHub star 수, 이슈 활성도, 공식 커뮤니티
- **라이선스:** 상업적 사용이 가능한가 (반드시 확인)
- **호환성:** 내 파이썬 버전·다른 라이브러리와 충돌하지 않는가
- **유지보수성:** 정기적으로 업데이트되고 버그가 고쳐지는가 (최소 6개월 이내 업데이트 권장)

**4. 헷갈리기 쉬운 점**
모든 기준에서 1등인 라이브러리는 드뭅니다. 내 우선순위(예: 상호작용 > 디자인)를 기준으로 가중치를 두고 비교해야 합니다.

**5. 한 줄 정리**
여섯 기준으로 견주되, 내 우선순위에 맞춰 무게를 다르게 둡니다.

### 5단계 — 선택하기

**1. 정의**
비교 결과 중요 순위를 정해 최종 라이브러리를 고르는 단계입니다.

**2. 왜 필요한가?**
완벽한 정답은 없고, "내 상황에 가장 맞는" 선택이 있을 뿐입니다.

**3. 예시 (시각화 라이브러리)**
- 기본적인 시각화가 필요하면 **Matplotlib**
- 테마·스타일 등 시각적인 부분이 중요하면 **Seaborn**
- 상호작용이나 웹 기반 시각화가 필요하면 **Plotly**

**4. 헷갈리기 쉬운 점**
"남들이 다 쓰니까"가 아니라 "내 우선순위 1번 기능을 가장 잘 만족하는가"로 골라야 합니다. 다만 너무 마이너한 라이브러리는 자료가 적어 나중에 고생할 수 있습니다.

**5. 한 줄 정리**
선택은 내 우선순위 1번을 가장 잘 채우는 후보를 고르는 일입니다.

## 코드로 보기 — 시각화 라이브러리 비교 정리

| 기준 | Matplotlib | Seaborn | Plotly |
| --- | --- | --- | --- |
| 기능성 | 가장 기본, 거의 모든 시각화 요소 사용자 정의 가능 | 통계적 시각화, Matplotlib 기반, 테마·스타일 지원 | 상호작용·웹 기반, 지도·3D 등 다양한 시각화 |
| 사용 용이성 | 문서·레퍼런스 매우 많음 | 문서·레퍼런스 매우 많음 | 문서·레퍼런스 매우 많음 |
| 커뮤니티 | 가장 오래된 만큼 많은 수의 커뮤니티 | 활성화된 커뮤니티 | 활성화된 커뮤니티 |
| 라이선스 | 상업적 사용 허용 | 상업적 사용 허용 | 상업적 사용 허용(MIT) |
| 호환성 | Python >= 3.9 | Python >= 3.8 | Python >= 3.6 |
| 유지보수성 | 오래 개발된 만큼 안정적 | 꾸준한 업데이트 | 매우 잦은 업데이트, 회사가 지원 |

**코드목적**
같은 목적(시각화)을 가진 세 후보를 한 표로 정렬해, 내 우선순위에 맞는 선택을 돕는 것이 목적입니다.

**해석**
어느 하나가 모든 면에서 압도적이지 않습니다. "기본 시각화면 Matplotlib, 스타일이 중요하면 Seaborn, 상호작용·웹이면 Plotly"처럼 내가 무엇을 가장 중시하느냐에 따라 답이 달라집니다.

**실무 연결**
기술 선택 과정을 표로 남겨 두면, 나중에 "왜 이걸 골랐는지" 설명할 근거가 됩니다. 포트폴리오나 기술 보고서에서 이런 비교표는 의사결정 능력을 보여 주는 좋은 자료입니다.

## 직접 해보기

1. "웹에서 표 데이터를 긁어오기"라는 목표로 필요 기능과 키워드(한글·영어)를 적어 보세요.
2. 위 키워드로 PyPI에서 후보를 두 개 찾아, 최근 업데이트 날짜를 비교해 보세요.
3. 그 두 후보를 여섯 기준 표에 채워 보고, 어떤 기준을 가장 중시할지 정해 보세요.

## 헷갈리기 쉬운 포인트

- **한글 검색 vs 영어 검색:** 영어 키워드가 결과가 훨씬 많습니다.
- **AI 추천 vs 검증:** AI 답변은 출발점일 뿐, 공식 출처 확인이 필수입니다.
- **인기 vs 적합:** star가 많아도 내 우선순위에 안 맞으면 좋은 선택이 아닙니다.

## 셀프 체크

- [ ] 탐색의 다섯 단계를 순서대로 말할 수 있다.
- [ ] 필수 기능과 선택 기능을 구분해 적을 수 있다.
- [ ] 영어 키워드를 준비하는 이유를 안다.
- [ ] 탐색 경로 네 가지를 안다.
- [ ] 비교 기준 여섯 가지를 댈 수 있다.
- [ ] AI 답변을 검증해야 하는 이유를 안다.

**복습 질문 및 답변**

- (기본) 탐색의 첫 단계는? → 필요 기능을 정의하고 우선순위를 매기는 것.
- (이해 확인) 유지보수성은 무엇으로 판단하나요? → 최근 업데이트 여부, 버그 수정 빈도, GitHub 이슈 해결 등.
- (응용) 상업 프로젝트에 쓸 라이브러리에서 절대 빠뜨리면 안 되는 확인 항목은? → 라이선스(상업적 사용 허용 여부).

## 한 줄 정리

> 라이브러리 선택은 운이 아니라 절차입니다. 필요를 정의하고, 키워드로 찾고, 여섯 기준으로 비교해, 내 우선순위에 가장 맞는 것을 고르면 됩니다.
