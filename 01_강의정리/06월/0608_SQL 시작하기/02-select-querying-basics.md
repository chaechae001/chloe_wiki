# SELECT — 데이터 조회의 기본

> "테이블 안에 데이터는 잔뜩 있는데, 그중 '제목과 저자만' 보고 싶다면? SELECT 한 줄이면 됩니다."

`SELECT` `FROM` `와일드카드(*)` `DISTINCT` `LIMIT` `데이터 조회` `중복 제거`

## 핵심요약

- `SELECT`는 테이블에서 **원하는 컬럼의 데이터를 꺼내 보는** 명령이다.
- 기본 형태는 `SELECT 컬럼 FROM 테이블;` — "어떤 컬럼을, 어느 테이블에서"의 조합이다.
- 모든 컬럼을 보고 싶으면 컬럼 자리에 `*`(별표, 와일드카드)를 쓴다.
- `DISTINCT`는 뒤따르는 컬럼의 **중복을 제거**하고 보여 준다.
- `DISTINCT` 뒤에 컬럼을 2개 이상 적으면, 둘을 **묶어서** 중복을 판단한다(한 쪽만 같아도 다른 쪽이 다르면 다른 값 취급).
- 데이터가 많을 때는 `LIMIT n`으로 **상위 n개만** 확인할 수 있다.

## 개념 정리

### SELECT / FROM

**1. 정의**
`SELECT`는 '검색(가져오기)' 명령이고, `FROM`은 '어느 테이블에서'를 지정합니다. 둘은 거의 항상 짝으로 다닙니다.

**2. 왜 필요한가?**
테이블에는 컬럼이 여러 개지만, 매번 전부 다 필요한 건 아닙니다. 보고서에는 '제목'과 '저자'만 필요할 수도 있죠. 필요한 컬럼만 콕 집어 가져오면 화면도 깔끔하고 처리도 빨라집니다.

**3. 예시**

```sql
SELECT title, author
FROM book;
```

`book` 테이블에서 모든 책의 `title`(제목)과 `author`(저자) 컬럼을 가져옵니다. 흐름은 이렇습니다.

1. `SELECT title, author` → 가져올 컬럼을 고른다 (제목, 저자)
2. `FROM book` → 어느 테이블에서 가져올지 정한다 (book)
3. 결과로 제목·저자 두 컬럼만 담긴 표를 얻는다

**4. 헷갈리기 쉬운 점**
`SELECT`로 컬럼을 고른다고 해서 원본 테이블이 바뀌는 게 아닙니다. **조회는 '복사해서 보여 주기'일 뿐**, 원본은 그대로 남습니다.

**5. 한 줄 정리**
SELECT는 "이 테이블에서 이 컬럼들을 보여 줘"라는 요청이다.

> 비유: 도서관 사서에게 "이 서가에서 '제목'과 '저자'만 적힌 목록을 뽑아 주세요"라고 부탁하는 것과 같습니다. 책을 가져가는 게 아니라 목록만 받아 보는 거죠.

### 모든 컬럼 가져오기 — `*`

**1. 정의**
컬럼 자리에 `*`(별표)를 쓰면 테이블의 **모든 컬럼**을 가져옵니다. `*`를 와일드카드라고 부릅니다.

**2. 왜 필요한가?**
테이블에 어떤 데이터가 들었는지 통째로 훑어보고 싶을 때, 컬럼 이름을 일일이 쓰지 않고 `*` 하나로 전부 볼 수 있습니다.

**3. 예시**

```sql
SELECT *
FROM book;
```

`book` 테이블의 모든 컬럼(id, title, author, publisher 등)을 전부 가져옵니다.

**4. 헷갈리기 쉬운 점**
`*`는 편하지만, 실무에서 데이터가 많을 때 `SELECT *`를 남발하면 불필요한 컬럼까지 다 끌어와 느려질 수 있습니다. **'전부 다 보기'는 처음 살펴볼 때, '필요한 컬럼만'은 본격적인 작업에** — 라고 기억하면 좋습니다.

**5. 한 줄 정리**
`*`는 "이 테이블의 모든 컬럼을 보여 줘"라는 뜻이다.

> 비유: `*`는 메뉴판에서 "다 주세요"라고 말하는 것과 같습니다. 빠르지만, 정말 다 필요한지는 한 번 생각해 봐야죠.

### DISTINCT — 중복 제거

**1. 정의**
`DISTINCT`는 '뚜렷한, 구별되는'이라는 뜻으로, 뒤에 오는 컬럼의 **중복된 값을 하나로 합쳐** 보여 줍니다.

**2. 왜 필요한가?**
"우리 고객은 어느 나라에 살까?" 같은 질문에는 같은 나라가 수백 번 반복돼도 의미가 없습니다. 중복을 지우면 '종류'만 깔끔하게 볼 수 있습니다.

**3. 예시**

```sql
SELECT DISTINCT title, author
FROM book;
```

검색할 컬럼 앞에 `DISTINCT`를 붙입니다. 결과에서 같은 (제목, 저자) 조합은 한 번씩만 나옵니다.

**4. 헷갈리기 쉬운 점**
`DISTINCT` 뒤에 컬럼을 **2개 이상** 적으면, 컬럼을 따로따로가 아니라 **묶어서** 중복을 판단합니다. 한 쪽 컬럼 값이 같아도 다른 쪽이 다르면 '다른 데이터'로 취급해 둘 다 남습니다.

```text
예) (제목='어린왕자', 저자='생텍쥐페리')  ← 저자가 다르면
    (제목='어린왕자', 저자='홍길동')      ← 둘 다 살아남음
```

**5. 한 줄 정리**
DISTINCT는 "겹치는 건 하나로 합쳐서 종류만 보여 줘"라는 뜻이다.

> 비유: 명함이 잔뜩 든 상자에서 '회사 이름'만 중복 없이 추려 적는 것과 같습니다.

### LIMIT — 상위 N개만 보기

**1. 정의**
`LIMIT n`은 결과를 **위에서 n개까지만** 보여 줍니다.

**2. 왜 필요한가?**
데이터가 수만 건이면 전부 띄우는 것만으로도 느리고 눈에 들어오지도 않습니다. "일단 위에서 10개만 보고 분위기를 파악하자"는 식으로 미리보기처럼 활용합니다.

**3. 예시**

```sql
SELECT *
FROM Tracks
LIMIT 10;
```

`Tracks` 테이블에서 위에서 10개 행만 가져옵니다.

**4. 헷갈리기 쉬운 점**
`LIMIT`은 '내림차순으로 가장 큰 값 10개'를 뜻하지 않습니다. 그냥 **현재 순서 기준 위에서 n개**일 뿐입니다. "점수가 높은 5명"처럼 의미 있는 상위 N개를 뽑으려면 [정렬(ORDER BY)](04-like-orderby-limit.md)과 함께 써야 합니다.

**5. 한 줄 정리**
LIMIT은 "위에서 n개까지만 보여 줘"라는 뜻이다.

> 비유: 검색 결과의 '1페이지만 보기'와 비슷합니다. 전부 다 안 봐도 감을 잡을 수 있죠.

## 코드로 보기 — 음악 판매 데이터로 살펴보기

음악을 판매하는 가게의 데이터베이스(아티스트·앨범·트랙·고객·결제 정보를 담은 표들)를 예로 들어 봅니다.

```sql
-- 1) 전체 데이터 훑어보기
SELECT * FROM Artist;

-- 2) 데이터가 많은 트랙은 위에서 10개만
SELECT * FROM Tracks LIMIT 10;

-- 3) 고객들이 사는 '나라 종류'만 중복 없이
SELECT DISTINCT Country FROM Customers;
```

**코드목적**
어떤 데이터가 들어 있는지(1), 양이 많을 때 미리보기(2), 값의 '종류'만 추리기(3)를 차례로 보여 줍니다.

**해석**
- (1) `Artist` 테이블의 모든 컬럼·모든 행이 나옵니다.
- (2) `Tracks`의 윗부분 10개만 나와 화면이 가벼워집니다.
- (3) 고객 나라가 수천 명이어도 결과에는 'USA, Korea, ...'처럼 **나라 종류**만 한 번씩 나옵니다.

**실무 연결**
데이터 분석의 첫 단추는 거의 항상 "이 데이터가 어떻게 생겼지?"입니다. `SELECT * ... LIMIT`로 모양을 보고, `DISTINCT`로 범주(나라, 등급, 카테고리)의 종류를 파악하는 흐름은 분석·기획·QA 어디서든 그대로 쓰입니다.

## 헷갈리기 쉬운 포인트

- **`SELECT 컬럼` vs `SELECT *`**: 필요한 컬럼만 콕 집기 vs 모든 컬럼 통째로. 본격 작업엔 전자가 깔끔하고 빠름.
- **`DISTINCT 한 컬럼` vs `DISTINCT 여러 컬럼`**: 한 컬럼이면 그 값만으로 중복 판단, 여러 컬럼이면 조합 전체로 중복 판단.
- **`LIMIT` vs '상위권 뽑기'**: LIMIT 단독은 그냥 위에서 n개. 의미 있는 순위는 정렬과 함께.

## 한 줄 정리

> SELECT는 테이블에서 원하는 컬럼을 꺼내는 명령이며, `*`로 전부, `DISTINCT`로 중복 없이, `LIMIT`으로 위에서 일부만 볼 수 있다.
