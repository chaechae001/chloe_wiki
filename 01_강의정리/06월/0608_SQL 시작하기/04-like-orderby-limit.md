# LIKE · ORDER BY · LIMIT — 비슷한 값 찾기와 정렬하기

> "책 제목이 정확히 기억나진 않는데… '왕자'라는 단어가 들어갔던 것 같아요. 이럴 땐 어떻게 찾죠?"

`LIKE` `와일드카드(%)` `패턴 검색` `ORDER BY` `ASC` `DESC` `정렬` `LIMIT`

## 핵심요약

- `LIKE`는 정확히 일치하지 않아도 **특정 문자가 포함/시작/끝나는** 값을 찾는 명령이다.
- 와일드카드 `%`는 '아무 문자나 0개 이상'을 뜻한다. 위치에 따라 의미가 달라진다 — `'어린%'`(시작), `'%왕자'`(끝), `'%린왕%'`(포함).
- `ORDER BY`는 검색 결과를 **정렬**한다. `ASC`는 오름차순(작은 값부터), `DESC`는 내림차순(큰 값부터).
- 정렬 기준을 안 적으면 보통 오름차순이 기본이다.
- `ORDER BY`로 정렬한 뒤 `LIMIT n`을 붙이면 "상위 n개"를 의미 있게 뽑을 수 있다(예: 점수 높은 5명).
- 정렬 명령의 `DESC`는 [1번 글](01-sql-and-relational-database-basics.md)의 '테이블 구조 보기 DESC'와 **이름만 같고 기능이 다르다.**

## 개념 정리

### LIKE — 패턴으로 검색하기

**1. 정의**
`LIKE`는 특정 문자가 포함된 문자열을 찾고 싶을 때 쓰는 조건입니다. `WHERE` 안에서 `=` 대신 사용합니다.

**2. 왜 필요한가?**
`=`는 값이 **완전히 똑같아야** 찾습니다. 하지만 "제목에 '왕자'가 들어간 책"처럼 일부만 아는 경우가 많죠. `LIKE`는 이런 '부분 일치' 검색을 가능하게 합니다.

**3. 예시**

```sql
SELECT *
FROM book
WHERE title LIKE '어린왕자';
```

제목이 '어린왕자'인 책을 찾습니다. (와일드카드 없이 쓰면 `=`와 비슷하게 동작) 진짜 위력은 와일드카드 `%`와 함께 나옵니다.

**4. 헷갈리기 쉬운 점**
`LIKE`는 보통 문자열 컬럼에 씁니다. 또 `%` 없이 쓰면 부분 검색이 되지 않으니, '포함' 검색을 원한다면 `%`를 잊지 말아야 합니다.

**5. 한 줄 정리**
LIKE는 "이 글자가 들어간 값을 찾아 줘"라는 부분 일치 검색이다.

> 비유: 검색창에 단어 일부만 넣어도 관련 결과가 뜨는 것과 비슷합니다.

### 와일드카드 `%`의 위치별 의미

**1. 정의**
`%`는 '여기에 아무 문자나 와도 된다(0글자 포함)'를 뜻하는 만능 기호입니다.

**2. 왜 필요한가?**
앞부분만 아는지, 뒷부분만 아는지, 가운데 일부만 아는지에 따라 검색 방식이 다릅니다. `%`의 위치로 이를 표현합니다.

**3. 예시**

```sql
-- '어린'으로 시작하는 책 (뒤는 무엇이든)
SELECT * FROM book WHERE title LIKE '어린%';

-- '왕자'로 끝나는 책 (앞은 무엇이든)
SELECT * FROM book WHERE title LIKE '%왕자';

-- '린왕'이 어딘가에 포함된 책 (앞뒤 무엇이든)
SELECT * FROM book WHERE title LIKE '%린왕%';
```

`book` 테이블에 `어린왕자`, `돈키호테`가 있다면 `'%왕자'`는 '왕자'로 끝나는 `어린왕자`만 찾아냅니다.

**4. 헷갈리기 쉬운 점**
`%`의 위치를 헷갈리면 결과가 완전히 달라집니다. 핵심은 **"%는 그 자리에 글자가 더 있어도 된다"**는 것. `'어린%'`은 '어린'으로 시작만 하면 되고, `'%어린'`은 '어린'으로 끝나야 합니다.

```text
'어린%'   → 어린○○○  (시작)
'%왕자'   → ○○○왕자  (끝)
'%린왕%'  → ○○린왕○○ (포함)
```

**5. 한 줄 정리**
`%`는 '아무 문자나' — 앞에 붙으면 끝 검색, 뒤에 붙으면 시작 검색, 양쪽에 붙으면 포함 검색.

> 비유: 빈칸 채우기 문제의 빈칸과 같습니다. `어린___`은 '어린'으로 시작만 하면 무엇이든 정답.

### ORDER BY — 결과 정렬하기

**1. 정의**
`ORDER BY`는 검색 결과를 특정 컬럼 기준으로 **정렬**해서 출력하는 명령입니다.

**2. 왜 필요한가?**
"수학 점수가 높은 학생부터 보고 싶다", "비싼 곡부터 듣고 싶다" 같은 요청은 단순 검색만으로는 안 됩니다. 결과를 **순서대로 늘어놓는** 일이 필요하죠.

**3. 예시**

```sql
SELECT *
FROM score
ORDER BY math DESC;
```

`score` 테이블을 수학(`math`) 점수가 **높은 순(내림차순)**으로 정렬합니다.

| korean | math | english |
| --- | --- | --- |
| 90 | 96 | 92 |
| 88 | 80 | 71 |
| 100 | 78 | 88 |

수학 점수 96 → 80 → 78 순으로 줄이 재배열된 것을 볼 수 있습니다(국어·영어 값은 그 행을 따라 함께 움직입니다).

**4. 헷갈리기 쉬운 점**
`ORDER BY`는 **데이터를 보여 주는 순서만** 바꿉니다. 원본 테이블의 저장 순서가 바뀌는 게 아닙니다.

**5. 한 줄 정리**
ORDER BY는 "이 컬럼 기준으로 줄 세워서 보여 줘"라는 정렬 명령이다.

> 비유: 사진을 날짜순/이름순으로 보기 옵션을 바꾸는 것과 같습니다. 사진 자체가 바뀌는 건 아니죠.

### ASC / DESC — 오름차순과 내림차순

**1. 정의**
`ASC`는 오름차순(작은 값 → 큰 값), `DESC`는 내림차순(큰 값 → 작은 값)입니다.

**2. 왜 필요한가?**
'점수 낮은 순으로 보충 대상 찾기'에는 오름차순, '매출 높은 순으로 베스트 보기'에는 내림차순처럼, 목적에 따라 방향이 달라집니다.

**3. 예시**

```sql
SELECT *
FROM score
ORDER BY math ASC;
```

수학 점수가 **낮은 순(오름차순)**으로 정렬합니다.

```text
ASC  = 오름차순 (작은 값부터)
DESC = 내림차순 (큰 값부터)
```

**4. 헷갈리기 쉬운 점**
정렬의 `DESC`는 [1번 글에서 본 `DESC 테이블명`(테이블 구조 보기)](01-sql-and-relational-database-basics.md)과 **철자만 같고 기능이 완전히 다릅니다.** 위치로 구분하세요 — `ORDER BY 컬럼 DESC`면 내림차순, 단독 `DESC 테이블명`이면 구조 보기.

**5. 한 줄 정리**
ASC는 작은 값부터, DESC는 큰 값부터.

> 비유: 키 작은 사람부터 줄 세우기(ASC) vs 키 큰 사람부터 줄 세우기(DESC).

### LIMIT과의 조합 — 의미 있는 '상위 N개'

**1. 정의**
`ORDER BY`로 정렬한 뒤 `LIMIT n`을 붙이면, 정렬 기준에서 **상위 n개**만 뽑을 수 있습니다.

**2. 왜 필요한가?**
"수학을 가장 잘한 학생 5명"은 (1) 수학 점수로 내림차순 정렬하고 (2) 위에서 5명만 자르면 됩니다. 정렬 없이 `LIMIT`만 쓰면 그냥 위에서 5개일 뿐, '잘한 5명'이 아닙니다.

**3. 예시**

```sql
SELECT *
FROM score
ORDER BY math DESC
LIMIT 5;
```

수학 점수가 높은 순으로 정렬한 다음, 상위 5명만 가져옵니다.

**4. 헷갈리기 쉬운 점**
순서가 중요합니다. **정렬(ORDER BY)을 먼저, 자르기(LIMIT)를 나중에** 적용한다고 생각하면 됩니다. 정렬을 빼면 '상위'의 의미가 사라집니다.

**5. 한 줄 정리**
'의미 있는 상위 N개' = ORDER BY(정렬) + LIMIT(자르기).

> 비유: 시험 점수로 줄을 세운 뒤(정렬), 앞에서 5명만 호명(자르기)하는 것과 같습니다.

## 코드로 보기 — 음악 판매 데이터로 패턴 검색과 정렬

```sql
-- 1) 앨범 제목이 'Rock'으로 시작하는 항목
SELECT * FROM Album WHERE Title LIKE 'Rock%';

-- 2) 트랙 이름에 'Love'가 포함된 항목, 위에서 10개만
SELECT * FROM Tracks WHERE Name LIKE '%Love%' LIMIT 10;

-- 3) 단가가 비싼 곡부터 정렬
SELECT * FROM Tracks ORDER BY UnitPrice DESC;
```

**코드목적**
시작 패턴 검색(1), 포함 검색 + 미리보기(2), 내림차순 정렬(3)을 한눈에 보여 줍니다.

**해석**
- (1) 'Rock'으로 시작하는 앨범만 추려집니다(`Rock`, `Rock Ballads` 등).
- (2) 이름 어딘가에 'Love'가 든 트랙을, 일단 10개만 미리 봅니다.
- (3) 가장 비싼 단가의 곡이 맨 위에 옵니다.

**실무 연결**
검색창의 자동완성·연관검색, 베스트셀러/인기 랭킹, "최근 가입순" 회원 목록 — 사용자에게 보여 주는 거의 모든 '목록 화면'이 `LIKE`(검색)와 `ORDER BY`+`LIMIT`(정렬·상위 노출)의 조합으로 만들어집니다.

## 헷갈리기 쉬운 포인트

- **`=` vs `LIKE`**: 완전 일치(`=`) vs 부분 일치(`LIKE` + `%`).
- **`'어린%'` vs `'%어린'`**: 시작 검색 vs 끝 검색. `%`의 위치가 의미를 바꿈.
- **`ASC` vs `DESC`(정렬)**: 작은 값부터 vs 큰 값부터.
- **`DESC`(정렬) vs `DESC`(구조 보기)**: 같은 단어, 다른 기능. `ORDER BY ... DESC`인지 `DESC 테이블명`인지 위치로 구분.
- **`LIMIT` 단독 vs `ORDER BY` + `LIMIT`**: 그냥 위에서 n개 vs 정렬 기준 상위 n개.

## 셀프 체크

- [ ] `LIKE`가 부분 일치 검색이라는 걸 안다.
- [ ] `%`의 위치(앞/뒤/양쪽)에 따른 의미를 구분할 수 있다.
- [ ] `ORDER BY`로 정렬하는 방법을 안다.
- [ ] `ASC`와 `DESC`의 방향을 헷갈리지 않는다.
- [ ] '상위 N개'를 뽑으려면 정렬 + LIMIT이 필요하다는 걸 안다.

  - `WHERE title LIKE '%왕자';`
- (이해 확인) `ORDER BY math DESC`와 `ORDER BY math ASC`의 차이는?
  - 전자는 수학 점수 높은 순(내림차순), 후자는 낮은 순(오름차순).

  - `SELECT * FROM score ORDER BY math DESC LIMIT 5;`

## 한 줄 정리

> LIKE는 `%`로 부분 일치를 검색하고, ORDER BY는 결과를 `ASC`/`DESC`로 정렬하며, 정렬에 LIMIT을 더하면 의미 있는 '상위 N개'를 얻는다.
