# 이상 현상과 함수 종속 — 왜 정규화가 필요한가

> 데이터를 한 테이블에 몰아넣으면 처음엔 편합니다. 그런데 회원 이름 하나 바꾸려다 데이터가 어긋나고, 대여 기록 하나 지웠더니 고객까지 사라진다면? 이 글은 그 "사고"가 왜 일어나는지를 코드로 직접 보여줍니다.

`이상현상` `삽입이상` `갱신이상` `삭제이상` `함수종속` `결정자` `종속자` `정규화`

## 핵심요약

- 잘못된 데이터베이스 설계는 데이터를 넣고·고치고·지울 때 의도치 않은 부작용을 만든다. 이를 **이상 현상(Anomaly)** 이라고 한다.
- 이상 현상에는 **삽입 이상, 갱신 이상, 삭제 이상** 세 종류가 있다.
- 이상 현상의 근본 원인은 **서로 다른 성격의 데이터가 한 테이블에 뒤섞여 중복 저장**되기 때문이다.
- 이 중복·종속 관계를 이론적으로 설명하는 도구가 **함수 종속(Functional Dependency)** 이다.
- 어떤 속성 X의 값이 다른 속성 Y의 값을 유일하게 정한다면 `X → Y`로 쓰고, X를 **결정자**, Y를 **종속자**라고 한다.
- 함수 종속을 이해해야 어떤 정보를 어떤 테이블로 분리할지, 즉 **정규화**를 할 수 있다.

## 개념별 정리

### 이상 현상 (Anomaly)

**1. 정의**
잘못 설계된 테이블에서 데이터를 조작할 때 발생하는 논리적 오류입니다. "분명히 정상적인 작업인데 데이터가 이상해지는" 상황을 가리킵니다.

**2. 왜 필요한가?**
이상 현상을 알아야 "지금 이 테이블 설계가 위험하다"는 걸 판단할 수 있습니다. 실무에서는 서비스가 커진 뒤에야 데이터 불일치가 터지는 경우가 많아서, 설계 단계에서 이 위험을 미리 읽어내는 안목이 중요합니다.

**3. 예시**
모든 정보를 한 테이블에 담은 공유 킥보드 데이터입니다. 한 행에 고객·대여·킥보드 정보가 전부 섞여 있습니다.

```python
import sqlite3, pandas as pd
conn = sqlite3.connect(":memory:")

conn.executescript("""
CREATE TABLE customer_unnormalized (
    customer_id TEXT, customer_name TEXT,
    rental_time TEXT, rental_location TEXT,
    brand TEXT, model_year INTEGER,
    price_per_min INTEGER, basic_price INTEGER, company TEXT
);
INSERT INTO customer_unnormalized VALUES
 ('kmax6','김민준','2020-08-20 13:01:02, 2020-09-01 20:39:52','서울시 강남구 역삼동','boardkick',2015,100,1000,'rideon'),
 ('flykite','이서연','2020-11-11 22:01:30','서울시 동작구 대방동','willgo',2018,110,950,'everythere');
""")
```

이 테이블에서 세 가지 사고가 차례로 일어납니다.

```python
# 삽입 이상: 대여 이력이 없는 신규 고객을 넣으면?
conn.execute("INSERT INTO customer_unnormalized (customer_id, customer_name) VALUES ('newuser','최신규')")
print(pd.read_sql_query("SELECT * FROM customer_unnormalized WHERE customer_id='newuser'", conn))
```

```text
  customer_id customer_name rental_time rental_location brand model_year  \
0     newuser           최신규        None            None  None       None
  price_per_min basic_price company
0          None        None    None
```

대여 정보가 전부 `None(NULL)`인 채로 들어갑니다. 이 고객이 킥보드를 빌린 건지 안 빌린 건지조차 알 수 없게 됩니다. 이것이 **삽입 이상**입니다.

```python
# 갱신 이상: 'kmax6' 이름을 바꾸는데 실수로 한 행만 수정하면?
conn.execute("""UPDATE customer_unnormalized SET customer_name='김민'
                WHERE customer_id='kmax6'
                AND rental_time='2020-08-20 13:01:02, 2020-09-01 20:39:52'""")
print(pd.read_sql_query("SELECT customer_id, customer_name FROM customer_unnormalized WHERE customer_id='kmax6'", conn))
```

같은 ID인데 이름이 일부만 바뀌어 데이터가 어긋납니다. 이름이 여러 행에 중복 저장되어 있기 때문이며, 이것이 **갱신 이상**입니다.

```python
# 삭제 이상: 'flykite'의 대여 기록을 지우면?
conn.execute("DELETE FROM customer_unnormalized WHERE customer_id='flykite'")
```

대여 기록을 지웠을 뿐인데 **이서연 고객 정보 자체가 통째로 사라집니다.** 고객과 대여가 한 행에 묶여 있어서 생기는 **삭제 이상**입니다.

**4. 헷갈리기 쉬운 점**
세 가지를 "넣을 때 / 고칠 때 / 지울 때"로 외우면 쉽습니다. 흔한 오해는 "데이터가 중복되면 용량만 좀 더 쓰는 정도"라고 생각하는 것인데, 진짜 문제는 용량이 아니라 **중복된 값 사이에 불일치가 생기는 것**입니다.

**5. 한 줄 정리**
이상 현상은 "서로 다른 정보를 한 테이블에 욱여넣어서" 생기는, 넣기·고치기·지우기의 부작용입니다.

> 비유: 한 장의 종이에 친구 연락처와 그 친구와 만난 약속 기록을 같이 적어두면, 약속을 지우개로 지우다 연락처까지 지워지는 것과 같습니다.

### 함수 종속 (Functional Dependency)

**1. 정의**
어떤 속성 X의 한 값이 다른 속성 Y의 값을 항상 하나로 정한다면, "Y는 X에 함수적으로 종속된다"고 하고 `X → Y`로 적습니다. 이때 정하는 쪽 X를 **결정자**, 정해지는 쪽 Y를 **종속자**라고 합니다.

**2. 왜 필요한가?**
정규화는 결국 "어떤 속성이 어떤 속성을 결정하는가"를 보고 테이블을 쪼개는 작업입니다. 함수 종속이라는 언어가 없으면 "왜 이 컬럼을 떼어내야 하는지"를 설명할 수 없습니다.

**3. 예시**
킥보드 데이터에서 `고객 ID`를 알면 `고객 이름`이 하나로 정해집니다.

```text
고객 ID → 고객 이름        (kmax6 → 김민준)
브랜드  → 회사명           (boardkick → rideon)
브랜드  → 분당 가격, 기본료
```

종속의 성격에 따라 이름이 붙습니다.

- **완전 함수 종속**: 기본키(복합키)를 구성하는 속성 *전체*가 있어야 결정되는 경우
- **부분 함수 종속**: 복합키의 *일부* 속성만으로 결정되는 경우 (예: `(고객ID, 대여시간)`이 키인데 이름은 `고객ID`만으로 결정됨)
- **이행 함수 종속**: `X → Y`이고 `Y → Z`라서 결국 `X → Z`가 성립하는, 한 다리 건너 결정되는 경우 (예: `대여기록 → 브랜드 → 회사명`)

**4. 헷갈리기 쉬운 점**
"부분"과 "이행"을 자주 혼동합니다. **부분 함수 종속은 키의 조각 문제**(복합키 일부만으로 결정), **이행 함수 종속은 다리 건너 문제**(키가 아닌 속성이 또 다른 속성을 결정)입니다. 이 둘이 각각 2NF와 3NF에서 제거 대상이 됩니다.

**5. 한 줄 정리**
함수 종속은 "A를 알면 B가 자동으로 정해진다"는 관계이고, 정규화는 이 관계를 보고 테이블을 분리하는 일입니다.

> 비유: 주민등록번호(결정자)를 알면 생년월일(종속자)이 자동으로 정해지는 것과 같습니다.

## 코드로 보기 — 정규화 전후 한눈에 비교

```python
summary = {
    "단계": ["비정규화", "1NF", "2NF", "3NF"],
    "테이블 수": [1, 1, 2, 3],
    "제거된 문제": ["없음", "다중값 컬럼 제거(원자값)", "부분 함수 종속 제거", "이행 함수 종속 제거"],
    "남은 이상 현상": ["삽입/갱신/삭제 모두 존재", "갱신/삭제 여전히 존재", "일부 해소, 이행 종속 남음", "없음"],
}
print(pd.DataFrame(summary))
```

```text
     단계  테이블 수              제거된 문제           남은 이상 현상
0  비정규화      1                  없음  삽입/갱신/삭제 이상 모두 존재
1   1NF      1  다중값 컬럼 제거(원자값)    갱신/삭제 이상 여전히 존재
2   2NF      2         부분 함수 종속 제거    일부 해소, 이행 종속 남음
3   3NF      3         이행 함수 종속 제거                없음
```

**코드목적**
정규화가 한 번에 끝나는 게 아니라, 단계마다 "어떤 종속을 없애 어떤 이상을 해소하는지"를 한 장으로 보여주기 위한 요약입니다.

**해석**
단계가 올라갈수록 테이블 수가 늘어나는 대신, 남아 있는 이상 현상이 줄어듭니다. 3NF에 도달하면 세 가지 이상 현상이 모두 사라집니다.

**실무 연결**
서비스 기획·데이터 분석에서 "이 데이터를 어떻게 저장해야 나중에 안 깨질까"를 판단하는 출발점입니다. 회원·주문·상품을 한 테이블에 담을지 분리할지 결정할 때 바로 이 사고를 씁니다.

## 헷갈리기 쉬운 포인트

- **부분 함수 종속 vs 이행 함수 종속**: 부분은 *복합키의 일부*만으로 결정되는 것, 이행은 *키가 아닌 속성*이 또 다른 속성을 결정하는 것.
- **중복 vs 종속**: 중복은 "같은 값이 여러 번 저장된 현상", 종속은 "그 중복을 만들어내는 원인 관계". 종속을 끊으면 중복이 사라집니다.

## 셀프 체크

- [ ] 삽입·갱신·삭제 이상을 각각 한 문장으로 설명할 수 있다.
- [ ] 결정자와 종속자를 예를 들어 구분할 수 있다.
- [ ] 완전·부분·이행 함수 종속의 차이를 안다.
- [ ] 이상 현상의 근본 원인이 "중복 저장"임을 설명할 수 있다.

**복습 질문 및 답변**

- (기본) 갱신 이상이란? → 같은 사실이 여러 행에 중복 저장되어, 일부만 수정하면 데이터가 불일치하는 현상.
- (이해확인) `brand → company`에서 결정자와 종속자는? → 결정자는 brand, 종속자는 company.
- (응용) 회원 한 명이 게시글을 여러 개 쓴 서비스에서, 회원 정보와 게시글을 한 테이블에 두면 어떤 이상이 가장 먼저 문제가 될까? → 회원 정보가 게시글 수만큼 중복되어 갱신 이상, 그리고 게시글을 다 지우면 회원이 사라지는 삭제 이상.

## 한 줄 정리

> 이상 현상은 한 테이블에 정보를 몰아넣어 생기는 부작용이고, 그 원인인 함수 종속을 읽어내는 것이 정규화의 출발점입니다.
