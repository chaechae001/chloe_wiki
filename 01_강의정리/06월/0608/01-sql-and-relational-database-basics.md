# SQL과 관계형 데이터베이스 기초 — 데이터는 어떤 '표'에 담길까?

> "엑셀 표를 한 번이라도 본 적 있다면, 데이터베이스의 절반은 이미 이해한 셈입니다."

`SQL` `데이터베이스` `관계형 데이터베이스` `테이블` `컬럼` `레코드` `쿼리`

## 핵심요약

- **데이터베이스**는 여러 사람이 공유해 쓰려고 통합·관리하는 데이터의 모음이다.
- 데이터베이스에는 여러 종류(MariaDB, Amazon Redshift, Oracle DB 등)가 있지만, 검색·분석의 **기본 사용법은 종류와 상관없이 거의 같다.**
- **SQL**(Structured Query Language)은 데이터베이스에 접근하고 조작하기 위한 표준 언어다.
- 가장 많이 쓰이는 형태는 **관계형 데이터베이스**로, 서로 연결된 여러 개의 **테이블(표)**로 이루어진다.
- 테이블은 **컬럼(세로 항목)**과 **레코드(가로 한 줄)**로 구성되고, 모든 테이블은 고유한 이름으로 구분된다.
- 컴퓨터에게 내리는 SQL 명령 한 덩어리를 **쿼리(query)**라고 부른다.

## 개념 정리

### 데이터베이스

**1. 정의**
여러 사람이 함께 쓰기 위해, 흩어지지 않게 한곳에 통합해서 관리하는 데이터의 모음입니다.

**2. 왜 필요한가?**
데이터가 사람마다 다른 파일에 흩어져 있으면 같은 정보가 제각각이 되고, 누가 최신인지도 알 수 없습니다. 데이터베이스는 '믿을 수 있는 단일 출처'를 만들어 줍니다. 쇼핑몰의 주문 내역, 도서관의 대여 기록, 회사의 직원 정보처럼 여러 사람이 동시에 보고 갱신하는 데이터는 거의 다 데이터베이스에 들어 있습니다.

**3. 예시**
세상에는 MariaDB, Amazon Redshift, Oracle DB 등 수많은 데이터베이스 제품이 있습니다. 하지만 이 모든 걸 다 배울 필요는 없습니다. 검색과 분석에 쓰는 기본 문법은 제품이 달라도 거의 동일하기 때문입니다.

**4. 헷갈리기 쉬운 점**
'데이터베이스'와 'SQL'을 같은 것으로 오해하기 쉽습니다. 데이터베이스는 데이터가 담긴 **창고**, SQL은 그 창고에 무언가를 시키는 **명령어**입니다.

**5. 한 줄 정리**
데이터베이스는 여러 사람이 공유하는, 잘 정리된 데이터 창고다.

> 비유: 데이터베이스는 도서관입니다. 책(데이터)이 아무 데나 쌓여 있는 게 아니라, 규칙에 따라 정리되어 누구나 찾아볼 수 있게 되어 있죠.

### 관계형 데이터베이스

**1. 정의**
하나 이상의 **테이블(표)**로 이루어지고, 그 표들이 서로 연결된 데이터를 가지는 데이터베이스입니다. SQL로 제어합니다.

**2. 왜 필요한가?**
현실의 정보는 한 장의 표로 다 담기 어렵습니다. 예를 들어 도서관에는 '책 정보'도 있고 '회원 정보'도 있고 '누가 무슨 책을 빌렸는지'도 있습니다. 이걸 표 하나에 욱여넣으면 같은 정보가 계속 중복됩니다. 그래서 표를 역할별로 나누고, 표끼리 연결(관계)해 둡니다.

**3. 예시**
도서관 데이터베이스는 보통 이렇게 나뉩니다.

```text
book   : 책 정보            (id, title, author, publisher, date_received)
user   : 회원 정보          (id, name, email, phone, address)
rental : 대여 기록(연결고리) (id, book_id, user_id, rental_begin_date, rental_end_date)
```

`rental` 테이블이 `book_id`로는 책과, `user_id`로는 회원과 연결됩니다. 즉 "누가, 어떤 책을, 언제 빌렸는지"가 표 세 개의 연결로 표현됩니다.

**4. 헷갈리기 쉬운 점**
'관계형'이라는 말 때문에 사람 사이의 관계 같은 걸 떠올리기 쉽지만, 여기서 '관계'는 **표와 표가 서로 연결되어 있다**는 뜻입니다.

**5. 한 줄 정리**
관계형 데이터베이스 = 서로 연결된 여러 개의 표.

> 비유: 표 하나하나가 부서라면, 관계는 부서 간에 오가는 결재 라인입니다. 각자 맡은 일이 다르지만 연결되어 하나의 조직으로 움직입니다.

### SQL

**1. 정의**
Structured Query Language의 약자로, 데이터베이스에 **접근하고 조작**하기 위한 표준 언어입니다.

**2. 왜 필요한가?**
데이터를 마우스 클릭만으로 다루기엔 양도 많고 조건도 복잡합니다. "출판사가 A이면서 2024년 이후에 들어온 책만 보여줘" 같은 요청을 사람이 손으로 거르려면 끝이 없죠. SQL은 이런 요청을 짧은 문장으로 컴퓨터에 시킬 수 있게 합니다.

**3. 예시**
SQL로 할 수 있는 대표적인 일들입니다.

```text
1. 데이터 검색 (가장 먼저, 가장 많이 배우는 부분)
2. 데이터 삽입
3. 데이터 수정
4. 데이터 삭제
5. 데이터베이스 생성
6. 테이블 생성
7. 그 외 다수
```

가장 먼저 익힐 것은 **데이터 검색**입니다.

**4. 헷갈리기 쉬운 점**
SQL은 특정 회사의 프로그램이 아니라 '표준 언어'입니다. 다만 제품마다 사소한 문법 차이(예: 세미콜론 처리, 일부 함수 이름)가 있을 수 있어, 같은 SQL이 어떤 환경에서는 조금 다르게 동작하기도 합니다. 기본 개념은 공통입니다.

**5. 한 줄 정리**
SQL은 데이터베이스에 일을 시키는 표준 명령 언어다.

> 비유: 데이터베이스가 외국에 있는 거대한 창고라면, SQL은 그 창고 직원들이 모두 알아듣는 공용어입니다.

### 테이블의 구성요소 — 컬럼과 레코드

**1. 정의**
테이블은 **컬럼(Column)**과 **레코드(Record)**로 구성된 표입니다. 컬럼은 세로 방향의 '항목 종류', 레코드는 가로 방향의 '데이터 한 줄'입니다.

**2. 왜 필요한가?**
데이터를 표로 정리하면 '무엇을(컬럼)' '얼마나 많이(레코드)' 가지고 있는지 한눈에 보입니다. SQL 명령은 결국 "어떤 컬럼을, 어떤 조건의 레코드에서 꺼낼까/바꿀까"를 정하는 일입니다.

**3. 예시**

| 사번 | 이름 | 성별 |
| --- | --- | --- |
| 001 | 홍길동 | 남성 |
| 002 | 김철수 | 남성 |
| 003 | 김영희 | 여성 |

- **컬럼**: `사번`, `이름`, `성별` (세로 항목)
- **레코드**: `001 / 홍길동 / 남성` 같은 가로 한 줄
- 모든 테이블은 `Employees`처럼 **고유한 이름**으로 구분됩니다.

**4. 헷갈리기 쉬운 점**
컬럼과 레코드를 반대로 떠올리기 쉽습니다. **컬럼은 표의 '머리글(세로 줄기)', 레코드는 '한 사람/한 건의 데이터(가로 줄)'**라고 기억하세요.

**5. 한 줄 정리**
컬럼은 항목, 레코드는 한 줄의 데이터다.

> 비유: 출석부에서 '이름·번호·점수'가 컬럼이고, 학생 한 명 한 명의 줄이 레코드입니다.

## 코드로 보기 — 테이블 구조 살펴보기

본격적인 검색에 앞서, 테이블이 어떤 컬럼으로 생겼는지 먼저 확인할 수 있습니다.

```sql
DESC Employees;
```

**코드목적**
`Employees` 테이블이 어떤 컬럼들로 이루어져 있는지(구조)를 확인하기 위한 명령입니다. `DESC`는 '대상(테이블)을 설명(describe)하라'는 명령, `Employees`는 그 대상입니다.

**해석**
이 명령을 실행하면 테이블에 어떤 컬럼이 있고 각 컬럼이 어떤 형태의 값을 담는지 보여줍니다. 데이터를 꺼내기 전에 "이 표에 무슨 항목이 있더라?"를 먼저 점검하는 단계입니다.

**실무 연결**
실무에서 처음 보는 데이터베이스를 만나면, 곧장 데이터를 뽑기보다 테이블 구조부터 파악하는 게 순서입니다. 어떤 컬럼이 있는지 알아야 무엇을 검색·분석할 수 있는지 가늠할 수 있습니다.

> 주의: 여기서 본 `DESC`(테이블 구조 보기)는 뒤에서 배울 정렬 명령의 `DESC`(내림차순)와 **철자만 같고 기능이 완전히 다릅니다.** 자세한 차이는 [4번 글](04-like-orderby-limit.md)에서 다룹니다.

## 헷갈리기 쉬운 포인트

- **데이터베이스 vs SQL**: 데이터가 담긴 창고(데이터베이스) vs 창고에 일을 시키는 언어(SQL).
- **컬럼 vs 레코드**: 세로 항목(컬럼) vs 가로 한 줄의 데이터(레코드).
- **DESC(구조 보기) vs DESC(내림차순)**: 철자는 같지만 쓰임이 전혀 다름. 위치로 구분 — 단독으로 `DESC 테이블명`이면 구조 보기, `ORDER BY 컬럼 DESC`면 내림차순 정렬.

**복습 질문 및 답변**

- (기본) SQL은 무엇의 약자인가요?
  - Structured Query Language. 데이터베이스에 접근·조작하기 위한 표준 언어입니다.
- (이해 확인) 관계형 데이터베이스에서 '관계'는 무엇을 뜻하나요?
  - 사람 관계가 아니라, **테이블과 테이블이 서로 연결되어 있다**는 뜻입니다.
- (응용) 도서관에서 '대여 기록'을 별도 테이블로 두는 이유는 무엇일까요?
  - 책 정보와 회원 정보를 매번 중복 저장하지 않고, 두 표를 연결만 해서 "누가 무슨 책을 빌렸는지"를 효율적으로 표현하기 위함입니다.

## 한 줄 정리

> 데이터는 '서로 연결된 표(관계형 데이터베이스)'에 컬럼과 레코드로 담기고, 그 표를 다루는 표준 언어가 SQL이다.
