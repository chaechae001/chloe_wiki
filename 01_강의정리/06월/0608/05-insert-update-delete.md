# INSERT · UPDATE · DELETE — 데이터 추가·수정·삭제 (DML)

> "지금까지는 데이터를 '꺼내 보기'만 했습니다. 이제 직접 넣고, 고치고, 지워 봅니다. 단, 한 글자를 빠뜨리면 표 전체가 날아갈 수도 있어요."

`INSERT` `VALUES` `UPDATE` `SET` `DELETE` `DML` `CRUD`

## 핵심요약

- 데이터를 직접 바꾸는 명령들을 묶어 **DML(데이터 조작어, Data Manipulation Language)**이라 한다.
- `INSERT`는 테이블에 새 데이터를 **추가**, `UPDATE`는 저장된 값을 **수정**, `DELETE`는 데이터를 **삭제**한다.
- 이 세 가지에 조회(`SELECT`)를 더한 것이 데이터 다루기의 4대 동작 **CRUD**(Create / Read / Update / Delete)다.
- `UPDATE`와 `DELETE`에서 **`WHERE` 조건을 빠뜨리면 테이블 전체가 바뀌거나 삭제**된다 — 가장 주의해야 할 지점.
- 작업 후에는 항상 `SELECT`로 결과를 확인하는 습관이 안전하다.

## 개념 정리

### CRUD와 DML — 큰 그림

**1. 정의**
**CRUD**는 데이터 다루기의 네 가지 기본 동작입니다 — Create(생성), Read(조회), Update(수정), Delete(삭제). 이 중 데이터를 직접 바꾸는 명령(INSERT/UPDATE/DELETE)을 **DML**이라 부릅니다.

**2. 왜 필요한가?**
데이터는 한 번 넣고 끝이 아닙니다. 새 회원이 가입하고(추가), 주소가 바뀌고(수정), 탈퇴하면 정보를 지워야(삭제) 합니다. CRUD는 거의 모든 데이터 시스템의 뼈대입니다.

**3. 예시**

```text
Create → INSERT (새 데이터 추가)
Read   → SELECT (데이터 조회)        ← 1~4번 글에서 다룬 부분
Update → UPDATE (값 수정)
Delete → DELETE (데이터 삭제)
```

**4. 헷갈리기 쉬운 점**
CRUD 자체는 어렵지 않습니다. 실제로 까다로운 부분은 '여러 테이블을 어떻게 조합하고, 어떤 조건으로 거를까'를 설계하는 일입니다. 명령어 암기보다 **조건 설계**가 핵심입니다.

**5. 한 줄 정리**
CRUD = 만들고(C) 읽고(R) 고치고(U) 지우는(D) 4대 동작, 그중 쓰기 작업이 DML.

> 비유: 게시판을 떠올리면 쉽습니다. 글 쓰기(Create), 글 읽기(Read), 글 수정(Update), 글 삭제(Delete).

### INSERT — 데이터 추가

**1. 정의**
`INSERT`는 관계형 데이터베이스의 테이블에 새로운 값을 **저장(추가)**하는 명령입니다.

**2. 왜 필요한가?**
도서관에 새 책이 들어오면 목록에 등록해야 합니다. 회원이 가입하면 회원 표에 한 줄을 추가해야 하죠. 새 데이터를 쌓는 모든 일이 `INSERT`입니다.

**3. 예시**

```sql
INSERT INTO book(id, title, author, publisher)
VALUES('3', '햄릿', '윌리엄 셰익스피어', '새벽출판');
```

`book` 테이블에 '햄릿' 책 데이터를 추가합니다. 흐름은 이렇습니다.

1. `INSERT INTO book(...)` → 어느 테이블의, 어떤 컬럼에 넣을지 지정
2. `VALUES(...)` → 그 컬럼 순서대로 넣을 값을 적음
3. 결과로 표 맨 아래 새 줄이 생김

| id | title | author | publisher |
| --- | --- | --- | --- |
| 1 | 어린왕자 | 생텍쥐페리 | 새벽출판 |
| 2 | 돈키호테 | 미겔 데 세르반테스 | 새벽출판 |
| **3** | **햄릿** | **윌리엄 셰익스피어** | **새벽출판** |

**4. 헷갈리기 쉬운 점**
- 컬럼 목록을 **생략하면 테이블의 컬럼 순서대로** 값이 들어갑니다. 즉 `INSERT INTO book VALUES('3','햄릿',...)`처럼 쓸 수 있지만, 순서가 어긋나면 엉뚱한 컬럼에 값이 들어가니 주의해야 합니다.
- 컬럼 개수와 값 개수가 **다르면 오류**가 납니다.
- 값에 작은따옴표(`'`)가 들어가는 경우(예: 영어 이름 `O'Brien`)는 따옴표 처리(이스케이프)가 필요합니다.

**5. 한 줄 정리**
INSERT는 "이 테이블에 이런 값을 한 줄 추가해 줘"라는 명령이다.

> 비유: 출석부 맨 아래에 새 학생 한 줄을 적어 넣는 것과 같습니다.

### UPDATE — 데이터 수정

**1. 정의**
`UPDATE`는 테이블에 **이미 저장된 값을 수정**하는 명령입니다.

**2. 왜 필요한가?**
제목이 같은데 저자가 다른 책이 발견돼 헷갈린다면, 한쪽 제목을 '돈키호테 1'처럼 바꿔야 합니다. 회원 전화번호가 바뀌어도 수정이 필요하죠.

**3. 예시**

```sql
UPDATE book
SET title = '돈키호테 1'
WHERE title = '돈키호테';
```

제목이 '돈키호테'인 데이터의 제목을 '돈키호테 1'로 바꿉니다. 흐름은 이렇습니다.

1. `UPDATE book` → 어느 테이블을 고칠지 지정
2. `SET title = '돈키호테 1'` → 무엇을 어떤 값으로 바꿀지
3. `WHERE title = '돈키호테'` → **어떤 행만** 바꿀지 조건 지정

**4. 헷갈리기 쉬운 점**
**`WHERE`를 빠뜨리면 테이블의 모든 행이 수정됩니다.** `UPDATE book SET title = '돈키호테 1';`처럼 조건 없이 쓰면 모든 책 제목이 '돈키호테 1'로 바뀝니다. `SET`은 '바꿀 값', `WHERE`는 '바꿀 대상' — 둘은 역할이 다릅니다.

**5. 한 줄 정리**
UPDATE는 "조건에 맞는 행의 값을 이렇게 바꿔 줘"라는 명령이다.

> 비유: 출석부에서 특정 학생의 점수만 지우고 다시 적는 것. 단, '누구'를 안 정하면(WHERE 없음) 반 전체 점수를 한꺼번에 덮어쓰게 됩니다.

### DELETE — 데이터 삭제

**1. 정의**
`DELETE`는 테이블에 저장된 값을 **삭제**하는 명령입니다.

**2. 왜 필요한가?**
잘못 입력된 데이터, 더 이상 필요 없는 기록을 정리해야 할 때 씁니다.

**3. 예시**

```sql
DELETE
FROM book
WHERE title = '돈키호테 1';
```

제목이 '돈키호테 1'인 책 데이터를 `book` 테이블에서 삭제합니다.

| id | title | author | publisher |
| --- | --- | --- | --- |
| 1 | 어린왕자 | 생텍쥐페리 | 새벽출판 |
| 3 | 햄릿 | 윌리엄 셰익스피어 | 새벽출판 |

('돈키호테 1' 행이 사라진 모습)

**4. 헷갈리기 쉬운 점**
**`WHERE`가 없으면 테이블의 모든 데이터가 삭제됩니다.** `DELETE FROM book;`은 책 전체를 지웁니다. 이건 SQL에서 가장 위험한 실수 중 하나입니다. 삭제 전에는 같은 조건으로 먼저 `SELECT`를 돌려 '정말 이 행들만 지워지는지' 확인하는 습관이 안전합니다.

**5. 한 줄 정리**
DELETE는 "조건에 맞는 행을 지워 줘"라는 명령이며, 조건을 빠뜨리면 전부 지워진다.

> 비유: 휴지통에 파일을 버리는 것과 비슷한데, '어떤 파일'을 안 고르면(WHERE 없음) 폴더 전체를 비우는 셈입니다.

## 코드로 보기 — 안전하게 수정·삭제하기

실습에서는 보통 조회용 데이터베이스를 직접 건드리지 않고, **별도의 연습용 테이블**을 만들어 추가/수정/삭제를 연습합니다. 아래는 가격(`price`)·재고(`stock`)·평점(`rating`) 컬럼이 있는 도서 테이블을 가정한 예입니다.

```sql
-- 1) 추가
INSERT INTO book(id, title, price, stock, rating)
VALUES('10', '데이터 입문', 25000, 5, 4);

-- 2) 수정: 특정 책 가격 변경
UPDATE book SET price = 39.99 WHERE title = '데이터 입문';

-- 3) 수정: 특정 조건의 재고를 일괄 증가
UPDATE book SET stock = stock + 10 WHERE rating >= 4;

-- 4) 삭제: 평점이 1인 책 전체 삭제
DELETE FROM book WHERE rating = 1;

-- 5) 항상 작업 후 확인
SELECT * FROM book;
```

**코드목적**
추가(1) → 단건 수정(2) → 조건부 일괄 수정(3) → 조건부 삭제(4) → 검증(5)이라는 실제 작업 흐름을 보여 줍니다.

**해석**
- (2) `WHERE`로 '데이터 입문' 한 권만 골라 가격을 바꿉니다.
- (3) `stock = stock + 10`은 "현재 재고에 10을 더한다"는 뜻 — 평점 4 이상인 책들의 재고가 한꺼번에 늘어납니다.
- (4) 평점이 1인 책만 삭제됩니다. `WHERE`를 빼면 전부 지워지니 위험.
- (5) 작업이 의도대로 됐는지 마지막에 꼭 조회로 확인합니다.

**실무 연결**
- **개발 직무**: 회원 가입(INSERT), 프로필 수정(UPDATE), 탈퇴 처리(DELETE)처럼 CRUD는 서비스의 기본 동작 그 자체입니다.
- **데이터 분석 직무**: 원본 데이터를 함부로 수정·삭제하는 일은 위험해서 실무에선 제한적입니다. 분석가는 주로 조회(Read)를 다루고, 변경 작업은 신중하게(보통 사본·별도 환경에서) 합니다. 그래서 **'분석은 읽기 중심, 개발은 CRUD 전반'**이라는 감각이 중요합니다.

## 헷갈리기 쉬운 포인트

- **INSERT의 컬럼 명시 vs 생략**: 명시하면 적은 순서대로, 생략하면 테이블 컬럼 순서대로 값이 들어감(순서 어긋나면 사고).
- **UPDATE의 `SET` vs `WHERE`**: `SET`은 '바꿀 값', `WHERE`는 '바꿀 대상'.
- **`WHERE` 있음 vs 없음 (UPDATE/DELETE)**: 있으면 일부만, 없으면 **전체**가 바뀌거나 삭제됨 — 가장 흔하고 치명적인 실수.
- **DELETE vs SELECT 검증**: 지우기 전에 같은 조건으로 조회해 영향 범위를 먼저 확인.

## 셀프 체크

- [ ] CRUD 네 동작과 DML(INSERT/UPDATE/DELETE)의 관계를 안다.
- [ ] `INSERT INTO ... VALUES ...`의 구조를 안다.
- [ ] `UPDATE`에서 `SET`과 `WHERE`의 역할을 구분할 수 있다.
- [ ] `WHERE`를 빠뜨리면 전체가 바뀌거나 삭제된다는 위험을 안다.
- [ ] 변경 작업 후 `SELECT`로 확인하는 습관을 이해했다.

**복습 질문 및 답변**

- (기본) 새 데이터를 추가하는 명령은 무엇인가요?
  - `INSERT`. `INSERT INTO 테이블(컬럼...) VALUES(값...);` 형태로 씁니다.
- (이해 확인) `DELETE FROM book;`을 실행하면 어떻게 되나요?
  - `WHERE`가 없으므로 `book` 테이블의 모든 데이터가 삭제됩니다(매우 위험).
- (응용) 평점이 1인 책만 안전하게 지우려면 어떤 순서로 작업할까요?
  - 먼저 `SELECT * FROM book WHERE rating = 1;`로 대상을 확인한 뒤, `DELETE FROM book WHERE rating = 1;`를 실행하고, 마지막에 다시 조회로 검증합니다.

## 한 줄 정리

> INSERT·UPDATE·DELETE는 데이터를 직접 추가·수정·삭제하는 DML이며, `WHERE` 조건을 빠뜨리면 테이블 전체가 영향을 받으므로 항상 조건과 사후 확인에 신중해야 한다.
