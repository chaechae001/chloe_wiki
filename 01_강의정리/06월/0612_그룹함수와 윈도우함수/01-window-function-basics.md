# 윈도우 함수 첫걸음 — 행을 지우지 않는 집계

> 평균을 구하면 보통 데이터가 한 줄로 줄어듭니다. 그런데 "각 직원의 급여" 옆에 "그 부서의 평균 급여"를 나란히 붙이고 싶다면? 행을 지우지 않는 집계, 윈도우 함수가 필요합니다.

`윈도우 함수` `OVER` `PARTITION BY` `ORDER BY` `WINDOWING` `집계 함수` `데이터 분석`

## 핵심요약

- 데이터 분석용 SQL 함수는 크게 **집계 함수 / 그룹 함수 / 윈도우 함수** 세 갈래로 나뉜다.
- 일반 집계 함수 + `GROUP BY`는 결과를 **압축**한다(행이 줄어든다).
- 윈도우 함수는 **원본 행 수를 그대로 유지**하면서 옆에 계산 결과를 덧붙인다.
- 윈도우 함수에는 `OVER` 구문이 **반드시** 따라온다.
- `OVER` 안에는 세 개의 손잡이가 있다: `PARTITION BY`(그룹 나누기), `ORDER BY`(정렬), `WINDOWING`(범위 지정).
- `WINDOWING`(ROWS 등)으로 "어디부터 어디까지를 한 묶음으로 볼지"를 정하면 같은 함수라도 결과가 달라진다.
- 윈도우 함수는 데이터베이스 종류·버전에 따라 지원 범위가 다르므로 버전 확인이 필요하다.

## 개념별 정리

### 데이터 분석을 위한 세 가지 함수

**1. 정의**
데이터를 통계 내는 SQL 함수는 목적에 따라 세 갈래로 나눌 수 있습니다. 여러 행을 하나로 합치는 **집계 함수**(SUM·AVG·COUNT 등), 집계에 소계·총계를 더해 주는 **그룹 함수**(ROLLUP·CUBE 등), 그리고 행을 유지한 채 행과 행의 관계를 계산하는 **윈도우 함수**입니다.

**2. 왜 필요한가?**
"전체 매출이 얼마인가?"(집계), "부서별·직무별 소계까지 한눈에"(그룹), "각 주문이 전체에서 차지하는 비중은?"(윈도우)처럼 분석 질문의 모양이 다르기 때문입니다. 질문에 맞는 도구를 고르는 게 분석의 첫 단추입니다.

**3. 예시**
같은 "평균 급여"라도 쓰임이 다릅니다.

```sql
-- 집계 함수: 결과가 한 줄로 압축됨
SELECT AVG(SALARY) AS AVG_SALARY
FROM EMPLOYEE;

-- 윈도우 함수: 모든 직원 행을 유지하면서 부서 평균을 옆에 붙임
SELECT
    ID, NAME, SALARY,
    AVG(SALARY) OVER (PARTITION BY DEPARTMENT_ID) AS DEPARTMENT_AVG
FROM EMPLOYEE;
```

**4. 헷갈리기 쉬운 점**
"집계 함수 = GROUP BY"라고만 외우면 윈도우 함수가 낯설게 느껴집니다. 집계 함수는 윈도우 함수의 `OVER` 안에서도 쓰입니다. 즉 함수 이름(SUM·AVG)이 같아도, `GROUP BY`와 쓰느냐 `OVER`와 쓰느냐에 따라 동작이 완전히 달라집니다.

**5. 한 줄 정리**
집계는 합치고, 그룹은 소계까지 더하고, 윈도우는 행을 살린 채 계산한다.

> 비유: 집계 함수는 반죽을 한 덩어리로 뭉치는 것, 윈도우 함수는 빵을 그대로 둔 채 각 빵 옆에 영양성분표 스티커만 붙이는 것.

### 윈도우 함수의 기본 구조

**1. 정의**
윈도우 함수는 순위·집계 등 **행과 행 사이의 관계를 정의하는 함수**이며, 항상 `OVER` 구문과 함께 씁니다.

```sql
SELECT WINDOW_FUNCTION(ARGUMENTS)
       OVER ( [PARTITION BY 컬럼] [ORDER BY 절] [WINDOWING 절] )
FROM 테이블명;
```

**2. 왜 필요한가?**
`OVER`는 "이 계산을 어떤 범위(window, 창)를 기준으로 할지"를 알려 주는 안내문입니다. 이 창을 어떻게 설정하느냐에 따라 순위·누적합·평균이 모두 달라지므로, `OVER`의 세 구성요소를 이해하는 것이 윈도우 함수의 전부라고 해도 과언이 아닙니다.

**3. 예시 — OVER 안의 세 손잡이**

| 구성요소 | 역할 |
| ------- | ---- |
| `ARGUMENTS` | 윈도우 함수가 필요로 하는 인수 |
| `PARTITION BY` | 전체 집합을 소그룹(칸막이)으로 나누는 기준 |
| `ORDER BY` | 소그룹 안에서의 정렬 기준 |
| `WINDOWING` | 행에 대한 범위 기준(어디부터 어디까지) |

`WINDOWING` 절에서 자주 보는 키워드는 다음과 같습니다.

| 키워드 | 의미 |
| ----- | ---- |
| `ROWS` | 물리적 행 단위로 범위를 지정 |
| `UNBOUNDED PRECEDING` | 창의 시작을 "첫 번째 행"으로 |
| `UNBOUNDED FOLLOWING` | 창의 끝을 "마지막 행"으로 |
| `CURRENT ROW` | 현재 행을 경계로 |

**4. 헷갈리기 쉬운 점**
세 손잡이는 모두 **선택 사항**입니다(대괄호 `[ ]`). 순위 함수처럼 `ORDER BY`만 필요한 경우도, 부서 평균처럼 `PARTITION BY`만 필요한 경우도, `OVER()`처럼 둘 다 비워 전체를 한 묶음으로 보는 경우도 있습니다.

**5. 한 줄 정리**
`OVER( 나눌 기준 · 정렬 기준 · 범위 기준 )` — 이 세 가지로 계산의 무대를 설계한다.

> 비유: `PARTITION BY`는 교실에 칸막이를 세우는 일, `ORDER BY`는 칸막이 안에서 키 순으로 줄 세우는 일, `WINDOWING`은 "앞에서 세 명까지만 본다"처럼 보는 범위를 정하는 일.

## 코드로 보기 — 부서 평균을 옆에 붙이기

같은 결과를 서브쿼리로도, 윈도우 함수로도 만들 수 있습니다.

```sql
-- (1) 스칼라 서브쿼리 방식
SELECT
    ID, NAME, SALARY, DEPARTMENT_ID,
    (SELECT AVG(SALARY)
     FROM EMPLOYEE B
     WHERE B.DEPARTMENT_ID = A.DEPARTMENT_ID) AS DEPARTMENT_AVG
FROM EMPLOYEE A
ORDER BY A.DEPARTMENT_ID;

-- (2) 윈도우 함수 방식 (같은 결과, 훨씬 간결)
SELECT
    ID, NAME, SALARY,
    AVG(SALARY) OVER (PARTITION BY DEPARTMENT_ID) AS DEPARTMENT_AVG
FROM EMPLOYEE;
```

결과(부서 1·2):

| ID | NAME | SALARY | DEPARTMENT_ID | DEPARTMENT_AVG |
| -- | ---- | ------ | ------------- | -------------- |
| 1000 | JAMES | 8000 | 1 | 5875 |
| 1002 | STEVE | 4000 | 1 | 5875 |
| 1004 | ALICE | 10000 | 1 | 5875 |
| 1003 | ROBERT | 1500 | 1 | 5875 |
| 1005 | JANNET | 6000 | 2 | 6000 |
| 1001 | JESSICA | 6000 | 2 | 6000 |

**코드목적**
각 직원 행을 그대로 두면서, 그 직원이 속한 부서의 평균 급여를 같은 줄에 함께 보여 주는 것이 목적입니다.

**해석**
부서 1에 속한 네 명은 모두 같은 평균값 `5875`를 갖습니다. 행이 줄지 않았다는 점이 핵심입니다. 만약 `GROUP BY DEPARTMENT_ID`로 평균을 냈다면 결과는 부서당 한 줄, 총 두 줄로 압축됐을 것입니다.

**실무 연결**
"내 급여는 부서 평균보다 위인가 아래인가?"처럼 **개별 값과 기준선을 한 화면에서 비교**하는 리포트에 바로 쓰입니다. 서브쿼리보다 짧고 읽기 쉬워 대시보드 쿼리 유지보수가 편해집니다.

## 헷갈리기 쉬운 포인트

- **GROUP BY 집계 vs 윈도우 집계**: `GROUP BY`는 행을 묶어 **줄인다**. 윈도우 집계는 행을 **유지**하고 계산값만 덧붙인다. "행 수가 줄었는가?"로 둘을 구분하세요.
- **OVER() vs OVER(PARTITION BY ...)**: 빈 `OVER()`는 전체를 하나의 창으로 보고, `PARTITION BY`가 있으면 그 컬럼 값별로 창이 쪼개집니다.

**복습 질문 및 답변**

- (기본) 윈도우 함수에 반드시 따라오는 구문은?
  → `OVER` 구문.
- (이해확인) `GROUP BY`로 부서 평균을 내는 것과 `AVG() OVER(PARTITION BY 부서)`의 결과는 어떻게 다른가?
  → 전자는 부서당 한 줄로 압축되고, 후자는 모든 원본 행을 유지한 채 같은 부서끼리 같은 평균값을 갖는다.
- (응용) "각 직원의 급여가 부서 평균보다 높으면 '상위', 낮으면 '하위'로 표시"하려면 어떤 순서로 쿼리를 구성하면 될까?
  → 먼저 `AVG() OVER(PARTITION BY 부서)`로 부서 평균 컬럼을 만든 뒤, 바깥쪽에서 그 컬럼과 개별 급여를 `CASE`로 비교한다(윈도우 함수는 `WHERE`에 직접 못 쓰므로 인라인 뷰로 감싼다).

## 한 줄 정리

> 윈도우 함수는 행을 지우지 않는 집계이며, 모든 비밀은 `OVER` 안의 세 손잡이(나누기·정렬·범위)에 있다.
