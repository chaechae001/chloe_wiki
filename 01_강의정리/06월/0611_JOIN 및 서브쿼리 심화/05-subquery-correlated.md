# 서브쿼리 ① 동작 방식 — 연관 vs 비연관

> "평균보다 비싼 상품"을 찾으려면 먼저 '평균'을 알아야 합니다. 그 '평균'을 쿼리 안에서 즉석으로 계산해 끼워 넣는 것이 서브쿼리, 즉 쿼리 속의 쿼리입니다.

`서브쿼리` `Subquery` `연관서브쿼리` `비연관서브쿼리` `Correlated` `EXISTS`

## 핵심요약

- **서브쿼리**는 쿼리 안에 들어가는 또 다른 쿼리다 — 바깥쪽이 메인쿼리, 안쪽이 서브쿼리.
- 동작 방식으로 나누면 **비연관 서브쿼리**와 **연관 서브쿼리**로 갈린다.
- **비연관(Un-Correlated)**: 서브쿼리가 메인쿼리 컬럼을 **참조하지 않음** → 딱 한 번 실행되어 값을 제공.
- **연관(Correlated)**: 서브쿼리가 메인쿼리 컬럼을 **참조함** → 메인쿼리의 **행마다** 서브쿼리가 다시 실행.
- 구분 기준은 단 하나: **"서브쿼리 안에 메인쿼리의 컬럼이 들어가는가?"**
- `EXISTS`는 대표적인 연관 서브쿼리 형태, 같은 일을 `IN`(비연관)으로도 표현할 수 있다.

## 개념별 정리

### 비연관 서브쿼리

**1. 정의**
서브쿼리가 메인쿼리의 컬럼을 전혀 참조하지 않고 **혼자 독립적으로 실행**되는 서브쿼리다. 보통 메인쿼리에 "특정한 값 하나"나 "값 목록"을 제공한다.

**2. 왜 필요한가?**
"전체 평균", "최댓값", "특정 조건을 만족하는 ID 목록"처럼 **먼저 계산해 둬야 할 기준값**이 있을 때, 그 계산을 쿼리 안에 깔끔히 넣을 수 있다.

**3. 예시 (평균 단가보다 비싼 트랙)**
```sql
SELECT Name, UnitPrice
FROM tracks
WHERE UnitPrice > (
    SELECT AVG(UnitPrice)
    FROM tracks
)
ORDER BY UnitPrice DESC;
```
안쪽 `SELECT AVG(UnitPrice)`는 메인쿼리와 무관하게 한 번 실행돼 평균값 하나를 내놓고, 바깥쪽은 그 값과 각 트랙 단가를 비교한다.

**4. 헷갈리기 쉬운 점**
비연관 서브쿼리는 "먼저 계산한 값을 상수처럼 끼워 넣는 것"이라고 보면 된다. 메인쿼리가 1만 행이든 100만 행이든 서브쿼리는 **딱 한 번만** 돈다.

**5. 한 줄 정리**
비연관 서브쿼리는 혼자 한 번 실행돼 기준값을 제공하는, 독립적인 쿼리다.

> 비유: 시험 채점 전에 먼저 "반 평균 점수"를 칠판에 적어 두고(한 번 계산), 각자 자기 점수와 비교하는 것.

### 연관 서브쿼리

**1. 정의**
서브쿼리 안에 **메인쿼리의 컬럼이 조건으로 들어가** 서로 엮인 서브쿼리다. 메인쿼리가 한 행을 볼 때마다, 그 행의 값을 받아 서브쿼리가 **매번 다시 실행**된다.

**2. 왜 필요한가?**
"각 트랙이 **자기가 속한 앨범**의 평균보다 긴가?"처럼, 비교 기준이 **행마다 달라지는** 질문에 쓴다. 강의 슬라이드의 "본인이 속한 부서 평균 급여보다 높은 직원" 예시가 정확히 이 구조다.

**3. 예시 (자기 앨범 평균보다 긴 트랙)**
```sql
SELECT t.Name,
       t.Milliseconds,
       t.AlbumId
FROM tracks t
WHERE t.Milliseconds > (
    SELECT AVG(t2.Milliseconds)
    FROM tracks t2
    WHERE t2.AlbumId = t.AlbumId          -- 메인쿼리 t.AlbumId 참조 ← 연관
)
ORDER BY t.AlbumId, t.Milliseconds DESC
LIMIT 20;
```
서브쿼리 안의 `t.AlbumId`가 메인쿼리의 현재 행을 가리킨다. 그래서 트랙마다 "자기 앨범의 평균"이 새로 계산된다.

**4. 헷갈리기 쉬운 점**
연관 서브쿼리는 행마다 서브쿼리가 다시 도니 데이터가 많으면 느려질 수 있다. 하지만 "행마다 기준이 다른" 질문은 연관 서브쿼리가 가장 자연스럽다. 메인쿼리 컬럼(`t.AlbumId`)이 서브쿼리 안에 등장하는 순간 연관이다.

**5. 한 줄 정리**
연관 서브쿼리는 메인쿼리의 각 행 값을 받아 매번 다시 실행되는, 행별 맞춤 비교다.

> 비유: 학생마다 "**자기 반** 평균"과 비교하는 것 — 반이 바뀌면 비교 기준도 바뀐다.

### EXISTS — 존재만 확인하는 연관 서브쿼리

**1. 정의**
`EXISTS`는 서브쿼리 결과가 **한 건이라도 있으면 참**, 없으면 거짓으로 판정하는 연산자다. 값을 가져오는 게 아니라 "존재 여부"만 본다.

**2. 왜 필요한가?**
"실제로 판매된 적 있는 트랙", "주문이 하나라도 있는 고객"처럼 **있냐 없냐만** 따지면 충분할 때 효율적이다.

**3. 예시 (한 번이라도 팔린 트랙)**
```sql
SELECT t.Name AS TrackName
FROM tracks t
WHERE EXISTS (
    SELECT 1
    FROM invoice_items ii
    WHERE ii.TrackId = t.TrackId          -- 메인쿼리 t.TrackId 참조 ← 연관
)
ORDER BY t.Name
LIMIT 10;
```
서브쿼리의 `SELECT 1`은 "무엇을" 가져올지가 중요하지 않다는 표시다. 존재만 보면 되니 `1`을 둔다.

**4. 헷갈리기 쉬운 점**
같은 결과를 비연관 `IN`으로도 쓸 수 있다. 아래 두 쿼리는 결과가 같지만 동작 방식이 다르다 — `EXISTS`는 행마다 존재를 확인(연관), `IN`은 목록을 먼저 만들어 비교(비연관)한다.

```sql
-- 같은 결과, 비연관 IN 버전
SELECT t.Name AS TrackName
FROM tracks t
WHERE t.TrackId IN (
    SELECT ii.TrackId
    FROM invoice_items ii                 -- 메인쿼리 컬럼 미참조 ← 비연관
)
ORDER BY t.Name
LIMIT 10;
```

**5. 한 줄 정리**
`EXISTS`는 "있기만 하면 통과"시키는 연관 서브쿼리의 대표 형태다.

## 코드로 보기 — 연관 서브쿼리로 "앨범 있는 아티스트"

```sql
SELECT Name AS ArtistName
FROM artists a
WHERE (
    SELECT COUNT(*)
    FROM albums al
    WHERE al.ArtistId = a.ArtistId        -- 메인쿼리 a.ArtistId 참조 ← 연관
) > 0
ORDER BY Name;
```

**코드목적**
앨범이 한 장이라도 있는 아티스트의 이름만 골라낸다.

**해석**
메인쿼리는 아티스트를 한 명씩 본다. 각 아티스트(`a`)마다 서브쿼리가 "이 아티스트의 앨범 수"를 세고, 그 수가 0보다 크면 결과에 남긴다. 서브쿼리 안의 `a.ArtistId`가 메인쿼리의 현재 행을 참조하므로 전형적인 연관 서브쿼리다. 강의의 "본인 부서 평균 급여 초과 직원" 패턴과 같은 구조다.

**실무 연결**
"활동 이력이 있는 사용자만", "재고가 남은 상품만"처럼 **메인 대상마다 관련 데이터의 유무·조건**을 따지는 필터링에 연관 서브쿼리가 폭넓게 쓰인다.

## 직접 해보기

1. (비연관) `'AC/DC'` 아티스트의 `ArtistId`를 서브쿼리로 구해, 그 아티스트의 앨범 제목을 모두 조회해 보세요.
2. (연관) 각 고객에 대해, 인보이스 총액이 10 이상인 인보이스가 존재하는 고객만 `EXISTS`로 골라내 보세요.
3. 문제 2를 `IN`(비연관)으로도 작성해 보고, 두 결과가 같은지 비교해 보세요.

## 헷갈리기 쉬운 포인트

- **연관 vs 비연관**: 서브쿼리 안에 메인쿼리 컬럼이 있으면 연관, 없으면 비연관. 이 한 가지만 보면 된다.
- **EXISTS vs IN**: 결과는 같을 수 있지만, EXISTS는 "존재 확인"(연관), IN은 "목록 비교"(비연관)다. NULL이 섞인 데이터에서는 `NOT IN`이 예상과 다르게 동작할 수 있어 `NOT EXISTS`가 더 안전한 경우가 있다.
- **서브쿼리 위치**: 서브쿼리는 WHERE뿐 아니라 SELECT·HAVING·FROM 등 여러 자리에 올 수 있다(다음 글들에서 확인).

## 셀프 체크

- [ ] 서브쿼리가 "쿼리 안의 쿼리"임을 설명할 수 있다.
- [ ] 연관/비연관을 "메인쿼리 컬럼 참조 여부"로 구분할 수 있다.
- [ ] 비연관 서브쿼리가 한 번만 실행됨을 안다.
- [ ] 연관 서브쿼리가 행마다 다시 실행됨을 안다.
- [ ] `EXISTS`가 존재 여부만 보는 연관 서브쿼리임을 안다.

**복습 질문 및 답변**

- (기본) 연관 서브쿼리와 비연관 서브쿼리를 가르는 기준은 무엇인가요?
  → 서브쿼리 안에 메인쿼리의 컬럼이 조건으로 들어가는지 여부입니다.
- (이해 확인) 비연관 서브쿼리는 메인쿼리 행 수가 많아지면 실행 횟수도 늘어나나요?
  → 아닙니다. 메인쿼리와 무관하게 딱 한 번만 실행되어 값을 제공합니다.
- (응용) "각 트랙이 자기 앨범 평균보다 긴가"를 비연관 서브쿼리로 풀기 어려운 이유는?
  → 비교 기준(앨범 평균)이 행마다 달라지므로, 메인쿼리 컬럼을 참조하는 연관 서브쿼리가 자연스럽기 때문입니다.

## 한 줄 정리

> 서브쿼리는 쿼리 속의 쿼리이며, 메인쿼리 컬럼을 참조하면 행마다 다시 도는 연관, 참조하지 않으면 한 번만 도는 비연관이다.
