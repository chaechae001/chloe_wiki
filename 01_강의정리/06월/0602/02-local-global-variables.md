# 지역변수 vs 전역변수 — 변수가 보이는 '범위'를 이해하기

> 함수 안에서 분명히 만든 변수인데, 함수 밖에서 부르면 "그런 이름 없는데?"라며 에러가 납니다. 변수에도 '활동 범위'가 있기 때문입니다.

`지역변수` `전역변수` `scope` `Shadowing` `global` `NameError`

## 핵심요약

- 변수가 보이는 범위를 **scope(스코프)** 라고 한다.
- **지역변수(Local)**: 함수 안에서 정의 → 그 함수 안에서만 존재. 밖에서 부르면 `NameError`.
- **전역변수(Global)**: 함수 밖에서 정의 → 프로그램 어디서나 읽을 수 있다.
- 함수 안에서 전역변수를 **읽는 것**은 자유롭지만, **값을 바꾸려면** `global` 선언이 필요하다.
- 같은 이름의 지역변수가 전역변수를 가리는 현상을 **Shadowing**이라고 한다.
- `global`은 편리하지만 "어디서 값이 바뀌었는지" 추적을 어렵게 만들 수 있어 신중히 써야 한다.

---

## 개념별 정리

### 지역변수(Local Variable)

**1. 정의**
함수(또는 특정 구문) 안에서 정의한 변수로, 정의한 그 범위 안에서만 사용할 수 있다.

**2. 왜 필요한가?**
함수마다 자기 변수를 따로 가질 수 있어야 서로 간섭하지 않는다. 함수 안의 임시 계산값이 밖으로 새어 나가 다른 코드를 망치는 일을 막아 준다.

**3. 예시**

```python
def greet():
    msg = "함수 안에서 안녕!"   # 지역변수
    print(msg)

greet()
print(msg)   # 함수 밖에서는 msg를 모름
```

실행 결과:
```
함수 안에서 안녕!
Traceback (most recent call last):
  ...
NameError: name 'msg' is not defined
```

**4. 헷갈리기 쉬운 점**
함수가 끝나면 그 안의 지역변수는 사라진다. "분명히 위에서 만들었는데 왜 없다고 하지?"의 답은 "그건 함수 안에서만 살던 변수라서"다.

**5. 한 줄 정리**
지역변수는 함수라는 방 안에서만 사는 변수다.

### 전역변수(Global Variable)

**1. 정의**
함수 밖에서 정의한 변수로, 프로그램 어디서나 읽을 수 있다.

**2. 왜 필요한가?**
프로그램 전체가 공유해야 하는 정보(설정값, 전체 상태 등)를 담는다.

**3. 예시**

```python
msg = "Python is awesome!"   # 전역변수

def display():
    print("함수 안:", msg)    # 전역변수 읽기 OK

display()
print("함수 밖:", msg)        # 함수 밖에서도 OK
```

실행 결과:
```
함수 안: Python is awesome!
함수 밖: Python is awesome!
```

**4. 헷갈리기 쉬운 점**
전역변수는 함수 안에서 **읽기**는 자유롭다. 하지만 함수 안에서 그 값을 **새로 대입하면** 파이썬은 그걸 "새 지역변수"로 만들어 버린다(다음 항목 참고).

**5. 한 줄 정리**
전역변수는 집 전체에서 보이는 변수다.

### Shadowing (그림자처럼 가리기)

**1. 정의**
함수 안에서 전역변수와 **같은 이름**의 변수를 정의하면, 함수 안에서는 지역변수가 전역변수를 가린다. 전역변수 자체는 그대로 유지된다.

**2. 왜 필요한가?(왜 알아야 하는가)**
"분명 전역값을 바꿨는데 밖에서는 안 바뀌어 있다"는 혼란의 원인이 바로 이것이다. 의도치 않은 버그를 피하려면 반드시 이해해야 한다.

**3. 예시**

```python
s = "I love Python"   # 전역

def fun():
    s = "Me too."     # 지역(전역을 가림)
    print(s)

fun()       # → Me too.
print(s)    # → I love Python (전역은 그대로)
```

실행 결과:
```
Me too.
I love Python
```

**4. 헷갈리기 쉬운 점**
매개변수도 Shadowing을 일으킨다. 아래는 전역 `count`가 끝까지 0인 예다.

```python
count = 0
def increase(count=0):   # 매개변수 count가 전역을 가림
    count = count + 1    # 여기서 바뀌는 건 지역 count
increase()
print(count)             # 전역은 그대로 0
```

실행 결과:
```
0
```

**5. 한 줄 정리**
같은 이름이어도 함수 안의 변수는 "다른 방의 동명이인"일 수 있다.

> 비유: 개발자가 말하는 "완료"(내 기능 기준)와 PM이 말하는 "완료"(릴리스 기준)는 같은 단어지만 다른 범위를 가리킨다. 소통할 때 "어느 범위의 값을 말하는지" 맞춰야 하는 것과 똑같다.

### `global` — 전역변수를 함수 안에서 바꾸기

**1. 정의**
함수 안에서 전역변수의 값을 **수정**하고 싶을 때, 그 변수가 전역임을 알리는 선언이다.

**2. 왜 필요한가?**
`global` 없이 함수 안에서 전역변수에 새 값을 대입하면 지역변수가 만들어진다. 전역값을 진짜로 바꾸려면 `global`로 "이건 밖에 있는 그 변수야"라고 명시해야 한다.

**3. 예시**

```python
count = 0

def increase():
    global count    # 이 선언이 있어야 전역을 바꿀 수 있음
    count += 1

increase()
print(count)        # → 1
```

실행 결과:
```
1
```

**4. 헷갈리기 쉬운 점**
`global`로 바꾼 값은 함수가 끝나도 전역에 남아 프로그램 전체에 전파된다. 편하지만, 값이 "어디서 바뀌었는지" 추적하기 어려워질 수 있어 남용은 피하는 게 좋다.

**5. 한 줄 정리**
`global`은 함수 안에서 전역변수를 "진짜로" 바꿀 수 있게 해 주는 권한 선언이다.

## 코드로 보기 — 프로젝트 상황으로 보는 scope

scope를 "각 역할이 다루는 범위"에 빗대 보자. 전역변수는 프로젝트 전체가 공유하는 정보, 지역변수는 각자 작업 안에서만 의미 있는 값이다.

```python
# 전역 변수 — 프로젝트 전체가 공유
project_budget = 100_000_000   # 전체 예산
project_status = "진행중"       # 전체 상태

def develop_feature():          # 개발자 영역
    local_task = "로그인 기능 구현"   # 지역
    hours_spent = 8                 # 지역
    print(f"[개발자] 작업: {local_task}, 투입시간: {hours_spent}h")
    print(f"[개발자] (참고) 전체 상태: {project_status}")  # 전역은 읽기 가능

def analyze():                  # 분석가 영역
    module_a_cost = 30_000_000
    module_b_cost = 25_000_000
    used_ratio = (module_a_cost + module_b_cost) / project_budget  # 전역 참조
    print(f"[분석가] 예산 소진율: {used_ratio:.0%}")

def manage():                   # PM 영역
    global project_status       # 전역을 '수정'할 권한
    project_status = "위험"
    print(f"[PM] 상태 변경 -> {project_status}")

develop_feature()
analyze()
manage()
print(f"최종 전체 상태: {project_status}")
```

실행 결과:
```
[개발자] 작업: 로그인 기능 구현, 투입시간: 8h
[개발자] (참고) 전체 상태: 진행중
[분석가] 예산 소진율: 55%
[PM] 상태 변경 -> 위험
최종 전체 상태: 위험
```

**코드목적**
세 함수(개발자·분석가·PM)가 각자 지역변수를 쓰면서, 전역변수는 누가 읽고(분석가) 누가 바꾸는지(PM) 보여 준다.

**해석**
`local_task`, `hours_spent`는 함수 밖에서는 보이지 않는다. 분석가는 전역 예산을 "읽어서" 소진율 55%를 계산하지만 값을 바꾸진 않는다. PM만 `global`로 전체 상태를 "위험"으로 바꿨고, 그 변경은 함수가 끝난 뒤에도 전역에 남았다(`최종 전체 상태: 위험`).

**실무 연결**
전역 상태를 아무나 바꾸면 추적이 어려워진다. 그래서 실무에서는 "값을 바꾸는 권한"을 한 곳(예: 특정 함수/클래스)에만 두는 식으로 설계한다. 이 감각이 다음 단계인 [클래스](06-class-and-oop.md) 설계로 자연스럽게 이어진다.

## 헷갈리기 쉬운 포인트

- **읽기 vs 쓰기**: 함수 안에서 전역변수 읽기는 자유, 값 변경은 `global` 필요.
- **같은 이름 ≠ 같은 변수**: 함수 안의 동명 변수는 Shadowing으로 전역을 가리는 별개 변수일 수 있다.
- **매개변수도 지역변수**: 매개변수 이름이 전역과 같으면 함수 안에서는 매개변수가 우선한다.

**복습 질문 및 답변**

- (기본) 지역변수와 전역변수의 차이는?
  → 지역변수는 함수 안에서만 존재하고, 전역변수는 프로그램 어디서나 읽을 수 있다.
- (이해 확인) 함수 안에서 전역변수에 새 값을 대입했는데 밖에서는 안 바뀌어 있다. 왜?

- (응용) 카운터를 여러 함수가 함께 늘려야 한다면 어떻게 구현할까?
  → 전역변수로 두고 늘리는 함수에서 `global`을 선언하거나, 더 안전하게는 값을 관리하는 클래스를 두어 그 안에서만 변경한다.

## 한 줄 정리

> 변수에는 보이는 범위(scope)가 있어 지역변수는 함수 안에서만, 전역변수는 어디서나 읽히며, 함수 안에서 전역값을 바꾸려면 `global`이 필요하다.
