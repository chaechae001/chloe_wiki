# 집계 함수와 GROUP BY / HAVING — 여러 행을 하나로 요약하기

> "고객이 몇 명이지?", "장르별 매출은 얼마지?" 같은 질문에 답하려면, 수많은 행을 하나의 숫자로 압축해야 합니다.

`집계 함수` `COUNT` `SUM` `AVG` `MAX` `MIN` `GROUP BY` `HAVING` `DISTINCT` `GROUP_CONCAT`

## 핵심요약

- **집계 함수**는 여러 행을 입력받아 *단일 값 하나*를 돌려준다. (`COUNT`·`SUM`·`AVG`·`MAX`·`MIN` 등)
- `GROUP BY`와 함께 쓰면 "그룹별로" 집계할 수 있다. ("국가별 고객 수", "장르별 매출")
- `DISTINCT`를 붙이면 중복을 제거한 뒤 집계한다. (`COUNT(DISTINCT ...)`)
- `WHERE`는 집계 *전* 개별 행을 거르고, `HAVING`은 집계 *후* 그룹을 거른다.
- `GROUP_CONCAT`은 여러 행의 값을 하나의 문자열로 이어 붙인다.
- 날짜에서 연도만 뽑아 그룹화하려면 `strftime('%Y', 날짜)`를 활용한다.

## 개념별 정리

### COUNT — 개수 세기

**1. 정의**
행의 개수를 세는 함수입니다. `COUNT(*)`는 모든 행을, `COUNT(컬럼)`은 그 컬럼이 NULL이 아닌 행을 셉니다.

**2. 왜 필요한가?**
"전체 트랙은 몇 개인가", "국가별 고객은 몇 명인가" 같은 가장 기본적인 질문에 답하기 위해서입니다.

**3. 예시**

```sql
-- 국가별 고객 수 (많은 순)
SELECT Country,
       COUNT(CustomerId) AS 고객수
FROM customers
GROUP BY Country
ORDER BY 고객수 DESC;
```

**4. 헷갈리기 쉬운 점**
`COUNT(컬럼)`은 NULL을 세지 않습니다. NULL이 섞인 컬럼을 세면 전체 행 수보다 적게 나올 수 있으니, "무조건 전체 행 수"를 원하면 `COUNT(*)`를 씁니다.

**5. 한 줄 정리**
COUNT는 "몇 개인가?"에 답하는 가장 기본 도구다.

> 비유: 출석부에서 이름이 적힌 줄을 손가락으로 세어 내려가는 것과 같습니다.

### DISTINCT — 중복 제거 후 세기

**1. 정의**
집계하기 전에 중복된 값을 먼저 제거합니다. `COUNT(DISTINCT 컬럼)`이 가장 흔한 형태입니다.

**2. 왜 필요한가?**
청구서(invoices) 테이블에는 한 고객이 여러 번 등장합니다. 그냥 세면 "청구서 수"가 되고, `DISTINCT`로 세야 "실제 구매한 고객 수"가 됩니다.

**3. 예시**

```sql
-- 실제로 청구서가 발생한 '고유 고객 수'
SELECT COUNT(DISTINCT CustomerId) AS 구매고객수
FROM invoices;
```

**4. 헷갈리기 쉬운 점**
`COUNT(CustomerId)`와 `COUNT(DISTINCT CustomerId)`는 전혀 다른 숫자입니다. 앞은 "청구서 줄 수", 뒤는 "사람 수"입니다. 무엇을 세고 싶은지 먼저 정해야 합니다.

**5. 한 줄 정리**
DISTINCT는 "줄 수"가 아니라 "사람 수"를 셀 때 쓴다.

> 비유: 방명록의 서명 횟수(중복 포함)와 실제 방문한 사람 수(중복 제거)의 차이입니다.

### SUM · AVG · MAX · MIN — 합·평균·최대·최소

**1. 정의**
숫자 컬럼을 더하고(`SUM`), 평균 내고(`AVG`), 가장 큰 값(`MAX`)·가장 작은 값(`MIN`)을 구합니다.

**2. 왜 필요한가?**
매출 합계, 평균 단가, 최고가·최저가처럼 숫자를 요약하는 거의 모든 분석에 쓰입니다.

**3. 예시**

```sql
-- 연도별 총 매출 (날짜에서 연도만 추출해 그룹화)
SELECT strftime('%Y', InvoiceDate) AS 연도,
       ROUND(SUM(Total), 2)        AS 연매출
FROM invoices
GROUP BY 연도
ORDER BY 연도;
```

`strftime('%Y', 날짜)`는 날짜 문자열에서 연도(예: `2009`)만 뽑아내는 SQLite 함수입니다. 이를 `GROUP BY`에 쓰면 "연도별"로 묶을 수 있습니다.

**4. 헷갈리기 쉬운 점**
나눗셈으로 단위를 바꿀 때 실수가 잦습니다. 재생시간을 밀리초에서 분으로 바꾸려면 `/ 60000`이어야 합니다. 또 정수끼리 나누면 소수점이 잘리므로, 소수가 필요하면 `/ 60000.0`처럼 소수로 나누거나 `ROUND(...)`로 자릿수를 정리합니다.

**5. 한 줄 정리**
SUM·AVG·MAX·MIN은 숫자 컬럼을 한 값으로 압축하는 4총사다.

> 비유: 시험지 한 더미를 받아 총점(SUM)·평균(AVG)·최고점(MAX)·최저점(MIN)을 적어 내는 것과 같습니다.

### GROUP BY — 그룹별로 묶기

**1. 정의**
같은 값을 가진 행들을 한 그룹으로 묶어, 그룹마다 집계 함수를 적용합니다.

**2. 왜 필요한가?**
"전체 매출"이 아니라 "연도별 매출", "장르별 트랙 수"처럼 *쪼개서 보고 싶을 때* 필수입니다.

**3. 예시**

```sql
-- 앨범별 트랙 수 (많은 순)
SELECT AlbumId,
       COUNT(TrackId) AS track_count
FROM tracks
GROUP BY AlbumId
ORDER BY track_count DESC;
```

**4. 헷갈리기 쉬운 점**
`SELECT`에 집계하지 않은 일반 컬럼을 넣으려면 원칙적으로 그 컬럼이 `GROUP BY`에도 있어야 합니다. "묶는 기준"과 "보여 줄 컬럼"을 맞춰 주는 습관이 필요합니다.

**5. 한 줄 정리**
GROUP BY는 "~별로" 쪼개서 집계하는 스위치다.

> 비유: 학생들을 반별로 줄 세운 뒤, 반마다 평균 점수를 적는 것과 같습니다.

### HAVING — 집계 결과에 조건 걸기

**1. 정의**
`GROUP BY`로 묶어 집계한 *결과*에 조건을 거는 절입니다.

**2. 왜 필요한가?**
"트랙이 15개 이상인 앨범만", "총매출이 40달러 이상인 고객만"처럼, 집계한 뒤의 숫자로 걸러야 할 때가 있습니다. 이건 `WHERE`로는 못 합니다.

**3. 예시**

```sql
-- 트랙이 15개 이상인 앨범만
SELECT AlbumId,
       COUNT(TrackId) AS 트랙수
FROM tracks
GROUP BY AlbumId
HAVING 트랙수 >= 15
ORDER BY 트랙수 DESC;
```

**4. 헷갈리기 쉬운 점**
`WHERE`는 집계 *전* 개별 행을, `HAVING`은 집계 *후* 그룹을 거릅니다. "COUNT가 15 이상"처럼 집계 결과를 조건으로 쓰려면 반드시 `HAVING`이어야 합니다.

**5. 한 줄 정리**
HAVING은 "묶고 센 다음"에 거는 조건이다.

> 비유: 반별 평균을 먼저 낸 뒤, 평균 80점 이상인 반만 골라내는 것입니다. (개별 학생 점수로 거르면 WHERE)

### GROUP_CONCAT — 여러 행을 한 문자열로

**1. 정의**
같은 그룹에 속한 여러 행의 값을 하나의 문자열로 이어 붙입니다. 구분자도 지정할 수 있습니다.

**2. 왜 필요한가?**
"이 앨범의 트랙 이름들을 한 칸에 쉼표로 나열"하거나 "장르마다 어떤 미디어 타입이 있는지 한 줄로" 보여 줄 때 유용합니다.

**3. 예시**

```sql
-- 장르별로 어떤 미디어 타입이 있는지 한 문자열로 나열
SELECT g.Name                        AS 장르,
       GROUP_CONCAT(DISTINCT m.Name) AS 미디어타입목록
FROM tracks t
INNER JOIN genres g      ON t.GenreId     = g.GenreId
INNER JOIN media_types m ON t.MediaTypeId = m.MediaTypeId
GROUP BY g.Name;
```

**4. 헷갈리기 쉬운 점**
`GROUP_CONCAT(DISTINCT ...)`로 중복을 제거하지 않으면 같은 값이 여러 번 붙어 지저분해질 수 있습니다.

**5. 한 줄 정리**
GROUP_CONCAT은 "여러 줄을 한 줄 문자열로" 묶는 도구다.

> 비유: 영수증의 여러 품목을 "사과, 우유, 빵"처럼 한 줄로 적어 주는 것과 같습니다.

## 코드로 보기 — 장르별 총 용량 리포트

```sql
SELECT g.Name                              AS 장르,
       ROUND(SUM(t.Bytes) / 1048576.0, 1) AS 총용량_MB
FROM tracks t
JOIN genres g ON t.GenreId = g.GenreId
GROUP BY g.Name
ORDER BY 총용량_MB DESC;
```

**코드목적**
장르마다 트랙들의 용량을 모두 더해, 어떤 장르가 저장 공간을 많이 차지하는지 한눈에 보는 리포트입니다.

**해석**
1단계로 트랙과 장르 테이블을 조인해 "트랙마다 장르 이름"을 붙입니다. 2단계로 `GROUP BY g.Name`으로 장르별로 묶고, 3단계로 바이트를 `1048576`(=1MB)으로 나눠 MB 단위 합계를 구합니다. `ROUND(..., 1)`로 소수 첫째 자리까지 정리해 읽기 좋게 만듭니다. 결과는 "장르 / 총용량_MB" 두 열로, 용량이 큰 장르부터 정렬되어 나옵니다.

**실무 연결**
이런 그룹별 합계는 대시보드의 기본입니다. "카테고리별 매출", "부서별 비용", "지역별 사용자 수"처럼, 현업 리포트의 절반 이상이 이 패턴(조인 → 그룹화 → 합계 → 정렬)으로 만들어집니다.

## 헷갈리기 쉬운 포인트

- **WHERE vs HAVING**: `WHERE`는 집계 전(개별 행), `HAVING`은 집계 후(그룹). "COUNT가 N 이상" 같은 조건은 반드시 `HAVING`.
- **COUNT(*) vs COUNT(컬럼)**: `COUNT(*)`는 모든 행, `COUNT(컬럼)`은 그 컬럼이 NULL이 아닌 행만.
- **COUNT(컬럼) vs COUNT(DISTINCT 컬럼)**: 앞은 "줄 수", 뒤는 "중복 제거한 값의 가짓수".

**복습 질문 및 답변**

- (기본) 여러 행을 하나의 값으로 줄이는 함수를 무엇이라 하나요?
  → 집계 함수입니다.
- (이해 확인) "장르별 트랙 수"를 구하려면 어떤 절이 반드시 필요한가요?
  → `GROUP BY`(장르 기준으로 묶기)입니다.
- (응용) "고객별 총매출이 평균 이상인 고객"을 뽑을 때, 평균과 비교하는 조건은 `WHERE`와 `HAVING` 중 어디에 들어가야 하나요?
  → 집계(SUM) 결과를 비교하므로 `HAVING`입니다.

## 한 줄 정리

> 집계 함수는 수많은 행을 하나의 숫자로 압축하고, `GROUP BY`는 그것을 "~별"로 쪼개며, `HAVING`은 그 결과에 조건을 건다.
