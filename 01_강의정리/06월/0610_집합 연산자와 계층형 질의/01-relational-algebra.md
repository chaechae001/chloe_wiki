# 관계형 대수와 STANDARD SQL — SQL이 표를 다루는 큰 그림

> SQL 문법을 외우기 전에, "데이터베이스는 표를 가지고 대체 무슨 연산을 하는가?"를 먼저 알면 나머지가 훨씬 쉬워집니다.

`관계형 대수` `STANDARD SQL` `집합 연산` `관계 연산` `합집합` `교집합` `차집합` `카티션 곱`

## 핵심요약

- **관계형 대수**는 관계형 데이터베이스에서 원하는 정보를 끌어내기 위한 *기본 연산들의 모음*이다.
- 크게 **일반 집합 연산**과 **순수 관계 연산** 두 갈래로 나뉜다.
- 일반 집합 연산: 합집합·교집합·차집합·카티션 곱 → SQL의 `UNION` · `INTERSECT` · `EXCEPT` · `CROSS JOIN`에 대응한다.
- 순수 관계 연산: 셀렉션·프로젝션·조인·디비전 → SQL의 `WHERE` · `SELECT` · `JOIN`에 대응한다.
- 이번 강의의 핵심인 **집합 연산자**와 **계층형 질의**는 모두 이 큰 그림 안에서 출발한다.
- 표준(STANDARD) 개념은 같아도, 실제 문법은 DBMS마다 조금씩 다르다.

## 개념별 정리

### 관계형 대수란?

**1. 정의**
표(테이블) 두세 개를 입력으로 받아, 원하는 결과 표를 만들어 내는 *연산 규칙들의 집합*입니다. 수학의 사칙연산처럼 "데이터 표에 적용하는 기본 연산"이라고 보면 됩니다.

**2. 왜 필요한가?**
SQL은 결국 이 연산들을 사람이 쓰기 편한 문장으로 바꿔 놓은 것입니다. 연산의 종류를 알아두면, 새로운 SQL 키워드를 만났을 때 "아, 이건 차집합 역할이구나" 하고 자리를 잡을 수 있습니다.

**3. 예시**
관계형 대수는 두 갈래로 나뉩니다.

| 갈래 | 포함 연산 | 대응 SQL |
| --- | --- | --- |
| 일반 집합 연산 | 합집합·교집합·차집합·카티션 곱 | `UNION` · `INTERSECT` · `EXCEPT` · `CROSS JOIN` |
| 순수 관계 연산 | 셀렉션·프로젝션·조인·디비전 | `WHERE` · `SELECT` · `JOIN` · (거의 안 씀) |

**4. 헷갈리기 쉬운 점**
"집합 연산"과 "관계 연산"이라는 이름이 비슷해서 헷갈립니다. 집합 연산은 *두 표를 통째로 위아래로 합치거나 빼는 것*이고, 관계 연산은 *한 표 안에서 행을 고르거나 열을 추리거나 다른 표와 옆으로 잇는 것*입니다.

**5. 한 줄 정리**
관계형 대수는 SQL의 뼈대이고, 문법은 그 위에 입혀진 살이다.

> 비유: 관계형 대수가 "요리의 기본 조리법(굽기·삶기·섞기)"이라면, SQL 문법은 "특정 레스토랑의 레시피 표기법"입니다. 조리법을 알면 어느 레시피든 빠르게 이해됩니다.

### 일반 집합 연산 — 두 표를 통째로 다루기

**1. 정의**
같은 모양(열 구성)을 가진 두 표를 마치 수학의 집합처럼 합치거나, 겹치는 부분만 남기거나, 빼는 연산입니다.

**2. 왜 필요한가?**
"올해 구매 고객과 작년 구매 고객을 한 명단으로 합치고 싶다", "두 해 모두 구매한 고객만 보고 싶다" 같은 요구는 조인이 아니라 집합 연산으로 더 자연스럽게 풀립니다.

**3. 예시**
세 개의 작은 표 A·B·C가 있을 때 결과를 그림으로 보면 다음과 같습니다. (강의 슬라이드의 예시 데이터)

- A 릴레이션: `(A1,B1,1) (A2,B2,2) (A3,B3,3)`
- B 릴레이션: `(A1,B1,1) (A4,B4,4)`

| 연산 | 의미 | 결과 |
| --- | --- | --- |
| 합집합 (A∪B) | 두 표를 합치고 중복 제거 | A1·A2·A3·A4 행 |
| 교집합 (A∩B) | 양쪽에 모두 있는 행 | A1 행 |
| 차집합 (A−B) | A에는 있고 B에는 없는 행 | A2·A3 행 |
| 카티션 곱 (B×C) | 모든 조합을 짝지음 | B의 각 행 × C의 각 행 |

**4. 헷갈리기 쉬운 점**
카티션 곱(카티션 프로덕트)은 "두 표의 모든 조합"을 만들어 행 수가 폭발적으로 늘어납니다. 의도치 않게 발생하면 성능 사고로 이어지므로, 보통은 조인의 조건이 빠졌을 때 실수로 나타납니다. (조인 편에서 자세히 다룹니다.)

**5. 한 줄 정리**
일반 집합 연산은 "두 표를 위아래로" 다루는 연산이다.

> 비유: 두 반의 출석부를 한 장으로 합치거나(합집합), 두 반에 모두 있는 학생만 추리거나(교집합), 우리 반에만 있는 학생을 찾는 것(차집합)과 같습니다.

### 순수 관계 연산 — 한 표를 다루고 옆으로 잇기

**1. 정의**
표에서 조건에 맞는 행만 고르고(셀렉션), 필요한 열만 추리고(프로젝션), 다른 표와 옆으로 잇는(조인) 연산입니다.

**2. 왜 필요한가?**
우리가 매일 쓰는 `SELECT ... FROM ... WHERE ...`가 바로 이 연산들의 조합입니다. 가장 기본적이면서 가장 많이 쓰입니다.

**3. 예시**

| 연산 | 하는 일 | 대응 SQL |
| --- | --- | --- |
| 셀렉션(Selection) | 조건에 맞는 **행**을 고름 | `WHERE` 절 |
| 프로젝션(Projection) | 원하는 **열**만 추림 | `SELECT` 절 |
| 조인(Join) | 두 표를 키로 **옆으로** 이음 | 다양한 `JOIN` |
| 디비전(Division) | 특정 조건을 모두 만족하는 행 추출 | 실무에서 거의 안 씀 |

**4. 헷갈리기 쉬운 점**
"셀렉션 = SELECT"라고 오해하기 쉽지만, 관계형 대수에서 **셀렉션은 행을 고르는 `WHERE`**에 해당하고, **열을 고르는 것은 프로젝션(`SELECT` 절)**입니다. 이름과 SQL 키워드가 어긋나 있다는 점을 기억해 두세요.

**5. 한 줄 정리**
순수 관계 연산은 "한 표를 다듬고 다른 표와 잇는" 연산이다.

> 비유: 명단에서 조건에 맞는 사람만 형광펜으로 표시(셀렉션)하고, 이름·전화번호 열만 오려내고(프로젝션), 다른 명단과 학번으로 짝지어 붙이는 것(조인)과 같습니다.

## 코드로 보기 — 집합 연산과 관계 연산을 한눈에

```sql
-- 순수 관계 연산: 셀렉션(WHERE) + 프로젝션(SELECT)
SELECT FirstName, LastName     -- 프로젝션: 이름 열만 추림
FROM customers
WHERE Country = 'Brazil';      -- 셀렉션: 브라질 고객 행만 고름

-- 일반 집합 연산: 두 표를 위아래로 합치기(UNION)
SELECT FirstName, LastName FROM employees
UNION
SELECT FirstName, LastName FROM customers;
```

**코드목적**
앞의 쿼리는 한 표(고객)에서 행과 열을 다듬는 *관계 연산*이고, 뒤의 쿼리는 두 표(직원·고객)를 위아래로 합치는 *집합 연산*입니다. 같은 SQL이지만 성격이 전혀 다른 두 갈래를 나란히 보여 줍니다.

**해석**
앞 쿼리는 "브라질 고객의 이름"이라는 좁혀진 표 하나를 돌려줍니다. 뒤 쿼리는 직원과 고객의 이름을 한 명단으로 합쳐, 두 표에 흩어져 있던 사람들을 하나의 목록으로 보여 줍니다.

**실무 연결**
실무에서 "여러 출처의 명단을 하나로 합쳐 메일을 보내야 한다"거나 "두 기간에 모두 활동한 사용자만 추려야 한다"는 요구는 끊임없이 등장합니다. 이때 관계 연산만으로는 부족하고 집합 연산이 필요합니다.

## 헷갈리기 쉬운 포인트

- **집합 연산 vs 관계 연산**: 집합 연산은 두 표를 *위아래(세로)*로 합치거나 빼는 것, 관계 연산은 한 표를 다듬거나 다른 표와 *옆(가로)*으로 잇는 것.
- **셀렉션 vs SELECT**: 관계형 대수의 셀렉션은 행을 고르는 `WHERE`에 해당하고, SQL의 `SELECT` 키워드는 열을 고르는 프로젝션에 가깝다.
- **카티션 곱 vs 조인**: 카티션 곱은 모든 조합을 만들고, 조인은 거기서 조건(키 일치)에 맞는 조합만 남긴 것.
