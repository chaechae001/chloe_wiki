# loc와 iloc — 라벨로 뽑을까, 위치로 뽑을까

> "3번째 행, 7번째 열의 값"과 "연우의 수학 점수"는 같은 칸을 가리킬 수도 있습니다. 같은 데이터를 부르는 두 가지 방식, 언제 무엇을 써야 할까요?

`loc` `iloc` `라벨 기반` `위치 기반` `슬라이싱` `copy`

## 핵심요약

- `loc`는 **라벨(이름) 기반** 조회입니다. 인덱스 이름·컬럼 이름으로 데이터를 고릅니다.
- `iloc`는 **위치(정수) 기반** 조회입니다. 0, 1, 2… 번째 순서로 데이터를 고릅니다.
- 둘 다 `[행, 열]` 형태로 씁니다. `:`은 "전체"를 뜻합니다.
- `iloc` 슬라이싱은 **끝 번호를 포함하지 않습니다**(`0:10`은 0~9번째).
- 분석할 때는 코드 의미가 잘 드러나는 `loc`가 기본, 자동화·위치 처리에는 `iloc`가 유리합니다.
- 일부만 떼어 따로 다룰 때는 `.copy()`를 붙여 원본이 바뀌지 않게 보호합니다.
- `loc`/`iloc`로 특정 칸을 골라 **값을 바꿀 수도** 있습니다.

---

## loc — 라벨(이름)로 고르기

**1. 정의**
인덱스 이름과 컬럼 이름을 받아 그에 해당하는 데이터를 뽑습니다. `df.loc[행조건, 열선택]` 형태입니다.

**2. 왜 필요한가?**
컬럼 이름을 그대로 적기 때문에 **코드만 봐도 무엇을 뽑는지 의미가 드러납니다.** 분석 코드의 가독성이 좋아져 실무에서 가장 많이 씁니다.

**3. 예시**

```python
# 전체 행, 특정 컬럼들만 조회
df_srv.loc[:, ['location', 'cpu_usage', 'uptime_days']]

# 전체 행, 전체 열 (시작점)
df_srv.loc[:, :]
```

**4. 헷갈리기 쉬운 점**
`loc`의 라벨 슬라이싱은 상황에 따라 **끝 라벨을 포함**할 수 있습니다. 위치 기반인 `iloc`와 규칙이 다르니, "지금 라벨로 자르는지 위치로 자르는지"를 먼저 구분해야 합니다.

**5. 한 줄 정리**
`loc`는 "이름표를 보고 고르는" 방식입니다.

> 🏷️ 비유: `loc`는 사물함에 붙은 **이름표("연우")** 를 보고 찾는 것입니다.

### iloc — 위치(순서)로 고르기

**1. 정의**
이름이 아니라 **정수 위치**로 데이터를 뽑습니다. `df.iloc[행위치, 열위치]` 형태입니다.

**2. 왜 필요한가?**
컬럼 이름을 모르거나, 반복문으로 위치를 하나씩 옮겨 가며 처리하는 **자동화·대용량 처리**에 유리합니다.

**3. 예시**

```python
df_srv.iloc[:, :]    # 전체 (시작점)
df_srv.iloc[:, 7]    # 7번째 열 (예: cpu_usage)
df_srv.iloc[0, 7]    # 0번째 행, 7번째 열의 한 칸

df_sup.iloc[:5, :3]  # 0~4행, 0~2열
df_sup.iloc[:5, 3:8] # 0~4행, 3~7열
```

**4. 헷갈리기 쉬운 점**
숫자만 보면 7번째 열이 어떤 컬럼인지 코드로는 알 수 없습니다. 가독성이 떨어지는 게 `iloc`의 단점입니다.

**5. 한 줄 정리**
`iloc`는 "몇 번째인지 세서 고르는" 방식입니다.

> 🔢 비유: `iloc`는 사물함을 **번호("위에서 네 번째 칸")** 로 찾는 것입니다.

---

## 슬라이싱의 끝값 규칙

`iloc` 슬라이싱은 파이썬 기본 슬라이싱과 똑같이 **끝 번호를 포함하지 않습니다.**

```python
df.iloc[0:10]     # 0~9번째 행 (10번째는 빠짐) → 처음 10개
df.iloc[100:105]  # 100~104번째 행 (105번째는 빠짐)
df.iloc[0:3, 1:3] # 0~2행, 1~2열
```

처음엔 "10개를 원하는데 왜 10이 안 들어가지?"라며 헷갈리기 쉽지만, **"끝 번호 직전까지"** 라고 기억하면 됩니다.

---

## 컬럼 선택 자동화 — columns.tolist()

컬럼 이름을 매번 문자열로 직접 적는 대신, 컬럼 목록을 리스트로 받아 인덱싱·슬라이싱으로 골라낼 수 있습니다.

```python
df_wel.columns.tolist()           # 컬럼명을 리스트로
df_wel.columns.tolist()[0]        # 첫 번째 컬럼명
fc = df_wel.columns.tolist()[0:7] # 앞 7개 컬럼명만
df_wel.loc[:, fc].head()          # 그 컬럼들만 조회
```

이렇게 하면 컬럼 개수가 많아도 일일이 타이핑하지 않고, 위치만 바꿔 가며 컬럼을 선택하는 자동화가 가능합니다.

---

## 일부만 떼어낼 땐 .copy()

분석용으로 일부 컬럼만 떼어 새 변수에 담을 때는 `.copy()`를 붙이는 습관이 중요합니다. 붙이지 않으면 원본과 연결되어, 새 변수를 바꿨는데 원본까지 바뀌는 일이 생길 수 있습니다.

```python
df_wel2 = df_wel.loc[:, ['soldier_id', 'region', 'satisfaction_score']].copy()
df_wel2.head()
```

> ⚠️ `copy`가 아니라 반드시 `copy()`처럼 **소괄호를 붙여 호출**합니다.

---

## loc·iloc으로 값 바꾸기

조회뿐 아니라, 고른 위치에 **값을 직접 넣어** 데이터를 수정할 수도 있습니다.

```python
df.loc["서아", "국어"] = 100  # '서아' 행, '국어' 열의 값을 100으로
df.iloc[1, 1] = 99            # 1번째 행, 1번째 열의 값을 99로
```

라벨로 바꾸고 싶으면 `loc`, 위치로 바꾸고 싶으면 `iloc`을 씁니다.

---

## 코드로 보기 — 같은 칸을 두 방식으로 가리키기

```python
# 성적표에서 '연우'의 '수학' 점수를 뽑는 두 가지 방법
grade.loc["연우", "수학"]  # 라벨 기반
grade.iloc[3, 1]          # 위치 기반 (연우가 3번째 행, 수학이 1번째 열)
```

**코드목적**
같은 한 칸을 "이름"으로도, "순서"로도 가리킬 수 있음을 보여 줍니다.

**해석**
`loc`는 사람이 읽기 좋고(연우의 수학), `iloc`는 컴퓨터가 반복 처리하기 좋습니다(3행 1열). 결과 값은 같지만 사고방식이 다릅니다.

**실무 연결**
보고서·분석 코드에서는 의미가 드러나는 `loc`를 기본으로 쓰고, 수천 개 컬럼을 반복문으로 훑는 전처리 자동화에서는 `iloc`로 위치를 옮겨 가며 처리합니다.

## 헷갈리기 쉬운 포인트

- **loc vs iloc**: 라벨(이름)이면 `loc`, 위치(정수)면 `iloc`.
- **슬라이싱 끝값**: `iloc[0:10]`은 10 미포함, `loc`의 라벨 슬라이싱은 끝 라벨 포함 가능.
- **copy() 유무**: 붙이면 원본과 분리, 안 붙이면 원본이 함께 바뀔 수 있음.
