# 데이터 분석 프로젝트는 어떻게 흘러가는가

> 분석을 처음 시작하면 "그래서 뭘 먼저 해야 하지?"가 가장 막막합니다. 사실 거의 모든 데이터 분석은 똑같은 네 단계를 따라갑니다. 그 지도를 먼저 손에 쥐어 봅시다.

`데이터분석` `워크플로우` `pandas` `시각화` `요소수대란` `현실데이터`

## 핵심요약

- 데이터 분석은 **불러오기 → 전처리 → 분석 → 시각화**라는 네 단계로 흐른다.
- "전처리"가 전체 시간의 가장 큰 부분을 차지한다 — 화려한 그래프보다 지루한 청소가 먼저다.
- 단계마다 주로 쓰는 도구(라이브러리)가 정해져 있다: `pandas`(표 다루기), `matplotlib`·`seaborn`(그래프), `folium`(지도).
- 토이 데이터가 아니라 **실제로 뉴스가 된 데이터**를 다루면, 분석이 곧 "현실 문제에 답하기"가 된다.
- 좋은 분석은 멋진 결과가 아니라 **"믿을 수 있는 결과"**다. 그래서 중간 점검(결측치·이상치 확인)이 중요하다.
- 같은 흐름이 요소수·유가·지하철 어떤 주제에도 그대로 적용된다.

## 개념별 정리

### 데이터 분석의 4단계 워크플로우

**1. 정의**
데이터를 받아서 인사이트(쓸모 있는 결론)에 도달하기까지의 표준 순서입니다. 보통 이렇게 흐릅니다.

1. **불러오기(Load)**: 파일(주로 CSV)을 파이썬으로 읽어 표 형태로 만든다.
2. **전처리(Preprocessing)**: 비어 있거나 잘못된 값을 정리하고, 분석하기 좋은 형태로 다듬는다.
3. **분석(Analysis)**: 평균·분포·관계 등을 계산하며 데이터에 질문을 던진다.
4. **시각화(Visualization)**: 결과를 그래프나 지도로 그려 한눈에 보이게 한다.

**2. 왜 필요한가?**
순서가 정해져 있으면 "지금 내가 어디쯤 있는지"를 항상 알 수 있습니다. 전처리를 건너뛰고 바로 그래프를 그리면, 비어 있는 값이나 0원짜리 가격 같은 함정 때문에 **틀린 결론**을 멋지게 그려내는 사고가 납니다. 실무에서도 보고서의 신뢰는 이 단계들을 빠짐없이 밟았는지에서 갈립니다.

**3. 예시**
요소수 재고 분석 프로젝트의 시작 부분은 이 4단계를 그대로 보여줍니다.

```python
import numpy as np
import pandas as pd

# 1) 불러오기
df = pd.read_csv("./data/urea_data.csv")

# 2) 전처리 — 비어 있는 '영업시간' 열 삭제
df = df.drop('openTime', axis=1)

# 3) 분석 — 평균 재고량 계산
inven_mean = df['inventory'].mean()
print(f"재고량 평균은 {inven_mean:.2f}개")

# 4) 시각화 — (뒤 글에서) 히스토그램·지도로 표현
```

위 코드는 "파일을 읽고 → 쓸모없는 열을 버리고 → 평균을 구하는" 흐름을 단 몇 줄로 보여줍니다. 분석 전체가 결국 이 패턴의 반복입니다.

**4. 헷갈리기 쉬운 점**
초보자는 "분석 = 그래프 그리기"라고 생각해 4단계 중 시각화에만 힘을 쏟습니다. 하지만 실제로는 **2단계 전처리가 가장 오래 걸리고 가장 중요**합니다. 그래프는 깨끗한 데이터 위에서만 진실을 말합니다.

**5. 한 줄 정리**
데이터 분석은 "불러오고 → 청소하고 → 질문하고 → 보여주는" 네 단계의 반복이다.

> 비유: 요리와 같습니다. 장보기(불러오기) → 손질·세척(전처리) → 조리(분석) → 플레이팅(시각화). 재료를 안 씻고 바로 볼링하면, 아무리 예쁘게 담아도 먹을 수 없습니다.

### 단계마다 손이 가는 도구(라이브러리)

**1. 정의**
라이브러리는 "이미 만들어진 기능 묶음"입니다. 분석 단계마다 자주 쓰는 라이브러리가 정해져 있습니다.

| 단계 | 라이브러리 | 하는 일 |
|------|-----------|---------|
| 표 다루기 전반 | `pandas` | CSV 읽기, 표(DataFrame) 가공, 통계 계산 |
| 숫자 계산 | `numpy` | 빠른 수치 연산, 배열 |
| 그래프 | `matplotlib` | 기본 그래프(선·막대·히스토그램) |
| 예쁜 통계 그래프 | `seaborn` | 박스플롯·히트맵 등을 짧은 코드로 |
| 지도 | `folium` | 위도·경도를 인터랙티브 지도에 표시 |

**2. 왜 필요한가?**
바닥부터 직접 만들면 평균 하나 구하는 데도 한참 걸립니다. 라이브러리는 검증된 도구라서, 우리는 "무엇을 분석할지"에만 집중할 수 있습니다. 면접·실무에서도 "어떤 작업에 어떤 라이브러리를 쓰는가"를 아는 것이 기본기로 통합니다.

**3. 예시**
```python
import numpy as np            # 수치 계산
import pandas as pd           # 표 다루기
import matplotlib.pyplot as plt  # 그래프
import seaborn as sns         # 통계 그래프
import folium                 # 지도
```
분석을 시작할 때 거의 항상 등장하는 "기본 세트"입니다.

**4. 헷갈리기 쉬운 점**
`matplotlib`와 `seaborn`은 둘 다 그래프 도구라 헷갈립니다. `seaborn`은 사실 `matplotlib` 위에 얹힌 도구로, **더 적은 코드로 더 예쁜 통계 그래프**를 그려줍니다. 둘은 경쟁자가 아니라 같이 씁니다.

**5. 한 줄 정리**
표는 `pandas`, 그래프는 `matplotlib`/`seaborn`, 지도는 `folium`이 담당한다.

> 비유: 라이브러리는 공구함의 도구들입니다. 못 박을 땐 망치(`matplotlib`), 나사는 드라이버(`folium`)처럼, 작업마다 맞는 도구가 따로 있습니다.

### 왜 "현실 데이터"로 연습하는가

**1. 정의**
교과서용으로 깔끔하게 정리된 데이터가 아니라, 공공데이터 포털 같은 곳에서 실제로 수집된 — 그래서 결측치와 오류가 섞여 있는 — 데이터를 말합니다.

**2. 왜 필요한가?**
현실 데이터는 더럽습니다. 비어 있는 칸, 0원짜리 가격, 같은 지역을 "인천"과 "인천광역시"로 다르게 적은 표기 등이 늘 있습니다. 이런 데이터를 다뤄봐야 **실무에서 진짜 쓰이는 분석력**이 길러집니다. 2021년 요소수 대란처럼 사회적으로 중요했던 문제를 다루면, 분석 결과가 곧 의미 있는 답이 됩니다.

**3. 예시**
- **요소수 데이터**: 전국 200여 개 주유소의 요소수 가격·재고를 분석
- **유가 데이터**: 전국 1만여 개 주유소의 4개년 휘발유 가격을 분석
- **지하철 데이터**: 서울 지하철 역별 승하차 인원으로 혼잡도를 분석

세 데이터 모두 공공데이터 포털·서울 열린데이터광장에서 받은 실제 자료입니다.

**4. 헷갈리기 쉬운 점**
"현실 데이터는 어려우니 나중에"라고 미루기 쉽지만, 사실 **처음부터 더러운 데이터를 만나봐야** 전처리 감각이 생깁니다. 깨끗한 데이터만 다루면 정작 실무에서 길을 잃습니다.

**5. 한 줄 정리**
현실 데이터는 지저분하지만, 그 지저분함을 다루는 것이 진짜 실력이다.

## 코드로 보기 — 분석의 첫 5줄

```python
import numpy as np
import pandas as pd

df = pd.read_csv("./data/urea_data.csv")
print(df.shape)   # (200, 11)  → 행 200개, 열 11개
df.head()         # 위에서 5줄 미리 보기
```

**코드목적**
파일을 표로 읽어 들이고, "데이터가 몇 행 몇 열인지, 어떻게 생겼는지"를 가장 먼저 확인하기 위한 코드입니다.

**해석**
`df.shape`가 `(200, 11)`이면 요소수 유통 주유소 200곳에 대해 11가지 정보(주소·재고·가격·위도·경도·전화번호 등)가 들어 있다는 뜻입니다. `head()`로 실제 값들을 눈으로 확인하면, 어떤 전처리가 필요한지 감이 잡힙니다.

**실무 연결**
어떤 분석이든 첫 동작은 "데이터의 크기와 모양 확인"입니다. 데이터가 100만 행인지 200행인지에 따라 분석 전략과 사용할 도구가 달라지기 때문입니다.

## 헷갈리기 쉬운 포인트

- **분석 vs 시각화**: 분석은 "계산해서 답을 얻는 것", 시각화는 "그 답을 보이게 하는 것"입니다. 그래프를 그렸다고 분석이 끝난 게 아닙니다.
- **라이브러리 vs 함수**: 라이브러리는 도구 묶음(예: `pandas`), 함수는 그 안의 개별 기능(예: `read_csv`)입니다.
- **전처리 vs 분석**: 전처리는 "데이터를 믿을 수 있게 만드는 일", 분석은 "그 데이터에 질문하는 일"입니다.

## 한 줄 정리

> 모든 데이터 분석은 "불러오기 → 전처리 → 분석 → 시각화"라는 같은 길을 걷는다. 이 지도를 쥐고 있으면 어떤 데이터 앞에서도 길을 잃지 않는다.
