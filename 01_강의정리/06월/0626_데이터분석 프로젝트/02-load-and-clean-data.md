# 데이터 불러오기와 정제 — 분석의 80%는 청소다

> 그래프는 화려하지만, 분석가가 실제로 가장 오래 붙잡는 일은 "비어 있는 칸 메우고, 이상한 값 골라내고, 잘못된 형식 고치는" 지루한 청소입니다. 이 청소가 분석의 신뢰를 결정합니다.

`결측치` `이상치` `형변환` `데이터정합성` `read_csv` `info` `describe` `전처리`

## 핵심요약

- `read_csv`로 파일을 표(DataFrame)로 읽고, `info()`·`describe()`로 데이터의 건강 상태를 진단한다.
- **결측치(missing)**: 비어 있는 값. 열 전체가 비면 그 열을 버리기도 한다(`drop`).
- **이상치(outlier)**: 음수 가격이나 0원처럼 말이 안 되는 값. 정렬해서 양 끝을 살펴보면 잡힌다.
- **형 변환**: 날짜가 숫자(`20180601`)로 읽히면 `datetime`으로 바꿔야 날짜처럼 다룰 수 있다.
- **데이터 정합성**: "한 주유소는 7일 내내 같은 브랜드여야 한다" 같은 상식을 코드로 점검한다.
- 청소의 목적은 "데이터를 믿을 수 있게" 만드는 것. 모든 분석의 토대가 여기서 결정된다.

## 개념별 정리

### 데이터 진단 — info()와 describe()

**1. 정의**
데이터를 읽은 직후, "이 데이터가 어떻게 생겼는지"를 빠르게 파악하는 두 가지 점검 도구입니다.
- `df.info()`: 각 열의 데이터 종류(숫자/문자), 비어 있지 않은 값의 개수를 보여줌
- `df.describe()`: 숫자 열의 평균·최소·최대·사분위수 등 요약 통계를 보여줌

**2. 왜 필요한가?**
청소를 시작하려면 "어디가 더러운지"부터 알아야 합니다. `info()`는 결측치가 있는 열을, `describe()`는 이상치(예: 최솟값이 0인 가격)를 한눈에 드러냅니다. 실무에서 데이터를 받으면 가장 먼저 하는 동작입니다.

**3. 예시**
유가 데이터를 `describe(include='all')`로 점검하면 이런 단서가 나옵니다.

```python
f18.describe(include='all')
```

여기서 발견한 점검 포인트:
- 주유소 고유 번호가 11,673개이며 최대 7번까지 기록됨(7일치 데이터라는 뜻)
- '기간'이 날짜가 아니라 **숫자**로 인식되고 있음 → 형 변환 필요
- '지역'의 종류가 229개로 너무 잘게 나뉨 → 시·도 단위로 묶을 필요
- '휘발유' 가격의 최솟값이 **0** → 이상치 의심

**4. 헷갈리기 쉬운 점**
`describe()`는 기본적으로 **숫자 열만** 요약합니다. 문자 열(브랜드·지역)까지 보려면 `include='all'`을 넣어야 합니다. 이걸 모르면 "왜 브랜드 정보가 안 나오지?" 하고 헤맵니다.

**5. 한 줄 정리**
`info()`로 빈칸을, `describe()`로 이상한 값을 가장 먼저 찾는다.

> 비유: 건강검진의 기초 검사입니다. 본격 치료(분석) 전에 혈압·체온부터 재는 것과 같습니다.

### 결측치(Missing Value) 처리

**1. 정의**
값이 비어 있는 칸을 결측치라고 합니다. 파이썬에서는 보통 `NaN`(Not a Number)으로 표시됩니다.

**2. 왜 필요한가?**
비어 있는 값은 평균 계산을 망치거나 그래프를 그릴 때 오류를 냅니다. 그냥 두면 결과를 믿을 수 없으니, **버리거나 채우거나** 결정해야 합니다.

**3. 예시**
요소수 데이터에서 `info()`로 보니 '영업시간(openTime)' 열에만 결측치가 있었습니다. 영업시간 정보가 거의 없어 분석에 쓸모가 없으므로 열 전체를 삭제했습니다.

```python
df.info()                       # openTime 열에 결측치 발견
df = df.drop('openTime', axis=1)  # 열 전체 삭제 (axis=1 = 열 방향)
```

**4. 헷갈리기 쉬운 점**
`drop`의 `axis` 값이 헷갈립니다. `axis=0`은 **행(가로줄)** 삭제, `axis=1`은 **열(세로줄)** 삭제입니다. 열을 지우려는데 `axis=0`을 쓰면 엉뚱한 행이 사라집니다.

**5. 한 줄 정리**
비어 있으면 버릴지 채울지 정해라 — 쓸모없는 열은 과감히 `drop`.

> 비유: 설문지에서 응답이 하나도 없는 문항은 통째로 빼는 것과 같습니다.

### 이상치(Outlier) 점검

**1. 정의**
다른 값들과 동떨어진, 말이 안 되는 극단값입니다. 음수 가격, 0원, 터무니없이 큰 재고량 등이 해당합니다.

**2. 왜 필요한가?**
이상치 하나가 평균을 크게 흔들고 그래프를 왜곡합니다. 다만 "진짜 오류인지(0원=영업중단)" 아니면 "드물지만 실제 값인지"를 구분해야 합니다 — 도메인(분야) 지식이 필요한 대목입니다.

**3. 예시**
요소수 재고와 가격을 정렬해 양 끝(가장 작은 값·가장 큰 값)을 직접 눈으로 점검했습니다.

```python
# 재고량이 가장 적은 5개, 가장 많은 5개를 본다
df['inventory'].sort_values()[:5]
df['inventory'].sort_values()[-5:]
```

확인 결과 음수나 비현실적으로 큰 값이 없어 "이상치 없음"으로 판단했습니다. 반면 유가 데이터에서는 휘발유 가격이 `0`인 행이 있었는데, 같은 주유소를 들여다보니 다른 날엔 1,595원이었습니다. **0은 그날 영업하지 않았다는 의미**로 보고 제거했습니다.

```python
f18.loc[f18['휘발유'] == 0]          # 0원인 행 확인
f18 = f18.loc[f18['휘발유'] != 0, :]  # 0원인 행 제거
```

**4. 헷갈리기 쉬운 점**
이상치를 무조건 지우면 안 됩니다. "강남의 비싼 주유소"는 이상치처럼 보여도 **진짜 데이터**입니다. 0원처럼 명백한 오류만 제거하고, 나머지는 도메인 지식으로 판단합니다.

**5. 한 줄 정리**
정렬해서 양 끝을 보고, 명백한 오류(0·음수)만 골라낸다.

> 비유: 시험 점수에 적힌 "-5점"이나 "200점"은 입력 실수입니다. 하지만 "98점"은 드물어도 진짜 점수일 수 있습니다.

### 형 변환(Type Conversion)

**1. 정의**
컴퓨터가 잘못 인식한 데이터의 "종류"를 올바르게 바꾸는 일입니다. 대표적으로 날짜가 숫자로 읽힌 경우를 날짜형(`datetime`)으로 고칩니다.

**2. 왜 필요한가?**
`20180601`이 숫자로 남아 있으면 "6월 1일과 6월 7일 사이 며칠"같은 날짜 계산을 할 수 없습니다. 날짜형으로 바꿔야 비로소 날짜답게 다룰 수 있습니다.

**3. 예시**
```python
# 숫자 20180601 → 날짜 2018-06-01 로 변환
f18['기간'] = f18['기간'].apply(lambda x: pd.to_datetime(str(int(x))))
```
가격이 문자로 읽히는 경우도 흔한데, 이때는 `pd.to_numeric`으로 숫자로 바꿉니다.

**4. 헷갈리기 쉬운 점**
숫자처럼 보여도 실제로는 문자(`'1579'`)일 수 있습니다. 문자끼리는 더하면 이어붙기(`'15'+'79'='1579'`)가 되므로, 계산 전에 반드시 형을 확인해야 합니다.

**5. 한 줄 정리**
날짜는 날짜답게, 숫자는 숫자답게 — 형을 맞춰야 계산이 된다.

> 비유: 자물쇠 비밀번호를 "글자"로 적어두면 더하기를 할 수 없습니다. "숫자"로 바꿔야 연산이 됩니다.

### 데이터 정합성(Consistency) 확인

**1. 정의**
"이 데이터는 당연히 이래야 한다"는 상식이 실제로 지켜졌는지 코드로 검사하는 일입니다.

**2. 왜 필요한가?**
수집 과정에서 오류가 섞이면, 한 주유소가 7일 사이에 브랜드가 바뀐 것처럼 기록되기도 합니다. 이런 모순된 데이터를 그대로 두면 집계가 어긋납니다.

**3. 예시**
"한 주유소는 7일 동안 지역·브랜드·셀프여부가 변하지 않아야 한다"는 전제를 점검했습니다.

```python
# 주유소별로 지역·상표·셀프여부의 '종류 수'를 센다 (정상이면 모두 1)
unique_count = f18.groupby('번호')[['지역','상표','셀프여부']].nunique()

# 종류가 1이 아닌(=값이 바뀐) 주유소만 추려낸다
target = unique_count.loc[(unique_count != 1).sum(axis=1) != 0]
```

이렇게 찾아낸 두 주유소(예: 7일 중 6일은 현대오일뱅크, 마지막 날만 다른 브랜드)는 수집 오류로 보고 제거했습니다.

**4. 헷갈리기 쉬운 점**
`nunique()`(고유값의 **개수**)와 `unique()`(고유값 **목록**)는 다릅니다. 정합성 점검에는 "몇 종류인가"가 필요하므로 `nunique()`를 씁니다.

**5. 한 줄 정리**
"당연한 규칙"을 코드로 검사해 모순된 데이터를 걸러낸다.

> 비유: 같은 사람의 주민번호가 서류마다 다르다면 어딘가 입력 오류입니다. 그런 모순을 찾아내는 검사입니다.

## 코드로 보기 — 유가 데이터 정제 한 사이클

```python
f18 = pd.read_csv('./data/gas_price_2018.csv')

f18 = f18.drop(0)                                  # 0번 행: 메타 헤더라 제거
f18['기간'] = f18['기간'].apply(lambda x: pd.to_datetime(str(int(x))))  # 형 변환
f18['지역2'] = f18['지역'].apply(lambda x: x.split()[0])  # '강원 강릉시' → '강원'
f18 = f18.loc[f18['휘발유'] != 0, :]                # 0원(영업중단) 제거

# 정합성: 7일간 값이 바뀐 주유소 찾아 제거
uc = f18.groupby('번호')[['지역','상표','셀프여부']].nunique()
target = uc.loc[(uc != 1).sum(axis=1) != 0]
f18 = f18.loc[~f18['번호'].isin(target.index)]
```

**코드목적**
원본 CSV를 "신뢰할 수 있는 표"로 만들기 위한 청소 한 바퀴입니다. 불필요한 행 제거 → 형 변환 → 새 컬럼 생성 → 이상치 제거 → 정합성 점검을 순서대로 수행합니다.

**해석**
이 과정을 거치면 2018년 데이터는 8만여 행에서 모순·오류가 걸러진 깨끗한 표로 정리됩니다. `'지역2'`라는 새 컬럼이 생긴 덕분에 이후 "시·도별 가격 비교"가 가능해집니다.

**실무 연결**
실제 분석 업무 시간의 절반 이상이 이런 정제 코드 작성입니다. 깨끗하게 정제된 데이터는 이후 모든 분석·시각화·보고서의 신뢰를 떠받칩니다. 정제 과정을 기록해두면 "이 결론이 어떤 데이터에서 나왔는지" 추적도 가능합니다.

## 헷갈리기 쉬운 포인트

- **`axis=0` vs `axis=1`**: 0은 행(가로줄), 1은 열(세로줄). 열을 지우려면 `axis=1`.
- **`unique()` vs `nunique()`**: 앞은 고유값 **목록**, 뒤는 고유값 **개수**.
- **결측치 vs 이상치**: 결측치는 "비어 있음", 이상치는 "값은 있지만 말이 안 됨".
- **이상치 제거 vs 보존**: 명백한 오류(0·음수)는 제거, 드물지만 진짜인 값은 보존.

**복습 질문 및 답변**

*기본:* 결측치와 이상치의 차이는 무엇인가요?
→ 결측치는 값이 비어 있는 것, 이상치는 값은 있지만 비현실적인 극단값입니다.

*이해 확인:* 휘발유 가격이 0원인 행을 왜 제거했나요?
→ 같은 주유소의 다른 날 가격은 정상이었고, 0원은 그날 영업하지 않았다는 의미라 분석에서 빼는 것이 맞기 때문입니다.

*응용:* "한 주유소는 7일 내내 같은 브랜드"라는 규칙을 코드로 점검하려면 어떤 함수가 필요할까요?
→ `groupby('번호')` 후 `nunique()`로 브랜드 종류 수를 세고, 그 수가 1이 아닌 주유소를 골라냅니다.

## 한 줄 정리

> 분석의 신뢰는 그래프가 아니라 청소에서 나온다. 결측치·이상치·형 오류·모순을 잡아내야 비로소 데이터를 믿을 수 있다.
