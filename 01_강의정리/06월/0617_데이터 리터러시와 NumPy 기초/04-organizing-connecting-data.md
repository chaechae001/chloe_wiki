# 데이터를 모으고 연결하기 — 수집 원천부터 관계형 DB까지

> 좋은 분석은 "한 덩어리의 깨끗한 데이터"가 거의 없다는 사실에서 출발합니다. 데이터는 여기저기서 모아, 서로 연결할 수 있는 구조로 다듬어야 비로소 분석할 수 있습니다.

`데이터 수집 원천` · `정형/비정형` · `반정형` · `변수 척도` · `관계형 데이터베이스` · `키` · `Join/Concat/Merge`

## 핵심요약

- 데이터는 데이터베이스·크롤링·로그·센서·설문·Open API 등 **다양한 원천**에서 나오며, 원천마다 신뢰도 특성이 다르다.
- 공개 데이터는 공공데이터포털, 네이버 데이터랩, AI Hub, 통합 데이터지도 등에서 얻을 수 있다.
- 데이터는 형식에 따라 **정형 / 비정형(+ 반정형)** 으로 나뉘고, 활용 기법이 달라진다.
- 변수의 척도는 **명목 · 서열 · 등간 · 비율** 네 가지이며, 척도에 따라 가능한 연산·분석이 다르다.
- **관계형 데이터베이스**의 핵심은 **키(Key) · 유일성 · 무결성**으로, 여러 데이터를 안전하게 연결하는 토대다.
- 데이터를 합치는 방식은 **Concat(이어 붙이기) · Merge/Join(공통 키로 병합)** 으로 나뉜다.

## 개념별 정리

### 데이터 수집 원천

**1. 정의**
같은 데이터라도 어디서 왔는지에 따라 신뢰도와 가공 방법이 달라집니다. 대표적인 원천은 다음과 같습니다.

- **데이터베이스**: 여러 사람이 공유·사용할 목적으로 체계화해 통합·관리하는 데이터의 집합(사내 DB·CRM·ERP 등). 가장 신뢰도 높고 구조화된 데이터로, 주로 SQL이나 내부 API로 접근
- **크롤링 데이터**: 인터넷상의 정보 중 자동화 기기로 탐색·수집한 데이터(BeautifulSoup·Selenium·Scrapy 등 사용). 반드시 합법성(robots.txt·이용약관·상업적 이용 가능 여부)을 확인해야 하고, 사이트 구조가 바뀌면 유지보수가 필요
- **로그 데이터**: 실제 현실에서 발생하는 사건(클릭·검색·방문·구매·오류)을 데이터로 기록한 것. 보통 Raw Log → 파싱 → 정제 과정을 거침
- **센서 데이터**: 물리적 환경에 특정 기기가 반응하여 수집한 데이터(IoT·인공지능 분야에서 매우 중요). 실시간 스트리밍 처리가 필요한 경우가 많음
- **설문 데이터**: 설문조사 결과를 기반으로 수집한 것
- **Open API 데이터**: 파일 혹은 API를 활용해 제공되는 데이터(공공데이터포털·기상청 API 등, 보통 JSON/XML 응답). 메타데이터(제공기관·수집기준일·갱신주기·항목정의·이용조건) 확인이 필수

**2. 원천별 신뢰도 주의점**
- **크롤링**: 모든 웹 데이터는 HTML로 구조화되어 있어 다시 확인 가능하지만, 대상 페이지의 신뢰도를 먼저 파악해야 함
- **로그**: 기록 자체의 오류(한 행동이 중복 적재), 설계 과정의 실수(잘못된 값 인식)가 생길 수 있어, 분석 시 로그를 일부러 남기고 확인하는 것이 바람직
- **센서**: 숫자의 의미 파악이 어렵고 용량이 커 처리에 어려움 → 중복·결측·오류를 먼저 검증
- **설문**: 응답자 자체로 인한 편향 가능, 개수가 적어 간단한 분석에 그칠 수 있어 계획 단계부터 장치 필요
- **Open API**: 제공받은 파일·API의 신뢰도가 선행되어야 전체 신뢰성 판단 가능 → **메타 데이터(Meta Data)** 를 확보해 데이터의 의미를 명확히 이해해야 함

**3. 공개 데이터를 어디서 얻나**
| 사이트 | 특징 |
| --- | --- |
| 공공데이터포털(data.go.kr) | 행정안전부가 국민에게 다양한 공공데이터를 무료 제공(기술 특허·부동산·식당 등) |
| 네이버 데이터랩(datalab.naver.com) | GUI 기반으로 검색어·쇼핑 카테고리 등 데이터 현황 탐색 |
| AI Hub(aihub.or.kr) | 인공지능 모델 학습에 초점을 맞춘 데이터 제공(한국어·영상·헬스케어 등) |
| 통합 데이터지도(bigdata-map.kr) | 공공·민간 데이터를 한데 모아 검색, 유료/무료 구분 제공 |

**4. 헷갈리기 쉬운 점**
- **집계 데이터 vs 로우(raw) 데이터**: 통계청 자료처럼 이미 집계된 데이터는 가공 여지가 제한적입니다. 프로젝트·분석용으로는 **가공 전 원자료(로우 데이터)** 확보가 중요합니다.
- 기업 소속이 아니라면 양질 데이터 확보가 어렵기 때문에, 프로젝트는 탐색 목적의 **공개 데이터** 활용이 현실적입니다.

**5. 한 줄 정리**
데이터를 받을 땐 "어디서, 어떻게 만들어졌는가(원천과 메타 데이터)"를 먼저 확인합니다.

> 누가 이 데이터를 모으고 다듬을까? — 데이터를 수집·저장·처리해 활용 가능한 형태로 만드는 **데이터 파이프라인**(수집 → 저장 → 처리·정제 → 분석/AI 활용)을 구축하는 역할이 **데이터 엔지니어**입니다. 분석가보다 개발자에 가까우며, 자동화 프로그램과 처리 시스템을 만듭니다. "책을 스캔해 학습 데이터를 만들었다"는 한 문장 뒤에도 스캔 장비·저장 시스템·문자 인식·고문서 처리·정제 같은 복잡한 과정이 숨어 있습니다.

### 정형 / 비정형 / 반정형 데이터

**1. 정의**
- **정형 데이터**: 미리 정해 놓은 형식과 구조가 있어 고정된 자리에 저장된 데이터(엑셀·DB 테이블 형태)
- **비정형 데이터**: 정의된 구조가 없는 데이터(텍스트·이미지·영상·오디오)
- **반정형 데이터**: 구조가 일부 있는 데이터(JSON, 딕셔너리 구조 등)

**2. 왜 필요한가?**
데이터 형식에 따라 적용할 수 있는 분석 기법이 달라지기 때문입니다. 일반적인 통계·머신러닝 기법은 **정형 데이터** 중심으로 적용됩니다.

**3. 활용 방식의 차이**
- **정형 데이터**: 평균·표준편차·단순 시각화 등 일차적 분석 → 심화된 통계 기법 → 머신러닝 등 AI 알고리즘 구현까지 다양하게 활용
- **비정형 데이터**: 딥러닝을 통한 AI 구현에 주로 활용, 일반 통계 기법 적용에는 한계. 정성적 분석에서는 저품질로 취급되기도 하지만, 비정형 데이터를 정성적으로 분석하려는 연구도 활발

**4. 헷갈리기 쉬운 점**
"비정형 = 쓸모없다"가 아닙니다. 비정형 데이터는 통계 기법엔 한계가 있지만, 딥러닝 시대에는 오히려 핵심 자원입니다(대부분의 최신 AI 모델은 비정형 데이터 기반으로 개발). 실제로 전체 데이터 중 비정형이 차지하는 비중은 매우 크며(흔히 80% 이상으로 언급), 이를 다루려면 자연어 처리(NLP)·컴퓨터 비전 같은 AI 기법이 필요합니다.

**5. 한 줄 정리**
데이터의 형식이 곧 분석 방법을 결정합니다.

> 비유: 정형 데이터는 **잘 정리된 서랍장**, 비정형 데이터는 **사진·메모가 뒤섞인 상자**입니다. 서랍장은 바로 찾아 쓰고, 상자는 먼저 분류해야 합니다.

### 변수의 척도 (명목 · 서열 · 등간 · 비율)

**1. 정의**
변수의 속성(척도)에 따라 가능한 연산과 분석 방법이 달라집니다.

| 구분 | 척도 | 의미 | 예시 |
| --- | --- | --- | --- |
| 범주형 | 명목 척도 | 데이터를 단순히 숫자로 변환(구분만) | 남자:1, 여자:2 / 주민번호 |
| 범주형 | 서열 척도 | 데이터에 순서만 존재 | 금메달:1, 은메달:2, 동메달:3 / 등수 |
| 수치형 | 등간 척도 | 값의 상대적 크기 비교 가능(0이 절대적 없음 아님) | 온도 |
| 수치형 | 비율 척도 | 절대적 영점(0)이 존재하는 값 | 키, 몸무게 |

**2. 왜 필요한가?**
척도를 모르면 "해서는 안 될 연산"을 하게 됩니다. 변수의 속성에 따라 데이터 활용성에 차이가 날 수 있습니다.

**3. 예시 (범주형의 사칙연산 함정)**
범주형 데이터는 사칙 연산이 불가능합니다(수학적 연산에 한계가 있어 적용 가능한 기법에도 제한).
```
남자(1) * 2 = 여자(2)   ← 말이 안 됨
2등 x 2 = 4등            ← 말이 안 됨
```

**4. 헷갈리기 쉬운 점**
숫자로 적혀 있다고 다 같은 숫자가 아닙니다. "성별=1, 2"는 **이름표(범주)** 일 뿐 크기가 아닙니다. 다만 통계적 분석의 카이제곱 검정, 머신러닝의 CatBoost 같은 기법으로 범주형도 다룰 수 있습니다.

**5. 한 줄 정리**
변수의 척도를 알아야 어떤 연산·분석이 허용되는지 알 수 있습니다.

### 관계형 데이터베이스 (키 · 유일성 · 무결성)

**1. 정의**
**관계형 데이터베이스(RDB)** 는 데이터를 행(Row)과 열(Column)의 테이블(Table) 형식으로 저장하고, 서로 관계 있는 데이터를 관리하는 방식입니다. 빅데이터의 특성을 흔히 **3V = Velocity(속도) + Volume(양) + Variety(다양성)** 로 설명하며, RDB는 다양한 종류의 데이터를 알맞게 구분해 저장합니다.

핵심 용어는 세 가지입니다.
- **키(Key)**: 데이터의 속성(열) 중 식별자로 이용 가능한 속성
- **유일성**: 하나의 키가 하나의 데이터를 정확히 식별할 수 있는 성질
- **무결성**: 데이터에서 키 값이 비어 있거나 중복되지 않아야 하는 성질

**2. 왜 필요한가?**
보유한 다른 데이터와 유기적으로 연결해 넓은 시야로 분석하려면 RDB 형식이 사실상 필수입니다. **키가 없으면 그 데이터가 어떤 개인·상황을 의미하는지 알 수 없어**, 분석을 완성해도 실제로 활용할 수 없습니다.

**3. 예시 (키로 연결하기)**
이름이 키 역할을 할 수 있을까요? 같은 이름이 여럿이면 유일성이 깨져 키가 될 수 없습니다. 그래서 학생 테이블의 학번(Stud_Id)처럼 **유일하고 비어 있지 않은** 식별자가 필요합니다.
- **개체 무결성**: 모든 데이터는 키를 가져야 하며 중복이거나 결측일 수 없다.
- **참조 무결성**: 참조 관계에 있는 두 데이터가 항상 일관된 값을 가진다.

**4. 헷갈리기 쉬운 점**
겉보기에 키 역할을 하는 데이터가 있어도, **유일성**(중복을 제외한 전체 데이터 개수 = 중복을 제외한 전체 키 개수)을 반드시 확인해야 합니다.

**5. 한 줄 정리**
키·유일성·무결성이 갖춰져야 데이터를 안전하게 연결할 수 있습니다.

> 비유: 키는 사람의 **주민등록번호**입니다. 동명이인이 있어도 번호는 겹치지 않기에, 누가 누군지 정확히 연결할 수 있습니다.

### 데이터의 연결 (Concat · Merge/Join)

**1. 정의**
- **Data Concat**: 데이터를 수직/수평으로 이어 붙여 병합(축 기준 연결)
  - `axis=0`: 위아래로 쌓기(행 추가)
  - `axis=1`: 좌우로 붙이기(열 추가)
- **Data Merge / Join**: 공통된 컬럼(키)을 기준으로 데이터를 병합

**2. 왜 필요한가?**
데이터 분석은 단일 데이터보다 여러 데이터를 연결해 보는 경우가 많습니다. 그래서 양질의 데이터는 다른 데이터와 연결되기 좋은 구조를 띠고 있어야 합니다.

**3. 예시 (Join의 4가지)**
Merge(Join)는 어떤 기준으로 행을 남기느냐에 따라 네 가지로 나뉩니다.
- **INNER JOIN**: 양쪽 모두에 키가 있는 행만
- **LEFT JOIN**: 왼쪽 기준 전부 + 매칭되는 오른쪽
- **RIGHT JOIN**: 오른쪽 기준 전부 + 매칭되는 왼쪽
- **OUTER JOIN**: 양쪽 전부(매칭 안 되면 빈 값)

이름·성별·나이·직업 테이블과 이름·거주지·학력 테이블을 **이름(키)** 으로 Join하면, 한쪽에만 있는 사람의 거주지·학력은 빈 값(?)으로 채워집니다.

**4. 헷갈리기 쉬운 점**
- **Concat vs Merge**: Concat은 "그냥 이어 붙이기(축 기준)", Merge는 "공통 키로 맞춰 붙이기"입니다.
- Join 종류를 잘못 고르면 데이터가 누락되거나(INNER) 빈 값이 잔뜩 생깁니다(OUTER).

**5. 한 줄 정리**
이어 붙일 땐 Concat, 키로 맞춰 합칠 땐 Merge/Join입니다.

## 코드로 보기 — 분석용 테이블은 어떻게 만들어지나

이 글은 개념 중심이지만, 실무 흐름을 한 번에 정리합니다.

서비스 운영 후 쌓인 **정규화된 DB**(중복을 줄여 잘게 나눈 테이블들)에서, 분석가는 필요한 테이블을 **키로 Join**하고 결측을 처리해 **분석용 테이블(비정규화 형태)** 을 만듭니다.

```
정규화 DB(여러 테이블)
   │   ① 공통 키로 Join/Merge
   ▼
하나로 합쳐진 넓은 테이블
   │   ② 결측·이상치 처리(전처리)
   ▼
분석용 데이터셋(비정규화)  →  통계·시각화·머신러닝
```

**해석**
- DB 정규화는 주로 DB 설계·관리(DBA) 영역입니다.
- 분석가가 하는 "가공"은 분석 목적의 데이터셋 생성(조인·결측 처리 등)에 가깝습니다. 즉 "1차/2차/3차 가공"과 "DB 정규화"는 같은 개념이 아닙니다.

**실무 연결**
SQL을 "워드·엑셀급 필수 역량"이라 부르는 이유가 여기 있습니다. 데이터를 조인하고 가공해 분석용 테이블을 만드는 일이 데이터 직무의 일상이기 때문입니다.

## 직접 해보기

1. 내 프로젝트에 쓸 공개 데이터를 위 네 사이트에서 하나씩 찾아, 각각 정형/비정형/반정형 중 무엇인지 분류해 보세요.
2. 가상의 "회원" 테이블과 "주문" 테이블을 설계하고, 둘을 연결할 **키**를 정해 보세요. 그 키가 유일성·무결성을 만족하는지 점검해 보세요.
3. 같은 두 테이블을 INNER / LEFT JOIN 했을 때 결과 행 수가 어떻게 달라질지 손으로 그려 보세요.

## 헷갈리기 쉬운 포인트

- **정형 vs 비정형**: 구조가 고정됐나(정형) vs 없나(비정형). 반정형(JSON)은 그 중간.
- **명목/서열 vs 등간/비율**: 앞 둘은 범주(사칙연산 불가), 뒤 둘은 수치(연산 가능, 비율만 절대영점 있음).
- **Concat vs Merge/Join**: 축으로 이어 붙이기 vs 공통 키로 병합.
- **집계 데이터 vs 로우 데이터**: 이미 요약됐나 vs 원자료 그대로인가.

**복습 질문 및 답변**

- (기본) 관계형 데이터베이스에서 키(Key)란 무엇인가요?
  - 데이터의 속성(열) 중 각 데이터를 식별할 수 있는 속성입니다.
- (이해 확인) 명목 척도 데이터를 사칙연산하면 왜 안 되나요?
  - 숫자가 크기가 아니라 범주(이름표)일 뿐이라, "남자(1)×2=여자(2)"처럼 의미 없는 결과가 나오기 때문입니다.
- (응용) 두 테이블을 합쳤더니 한쪽에만 있는 행이 빈 값으로 잔뜩 생겼습니다. 어떤 Join을 썼을 가능성이 큰가요?
  - 양쪽을 모두 남기는 OUTER JOIN(또는 한쪽 전체를 남기는 LEFT/RIGHT JOIN)일 가능성이 큽니다.

## 한 줄 정리
