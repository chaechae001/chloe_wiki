# 과적합과 회귀 평가지표 — 훈련 성적과 실전 성적은 다르다

> 훈련 데이터에서 잘 맞힌다고 좋은 모델이 아닙니다. 처음 보는 데이터에서도 통해야 합니다. 이 글은 과적합을 수치로 잡아내고, RMSE·MSE·MAE 중 무엇을 언제 써야 하는지 정리합니다.

`과적합` · `다항회귀` · `RMSE` · `MAE` · `이상치`

## 핵심요약

- 과적합(Overfitting)은 훈련 데이터에만 지나치게 맞춰져 새 데이터에서 성능이 떨어지는 현상이다.
- 다항 회귀에서 차수를 높이면 훈련 오차는 계속 줄지만, 어느 순간부터 테스트 오차가 다시 커진다.
- 과적합은 train RMSE와 test RMSE의 벌어짐(gap)으로 진단한다.
- RMSE·MSE는 오차를 제곱하므로 이상치(outlier)에 민감하고, MAE는 상대적으로 둔감하다.
- 이상치가 중요한 신호면 RMSE, 이상치를 무시하고 전형적 오차를 보고 싶으면 MAE를 쓴다.

## 1. 과적합과 다항 회귀

### 1) 정의

과적합은 모델이 훈련 데이터의 우연한 노이즈까지 통째로 외워 버려, 정작 처음 보는 데이터에서는 성능이 떨어지는 상태입니다. 반대로 과소적합(Underfitting)은 모델이 너무 단순해 훈련 데이터의 패턴조차 제대로 못 잡는 상태입니다.

### 2) 왜 필요한가

우리가 모델을 만드는 목적은 훈련 데이터를 잘 맞히는 게 아니라 **미래의 새 데이터를 잘 예측하는 것**입니다. 훈련 성적만 보고 모델을 고르면, 실전에서 무너지는 모델을 최고라고 착각하게 됩니다. 과적합 개념은 "훈련 성적과 실전 성적을 반드시 구분해서 봐야 한다"는 원칙을 알려 줍니다.

### 3) 핵심 흐름 재구성

다항 회귀(Polynomial Regression)는 직선 대신 곡선으로 데이터를 맞춥니다. 차수(degree)를 올릴수록 곡선이 자유롭게 휘어져 훈련 데이터의 점들을 더 촘촘히 지나갑니다.

```text
1차 : ŷ = β₀ + β₁x                 (직선)
2차 : ŷ = β₀ + β₁x + β₂x²          (완만한 곡선)
n차 : ŷ = β₀ + β₁x + ... + βₙxⁿ    (매우 구불구불한 곡선)
```

차수가 높아지면 훈련 오차는 계속 줄어듭니다. 하지만 곡선이 노이즈까지 따라가기 시작하면, 새 데이터에서의 오차(테스트 오차)는 오히려 커집니다. 이 지점이 과적합의 시작입니다. 그래서 데이터를 훈련용과 테스트용으로 나눠서 **두 오차를 함께 관찰**하는 것이 핵심입니다.

### 4) 쉬운 예시

시험 공부에 비유하면, 기출문제 100개를 통째로 외운 학생은 그 100개는 완벽하게 풉니다(훈련 오차 0). 하지만 조금만 변형된 새 문제가 나오면 무너집니다(테스트 오차 급증). 개념을 이해한 학생은 기출을 조금 틀릴 수 있어도 새 문제에 잘 대응합니다. 우리가 원하는 건 후자입니다.

### 5) 코드 예시

`tips`에서 차수를 1부터 12까지 올려 가며 train/test RMSE를 함께 봅니다.

```python
import numpy as np, seaborn as sns
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.pipeline import make_pipeline
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_squared_error

df = sns.load_dataset('tips')
X = df[['total_bill']].values
y = df['tip'].values
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=42)

for deg in [1, 2, 3, 5, 8, 12]:
    m = make_pipeline(PolynomialFeatures(deg, include_bias=False),
                      LinearRegression()).fit(Xtr, ytr)
    rtr = np.sqrt(mean_squared_error(ytr, m.predict(Xtr)))
    rte = np.sqrt(mean_squared_error(yte, m.predict(Xte)))
    print(f'차수 {deg:>2}: TrainRMSE={rtr:.4f}  TestRMSE={rte:.4f}')
```

```text
차수  1: TrainRMSE=1.0783  TestRMSE=0.8674
차수  2: TrainRMSE=1.0783  TestRMSE=0.8679
차수  3: TrainRMSE=1.0387  TestRMSE=0.9547
차수  5: TrainRMSE=0.9904  TestRMSE=0.9178
차수  8: TrainRMSE=0.9813  TestRMSE=0.9268
차수 12: TrainRMSE=0.9510  TestRMSE=0.9766
```

### 코드 목적

차수를 높이며 훈련 오차와 테스트 오차가 어떻게 갈라지는지 눈으로 확인해, 과적합이 시작되는 지점을 찾습니다.

### 코드 흐름

1. 데이터를 train 70%, test 30%로 분리한다.
2. `PolynomialFeatures`로 입력을 고차항으로 확장하고 선형 회귀를 붙인다.
3. 차수마다 train RMSE와 test RMSE를 모두 계산한다.
4. 두 값이 벌어지는 지점을 관찰한다.

### 실행 결과 해석

**train RMSE는 차수가 오를수록 계속 줄어듭니다**(1.078 → 0.951). 곡선이 훈련 점들을 점점 더 잘 통과하기 때문입니다. 반면 **test RMSE는 가장 단순한 1차에서 이미 0.867로 최저**이고, 차수를 올릴수록 오히려 나빠져 12차에서는 0.977까지 올라갑니다. 즉 이 데이터에서는 굳이 복잡한 곡선이 필요 없고, 단순한 직선이 새 데이터에 가장 잘 일반화됩니다. train은 좋아지는데 test는 나빠지는 이 패턴이 과적합의 전형적인 신호입니다.

### 실무 연결

과적합 진단은 실무에서 **모델을 배포하기 전 반드시 거치는 관문**입니다. 훈련 성능만 보고 복잡한 모델을 배포하면, 실제 서비스 트래픽에서 성능이 급락합니다. 항상 별도의 검증 데이터로 일반화 성능을 확인해야 합니다. 이 원리를 자동화한 것이 [3편의 교차검증](03-data-leakage-and-pipeline.md)입니다.

### 6) 헷갈리는 점

"train 오차가 낮으면 좋은 모델"이라는 오해가 가장 흔합니다. train 오차는 얼마든지 0으로 만들 수 있으므로 좋은 모델의 근거가 되지 못합니다. 중요한 건 test 오차와, train·test 오차의 간격입니다.

### 7) 한 줄 정리

> 과적합은 훈련 성적과 실전 성적이 벌어지는 현상이며, 데이터를 나눠 두 오차를 함께 봐야만 잡아낼 수 있다.

## 2. 회귀 평가지표 — RMSE·MSE·MAE

### 1) 정의

세 지표 모두 "예측이 정답에서 평균 얼마나 벗어나는가"를 재지만, 오차를 다루는 방식이 다릅니다.

```text
MSE  = (1/n) Σ (yᵢ − ŷᵢ)²        오차를 제곱해 평균 (단위: 원래값²)
RMSE = √MSE                        MSE에 제곱근 (단위: 원래값)
MAE  = (1/n) Σ |yᵢ − ŷᵢ|          오차의 절대값을 평균 (단위: 원래값)
```

### 2) 왜 필요한가

같은 모델이라도 어떤 지표로 평가하느냐에 따라 "좋다/나쁘다"의 판단이 달라질 수 있습니다. 특히 데이터에 이상치가 있을 때, RMSE와 MAE는 전혀 다른 이야기를 합니다. 문제 상황에 맞는 지표를 골라야 올바른 의사결정을 할 수 있습니다.

### 3) 핵심 흐름 재구성

핵심은 **제곱의 유무**입니다. RMSE·MSE는 오차를 제곱하므로, 크게 틀린 몇 건이 전체 점수를 크게 끌어올립니다. 오차가 10이면 제곱은 100이 되어 압도적인 영향을 줍니다. 반면 MAE는 절대값만 취하므로 큰 오차든 작은 오차든 크기에 비례해서만 반영합니다. 그래서 RMSE는 "이상치에 민감", MAE는 "이상치에 둔감(robust)"하다고 말합니다.

### 4) 쉬운 예시

배달 예상 시간을 예측하는 서비스를 생각해 봅시다. 대부분 예측은 2~3분 오차인데, 어쩌다 한 번 40분이나 틀리는 경우가 있습니다. 이 40분짜리 대형 실수를 심각하게 다뤄야 한다면(고객이 크게 화나므로) RMSE가 적합합니다. 반대로 "가끔 있는 극단적 배달은 예외로 두고, 평소 오차가 몇 분인지"를 알고 싶으면 MAE가 적합합니다.

### 5) 코드 예시

정상 데이터에 일부러 큰 이상치를 주입해, RMSE와 MAE가 각각 얼마나 반응하는지 봅니다.

```python
import numpy as np, seaborn as sns
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error, mean_absolute_error

df = sns.load_dataset('tips')
X = df[['total_bill']].values; y = df['tip'].values
y_hat = LinearRegression().fit(X, y).predict(X)

# 정상 상태 지표
rmse_clean = np.sqrt(mean_squared_error(y, y_hat))
mae_clean  = mean_absolute_error(y, y_hat)

# 이상치 주입: 상위 5건에 오차 20달러를 인위적으로 만듦
y_bad = y.copy();      y_bad[:5]    += 10.0
yp_bad = y_hat.copy(); yp_bad[:5]   -= 10.0
rmse_bad = np.sqrt(mean_squared_error(y_bad, yp_bad))
mae_bad  = mean_absolute_error(y_bad, yp_bad)

print(f'[정상]   RMSE={rmse_clean:.4f}  MAE={mae_clean:.4f}')
print(f'[이상치] RMSE={rmse_bad:.4f}  MAE={mae_bad:.4f}')
print(f'RMSE {rmse_bad/rmse_clean:.2f}배 증가, MAE {mae_bad/mae_clean:.2f}배 증가')
```

```text
[정상]   RMSE=1.0179  MAE=0.7458
[이상치] RMSE=2.9935  MAE=1.1381
RMSE 2.94배 증가, MAE 1.53배 증가
```

### 코드 목적

동일한 이상치 주입에 대해 RMSE와 MAE가 얼마나 다르게 반응하는지를 배율로 확인합니다.

### 코드 흐름

1. 정상 상태의 RMSE와 MAE를 먼저 구한다.
2. 데이터 5건에 오차 20달러짜리 극단 이상치를 만든다.
3. 이상치가 있는 상태의 RMSE와 MAE를 다시 계산한다.
4. 두 지표의 증가 배율을 비교한다.

### 실행 결과 해석

단 5건의 이상치가 들어오자 **RMSE는 2.94배**(1.02 → 2.99) 뛴 반면 **MAE는 1.53배**(0.75 → 1.14)만 올랐습니다. RMSE가 이상치에 훨씬 예민하게 반응한다는 것이 숫자로 드러납니다. 만약 이 5건이 측정 오류(무시해야 할 노이즈)라면, RMSE로 모델을 평가하면 실제보다 훨씬 나쁘게 보이는 착시가 생깁니다. 반대로 이 5건이 반드시 잡아야 할 중요한 사고 케이스라면, RMSE의 강한 반응이 오히려 바람직합니다.

### 실무 연결

수요 예측, 가격 예측, ETA(도착 예상 시간) 예측 등에서 지표 선택은 곧 비즈니스 판단입니다. 큰 실수의 비용이 유난히 큰 도메인(의료, 금융 리스크)에서는 RMSE를, 극단값이 잦고 전형적 성능이 궁금한 도메인에서는 MAE를 택하는 식으로 목적에 맞춰 고릅니다.

### 6) 헷갈리는 점

RMSE와 MAE 중 "무조건 어느 것이 옳다"는 답은 없습니다. 데이터에 이상치가 있는지, 그 이상치를 중요하게 볼지가 선택 기준입니다. 또한 RMSE는 항상 MAE보다 크거나 같습니다(오차가 모두 같을 때만 같음).

### 7) 한 줄 정리

> RMSE는 큰 오차를 크게 벌하고 MAE는 오차를 있는 그대로 재므로, 이상치를 어떻게 다룰지가 지표 선택을 결정한다.


### 실행 결과 해석

제곱 항이 대형 오차를 증폭시키기 때문에 RMSE의 증가율이 MAE의 약 두 배에 달합니다. 이 배율 차이가 곧 두 지표의 성격 차이입니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 과적합 vs 과소적합 | 훈련엔 강하나 테스트에 약하면 과적합, 훈련조차 못 맞히면 과소적합 |
| train RMSE vs test RMSE | 훈련 성적 vs 실전 성적. 둘의 간격으로 과적합을 진단 |
| RMSE vs MAE | 제곱하는 RMSE는 이상치에 민감, 절대값인 MAE는 둔감 |
| MSE vs RMSE | 값의 크기·단위만 다르고 모델 순위는 동일 |

데이터를 훈련용과 테스트용으로 나눈 뒤, train 오차는 계속 줄어드는데 test 오차가 다시 커지기 시작하는 지점을 관찰합니다. 두 오차의 간격이 벌어질수록 과적합이 심한 것입니다.

</details>

**Q2. RMSE가 MAE보다 이상치에 민감한 이유는 무엇인가요?**

<details>
<summary>답</summary>

RMSE는 오차를 제곱하기 때문입니다. 오차가 10이면 제곱은 100이 되어 전체 평균을 크게 끌어올립니다. MAE는 절대값만 취하므로 오차 크기에 비례해서만 반영되어, 이상치의 영향이 상대적으로 작습니다.

</details>

**Q3. 이상치가 측정 오류(노이즈)라고 확신할 때 RMSE로 평가하면 어떤 문제가 생기나요?**

<details>
<summary>답</summary>

무시해야 할 노이즈가 제곱되어 RMSE를 부풀리므로, 모델이 실제보다 훨씬 나쁘게 평가됩니다. 이 경우 MAE를 쓰거나 이상치를 먼저 정제한 뒤 평가하는 편이 정확합니다.

</details>

## 한 줄 정리

> 좋은 모델은 훈련이 아니라 처음 보는 데이터에서 통하는 모델이며, 평가지표는 데이터의 이상치 성격에 맞춰 골라야 한다.
