# 전체 흐름과 탐색적 데이터 분석(EDA)

> 모델을 만들기 전에, 데이터가 어떻게 생겼는지부터 눈으로 확인하는 습관이 프로젝트의 절반을 결정한다.

`머신러닝 프로젝트` · `EDA` · `데이터 확인` · `분포` · `모델 전략`

## 핵심요약

- 머신러닝 프로젝트는 크게 **데이터 분석 단계**와 **머신러닝 단계**로 나뉜다.
- 전체 흐름은 데이터 수집 → EDA → 모델 선택 → 데이터 전처리 → 모델 학습 → 평가 및 예측으로 이어진다.
- EDA(탐색적 데이터 분석)는 "모델을 적용하기 전에 데이터 스스로에 대한 정보를 읽어내는" 과정이다.
- 데이터의 크기, 자료형, 결측 여부, 분포를 먼저 확인하면 어떤 전처리와 모델이 필요한지 방향이 잡힌다.
- EDA의 궁극적 목표는 "예쁜 그래프"가 아니라 **머신러닝 전략 수립**이다.

## 1. 머신러닝 프로젝트의 전체 흐름

### 1) 정의

머신러닝 프로젝트는 데이터를 모아 다듬고, 그 데이터로 모델을 학습시켜 예측하는 일련의 과정입니다. 이 과정은 크게 두 덩어리로 나뉩니다. 앞쪽은 데이터를 이해하고 정리하는 **데이터 분석 단계**, 뒤쪽은 실제로 모델을 만들고 평가하는 **머신러닝 단계**입니다.

| 단계 | 세부 과정 | 하는 일 |
|------|----------|--------|
| 데이터 분석 | 데이터 수집 | 신뢰할 수 있는 모델을 위해 고품질 데이터 확보 |
| 데이터 분석 | EDA | 데이터의 특성과 패턴 이해 |
| 데이터 분석 | 모델 선택 | EDA 결과로 어떤 모델을 쓸지 결정 |
| 머신러닝 | 데이터 전처리 | 선택한 모델에 맞게 데이터 가공 |
| 머신러닝 | 모델 학습 | 데이터의 패턴을 학습 |
| 머신러닝 | 평가 및 예측 | 성능 확인, 약점 파악, 개선 |

### 2) 왜 필요한가

순서 없이 곧바로 모델부터 돌리면, 어떤 전처리가 필요한지 모른 채 성능이 나쁜 결과만 얻게 됩니다. 흐름을 알면 지금 내가 어느 단계에 있고, 다음에 무엇을 해야 하는지가 분명해집니다.

- 데이터 분석에서: 데이터를 이해하지 못하면 잘못된 모델을 고르게 됩니다.
- 실무에서: 팀원과 "지금 전처리 단계"처럼 공통 언어로 소통할 수 있습니다.

### 3) 핵심 흐름 재구성

여기서 한 가지 중요한 관점은, 이 흐름이 **한 방향으로만 흐르지 않는다**는 점입니다. 평가 결과가 나쁘면 다시 전처리나 모델 선택으로 돌아갑니다. 즉 평가 → 전처리 → 학습 → 평가를 여러 번 반복하며 성능을 끌어올리는 순환 구조에 가깝습니다.

### 4) 쉬운 예시

요리에 비유하면 이해가 쉽습니다. 데이터 수집은 장보기, EDA는 재료를 꺼내 상태를 살펴보는 일, 전처리는 씻고 다듬기, 모델 학습은 실제 조리, 평가는 간을 보는 단계입니다. 재료 상태를 안 보고 바로 볶기 시작하면 상한 재료를 넣게 될 수 있습니다.

### 5) 헷갈리는 점

"모델 선택"은 데이터 분석 단계에, "모델 학습"은 머신러닝 단계에 있습니다. 선택은 EDA 결과를 보고 후보를 정하는 일이고, 학습은 실제 데이터로 파라미터를 맞추는 일입니다.

### 6) 한 줄 정리

> 머신러닝 프로젝트는 "데이터를 이해하고 다듬는 앞 단계"와 "모델을 만들고 평가하는 뒤 단계"의 반복이다.

## 2. 탐색적 데이터 분석(EDA)

### 1) 정의

EDA(Exploratory Data Analysis)는 가설 검증이나 모델을 적용하기 **전에** 데이터 스스로가 어떤 정보를 담고 있는지 드러내도록 살펴보는 과정입니다. 데이터의 크기, 자료형, 결측 여부, 값의 분포를 확인하는 것이 시작점입니다.

### 2) 왜 필요한가

- 데이터의 특성을 알아야 명확한 문제 정의와 목표 설정이 가능합니다.
- 분포가 한쪽으로 치우쳐 있으면 로그 변환이나 표준화가 필요할 수 있습니다.
- 분류 문제에서 정답 클래스의 비율이 크게 불균형하면(예: 사망과 생존이 6:4) 샘플링 전략을 미리 고민해야 합니다.

### 3) 핵심 흐름 재구성

EDA는 다시 세 단계로 이어집니다. **데이터 확인 → 데이터 정제 → 특성 엔지니어링** 순서입니다. 이번 글에서는 첫 단계인 데이터 확인에 집중하고, 정제와 특성 엔지니어링은 다음 글에서 다룹니다.

데이터 확인 단계에서 자주 쓰는 함수는 다음과 같습니다.

| 함수 | 하는 일 |
|------|--------|
| `.shape` | 데이터의 (행 수, 열 수) 확인 |
| `.info()` | 각 변수의 자료형과 결측치 개수 확인 |
| `.head()` / `.tail()` | 상위·하위 5개 행으로 실제 값 모양 확인 |
| `.describe()` | 수치형 변수의 평균, 표준편차, 분위수 요약 |

### 4) 쉬운 예시

식당 팁 데이터를 처음 열었다고 해봅시다. `.shape`로 244건인 걸 확인하고, `.info()`로 총 계산서 금액과 팁이 숫자형인지 확인하고, `.describe()`로 평균 팁이 약 3달러라는 걸 봅니다. 이렇게 몇 줄만으로도 "이 데이터는 회귀로 팁 금액을 예측하기 좋겠다"는 감이 잡힙니다.

### 5) 코드 예시

```python
import seaborn as sns

# 회귀용 예제 데이터: 식당 팁 데이터 (총 계산서 금액으로 팁 예측)
tips = sns.load_dataset('tips')

print(tips.shape)      # (행 수, 열 수)
tips.info()            # 자료형과 결측치 개수
tips.describe()        # 수치형 변수 기술통계량
```

수치형 변수의 분포를 눈으로 확인할 때는 히스토그램이 유용합니다.

```python
import matplotlib.pyplot as plt

# 총 계산서 금액의 분포 확인 (KDE 곡선 함께 표시)
sns.histplot(data=tips, x='total_bill', kde=True)
plt.xlabel('총 계산서 금액 ($)')
plt.show()
```

### 6) 헷갈리는 점

`.info()`와 `.describe()`는 목적이 다릅니다. `.info()`는 자료형과 결측치 같은 **구조**를 보여주고, `.describe()`는 평균·분위수 같은 **통계값**을 보여줍니다.

### 7) 한 줄 정리

> EDA는 데이터를 처음 만났을 때 크기·자료형·분포를 읽어 모델 전략을 세우는 준비 단계다.

## 코드로 보기 — 두 문제 유형을 나란히 확인하기

```python
import seaborn as sns

# 회귀 문제: 팁 금액 예측
tips = sns.load_dataset('tips')

# 분류 문제: 생존 여부 예측
titanic = sns.load_dataset('titanic')

print('회귀 데이터 크기:', tips.shape)      # (244, 7) 정도
print('분류 데이터 크기:', titanic.shape)   # (891, 15) 정도

# 분류 문제에서는 정답 클래스의 비율을 꼭 확인
print(titanic['survived'].value_counts(normalize=True))
```

### 코드 목적

회귀와 분류, 두 문제를 같은 방식으로 살펴보되 분류에서는 정답 비율까지 확인하려는 코드입니다.

### 코드 흐름

1. 두 데이터셋을 불러온다.
2. `.shape`로 크기를 비교한다.
3. 분류 데이터는 정답(생존/사망)의 비율을 추가로 확인한다.
4. 비율이 불균형하면 이후 모델링에서 대응 전략을 세운다.

### 실행 결과 해석

생존 비율이 약 0.38, 사망 비율이 약 0.62처럼 나온다면 두 클래스가 1:1이 아니라는 뜻입니다. 이 경우 모델이 "무조건 사망"이라고만 찍어도 정확도가 62%가 나오므로, 정확도 하나만 보고 성능을 판단하면 안 된다는 신호가 됩니다.

### 실무 연결

이탈 예측, 사기 탐지처럼 정답 클래스가 드문 문제에서는 이 비율 확인이 특히 중요합니다. 불균형이 심하면 샘플링이나 평가 지표 선택을 다르게 가져갑니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 데이터 분석 단계 vs 머신러닝 단계 | 앞은 데이터를 이해·정리하는 과정, 뒤는 모델을 만들고 평가하는 과정 |
| 모델 선택 vs 모델 학습 | 선택은 EDA로 후보를 정하는 일, 학습은 데이터로 파라미터를 맞추는 일 |
| `.info()` vs `.describe()` | 자료형·결측 등 구조 확인 vs 평균·분위수 등 통계 확인 |
