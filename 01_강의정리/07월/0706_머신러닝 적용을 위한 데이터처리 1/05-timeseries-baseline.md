# 시계열 분석 입문 — 성분 분해와 베이스라인 모델

> 복잡한 모델 이전에, 시계열을 추세·계절·잔차로 나누고 간단한 예측 기준선을 세우는 글입니다.

`시계열` · `STL분해` · `계절성` · `베이스라인` · `MAPE`

## 핵심요약

- 시계열 데이터는 시간 순서가 의미를 가지므로, 순서를 섞으면 안 되는 특별한 데이터다.
- STL 분해는 시계열을 **추세(Trend) + 계절성(Seasonal) + 잔차(Residual)**로 나눠 구조를 드러낸다.
- 예측을 시작할 때는 복잡한 모델보다 **베이스라인**(전체 평균, 직전 1년 평균, 계절 naive)을 먼저 세운다.
- MAPE는 오차를 실제값 대비 **백분율(%)**로 표현해 직관적으로 비교하기 좋은 평가지표다.
- 베이스라인의 목적은 "이보다 나은가?"를 판단할 최소 기준선을 만드는 것이다.

## 1. 시계열 성분 분해(STL)

### 1) 정의

STL 분해는 하나의 시계열을 세 가지 성분으로 나누는 기법입니다. 장기적인 방향인 추세, 주기적으로 반복되는 계절성, 그리고 둘로 설명되지 않는 무작위 변동인 잔차입니다.

```
원본 시계열 = 추세(Trend) + 계절성(Seasonal) + 잔차(Residual)
```

### 2) 왜 필요한가

- 원본 그래프만 보면 추세와 계절성이 뒤섞여 패턴을 읽기 어렵습니다.
- 분해하면 "장기적으로 오르는가", "특정 분기에 반복적으로 튀는가"를 따로 볼 수 있습니다.
- 잔차(설명되지 않는 부분)가 크면 아직 모델이 놓친 패턴이 있다는 신호입니다.

### 3) 핵심 흐름 재구성

```
1. 데이터를 시간 순서대로 정렬하고 주기(period)를 정한다.
   - 분기 데이터: period=4,  월 데이터: period=12
2. STL(data, period).fit()으로 세 성분을 계산한다.
3. Observed / Trend / Seasonal / Residual 4개를 위아래로 나란히 시각화한다.
4. 추세 방향, 계절 패턴의 반복, 잔차의 크기를 읽는다.
```

### 4) 쉬운 예시

아이스크림 가게 매출을 생각해 봅시다. 해가 갈수록 가게가 유명해져 매출이 우상향(추세)하고, 매년 여름마다 크게 오르고 겨울에 떨어지는(계절성) 패턴이 반복됩니다. 그리고 특정 달에 우연히 날씨가 궂어 매출이 튀는 것(잔차)이 섞여 있습니다. STL은 이 세 가지를 각각 떼어 보여줍니다.

### 5) 코드 예시

추세와 계절성을 가진 분기 데이터(가상)를 만들어 STL로 분해합니다.

```python
import numpy as np, pandas as pd
from statsmodels.tsa.seasonal import STL
np.random.seed(42)

# 추세(우상향) + 분기 계절성 + 잡음을 가진 가상 분기 데이터
trend = np.linspace(2, 9, 48)
season = np.tile([0.6, -0.3, 0.9, -0.5], 12)
noise = np.random.normal(0, 0.3, 48)
value = pd.Series((trend + season + noise).round(2))

res = STL(value, period=4).fit()
print('추세 처음 4개:', res.trend[:4].round(2).tolist())
# [2.44, 2.55, 2.67, 2.79]  ← 완만히 증가
print('계절 처음 4개:', res.seasonal[:4].round(2).tolist())
# [0.2, -0.73, 0.86, -0.42] ← 분기마다 반복되는 패턴
```

### 6) 헷갈리는 점

- `period`는 계절이 반복되는 주기입니다. 분기 데이터면 4(1년=4분기), 월 데이터면 12를 줍니다. 잘못 주면 계절 성분이 엉뚱하게 나옵니다.
- 세 성분을 더하면 대체로 원본과 비슷해집니다(가법 모델 기준). 분해는 "나누기"이지 "버리기"가 아닙니다.
- 잔차가 특정 시점에 유독 크면 그 시점에 이상 이벤트가 있었을 가능성이 있어 이상치 탐지에 활용됩니다.

### 7) 한 줄 정리

> STL 분해는 시계열을 추세·계절·잔차로 나눠, 뒤섞여 보이지 않던 구조를 드러내는 도구입니다.

## 코드로 보기 — 베이스라인 모델 3종과 MAPE

예측을 시작할 때는 복잡한 모델보다 간단한 기준선을 먼저 세웁니다.

```python
def mape(y_true, y_pred):
    y_true, y_pred = np.array(y_true), np.array(y_pred)
    return np.mean(np.abs((y_true - y_pred) / y_true)) * 100

train, test = value[:-4], value[-4:]   # 마지막 1년(4분기)을 예측 대상으로

# 모델1: 전체 평균으로 예측
pred_hist = train.mean()
# 모델2: 직전 1년 평균으로 예측
pred_lastyr = train[-4:].mean()
# 모델3: 계절 naive — 직전 주기를 그대로 반복
pred_seasonal = train[-4:].values

print('전체평균 MAPE   :', round(mape(test, [pred_hist]*4), 2), '%')     # 39.56 %
print('직전1년평균 MAPE:', round(mape(test, [pred_lastyr]*4), 2), '%')   # 5.91 %
print('계절naive MAPE  :', round(mape(test, pred_seasonal), 2), '%')     # 5.35 %
```

MAPE 계산식은 다음과 같습니다.

```
MAPE = mean( |실제값 − 예측값| ÷ |실제값| ) × 100   (단위: %)
```

### 코드 목적

세 가지 단순 규칙으로 예측해 보고, 어떤 기준선이 이 데이터에 가장 잘 맞는지 MAPE로 비교합니다.

### 코드 흐름

1. `mape` 함수를 정의한다(오차를 실제값 대비 %로 환산).
2. 마지막 1년을 예측 대상(test)으로 떼어 둔다.
3. 전체 평균 / 직전 1년 평균 / 계절 naive 세 방식으로 예측한다.
4. 각 예측의 MAPE를 계산해 비교한다.

### 실행 결과 해석

전체 평균 예측의 MAPE는 39.56%로 오차가 큽니다. 우상향 추세가 있는 데이터를 오래된 낮은 값까지 평균 내버려, 최근 값보다 한참 낮게 예측했기 때문입니다. 반면 직전 1년 평균(5.91%)과 계절 naive(5.35%)는 최근 수준과 계절 패턴을 반영해 훨씬 정확합니다. 이처럼 데이터에 추세·계절성이 있으면, 단순 전체 평균은 좋은 기준선이 아닙니다.

### 실무 연결

수요 예측, 매출 예측, 재고 예측에서 복잡한 모델(ARIMA, Prophet, 딥러닝)을 도입하기 전에 이런 베이스라인을 먼저 세웁니다. 새 모델이 계절 naive보다 못하다면 그 모델은 쓸 이유가 없습니다. 베이스라인은 "이보다 나아야 의미가 있다"는 합격선 역할을 합니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 추세 vs 계절성 | 장기적 방향은 추세, 주기적으로 반복되는 패턴은 계절성 |
| 계절 naive vs 전체 평균 | 직전 주기를 반복하면 계절 naive, 모든 과거를 평균 내면 전체 평균 |
| MAPE vs MSE | 오차를 %로 보는 것이 MAPE, 제곱해 크기로 보는 것이 MSE |
| train vs test 분리 | 시계열은 순서를 지켜 과거를 train, 미래를 test로 나눔(무작위 분할 금지) |

**Q1. 시계열은 왜 train/test를 무작위로 나누면 안 되나요?**

<details>
<summary>답</summary>

시간 순서 자체가 정보이기 때문입니다. 무작위로 섞으면 미래 데이터가 학습에 섞여 들어가(데이터 누수) 실제보다 성능이 좋아 보입니다. 시계열은 항상 과거를 train, 미래를 test로 순서를 지켜 나눠야 현실적인 예측 성능을 알 수 있습니다.

</details>

**Q2. 베이스라인 모델을 굳이 만드는 이유는 무엇인가요?**

<details>
<summary>답</summary>

새로 만든 복잡한 모델이 정말 쓸모 있는지 판단할 기준선이 필요하기 때문입니다. 계절 naive 같은 단순 규칙보다 못한 모델은 복잡성만 늘릴 뿐 가치가 없습니다. 베이스라인은 "이보다 나아야 한다"는 합격선입니다.

</details>

**Q3. MAPE의 단점은 없나요?**

<details>
<summary>답</summary>

있습니다. 실제값에 0이 포함되면 분모가 0이 되어 계산이 무한대가 되거나 에러가 납니다. 또 실제값이 매우 작은 구간에서는 작은 오차도 큰 %로 부풀려집니다. 이럴 때는 분모를 보정하거나 SMAPE 같은 대안 지표를 씁니다.

</details>
