# EDA 4단계 워크플로우 — 데이터가 스스로 말하게 하기

> 모델을 돌리기 전에, 데이터의 생김새를 먼저 이해하는 습관을 만드는 글입니다.

`EDA` · `탐색적데이터분석` · `pandas` · `groupby` · `데이터시각화`

## 핵심요약

- EDA(탐색적 데이터 분석)는 가설을 세우기 전에 데이터가 스스로 패턴을 드러내도록 살펴보는 과정이다.
- 실무에서는 대개 **확인 → 정제 → 특성 엔지니어링 → 상관관계 분석**의 4단계 흐름을 따른다.
- Pandas의 핵심 동작은 선택(`.loc`), 정렬(`sort_values`), 카운트(`value_counts`), 조작(파생변수), 집계(`groupby`) 다섯 가지로 요약된다.
- 시각화는 line·scatter·bar·hist·kde 다섯 종류만 알아도 대부분의 초기 탐색을 처리할 수 있다.
- EDA의 목적은 "예쁜 그래프"가 아니라 **다음 단계(정제·모델링)에서 무엇을 할지 결정하는 근거**를 만드는 것이다.

## 1. EDA(탐색적 데이터 분석)

### 1) 정의

EDA는 데이터를 모델에 넣기 전에 구조, 분포, 결측, 관계를 눈으로 확인하며 "이 데이터가 어떤 데이터인지" 파악하는 과정입니다. 통계 검정으로 결론을 내리기 전에, 먼저 데이터에게 질문을 던지는 단계라고 볼 수 있습니다.

### 2) 왜 필요한가

- 데이터를 모르고 모델을 돌리면, 결과가 좋아도 왜 좋은지 설명할 수 없습니다.
- 결측치나 이상치를 발견하지 못하면 모델이 엉뚱한 값을 학습합니다.
- 어떤 변수를 쓸지, 어떤 파생변수를 만들지 판단하는 근거가 EDA에서 나옵니다.
- 실무에서는 "데이터 확인 없이 모델부터 돌렸다"가 가장 흔한 실패 원인입니다.

### 3) 핵심 흐름 재구성

EDA는 보통 아래 4단계로 정리하면 기억하기 쉽습니다.

```
1단계 데이터 확인   : 구조, 타입, 분포 파악        → head(), info(), describe()
2단계 정제         : 결측·이상치 처리             → isnull(), dropna(), fillna()
3단계 특성 엔지니어링 : 기존 변수로 새 의미 만들기      → 파생변수, 구간화(binning)
4단계 상관관계 분석  : 변수 간 관계 확인            → corr(), heatmap
```

이 순서는 절대적인 규칙은 아니지만, "먼저 보고, 고치고, 만들고, 관계를 확인한다"는 흐름은 대부분의 프로젝트에서 공통으로 나타납니다.

### 4) 쉬운 예시

카페 매출 데이터를 처음 받았다고 해봅시다. 바로 예측 모델을 만들기보다는, 먼저 몇 행인지(확인), 매출에 빈칸이 있는지(정제), 요일과 시간대를 합쳐 "주말 저녁" 같은 변수를 만들지(특성 엔지니어링), 방문객 수와 매출이 얼마나 붙어 다니는지(상관) 살펴보는 것이 EDA입니다. 이 과정을 거치면 "무엇을 예측할 수 있는 데이터인지"가 눈에 들어옵니다.

### 5) 코드 예시

Pandas의 다섯 가지 핵심 동작을 공개 데이터셋(`penguins`, `tips`)으로 정리했습니다.

```python
import seaborn as sns
import pandas as pd

peng = sns.load_dataset('penguins')

# (1) 선택 — 조건에 맞는 행/열만 뽑기
adelie = peng.loc[peng['species'] == 'Adelie', ['species', 'body_mass_g']]
print('Adelie 표본 수:', len(adelie))    # 152

# (2) 카운트 — 범주별 빈도
print(peng['species'].value_counts())
# Adelie 152 / Gentoo 124 / Chinstrap 68

# (3) 집계 — 그룹별 평균
print(peng.groupby('species')['body_mass_g'].mean().round(1))
# Adelie 3700.7 / Chinstrap 3733.1 / Gentoo 5076.0
```

```python
tips = sns.load_dataset('tips')

# (4) 조작 — 파생변수: 팁 비율(%)
tips.loc[:, 'tip_rate'] = (tips['tip'] / tips['total_bill'] * 100).round(2)
print(tips['tip_rate'].mean())   # 16.08 (%)
```

결과를 보면 Gentoo 펭귄의 평균 체중(5076g)이 다른 두 종(약 3700g)보다 확연히 큽니다. 이런 차이는 나중에 "체중만으로 종을 어느 정도 구분할 수 있겠다"는 가설로 이어집니다.

### 6) 헷갈리는 점

- `.loc[:, cols]`처럼 콜론을 명시하는 습관을 들이면, 행 조건과 열 선택이 한눈에 구분됩니다.
- `value_counts()`는 기본적으로 빈도 내림차순으로 정렬되고, 결측치는 세지 않습니다. 결측까지 보려면 `dropna=False`를 줍니다.
- `groupby().mean()`은 숫자 컬럼만 자동으로 계산합니다. 문자열 컬럼이 섞여 있어도 에러가 나지 않고 조용히 빠집니다.

### 7) 한 줄 정리

> EDA는 데이터를 모델에 넣기 전에 "이 데이터가 무엇인지" 먼저 이해하는 정찰 활동입니다.

## 코드로 보기 — 1차 스캔 3종 세트

```python
import seaborn as sns
tips = sns.load_dataset('tips')

tips.head(3)               # 실제 값 몇 개 훑어보기
tips.info()                # 타입, 결측, 행 수 확인
tips.describe().round(2)   # 수치형 요약 통계
```

`describe()` 출력(일부):

```
       total_bill     tip    size
count      244.00  244.00  244.00
mean        19.79    3.00    2.57
std          8.90    1.38    0.95
min          3.07    1.00    1.00
50%         17.80    2.90    2.00
max         50.81   10.00    6.00
```

### 코드 목적

데이터를 받자마자 "몇 개인지, 어떤 타입인지, 값의 범위가 어떤지"를 3줄로 파악하기 위한 코드입니다.

### 코드 흐름

1. `head()`로 실제 값의 생김새를 확인한다.
2. `info()`로 컬럼 타입과 결측 여부를 확인한다.
3. `describe()`로 수치형 변수의 분포(평균, 표준편차, 최소·최대)를 확인한다.

### 실행 결과 해석

`total_bill`은 최소 3.07에서 최대 50.81까지 퍼져 있고 평균이 19.79입니다. 평균(19.79)이 중앙값(17.80)보다 크므로 분포가 오른쪽으로 살짝 치우쳐 있다고 읽을 수 있습니다. 이런 치우침은 이후 이상치 처리나 로그 변환을 고려할 단서가 됩니다.

### 실무 연결

데이터 대시보드나 분석 보고서의 첫 페이지는 거의 항상 이 3종 세트로 시작합니다. "데이터 개요"를 먼저 보여줘야 이후 분석의 신뢰가 생기기 때문입니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| `.loc` vs `.iloc` | 라벨(이름) 기준 선택은 `.loc`, 정수 위치 기준 선택은 `.iloc` |
| `info()` vs `describe()` | 타입·결측 구조를 보는 것이 `info()`, 수치 분포를 보는 것이 `describe()` |
| 평균 vs 중앙값 | 이상치에 흔들리는 것이 평균, 이상치에 강한 것이 중앙값 |
| EDA vs 통계 검정 | 데이터를 살펴 가설을 만드는 것이 EDA, 그 가설을 확률로 판정하는 것이 검정 |
