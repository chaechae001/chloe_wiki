# 미니배치와 최적화 기초 — 에포크보다 업데이트의 양을 읽는 법

> 두 모델을 똑같이 40에포크 학습했다고 해서 같은 양의 일을 한 것은 아닙니다. 배치 크기가 달라지면 한 에포크 안의 업데이트 횟수부터 달라지므로, 손실과 시간도 같은 기준으로 비교해야 합니다.

`Full-batch` · `Mini-batch` · `Epoch` · `Step` · `학습률` · `공정 비교`

## 핵심요약

- Full-batch는 전체 데이터로 한 번의 기울기를 계산하고, mini-batch는 작은 묶음마다 기울기를 추정해 자주 갱신한다.
- 에포크는 전체 데이터를 한 번 사용한 단위이고, 스텝은 가중치를 한 번 갱신한 단위다.
- 스텝 수는 보통 $\lceil N/B\rceil$이며, 같은 에포크라도 배치 크기가 작으면 업데이트가 많아진다.
- 저장된 2,000개 회귀 실험에서 full-batch는 에포크당 1스텝·최종 MSE `0.0436`, 배치 64는 표시상 31스텝·`0.0114`였다.
- 다른 저장 실험에서는 mini-batch의 손실이 더 낮았지만 총 벽시계 시간은 `18.68초`로 full-batch의 `5.98초`보다 길었다. 따라서 “항상 더 빠르다”는 결론은 성립하지 않는다.

## 1. Full-batch와 Mini-batch — 한 번에 얼마를 보고 움직일까

### 1) 정의

경사하강법의 기본 갱신식은 다음과 같습니다.

$$
\theta_{t+1}=\theta_t-\eta\nabla_{\theta}L_B(\theta_t)
$$

$B$는 이번 갱신에 사용한 데이터 묶음이고, $\eta$는 학습률입니다.

- Full-batch: $B$가 전체 학습 데이터다.
- Mini-batch: $B$가 전체보다 작은 데이터 묶음이다.
- 순수 SGD: 엄밀하게는 샘플 하나로 갱신하지만, 실무에서는 mini-batch 학습을 넓게 SGD라고 부르기도 한다.

### 2) 왜 필요한가

전체 데이터의 기울기는 방향이 비교적 안정적이지만 한 번 계산하는 비용과 메모리 요구량이 큽니다. 미니배치 기울기는 일부 데이터로 추정하므로 흔들림이 있지만, 더 자주 업데이트하고 메모리 사용량을 조절할 수 있습니다.

배치 크기는 단순한 속도 옵션이 아니라 기울기 추정의 노이즈와 업데이트 빈도를 함께 바꾸는 하이퍼파라미터입니다.

### 3) 핵심 흐름 재구성

데이터가 $N=2{,}000$개라고 해 봅시다.

| 배치 크기 $B$ | 에포크당 스텝 | 한 스텝에서 보는 데이터 |
|---:|---:|---:|
| 2,000 | 1 | 전체 데이터 |
| 200 | 10 | 전체의 10% |
| 64 | $\lceil2000/64\rceil=32$ | 최대 64개 |
| 32 | $\lceil2000/32\rceil=63$ | 최대 32개 |

일부 로그가 정수 나눗셈 `2000 // 64`를 사용하면 31로 표시되지만, 마지막 16개 샘플까지 처리한다면 실제 배치는 32개입니다. `drop_remainder=True`처럼 마지막 불완전 배치를 버리는 설정인지 확인해야 합니다.

### 4) 쉬운 예시

설문지 2,000장을 모두 읽고 한 번 의견을 고치는 방식이 full-batch입니다. 64장씩 읽고 의견을 계속 고치는 방식이 mini-batch입니다.

후자는 중간 피드백을 자주 받지만, 한 바퀴 동안 의견 수정 횟수도 훨씬 많습니다. 그러므로 “한 바퀴”만 비교해서 계산량이 같다고 보면 안 됩니다.

### 5) 코드 예시

```python
import math

n_samples = 2000

for batch_size in [2000, 200, 64, 32]:
    steps = math.ceil(n_samples / batch_size)
    print(f"batch={batch_size:4d}, steps/epoch={steps:2d}")
```

```text
batch=2000, steps/epoch= 1
batch= 200, steps/epoch=10
batch=  64, steps/epoch=32
batch=  32, steps/epoch=63
```

### 6) 헷갈리는 점

배치가 작다고 한 에포크의 총 연산이 정확히 배치 수만큼 늘어나는 것은 아닙니다. 각 배치의 연산량은 작고, 하드웨어 병렬성·입출력·컴파일 비용도 영향을 줍니다.

또한 mini-batch가 더 많은 스텝을 수행해 같은 에포크에서 손실이 낮아졌다면, 배치 방식 자체와 업데이트 횟수 효과가 섞여 있습니다.

### 7) 한 줄 정리

> 배치 크기는 한 번에 보는 데이터와 에포크당 업데이트 횟수를 동시에 결정한다.

## 2. Epoch·Step·학습률 — 세 축으로 학습량 읽기

### 1) 정의

- Epoch: 전체 학습 데이터를 한 번 순회한 단위
- Step: 하나의 배치로 순전파·역전파·파라미터 갱신을 마친 단위
- 학습률: 한 스텝에서 기울기를 얼마나 크게 반영할지 정하는 계수

총 스텝 수는 대략 다음과 같습니다.

$$
\text{total steps}=\text{epochs}\times\left\lceil\frac{N}{B}\right\rceil
$$

### 2) 왜 필요한가

같은 40에포크라도 full-batch는 약 40번, 배치 64는 약 1,280번 갱신할 수 있습니다. 학습률이 같다면 후자는 훨씬 많은 파라미터 이동 기회를 갖습니다.

따라서 에포크 기준 곡선만으로 “더 빠르게 수렴했다”고 말하기 전에 스텝 수와 경과 시간을 함께 확인해야 합니다.

### 3) 핵심 흐름 재구성

학습률과 배치 크기는 따로 보되 함께 해석합니다.

- 학습률이 너무 작음: 각 스텝의 이동이 작아 손실 감소가 느릴 수 있다.
- 학습률이 너무 큼: 최솟값 주변에서 진동하거나 손실이 발산할 수 있다.
- 배치가 작음: 기울기 변동성이 커질 수 있지만 업데이트는 많아진다.
- 배치가 큼: 기울기가 안정적일 수 있지만 업데이트는 적어진다.

배치 크기를 바꾸면 적절한 학습률 범위도 달라질 수 있으므로, 비교 목적을 먼저 정해야 합니다.

### 4) 쉬운 예시

계단을 내려가는 사람에게 스텝은 발걸음 수, 학습률은 보폭입니다. 에포크는 건물 한 층을 모두 둘러본 횟수에 가깝습니다.

한 사람은 한 바퀴에 한 걸음만, 다른 사람은 32걸음을 걸었다면 바퀴 수만 같다고 이동량이 같지는 않습니다.

### 5) 코드 예시

```python
import math

def training_budget(n_samples, batch_size, epochs):
    steps_per_epoch = math.ceil(n_samples / batch_size)
    return {
        "steps_per_epoch": steps_per_epoch,
        "total_steps": steps_per_epoch * epochs,
    }

print(training_budget(2000, 2000, 40))
print(training_budget(2000, 64, 40))
```

```text
{'steps_per_epoch': 1, 'total_steps': 40}
{'steps_per_epoch': 32, 'total_steps': 1280}
```

### 6) 헷갈리는 점

학습률이 같다고 완전히 공정한 비교가 되는 것은 아닙니다. 총 스텝이 다르면 누적 업데이트 기회가 다릅니다. 반대로 총 스텝을 맞추면 데이터 순회 횟수가 달라질 수 있습니다.

공정성은 하나의 고정 규칙이 아니라 질문에 맞는 통제입니다. 같은 데이터 노출량, 같은 업데이트 수, 같은 시간 예산 중 무엇을 맞출지 명시해야 합니다.

### 7) 한 줄 정리

> 에포크는 데이터 노출량, 스텝은 갱신 횟수, 학습률은 갱신 크기를 설명한다.

## 3. 공정한 비교 — 무엇을 같게 둘 것인가

### 1) 정의

공정한 비교란 모든 조건을 무조건 같게 만드는 것이 아니라, 검증하려는 가설 이외의 중요한 조건을 통제하는 것입니다.

### 2) 왜 필요한가

배치 크기 비교에서 모델 초기값과 데이터 순서까지 다르면 손실 차이를 배치 효과로 돌리기 어렵습니다. 벽시계 시간도 하드웨어 예열과 데이터 로딩에 영향을 받으므로 반복 측정이 필요합니다.

### 3) 핵심 흐름 재구성

| 비교 질문 | 맞춰야 할 핵심 조건 | 함께 보고할 지표 |
|---|---|---|
| 같은 데이터 노출량에서 누가 낮은 손실인가 | epochs | 총 steps, 최종 loss |
| 같은 업데이트 수에서 누가 효율적인가 | total steps | 처리한 샘플 수, loss |
| 같은 시간 예산에서 누가 유리한가 | wall-clock budget | 도달 loss, 처리량 |
| 일반화가 더 좋은가 | 동일 분할·평가 시점 | validation metric, 반복 평균 |

### 4) 쉬운 예시

달리기 선수를 비교할 때 같은 거리, 같은 시간, 같은 걸음 수는 서로 다른 질문입니다. 100m 기록을 비교하면서 한 선수에게 300m를 뛰게 하면 공정하지 않습니다.

### 5) 코드 예시

```python
comparison = {
    "same_model": True,
    "same_initial_weights": True,
    "same_data_order": True,
    "same_learning_rate": True,
    "same_epochs": True,
    "same_total_steps": False,
}

for condition, controlled in comparison.items():
    print(f"{condition:22s}: {controlled}")
```

이 기록은 같은 에포크 비교이지만 총 스텝은 다르다는 점을 투명하게 보여 줍니다.

### 6) 헷갈리는 점

저장된 한 실험에서 full-batch 최종 손실은 `0.1385`, 총 시간은 `5.98초`였고, mini-batch는 `0.0100`, `18.68초`였습니다. Mini-batch가 더 낮은 손실에 도달했지만 전체 실행은 더 오래 걸렸습니다.

이 수치만으로 목표 손실까지의 시간 우열도 확정할 수 없습니다. 에포크별 시간-손실 전체 기록과 반복 측정이 있어야 특정 손실 임계값에 먼저 도달한 시점을 비교할 수 있습니다.

### 7) 한 줄 정리

> 비교 결과보다 먼저 어떤 예산과 조건을 맞췄는지 밝혀야 한다.

## 코드로 보기 — 동일 에포크 결과를 스텝과 시간으로 다시 읽기

```python
experiments = [
    {
        "name": "full_batch",
        "steps_per_epoch": 1,
        "epochs": 100,
        "final_loss": 0.1385,
        "seconds": 5.98,
    },
    {
        "name": "mini_batch",
        "steps_per_epoch": 63,
        "epochs": 100,
        "final_loss": 0.0100,
        "seconds": 18.68,
    },
]

for exp in experiments:
    total_steps = exp["steps_per_epoch"] * exp["epochs"]
    print(
        exp["name"],
        "steps=", total_steps,
        "loss=", exp["final_loss"],
        "seconds=", exp["seconds"],
    )
```

### 코드 목적

같은 100에포크 결과를 총 업데이트 수, 최종 손실, 벽시계 시간의 세 기준으로 다시 비교합니다.

### 코드 흐름

1. 각 실험의 에포크당 스텝 수를 기록한다.
2. 에포크 수와 곱해 총 스텝을 계산한다.
3. 최종 손실과 전체 시간을 함께 출력한다.
4. 무엇이 통제되지 않았는지 확인한다.

### 저장된 실행 결과를 반영한 출력

```text
full_batch steps= 100 loss= 0.1385 seconds= 5.98
mini_batch steps= 6300 loss= 0.01 seconds= 18.68
```

### 실행 결과 해석

Mini-batch는 같은 에포크 동안 훨씬 많은 업데이트를 수행해 더 낮은 손실에 도달했습니다. 동시에 전체 벽시계 시간은 더 길었습니다. 따라서 이 조건의 안전한 결론은 “업데이트 예산이 다른 동일 에포크 비교에서 mini-batch가 더 낮은 최종 손실을 기록했다”입니다.

별도의 회귀 실험에서는 40에포크 후 full-batch가 표시상 에포크당 1스텝·MSE `0.0436`, 배치 64가 31스텝·MSE `0.0114`였습니다. 단, 31은 정수 나눗셈 표기이며 마지막 작은 배치를 포함한 실제 스텝 수와 다를 수 있습니다.

학습 곡선의 x축을 에포크로 두면 같은 데이터 순회 횟수에서 손실이 얼마나 줄었는지 볼 수 있고, x축을 누적 시간으로 바꾸면 실제 계산 비용 대비 손실 감소를 볼 수 있습니다. 두 그래프는 서로 다른 질문에 답하므로 어느 하나만 보고 “더 빠르다”고 결론 내리지 않습니다.

### 실무 연결

실험 표에는 `batch_size`, `epochs`, `steps`, `learning_rate`, `elapsed_time`, 난수 시드, 검증 지표를 함께 남깁니다. 그래야 비용과 성능 사이의 선택을 재현할 수 있습니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| Epoch vs Step | Epoch는 전체 데이터 순회 수이고, step은 파라미터 갱신 횟수다. |
| 수렴 속도 vs 실행 시간 | 수렴 속도는 손실 감소의 기준축에 따라 달라지고, 실행 시간은 실제 벽시계 비용이다. |
| 작은 배치 vs 빠른 학습 | 작은 배치는 업데이트를 늘리지만 총 시간이 언제나 짧아지는 것은 아니다. |
| 같은 학습률 vs 공정한 비교 | 학습률만 같아도 총 스텝과 데이터 노출량이 다르면 비교 질문을 명시해야 한다. |

- [ ] 에포크·스텝·학습률이 각각 무엇을 나타내는지 구분할 수 있다.
- [ ] 같은 에포크 비교가 같은 업데이트 예산을 뜻하지 않음을 설명할 수 있다.
- [ ] 손실과 벽시계 시간을 함께 해석할 수 있다.
- [ ] 비교 질문에 맞는 통제 조건을 고를 수 있다.

### 복습 질문 및 답변

**Q1. Mini-batch의 기울기가 full-batch보다 흔들릴 수 있는 이유는 무엇인가요?**

<details>
<summary>답</summary>

전체 데이터가 아니라 일부 표본으로 전체 손실의 기울기를 추정하기 때문입니다. 배치 구성에 따라 추정값이 달라질 수 있으며, 데이터 셔플과 배치 크기가 변동성에 영향을 줍니다.

</details>

**Q2. 동일 에포크에서 mini-batch의 손실이 더 낮으면 최적화 방법이 무조건 우월한가요?**

<details>
<summary>답</summary>

아닙니다. Mini-batch가 더 많은 스텝을 수행했을 수 있습니다. 총 업데이트 수, 시간, 초기값과 데이터 순서를 확인한 뒤 비교 범위를 제한해야 합니다.

</details>

**Q3. 배치 크기 비교 실험에서 최소한 무엇을 기록해야 하나요?**

<details>
<summary>답</summary>

배치 크기, 에포크, 에포크당·전체 스텝, 학습률, 최종 손실과 검증 지표, 경과 시간, 초기값과 데이터 순서를 재현할 시드를 기록하는 것이 좋습니다.

</details>

## 한 줄 정리

> Full-batch와 mini-batch를 올바르게 비교하려면 에포크만 보지 말고, 스텝·학습률·처리한 데이터·벽시계 시간을 같은 질문 안에서 함께 읽어야 한다.
