# 딥러닝 학습의 실패 모드 — 증상부터 해결책까지 연결하는 진단 지도

> 손실이 줄지 않을 때 무작정 층을 늘리거나 학습 시간을 길게 잡으면 원인을 더 찾기 어려워집니다. 먼저 학습 속도, 기울기 흐름, 초기화, 일반화 중 어디에서 문제가 시작됐는지 구분해야 합니다.

`최적화` · `기울기 소실` · `가중치 초기화` · `과적합` · `진단 순서`

## 핵심요약

- 딥러닝 학습의 대표 실패 모드는 느린 최적화, 기울기 소실, 부적절한 초기화, 과적합으로 나눌 수 있다.
- 네 문제는 독립적이지 않다. 초기화와 활성화 함수는 기울기 흐름에 영향을 주고, 최적화 방식은 수렴 속도와 일반화 양상에 함께 관여한다.
- 훈련 손실, 검증 손실, 기울기 크기, 층별 활성값 분포, 업데이트 횟수를 함께 봐야 원인을 좁힐 수 있다.
- 해결책은 증상에 맞게 선택한다. 배치와 옵티마이저, 활성화 함수, Xavier·He 초기화, 규제를 무조건 한꺼번에 적용하지 않는다.
- 저장된 실험 결과는 특정 데이터·초기값·학습률에서 나온 관찰값이므로 보편적인 알고리즘 순위로 해석하지 않는다.

## 1. 네 가지 실패 모드 — 무엇이 잘못됐는지 이름 붙이기

### 1) 정의

딥러닝의 학습은 손실 함수 $L(\theta)$를 작게 만드는 파라미터 $\theta$를 찾는 과정입니다.

$$
\theta^*=\arg\min_{\theta}L(\theta)
$$

하지만 손실을 낮추는 경로에서는 서로 다른 문제가 나타날 수 있습니다.

| 실패 모드 | 대표 증상 | 먼저 확인할 것 |
|---|---|---|
| 학습 속도 | 손실이 매우 천천히 감소하거나 한 에포크가 지나치게 오래 걸림 | 배치 크기, 스텝 수, 학습률, 연산 자원 |
| 기울기 소실 | 입력층에 가까운 층의 가중치가 거의 변하지 않음 | 층별 기울기 크기, 활성화 함수, 깊이 |
| 초기화 문제 | 시작부터 출력이 포화되거나 실행마다 학습 양상이 크게 흔들림 | 층별 활성값 분산, fan-in/out, 난수 시드 |
| 과적합 | 훈련 성능은 좋아지지만 검증 성능이 정체되거나 악화됨 | 훈련-검증 간격, 데이터 분할, 모델 복잡도 |

### 2) 왜 필요한가

같은 “손실이 높다”는 현상도 원인은 다를 수 있습니다. 학습률이 너무 작을 수도 있고, 앞쪽 층으로 기울기가 전달되지 않을 수도 있으며, 검증 손실만 높다면 최적화보다 일반화가 문제일 수 있습니다.

원인을 구분하지 않으면 서로 반대되는 처방을 내릴 수 있습니다. 예를 들어 학습이 느리다고 모델을 더 크게 만들면 연산 비용과 과적합 위험이 함께 커질 수 있습니다.

### 3) 핵심 흐름 재구성

진단은 다음 순서로 진행하면 효율적입니다.

1. 데이터와 손실 계산이 정상인지 확인한다.
2. 훈련 손실이 실제로 감소하는지 본다.
3. 에포크가 아니라 스텝과 경과 시간도 함께 비교한다.
4. 층별 기울기와 활성값의 크기가 유지되는지 확인한다.
5. 훈련과 검증 곡선의 간격을 확인한다.
6. 한 번에 한 변수만 바꾸어 다시 실험한다.

### 4) 쉬운 예시

자동차가 목적지에 도착하지 못한 상황을 떠올려 봅시다. 속도가 느린지, 엔진의 힘이 바퀴까지 전달되지 않는지, 출발 방향이 잘못됐는지, 연습 도로에서만 운전이 잘되는지를 먼저 나눠 봐야 합니다.

딥러닝에서도 “더 오래 달리기”보다 고장 위치를 찾는 일이 먼저입니다.

### 5) 코드 예시

학습 기록을 한 화면에서 진단할 수 있도록 최소 지표를 모읍니다.

```python
diagnostics = {
    "train_loss": [0.72, 0.58, 0.47, 0.40],
    "validation_loss": [0.74, 0.63, 0.61, 0.69],
    "steps_per_epoch": 32,
    "gradient_norm_first_layer": 0.00003,
    "gradient_norm_last_layer": 0.18,
}

gap = diagnostics["validation_loss"][-1] - diagnostics["train_loss"][-1]
print(f"generalization gap = {gap:.2f}")
print("first/last gradient ratio =", 0.00003 / 0.18)
```

이 기록에서는 훈련-검증 손실 간격이 벌어지고, 첫 층의 기울기가 마지막 층보다 매우 작습니다. 과적합과 기울기 흐름 문제를 함께 의심할 수 있습니다.

### 6) 헷갈리는 점

한 지표만으로 원인을 확정하면 안 됩니다. 첫 층의 기울기가 작아도 모델이 이미 수렴한 상태일 수 있고, 검증 손실의 일시적 상승은 작은 검증 세트의 변동일 수 있습니다.

따라서 절댓값 하나보다 시간에 따른 추세와 비교 실험을 봅니다.

### 7) 한 줄 정리

> 실패 모드를 이름 붙이면 막연한 튜닝이 검증 가능한 진단으로 바뀐다.

## 2. 실패 모드의 상호관계 — 한 설정이 여러 문제를 움직인다

### 1) 정의

딥러닝의 설정은 사슬처럼 연결됩니다.

```text
초기화와 활성화 함수
        ↓
층별 활성값과 기울기 흐름
        ↓
업데이트의 안정성과 수렴 속도
        ↓
훈련 성능과 일반화 간격
```

예를 들어 ReLU 계열에 맞지 않는 작은 초기값을 쓰면 층을 지날수록 신호가 약해질 수 있습니다. 이 상태에서 옵티마이저만 바꾸어도 근본 원인이 남습니다.

### 2) 왜 필요한가

여러 설정을 동시에 바꾸면 성능은 좋아질 수 있지만 무엇이 효과를 냈는지 알 수 없습니다. 재현 가능한 학습 방법을 만들려면 가설과 변경 항목을 대응시켜야 합니다.

### 3) 핵심 흐름 재구성

문제와 개입의 연결은 다음처럼 정리할 수 있습니다.

| 관찰 | 가능한 원인 | 우선 실험 |
|---|---|---|
| 에포크당 시간이 너무 김 | 배치·데이터 파이프라인·모델 규모 | 배치별 시간과 스텝 수 측정 |
| 앞쪽 층의 기울기가 거의 0 | 포화 활성화·깊이·초기화 | 활성화 함수와 초기화 조합 비교 |
| 시작 손실이 실행마다 크게 다름 | 초기화 분산·시드·데이터 순서 | 시드를 여러 개로 반복 |
| 훈련 손실만 계속 감소 | 모델 복잡도·데이터 부족 | 규제와 조기 종료 비교 |

### 4) 쉬운 예시

샤워기의 물 온도를 맞출 때 수압과 온도 손잡이를 동시에 크게 돌리면 무엇 때문에 바뀌었는지 알기 어렵습니다. 하나를 고정하고 다른 하나만 움직여야 원인과 결과를 배울 수 있습니다.

### 5) 코드 예시

실험 조건을 명시적으로 기록하면 비교의 공정성을 확인하기 쉽습니다.

```python
experiments = [
    {"name": "baseline", "batch": 64, "lr": 0.01, "activation": "relu"},
    {"name": "smaller_batch", "batch": 32, "lr": 0.01, "activation": "relu"},
]

changed = [
    key for key in experiments[0]
    if experiments[0][key] != experiments[1][key]
]
print("changed variables:", changed)
```

```text
changed variables: ['name', 'batch']
```

실제 분석에서는 `name`을 제외하고 배치 크기 하나만 달라졌는지 확인합니다.

### 6) 헷갈리는 점

“가장 좋은 설정”은 데이터와 모델, 목표 지표, 시간 예산에 따라 달라집니다. 한 실험의 최저 손실이 모든 상황의 정답은 아닙니다.

또한 검증 데이터를 매 에포크 확인했다면 그 데이터는 모델 선택에 관여한 검증 세트입니다. 최종 성능을 보고할 독립 테스트 세트와 구분해야 합니다.

### 7) 한 줄 정리

> 설정의 상호작용을 이해하되, 비교 실험에서는 한 번에 한 가지 가설을 검증한다.

## 코드로 보기 — 학습 기록으로 실패 모드 후보 만들기

```python
def diagnose(train_loss, val_loss, first_grad, last_grad):
    findings = []

    if train_loss[-1] > train_loss[0] * 0.9:
        findings.append("최적화 정체 가능성")

    gradient_ratio = first_grad / max(last_grad, 1e-12)
    if gradient_ratio < 1e-3:
        findings.append("앞쪽 층 기울기 약화 가능성")

    if val_loss[-1] > min(val_loss) and train_loss[-1] < train_loss[0]:
        findings.append("과적합 가능성")

    return findings


result = diagnose(
    train_loss=[0.72, 0.55, 0.39, 0.21],
    val_loss=[0.73, 0.58, 0.56, 0.66],
    first_grad=2e-5,
    last_grad=0.12,
)

print(result)
```

### 코드 목적

훈련·검증 손실과 층별 기울기 비율을 이용해 확인할 실패 모드의 후보를 만듭니다.

### 코드 흐름

1. 훈련 손실이 충분히 감소했는지 확인한다.
2. 첫 층과 마지막 층의 기울기 크기를 비교한다.
3. 훈련 손실은 감소하지만 검증 손실이 최저점 이후 상승했는지 본다.
4. 조건에 맞는 항목을 진단 후보로 반환한다.

### 실행 결과 예시

```text
['앞쪽 층 기울기 약화 가능성', '과적합 가능성']
```

### 실행 결과 해석

이 결과는 확정 진단이 아니라 다음 실험의 우선순위입니다. 활성화 함수와 초기화 조합을 점검하고, 동시에 검증 곡선의 최저점과 규제 효과를 비교할 근거가 됩니다.

저장된 별도 실험에서는 훈련 손실·정확도가 `0.0052 / 1.000`, 검증용 데이터의 손실·정확도가 `0.0826 / 0.960`이었습니다. 이 조건에서는 훈련-검증 간격이 관찰되지만, 한 번의 결과만으로 과적합의 심각도나 해결책의 우열을 단정할 수 없습니다.

학습 곡선을 볼 때 x축은 에포크, y축은 손실로 읽습니다. 훈련 곡선은 계속 내려가는데 검증 곡선이 바닥을 찍고 다시 올라가면 일반화 간격이 벌어지는 신호입니다. 활성화 함수나 초기화 비교 그래프는 최종 정확도 하나보다 초반 정체 구간과 층별 신호가 유지되는 양상을 함께 봐야 합니다.

### 실무 연결

진단 함수를 자동 알림으로 쓰기보다 대시보드의 점검 규칙으로 활용합니다. 실제 판단에서는 여러 시드의 반복 결과, 기울기 분포, 데이터 누수 여부를 함께 확인합니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 최적화 실패 vs 과적합 | 최적화 실패는 훈련 데이터도 잘 맞추지 못하고, 과적합은 훈련 성능에 비해 검증 성능이 뒤처진다. |
| 기울기 소실 vs 작은 학습률 | 둘 다 업데이트가 작지만, 기울기 소실은 층별 차이가 크고 작은 학습률은 전체 갱신을 함께 줄인다. |
| 초기화 vs 난수 시드 | 초기화는 값의 분포 규칙이고, 시드는 같은 난수 결과를 재현하기 위한 시작점이다. |
| 검증 세트 vs 테스트 세트 | 검증 세트는 설정 선택에 사용하고, 테스트 세트는 선택이 끝난 모델의 최종 평가에 남겨 둔다. |

**Q2. 여러 해결책을 한꺼번에 적용하면 왜 진단이 어려워지나요?**

<details>
<summary>답</summary>

결과 변화에 대한 원인 귀속이 불가능해집니다. 한 조건을 기준선으로 두고 가설 하나에 대응하는 변수만 바꾸면 효과를 설명하고 재현하기 쉽습니다.

</details>

**Q3. 매 에포크마다 확인한 데이터를 최종 테스트 결과라고 부르면 안 되는 이유는 무엇인가요?**

<details>
<summary>답</summary>

그 결과를 보며 에포크 수나 설정을 선택했다면 이미 모델 선택 과정에 사용됐기 때문입니다. 따라서 검증 세트로 보고, 최종 테스트용 데이터는 별도로 보존해야 합니다.

</details>

## 한 줄 정리
