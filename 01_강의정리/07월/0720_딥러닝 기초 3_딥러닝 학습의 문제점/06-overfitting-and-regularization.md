# 과적합과 L1·L2 정규화 — 훈련 성적보다 새 데이터의 성적을 본다

> 훈련 정확도 1.0은 언제나 좋은 소식일까요? 훈련 데이터가 120개뿐인데 특징이 30개라면, 모델은 규칙보다 샘플의 우연한 흔적을 외울 수 있습니다. 과적합을 판단하려면 훈련 점수가 아니라 훈련과 검증 사이의 간격을 봐야 합니다.

`과적합` · `일반화` · `검증 데이터` · `L1 정규화` · `L2 정규화`

## 핵심요약

- 과적합은 훈련 데이터의 패턴과 잡음을 지나치게 외워 새로운 데이터에서 성능이 떨어지는 상태다.
- 훈련 손실과 검증 손실의 방향, 훈련·검증 지표의 차이를 함께 봐야 과적합을 진단할 수 있다.
- L1은 가중치 절댓값의 합, L2는 가중치 제곱합을 손실에 더해 복잡도를 억제한다.
- 저장된 실험에서는 모든 주요 설정의 훈련 정확도가 거의 1.0이었지만 검증 정확도는 0.752~0.842로 차이가 났다.
- 이 실행에서 최고 검증 정확도는 L2의 0.842였고, L1은 0.832, 규제 없는 기준 모델은 0.770이었다.
- 매 에포크 확인한 데이터는 최종 테스트가 아니라 검증 데이터로 해석해야 하며, 마지막 일반화 평가는 별도 테스트 세트로 수행해야 한다.

## 1. 과적합과 일반화 격차

### 1) 정의

과적합은 모델이 훈련 데이터에서는 매우 잘 맞지만 학습에 사용하지 않은 데이터에서는 성능이 떨어지는 상태입니다. 일반화는 훈련에서 배운 규칙을 새로운 데이터에도 적용하는 능력입니다.

분류 정확도를 기준으로 한 일반화 격차는 다음처럼 계산할 수 있습니다.

$$
\text{gap} = \text{train accuracy} - \text{validation accuracy}
$$

격차가 크다는 사실은 과적합의 신호가 될 수 있지만, 한 값만으로 확정하지 않고 손실 곡선과 데이터 분할도 함께 봅니다.

### 2) 왜 필요한가

모델의 목적은 이미 본 샘플의 답을 기억하는 것이 아니라 새로운 입력을 올바르게 판단하는 것입니다. 따라서 훈련 점수만 최적화하면 실제 사용 성능을 잘못 평가할 수 있습니다.

특히 데이터 수보다 특성 수와 모델 파라미터가 많으면 잡음까지 표현할 여지가 커집니다. 훈련 데이터가 작을수록 검증 결과의 변동성도 커질 수 있으므로 반복 평가가 중요합니다.

### 3) 핵심 흐름 재구성

훈련 과정에서 자주 나타나는 패턴은 다음과 같습니다.

1. 초반에는 훈련 손실과 검증 손실이 함께 감소한다.
2. 어느 시점부터 훈련 손실은 계속 감소한다.
3. 검증 손실은 더 줄지 않거나 다시 증가한다.
4. 두 곡선의 간격이 벌어지면 새로운 데이터에 대한 일반화가 약해졌을 가능성을 의심한다.

정확도는 임계값을 넘었는지만 보지만 손실은 예측 확률의 확신도까지 반영합니다. 정확도가 비슷해도 검증 손실이 증가할 수 있으므로 둘을 함께 기록합니다.

### 4) 쉬운 예시

예상 문제와 답을 통째로 외운 학생은 같은 시험에서는 만점을 받을 수 있습니다. 그러나 표현만 바뀐 문제에서 틀린다면 원리를 이해한 것이 아닙니다. 훈련 데이터는 본 문제, 검증 데이터는 표현이 바뀐 연습 문제에 해당합니다.

### 5) 코드 예시

```python
def generalization_gap(train_accuracy, validation_accuracy):
    return train_accuracy - validation_accuracy

baseline_gap = generalization_gap(1.000, 0.770)
l2_gap = generalization_gap(1.000, 0.842)

print(f"baseline gap: {baseline_gap:.3f}")
print(f"L2 gap: {l2_gap:.3f}")
```

```text
baseline gap: 0.230
L2 gap: 0.158
```

이 실행에서는 L2 설정의 격차가 기준 모델보다 0.072 작았습니다. 그러나 격차가 작다는 이유만으로 모델을 고르면 안 됩니다. 훈련과 검증 성능이 모두 낮은 과소적합 모델도 격차가 작을 수 있기 때문입니다.

### 6) 헷갈리는 점

훈련 정확도와 검증 정확도가 모두 높고 차이가 작을 때가 바람직합니다. 단순히 gap만 최소화하면 아무것도 학습하지 못한 모델을 좋은 모델로 착각할 수 있습니다.

### 7) 한 줄 정리

> 과적합은 훈련 점수가 높다는 사실이 아니라, 새 데이터로 옮겨 갔을 때 성능이 유지되지 않는 현상이다.

## 2. L1과 L2 정규화

### 1) 정의

정규화는 데이터 손실에 가중치 크기에 대한 패널티를 더해 모델이 지나치게 복잡한 해를 선택하지 않도록 유도합니다.

L1 정규화는 가중치 절댓값의 합을 사용합니다.

$$
L_{\text{total}}
= L_{\text{data}} + \lambda\sum_i |w_i|
$$

L2 정규화는 가중치 제곱합을 사용합니다.

$$
L_{\text{total}}
= L_{\text{data}} + \lambda\sum_i w_i^2
$$

$\lambda$는 규제 강도를 정하는 하이퍼파라미터입니다.

### 2) 왜 필요한가

규제가 없으면 모델은 훈련 손실을 줄이기 위해 일부 가중치를 매우 크게 만들 수 있습니다. 큰 가중치는 입력의 작은 변화에도 출력이 크게 흔들리게 할 수 있습니다.

L1과 L2는 훈련 오차를 조금 허용하는 대신 더 단순한 가중치 구성을 선택하도록 압력을 줍니다. 이는 훈련 점수 자체보다 새로운 데이터의 성능을 개선하려는 절충입니다.

### 3) 핵심 흐름 재구성

가중치 $w>0$인 구간에서 L1 패널티의 기울기는 일정한 방향을 가집니다.

$$
\frac{\partial}{\partial w}\lambda|w| = \lambda
$$

L2 패널티의 기울기는 가중치 크기에 비례합니다.

$$
\frac{\partial}{\partial w}\lambda w^2 = 2\lambda w
$$

따라서 L1은 작은 가중치에도 일정한 축소 압력을 주어 일부 값을 0 근처로 보내는 희소성을 유도할 수 있습니다. L2는 큰 가중치일수록 더 강하게 줄이고 여러 가중치를 부드럽게 작은 값으로 분산시키는 경향이 있습니다.

### 4) 쉬운 예시

가방에 물건을 담을 때 L1은 물건 하나를 넣을 때마다 일정한 요금을 내는 방식과 비슷합니다. 덜 중요한 물건은 아예 빼게 됩니다. L2는 무거운 물건에 더 가파른 요금을 매기는 방식과 비슷해, 지나치게 무거운 한 물건에 의존하지 않게 합니다.

### 5) 코드 예시

```python
from tensorflow import keras
from tensorflow.keras import layers, regularizers

model_l1 = keras.Sequential([
    layers.Input(shape=(30,)),
    layers.Dense(
        64,
        activation="relu",
        kernel_regularizer=regularizers.l1(1e-4),
    ),
    layers.Dense(1, activation="sigmoid"),
])

model_l2 = keras.Sequential([
    layers.Input(shape=(30,)),
    layers.Dense(
        64,
        activation="relu",
        kernel_regularizer=regularizers.l2(1e-3),
    ),
    layers.Dense(1, activation="sigmoid"),
])
```

두 모델은 규제 종류뿐 아니라 계수도 다르므로, 실제 비교에서는 여러 $\lambda$ 후보를 검증 데이터로 선택해야 합니다.

### 6) 헷갈리는 점

L1과 L2가 가중치를 직접 삭제하거나 모델 크기를 자동으로 줄이는 것은 아닙니다. 손실에 패널티를 추가해 학습 방향을 바꾸며, L1으로 0에 가까워진 가중치를 실제 구조 압축으로 연결하려면 별도 처리와 검증이 필요합니다.

### 7) 한 줄 정리

> L1과 L2는 훈련 오차에 가중치 복잡도 비용을 더해, 외우기 쉬운 해보다 일반화하기 쉬운 해를 선택하도록 유도한다.

## 3. 저장된 비교 실험 읽기

### 1) 정의

정규화 비교 실험은 같은 데이터와 기본 구조에서 규제 설정을 바꾸고 훈련·검증 성능을 비교하는 과정입니다.

### 2) 왜 필요한가

정규화는 항상 성능을 높이는 마법이 아닙니다. 규제 강도가 너무 약하면 효과가 없고 너무 강하면 필요한 패턴까지 배우지 못합니다. 실제 검증 결과를 통해 적절한 설정을 골라야 합니다.

### 3) 핵심 흐름 재구성

저장된 실험은 훈련 샘플 120개, 검증 샘플 400개, 특성 30개를 사용했습니다. 정답 생성에는 일부 특성만 직접 관여하고 나머지는 잡음 역할을 하므로, 모델이 불필요한 패턴을 외우기 쉬운 조건입니다.

| 설정 | 훈련 정확도 | 검증 정확도 | 격차 |
|---|---:|---:|---:|
| 규제 없음 | 1.000 | 0.770 | 0.230 |
| L2 | 1.000 | 0.842 | 0.158 |
| L1 | 1.000 | 0.832 | 0.168 |
| Dropout | 1.000 | 0.810 | 0.190 |
| BatchNorm | 0.992 | 0.752 | 0.239 |
| BatchNorm+Dropout+L2 | 1.000 | 0.788 | 0.212 |

이 한 번의 저장 실행에서 검증 정확도가 가장 높은 설정은 L2의 0.842입니다. L1은 0.832로 뒤를 이었고, 둘 다 규제 없는 모델의 0.770보다 높았습니다.

반면 BatchNorm 단독과 결합 설정은 이 실행에서 L2보다 낮았습니다. 따라서 여러 기법을 결합하면 언제나 가장 좋다거나 BatchNorm 조합이 우월하다고 단정할 수 없습니다. 각 기법의 동작은 [드롭아웃과 배치 정규화](07-dropout-and-batch-normalization.md)에서 구분해 살펴봅니다.

### 4) 쉬운 예시

여러 공부법을 한 학생씩 한 번만 시험한 결과와 같습니다. 이번에는 L2 방식의 점수가 가장 높았지만, 학생의 시작점과 우연한 문제 구성이 달랐을 수 있습니다. 같은 조건을 여러 번 반복해야 공부법 자체의 경향을 말할 수 있습니다.

### 5) 코드 예시

```python
records = {
    "baseline": (1.000, 0.770),
    "L2": (1.000, 0.842),
    "L1": (1.000, 0.832),
    "Dropout": (1.000, 0.810),
    "BatchNorm": (0.992, 0.752),
    "BN+Dropout+L2": (1.000, 0.788),
}

for name, (train_acc, valid_acc) in records.items():
    gap = train_acc - valid_acc
    print(f"{name:16s} valid={valid_acc:.3f} gap={gap:.3f}")
```

결과표를 만들 때 `valid_acc`와 `gap`을 같이 보면 검증 성능이 높은지, 훈련과 얼마나 벌어졌는지 동시에 확인할 수 있습니다.

### 6) 헷갈리는 점

실험 코드에서는 매 에포크마다 별도 데이터의 성능을 확인했습니다. 이렇게 모델 선택과 해석에 반복해서 사용한 데이터는 **검증 데이터**입니다. 최종 테스트 데이터라고 부르면 평가 절차를 혼동하게 됩니다.

최종 성능을 공정하게 추정하려면 모델과 하이퍼파라미터를 확정한 뒤, 그동안 보지 않은 테스트 세트를 한 번 평가해야 합니다.

### 7) 한 줄 정리

> 저장 실험에서 L2가 가장 높은 검증 정확도를 보였지만, 이는 별도 테스트 평가와 반복 실험이 필요한 조건부 관찰이다.

## 코드로 보기 — 검증 곡선으로 모델 선택 시점 찾기

```python
history = model.fit(
    x_train,
    y_train,
    validation_data=(x_valid, y_valid),
    epochs=60,
    batch_size=16,
    verbose=0,
)

valid_losses = history.history["val_loss"]
best_epoch = min(range(len(valid_losses)), key=valid_losses.__getitem__)

print("best epoch:", best_epoch + 1)
print("best validation loss:", valid_losses[best_epoch])
```

### 코드 목적

마지막 에포크만 보는 대신 검증 손실이 가장 낮았던 시점을 찾아, 과적합이 진행되기 전의 모델 후보를 선택합니다.

### 코드 흐름

1. 훈련 데이터로 가중치를 갱신한다.
2. 매 에포크마다 검증 데이터의 손실을 기록한다.
3. 검증 손실이 최소인 에포크를 찾는다.
4. 선택한 설정을 별도 테스트 세트에서 마지막으로 평가한다.

### 실행 결과 해석

검증 손실이 어느 시점부터 증가한다면 마지막 에포크의 가중치보다 최소 검증 손실 시점이 일반화에 유리할 수 있습니다. 정확한 선택은 여러 분할이나 교차검증으로 안정성을 확인해야 합니다.

### 실무 연결

운영 모델에서는 훈련 성능보다 시간 순서나 사용자 단위로 분리한 검증 성능이 중요합니다. 데이터 누수가 있으면 검증 점수가 실제보다 높아질 수 있으므로, 먼저 분할 기준을 점검하고 그다음 규제 강도를 조정합니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 훈련 성능 vs 일반화 성능 | 본 데이터에 대한 성능 vs 보지 않은 데이터에 규칙을 적용하는 성능 |
| 검증 데이터 vs 테스트 데이터 | 모델·하이퍼파라미터 선택에 반복 사용 vs 최종 평가에 제한적으로 사용 |
| 과적합 vs 과소적합 | 훈련은 좋고 검증은 나쁜 상태 vs 훈련 자체도 충분히 학습하지 못한 상태 |
| L1 vs L2 | 절댓값 패널티로 희소성 유도 vs 제곱 패널티로 큰 가중치를 부드럽게 억제 |
| 작은 gap vs 좋은 모델 | 격차만 작을 수 있음 vs 검증 성능 자체도 충분히 높아야 함 |
| 정확도 vs 손실 | 맞힌 비율 vs 예측 확률의 오차와 규제 패널티까지 반영한 최적화 값 |

### 복습 질문 및 답변

**Q1. 훈련 정확도 1.0인데도 과적합일 수 있는 이유는 무엇인가요?**

<details>
<summary>답</summary>

모델이 일반 규칙이 아니라 훈련 샘플의 잡음과 우연한 패턴까지 외웠을 수 있기 때문입니다. 보지 않은 검증 데이터의 정확도와 손실을 함께 확인해야 합니다.

</details>

**Q2. 저장 결과만으로 L2가 모든 문제에서 가장 좋다고 결론 내릴 수 있나요?**

<details>
<summary>답</summary>

아닙니다. 한 번의 가상 데이터 실행이고 기법별 규제 강도도 다릅니다. 여러 난수 시드와 하이퍼파라미터 후보로 반복하고 별도 테스트 세트에서 확인해야 합니다.

</details>

**Q3. L1과 L2 중 하나를 선택할 때 무엇을 확인해야 하나요?**

<details>
<summary>답</summary>

희소한 가중치가 필요한지, 큰 가중치를 전반적으로 부드럽게 줄이고 싶은지 먼저 판단합니다. 이후 규제 계수를 여러 값으로 검증하고, 검증 손실·정확도·안정성을 함께 비교해 선택합니다.

</details>

## 한 줄 정리

> 과적합 방지는 훈련 점수를 낮추는 벌칙이 아니라, L1·L2 같은 복잡도 제어와 올바른 검증 절차로 새 데이터에서도 유지되는 규칙을 찾는 과정이다.
