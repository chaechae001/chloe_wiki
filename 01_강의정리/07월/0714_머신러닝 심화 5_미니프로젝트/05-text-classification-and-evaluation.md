# 텍스트 분류 모델과 평가 — 정확도 한 줄로는 알 수 없는 것들

> 17개 유형을 맞히는 모델의 정확도가 0.75라면 잘한 걸까요, 못한 걸까요. 답은 "어느 유형에서 틀렸는지 봐야 안다"입니다. 이 글은 희소한 텍스트 벡터에 어떤 분류기를 왜 쓰는지, 그리고 accuracy 한 줄 뒤에 숨은 것들을 어떻게 꺼내 보는지 정리합니다.

`나이브베이즈` · `LinearSVC` · `클래스불균형` · `macro F1` · `혼동행렬`

## 핵심요약

- 고차원 희소 텍스트 벡터에서는 거리 기반 KNN이 약하고(accuracy 0.67), 선형 SVM이 가장 강했다(0.75).
- 원본 데이터는 최대 유형과 최소 유형의 비율이 약 400 대 1이었고, 유형별 상한을 두는 언더샘플링으로 균형을 맞춘 뒤 학습했다.
- 정확도만 보면 모델이 어떤 유형을 통째로 놓치는지 보이지 않으므로 클래스별 precision·recall·F1을 함께 봐야 한다.
- macro 평균은 모든 클래스를 동등하게, weighted 평균은 샘플 수에 비례해 반영하므로 불균형 데이터에서 둘의 차이가 곧 소수 클래스 성적표다.
- 혼동행렬을 보면 교통과 자동차, 행정과 안전건설처럼 어휘가 겹치는 유형끼리 서로 흡수되는 패턴이 드러난다.

## 1. 텍스트 분류기 선택

### 1) 정의

분류기(classifier)는 입력 벡터를 받아 미리 정해진 클래스 중 하나를 고르는 모델입니다. 이 프로젝트에서는 거리 기반(KNN), 확률 기반(나이브 베이즈), 마진 기반(선형 SVM), 트리 앙상블(랜덤 포레스트·부스팅) 등 성격이 다른 다섯 계열을 나란히 비교했습니다.

### 2) 왜 필요한가

"어떤 모델이 제일 좋은가"에는 정답이 없습니다. 데이터의 모양이 답을 결정합니다. 텍스트 TF-IDF 벡터는 두 가지 뚜렷한 특징이 있습니다.

- 차원이 매우 높다 (어휘 사전 11,143개)
- 거의 다 0이다 (밀도 약 0.09%)

이 두 조건에서 어떤 모델이 유리한지 아는 것이 모델 선택의 핵심입니다.

### 3) 핵심 흐름 재구성

계열별로 이 데이터에서 어떻게 작동하는지 정리하면 이렇습니다.

**거리 기반(KNN)**은 새 문서 주변의 가장 가까운 K개 이웃을 보고 다수결로 결정합니다. 그런데 1만 차원이 넘는 공간에서는 모든 점 사이의 거리가 비슷해지는 **차원의 저주**가 발생합니다. "가까운 이웃"이라는 개념 자체가 흐려지므로 성능이 떨어집니다. 게다가 예측할 때마다 모든 훈련 데이터와 거리를 계산해야 해서 느립니다.

**나이브 베이즈(MultinomialNB)**는 각 클래스에서 각 단어가 나올 확률을 학습하고, 베이즈 정리로 "이 단어 조합이 나왔을 때 가장 그럴듯한 클래스"를 고릅니다. 단어들이 서로 독립이라는 가정이 현실적으로 틀렸지만, 문서 분류에서는 놀랍도록 잘 통합니다. 학습이 사실상 빈도 세기라 매우 빠릅니다.

**선형 SVM(LinearSVC)**은 클래스를 가르는 초평면을 찾되, 경계와 데이터 사이의 여백(마진)을 최대로 벌립니다. 차원이 샘플 수만큼 많은 고차원 희소 데이터에서 선형 경계는 대체로 충분히 강력하고, 마진 최대화 덕분에 과적합도 억제됩니다. 텍스트 분류의 오랜 기본기입니다.

**트리 앙상블(랜덤 포레스트, 부스팅)**은 "이 단어의 TF-IDF 값이 0.3보다 큰가?" 같은 조건을 반복해 분기합니다. 표 형태 데이터에서는 강력하지만, 특성이 1만 개인데 대부분 0인 상황에서는 유용한 분기 기준을 찾기가 상대적으로 어렵습니다.

**앙상블 투표(VotingClassifier)**는 성격이 다른 모델들의 예측을 모아 다수결로 결정합니다. 서로 다른 실수를 하는 모델들을 묶으면 실수가 상쇄되는 효과가 있습니다.

### 4) 쉬운 예시

병원 진료로 비유하면, KNN은 "증상이 비슷했던 과거 환자 17명을 찾아 그들의 진단명 중 다수를 고르는" 방식입니다. 나이브 베이즈는 "기침·발열이 각 질병에서 얼마나 흔한지 통계를 보고 가장 그럴듯한 병을 고르는" 방식이고, SVM은 "질병 A와 B를 가장 안전하게 나누는 기준선을 긋고 그 기준으로 판정하는" 방식입니다. 앙상블은 세 의사의 소견을 모아 다수결로 결정하는 협진입니다.

### 5) 코드 예시

```python
from sklearn.naive_bayes import MultinomialNB
from sklearn.svm import LinearSVC
from sklearn.metrics import classification_report

nb = MultinomialNB().fit(X_train_tfidf, y_train)
svm = LinearSVC(random_state=42).fit(X_train_tfidf, y_train)

for name, model in [("NaiveBayes", nb), ("LinearSVC", svm)]:
    pred = model.predict(X_test_tfidf)
    print(name)
    print(classification_report(y_test, pred, target_names=le.classes_))
```

### 6) 헷갈리는 점

"복잡한 모델이 더 좋다"는 오해가 흔합니다. 이 실험에서 가장 단순한 축에 속하는 선형 SVM이 부스팅 계열보다 나은 성능을 냈습니다. 데이터의 구조가 선형 분리에 가까우면 복잡한 비선형 모델은 이득 없이 시간만 더 씁니다.

### 7) 한 줄 정리

> 고차원 희소 텍스트 벡터에서는 거리 기반 모델이 불리하고 선형·확률 기반 모델이 유리하다.

## 2. 클래스 불균형과 대응

### 1) 정의

클래스 불균형(class imbalance)은 정답 클래스별 데이터 개수가 크게 차이 나는 상태입니다. 다수 클래스(majority)와 소수 클래스(minority)의 비율이 벌어질수록 문제가 커집니다.

### 2) 왜 필요한가

모델은 손실을 줄이는 방향으로 학습합니다. 그런데 어떤 클래스가 전체의 38%를 차지하고 다른 클래스가 0.1%뿐이라면, 소수 클래스를 통째로 포기하고 다수 클래스만 잘 맞혀도 손실이 크게 줄어듭니다. 모델은 "게으른 정답"에 안착하게 되고, 정작 실무에서 중요한 소수 사례를 못 잡습니다.

### 3) 핵심 흐름 재구성

원본 민원 데이터는 총 769,710건, 17개 유형이었습니다. 유형별 분포를 보면 이렇습니다.

| 순위 | 유형 | 건수 | 전체 대비 |
|---|---|---|---|
| 1 | 자동차 | 295,107 | 38.3% |
| 2 | 안전건설 | 93,747 | 12.2% |
| 3 | 교통 | 85,465 | 11.1% |
| … | … | … | … |
| 16 | 토지 | 6,092 | 0.8% |
| 17 | 정보통신 | 744 | 0.1% |

최대와 최소의 비율이 $295{,}107 \div 744 \approx 397$, 약 **400 대 1**입니다.

이 상태로 학습하면 어떤 일이 벌어질까요. 아무 생각 없이 늘 "자동차"만 답하는 모델을 상상해 봅시다. 정확도는 $295{,}107 \div 769{,}710 \approx 0.383$, 무려 38.3%가 나옵니다. 17개 중 하나를 무작위로 찍는 확률(5.9%)의 여섯 배가 넘습니다. 하지만 이 모델은 아무것도 학습하지 않았습니다.

여기서 채택한 대응은 **언더샘플링(다수 클래스 줄이기)** 입니다. 유형별로 최대 2,000건까지만 무작위 추출해 32,744건으로 줄였습니다. 정보통신만 원래 744건이라 그대로이고, 나머지 16개 유형은 각 2,000건입니다. 이렇게 하면 최대·최소 비율이 400 대 1에서 **약 2.7 대 1**로 완화됩니다.

대응 방법을 정리하면 이렇습니다.

- **언더샘플링**: 다수 클래스를 잘라 낸다. 데이터가 충분히 많을 때 간단하고 학습도 빨라진다. 정보 손실이 단점.
- **오버샘플링**: 소수 클래스를 복제하거나 SMOTE로 합성한다. 정보 손실은 없지만 과적합 위험이 있다.
- **클래스 가중치**: `class_weight='balanced'`로 소수 클래스의 오답에 더 큰 벌점을 준다. 데이터를 건드리지 않는다.
- **평가지표 교체**: accuracy 대신 macro F1을 최적화 대상으로 삼는다.

### 4) 쉬운 예시

카드 부정거래 탐지를 생각해 보세요. 100만 건 중 부정거래가 500건이라면, "전부 정상"이라고 답하는 모델의 정확도는 99.95%입니다. 숫자만 보면 완벽하지만 잡아야 할 것을 하나도 못 잡았습니다. 불균형 데이터에서 정확도가 무의미해지는 전형적인 상황입니다.

```python
                .reset_index(drop=True))

print(df_sampled["category"].value_counts().head(3))
print(df_sampled["category"].value_counts().tail(1))

```


### 6) 헷갈리는 점

언더샘플링·오버샘플링은 **훈련 데이터에만** 적용해야 합니다. 테스트 데이터의 분포를 인위적으로 바꾸면, 실제 서비스에서 마주할 분포와 다른 조건에서 평가하게 되어 성능이 부풀려집니다. 이 프로젝트처럼 샘플링 후에 분리하는 방식은 학습 편의를 위한 것이며, 실제 운영 성능은 원본 분포에서 다시 확인해야 합니다.

### 7) 한 줄 정리

> 클래스 불균형은 모델이 다수 클래스만 답해도 높은 정확도를 얻게 만들므로, 데이터든 가중치든 지표든 어느 하나는 반드시 손봐야 한다.

## 3. accuracy를 넘어서 — precision, recall, F1

### 1) 정의

네 지표를 한 클래스 관점에서 정의하면 이렇습니다.

$$
\text{Precision} = \frac{TP}{TP + FP}, \qquad
\text{Recall} = \frac{TP}{TP + FN}
$$

Precision은 "이 유형이라고 **예측한 것들 중** 실제로 맞은 비율", Recall은 "실제로 이 유형인 것들 중 **찾아낸** 비율"입니다. 분모가 다르다는 점이 전부입니다. 하나는 예측을 기준으로, 하나는 정답을 기준으로 나눕니다.

$$
F_1 = \frac{2 \times \text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}
$$

F1은 두 값의 조화 평균입니다. 산술 평균이 아니라 조화 평균을 쓰는 이유는, **한쪽이 극단적으로 낮으면 전체 점수도 확 떨어지게** 하기 위해서입니다. Precision 1.0, Recall 0.0이면 산술 평균은 0.5지만 F1은 0입니다.

### 2) 왜 필요한가

Accuracy는 17개 유형 전체를 뭉뚱그린 한 개의 숫자입니다. 이 숫자로는 "어떤 유형에서 얼마나 틀렸는지"를 전혀 알 수 없습니다. 클래스별 precision·recall을 봐야 비로소 개선할 지점이 보입니다.

### 3) 핵심 흐름 재구성

실제 결과에서 이 차이가 어떻게 드러나는지 봅시다. 나이브 베이즈 모델의 전체 accuracy는 **0.70**이었습니다. 나쁘지 않아 보입니다. 그런데 정보통신 유형만 떼어 보면 이렇습니다.

```text
정보통신    precision 0.96    recall 0.35    f1 0.51    support 144
```

Precision 0.96은 "정보통신이라고 예측한 건 거의 다 맞았다"는 뜻입니다. Recall 0.35는 "실제 정보통신 144건 중 35%만 찾아냈다"는 뜻입니다. 역산하면 약 50건만 맞히고 **94건을 놓쳤습니다**. 모델이 아주 확신이 설 때만 정보통신이라 답하고, 애매하면 다른 유형으로 넘겨 버린 것입니다. Accuracy 0.70 뒤에 이런 구멍이 숨어 있었습니다.

이제 평균 방식의 차이를 봅시다.

$$
\text{macro F1} = \frac{1}{K}\sum_{k=1}^{K} F_1^{(k)}, \qquad
\text{weighted F1} = \sum_{k=1}^{K} \frac{n_k}{N} F_1^{(k)}
$$

macro는 클래스별 F1을 그냥 산술 평균합니다. 데이터가 744건인 유형이든 2,000건인 유형이든 **똑같은 한 표**입니다. weighted는 각 클래스의 샘플 수 $n_k$를 가중치로 곱합니다. 큰 클래스의 성적이 전체 점수를 좌우합니다.

이 프로젝트의 테스트셋은 언더샘플링 덕분에 유형별로 대체로 400건 안팎이라 두 평균이 거의 같습니다(예: 선형 SVM은 macro 0.75, weighted 0.74). 하지만 **원본 분포에서라면 이야기가 완전히 달라집니다.** 앞서 만든 "늘 자동차라고 답하는" 모델을 원본 분포에서 평가해 봅시다. 자동차의 precision은 0.383, recall은 1.0이므로 F1은 $2 \times 0.383 \times 1.0 \div 1.383 \approx 0.554$이고, 나머지 16개 유형의 F1은 전부 0입니다. 그러면 이렇게 됩니다.

- accuracy = 0.383
- weighted F1 = $0.383 \times 0.554 \approx 0.212$
- macro F1 = $0.554 \div 17 \approx 0.033$

**macro F1만이 이 모델이 쓸모없다는 사실을 정직하게 말해 줍니다.** 불균형 문제에서 macro를 봐야 하는 이유가 이 숫자 차이에 있습니다.

### 4) 쉬운 예시

스팸 필터로 생각해 보세요. Precision이 낮으면 정상 메일이 스팸함으로 들어가 중요한 메일을 놓칩니다. Recall이 낮으면 스팸이 받은편지함으로 새어 들어옵니다. 어느 쪽 실수가 더 아픈지에 따라 임계값을 조정합니다. 민원 라우팅이라면, 잘못된 부서로 보내는 것(precision 하락)보다 아예 분류를 못 해 미배정으로 남기는 것(recall 하락)이 더 큰 문제일 수 있습니다.

### 5) 코드 예시

```python
from sklearn.metrics import classification_report, f1_score

pred = svm.predict(X_test_tfidf)

print(classification_report(y_test, pred, target_names=le.classes_))
print("macro    F1:", round(f1_score(y_test, pred, average="macro"), 3))
print("weighted F1:", round(f1_score(y_test, pred, average="weighted"), 3))
```

### 6) 헷갈리는 점

"F1이 높으면 무조건 좋다"고 생각하기 쉽지만, F1은 precision과 recall을 **같은 비중으로** 취급합니다. 두 실수의 비용이 다른 도메인에서는 $F_\beta$로 한쪽에 가중치를 주거나, 아예 recall을 목표 수준으로 고정하고 precision을 최대화하는 방식이 더 적절합니다.

### 7) 한 줄 정리

> Accuracy는 요약일 뿐이고, 클래스별 precision·recall과 macro 평균을 봐야 모델이 무엇을 놓치고 있는지 알 수 있다.

## 4. 혼동행렬 읽기와 오분류 원인

### 1) 정의

혼동행렬(confusion matrix)은 행이 실제 클래스, 열이 예측 클래스인 표입니다. $(i, j)$ 칸의 값은 "실제로는 $i$인데 $j$로 예측한 건수"입니다. 대각선이 정답이고, 대각선 밖의 값이 전부 오분류입니다.

### 2) 왜 필요한가

Precision·recall은 클래스별 성적을 알려 주지만 "**어디로** 틀렸는지"는 말해 주지 않습니다. 혼동행렬은 오답이 어느 클래스로 흘러갔는지 방향까지 보여 주므로, 개선 아이디어가 바로 나옵니다. 두 유형이 서로 헷갈린다면 그 둘을 구분하는 특성을 추가하거나, 아예 한 유형으로 합치는 것도 선택지입니다.

### 3) 핵심 흐름 재구성

전처리 단계의 단어 빈도 분석에서 이미 예고가 있었습니다. 유형별 상위 10개 단어를 뽑아 보니 **교통과 자동차가 상당수 겹쳤습니다.** 두 유형 모두 "주차", "차량", "도로", "단속" 같은 단어를 공유하기 때문입니다. TF-IDF 벡터가 비슷하니 모델이 구분하지 못하는 것은 당연한 결과입니다.

KNN 결과에서 이 예고가 그대로 실현됐습니다.

```text
교통     precision 0.56   recall 0.45   f1 0.50   support 401
자동차   precision 0.61   recall 0.91   f1 0.73   support 415
```

숫자를 역산해 봅시다. 자동차는 recall이 0.91이므로 415건 중 약 378건을 맞혔습니다. 그런데 precision이 0.61이라는 건, 자동차라고 예측한 총 건수가 $378 \div 0.61 \approx 620$건이라는 뜻입니다. 즉 **약 242건이 다른 유형인데 자동차로 잘못 분류됐습니다.** 같은 시점에 교통은 401건 중 221건을 놓쳤습니다. 두 숫자를 나란히 놓으면 그림이 선명합니다. **놓친 교통 민원 상당수가 자동차로 빨려 들어간 것입니다.**

이런 오분류의 원인은 크게 세 가지로 정리됩니다.

- **어휘 중복**: 교통 vs 자동차, 행정 vs 안전건설처럼 같은 단어를 쓰는 유형끼리 헷갈린다. 실제로 행정 유형의 F1은 모든 모델에서 0.51~0.62로 가장 낮은 축이었다.
- **데이터 부족**: 정보통신은 744건뿐이라 나이브 베이즈에서 recall 0.35까지 떨어졌다. 다만 선형 SVM에서는 precision 0.82 / recall 0.90으로 회복됐는데, 이 유형의 어휘가 다른 유형과 잘 겹치지 않아 마진 기반 경계가 잘 잡힌 덕분이다.
- **라벨 자체의 모호성**: "도로에 불법 주차된 차량" 민원은 사람이 봐도 교통인지 자동차인지 판단이 갈린다. 정답 라벨에 이미 노이즈가 있으면 모델 성능에 상한이 생긴다.

반대로 잘 맞힌 유형들은 전용 어휘가 뚜렷합니다. 세무는 모든 모델에서 F1 0.84~0.92, 상하수도는 0.80~0.89를 기록했습니다. "취득세", "누수" 같은 단어가 다른 유형에 거의 나오지 않기 때문입니다.

### 4) 쉬운 예시

모의고사 성적표를 떠올려 보세요. "60점"이라는 총점만 보면 무엇을 모르는지 알 수 없지만, 오답 노트에 "확률 문제를 통계 개념으로 착각해서 틀렸다"가 반복적으로 적혀 있다면 공부 방향이 바로 정해집니다. 혼동행렬이 바로 그 오답 노트입니다.

### 5) 코드 예시

```python
import pandas as pd
from sklearn.metrics import confusion_matrix

cm = confusion_matrix(y_test, pred)
cm_df = pd.DataFrame(cm, index=le.classes_, columns=le.classes_)

# 대각선(정답)을 지우고 오분류가 많은 쌍 상위 10개 확인
import numpy as np
errors = cm_df.copy()
np.fill_diagonal(errors.values, 0)
top_pairs = errors.stack().sort_values(ascending=False).head(10)
print(top_pairs)
```

대각선을 0으로 지우고 남은 값을 정렬하면, 어떤 유형 쌍이 서로 가장 많이 헷갈리는지가 바로 나옵니다. 17×17 표를 눈으로 훑는 것보다 훨씬 빠릅니다.

### 6) 헷갈리는 점

혼동행렬의 행과 열을 바꿔 읽는 실수가 잦습니다. **행을 따라 가로로 읽으면 recall**(실제 A가 어디로 갔나), **열을 따라 세로로 읽으면 precision**(A로 예측한 것들이 실제로는 무엇이었나)입니다. 방향을 헷갈리면 결론이 정반대가 됩니다.

### 7) 한 줄 정리

> 혼동행렬은 오답이 어느 클래스로 흘러갔는지 방향을 보여 주므로, 지표 숫자만으로는 보이지 않는 개선 지점을 찾아 준다.

## 코드로 보기 — 여섯 모델 비교와 앙상블

```python
from sklearn.neighbors import KNeighborsClassifier
from sklearn.naive_bayes import MultinomialNB
from sklearn.svm import LinearSVC
from sklearn.ensemble import RandomForestClassifier, VotingClassifier
from xgboost import XGBClassifier
from sklearn.metrics import accuracy_score, f1_score

models = {
    "KNN(k=17)":  KNeighborsClassifier(n_neighbors=17),
    "NaiveBayes": MultinomialNB(),
    "LinearSVC":  LinearSVC(random_state=42),
    "RandomForest": RandomForestClassifier(n_estimators=100, random_state=42),
    "XGBoost": XGBClassifier(n_estimators=200, max_depth=5,
                             learning_rate=0.3, random_state=42),
}

fitted = {}
for name, model in models.items():
    model.fit(X_train_tfidf, y_train)
    fitted[name] = model
    pred = model.predict(X_test_tfidf)
    print(f"{name:<13} acc={accuracy_score(y_test, pred):.2f} "
          f"macroF1={f1_score(y_test, pred, average='macro'):.2f} "
          f"weightedF1={f1_score(y_test, pred, average='weighted'):.2f}")

# 성능이 좋았던 세 모델을 하드 보팅으로 결합
ensemble = VotingClassifier(
    estimators=[("rf", fitted["RandomForest"]),
```

성격이 다른 다섯 분류기를 같은 벡터·같은 분할 조건에서 학습해 공정하게 비교하고, 상위 모델들을 결합해 추가 이득이 있는지 확인합니다.

3. 성능 상위 세 모델을 하드 보팅으로 묶어 다시 평가한다.

### 실행 결과 해석

여섯 모델의 성적을 한 표로 정리하면 이렇습니다(테스트 6,549건 기준).

| 모델 | accuracy | macro F1 | weighted F1 |
|---|---|---|---|
| KNN (k=17) | 0.67 | 0.67 | 0.67 |
| MultinomialNB | 0.70 | 0.69 | 0.70 |
| LinearSVC | 0.75 | 0.75 | 0.74 |
| RandomForest | 0.73 | 0.74 | 0.73 |
| XGBoost | 0.72 | 0.73 | 0.73 |

**KNN이 가장 낮습니다(0.67).** 1만 차원 희소 공간에서 거리 개념이 흐려진다는 예측이 그대로 확인됐습니다. 이론적 성질이 실제 숫자로 드러난 사례입니다.

**LinearSVC가 단일 모델 중 최고입니다(0.75).** 부스팅 계열보다 단순한데도 앞섰습니다. TF-IDF 벡터가 이미 유형별로 방향이 갈라져 있어 선형 경계로 충분했기 때문입니다.

**앙상블 이득은 크지 않습니다.** 단일 최고 모델 대비 accuracy는 그대로 0.75이고 macro F1이 0.75에서 0.76으로 0.01 오르는 데 그쳤습니다. 세 모델이 비슷한 유형(교통·행정)에서 비슷하게 틀리기 때문에 실수가 상쇄되지 않은 것입니다. 앙상블은 구성 모델들이 **서로 다른 실수**를 할 때 효과가 큽니다. 학습·예측 시간이 세 배 이상 늘어나는 비용을 감안하면, 이 정도 이득이 배포할 가치가 있는지는 별도 판단이 필요합니다.

**모든 모델이 같은 유형에서 무너집니다.** 교통(F1 0.50~0.58)과 행정(0.51~0.62)은 모델을 바꿔도 개선되지 않았습니다. 이는 모델의 문제가 아니라 **데이터와 라벨 정의의 문제**라는 신호입니다. 이럴 때 하이퍼파라미터를 더 돌리는 것은 헛수고이고, 유형 체계를 재설계하거나 두 유형을 구분할 추가 특성(민원 접수 경로, 첨부 정보 등)을 확보하는 쪽이 현실적입니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| precision vs recall | 예측한 것 중 맞은 비율이 precision, 실제 정답 중 찾아낸 비율이 recall |
| macro F1 vs weighted F1 | 클래스마다 한 표씩이면 macro, 샘플 수에 비례하면 weighted |
| accuracy vs macro F1 | 전체 정답률이 accuracy, 소수 클래스까지 동등하게 본 평균이 macro F1 |
| 언더샘플링 vs 오버샘플링 | 다수 클래스를 줄이면 언더, 소수 클래스를 늘리면 오버 |
| 하드 보팅 vs 소프트 보팅 | 예측 클래스로 다수결이면 하드, 예측 확률을 평균하면 소프트 |
| 배깅 vs 부스팅 | 독립적으로 여러 모델을 만들어 합치면 배깅, 앞 모델의 오차를 이어서 보완하면 부스팅 |

**Q3. 모델을 여러 개 바꿔 봐도 특정 두 유형이 계속 서로 헷갈립니다. 다음 수순은 무엇인가요?**

> 텍스트 분류는 정확도 한 줄이 아니라 클래스별 precision·recall과 혼동행렬로 읽어야 하며, 모든 모델이 같은 곳에서 틀린다면 그건 모델이 아니라 데이터의 문제다.
