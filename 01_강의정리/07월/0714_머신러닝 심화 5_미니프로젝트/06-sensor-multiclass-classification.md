# 센서 신호 다중분류 — 500개가 넘는 주파수 대역에서 유형을 읽어내기

> 사람이 귀로 듣고 "이건 누수 소리"라고 판단하던 일을 숫자 533개로 바꿔 모델에게 맡깁니다. 이 글은 고차원 센서 피처를 다루는 관점과, 단일 트리에서 부스팅까지 성능이 올라가는 이유를 정리합니다.

`고차원 피처` · `다중분류` · `MinMax 스케일링` · `라벨 인코딩` · `트리 앙상블`

## 핵심요약

- 배관에 붙은 진동 센서는 0Hz부터 5120Hz까지 10Hz 간격으로 진동 크기를 기록해, 한 건당 500개가 넘는 숫자를 만든다.
- 여기에 감지 10회분의 "최대 주파수 / 최대 크기" 20개를 더해 독립변수 533개, 학습 데이터 62,564건으로 5개 유형을 분류한다.
- 유형별 평균 곡선을 그려 보면 최대 크기는 정상음이 압도적으로 낮고, 최대 주파수는 옥내누수가 가장 높아 두 축의 조합이 유형을 가른다.
- 트리는 스케일에 둔감하지만 거리 기반 모델과 코드를 공유하려면 MinMax 스케일링이, 문자열 라벨을 학습시키려면 라벨 인코딩이 필요하다.
- 단일 트리 weighted F1 0.55 → 랜덤포레스트 0.67 → 부스팅 0.80으로, 오차를 다루는 방식이 달라질수록 성능이 계단식으로 올라갔다.

## 1. 고차원 센서 피처를 바라보는 관점

### 1) 정의

고차원 피처란 한 건의 데이터를 설명하는 열(컬럼)의 개수가 수백~수천 개에 이르는 상태를 말합니다. 이번 문제에서 한 건은 "센서가 한 번 측정한 결과"이고, 그 한 건이 533개의 숫자로 표현됩니다.

숫자의 출처는 두 갈래입니다.

```text
주파수 대역 피처 : 0HZ, 10HZ, 20HZ, ... , 5120HZ  → 513개
                  각 칸에는 그 주파수에서 잡힌 진동 크기가 들어감

감지 회차 피처   : (최대 주파수, 최대 크기) × 10회 → 20개
                  n번째 감지에서 가장 세게 울린 주파수와 그때의 크기
```

### 2) 왜 필요한가

소리나 진동은 "크다/작다"라는 한 숫자로 설명되지 않습니다. 같은 크기의 소리라도 낮은 음이 많은지 높은 음이 많은지에 따라 성격이 완전히 다르기 때문입니다. 신호를 주파수 대역별로 잘게 쪼개 놓으면, 모델이 "몇 Hz 부근이 유난히 센가"라는 형태로 패턴을 학습할 수 있습니다.

대신 열이 많아지면 학습이 느려지고, 노이즈 열이 섞여 과적합 위험이 커지고, 사람이 한눈에 훑어볼 수 없게 됩니다. 그래서 고차원 데이터에서는 열 하나하나를 보는 대신 **묶어서 요약해 보는 습관**이 중요합니다.

### 3) 핵심 흐름 재구성

열이 533개라고 해서 표를 533번 스크롤할 수는 없습니다. 실제로 쓰는 접근은 이렇습니다.

1. 열 이름의 규칙으로 그룹을 나눈다 — `HZ`로 끝나면 주파수 대역, `MAX`로 시작하면 감지 회차 정보.
2. 정답 라벨로 그룹화해 각 열의 평균을 낸다 — 5행 × 513열짜리 요약표가 만들어진다.
3. 요약표를 선그래프로 그린다 — x축은 주파수, y축은 평균 진동, 선 하나가 유형 하나.
4. 선들이 벌어지는 구간을 찾는다 — 그 구간이 곧 "모델이 쓸 만한 정보가 있는 곳"이다.

그래프에서 읽은 내용은 두 가지였습니다. 첫째, 모든 유형이 **0~500Hz 저주파 구간에서 평균값이 가장 높아** 신호 에너지 대부분이 저주파에 몰려 있습니다. 둘째, 그 안에서도 **400Hz 부근을 보면 옥외누수 → 옥내누수 → 환경음 → 기계·전기음 → 정상음 순으로 평균이 뚜렷하게 층을 이룹니다.** 선이 겹치지 않고 층층이 놓인다는 건, 그 구간 값 하나만 봐도 유형을 어느 정도 맞힐 수 있다는 뜻입니다.

감지 회차 정보도 같은 방식으로 봤습니다. 1회차 기준 유형별 평균을 보면 이렇습니다.

| 유형 | 최대 주파수 평균 | 최대 크기 평균 |
|---|---|---|
| 옥내누수 | 585 | 507 |
| 환경음 | 564 | 521 |
| 옥외누수 | 562 | 530 |
| 정상음 | 436 | 169 |
| 기계·전기음 | 357 | 582 |

여기서 유형을 가르는 축이 보입니다. **정상음은 크기가 169로 다른 유형의 3분의 1 수준**이라 크기 축만으로 거의 분리됩니다. **기계·전기음은 주파수가 357로 가장 낮은데 크기는 582로 가장 큽니다** — "낮고 센 소리"라는 조합이 고유한 지문이 됩니다. 문제는 나머지 셋입니다. 옥내누수·환경음·옥외누수는 주파수 562~585, 크기 507~530으로 서로 붙어 있습니다. 나중에 모델이 환경음을 잘 못 맞히는 이유가 여기서 예고됩니다.

### 4) 쉬운 예시

노래방에서 나오는 소리를 생각해 봅시다. "소리가 크다"만으로는 반주인지 사람 목소리인지 구분되지 않습니다. 하지만 이퀄라이저 막대를 보면 베이스 쪽이 튀는지 고음 쪽이 튀는지가 한눈에 보입니다. 주파수 대역 513개는 이 이퀄라이저 막대를 아주 촘촘하게 만든 것이고, 유형별 평균 곡선은 "누수 소리의 이퀄라이저 모양"과 "정상 소리의 이퀄라이저 모양"을 겹쳐 그린 그림입니다.

### 5) 코드 예시

```python
import matplotlib.pyplot as plt

# 열 이름 규칙으로 피처 그룹 분리
hz_cols  = [c for c in df.columns if c.endswith('HZ')]     # 주파수 대역
max_cols = [c for c in df.columns if c.startswith('MAX')]  # 감지 회차 정보

# 라벨별로 각 주파수 열의 평균 → 5행 × 513열 요약표
profile = df.groupby('label')[hz_cols].mean()

for label in profile.index:
    plt.plot(range(len(hz_cols)), profile.loc[label], label=label)
plt.xlabel('주파수 대역 순번'); plt.ylabel('평균 진동'); plt.legend()
plt.show()
```

핵심은 `groupby(라벨)[피처들].mean()` 한 줄입니다. 62,564행짜리 표를 5행짜리 "유형 프로필"로 압축해 주고, 그 프로필을 겹쳐 그리면 어느 구간이 유형을 가르는지가 눈에 들어옵니다.

### 6) 헷갈리는 점

"열이 많으면 무조건 성능이 좋다"고 오해하기 쉽습니다. 정보가 많다는 뜻이기도 하지만 노이즈도 많다는 뜻입니다. 이번처럼 신호가 저주파에 몰려 있으면 고주파 쪽 수백 개 열은 거의 상수에 가까워 학습에 기여하지 못합니다. 반대로 그래프에서 선이 겹치는 구간이라고 쓸모없는 것도 아닙니다. 평균은 겹쳐도 분산이 다르면 트리는 그 차이를 찾아냅니다.

### 7) 한 줄 정리

> 고차원 센서 피처는 열 하나씩이 아니라 라벨별 평균 프로필로 압축해 보고, 선이 벌어지는 구간에서 분류 단서를 찾는다.

## 2. 스케일링과 라벨 인코딩

### 1) 정의

MinMax 스케일링은 각 열의 값을 그 열의 최소값 0, 최대값 1로 옮겨 담는 변환입니다.

$$
x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}}
$$

이 식은 "그 열에서 가장 작은 값을 0, 가장 큰 값을 1로 두고, 나머지는 그 사이 몇 퍼센트 지점인지로 바꾼다"는 뜻입니다. 값이 100이고 그 열의 범위가 0~500이라면 $x' = 100/500 = 0.2$가 됩니다.

라벨 인코딩은 문자열로 된 정답을 정수로 바꾸는 변환입니다. 알파벳 오름차순으로 번호를 매기므로 `in→0`, `noise→1`, `normal→2`, `other→3`, `out→4`가 됩니다.

### 2) 왜 필요한가

스케일링이 필요한 이유는 열마다 값의 단위가 다르기 때문입니다. 주파수 대역 열은 진동 크기가 한 자리 수인 곳도 있고, 최대 주파수 열은 4000을 넘기도 합니다. 거리나 가중치를 쓰는 모델은 큰 숫자를 가진 열에 끌려다니게 됩니다. 트리 계열은 "값이 임계값보다 큰가"만 보므로 스케일에 영향받지 않지만, 나중에 다른 모델로 갈아탈 때 전처리 코드를 재사용하려면 스케일링을 미리 넣어 두는 편이 안전합니다.

라벨 인코딩이 필요한 이유는 더 단순합니다. 대부분의 분류 모델은 정답을 정수 배열로 받으므로, 문자열을 그대로 넣으면 학습 자체가 되지 않습니다.

### 3) 핵심 흐름 재구성

전처리에서 가장 중요한 규칙은 **학습 데이터에서 기준을 배우고, 테스트 데이터에는 그 기준을 그대로 적용한다**는 것입니다.

```text
학습셋 : fit_transform()   → 최소·최대값(또는 클래스 목록)을 배우고 동시에 변환
테스트셋: transform()       → 배운 기준으로 변환만 수행
```

테스트셋에도 `fit`을 하면 테스트셋의 최소·최대값이 전처리에 반영되어, 아직 보지 않아야 할 정보가 새어 들어옵니다. 이것이 데이터 누수(leakage)입니다.

또 하나, 라벨 인코딩 결과의 **0~4는 순서나 크기를 뜻하지 않습니다.** 옥외누수(4)가 정상음(2)보다 "크다"는 의미가 아니라 서로 다른 상자에 붙인 번호일 뿐이고, 다중분류 모델도 이 번호를 크기가 아닌 상자 이름으로 취급합니다.

### 4) 쉬운 예시

키(150~190cm)와 몸무게(45~95kg)로 사람을 분류한다고 해 봅시다. 두 값을 그대로 더해 거리를 재면 키가 훨씬 큰 목소리를 냅니다. 둘 다 0~1로 옮겨 놓으면 "각자 자기 범위에서 몇 퍼센트 지점인가"라는 같은 잣대로 비교됩니다. 라벨 인코딩은 반 이름 "A반, B반, C반"을 출석부에 0, 1, 2로 적어 두는 것과 같습니다. C반이 A반보다 크다는 뜻이 아니듯이 말입니다.

### 5) 코드 예시

```python
from sklearn.preprocessing import MinMaxScaler, LabelEncoder

# 독립변수: 학습셋에서 최소·최대를 배우고, 테스트셋에는 적용만
scaler = MinMaxScaler()
X_train = scaler.fit_transform(X_train)
X_test  = scaler.transform(X_test)

# 종속변수: 문자열 라벨 → 정수
le = LabelEncoder()
y_train = le.fit_transform(y_train)
y_test  = le.transform(y_test)

print(le.classes_)   # ['in' 'noise' 'normal' 'other' 'out']
```

```text
X_train.shape → (62564, 533)
변환 후 값 예시 → 0.0, 0.2169, 0.1301, ... 0.9417
결측값 개수 → 0
```

### 6) 헷갈리는 점

`fit_transform`과 `transform`을 헷갈려 테스트셋에도 `fit_transform`을 쓰는 실수가 흔합니다. 또 라벨 인코딩과 원-핫 인코딩을 혼동하기도 하는데, **종속변수(정답)는 라벨 인코딩, 순서 없는 범주형 독립변수는 원-핫 인코딩**이 기본 원칙입니다.

### 7) 한 줄 정리

> 스케일링은 열마다 다른 단위를 같은 잣대로 맞추고, 라벨 인코딩은 문자열 정답을 모델이 받을 수 있는 번호로 바꾼다.

## 3. 트리 계열 모델 비교 — 왜 이 순서로 좋아지는가

### 1) 정의

세 모델 모두 "조건으로 데이터를 갈라 나가는 트리"를 기본 단위로 쓰지만, 트리를 몇 개 쓰고 어떻게 합치는지가 다릅니다.

| 모델 | 트리 구성 방식 | 한 문장 요약 |
|---|---|---|
| 의사결정트리 | 트리 1개 | 데이터를 조건으로 반복해서 갈라 최종 칸의 다수 클래스로 예측 |
| 랜덤포레스트 | 트리 여러 개, 병렬 | 서로 다른 샘플·피처로 트리를 여러 개 만들고 투표 (배깅) |
| 부스팅 | 트리 여러 개, 순차 | 앞 트리가 틀린 부분을 다음 트리가 집중해서 보완 (부스팅) |

### 2) 왜 필요한가

단일 트리는 해석은 쉽지만 데이터가 조금만 바뀌어도 구조가 통째로 달라질 만큼 불안정합니다. 이 불안정함(분산)을 줄이려면 여러 트리의 의견을 평균 내면 되고, 그것이 랜덤포레스트입니다. 하지만 평균을 내는 것만으로는 "아무도 못 맞히는 어려운 구간"이 그대로 남습니다. 그 남은 오차를 다음 트리가 겨냥하게 만드는 것이 부스팅입니다.

### 3) 핵심 흐름 재구성

같은 데이터, 같은 전처리로 세 모델을 학습해 테스트셋 7,820건에서 비교한 결과입니다.

| 모델 | 설정 | Accuracy | Macro F1 | **Weighted F1** |
|---|---|---|---|---|
| 의사결정트리 | max_depth=7 | 0.61 | 0.43 | **0.55** |
| 랜덤포레스트 | n=100, depth=10 | 0.70 | 0.58 | **0.67** |
| 랜덤포레스트 | n=100, depth=12 | — | — | **0.74** |
| 부스팅 | n=50, lr=0.1, depth=8 | 0.80 | 0.75 | **0.80** |

성능이 오르는 이유를 클래스별로 뜯어보면 훨씬 선명합니다.

- **의사결정트리**: 정상음 F1 0.97로 거의 완벽하지만 **환경음 F1이 0.00**입니다. 환경음 878건 중 단 한 건도 환경음으로 예측하지 못했습니다. 대신 옥외누수의 재현율이 0.84로 높은데, 애매한 건을 전부 옥외누수로 몰아넣었다는 뜻입니다. 깊이 7짜리 트리 하나로는 533개 피처 중 극히 일부만 분기에 쓸 수 있어, 겹쳐 있는 세 유형을 갈라낼 여유가 없습니다.
- **랜덤포레스트**: 환경음 F1이 0.29로 살아났습니다. 흥미로운 건 환경음의 **정밀도가 0.96인데 재현율은 0.17**이라는 점입니다. "환경음이라고 말하면 거의 맞지만, 대부분은 자신 없어 말을 못 한다"는 상태입니다. 트리 100개가 투표하니 확실한 건은 잡아내지만, 애매한 건은 여전히 다수파인 옥외누수로 넘어갑니다.
- **부스팅**: 환경음 F1 0.58, 기계·전기음 0.70, 정상음 1.00. 이전 트리가 틀린 건에 가중치를 주며 순차 학습하므로 **소수 클래스이면서 다른 유형과 겹치는 구간**이 집중적으로 개선됩니다. 앞서 "옥내누수·환경음·옥외누수가 서로 붙어 있다"고 봤던 바로 그 구간입니다.

랜덤포레스트에서 깊이만 10에서 12로 올려도 weighted F1이 0.67에서 0.74로 뛰었다는 점도 중요합니다. 피처가 533개나 되면 얕은 트리로는 정보를 다 못 쓰므로, 고차원 데이터에서는 깊이를 조금 더 허용하는 편이 유리할 수 있습니다.

### 4) 쉬운 예시

병원 진료에 비유하면, 의사결정트리는 의사 한 명이 문진표를 따라 진단하는 것이고, 랜덤포레스트는 서로 다른 자료를 본 의사 100명이 각자 진단해 다수결로 정하는 협진입니다. 부스팅은 첫 의사가 놓친 환자를 두 번째 의사가 다시 보고, 그래도 남은 환자를 세 번째 의사가 보는 릴레이 진료입니다. 흔한 병은 협진으로 충분하지만, 드물고 헷갈리는 병은 릴레이 방식이 훨씬 잘 잡아냅니다.

### 5) 코드 예시

```python
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier
from xgboost import XGBClassifier
from sklearn.metrics import classification_report

models = {
    'tree':   DecisionTreeClassifier(max_depth=7, random_state=42),
    'forest': RandomForestClassifier(n_estimators=100, max_depth=10, random_state=42),
    'boost':  XGBClassifier(n_estimators=50, learning_rate=0.1,
                            max_depth=8, random_state=42, n_jobs=-1),
}

for name, model in models.items():
    model.fit(X_train, y_train)
    report = classification_report(y_test, model.predict(X_test), output_dict=True)
    print(f"{name:7s} weighted F1 = {report['weighted avg']['f1-score']:.2f}")
```

### 6) 헷갈리는 점

Accuracy와 Weighted F1을 같은 값으로 착각하기 쉽습니다. 의사결정트리는 accuracy 0.61인데 weighted F1은 0.55로 더 낮습니다. 정확도는 "맞힌 개수 비율"만 보지만 F1은 정밀도와 재현율을 함께 보기 때문에, 특정 클래스를 통째로 놓친 상태가 F1에서 더 크게 드러납니다. 또 Macro와 Weighted를 혼동하면 안 됩니다. 의사결정트리의 macro F1은 0.43으로 weighted 0.55보다 훨씬 낮은데, 이는 건수가 적은 클래스를 특히 못 맞혔다는 신호입니다.

### 7) 한 줄 정리

> 트리 하나 → 여러 개 투표 → 오차를 이어받는 순차 학습으로 갈수록, 겹쳐 있는 소수 클래스를 갈라내는 능력이 좋아진다.

## 코드로 보기 — 유형별 프로필로 분류 단서 찾기

```python
# 감지 회차별 '최대 주파수'와 '최대 크기'를 유형별 평균으로 압축
freq_cols = [f'MAX{i}' for i in range(0, 20, 2)]   # 짝수 → 최대 주파수
leak_cols = [f'MAX{i}' for i in range(1, 20, 2)]   # 홀수 → 최대 크기

freq_profile = df.groupby('label')[freq_cols].mean()
leak_profile = df.groupby('label')[leak_cols].mean()

print(freq_profile.iloc[:, 0].round(0))   # 1회차 최대 주파수 평균
print(leak_profile.iloc[:, 0].round(0))   # 1회차 최대 크기 평균
```

```text
최대 주파수 평균 : in 585, other 564, out 562, normal 436, noise 357
최대 크기 평균   : noise 582, out 530, other 521, in 507, normal 169
```

### 코드 목적

533개 피처 중 해석하기 쉬운 20개만 골라, 유형을 가르는 축이 무엇인지 사람이 읽을 수 있는 크기로 압축합니다.

### 코드 흐름

1. 열 이름의 짝수/홀수 규칙으로 "최대 주파수"와 "최대 크기"를 분리한다.
2. 유형별로 그룹화해 10회분 평균을 낸다.
3. 두 축의 값을 나란히 놓고, 어느 유형이 분리되고 어느 유형이 겹치는지 확인한다.

### 실행 결과 해석

두 축을 함께 보면 유형별 위치가 뚜렷하게 갈립니다. **정상음은 크기 169로 다른 유형(507~582)의 3분의 1 수준**이라 크기 축 하나로 거의 분리됩니다. **기계·전기음은 주파수 357로 가장 낮고 크기 582로 가장 높아** 두 축의 조합이 고유합니다. 반면 옥내누수·환경음·옥외누수는 주파수 562~585, 크기 507~530으로 거의 포개져 있습니다.

이 겹침이 모델 결과와 정확히 맞아떨어집니다. 정상음은 모든 모델에서 F1 0.95 이상이었고, 겹쳐 있던 환경음은 단일 트리 0.00 → 랜덤포레스트 0.29 → 부스팅 0.58로 마지막까지 가장 어려운 클래스였습니다. **EDA에서 본 겹침이 곧 모델이 고전할 지점을 미리 알려 준 셈**입니다.

### 실무 연결

설비 이상 감지, 제조 라인 불량 판정, 음성 이벤트 분류처럼 센서 신호를 다루는 문제는 모두 이 구조를 씁니다. 모델을 돌리기 전에 클래스별 프로필을 그려 두면 어떤 클래스가 헷갈릴지 미리 예측할 수 있고, 나중에 성능이 안 나올 때 "모델 탓인지 데이터가 원래 겹치는 탓인지"를 구분할 수 있습니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| Accuracy vs Weighted F1 | 맞힌 비율만 보면 Accuracy, 정밀도·재현율을 클래스 크기로 가중 평균하면 Weighted F1 |
| Macro avg vs Weighted avg | 클래스를 똑같이 취급하면 Macro, 건수로 가중하면 Weighted. 둘의 격차가 크면 소수 클래스가 약하다는 신호 |
| 배깅 vs 부스팅 | 여러 트리를 독립적으로 만들어 투표하면 배깅, 앞 트리의 오차를 이어받아 순차 학습하면 부스팅 |
| 라벨 인코딩 vs 원-핫 인코딩 | 정답 라벨은 정수 하나로(라벨 인코딩), 순서 없는 범주형 입력은 열을 나눠서(원-핫) |
| `fit_transform` vs `transform` | 학습셋에서 기준을 배울 때는 `fit_transform`, 테스트셋에 적용만 할 때는 `transform` |

## 한 줄 정리

> 500개가 넘는 센서 피처는 라벨별 프로필로 압축해 읽고, 겹쳐 있는 유형을 갈라내려면 오차를 이어받아 학습하는 부스팅이 단일 트리보다 유리하다.
