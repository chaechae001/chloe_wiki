# 한국어 텍스트 전처리와 벡터화 — 문장을 숫자로 바꾸는 과정

> 모델은 "불법 주정차 신고합니다"라는 문장을 읽지 못합니다. 읽을 수 있는 건 숫자뿐입니다. 이 글은 한국어 민원 문장을 어떻게 숫자 벡터로 바꾸는지, 그 과정에서 왜 형태소 분석이 필요하고 TF-IDF가 무엇을 계산하는지 정리합니다.

`형태소분석` · `토큰화` · `BoW` · `TF-IDF` · `희소행렬`

## 핵심요약

- 텍스트는 비정형 데이터라 모델에 그대로 넣을 수 없고, 반드시 고정 길이의 숫자 벡터로 바꿔야 한다.
- 한국어는 띄어쓰기만으로 단어를 자를 수 없어서(조사·어미가 붙음) 형태소 분석기로 토큰화해야 한다.
- BoW는 단어 등장 횟수만 세고, TF-IDF는 "이 문서에서 자주 + 다른 문서에서는 드물게" 나오는 단어에 큰 가중치를 준다.
- 민원 텍스트 26,195건을 명사 기준으로 벡터화하니 어휘 사전이 11,143개가 되어, 26,195 × 11,143 크기의 희소 행렬이 만들어졌다.
- 이 행렬에서 0이 아닌 값은 262,126개뿐(전체의 약 0.09%)이라, 밀집 배열이 아닌 희소 행렬 형식으로 다뤄야 한다.

## 1. 텍스트 수치화와 정제

### 1) 정의

텍스트 수치화(vectorization)는 문장 하나를 숫자들의 나열, 즉 벡터로 바꾸는 작업입니다. 그 앞 단계인 정제(cleaning)는 분석에 방해가 되는 기호·특수문자·불필요한 공백을 먼저 걷어내는 작업입니다.

### 2) 왜 필요한가

머신러닝 모델은 결국 덧셈과 곱셈을 하는 계산 장치입니다. 회귀 모델이 "면적 84, 층수 12" 같은 숫자를 받았듯이, 분류 모델도 "민원 문장"을 숫자 특성으로 받아야만 학습할 수 있습니다. 게다가 모델은 모든 샘플이 **같은 길이의 벡터**로 들어와야 하는데, 문장은 길이가 제각각입니다. 벡터화는 이 두 문제를 한꺼번에 해결합니다.

정제가 먼저 필요한 이유는 노이즈 때문입니다. 개인정보가 가려진 자리 표시자, 문장부호, 이모지 같은 것들은 민원 유형을 구분하는 데 아무 도움이 안 되면서 어휘 사전만 부풀립니다.

### 3) 핵심 흐름 재구성

전체 파이프라인은 아래 순서로 흘러갑니다.

```text
원본 문장 → 정제 → 토큰화 → 어휘 사전 구축 → 가중치 계산 → 벡터
```

정제 단계에서는 정규표현식으로 한글·영문·숫자·공백만 남기고 나머지를 지운 뒤, 연속된 공백을 하나로 줄입니다. 이 한 단계만 거쳐도 `#@주소#` 같은 마스킹 토큰이나 마침표·물음표가 사라져서 뒤따르는 토큰화가 훨씬 깔끔해집니다.

### 4) 쉬운 예시

쇼핑몰 리뷰를 생각해 보세요. "배송 진짜 빠름!!! ★★★★★" 이라는 리뷰에서 별표와 느낌표는 감정 분석에 쓸 수도 있지만, 유형 분류(배송/품질/환불)에는 쓸모가 없습니다. "배송 진짜 빠름"만 남기는 것이 정제입니다.

### 5) 코드 예시

```python
import re

def clean_text(text):
    # 한글, 영문, 숫자, 공백만 남기고 나머지 문자 제거
    text = re.sub(r"[^가-힣a-zA-Z0-9\s]", "", text)
    # 연속 공백을 하나로 줄이고 양끝 공백 제거
    return re.sub(r"\s+", " ", text).strip()

sample = "아파트 앞 도로가 파손되었습니다!! (#@주소#) 빠른 보수 부탁드립니다."
print(clean_text(sample))
```

```text
아파트 앞 도로가 파손되었습니다 빠른 보수 부탁드립니다
```

### 6) 헷갈리는 점

숫자를 지울지 말지가 자주 헷갈립니다. 민원 분류처럼 "몇 동 몇 호" 같은 숫자가 유형과 무관하면 지워도 되지만, 금액·날짜가 중요한 도메인에서는 지우면 정보가 날아갑니다. 정제 규칙은 항상 **문제에 종속적**입니다.

### 7) 한 줄 정리

> 정제는 유형 판단에 기여하지 않는 문자를 미리 걷어내 어휘 사전의 군더더기를 줄이는 준비 작업이다.

## 2. 한국어 토큰화와 형태소 분석

### 1) 정의

토큰화(tokenization)는 문장을 의미 단위(토큰)로 쪼개는 작업입니다. 형태소 분석은 그중에서도 "더 이상 쪼갤 수 없는 최소 의미 단위"인 형태소로 나누고, 각 조각의 품사까지 붙여 주는 작업입니다.

### 2) 왜 필요한가

영어는 공백으로 자르면 대체로 단어가 나옵니다. `"the cat sleeps"` → `the / cat / sleeps`. 그런데 한국어는 그렇지 않습니다.

```text
가로등이 / 가로등을 / 가로등은 / 가로등에
```

사람 눈에는 전부 "가로등"이지만, 공백 기준으로 자르면 서로 다른 네 개의 단어가 됩니다. 어휘 사전이 네 배로 부풀고, 정작 같은 뜻이라는 사실은 모델이 알 수 없습니다. 조사와 어미를 떼어 내는 형태소 분석이 한국어 처리의 첫 관문인 이유입니다.

### 3) 핵심 흐름 재구성

한국어 형태소 분석기는 보통 두 가지 출력을 제공합니다.

- **명사 추출**: 문장에서 명사만 골라냅니다. 조사·어미·부사가 전부 사라져 주제어만 남습니다.
- **형태소 분리**: 조사와 어미까지 포함해 모든 형태소를 나열합니다.

유형 분류처럼 "무엇에 관한 글인가"를 맞히는 문제에서는 명사만 남기는 쪽이 유리합니다. 조사(`이`, `를`, `에서`)는 어느 유형에나 똑같이 등장해서 유형을 구분하는 힘이 거의 없기 때문입니다. 실제로 이 프로젝트의 본 모델은 명사 추출을 토크나이저로 사용했습니다.

불용어(stopword) 제거도 같은 맥락입니다. 민원 텍스트라면 "부탁", "요청", "신고" 같은 단어가 거의 모든 유형에 나오는데, 이런 단어를 남겨 두면 벡터의 대부분을 무의미한 값이 차지합니다. 다만 뒤에서 볼 TF-IDF는 이런 단어의 가중치를 자동으로 낮춰 주므로, 별도의 불용어 사전 없이도 어느 정도 효과가 납니다.

### 4) 쉬운 예시

"공원 가로등이 고장 나서 밤에 어둡습니다"라는 문장을 처리해 봅시다.

- 공백 기준: `공원` / `가로등이` / `고장` / `나서` / `밤에` / `어둡습니다` → 6개, 그중 3개는 조사가 붙어 있음
- 명사 기준: `공원` / `가로등` / `고장` / `밤` → 4개, 전부 주제어

두 번째가 "가로등 고장 민원"이라는 성격을 훨씬 선명하게 드러냅니다.

### 5) 코드 예시

```python
from konlpy.tag import Okt

okt = Okt()
sentence = "공원 가로등이 고장 나서 밤에 어둡습니다"

print(okt.nouns(sentence))   # 명사만 추출
print(okt.morphs(sentence))  # 형태소 단위 전체 분리
```

`nouns()`는 주제어만 남기고, `morphs()`는 조사·어미까지 모두 토큰으로 만듭니다. 뒤에서 벡터화기에 이 함수를 그대로 `tokenizer` 인자로 넘겨 주면, 벡터화기가 문서를 자를 때 이 규칙을 사용합니다.

### 6) 헷갈리는 점

형태소 분석은 공짜가 아닙니다. 문장마다 분석기를 돌려야 해서 수만 건 규모에서는 수 분이 걸립니다. 실제로 16,744건을 명사 추출하는 데 약 1분, 훈련 데이터 26,195건을 벡터화하는 데 몇 분이 소요됐습니다. 하이퍼파라미터를 바꿔 가며 여러 번 실험할 때는 토큰화 결과를 미리 저장해 두는 편이 낫습니다.

### 7) 한 줄 정리

> 한국어는 단어에 조사와 어미가 달라붙기 때문에, 형태소 분석기로 토큰화해야 같은 뜻의 단어가 하나의 특성으로 모인다.

## 3. BoW와 TF-IDF 벡터화

### 1) 정의

BoW(Bag of Words)는 문서를 "어떤 단어가 몇 번 나왔는가"의 목록으로만 표현하는 방식입니다. 단어 순서는 버리고 개수만 봅니다. TF-IDF는 여기에 한 걸음 더 나아가, **문서 안에서는 자주 나오지만 전체 문서 집합에서는 드물게 나오는 단어**에 높은 점수를 주는 가중치 방식입니다.

### 2) 왜 필요한가

BoW만 쓰면 문제가 생깁니다. 민원 문서 대부분에 "신고", "요청", "부탁" 같은 단어가 들어 있어서, 이 단어들의 등장 횟수가 항상 가장 큽니다. 하지만 모든 유형에 다 나오는 단어는 유형을 구분하는 데 전혀 도움이 안 됩니다. TF-IDF는 이런 흔한 단어의 값을 자동으로 깎아 내리고, 특정 유형에만 나오는 단어("과태료", "예방접종", "지목변경")를 도드라지게 만듭니다.

### 3) 핵심 흐름 재구성

TF-IDF는 두 항의 곱입니다.

$$
\text{TF-IDF}(t, d) = \text{TF}(t, d) \times \text{IDF}(t)
$$

여기서 $t$는 단어(term), $d$는 문서(document)입니다. 각 항의 의미는 이렇습니다.

$$
\text{TF}(t, d) = \text{문서 } d \text{ 안에서 단어 } t \text{ 가 등장한 횟수}
$$

"이 문서에서 이 단어가 얼마나 중요한가"를 문서 내부 기준으로 잰 값입니다.

$$
\text{IDF}(t) = \log\!\left(\frac{1 + n}{1 + \text{df}(t)}\right) + 1
$$

$n$은 전체 문서 수, $\text{df}(t)$는 단어 $t$가 등장한 문서의 개수입니다. 분모의 $\text{df}$가 커질수록(= 흔한 단어일수록) 분수가 작아지고 로그값도 작아지므로, **흔한 단어의 IDF는 1에 가까워지고 희귀한 단어의 IDF는 커집니다**. 분자·분모에 1을 더하는 건 0으로 나누는 사고를 막기 위한 장치이고, 마지막에 1을 더하는 건 모든 문서에 나오는 단어라도 값이 0이 되어 완전히 사라지지 않게 하려는 장치입니다.

마지막으로 문서별 벡터를 L2 정규화합니다. 긴 문서는 단어 수가 많아 값이 커지는데, 정규화하면 길이가 아니라 **단어 구성 비율**로 문서를 비교할 수 있습니다.

### 4) 쉬운 예시

영어 문장 3개로 손계산을 해 보겠습니다. 문서 수 $n = 3$입니다.

```text
d1: the cat sleeps quietly
d2: the dog barks quietly
d3: the cat and dog run together
```

`the`는 세 문서 모두에 나오므로 $\text{df} = 3$ → $\text{IDF} = \log(4/4) + 1 = 1$
`cat`은 두 문서에 나오므로 $\text{df} = 2$ → $\text{IDF} = \log(4/3) + 1 \approx 1.288$
`sleeps`는 한 문서에만 나오므로 $\text{df} = 1$ → $\text{IDF} = \log(4/2) + 1 \approx 1.693$

d1의 네 단어는 모두 한 번씩 나오므로 TF는 전부 1이고, 원시 점수는 IDF 그대로입니다. 이를 L2 정규화(벡터 길이로 나누기)하면 d1의 값은 이렇게 나옵니다.

```text
d1 →  the 0.3731 | cat 0.4805 | quietly 0.4805 | sleeps 0.6317
```

셋 다 한 번씩 등장했는데도 점수가 다릅니다. **모든 문서에 나오는 `the`가 가장 낮고, 이 문서에만 있는 `sleeps`가 가장 높습니다.** 이것이 TF-IDF의 핵심 직관입니다. 같은 계산을 d3에 하면 `the`는 0.2782까지 더 떨어지는데, d3이 더 길어서 정규화 나눗셈의 분모가 커졌기 때문입니다.

### 5) 코드 예시

```python
from sklearn.feature_extraction.text import TfidfVectorizer

docs = ["the cat sleeps quietly",
        "the dog barks quietly",
        "the cat and dog run together"]

vectorizer = TfidfVectorizer()
tfidf = vectorizer.fit_transform(docs)

print(tfidf.shape)                        # (3, 9) — 문서 3개 × 어휘 9개
print(vectorizer.get_feature_names_out())  # 어휘 사전
```

한국어에 적용할 때는 토크나이저만 바꿔 끼우면 됩니다.

```python
def noun_tokenizer(text):
    return okt.nouns(text)

vectorizer = TfidfVectorizer(tokenizer=noun_tokenizer)
```

### 6) 헷갈리는 점

`fit_transform`과 `transform`을 구분하지 못하는 실수가 잦습니다. 어휘 사전과 IDF 값은 **훈련 데이터에서만** 학습해야 합니다. 테스트 데이터에 `fit`을 다시 하면 테스트 문서의 단어 분포가 학습에 스며드는 데이터 누수가 되고, 게다가 훈련 때와 열 개수가 달라져 모델이 아예 동작하지 않습니다.

### 7) 한 줄 정리

> TF-IDF는 "이 문서에서 자주 나오면 올리고, 모든 문서에서 나오면 내린다"는 두 규칙을 곱해 단어의 변별력을 점수화한다.

## 4. 희소 행렬과 어휘 사전 크기

### 1) 정의

희소 행렬(sparse matrix)은 원소 대부분이 0인 행렬을 말합니다. 0이 아닌 값의 **위치와 값만** 저장해서 메모리를 아끼는 자료구조입니다.

### 2) 왜 필요한가

텍스트 벡터화 결과는 필연적으로 희소합니다. 어휘 사전에는 만 개가 넘는 단어가 있는데, 문장 하나에는 열 개 남짓만 들어 있기 때문입니다. 나머지 만 개 이상의 자리는 전부 0입니다. 이걸 일반 배열로 만들면 메모리가 순식간에 터집니다.

### 3) 핵심 흐름 재구성

이 프로젝트의 실제 수치로 확인해 봅시다. 훈련 데이터 26,195건을 명사 토크나이저로 벡터화하자 어휘 사전 크기가 **11,143개**가 되었고, 결과는 `26,195 × 11,143` 모양의 희소 행렬이 되었습니다. 여기서 0이 아닌 값은 **262,126개**입니다.

전체 칸 수는 $26{,}195 \times 11{,}143 \approx 2.92 \times 10^8$, 즉 약 2억 9천만 칸입니다. 채워진 칸의 비율을 계산하면 이렇게 됩니다.

$$
\text{밀도} = \frac{262{,}126}{26{,}195 \times 11{,}143} \approx 0.0009
$$

**약 0.09%만 채워져 있고 99.9%는 0**이라는 뜻입니다. 문서 하나당 평균 $262{,}126 \div 26{,}195 \approx 10$개의 고유 명사만 담겨 있다는 계산도 나옵니다. 실제로 민원 한 건은 대체로 한두 문장이므로 납득할 만한 숫자입니다.

만약 이 행렬을 밀집 배열(`toarray()`)로 펼치면 8바이트 실수 기준으로 2억 9천만 × 8바이트 ≈ 2.3GB가 필요합니다. 반면 희소 형식은 26만 개 값과 그 좌표만 저장하므로 수 메가바이트로 끝납니다.

### 4) 쉬운 예시

대형 마트의 영수증을 떠올려 보세요. 마트에 상품이 3만 종 있지만 손님 한 명의 영수증에는 보통 10개 남짓이 찍힙니다. "3만 칸짜리 표에 10칸만 채운" 상태가 매 영수증마다 반복되는 셈이고, 이것이 정확히 희소 행렬입니다.

### 5) 코드 예시

```python
X_train_tfidf = vectorizer.fit_transform(X_train)  # 훈련 데이터로 사전 학습
X_test_tfidf = vectorizer.transform(X_test)        # 테스트는 변환만

print(X_train_tfidf.shape)   # (26195, 11143)
print(X_train_tfidf.nnz)     # 262126 — 0이 아닌 값의 개수
density = X_train_tfidf.nnz / (X_train_tfidf.shape[0] * X_train_tfidf.shape[1])
print(f"밀도: {density:.4%}")
```

```text
(26195, 11143)
262126
밀도: 0.0898%
```

### 6) 헷갈리는 점

`toarray()`를 습관적으로 붙이면 안 됩니다. 앞의 세 문장짜리 예제처럼 작을 때는 확인용으로 괜찮지만, 실제 데이터에서는 메모리 부족으로 커널이 죽습니다. 사이킷런의 대부분 모델은 희소 행렬을 그대로 받으므로 변환할 필요가 없습니다.

### 7) 한 줄 정리

> 텍스트 벡터는 어휘 사전만큼 넓고 거의 다 0이므로, 반드시 희소 형식으로 만들고 그대로 모델에 넘겨야 한다.

## 코드로 보기 — 민원 텍스트 벡터화 전체 파이프라인

```python
import re
from konlpy.tag import Okt
from sklearn.preprocessing import LabelEncoder
from sklearn.model_selection import train_test_split
from sklearn.feature_extraction.text import TfidfVectorizer

okt = Okt()

# 1) 정제
def clean_text(text):
    text = re.sub(r"[^가-힣a-zA-Z\s]", "", text)
    return re.sub(r"\s+", " ", text).strip()

df["clean_text"] = df["text"].apply(clean_text)

# 2) 정답 라벨을 정수로 인코딩
le = LabelEncoder()
df["label"] = le.fit_transform(df["category"])

# 3) 훈련/테스트 분리 (8:2)
X_train, X_test, y_train, y_test = train_test_split(
    df["clean_text"], df["label"], test_size=0.2, random_state=42)

# 4) 명사 토크나이저로 TF-IDF 벡터화
def noun_tokenizer(text):
    return okt.nouns(text)

vectorizer = TfidfVectorizer(tokenizer=noun_tokenizer)
X_train_tfidf = vectorizer.fit_transform(X_train)
X_test_tfidf = vectorizer.transform(X_test)
```

### 코드 목적

한국어 민원 문장을 모델이 바로 학습할 수 있는 숫자 행렬로 바꾸고, 정답 유형도 정수 라벨로 맞추는 것이 목적입니다.

### 코드 흐름

1. 정규표현식으로 기호를 걷어내 정제한다.
2. 문자열 유형명을 `LabelEncoder`로 0부터 시작하는 정수로 바꾼다.
3. 훈련 80% / 테스트 20%로 나눈다.
4. 훈련 데이터에만 `fit_transform`, 테스트에는 `transform`만 적용해 벡터화한다.

### 실행 결과 해석

원본 민원 데이터는 총 **769,710건**이고 유형은 **17개**였습니다. 그런데 자동차 유형이 295,107건인 반면 정보통신은 744건에 불과해, 비율이 약 **400 대 1**까지 벌어졌습니다. 그래서 유형별로 최대 2,000건까지만 뽑아 **32,744건**으로 줄인 뒤 학습에 사용했습니다. 정보통신만 744건 그대로이고 나머지 16개 유형은 각 2,000건입니다.

라벨 인코딩 결과 유형명이 가나다순으로 0~16에 배정됐습니다(건축허가 → 0, 경제 → 1, 교통 → 2 …). 여기서 주의할 점은 이 숫자에 **크기 의미가 없다**는 것입니다. 교통(2)이 경제(1)보다 크다는 뜻이 아니라 그냥 이름표입니다.

8:2 분리 후 훈련 26,195건, 테스트 6,549건이 되었고, 벡터화 결과는 앞서 본 대로 `26,195 × 11,143` 희소 행렬입니다. 어휘 사전 11,143개는 "민원 텍스트에서 등장한 고유 명사의 종류"로, 데이터를 더 넣으면 계속 늘어납니다. 사전이 너무 커지면 `max_features`나 `min_df`로 상한을 두어 희귀 단어를 잘라 내는 것이 일반적인 대응입니다.

벡터화된 결과를 차원 축소해 2차원으로 그려 보면, 같은 유형의 문서들이 눈에 띄게 뭉쳐 있는 모습이 나타납니다. 이는 TF-IDF 공간에서 이미 유형별 방향성이 어느 정도 형성됐다는 뜻이고, 선형 분류기만으로도 쓸 만한 성능이 나올 것이라는 예고이기도 합니다.

### 실무 연결

이 파이프라인은 고객센터 문의 자동 라우팅, 스팸 필터, 리뷰 카테고리 자동 태깅, 사내 문서 자동 분류 같은 업무에 그대로 옮겨 갑니다. 특히 "접수된 글을 담당 부서로 넘기는" 업무는 사람이 하면 건당 수십 초가 걸리지만, 벡터화 + 분류 모델은 밀리초 단위로 처리합니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| BoW vs TF-IDF | 등장 횟수만 세면 BoW, 흔한 단어의 가중치를 깎으면 TF-IDF |
| 명사 추출 vs 형태소 분리 | 주제어만 남기면 명사 추출, 조사·어미까지 토큰으로 만들면 형태소 분리 |
| TF vs IDF | 문서 하나 안의 빈도가 TF, 전체 문서에서의 희귀도가 IDF |
| `fit_transform` vs `transform` | 사전과 IDF를 새로 학습하면 `fit_transform`, 학습된 기준으로 변환만 하면 `transform` |
| 라벨 인코딩 vs 원-핫 인코딩 | 정답(y)은 정수 라벨이면 충분, 순서 없는 입력 특성(X)은 원-핫이 안전 |
| 희소 행렬 vs 밀집 배열 | 0이 아닌 값만 저장하면 희소, 모든 칸을 저장하면 밀집 |

### 복습 질문 및 답변

**Q1. BoW 대신 TF-IDF를 쓰는 이유는 무엇인가요?**

<details>
<summary>답</summary>

BoW는 등장 횟수만 세기 때문에, 모든 문서에 흔하게 나오는 단어("신고", "요청")가 가장 큰 값을 갖습니다. 그런데 이런 단어는 유형을 구분하는 힘이 없습니다. TF-IDF는 IDF 항으로 흔한 단어의 가중치를 낮추고 특정 문서에만 나오는 단어를 부각시켜, 문서의 변별력 있는 특징을 살립니다.

</details>

**Q2. 어휘 사전이 11,143개인데 문서당 평균 10개 단어만 채워진다면 어떤 문제가 생기나요?**

<details>
<summary>답</summary>

행렬의 99.9%가 0인 극단적인 고차원 희소 데이터가 됩니다. 밀집 배열로 저장하면 메모리가 폭발하므로 희소 형식이 필수입니다. 또한 거리 기반 알고리즘(KNN 등)은 이런 고차원 공간에서 모든 점 사이 거리가 비슷해지는 차원의 저주 때문에 성능이 떨어지고, 선형 모델이나 나이브 베이즈가 상대적으로 잘 작동합니다.

</details>

**Q3. 새로 들어온 민원에 훈련 때 없던 단어만 잔뜩 들어 있다면 벡터는 어떻게 되나요?**

<details>
<summary>답</summary>

`transform`은 학습된 어휘 사전에 없는 단어를 그냥 무시합니다. 따라서 그 문서의 벡터는 거의 모든 값이 0인 상태가 되고, 모델은 사실상 정보 없이 예측하게 됩니다. 실무에서는 이런 미등록 단어(OOV) 비율을 주기적으로 모니터링하고, 일정 수준을 넘으면 사전을 다시 학습하거나 문자 단위 n-gram, 사전 학습 임베딩 같은 대안을 검토합니다.

</details>
