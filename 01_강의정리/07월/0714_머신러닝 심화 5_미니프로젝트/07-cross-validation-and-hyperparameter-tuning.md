# 교차검증과 하이퍼파라미터 튜닝 — 성능을 끌어올리는 마지막 30%

> 모델을 고르고 나면 끝일 것 같지만, 진짜 차이는 그다음에 납니다. 이 글은 단일 검증셋의 한계에서 출발해 교차검증, 정규화, 자동 탐색까지 성능을 0.80에서 0.93으로 끌어올린 절차를 정리합니다.

`교차검증` · `StratifiedKFold` · `L1/L2 정규화` · `하이퍼파라미터 탐색` · `목적함수`

## 핵심요약

- 검증셋을 한 번만 잘라 성능을 재면, 그 한 번의 분할 운에 따라 점수가 흔들려 모델 비교의 근거가 약해진다.
- K-Fold는 데이터를 K조각으로 나눠 모든 조각이 한 번씩 검증셋이 되게 하고, 그 평균으로 성능을 판단한다.
- StratifiedKFold는 각 폴드의 클래스 비율을 원본과 같게 유지해, 소수 클래스가 특정 폴드에 몰리는 사고를 막는다.
- L1/L2 정규화는 가중치가 커지는 것에 벌점을 매겨 과적합을 억제한다. 이번 데이터에서는 둘을 함께 켰을 때 weighted F1이 0.84에서 0.85로 올랐다.
- 손으로 값을 바꿔 가며 실험하는 대신 목적함수·탐색공간·시행 횟수만 정의하면 자동으로 최적 조합을 찾을 수 있고, 그 결과 테스트 weighted F1이 0.80에서 0.93으로 개선됐다.

## 1. 단일 검증셋의 한계와 K-Fold 교차검증

### 1) 정의

교차검증(Cross Validation)은 데이터를 여러 조각으로 나눠 **번갈아 가며 검증셋 역할을 맡기고, 그 성능들의 평균으로 모델을 평가**하는 방법입니다. K개로 나누면 K-Fold 교차검증이라고 부릅니다.

```text
5-Fold (■ = 검증, □ = 학습)
1회차 ■ □ □ □ □ → s1      4회차 □ □ □ ■ □ → s4
2회차 □ ■ □ □ □ → s2      5회차 □ □ □ □ ■ → s5
3회차 □ □ ■ □ □ → s3      최종 성능 = (s1+s2+s3+s4+s5) / 5
```

### 2) 왜 필요한가

데이터를 한 번만 8:2로 잘라 검증하면, 그 20%에 우연히 쉬운 건들만 들어갈 수도 있고 어려운 건들만 몰릴 수도 있습니다. 그러면 같은 모델인데도 잘라내는 방식에 따라 점수가 오르내립니다. 하이퍼파라미터를 비교할 때 이 흔들림은 치명적입니다. `max_depth=6`과 `max_depth=8` 중 뭐가 나은지 판단해야 하는데, 그 차이보다 분할 운의 차이가 더 클 수 있기 때문입니다.

교차검증은 모든 데이터가 한 번씩 검증셋이 되도록 만들어 이 운의 영향을 평균으로 상쇄합니다. **하이퍼파라미터 비교는 반드시 교차검증 위에서 해야 한다**는 원칙이 여기서 나옵니다.

### 3) 핵심 흐름 재구성

교차검증에는 대가가 따릅니다. 5-Fold는 곧 **모델을 5번 학습시킨다**는 뜻이고, 후보 조합이 4개면 총 20번을 학습해야 합니다. 실제로 이번 데이터에서 조합 하나를 5-Fold로 평가하는 데 2~3분이 걸렸습니다. 그래서 데이터가 크면 먼저 단일 검증셋으로 모델 종류를 좁히고, 후보가 2~3개로 줄었을 때 교차검증으로 정밀 비교하는 순서를 씁니다.

마지막 단계도 중요합니다. 교차검증에서 만들어진 5개 모델은 각각 데이터의 80%만 본 모델이므로 그대로 쓰지 않습니다. **교차검증은 "어떤 설정이 좋은가"를 고르는 도구이고, 최종 모델은 그 설정으로 전체 데이터를 다시 학습해 만듭니다.**

### 4) 쉬운 예시

수능 모의고사에 비유하면, 한 번 친 점수로 실력을 판단하는 것이 단일 검증셋입니다. 그날 컨디션이나 문제 유형 운에 따라 점수가 크게 달라집니다. 다섯 번 치고 평균을 내면 진짜 실력에 훨씬 가까워지는데, 교차검증은 이 "다섯 번 치기"를 데이터를 돌려 가며 하는 것입니다.

### 5) 코드 예시

```python
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.metrics import f1_score, make_scorer

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(model, X_train, y_train, cv=cv,
                         scoring=make_scorer(f1_score, average='weighted'))
print(scores, scores.mean())   # 폴드별 점수 5개와 그 평균
```

`shuffle=True`를 켜야 원본이 유형별로 정렬돼 있어도 폴드가 한쪽으로 쏠리지 않고, `random_state`를 고정해야 다음에 다시 돌렸을 때 같은 분할이 재현됩니다.

### 6) 헷갈리는 점

교차검증 점수를 최종 성능으로 보고하는 실수가 흔합니다. 이 점수는 **하이퍼파라미터를 고르는 데 이미 사용한 값**이라 약간 낙관적이므로, 최종 보고는 튜닝에 한 번도 쓰지 않은 테스트셋으로 해야 합니다. 이번 사례에서는 교차검증 평균 0.9335와 테스트셋 0.9317이 거의 일치해, 탐색이 과하게 치우치지 않았음을 확인할 수 있었습니다.

### 7) 한 줄 정리

> 교차검증은 분할 운을 평균으로 지워, 하이퍼파라미터를 비교할 수 있는 안정된 잣대를 만들어 준다.

## 2. StratifiedKFold — 클래스 비율을 지키는 분할

### 1) 정의

StratifiedKFold는 K-Fold를 만들 때 **각 폴드의 클래스 구성 비율이 원본 데이터와 최대한 같아지도록** 나누는 방식입니다. 층(strata)을 유지한다는 뜻에서 층화 분할이라고 부릅니다.

### 2) 왜 필요한가

이번 데이터의 유형별 건수는 정상음 19,704 / 옥외누수 17,539 / 옥내누수 13,273 / 환경음 7,019 / 기계·전기음 5,029로, 가장 많은 클래스와 가장 적은 클래스가 약 3.9배 차이 납니다. 이런 상태에서 무작위로 5등분하면 어떤 폴드에는 기계·전기음이 평소보다 훨씬 적게 들어갈 수 있습니다.

그러면 그 폴드에서 학습한 모델은 소수 클래스를 거의 배우지 못하고, 검증할 때도 샘플이 부족해 F1이 불안정하게 튑니다. 결국 폴드마다 점수가 들쭉날쭉해져 평균이 신뢰를 잃습니다. 극단적으로 소수 클래스가 한 폴드에 0건 들어가면 그 클래스의 F1은 계산조차 되지 않습니다.

### 3) 핵심 흐름 재구성

층화 분할이 실제로 어떻게 동작하는지는 두 가지 그림으로 확인했습니다.

**어떤 샘플이 어느 폴드에서 검증에 쓰였나.** x축이 샘플 번호, y축이 폴드 번호이고, 각 폴드의 학습 샘플과 검증 샘플을 다른 색으로 찍었습니다. 검증 색이 폴드마다 x축 전체에 고르게 흩어져 있고, 세로로 보면 **모든 샘플이 정확히 한 번씩만 검증에 쓰였습니다**. 셔플이 작동해 앞부분·뒷부분이 통째로 한 폴드에 몰리는 일이 없었다는 뜻입니다.

**폴드별 클래스 구성.** 폴드마다 학습셋과 검증셋의 클래스별 건수를 누적 막대로 쌓았더니, 5개 폴드의 막대가 색 비율까지 거의 똑같았습니다. 학습셋 막대와 검증셋 막대도 높이만 4:1로 다를 뿐 색 구성은 같았습니다. **원본의 클래스 비율이 10개 막대 전부에 복제된 것**이 층화 분할의 효과입니다.

수식으로 쓰면, 클래스 $c$의 원본 비율이 $p_c$일 때 각 폴드 $k$에서도

$$
\frac{n_{k,c}}{n_k} \approx p_c \quad (\text{모든 } k, c \text{에 대해})
$$

이 식은 "어느 폴드를 열어 봐도 클래스 구성 비율이 전체와 비슷하다"는 뜻입니다. 예를 들어 원본에서 기계·전기음이 8%라면, 5개 폴드 각각에서도 대략 8%가 유지됩니다.

### 4) 쉬운 예시

100명 중 남학생 80명, 여학생 20명인 학급을 5개 조로 나눈다고 해 봅시다. 그냥 뽑기로 나누면 어떤 조는 여학생이 1명, 다른 조는 8명이 될 수 있습니다. 층화 분할은 남학생 80명에서 16명씩, 여학생 20명에서 4명씩 따로 뽑아 조를 만드는 방식이라, 모든 조가 16:4로 원래 비율을 유지합니다.

### 5) 코드 예시

```python
from sklearn.model_selection import StratifiedKFold
import numpy as np

skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

for i, (tr, va) in enumerate(skf.split(X, y), 1):   # split에 y를 반드시 넘김
    print(f'Fold {i} 검증셋 클래스 분포: {np.bincount(y[va], minlength=5)}')
```

`KFold.split(X)`는 y가 없어도 되지만 `StratifiedKFold.split(X, y)`는 y가 반드시 필요합니다. 비율을 맞추려면 정답을 봐야 하기 때문입니다.

### 6) 헷갈리는 점

분류 문제인데 습관적으로 일반 `KFold`를 쓰는 경우가 많습니다. `cross_val_score`에 정수(`cv=5`)만 넘기면 분류에서는 내부적으로 층화 분할이 적용되지만 셔플은 켜지지 않습니다. 데이터가 라벨 순서대로 정렬돼 있다면 부족하므로, `StratifiedKFold(shuffle=True, random_state=...)`를 직접 만들어 넘기는 편이 안전합니다.

### 7) 한 줄 정리

> StratifiedKFold는 모든 폴드에 원본의 클래스 비율을 복제해, 불균형 데이터에서도 폴드별 점수를 믿을 수 있게 만든다.

## 3. L1·L2 정규화 — 과적합에 매기는 벌점

### 1) 정의

정규화(Regularization)는 모델이 학습할 때 최소화하는 목표에 **"가중치가 커지면 손해"라는 벌점 항을 추가**하는 기법입니다.

$$
\text{최종 목표} = \underbrace{L(y, \hat{y})}_{\text{예측 오차}} + \underbrace{\alpha \sum_{j} |w_j|}_{\text{L1 벌점}} + \underbrace{\frac{\lambda}{2} \sum_{j} w_j^2}_{\text{L2 벌점}}
$$

이 식은 "예측을 잘 맞히되, 그러려고 가중치를 무리하게 키우면 그만큼 점수를 깎는다"는 뜻입니다. $\alpha$와 $\lambda$는 벌점의 세기를 정하는 손잡이로, 0이면 벌점 없음, 크게 할수록 가중치를 강하게 억누릅니다.

두 벌점의 성격은 다릅니다.

- **L1(절대값)**: 작은 가중치를 아예 0으로 밀어냅니다. 결과적으로 쓸모없는 피처를 잘라내는 변수 선택 효과가 생깁니다.
- **L2(제곱)**: 모든 가중치를 0 쪽으로 고르게 줄입니다. 0으로 만들지는 않고 전체를 매끄럽게 다듬습니다.

### 2) 왜 필요한가

피처가 533개나 되면 모델은 특정 피처 몇 개에 큰 가중치를 몰아주며 훈련 데이터를 외워 버릴 여지가 큽니다. 훈련 성적은 좋아지지만 새 데이터에서는 무너집니다. 정규화는 "그렇게 극단적으로 기울어지려면 대가를 치러라"고 제약을 걸어 모델을 조금 더 겸손하게 만듭니다.

### 3) 핵심 흐름 재구성

부스팅 모델에서 `reg_alpha`(L1)와 `reg_lambda`(L2)를 0과 1로 바꿔 가며 네 가지 조합을 비교했습니다. 나머지 설정은 모두 고정했습니다.

| L1(alpha) | L2(lambda) | Accuracy | Macro F1 | **Weighted F1** | 환경음 F1 | 기계·전기음 F1 |
|---|---|---|---|---|---|---|
| 0 | 0 | 0.84 | 0.80 | **0.84** | 0.69 | 0.73 |
| 1 | 0 | 0.84 | 0.80 | **0.84** | 0.69 | 0.72 |
| 0 | 1 | 0.84 | 0.80 | **0.84** | 0.69 | 0.73 |
| 1 | 1 | 0.85 | 0.81 | **0.85** | 0.72 | 0.74 |

**하나만 켰을 때는 거의 변화가 없습니다.** L1만 올려도 L2만 올려도 weighted F1은 0.84 그대로여서, 정규화를 넣었다고 자동으로 성능이 오르지는 않습니다. 반면 **둘을 함께 켰을 때 0.85로 올랐고**, 이 상승은 전체가 고르게 오른 것이 아니라 특정 클래스에서 왔습니다. 환경음 F1이 0.69에서 0.72로, 기계·전기음이 0.73에서 0.74로 올랐고 이미 완벽하던 정상음(F1 1.00)은 그대로입니다. 즉 **정규화는 모델이 애매해하던 경계 부근에서 판단을 다듬어 줍니다.** 클래스를 똑같이 취급하는 macro F1이 0.80에서 0.81로 오른 것도 건수가 적은 클래스가 좋아졌다는 신호입니다.

### 4) 쉬운 예시

시험에서 한 과목만 만점 받고 나머지를 버리는 전략을 막고 싶다면 "한 과목 점수가 일정 이상 올라갈수록 가산점을 깎는다"는 규칙을 두면 됩니다. 학생은 자연히 모든 과목을 고르게 챙기게 됩니다. L2가 이 방식이고, L1은 여기에 더해 "공부하지 않을 과목은 아예 포기하라"고 정리해 주는 규칙입니다.

### 5) 코드 예시

```python
for a, l in [(0, 0), (1, 0), (0, 1), (1, 1)]:
    model = XGBClassifier(n_estimators=50, learning_rate=0.3, max_depth=6,
                          reg_alpha=a, reg_lambda=l,   # L1, L2
                          random_state=42, n_jobs=-1).fit(X_train, y_train)
    rep = classification_report(y_test, model.predict(X_test), output_dict=True)
    print(f'alpha={a}, lambda={l} → weighted F1 {rep["weighted avg"]["f1-score"]:.2f}')
```

### 6) 헷갈리는 점

L1을 켜면 무조건 피처가 줄어들 것이라 기대하기 쉽지만, 트리 기반 부스팅에서 정규화는 선형 모델과 달리 리프 노드의 출력값에 걸립니다. "피처가 사라진다"기보다 "각 트리의 예측 폭이 얌전해진다"에 가깝습니다. 또 벌점을 세게 걸수록 좋다고 오해하기 쉬운데, 지나치면 모델이 단순해져 과소적합으로 돌아섭니다.

### 7) 한 줄 정리

> 정규화는 가중치가 커지는 데 벌점을 매겨 과적합을 억제하며, 효과는 대체로 모델이 헷갈려하던 소수·경계 클래스에서 먼저 나타난다.

## 4. 수동 튜닝의 한계와 자동 탐색

### 1) 정의

하이퍼파라미터 탐색을 자동화하려면 세 가지만 정의하면 됩니다.

| 구성 요소 | 뜻 | 이번 사례 |
|---|---|---|
| 목적함수(objective) | 조합 하나를 받아 "이 조합이 얼마나 좋은지" 점수를 돌려주는 함수 | 5-Fold 교차검증 weighted F1의 평균 |
| 탐색공간(search space) | 각 파라미터가 가질 수 있는 후보의 범위 | learning_rate ∈ {0.1, 0.3}, max_depth ∈ {6, 8} |
| 시행 횟수(n_trials) | 몇 개의 조합을 실제로 실험할 것인가 | 4회 (2 × 2 = 전체 조합 수) |

이 셋을 정의해 두면 탐색 도구가 조합을 골라 목적함수에 넣고, 점수를 보며 다음 조합을 고르는 일을 반복합니다.

### 2) 왜 필요한가

앞선 모델 비교에서 랜덤포레스트의 깊이를 10에서 12로 바꿨더니 weighted F1이 0.67에서 0.74로 올랐습니다. 값 하나만 손봐도 이만큼 달라지는데, 실제로는 나무 개수·깊이·학습률·정규화 계수가 동시에 얽혀 있습니다. 파라미터 4개에 후보가 3개씩만 있어도 81가지 조합이고, 각 조합을 5-Fold로 평가하면 405번 학습해야 합니다. 게다가 손으로 실험하면 어떤 조합을 이미 시도했는지, 왜 그 값을 골랐는지가 머릿속에만 남아 재현이 어렵습니다. 목적함수와 탐색공간을 코드로 적어 두면 그 자체가 실험 기록이 됩니다.

### 3) 핵심 흐름 재구성

실제 탐색은 두 단계로 진행했습니다.

**연습 단계.** 다른 값은 모두 고정하고 학습률만 {0.1, 0.3} 중에서 고르게 해 2회 시행했습니다. 결과 점수는 0.5654였는데, 낮은 이유는 학습률 때문이 아니라 `max_depth`를 2로 묶어 뒀기 때문입니다. **탐색 밖에 있는 고정값이 성능의 천장을 정한다**는 점을 보여 주는 사례입니다. 또 후보가 2개이고 시행도 2회였는데 **두 번 모두 같은 값(0.1)을 뽑아 결국 비교가 이뤄지지 않았습니다.** 무작위 샘플링 기반 탐색은 이미 시도한 조합을 다시 제안할 수 있어서, 시행 횟수를 조합 수에 맞춰 둔다고 모든 조합을 훑는다는 보장은 없습니다.

**본 탐색.** 학습률 {0.1, 0.3}과 최대 깊이 {6, 8}을 함께 탐색하며 4회 시행했습니다.

```text
Trial 0: learning_rate=0.3, max_depth=6  → CV weighted F1 0.9022
Trial 1: learning_rate=0.3, max_depth=6  → CV weighted F1 0.9022  (중복)
Trial 2: learning_rate=0.3, max_depth=6  → CV weighted F1 0.9022  (중복)
Trial 3: learning_rate=0.3, max_depth=8  → CV weighted F1 0.9335  ← 최고

Best: learning_rate=0.3, max_depth=8, score=0.9335
```

4번 중 3번이 같은 조합이었고 마지막 한 번에서 최고 조합을 찾았습니다. 깊이가 6에서 8로 바뀐 것만으로 교차검증 점수가 0.9022에서 0.9335로 올랐는데, 앞선 글에서 "고차원 데이터에서는 깊이가 성능을 크게 좌우한다"고 관찰한 내용과 정확히 이어집니다.

**최종 적용.** 찾은 조합으로 전체 학습 데이터를 다시 학습해 테스트셋에서 평가했습니다.

| 단계 | 설정 | 테스트 Weighted F1 |
|---|---|---|
| 초기 부스팅 | n=50, lr=0.1, depth=8 | 0.80 |
| 정규화 조정 | n=50, lr=0.3, depth=6, L1=1, L2=1 | 0.85 |
| 자동 탐색 결과 | n=100, lr=0.3, depth=8, L2=1 | **0.9317** |

### 4) 쉬운 예시

카페에서 커피 레시피를 정한다고 해 봅시다. 원두 양, 물 온도, 추출 시간을 바꿀 수 있는데, 혼자 한 잔씩 내려 마시며 기억에 의존해 조정하는 것이 수동 튜닝입니다. 반면 "맛 점수를 매기는 방법(목적함수)", "각 항목의 허용 범위(탐색공간)", "몇 잔까지 시험할지(시행 횟수)"를 정해 두면 실험이 체계적으로 돌아가고 기록도 남습니다. 한 잔이 아니라 다섯 명에게 맛보여 평균을 내면(교차검증) 그날 입맛에도 흔들리지 않습니다.

### 5) 코드 예시

```python
import optuna

def objective(trial):
    params = {
        # 탐색공간
        'learning_rate': trial.suggest_categorical('learning_rate', [0.1, 0.3]),
        'max_depth':     trial.suggest_categorical('max_depth', [6, 8]),
        # 고정값 (탐색하지 않음)
        'n_estimators': 100, 'reg_lambda': 1, 'random_state': 42, 'n_jobs': -1,
    }
    cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
    scores = cross_val_score(XGBClassifier(**params), X_train, y_train, cv=cv,
                             scoring=make_scorer(f1_score, average='weighted'))
    return scores.mean()          # 이 값을 최대화

study = optuna.create_study(direction='maximize')
study.optimize(objective, n_trials=4)

# 찾은 조합으로 전체 학습 데이터를 다시 학습해 최종 모델을 만든다
final_model = XGBClassifier(**study.best_params, n_estimators=100,
                            reg_lambda=1, random_state=42, n_jobs=-1)
final_model.fit(X_train, y_train)
```

`suggest_categorical(name, [후보들])`은 목록에서 고르고, `suggest_int(name, low, high)`나 `suggest_float(name, low, high)`는 범위 안의 값을 고릅니다. `direction='maximize'`는 목적함수 반환값이 클수록 좋다는 뜻으로, F1처럼 높을수록 좋은 지표에 씁니다. 오차처럼 작을수록 좋은 값을 반환한다면 `'minimize'`로 바꿉니다.

### 6) 헷갈리는 점

탐색공간을 넓게 잡을수록 좋다고 생각하기 쉽지만, 조합 수가 늘어난 만큼 시행 횟수도 늘려야 하고 각 시행은 5번의 학습을 포함합니다. 실제로 이번 4회 탐색에도 조합당 2~3분씩 걸렸습니다. 처음에는 후보를 2~3개로 좁혀 감을 잡고, 좋아 보이는 구간 근처를 다시 촘촘히 탐색하는 방식이 효율적입니다. 또 하나, 탐색 대상이 아닌 고정값이 성능을 크게 좌우할 수 있다는 점을 잊으면 안 됩니다. 연습 단계에서 깊이를 2로 묶어 둔 탓에 아무리 학습률을 바꿔도 0.57 언저리를 벗어날 수 없었던 것이 그 예입니다.

### 7) 한 줄 정리

> 목적함수·탐색공간·시행 횟수 세 가지만 정의하면 튜닝을 자동화할 수 있고, 그 결과는 교차검증 위에서 골라야 신뢰할 수 있다.

## 코드로 보기 — 튜닝 전후 성능 비교

```python
settings = {
    'base':  dict(n_estimators=50,  learning_rate=0.1, max_depth=8),
    'tuned': dict(n_estimators=100, learning_rate=0.3, max_depth=8, reg_lambda=1),
}
for name, kw in settings.items():
    m = XGBClassifier(**kw, random_state=42, n_jobs=-1).fit(X_train, y_train)
    rep = classification_report(y_test, m.predict(X_test), output_dict=True)
    print(f'{name:6s} weighted F1 = {rep["weighted avg"]["f1-score"]:.4f}')
```

```text
base   weighted F1 = 0.80
tuned  weighted F1 = 0.9317
교차검증 평균 점수 = 0.9335
```

### 코드 목적

같은 데이터·같은 모델 종류에서 하이퍼파라미터만 바꿨을 때 성능이 얼마나 달라지는지를 하나의 숫자로 확인합니다.

### 코드 흐름

1. 튜닝 전 설정과 자동 탐색이 찾아 준 설정을 각각 학습한다.
2. 같은 테스트셋에서 두 모델의 weighted F1을 비교한다.
3. 교차검증 점수와 테스트 점수의 차이를 확인해 탐색이 과적합됐는지 점검한다.

### 실행 결과 해석

**weighted F1이 0.80에서 0.9317로 올랐습니다.** 모델 종류를 바꾼 것도, 피처를 새로 만든 것도 아니고 학습률·깊이·나무 개수·정규화 계수만 조정한 결과입니다. 전체 흐름을 놓고 보면 단일 트리 0.55 → 랜덤포레스트 0.67 → 부스팅 0.80 → 튜닝 후 0.93으로, **튜닝 단계가 모델 종류를 바꿔 얻은 개선폭(0.55 → 0.80)에 맞먹는 기여를 했습니다.**

또 하나 중요한 확인 포인트는 **교차검증 평균 0.9335와 테스트 점수 0.9317의 차이가 0.002에 불과하다**는 점입니다. 두 값이 크게 벌어졌다면 탐색이 검증 데이터에 과하게 맞춰졌다는 신호였을 텐데, 거의 일치하므로 새 데이터에서도 비슷한 성능을 기대할 수 있습니다.

### 실무 연결

모델을 서비스에 올리기 전 성능을 짜내야 하는 상황에서 가장 비용 대비 효과가 좋은 단계가 하이퍼파라미터 튜닝입니다. 데이터를 새로 모으거나 피처를 새로 설계하는 것보다 훨씬 빠르고, 코드로 남아 재현도 됩니다. 다만 튜닝은 이미 있는 정보를 최대한 활용하는 작업이라 한계가 있습니다. 0.93에서 더 올리려면 겹쳐 있는 유형을 갈라 줄 새로운 피처를 찾는 쪽으로 넘어가야 합니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 단일 검증셋 vs K-Fold | 한 번 잘라 한 번 평가하면 단일 검증셋, K번 돌려 평균 내면 K-Fold |
| KFold vs StratifiedKFold | 무작위로 나누면 KFold, 클래스 비율을 유지하며 나누면 StratifiedKFold |
| L1 vs L2 | 절대값 벌점으로 일부를 0으로 만들면 L1, 제곱 벌점으로 전체를 고르게 줄이면 L2 |
| 하이퍼파라미터 vs 파라미터 | 사람이 학습 전에 정하는 값이 하이퍼파라미터, 학습으로 배우는 값이 파라미터 |
| 교차검증 점수 vs 테스트 점수 | 튜닝에 사용한 점수가 교차검증 점수, 한 번도 쓰지 않은 데이터로 잰 값이 테스트 점수 |
| 탐색공간 vs 고정값 | 도구가 바꿔 가며 시험하는 값이 탐색공간, 그대로 두는 값이 고정값(성능 천장을 결정) |
