# 여행 지출 데이터 EDA와 전처리 — 흩어진 표를 하나의 학습 데이터로

> 원본은 여행, 여행객, 소비 내역이 따로 놀고 있는 일곱 개의 표였습니다. 여기서 학습 가능한 2,128행짜리 데이터 한 장을 만들기까지, 어떤 판단을 내렸는지 정리합니다.

`EDA` · `다중 라벨 인코딩` · `결측치 대체` · `IQR 이상치` · `테이블 병합`

## 핵심요약

- EDA는 그래프를 예쁘게 그리는 일이 아니라, 전처리 방법을 결정하기 위한 근거 수집이다.
- 한 칸에 여러 라벨이 들어 있는 컬럼은 다중 라벨 이진 인코딩으로 라벨마다 별도 열을 만든다.
- 결측치는 무조건 지우지 않는다. 수치형은 평균 대체, 정보가 거의 없는 열은 삭제가 낫다.
- 지출 데이터는 이상치가 극심해 IQR 기준으로 걸러야 박스플롯이 읽히는 수준이 된다.
- 병합은 키만 맞추면 되는 게 아니라 "1행이 무엇인가"를 통일하는 작업이다.

## 1. EDA — 전처리 방법을 정하기 위한 관찰

### 1) 정의

탐색적 데이터 분석(EDA, Exploratory Data Analysis)은 모델을 만들기 전에 데이터의 구조·분포·결측·이상치를 눈으로 확인하는 단계입니다. 목적은 "이 데이터를 어떻게 손봐야 모델에 넣을 수 있는가"에 대한 답을 얻는 것입니다.

### 2) 왜 필요한가

전처리 코드는 전부 판단의 결과물입니다. 결측을 평균으로 채울지 행을 지울지, 이상치를 자를지 둘지, 어떤 컬럼을 버릴지는 데이터를 보지 않고서는 정할 수 없습니다. EDA를 건너뛰면 전처리가 "관행대로"가 되고, 그 관행이 이 데이터에 맞을 보장은 없습니다.

### 3) 핵심 흐름 재구성

여행로그 데이터는 AI Hub의 국내 여행로그 데이터(수도권)를 사용했고, 일곱 갈래로 나뉘어 있습니다.

```text
코드 표        각 숫자 라벨이 무엇을 뜻하는지 알려주는 사전
여행 표        여행 1건 = 1행 (목적, 미션, 시작일, 종료일)
여행객 표      여행객 1명 = 1행 (성별·연령·학력·소득·여행 스타일 8종·동기)
소비 내역 4종  결제 1건 = 1행 (이동 / 활동 / 숙박 / 사전 소비)
```

EDA에서 확인한 주요 분포는 이렇습니다. 여행 목적·미션은 SNS 인생샷 여행과 쇼핑이 최상위이고 두 컬럼의 순위가 거의 일치하며, 여행 기간은 2~4일이 대부분입니다. 여행객은 여성이 남성보다 많고 연령대는 20~30대에 몰려 있으며, 학력은 4년제 대학, 가족 구성원 수는 1~4명이 최다입니다. 개인 소득은 월 200~300만원 구간, 가구 소득은 월 400~600만원 구간에 가장 많이 분포하고, 여행 빈도는 한 달 또는 1년 주기, 동반자 수는 0~3명에 집중돼 있습니다. 이 관찰들이 곧바로 전처리 방침으로 이어집니다. 목적·미션이 여러 라벨을 한 칸에 담고 있으니 이진 인코딩이 필요하고, 여행 기간은 시작일과 종료일에서 파생시켜야 하며, 소득처럼 이미 구간 번호인 컬럼은 그대로 수치로 쓸 수 있습니다.

### 4) 쉬운 예시

이사를 앞두고 짐을 정리하는 상황과 비슷합니다. 상자를 열어 보지 않고 "다 버리자"고 정하면 후회합니다. 하나씩 열어 보고 "이건 부피만 크고 안 쓰니 버린다", "이건 깨지기 쉬우니 따로 싼다"고 정하는 과정이 EDA입니다.

### 5) 코드 예시

지출 금액 네 종류를 비교하는 박스플롯이 이 프로젝트 EDA의 핵심 장면이었습니다.

```python

plt.boxplot(payments, tick_labels=['활동', '이동', '숙박', '사전소비'], showmeans=True)
```

이상치 때문에 박스가 바닥에 눌려 보이지 않을 정도였고, IQR로 걸러 낸 뒤에야 분포가 읽혔습니다. 그렇게 보니 **숙박비의 평균이 가장 높고, 적게 쓰는 사람과 많이 쓰는 사람의 격차도 숙박에서 가장 컸습니다.**

### 6) 헷갈리는 점

박스플롯의 점들을 보고 "이상치니까 전부 지워야 한다"고 결론 내리기 쉽지만, 여기서의 이상치는 대부분 실제로 돈을 많이 쓴 사람이지 오류가 아닙니다. 지우는 이유는 "틀린 값이라서"가 아니라 "소수의 극단값이 모델 학습을 지배하는 것을 막기 위해서"입니다.

### 7) 한 줄 정리

> EDA는 데이터를 구경하는 단계가 아니라, 뒤이을 전처리의 모든 판단에 근거를 대는 단계다.

## 2. 인코딩 — 한 칸에 여러 라벨이 들어 있을 때

### 1) 정의

인코딩은 문자나 코드로 된 값을 모델이 계산할 수 있는 숫자로 바꾸는 일입니다. 여기서는 두 가지를 썼습니다. 성별처럼 값이 하나뿐인 범주는 라벨 인코딩, 여행 목적처럼 한 칸에 여러 값이 들어 있는 범주는 다중 라벨 이진 인코딩입니다.

### 2) 왜 필요한가

여행 목적 컬럼은 `1;11;2;22;`처럼 세미콜론으로 이어 붙인 문자열입니다. 이 상태로는 숫자도 범주도 아니어서 어떤 모델에도 들어가지 않습니다. 게다가 이 문자열을 통째로 하나의 범주로 취급하면, 목적이 조금만 달라도 완전히 다른 값으로 인식되어 학습이 불가능해집니다.

### 3) 핵심 흐름 재구성

다중 라벨 이진 인코딩은 라벨마다 열을 만들고 포함 여부를 0/1로 표시하는 방식입니다.

| 원본 | 목적_1 | 목적_2 | ... | 목적_22 |
|---|---|---|---|---|
| `1;2;22;` | 1 | 1 | ... | 1 |
| `5;22;24;` | 0 | 0 | ... | 1 |

여행 목적과 여행 미션은 각각 28개 라벨이 있어 28개씩 총 56개 열이 생기고, 여행 동기는 10개 라벨이라 10개 열이 생깁니다. 여기에 여행 스타일 8종, 인적사항, 여행 기간을 더해 최종 독립변수가 **84개**가 됩니다.

여행 기간은 원본에 없는 파생변수로, 시작일과 종료일의 차이에 1을 더해 만들었습니다. 당일치기가 0일이 아니라 1일이 되도록 하기 위한 +1입니다.

### 4) 쉬운 예시

설문지에서 "관심 분야를 모두 고르세요"에 여행·요리·독서를 체크한 응답을 생각해 봅시다. 이걸 "여행요리독서"라는 하나의 답변으로 저장하면, 여행·요리만 고른 사람과 아무 관계도 없는 별개 그룹이 됩니다. 대신 분야마다 칸을 만들어 체크 여부를 표시하면, 두 사람이 여행과 요리에서 겹친다는 사실이 그대로 살아납니다.

### 5) 코드 예시

```python
def binary_labeling(df, column, prefix, label_range=28):   # 다중 라벨 → 라벨별 0/1 열
    label_sets = df[column].str.strip(';').str.split(';').apply(set)
    for i in range(1, label_range + 1):
        df[f'{prefix}_{i}'] = label_sets.apply(lambda s: 1 if str(i) in s else 0)
    return df

travel_df = binary_labeling(travel_df, 'TRAVEL_PURPOSE', 'TRAVEL_PURPOSE')

# 파생변수: 여행 기간(일)
travel_df['TRAVEL_DURATION_DAYS'] = (
    pd.to_datetime(travel_df['TRAVEL_END_YMD'])
    - pd.to_datetime(travel_df['TRAVEL_START_YMD'])
).dt.days + 1
```

`set`으로 바꾸는 이유는 포함 여부만 알면 되기 때문입니다. 리스트로 두고 매번 순회하는 것보다 조회가 빠릅니다.

### 6) 헷갈리는 점

라벨 인코딩과 이진 인코딩을 혼동하기 쉽습니다. 성별처럼 값이 하나만 오는 컬럼은 라벨 인코딩(남/여 → 0/1)으로 충분하지만, 여러 값이 동시에 올 수 있는 컬럼에 라벨 인코딩을 쓰면 "목적 조합"이라는 무의미한 범주가 수백 개 생깁니다. 값이 배타적인지 아닌지가 판단 기준입니다.

### 7) 한 줄 정리

> 한 칸에 여러 값이 들어 있는 컬럼은 값마다 열을 만들어 0/1로 펼쳐야 정보가 살아난다.

## 3. 결측치·이상치·병합 — 행의 단위를 맞추는 일

### 1) 정의

결측치 처리는 비어 있는 값을 채우거나 제거하는 작업, 이상치 처리는 분포에서 크게 벗어난 값을 다루는 작업, 병합은 흩어진 표를 공통 키로 이어 붙이는 작업입니다. 세 가지는 따로 배우지만 실제로는 한 흐름 안에서 서로 얽혀 있습니다.

### 2) 왜 필요한가

모델은 빈칸을 만나면 학습을 멈춥니다. 그렇다고 결측이 있는 행을 전부 지우면 표본이 급격히 줄어듭니다. 이상치는 학습을 멈추지는 않지만, 제곱 오차를 쓰는 회귀에서 소수의 극단값이 계수를 통째로 끌고 갑니다. 병합은 아예 하지 않으면 독립변수와 종속변수가 만나지 못합니다.

### 3) 핵심 흐름 재구성

이 프로젝트에서 내린 판단은 다음과 같습니다.

| 상황 | 선택 | 이유 |
|---|---|---|
| 가구 소득 결측 | 평균값 대체 | 수치형이고 표본을 잃고 싶지 않음 |
| 지역·선호지 등 다수 컬럼 | 컬럼 삭제 | 예측에 쓰지 않기로 한 정보 |
| 나머지 결측 행 | 행 삭제 | 대체 근거가 약하고 소수 |
| 총 지출 0원 · 극단값 | 행 제거 · IQR 기준 제거 | 종속변수로 부적합하거나 학습을 지배함 |

IQR 기준은 사분위 범위를 이용해 정상 범위를 정하는 방법입니다.

$$
\text{IQR} = Q_3 - Q_1, \quad
[\,Q_1 - 1.5 \times \text{IQR},\ \ Q_3 + 1.5 \times \text{IQR}\,]
$$

이 식은 "데이터를 크기순으로 줄 세워 가운데 절반이 차지하는 폭(IQR)을 재고, 그 폭의 1.5배만큼 양옆으로 늘린 구간을 정상으로 본다"는 뜻입니다.

병합은 두 단계입니다. 독립변수 쪽은 여행 표와 여행객 표를 여행객 ID로 이어 붙이고, 종속변수 쪽은 소비 내역 네 종류를 여행 ID로 붙인 뒤 합산합니다. 그다음이 중요한 지점인데, 여행객 ID로 다시 묶어 총합을 내고 중복 행을 제거합니다. 이 과정을 거쳐야 비로소 **1행 = 여행객 1명**이라는 단위가 확정됩니다.

### 4) 쉬운 예시

가계부를 정리한다고 해봅시다. 영수증(결제 1건)이 수백 장 있고, 가족 구성원 명단(사람 1명)이 따로 있습니다. "사람별 한 달 지출"을 알고 싶다면 영수증을 사람에게 붙이고 사람 단위로 합계를 내야 합니다. 영수증 단위 그대로 두면 한 사람이 여러 행에 흩어져 있어 "사람별"이 되지 않습니다.

### 5) 코드 예시

```python
# 1) 독립변수 병합: 여행 + 여행객
merged = pd.merge(travel_df, traveler_df, on='TRAVELER_ID', how='inner')
# 2) 종속변수 병합: 소비 내역 4종을 여행 ID로 붙이고 합산
for part in [activity_df, move_df, lodge_df, pre_expense_df]:
    merged = pd.merge(merged, part, on='TRAVEL_ID', how='left')
won_cols = [c for c in merged.columns if c.endswith('WON')]
merged['WON_SUM'] = merged[won_cols].sum(axis=1)
# 3) 행의 단위를 '여행객 1명'으로 통일
merged['WON_SUM'] = merged.groupby('TRAVELER_ID')['WON_SUM'].transform('sum')
merged = merged.drop_duplicates(subset='TRAVELER_ID').drop(columns=won_cols + ['TRAVEL_ID'])
# 4) 종속변수 이상치 정리
merged = merged[merged['WON_SUM'] > 0]
Q1, Q3 = merged['WON_SUM'].quantile([0.25, 0.75])
IQR = Q3 - Q1
merged = merged[(merged['WON_SUM'] >= Q1 - 1.5*IQR) & (merged['WON_SUM'] <= Q3 + 1.5*IQR)]
```

`how='left'`는 소비 기록이 없는 여행도 일단 남겨 두기 위한 선택이며, 합산 후 0원이 되는 행은 다음 단계에서 걸러집니다.

### 6) 헷갈리는 점

`transform('sum')`과 `groupby().sum()`을 헷갈리기 쉽습니다. 후자는 그룹당 한 행으로 줄어든 새 표를 만들지만, 전자는 원래 행 수를 유지한 채 각 행에 그룹 합계를 채워 넣습니다. 여기서는 다른 컬럼을 그대로 들고 있어야 했기 때문에 `transform`을 쓰고 중복만 따로 제거했습니다.

### 7) 한 줄 정리

> 병합은 키를 맞추는 작업이 아니라 "1행이 무엇을 의미하는가"를 통일하는 작업이다.

### 실행 결과 해석

**최종 데이터는 2,128행 × 86열**입니다. 여행객 ID 1개와 종속변수 1개를 빼면 독립변수는 84개입니다. `object` 1개(ID)를 빼고 전부 숫자라는 점, 모든 컬럼의 비결측 개수가 2,128로 동일하다는 점에서 인코딩과 결측 처리가 정상적으로 끝났음을 알 수 있습니다.

종속변수 분포는 **평균 347,067원인데 중앙값은 160,100원**입니다. 평균이 중앙값의 두 배가 넘는다는 것은 오른쪽으로 길게 늘어진 분포, 즉 소수의 고지출 여행객이 평균을 끌어올리고 있다는 뜻입니다. **표준편차 422,537원은 평균보다도 큰데**, 사람마다 지출 편차가 극심하다는 신호입니다. IQR로 한 번 걸러 낸 뒤에도 최소 600원부터 최대 1,859,750원까지 3,000배 넘게 벌어져 있습니다. 종속변수 자체의 산포가 이렇게 크면 뒤이을 회귀에서 RMSE가 수십만 원대로 나오는 것이 자연스럽고, 중앙값 160,100원은 곧 분류 문제의 기준선이 됩니다.

### 실무 연결

실무에서는 이 점검 결과를 리포트 첫 장에 씁니다. "표본 2,128건, 변수 84개, 종속변수 평균 34.7만원·중앙값 16.0만원, 우편향 분포"라는 한 문장이면 모델 성능에 대한 기대치가 팀 전체에서 조정됩니다. 종속변수가 심하게 치우쳐 있으면 로그 변환을 검토하거나, 금액 대신 등급으로 문제를 바꾸는 결정을 이 단계에서 내립니다.

## 직접 해보기

1. 한 칸에 `A;C;D;`처럼 여러 라벨이 들어 있는 컬럼이 있습니다. 라벨이 총 5종(A~E)이라면 인코딩 후 몇 개의 열이 생기고, 이 행의 값은 어떻게 되나요?
2. 어떤 컬럼의 사분위수가 $Q_1 = 100$, $Q_3 = 300$일 때 IQR 기준 정상 범위를 계산하고, 값 650은 이상치인지 판정하세요.
3. 결제 내역 표(1행=결제 1건)와 회원 표(1행=회원 1명)를 합쳐 "회원별 총 결제액"을 만들려고 합니다. 어떤 순서로 병합·집계해야 하나요?

<details>
<summary>정답 보기</summary>

1. 라벨마다 열을 만들므로 5개 열(A~E)이 생깁니다. 해당 행은 A=1, B=0, C=1, D=1, E=0이 됩니다. 라벨 종류가 늘어나면 열도 그만큼 늘어나므로, 라벨이 아주 많은 컬럼은 차원이 급격히 커진다는 점을 함께 고려해야 합니다.
2. IQR = 300 − 100 = 200입니다. 정상 범위는 $[100 - 1.5 \times 200,\ 300 + 1.5 \times 200] = [-200,\ 600]$이므로 650은 상한 600을 넘어 이상치로 판정됩니다. 다만 이상치라는 판정이 곧 "잘못된 값"을 뜻하지는 않으므로, 제거할지 남길지는 도메인 판단이 필요합니다.
3. 먼저 결제 내역을 회원 ID 기준으로 회원 표에 붙입니다(`how='left'`). 그다음 회원 ID로 그룹화해 결제액을 합산하고, 회원당 한 행만 남도록 중복을 제거합니다. 병합 전에 미리 집계해도 결과는 같지만, 이 순서로 하면 결제 기록이 없는 회원도 0원으로 남길 수 있습니다.

</details>

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 라벨 인코딩 vs 다중 라벨 이진 인코딩 | 값이 하나만 오면 라벨 인코딩, 여러 값이 동시에 오면 라벨별 0/1 열로 펼침 |
| 결측 삭제 vs 평균 대체 | 표본이 아깝고 수치형이면 대체, 대체 근거가 약하고 소수면 삭제 |
| `merge` vs `concat` | 공통 키로 옆으로 붙이면 merge, 같은 구조를 위아래로 이으면 concat |
| `groupby().sum()` vs `transform('sum')` | 전자는 그룹당 1행으로 축소, 후자는 행 수를 유지하며 그룹 합계를 채움 |
| 이상치 vs 오류값 | 분포에서 벗어난 값이 이상치, 측정·입력이 잘못된 값이 오류값 |

### 복습 질문 및 답변

**Q1. 여행 목적 컬럼을 라벨 인코딩이 아니라 다중 라벨 이진 인코딩으로 처리한 이유는 무엇인가요?**

<details>
<summary>답</summary>

한 여행이 여러 목적을 동시에 가질 수 있기 때문입니다. `1;2;22;`를 하나의 범주로 라벨 인코딩하면 목적 조합마다 새로운 범주가 생겨 수백 개의 의미 없는 값이 만들어지고, 목적 두 개가 겹치는 여행끼리의 유사성도 사라집니다. 라벨마다 열을 만들면 겹치는 부분이 그대로 드러납니다.

</details>

**Q2. 최종 데이터의 평균 지출이 중앙값의 두 배가 넘는다는 사실에서 무엇을 알 수 있나요?**

<details>
<summary>답</summary>

분포가 오른쪽으로 길게 늘어져 있다는 뜻입니다. 평균 347,067원, 중앙값 160,100원이라는 것은 대부분의 사람은 중앙값 근처에 몰려 있는데 소수의 고지출 여행객이 평균을 위로 끌어올리고 있다는 신호입니다. 이런 분포에서는 평균보다 중앙값이 대표값으로 더 적절하고, 회귀 성능도 낮게 나오기 쉽습니다.

</details>

**Q3. 소비 내역을 여행 ID로 붙인 뒤 다시 여행객 ID로 합산한 이유는 무엇인가요?**

<details>
<summary>답</summary>

문제 정의에서 예측 단위를 "여행객 1명"으로 정했기 때문입니다. 소비 내역은 결제 1건이 한 행, 여행 표는 여행 1건이 한 행이므로, 그대로 두면 한 사람이 여러 행에 흩어집니다. 여행 ID로 붙여 여행별 지출을 만들고, 다시 여행객 ID로 합산해 중복을 제거해야 1행 = 1명이 됩니다.

</details>
