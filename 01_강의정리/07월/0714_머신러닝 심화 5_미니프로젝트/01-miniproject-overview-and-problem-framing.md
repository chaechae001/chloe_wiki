# 미니프로젝트 문제 정의 — 실무 질문을 머신러닝 문제로 번역하기

> "여행 경비를 미리 알 수 있을까?", "이 민원은 어느 부서로 가야 할까?", "이 소리는 누수일까?" 세 질문은 전혀 다르게 들리지만, 머신러닝으로 옮기는 절차는 똑같습니다. 이 글은 그 번역 절차를 정리합니다.

`문제 정의` · `회귀와 분류` · `평가지표 선택` · `데이터 유형` · `종속변수 설계`

## 핵심요약

- 머신러닝 프로젝트의 첫 단계는 모델 선택이 아니라 "무엇을 예측할 것인가(종속변수)"를 정하는 일이다.
- 종속변수가 연속된 숫자면 회귀, 정해진 범주면 분류다. 같은 데이터로 둘 다 만들 수도 있다.
- 문제 유형이 정해지면 평가지표가 따라온다. 회귀는 RMSE·MAPE·R², 분류는 F1·재현율 계열이다.
- 데이터의 형태(정형 표 / 텍스트 / 센서 신호)에 따라 전처리 방식이 완전히 달라진다.
- 세 프로젝트 모두 공개 데이터를 쓰지만, "원본 그대로는 모델에 넣을 수 없다"는 점은 동일하다.

## 1. 실무 질문을 머신러닝 문제로 번역하기

### 1) 정의

문제 정의(Problem Framing)는 사람의 말로 된 질문을 모델이 계산할 수 있는 형태로 바꾸는 작업입니다. 구체적으로는 세 가지를 정하는 일입니다. 무엇을 맞힐 것인가(종속변수 $y$), 무엇을 보고 맞힐 것인가(독립변수 $X$), 잘 맞혔는지 어떻게 판단할 것인가(평가지표).

### 2) 왜 필요한가

모델은 스스로 목표를 정하지 못합니다. "여행 경비를 알고 싶다"는 말만으로는 학습을 시작할 수 없고, "이동·활동·숙박·사전 소비를 모두 더한 금액(원)을 예측한다"까지 내려와야 비로소 코드가 됩니다. 이 번역이 어긋나면 아무리 좋은 알고리즘을 써도 엉뚱한 답을 잘 맞히는 모델이 됩니다.

또 하나, 문제 정의는 전처리 범위를 결정합니다. 종속변수가 "여행 1건당 지출"인지 "여행객 1명당 누적 지출"인지에 따라 데이터를 묶는 단위(행의 의미)가 달라지고, 그에 따라 병합·집계 방식이 통째로 바뀝니다.

### 3) 핵심 흐름 재구성

세 프로젝트에 공통으로 적용되는 번역 절차는 다음 순서입니다.

```text
① 실무 질문 확인      "여행 경비를 예측할 수 있을까?"
② 종속변수 확정        y = 이동+활동+숙박+사전 소비 총액(원)
③ 행의 단위 확정       1행 = 여행객 1명
④ 독립변수 후보 선정    여행 목적/기간 + 여행객 인적사항·스타일
⑤ 문제 유형 판정       y가 연속값 → 회귀
⑥ 평가지표 선택        RMSE·MAPE·R²(+Adjusted R²)
⑦ 전처리 계획 수립     인코딩·결측 처리·이상치 처리·병합
```

여기서 ③번이 초보자가 가장 많이 건너뛰는 단계입니다. 여행 데이터는 원래 "여행 1건"이 한 행이고, 소비 내역은 "결제 1건"이 한 행입니다. 여행객 단위로 예측하기로 했다면, 결제 내역을 여행 ID로 붙인 뒤 다시 여행객 ID로 합산해야 행의 의미가 일치합니다.

### 4) 쉬운 예시

카페 사장님이 "매출을 예측하고 싶다"고 말했다고 해봅시다. 이 말만으로는 부족합니다. 일 매출인지 월 매출인지, 지점 단위인지 전체인지, 원 단위 금액인지 "잘 팔림/보통/안 팔림" 세 등급인지 정해야 합니다. 일 단위 금액이면 회귀, 세 등급이면 분류입니다. 같은 문장에서 완전히 다른 두 모델이 나옵니다.

### 5) 코드 예시

문제 정의가 코드로 내려오면 결국 이 네 줄로 압축됩니다.

```python
# ① 종속변수: 무엇을 맞힐 것인가
y = df['WON_SUM']                     # 여행객 1명의 총 지출액(원) → 연속값 → 회귀

# ② 독립변수: 무엇을 보고 맞힐 것인가 (식별자와 정답은 반드시 제외)
X = df.drop(columns=['TRAVELER_ID', 'WON_SUM'])

# ③ 평가지표: 잘 맞혔는지 어떻게 잴 것인가
from sklearn.metrics import mean_squared_error, mean_absolute_percentage_error, r2_score
```

`drop`에서 식별자 컬럼을 빼는 이유가 중요합니다. 여행객 ID는 정답과 아무 인과관계가 없는 번호일 뿐인데, 모델은 그 번호를 외워서 훈련 데이터만 맞히려 들 수 있습니다.

### 6) 헷갈리는 점

"데이터가 있으니 일단 모델을 돌려 보자"가 가장 흔한 함정입니다. 종속변수를 어떻게 만들지 정하지 않은 채 시작하면, 전처리를 다 끝낸 뒤에 다시 앞으로 돌아가야 합니다. 반대로 문제 정의가 끝나면 그 다음 단계는 대부분 기계적으로 이어집니다.

### 7) 한 줄 정리

> 문제 정의는 "무엇을 · 무엇으로 · 어떻게 평가할지"를 정하는 일이며, 이 세 가지가 정해져야 비로소 코드가 시작된다.

## 2. 회귀인가 분류인가 — 그리고 그 경계

### 1) 정의

회귀(Regression)는 종속변수가 연속된 숫자일 때, 분류(Classification)는 종속변수가 정해진 범주일 때 쓰는 방식입니다. 예측값의 성격이 다르므로 손실 함수도, 평가지표도 다릅니다.

### 2) 왜 필요한가

문제 유형을 잘못 잡으면 평가 자체가 성립하지 않습니다. 범주를 예측하는 모델에 RMSE를 들이대면 "정답 3번을 2.7로 맞혔다"는 무의미한 숫자가 나오고, 금액을 예측하는 모델에 정확도(accuracy)를 들이대면 "정확히 일치한 비율 0%"라는 쓸모없는 결과가 나옵니다.

### 3) 핵심 흐름 재구성

세 미니프로젝트를 이 기준으로 나란히 놓으면 차이가 선명해집니다.

| 구분 | 여행 지출 예측 | 민원 유형 분류 | 누수 유형 감지 |
|---|---|---|---|
| 데이터 형태 | 정형 표(여러 테이블) | 한국어 문장 | 고차원 센서 신호 |
| 종속변수 | 총 지출 금액(원) | 민원 유형 17종 | 누수 유형 5종 |
| 문제 유형 | 회귀 | 다중 분류 | 다중 분류 |
| 규모 | 2,128행 × 84개 변수 | 32,744문장 → 11,143차원 | 62,564행 × 533개 변수 |
| 주 평가지표 | RMSE · MAPE · R²/Adjusted R² | weighted F1 | weighted F1 |
| 최대 난점 | 변수 수 과다 · 이상치 | 클래스 불균형 · 어휘 다양성 | 차원 과다 · 클래스별 난이도 차 |

같은 "분류"라도 민원과 누수는 성격이 다릅니다. 민원은 17개 클래스가 비슷한 규모로 나뉘어 있고 어휘가 겹쳐서 헷갈리는 반면, 누수는 5개 클래스 중 정상음처럼 아주 쉬운 클래스와 환경음처럼 아주 어려운 클래스가 섞여 있습니다. 그래서 둘 다 클래스별 지표를 따로 봐야 합니다.

### 4) 쉬운 예시

병원 검사에 비유하면, 회귀는 "혈압 수치가 몇일까"를 맞히는 일이고 분류는 "고혈압인가 아닌가"를 판정하는 일입니다. 혈압 수치를 알면 기준선을 그어 판정으로 바꿀 수 있지만, 판정만 알아서는 수치를 되돌릴 수 없습니다. 회귀 → 분류 방향은 가능하고 그 반대는 불가능하다는 점이 중요합니다.

### 5) 코드 예시

연속값 종속변수를 기준선으로 잘라 범주형으로 바꾸는 코드는 이렇게 짧습니다.

```python
# 중앙값을 기준선으로 삼아 이진 라벨 생성
threshold = df['WON_SUM'].quantile(0.5)     # 160,100원
df['WON_CLASS'] = (df['WON_SUM'] > threshold).astype(int)   # 0=하위 지출, 1=고지출

print(df['WON_CLASS'].value_counts())
```

중앙값으로 자르면 두 클래스의 크기가 자동으로 거의 같아집니다. 클래스 불균형을 처음부터 만들지 않는 방법이지만, 대신 "실무적으로 의미 있는 기준선"과는 무관해질 수 있습니다.

### 6) 헷갈리는 점

"분류가 회귀보다 쉽다"는 오해가 있습니다. 실제로는 정보를 버리는 대가로 지표가 좋아 보이는 것입니다. 지출 금액을 상·하위로만 나누면 15만원과 16만원의 차이는 사라지지만, 기준선 근처의 애매한 표본은 여전히 틀립니다.

### 7) 한 줄 정리

> 종속변수가 연속값이면 회귀, 범주면 분류이며, 회귀 문제는 기준선을 그어 분류로 바꿀 수 있지만 그 반대는 불가능하다.

## 3. 데이터 유형이 전처리를 결정한다

### 1) 정의

전처리(Preprocessing)는 원본 데이터를 모델이 계산할 수 있는 숫자 행렬로 바꾸는 과정입니다. 목표는 항상 같지만, 출발점이 표인지 문장인지 신호인지에 따라 필요한 기술이 달라집니다.

### 2) 왜 필요한가

모델은 숫자만 먹습니다. "자가용"이라는 글자도, "도로에 포트홀이 생겼어요"라는 문장도, 512개 주파수 대역의 진폭 배열도 그대로는 입력이 되지 않습니다. 어떤 방식으로 숫자화하느냐가 모델 성능의 상한선을 결정합니다.

### 3) 핵심 흐름 재구성

세 프로젝트의 전처리 축을 비교하면 다음과 같습니다.

| 데이터 유형 | 핵심 전처리 | 결과 형태 | 주의점 |
|---|---|---|---|
| 정형 표 | 라벨 인코딩, 다중 라벨 이진화, 결측 대체, IQR 이상치 제거, 테이블 병합 | 행=관측, 열=변수 | 병합 기준 키와 행의 단위 |
| 한국어 텍스트 | 형태소 분석, 불용어 제거, TF-IDF 벡터화 | 희소 행렬(문서×단어) | 토크나이저 선택이 차원 수를 좌우 |
| 센서 신호 | 스케일 정규화, 라벨 인코딩, 불필요 컬럼 제거 | 행=측정, 열=주파수 대역 | 이미 숫자라도 스케일 차이가 큼 |

공통점도 있습니다. 세 프로젝트 모두 마지막에는 `(샘플 수 × 특성 수)` 형태의 숫자 행렬이 되고, 정규화를 거쳐 학습/테스트로 분리됩니다. 다른 것은 그 행렬을 만들기까지의 경로뿐입니다.

### 4) 쉬운 예시

같은 "요리 재료 준비"라도 채소는 씻고 썰면 되지만, 냉동육은 해동이 필요하고 마른 콩은 불려야 합니다. 최종적으로 냄비에 들어가는 형태는 비슷하지만 손질법은 재료마다 다릅니다. 전처리도 마찬가지입니다.

### 5) 코드 예시

세 유형의 "숫자화" 한 줄씩을 나란히 보면 차이가 분명합니다.

### 6) 헷갈리는 점

"센서 데이터는 이미 숫자니까 전처리가 필요 없다"고 생각하기 쉽습니다. 하지만 주파수 대역별로 값의 범위가 크게 다르면, 거리 기반이나 선형 계열 모델은 값이 큰 대역에만 끌려갑니다. 숫자라는 사실과 모델이 쓰기 좋은 숫자라는 사실은 다릅니다.

### 7) 한 줄 정리

> 전처리의 목적지는 언제나 숫자 행렬이지만, 표·텍스트·신호는 그곳에 도달하는 경로가 서로 다르다.

## 코드로 보기 — 문제 정의 체크리스트를 코드로 굳히기

```python
def frame_problem(df, target, id_cols):
    """문제 정의가 코드로 제대로 내려왔는지 점검하는 최소 함수"""
    y = df[target]
    X = df.drop(columns=id_cols + [target])

    task = '회귀' if y.nunique() > 20 else '분류'
    print(f'행 수(샘플): {len(df)}')
    print(f'독립변수 수: {X.shape[1]}')
    print(f'종속변수 고유값 수: {y.nunique()} → {task} 문제')
    print(f'결측 있는 열: {int(X.isnull().any().sum())}개')
    return X, y, task

X, y, task = frame_problem(df, target='WON_SUM', id_cols=['TRAVELER_ID'])
```

```text
행 수(샘플): 2128
독립변수 수: 84
종속변수 고유값 수: 2049 → 회귀 문제
결측 있는 열: 0개
```

### 코드 목적

모델을 만들기 전에 "지금 내가 푸는 문제가 무엇인지"를 숫자로 확인합니다. 사람이 머릿속으로만 정한 문제 정의를 데이터가 실제로 뒷받침하는지 검증하는 관문입니다.

### 코드 흐름

1. 종속변수와 식별자 컬럼을 분리해 독립변수 행렬을 만든다.
2. 종속변수의 고유값 개수로 회귀/분류를 자동 판정한다.
3. 샘플 수와 변수 수를 함께 출력해 규모를 확인한다.
4. 결측이 남아 있는지 마지막으로 점검한다.

### 실행 결과 해석

**2,128개 표본에 독립변수가 84개**입니다. 표본 대비 변수 비율이 약 25:1로, 통계적으로는 여유가 있어 보이지만 선형 모델 기준으로는 부담스러운 수치입니다. 실제로 이 데이터에서 84개 변수를 전부 넣은 다중회귀는 R² 0.30에 비해 Adjusted R²가 0.13까지 떨어집니다. 변수 수가 설명력을 부풀린 것입니다.

**종속변수 고유값이 2,049개**라는 것은 2,128명 중 거의 모든 사람의 지출 금액이 서로 다르다는 뜻으로, 명백한 연속값이자 회귀 문제입니다. 결측이 0개인 것은 앞선 전처리가 정상적으로 끝났다는 신호입니다.

### 실무 연결

실무에서는 이 점검을 기획 문서와 코드 사이의 연결고리로 씁니다. 기획서에 "고객 이탈 예측"이라고만 적혀 있으면, 이 함수를 돌려 종속변수 정의와 표본 규모를 확정한 뒤 회의에서 합의합니다. 표본 대비 변수 수가 지나치게 크면 이 단계에서 이미 변수 선택이나 규제가 필요하다는 결론이 나옵니다.

## 직접 해보기

1. "고객이 다음 달에 우리 서비스를 해지할까?"라는 질문을 회귀와 분류 중 어느 쪽으로 번역해야 하나요? 종속변수를 구체적으로 적어 보세요.
2. 종속변수가 `[120, 340, 55, 890, 210]`처럼 금액이라면 평가지표로 무엇을 고르고, 이를 3등급 분류로 바꾼다면 평가지표는 어떻게 바뀌나요?
3. 텍스트 데이터와 센서 데이터를 각각 모델에 넣기 직전 형태로 만들려면 어떤 전처리가 필요한지 한 문장씩 적어 보세요.

<details>
<summary>정답 보기</summary>

1. 분류입니다. 종속변수는 "다음 달 해지 여부"로 0(유지)/1(해지)의 이진 라벨이 됩니다. 만약 "며칠 뒤에 해지할까"를 묻는다면 종속변수가 일수라는 연속값이 되어 회귀가 됩니다. 같은 주제라도 질문의 형태에 따라 유형이 달라집니다.
2. 금액 예측은 회귀이므로 RMSE(오차의 크기)와 MAPE(오차의 비율), 설명력을 보는 R²를 함께 씁니다. 3등급 분류로 바꾸면 정확도만으로는 부족하고 클래스별 precision·recall과 이를 종합한 F1, 특히 클래스 크기를 반영한 weighted F1을 봐야 합니다.
3. 텍스트는 형태소 분석기로 토큰을 뽑고 불용어를 걸러 TF-IDF 같은 벡터화를 거쳐 문서×단어 행렬로 만듭니다. 센서는 이미 숫자이지만 대역별 스케일 차이가 크므로 표준화(평균 0·표준편차 1)를 적용하고, 라벨은 정수로 인코딩합니다.

</details>

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 회귀 vs 분류 | 예측값이 연속된 숫자면 회귀, 정해진 범주면 분류 |
| 문제 정의 vs 모델 선택 | 무엇을 맞힐지 정하는 것이 문제 정의, 어떻게 맞힐지 고르는 것이 모델 선택 |
| 독립변수 vs 식별자 | 예측에 쓰는 정보는 독립변수, 행을 구분하는 번호는 식별자이며 학습에서 제외 |
| 정확도 vs weighted F1 | 전체 맞힌 비율은 정확도, 클래스 크기를 반영해 precision·recall을 종합한 값이 weighted F1 |
| 정형 데이터 vs 비정형 데이터 | 행·열이 정해진 표는 정형, 문장·신호처럼 별도 변환이 필요한 것은 비정형 |

**Q1. 문제 정의 단계에서 반드시 정해야 하는 세 가지는 무엇인가요?**

<details>
<summary>답</summary>

무엇을 맞힐 것인가(종속변수), 무엇을 보고 맞힐 것인가(독립변수), 잘 맞혔는지 어떻게 잴 것인가(평가지표)입니다. 여기에 더해 "1행이 무엇을 의미하는가"라는 행의 단위까지 정해야 병합과 집계 방식이 확정됩니다.

</details>

**Q2. 같은 데이터로 회귀 모델과 분류 모델을 모두 만들 수 있는 이유는 무엇인가요?**

<details>
<summary>답</summary>

연속값 종속변수에 기준선을 그으면 범주가 만들어지기 때문입니다. 예를 들어 지출 금액의 중앙값을 기준으로 그 이하는 0, 초과는 1로 라벨링하면 그대로 이진 분류 문제가 됩니다. 다만 이 과정에서 금액의 세밀한 정보는 사라집니다.

</details>

**Q3. 정형 데이터, 텍스트, 센서 신호의 전처리에서 공통 목표와 서로 다른 점은 무엇인가요?**

<details>
<summary>답</summary>

공통 목표는 셋 다 `(샘플 수 × 특성 수)` 형태의 숫자 행렬을 만드는 것입니다. 다른 점은 경로입니다. 정형 데이터는 인코딩·결측 처리·병합이 중심이고, 텍스트는 형태소 분석과 벡터화가 중심이며, 센서는 이미 숫자이므로 스케일 정규화가 중심입니다.

</details>
