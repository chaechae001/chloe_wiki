# 반응형 웹과 viewport — 화면 조건을 CSS 규칙으로 바꾸기

> 같은 페이지라도 데스크톱과 휴대전화에서 사용할 수 있는 공간은 다릅니다. 반응형 웹의 핵심은 기기 이름을 외우는 것이 아니라, 콘텐츠가 불편해지는 화면 조건을 찾아 다른 배치 규칙을 적용하는 데 있습니다.

`responsive-web` · `viewport` · `media-query` · `breakpoint` · `cascade`

## 핵심요약
- 반응형 웹은 하나의 문서가 화면 조건에 따라 자연스럽게 재배치되도록 CSS를 바꾸는 설계 방식이다.
- viewport 메타 태그는 CSS가 기준으로 삼을 화면 너비와 초기 배율을 모바일 브라우저에 알려 준다.
- `@media`는 조건이 참일 때만 내부 CSS 규칙을 후보로 올린다.
- `min-width`는 지정 너비 이상, `max-width`는 지정 너비 이하에서 조건이 참이 된다.
- 미디어쿼리에서 다시 선언하지 않은 속성은 기본 규칙이 계속 적용되므로 캐스케이드 전체를 함께 읽어야 한다.
## 1. 반응형 웹의 출발점
### 1) 정의
반응형 웹은 화면 너비 같은 사용 환경의 조건에 맞춰 요소의 크기와 배치를 바꾸는 웹 설계 방식입니다.
HTML 구조를 화면마다 복제하기보다 하나의 콘텐츠 구조를 유지하고, CSS가 표현 방법을 조정합니다.
### 2) 왜 필요한가
넓은 화면에서 보기 좋은 두 열 배치를 좁은 화면에 그대로 두면 카드와 글자가 지나치게 작아질 수 있습니다.
반대로 모바일용 한 열 배치를 큰 화면에 그대로 쓰면 넓은 공간을 활용하지 못합니다.
반응형 설계는 다음 문제를 해결합니다.
- 가로 스크롤 없이 핵심 콘텐츠 읽기
- 메뉴와 버튼의 충분한 사용 공간 확보
- 이미지와 카드가 컨테이너 밖으로 넘치는 현상 방지
- 하나의 콘텐츠를 여러 화면에서 일관되게 관리
### 3) 핵심 흐름 재구성
반응형 화면은 보통 다음 순서로 설계합니다.
1. 먼저 기본 화면의 구조와 스타일을 만든다.
2. 브라우저 너비를 줄이며 콘텐츠가 불편해지는 지점을 찾는다.
3. 그 지점을 breakpoint로 정한다.
4. `@media` 안에서 꼭 바뀌어야 하는 속성만 다시 선언한다.
5. 경계값 앞뒤에서 결과를 비교한다.
여기서 중요한 것은 “특정 기기 전용 CSS”보다 “이 너비에서 콘텐츠가 어떻게 보여야 하는가”입니다.
### 4) 쉬운 예시
책상 위에서는 두 권의 책을 나란히 펼칠 수 있지만, 작은 이동식 테이블에서는 한 권씩 위아래로 놓는 편이 읽기 쉽습니다.
책의 내용은 같고, 사용할 수 있는 폭에 따라 놓는 방식만 달라집니다.
### 5) 코드 예시
```css
.card-list {
  display: grid;
  grid-template-columns: repeat(2, 1fr);
  gap: 16px;
}
@media (max-width: 800px) {
  .card-list {
    grid-template-columns: 1fr;
  }
}
```
화면 너비가 `800px` 이하가 되면 두 열이 한 열로 바뀝니다.
카드 내용이나 HTML 순서는 바뀌지 않고, 열 개수만 달라집니다.
### 6) 헷갈리는 점
반응형 웹과 적응형 웹은 함께 언급되지만 초점이 다릅니다.
반응형 웹은 같은 레이아웃이 화면 크기에 따라 유연하게 변하는 흐름에 가깝고, 적응형 웹은 미리 정한 몇 가지 화면 구성을 조건에 맞춰 선택하는 접근에 가깝습니다.
### 7) 한 줄 정리
> 반응형 웹은 콘텐츠를 바꾸는 것이 아니라, 사용할 수 있는 화면 공간에 맞게 표현 규칙을 바꾸는 설계다.

## 2. viewport와 모바일 화면의 기준
### 1) 정의
viewport는 브라우저가 웹 콘텐츠를 표시하는 화면 영역입니다.
모바일 브라우저는 작은 화면에서도 데스크톱 페이지를 축소해 보여 주기 위해 실제 기기 너비와 다른 가상의 레이아웃 너비를 사용할 수 있습니다.
### 2) 왜 필요한가
CSS 미디어쿼리는 viewport 너비를 기준으로 판단합니다.
viewport 설정이 빠지면 개발자가 기대한 경계값과 모바일 브라우저가 계산한 너비가 달라져 미디어쿼리가 예상과 다르게 작동할 수 있습니다.
### 3) 핵심 흐름 재구성
다음 메타 태그는 문서의 `<head>` 안에 둡니다.
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```
각 설정의 의미는 다음과 같습니다.
| 설정 | 의미 | 확인할 점 |
|---|---|---|
| `width=device-width` | viewport 너비를 기기 화면 너비와 맞춤 | CSS 픽셀 기준으로 경계값 판단 |
| `initial-scale=1.0` | 첫 화면의 배율을 1로 시작 | 의도하지 않은 초기 축소 방지 |
이 설정은 화면을 반응형으로 자동 변환하지 않습니다.
미디어쿼리가 실제 기기 너비를 기준으로 판단할 수 있는 출발점을 마련합니다.
### 4) 쉬운 예시
지도의 축척이 잘못 설정되어 있으면 같은 거리도 전혀 다른 길이로 읽힙니다.
viewport 메타 태그는 모바일 브라우저가 화면 너비라는 자를 올바른 축척으로 사용하게 하는 설정과 비슷합니다.
### 5) 코드 예시
```html
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>반응형 카드</title>
  </head>
  <body>
    <div class="status-card">화면 너비를 줄여 보세요.</div>
  </body>
</html>
```
### 6) 헷갈리는 점
`width=device-width`의 `width`는 HTML 요소의 CSS `width` 속성이 아닙니다.
메타 태그 안에서 브라우저의 표시 영역을 설정하는 별도의 키워드입니다.
### 7) 한 줄 정리
> viewport 설정은 모바일 브라우저와 CSS가 같은 화면 너비를 기준으로 대화하게 만든다.

## 3. 미디어쿼리와 CSS 캐스케이드
### 1) 정의
미디어쿼리는 화면 조건이 참일 때 내부 스타일 규칙을 활성화하는 CSS 구문입니다.
```css
@media (min-width: 320px) and (max-width: 800px) {
  /* 320px 이상이면서 800px 이하일 때 적용 */
}
```
### 2) 왜 필요한가
화면 구간마다 크기, 열 개수, 정렬 방향을 바꾸려면 조건부 스타일이 필요합니다.
HTML을 바꾸지 않고도 같은 요소에 다른 CSS 값을 적용할 수 있습니다.
### 3) 핵심 흐름 재구성
`and`로 연결된 두 조건은 모두 참이어야 합니다.
- viewport가 `319px`이면 `min-width: 320px`가 거짓이다.
- viewport가 `600px`이면 두 조건이 모두 참이다.
- viewport가 `801px`이면 `max-width: 800px`가 거짓이다.
조건이 참이어도 CSS 우선순위가 사라지는 것은 아닙니다.
선택자 우선순위가 같다면 뒤에 작성된 규칙이 앞선 규칙을 덮어씁니다.
```css
.notice {
  width: 500px;
  height: 240px;
  background-color: #ff6b6b;
}
@media (min-width: 320px) and (max-width: 800px) {
  .notice {
    width: 300px;
    height: 180px;
    background-color: #ffd43b;
  }
}
```
### 4) 쉬운 예시
기본 복장은 긴소매이고, 기온이 특정 범위에 들어오면 반소매 규칙을 적용한다고 생각할 수 있습니다.
조건에서 말하지 않은 신발 규칙은 기본 복장의 값을 그대로 유지합니다.
### 5) 코드 예시
```css
.notice {
  border: 4px solid #1c7ed6;
  color: #212529;
}
@media (max-width: 800px) {
  .notice {
    width: 100%;
    background-color: transparent;
  }
}
```
미디어쿼리 안에서 `border`와 `color`를 다시 선언하지 않았으므로 기본 규칙의 값이 계속 적용됩니다.
엄밀히 말하면 모든 속성이 부모로부터 상속되는 것은 아닙니다.
같은 요소에 이미 적용된 기본 선언이 캐스케이드에 남아 있는 경우와 부모에게서 물려받는 CSS 상속은 구분해야 합니다.
### 6) 헷갈리는 점
속성을 없애고 싶을 때 모든 속성에 `none`을 쓸 수 있는 것은 아닙니다.
- 테두리를 없앨 때: `border: none`
- 배경색을 투명하게 할 때: `background-color: transparent`
- 명세의 초기값으로 돌릴 때: `initial`
- 부모의 계산값을 명시적으로 받을 때: `inherit`
### 7) 한 줄 정리
> 미디어쿼리는 조건을 켜고 끌 뿐이며, 최종 스타일은 기본 규칙과 우선순위까지 합쳐 결정된다.

## 코드로 보기 — 경계값에서 변하는 상태 카드
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<section class="status-card">
  <h2>오늘의 작업</h2>
  <p>화면 폭에 맞춰 카드 크기와 색이 달라집니다.</p>
</section>
```
```css
* { box-sizing: border-box; }
body { margin: 0; padding: 24px; }
.status-card {
  width: 500px;
  min-height: 220px;
  padding: 24px;
  border: 4px solid #1c7ed6;
  background: #e7f5ff;
}
@media (min-width: 320px) and (max-width: 800px) {
  .status-card {
    width: 300px;
    min-height: 180px;
    background: #fff3bf;
  }
}
```
### 코드 목적
viewport 설정과 범위형 미디어쿼리가 함께 작동하는 최소 예제를 확인합니다.
### 코드 흐름
1. viewport를 기기 너비와 맞춘다.
2. 기본 카드 너비를 `500px`로 선언한다.
3. `320px` 이상 `800px` 이하에서 너비를 `300px`로 덮어쓴다.
4. 미디어쿼리에 없는 테두리와 패딩은 기본값을 유지한다.
5. 경계값의 바로 앞뒤에서 결과를 비교한다.
### 예상 렌더링
```text
viewport 900px → 카드 500px, 파란 배경, 파란 테두리 4px
viewport 800px → 카드 300px, 노란 배경, 파란 테두리 4px
viewport 320px → 카드 300px, 노란 배경, 파란 테두리 4px
viewport 319px → 카드 500px, 파란 배경, 파란 테두리 4px
```
### 실행 결과 해석
`800px`과 `320px`은 `min-width`와 `max-width`의 범위에 포함되므로 작은 카드 규칙이 적용됩니다.
`319px`에서는 조건이 거짓이 되어 기본 `500px`가 다시 적용되므로 가로 넘침이 생길 수 있습니다.
이 결과는 실제 지원 범위와 기본 스타일 방향을 함께 설계해야 한다는 점을 보여 줍니다.
### 실무 연결
상품 카드, 대시보드 요약 상자, 메뉴 패널처럼 제한된 화면에서 크기와 배치가 달라져야 하는 컴포넌트에 같은 원리를 적용할 수 있습니다.

3. `799px`, `800px`, `801px`에서 카드 너비를 기록해 경계값 오류가 있는지 판단해 보세요.

## 헷갈리기 쉬운 포인트
| 헷갈리는 개념 | 차이 |
|---|---|
| 반응형 웹 vs 적응형 웹 | 유동적으로 변하는 하나의 구성에 초점을 두는 방식 vs 정해 둔 여러 구성을 조건에 맞춰 선택하는 방식 |
| `min-width` vs `max-width` | 지정 너비 이상에서 참 vs 지정 너비 이하에서 참 |
| CSS 상속 vs 기본 선언 유지 | 부모의 계산값을 물려받는 것 vs 같은 요소의 기존 규칙이 캐스케이드에 남는 것 |
| `none` vs `transparent` | 속성이 지원할 때 값을 없애는 키워드 vs 색은 존재하지만 완전히 투명한 값 |

### 복습 질문 및 답변
**Q1. viewport 메타 태그만 추가하면 반응형 화면이 완성되나요?**
<details>
<summary>답</summary>

아닙니다. viewport는 모바일 브라우저의 화면 너비 기준을 맞춥니다. 실제 크기와 배치 변화는 유연한 너비와 미디어쿼리 같은 CSS 규칙으로 구현해야 합니다.

</details>
**Q2. 미디어쿼리 안에 `width`만 작성했는데 기본 배경색이 남는 이유는 무엇인가요?**
<details>
<summary>답</summary>

미디어쿼리는 해당 조건에서 `width` 선언만 추가로 활성화합니다. 배경색을 대체하는 선언이 없으므로 같은 요소에 적용된 기본 배경색 규칙이 최종 스타일에 남습니다.

</details>
**Q3. breakpoint를 기기 모델 목록만 보고 정하면 어떤 문제가 생길 수 있나요?**
