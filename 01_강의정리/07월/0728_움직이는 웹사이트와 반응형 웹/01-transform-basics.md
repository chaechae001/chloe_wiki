# CSS Transform 기초 — 요소의 모양과 좌표를 한 줄로 바꾸기
> 레이아웃을 다시 짜지 않고도 카드를 기울이고, 아이콘을 키우고, 배지를 옮길 수 있다.
> `transform`의 함수와 기준점, 작성 순서를 이해하면 움직임을 감으로 조절하지 않고 설계할 수 있다.

`transform` · `rotate` · `scale` · `translate` · `transform-origin`
## 핵심요약
- `transform`은 요소가 그려진 뒤 회전·확대·기울이기·이동을 적용한다.
- `rotate()`, `scale()`, `skew()`, `translate()`는 서로 다른 종류의 변형을 담당한다.
- 음수 각도와 음수 이동값을 사용하면 방향을 반대로 바꿀 수 있다.
- `transform-origin`은 회전과 확대가 시작되는 기준점을 정한다.
- 여러 함수를 한 선언에 조합할 수 있지만 작성 순서가 달라지면 결과도 달라진다.
---
## 1. Transform과 네 가지 기본 함수
### 1) 정의
`transform`은 요소의 원래 박스 정보를 유지한 채 화면에 그려지는 모양과 위치를 바꾸는 CSS 속성이다.

대표 함수는 회전하는 `rotate()`, 크기를 바꾸는 `scale()`, 비스듬히 기울이는 `skew()`, 위치를 옮기는 `translate()`다.
### 2) 왜 필요한가
사용자가 가리킨 카드만 살짝 커지게 하거나, 화살표 아이콘의 방향을 돌리거나, 알림 배지를 미세하게 옮길 때 매번 너비와 좌표를 다시 계산하면 코드가 복잡해진다.

변형 함수는 이런 시각적 변화를 한 속성 안에서 표현하므로 상태 변화와 애니메이션을 설계하기 쉽다.

또한 요소의 문서 흐름 속 자리 자체는 그대로 남는다.

따라서 주변 요소를 밀어내는 레이아웃 변경과, 화면 위에서만 보이는 시각적 이동을 구분할 수 있다.
### 3) 핵심 흐름
| 함수 | 입력값 예 | 화면에서 일어나는 일 | 자주 쓰는 상황 |
|---|---|---|---|
| `rotate()` | `rotate(15deg)` | 시계 방향으로 15도 회전 | 화살표, 배지, 카드 기울이기 |
| `scale()` | `scale(1.1)` | 가로·세로를 1.1배 확대 | 이미지와 버튼 강조 |
| `skew()` | `skewX(-8deg)` | x축 방향으로 기울이기 | 리본, 속도감 있는 장식 |
| `translate()` | `translate(20px, -8px)` | 오른쪽 20px, 위쪽 8px 이동 | 아이콘 정렬, 등장 효과 |
각도 단위 `deg`에서 양수는 기본적으로 시계 방향, 음수는 반시계 방향 회전을 뜻한다.

`scale(1)`은 원래 크기, `scale(0.8)`은 80%, `scale(1.2)`는 120% 크기다.

`scale(1.2, 0.8)`처럼 두 값을 쓰면 가로와 세로 비율을 따로 지정한다.

`translate()`의 첫 번째 값은 x축, 두 번째 값은 y축 이동량이다.

x축 양수는 오른쪽, y축 양수는 아래쪽이며 음수는 각각 반대 방향이다.

`skew(10deg, 5deg)`는 x축과 y축 기울기를 함께 정하지만, 읽기 쉬운 코드에서는 `skewX()`와 `skewY()`로 의도를 나누기도 한다.
### 4) 쉬운 예시
사진이 붙은 투명 필름을 책상 위에 올렸다고 생각해 보자.

필름을 돌리면 `rotate()`, 필름을 확대 복사하면 `scale()`, 한쪽으로 밀면 `translate()`, 모서리를 잡아 비스듬히 당기면 `skew()`에 해당한다.

책상 위에서 필름이 차지하던 예약 공간은 그대로라는 점이 일반 레이아웃 변경과의 차이다.
### 5) 코드 예시
```html
<div class="sample turn">회전</div>
<div class="sample grow">확대</div>
<div class="sample lean">기울이기</div>
<div class="sample move">이동</div>
```
```css
.sample {
  display: inline-grid;
  place-items: center;
  width: 90px;
  height: 60px;
  margin: 24px;
  border: 2px solid #315b8a;
  background: #eaf3ff;
}

.turn { transform: rotate(-8deg); }
.grow { transform: scale(1.15); }
.lean { transform: skewX(-10deg); }
.move { transform: translate(18px, -6px); }
```
### 6) 결과 해석과 헷갈리는 점
`turn`은 반시계 방향으로 8도 회전하고, `grow`는 가로와 세로가 모두 115%로 보인다.

`move`는 원래 자리보다 오른쪽 18px, 위쪽 6px에 그려지지만 다음 형제 요소의 배치 기준은 바뀌지 않는다.
- `scale(0)`은 원래 크기 유지가 아니라 가로와 세로가 0배가 되어 보이지 않는 상태다.
- `translate(50%, 0)`의 백분율은 일반적으로 변형되는 요소 자신의 크기를 기준으로 계산된다.
- 서로 다른 `transform` 선언을 여러 줄로 쓰면 누적되지 않고 캐스케이드에서 선택된 한 선언만 적용된다.
- 오래된 브라우저용 접두사가 필요하다면 접두사 선언 뒤에 표준 `transform` 선언도 함께 두어야 한다.
### 7) 한 줄 정리
> 네 가지 변형 함수는 요소의 레이아웃 자리는 유지하면서 화면에 그려지는 모양과 좌표를 바꾼다.

## 2. transform-origin으로 기준점 정하기
### 1) 정의
`transform-origin`은 회전하거나 확대할 때 축으로 삼을 지점을 정하는 속성이다.

기본값은 요소의 정중앙인 `50% 50%`다.
### 2) 왜 필요한가
같은 회전이라도 중앙을 축으로 돌면 팽이처럼 보이고, 왼쪽 끝을 축으로 돌면 문이 열리는 것처럼 보인다.

어떤 지점을 고정할지 결정하지 않으면 원하는 각도는 맞아도 움직임의 인상이 어색할 수 있다.
### 3) 핵심 흐름
두 값은 차례로 가로 기준점과 세로 기준점을 뜻한다.

| 선언 | 기준점 | 떠올리기 좋은 움직임 |
|---|---|---|
| `center center` | 정중앙 | 로딩 아이콘 회전 |
| `left center` | 왼쪽 가운데 | 옆으로 열리는 문 |
| `right top` | 오른쪽 위 | 모서리에 매달린 태그 |
| `25% 75%` | 왼쪽에서 25%, 위에서 75% | 사용자 정의 축 |
키워드와 백분율, 길이값을 사용할 수 있다.

기준점이 달라져도 회전각이나 배율 자체가 바뀌는 것은 아니다.

다만 기준점에서 멀리 떨어진 부분이 더 큰 궤적을 그리기 때문에 결과가 크게 달라 보인다.
### 4) 쉬운 예시
책상 위 연필을 가운데로 눌러 돌리는 경우와 지우개 쪽 끝을 눌러 돌리는 경우를 비교해 보자.

회전한 각도는 같아도 연필 끝이 지나가는 경로는 다르다.

`transform-origin`은 어느 손가락으로 연필을 고정할지를 정하는 규칙이다.
### 5) 코드 예시
```html
<button class="tag tag-center">중앙 회전</button>
<button class="tag tag-edge">왼쪽 회전</button>
```
```css
.tag {
  width: 120px;
  padding: 14px;
  border: 0;
  background: #ffd76a;
  transform: rotate(12deg);
}

.tag-center { transform-origin: center; }
.tag-edge { transform-origin: left center; }
```
### 6) 결과 해석과 헷갈리는 점
두 버튼은 모두 12도 회전하지만 `tag-center`는 가운데를 중심으로, `tag-edge`는 왼쪽 변을 붙잡은 채 회전한다.

따라서 오른쪽 끝의 이동 거리는 `tag-edge` 쪽이 더 크다.
- 기준점은 요소를 실제로 이동시키는 좌표가 아니라 변형 계산의 축이다.
- `transform-origin`만 작성하고 `transform`이 없으면 눈에 띄는 변화가 없다.
- 확대 효과에서도 기준점이 적용되므로 `left center`에서 확대하면 오른쪽 방향으로 더 많이 자란다.
### 7) 한 줄 정리
> `transform-origin`은 변형의 양이 아니라 변화가 시작되는 축을 결정한다.

## 3. 변형 함수 조합과 작성 순서
### 1) 정의
하나의 `transform` 값에는 여러 함수를 공백으로 이어 작성할 수 있다.
```css
.card {
  transform: translateX(80px) rotate(30deg) scale(1.05);
}
```
### 2) 왜 필요한가
카드를 옮기면서 기울이고 살짝 확대하는 효과를 각각 따로 선언하면 뒤의 선언이 앞의 선언을 덮어쓴다.

한 선언에 조합하면 모든 변형을 함께 유지할 수 있다.
### 3) 핵심 흐름
변형 함수는 단순한 독립 명령 목록이 아니라 좌표계 변환의 조합이다.

따라서 같은 함수와 같은 숫자를 사용해도 순서를 바꾸면 이동 방향과 최종 위치가 달라질 수 있다.

다음 두 선언은 서로 같지 않다.
```css
.move-then-turn {
  transform: translateX(80px) rotate(30deg);
}

.turn-then-move {
  transform: rotate(30deg) translateX(80px);
}
```
첫 번째 요소의 중심은 원래 위치에서 오른쪽으로 약 80px 이동한다.

두 번째 요소의 이동은 회전된 x축을 따르므로 중심은 대략 오른쪽 69.3px, 아래쪽 40px 방향에 놓인다.

이 수치는 $80 \times \cos 30^\circ \approx 69.3$, $80 \times \sin 30^\circ = 40$으로 이해할 수 있다.

실무에서는 행렬 계산을 매번 할 필요는 없지만, 순서를 바꾸면 결과가 달라진다는 사실은 반드시 기억해야 한다.
### 4) 쉬운 예시
사람이 정면을 본 채 앞으로 열 걸음 간 다음 오른쪽을 보는 경우와, 먼저 오른쪽을 본 다음 앞으로 열 걸음 가는 경우를 비교해 보자.

두 동작의 종류와 횟수는 같아도 마지막 위치가 다르다.

변형 함수의 순서도 이와 비슷하게 좌표 방향에 영향을 준다.
### 5) 코드 예시
```css
.card:hover {
  /* 한 선언 안에서 이동, 회전, 확대를 함께 유지한다. */
  transform: translateY(-8px) rotate(2deg) scale(1.03);
}
```
### 6) 결과 해석과 헷갈리는 점
마우스를 올리면 카드는 위로 8px 이동하고 2도 기울며 103% 크기로 보인다.

세 효과를 각기 다른 `transform` 선언으로 작성하면 마지막 선언 하나만 남는다는 점이 가장 흔한 실수다.
- `transform: rotate(5deg); transform: scale(1.1);`의 최종 결과는 확대뿐이다.
- 순서를 바꾼 결과가 미묘하다면 요소의 기준점과 이동 축을 함께 확인한다.
- 브라우저 개발자 도구에서 함수를 하나씩 끄고 켜면 각 함수의 역할을 분리해 볼 수 있다.
### 7) 한 줄 정리
> 여러 변형은 한 선언에 조합하고, 작성 순서까지 디자인의 일부로 다뤄야 한다.

## 코드로 보기 — 변형 비교 실험판
```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>Transform 비교</title>
  <style>
    body { font-family: sans-serif; padding: 40px; }
    .stage { display: flex; gap: 140px; margin-top: 60px; }
    .box {
      display: grid;
      place-items: center;
      width: 100px;
      height: 70px;
      background: #d9ecff;
      border: 2px solid #315b8a;
    }
    .first { transform: translateX(80px) rotate(30deg); }
    .second { transform: rotate(30deg) translateX(80px); }
  </style>
</head>
<body>
  <h1>변형 순서 비교</h1>
  <div class="stage">
    <div class="box first">이동 → 회전</div>
    <div class="box second">회전 → 이동</div>
  </div>
</body>
</html>
```
### 코드 목적
같은 `translateX(80px)`와 `rotate(30deg)`를 사용하더라도 작성 순서에 따라 최종 위치가 달라지는지 확인한다.
### 코드 흐름
1. 크기가 같은 상자 두 개를 만든다.
2. 첫 번째 상자에는 이동 함수를 앞에 작성한다.
3. 두 번째 상자에는 회전 함수를 앞에 작성한다.
4. 두 상자의 회전각과 중심 위치를 비교한다.
### 예상 렌더링
```text
first  중심 이동: x 방향 약 +80px, y 방향 약 0px
second 중심 이동: x 방향 약 +69.3px, y 방향 약 +40px
두 요소의 회전각: 모두 30deg
```
### 실행 결과 해석
두 상자의 기울기는 모두 30도지만 중심의 도착점은 다르다.

두 번째 상자는 회전된 지역 좌표의 x축을 따라 80px 이동하므로 오른쪽뿐 아니라 아래쪽으로도 움직인다.
### 실무 연결
카드 등장 효과, 접히는 메뉴, 배지 위치 보정처럼 이동과 회전이 섞인 UI에서는 함수 순서를 고정해야 화면 크기가 바뀌어도 움직임을 예측할 수 있다.

디자인 검수에서는 시작 위치, 기준점, 함수 순서를 함께 기록하면 비슷한 효과를 다른 컴포넌트에도 재사용하기 쉽다.

## 직접 해보기
1. 요소를 원래 크기의 80%로 줄이려면 어떤 변형 함수를 어떻게 작성해야 하는가?
2. `transform: rotate(10deg);` 다음 줄에 `transform: translateX(20px);`를 작성하면 화면에는 어떤 변형이 남는가?
3. 왼쪽 변이 고정된 채 열리는 안내 패널을 만든다면 어떤 `transform-origin`이 적절한가?

<details>
<summary>정답 보기</summary>
1. `transform: scale(0.8);`로 작성한다. `1`이 원래 크기이므로 `0.8`은 가로와 세로를 각각 80%로 표시한다.
2. 뒤에 작성된 `translateX(20px)`만 남는다. 같은 요소의 같은 속성 선언은 자동으로 합쳐지지 않으므로 두 함수를 한 선언에 써야 한다.
3. `transform-origin: left center;`가 적절하다. 왼쪽 가운데를 회전축으로 고정하면 문이 경첩을 중심으로 열리는 듯한 움직임을 만들 수 있다.
</details>
## 헷갈리기 쉬운 포인트
| 헷갈리는 개념 | 차이 |
|---|---|
| `translate()` vs `margin` | 앞은 그려지는 위치를 바꾸고 문서 흐름의 자리는 유지하며, 뒤는 박스 바깥 여백을 바꿔 주변 배치에 영향을 준다 |
| `scale(1)` vs `scale(0)` | 앞은 원래 크기이고, 뒤는 0배라 화면에서 보이지 않는다 |
| `rotate()` vs `skew()` | 앞은 요소 전체를 회전하고, 뒤는 축을 비틀어 평행선의 각도를 바꾼다 |
| `transform` vs `transform-origin` | 앞은 실제 변형을 지정하고, 뒤는 그 변형의 기준점만 정한다 |
| 함수 조합 vs 선언 반복 | 한 값에 함수를 나열하면 조합되고, 같은 속성을 반복 선언하면 선택된 마지막 값이 앞을 덮어쓴다 |

### 복습 질문 및 답변
**Q1. 기본 — `translate(30px, -10px)`는 요소를 어느 방향으로 옮기는가?**
<details>
<summary>답</summary>
원래 그려질 위치를 기준으로 오른쪽 30px, 위쪽 10px에 표시한다. 주변 요소가 사용하는 문서 흐름 속 자리는 그대로 유지된다.
</details>
**Q2. 이해 확인 — 같은 회전각인데 `transform-origin`에 따라 움직임이 달라지는 이유는?**
<details>
<summary>답</summary>
회전축에서 각 지점까지의 거리가 달라지기 때문이다. 축에서 먼 부분은 같은 각도로 회전해도 더 긴 원호를 지나므로 이동 폭이 더 크게 보인다.
</details>
**Q3. 응용 — 이동, 확대, 회전을 모두 적용했는데 확대만 보일 때 가장 먼저 확인할 것은?**
<details>
<summary>답</summary>
세 효과를 서로 다른 `transform` 선언에 썼는지 확인한다. 그렇다면 `transform: translate(...) scale(...) rotate(...);`처럼 한 선언으로 합치고, 그다음 함수 순서와 기준점을 조정한다.
</details>
## 한 줄 정리
> `transform`을 잘 다룬다는 것은 함수 이름만 외우는 일이 아니라, 기준점과 좌표, 조합 순서까지 읽어 원하는 시각적 변화를 예측하는 일이다.
