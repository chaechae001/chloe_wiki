# 페이지 레이아웃 워크숍 — 의미 구조에서 화면 흐름까지

> 한 페이지를 만드는 일은 상자를 예쁘게 놓는 것보다 정보의 역할을 먼저 나누는 일에서 시작합니다. 의미 있는 HTML 구조에 컨테이너·표시 방식·float 흐름을 차례로 연결하면 디버깅 가능한 레이아웃이 됩니다.

`semantic-html` · `container` · `navigation` · `article` · `debugging`

## 핵심요약
- `header`, `nav`, `main`, `article`, `footer`는 화면 위치가 아니라 콘텐츠 역할을 표현한다.
- 고정 너비 컨테이너는 `margin: 0 auto`로 좌우의 남는 공간을 균등하게 나눌 수 있다.
- 상단·본문·하단을 큰 구역부터 만든 뒤 내부 요소를 배치하면 오류 범위를 좁히기 쉽다.
- float 기반 열은 너비 합계, 부모의 포함 관계, 다음 구역의 `clear`를 함께 설계한다.
- 디버깅은 HTML 계층 → 큰 상자 크기 → 흐름 → 세부 장식 순서로 진행한다.

## 1. 의미 구조와 페이지 설계도
### 1) 정의
시맨틱 HTML은 콘텐츠가 어떤 역할을 하는지 태그 이름으로 드러내는 작성 방식입니다.
`header`는 도입부, `nav`는 주요 이동 경로, `main`은 핵심 콘텐츠, `article`은 독립적으로 이해 가능한 글, `footer`는 문서의 마무리 정보를 나타냅니다.

### 2) 왜 필요한가
모든 구역을 `div`로 만들면 화면은 비슷하게 보일 수 있지만 코드를 읽는 사람이 각 상자의 목적을 다시 추측해야 합니다.
역할이 드러나는 구조는 스타일 수정, 접근성 확인, 검색 엔진 해석, 팀 협업에서 공통 기준이 됩니다.
### 3) 핵심 흐름 재구성
페이지를 만들기 전에 콘텐츠를 상단·본문·하단으로 나눕니다.
상단에서는 페이지 제목과 주요 메뉴를 분리하고, 본문에서는 독립된 기록을 여러 `article`로 묶습니다.
마지막으로 하단에 문서의 보조 설명을 둡니다.
```text
body
└─ .page
   ├─ header
   │  ├─ h1
   │  └─ nav
   ├─ main
   │  ├─ article
   │  ├─ article
   │  └─ article
   └─ footer
```
### 4) 쉬운 예시
작은 독서 기록 페이지를 책 한 권처럼 생각해 봅시다.
표지와 목차 역할은 `header`와 `nav`, 실제 기록은 `main`, 각 기록 한 편은 `article`, 마무리 안내는 `footer`가 맡습니다.
### 5) 코드 예시
```html
<header class="page-header">
  <h1>작은 독서 기록</h1>
  <nav aria-label="주요 메뉴">
    <a href="#recent">최근 기록</a>
    <a href="#themes">주제</a>
  </nav>
</header>
<main id="recent">
  <article>
    <h2>천천히 읽는 기술</h2>
    <p>속도보다 질문을 남기는 읽기를 정리합니다.</p>
  </article>
</main>
<footer>한 문장씩 오래 남기는 기록</footer>
```
태그만 읽어도 각 구역의 역할과 콘텐츠 계층을 파악할 수 있습니다.
### 6) 헷갈리는 점
시맨틱 태그는 특정 디자인을 자동으로 보장하지 않습니다.
`header`가 항상 화면 최상단에 고정되는 것도 아니며, `footer`가 반드시 화면 바닥에 붙는 것도 아닙니다. 의미는 HTML이, 배치는 CSS가 담당합니다.

### 7) 한 줄 정리
> 페이지 설계는 보이는 위치보다 정보의 역할을 태그로 표현하는 데서 시작한다.

## 2. 컨테이너와 상단·본문·하단 구성
### 1) 정의
컨테이너는 여러 페이지 구역의 너비와 정렬 기준을 하나로 묶는 바깥 상자입니다.
고정 너비 컨테이너에 `margin: 0 auto`를 적용하면 좌우 자동 마진이 남은 공간을 반씩 나눠 상자가 가운데 놓입니다.
### 2) 왜 필요한가
각 구역마다 다른 너비와 왼쪽 시작점을 사용하면 제목, 카드, 하단 문구의 축이 어긋납니다.
하나의 컨테이너 기준을 사용하면 상단·본문·하단이 같은 세로선을 공유해 화면이 안정적으로 보입니다.
### 3) 핵심 흐름 재구성
먼저 전체 너비를 정한 뒤 큰 세 구역을 위에서 아래로 쌓습니다.
그다음 상단 안에서 제목과 메뉴, 본문 안에서 카드 열, 하단 안에서 마무리 문구를 배치합니다.
```css
.page {
  width: 880px;
  margin: 0 auto;
}
```
뷰포트가 `1200px`이라면 남는 가로 공간은 `320px`이고, 자동 마진은 왼쪽과 오른쪽에 각각 `160px`씩 배분됩니다.
### 4) 쉬운 예시
액자를 벽 가운데 거는 과정과 비슷합니다. 액자 너비를 먼저 정하고 벽의 남는 공간을 양쪽에 똑같이 나누면 중심이 맞습니다.
### 5) 코드 예시
```css
body {
  margin: 0;
  color: #27324a;
  background: #f3f5f9;
}
.page {
  width: 880px;
  margin: 0 auto;
  background: white;
}
.page-header,
.records,
.page-footer {
  padding: 24px 32px;
}
```
세 구역이 같은 컨테이너와 좌우 패딩을 공유하므로 텍스트 시작선이 맞습니다.
### 6) 헷갈리는 점
`margin: 0 auto`는 너비가 계산 가능한 상자에서 가로 가운데 정렬을 만들 때 유효합니다.

요소가 부모 너비를 이미 모두 차지한다면 좌우에 나눌 남는 공간이 없어 시각적 변화가 없습니다.
고정 너비가 화면보다 넓으면 가로 스크롤이 생길 수 있으므로 실제 서비스에서는 `max-width`와 유동 너비를 함께 고려합니다.
### 7) 한 줄 정리
> 컨테이너는 페이지의 공통 너비와 정렬 축을 정의해 모든 구역을 하나의 화면 체계로 묶는다.

## 3. 카드 배치와 디버깅 순서
### 1) 정의
통합 레이아웃 디버깅은 보이는 오류를 무작정 고치는 것이 아니라 구조와 흐름을 큰 단위부터 검증하는 과정입니다.
본문 카드를 float로 두 열 배치한다면 부모의 포함 관계와 하단의 시작 위치까지 하나의 묶음으로 확인합니다.
### 2) 왜 필요한가
작은 패딩 하나를 먼저 조절하면 구조적인 너비 초과나 float 영향이 가려질 수 있습니다.
검사 순서를 정하면 같은 증상을 반복해서 고치는 일을 줄이고 원인이 있는 상위 단계에서 해결할 수 있습니다.
### 3) 핵심 흐름 재구성
다음 순서로 확인하면 오류 범위를 빠르게 좁힐 수 있습니다.
1. HTML 닫는 태그와 부모·자식 계층이 올바른지 본다.
2. 컨테이너와 큰 구역에 임시 테두리를 넣어 실제 영역을 확인한다.
3. `box-sizing`, 너비, 패딩, 테두리의 합이 부모 너비를 넘는지 계산한다.
4. 계산된 `display`, `float`, `clear`를 확인한다.
5. 부모가 float 자식의 높이를 포함하는지 본다.
6. 마지막에 색상, 글꼴, 미세 여백을 조정한다.
### 4) 쉬운 예시
카드 두 장이 한 줄에 있어야 하는데 두 번째 카드가 내려갔다면 글자색부터 바꾸지 않습니다.
각 카드의 너비와 패딩을 합한 값, 카드 사이 마진, `box-sizing` 적용 여부를 먼저 계산합니다.
### 5) 코드 예시
```css
.records {
  display: flow-root;
}
.record-card {
  float: left;
  width: 48%;
  margin: 0 4% 24px 0;
}
.record-card:nth-child(2n) {
  margin-right: 0;
}
.page-footer {
  clear: both;
}
```
홀수 카드의 `48%`와 오른쪽 간격 `4%`, 짝수 카드의 `48%`를 더하면 정확히 `100%`가 됩니다.
### 6) 헷갈리는 점
하단이 위로 올라온다고 해서 하단 자체의 위치 속성만 문제인 것은 아닙니다.
원인은 본문 카드의 float, 부모 높이, 너비 초과처럼 앞선 구역에 있을 수 있습니다.
### 7) 한 줄 정리
> 통합 레이아웃은 오류가 보이는 요소보다 흐름을 만든 앞선 요소부터 검사해야 한다.

## 코드로 보기 — 작은 독서 기록 카드 페이지
```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>작은 독서 기록</title>
  <style>
    *, *::before, *::after { box-sizing: border-box; }
    body { margin: 0; color: #27324a; background: #f3f5f9; font-family: sans-serif; }
    a { color: inherit; text-decoration: none; }
    ul { margin: 0; padding: 0; list-style: none; }
    .page { width: 880px; margin: 32px auto; background: #fff; border: 1px solid #dbe1eb; }
    .page-header { display: flow-root; padding: 24px 32px; border-bottom: 1px solid #dbe1eb; }
    .page-header h1 { float: left; margin: 0; font-size: 26px; }
    .page-header nav { float: right; }
    .page-header li { float: left; margin-left: 8px; }
    .page-header a { display: block; padding: 8px 12px; background: #eef2ff; }
    .records { display: flow-root; padding: 32px; }
    .records > h2 { margin: 0 0 20px; }
    .record-card {
      float: left; width: 48%; min-height: 160px;
      margin: 0 4% 24px 0; padding: 20px;
      border: 1px solid #cad3e2; background: #fffaf0;
    }
    .record-card:nth-of-type(2n) { margin-right: 0; }
    .record-card h3 { margin: 0 0 12px; }
    .record-card p { margin: 0; line-height: 1.7; }
    .page-footer { clear: both; padding: 20px 32px; color: #fff; background: #27324a; }
  </style>
</head>
<body>
  <div class="page">
    <header class="page-header">
      <h1>작은 독서 기록</h1>
      <nav aria-label="주요 메뉴">
        <ul>
          <li><a href="#recent">최근 기록</a></li>
          <li><a href="#themes">읽기 주제</a></li>
        </ul>
      </nav>
    </header>
    <main class="records" id="recent">
      <h2>최근 남긴 문장</h2>
      <article class="record-card">
        <h3>질문을 남기는 읽기</h3><p>모르는 말을 한 문장의 질문으로 바꾸어 적었습니다.</p>
      </article>
      <article class="record-card">
        <h3>구조를 찾는 읽기</h3><p>문단의 역할을 붙여 글의 흐름을 지도처럼 정리했습니다.</p>
      </article>
      <article class="record-card" id="themes">
        <h3>다시 읽을 표시</h3><p>근거가 궁금한 대목을 다음 읽기의 출발점으로 삼았습니다.</p>
      </article>
      <article class="record-card">
        <h3>한 문장 요약</h3><p>읽은 내용을 설명하듯 한 문장으로 줄였습니다.</p>
      </article>
    </main>
    <footer class="page-footer">읽은 뒤에는 질문 하나를 남깁니다.</footer>
  </div>
</body>
</html>
```
### 코드 목적
의미 구조를 유지하면서 너비 `880px`의 중앙 컨테이너에 상단 메뉴, 두 열 카드 본문, 전체 너비 하단을 구성합니다.
### 코드 흐름
1. `header` 안에서 제목과 `nav`를 좌우로 배치한다.
2. 메뉴 링크를 블록으로 바꿔 충분한 클릭 영역을 만든다.
3. `main` 안의 `article`을 `48% + 4% + 48%` 비율로 두 열 배치한다.
4. `flow-root`로 상단과 본문이 float 자식을 감싸게 한다.
5. `footer`에서 앞선 float 흐름을 확실히 끊고 페이지를 마무리한다.
### 예상 렌더링
```text
┌──────────────────────────────────────────┐
│ 작은 독서 기록          최근 기록 | 읽기 주제 │
├──────────────────────────────────────────┤
│ 최근 남긴 문장                            │
│ ┌────────────────┐ ┌────────────────┐    │
│ │ 질문을 남기는 읽기 │ │ 구조를 찾는 읽기 │    │
│ └────────────────┘ └────────────────┘    │
│ ┌────────────────┐ ┌────────────────┐    │
│ │ 다시 읽을 표시   │ │ 한 문장 요약      │    │
│ └────────────────┘ └────────────────┘    │
├──────────────────────────────────────────┤
│ 읽은 뒤에는 질문 하나를 남깁니다.           │
└──────────────────────────────────────────┘
```
### 실행 결과 해석
뷰포트가 컨테이너보다 넓으면 좌우 자동 마진이 같은 크기로 계산되어 페이지가 가운데 놓입니다. 카드 두 장과 사이 간격의 합은 `100%`이므로 한 줄에 두 장씩 배치되며, 하단은 본문 아래에서 전체 너비를 사용합니다.
### 실무 연결
콘텐츠 목록, 포트폴리오 카드, 간단한 소개 페이지처럼 상단 탐색과 반복 카드가 필요한 화면의 기초 골격으로 활용할 수 있습니다. 이후 반응형 요구가 생기면 컨테이너를 유동 너비로 바꾸고 카드 배치 기술을 확장하면 됩니다.

## 직접 해보기
1. 페이지의 핵심 콘텐츠를 여러 독립 기록으로 나눌 때 사용할 두 시맨틱 태그는 무엇인가요?
2. 카드 너비가 각각 `47%`이고 첫 카드의 오른쪽 마진이 `6%`라면 한 행의 합은 얼마이며 두 카드가 들어갈 수 있나요?
3. 하단이 카드 옆으로 올라오고 본문 배경도 카드 높이를 감싸지 못할 때 어떤 순서로 수정할 수 있나요?
<details>
<summary>정답 보기</summary>

1. 전체 핵심 영역에는 `main`, 독립 기록 하나에는 `article`을 사용할 수 있습니다. 태그가 콘텐츠의 역할을 드러냅니다.
2. `47% + 6% + 47% = 100%`이므로 패딩과 테두리가 너비 안에 포함된다는 전제에서 두 카드가 한 행에 들어갑니다.
3. 먼저 본문의 실제 너비 합계를 확인하고, 본문 부모에 `display: flow-root`를 적용해 float 자식을 포함시킵니다. 이어서 하단에 `clear: both`가 있는지 확인합니다.
</details>

## 헷갈리기 쉬운 포인트
| 헷갈리는 개념 | 차이 |
|---|---|
| `header` vs `head` | 화면의 도입 구역과 문서 메타정보를 담는 비표시 영역의 차이 |
| `main` vs `article` | 페이지의 핵심 콘텐츠 전체와 독립적으로 이해 가능한 콘텐츠 한 단위 |
| 컨테이너 중앙 정렬 vs 텍스트 중앙 정렬 | `margin: 0 auto`는 상자를, `text-align: center`는 내부 인라인 콘텐츠를 정렬 |
| 구조 디버깅 vs 장식 조정 | 부모·너비·흐름을 확인하는 과정과 색상·글꼴·미세 여백을 다듬는 과정 |

### 복습 질문 및 답변
**Q1. `article`을 사용하기 좋은 콘텐츠는 어떤 콘텐츠인가요?**
<details>
<summary>답</summary>

페이지에서 떼어 내어 읽어도 제목과 본문만으로 의미를 이해할 수 있는 글이나 카드입니다. 독서 기록 한 편, 소식 한 건, 게시글 한 편이 예가 됩니다.
</details>
**Q2. 너비 `880px` 컨테이너가 너비 `1200px` 화면에서 가운데 놓이면 좌우 마진은 각각 얼마인가요?**
<details>
<summary>답</summary>

남는 공간은 `1200 - 880 = 320px`이고 이를 좌우가 반씩 나누므로 각각 `160px`입니다.
</details>
**Q3. 두 번째 카드가 다음 줄로 밀렸을 때 가장 먼저 무엇을 확인해야 하나요?**
<details>
<summary>답</summary>

카드 두 장의 실제 너비와 사이 마진, 패딩, 테두리 합이 부모 너비를 넘는지 확인합니다. 이어서 `box-sizing`과 float 방향을 검사한 뒤 세부 스타일을 봅니다.
</details>
