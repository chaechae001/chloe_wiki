# CSS 선택자와 캐스케이드 — 원하는 요소에 예측 가능한 스타일 적용하기
> 같은 속성을 여러 번 작성했는데도 브라우저가 하나의 값만 보여 주는 데에는 분명한 규칙이 있다.
> 선택자가 가리키는 범위와 우선순위를 함께 이해하면 CSS 충돌을 추측이 아니라 계산으로 해결할 수 있다.

`CSS 문법` · `선택자` · `상속` · `구체성` · `캐스케이드`
## 핵심요약
- CSS 규칙은 `선택자 { 속성: 값; }` 구조로 작성하고, HTML과 스타일을 분리할수록 관리가 쉬워진다.
- 타입 선택자는 같은 태그 전체, 클래스 선택자는 재사용 가능한 묶음, ID 선택자는 문서 안의 고유 요소를 겨냥한다.
- 공백을 둔 후손 선택자는 특정 영역 안에 있는 요소만 골라 전역 스타일의 부작용을 줄인다.
- 상속은 부모의 일부 글자 관련 속성을 자식이 이어받는 현상이며, 모든 속성이 상속되는 것은 아니다.
- 규칙이 충돌하면 중요도와 선언 위치, 선택자 구체성, 작성 순서를 차례로 따져 최종 값을 결정한다.
---
## 1. CSS 규칙과 연결 방식
### 1) 정의
CSS는 HTML 요소의 색, 글꼴, 크기, 배치처럼 화면에 보이는 표현을 지정하는 언어다.
하나의 규칙은 대상을 고르는 **선택자**, 바꿀 항목인 **속성**, 실제 설정인 **값**으로 이루어진다.
```css
.notice {
  color: navy;
  text-align: center;
}
```
### 2) 왜 필요한가
HTML이 정보의 의미와 구조에 집중하고 CSS가 표현을 맡으면 같은 구조를 여러 화면에서 재사용할 수 있다.
디자인 변경이 생겨도 마크업 전체를 고치지 않고 스타일 규칙만 수정할 수 있어 유지보수가 단순해진다.
### 3) 핵심 흐름
1. HTML에서 꾸밀 대상을 태그, 클래스, ID로 표시한다.
2. CSS 선택자로 그 대상을 가리킨다.
3. 중괄호 안에 `속성: 값;` 쌍을 작성한다.
4. 브라우저가 규칙을 모아 충돌을 해결한 뒤 화면을 그린다.

CSS를 연결하는 방식은 세 가지다.

| 방식 | 작성 위치 | 적합한 상황 | 주의점 |
|---|---|---|---|
| 인라인 | 요소의 `style` 속성 | 한 요소의 빠른 확인 | 구조와 표현이 섞이고 우선순위가 높다 |
| 내부 스타일 | 문서의 `<style>` | 한 페이지짜리 예제 | 여러 페이지에서 재사용하기 어렵다 |
| 외부 스타일 | 별도 스타일 문서와 `<link>` | 여러 페이지의 공통 디자인 | 연결 경로를 정확히 지정해야 한다 |
### 4) 쉬운 예시
인라인 방식은 메모지 한 장에 직접 색을 칠하는 것과 비슷하다.
내부 스타일은 한 방의 규칙표, 외부 스타일은 건물 전체가 함께 보는 디자인 안내서에 가깝다.
### 5) 코드 예시
```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>스타일 연결</title>
  <link rel="stylesheet" href="styles.css">
  <style>
    .local-note { color: teal; }
  </style>
</head>
<body>
  <h1 class="local-note">오늘의 공지</h1>
  <p style="font-weight: bold;">운영 시간이 변경되었습니다.</p>
</body>
</html>
```
```css
/* styles.css */
body {
  font-family: Arial, sans-serif;
  color: #222;
}
```
### 6) 헷갈리는 점
- 세미콜론은 마지막 선언에서 생략할 수 있어도 항상 붙이는 습관이 안전하다.
- `font-size = 18px`가 아니라 `font-size: 18px;`처럼 콜론과 세미콜론을 쓴다.
- 외부 스타일은 HTML에 CSS 코드를 복사하는 방식이 아니라 `<link>`로 연결하는 방식이다.
### 7) 한 줄 정리
> CSS 규칙은 대상을 고르고 속성에 값을 지정하며, 외부 연결이 여러 화면을 일관되게 관리하기 좋다.

## 2. 타입·클래스·ID·후손 선택자
### 1) 정의
선택자는 스타일을 적용할 HTML 요소를 찾는 표현식이다.
타입은 태그 이름, 클래스는 `.이름`, ID는 `#이름`, 후손 선택자는 `조상 후손`처럼 공백으로 표현한다.
### 2) 왜 필요한가
모든 제목을 한꺼번에 꾸밀 때와 특정 카드의 제목만 꾸밀 때는 대상 범위가 다르다.
선택자를 알맞게 고르면 불필요한 중복 클래스를 줄이고 다른 영역의 디자인이 함께 바뀌는 사고를 막을 수 있다.
### 3) 핵심 흐름
| 선택자 | 예 | 선택 범위 | 대표 용도 |
|---|---|---|---|
| 타입 | `p` | 모든 `p` | 기본 문단 스타일 |
| 클래스 | `.card` | `class="card"`인 모든 요소 | 반복되는 UI |
| ID | `#hero` | `id="hero"`인 고유 요소 | 한 영역 식별 |
| 후손 | `.card h2` | `.card` 내부의 모든 `h2` | 영역을 한정한 스타일 |
| 결합 | `li.active` | 클래스가 `active`인 `li` | 태그와 상태를 동시에 제한 |

`li.active`에는 공백이 없으므로 같은 요소가 두 조건을 모두 만족해야 한다.
반면 `li .active`는 `li` 안쪽 어딘가에 있는 별도 후손 요소를 찾는다.
### 4) 쉬운 예시
타입 선택자는 “모든 의자”, 클래스 선택자는 “예약석 표지가 붙은 의자들”, ID 선택자는 “A-17 좌석 하나”를 고르는 것과 같다.
후손 선택자는 “2층 열람실 안의 의자”처럼 먼저 구역을 좁힌 뒤 대상을 찾는다.
### 5) 코드 예시
```html
<section id="catalog">
  <article class="card featured">
    <h2>주간 추천</h2>
    <p class="summary">가볍게 읽기 좋은 글입니다.</p>
  </article>
  <article class="card">
    <h2>새 글</h2>
    <p class="summary">최근 업데이트를 모았습니다.</p>
  </article>
</section>
```
```css
h2 { color: #333; }
.card { border: 1px solid #bbb; }
#catalog { background-color: #f7f7f7; }
.card h2 { margin-bottom: 8px; }
article.featured { border-color: tomato; }
```
### 6) 헷갈리는 점
- 클래스는 여러 요소가 공유할 수 있고 한 요소가 여러 클래스를 가질 수도 있다.
- ID는 한 문서에서 고유하게 쓰는 식별자이므로 반복 UI의 디자인에는 클래스가 더 알맞다.
- `header p`는 직계 자식뿐 아니라 더 깊이 들어간 모든 `p`도 선택한다.
### 7) 한 줄 정리
> 선택자는 넓은 기본 규칙에서 시작해 클래스와 구조 관계로 필요한 범위만 좁히는 도구다.

## 3. 상속과 캐스케이드
### 1) 정의
상속은 부모 요소에 지정한 일부 속성값을 자식 요소가 별도 선언 없이 이어받는 동작이다.
캐스케이드는 한 요소의 같은 속성에 여러 후보가 있을 때 최종 값을 고르는 전체 결정 과정이다.
### 2) 왜 필요한가
부모에 글자색과 글꼴을 한 번만 선언하면 내부 문장에 일관된 디자인을 적용할 수 있다.
동시에 예외 요소는 더 직접적인 규칙으로 덮어쓸 수 있어 기본값과 변형을 함께 운영할 수 있다.
### 3) 핵심 흐름
글자색과 글꼴 계열은 대체로 상속되지만 `margin`, `padding`, `border`, `width`, `height` 같은 박스 속성은 기본적으로 상속되지 않는다.
충돌을 판단할 때는 다음 질문을 순서대로 확인한다.

1. 해당 요소에 직접 선언된 값이 있는가, 아니면 부모에게서 상속된 값뿐인가?
2. 인라인 선언처럼 선언 위치의 영향이 큰 규칙이 있는가?
3. 어느 선택자가 더 구체적인가?
4. 구체성이 같다면 어느 규칙이 뒤에 작성되었는가?

간단한 구체성 비교는 `ID > 클래스 > 타입`으로 기억할 수 있다.
후손 선택자는 포함된 선택자의 점수를 합쳐 비교하므로 `.panel p`가 `p`보다 구체적이다.
### 4) 쉬운 예시
가족의 기본 식사 시간을 부모가 정해 두면 자녀도 그 시간을 따르는 것이 상속이다.
하지만 한 사람에게만 별도 일정이 있으면 직접 지정된 일정이 기본 일정보다 먼저 적용된다.
### 5) 코드 예시
```html
<section class="panel">
  <h2 id="headline" class="accent">상태 알림</h2>
  <p>기본 안내 문장</p>
</section>
```
```css
.panel { color: #555; }
h2 { color: green; }
.panel h2 { color: blue; }
.accent { color: purple; }
#headline { color: crimson; }
```
`p`에는 직접 색을 지정하지 않았으므로 `.panel`의 `#555`를 상속받는다.
`h2`에는 여러 규칙이 맞지만 ID 선택자가 가장 구체적이므로 최종 글자색은 `crimson`이다.
### 6) 헷갈리는 점
- “나중에 쓴 규칙이 이긴다”는 말은 구체성 등 앞선 조건이 같을 때만 맞다.
- 부모의 높은 구체성이 자식의 직접 선언을 무조건 이기는 것은 아니다. 상속값은 직접 지정한 값보다 약하다.
- 선택자가 길다고 항상 강한 것은 아니다. 포함된 ID, 클래스, 타입의 종류와 개수를 비교해야 한다.
### 7) 한 줄 정리
> 상속은 기본값을 전달하고, 캐스케이드는 직접 선언과 구체성, 순서를 비교해 최종값을 정한다.

## 코드로 보기 — 한 카드에서 우선순위 추적하기
```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>캐스케이드 추적</title>
  <style>
    body { color: #444; }
    h2 { color: seagreen; }
    .card h2 { color: royalblue; }
    .title { color: darkorange; }
    #today { color: rebeccapurple; }
    .card p { color: #666; }
    .card p { color: #222; }
  </style>
</head>
<body>
  <article class="card">
    <h2 id="today" class="title">오늘의 일정</h2>
    <p>오후 두 시에 회의가 있습니다.</p>
    <small>변경 사항은 다시 안내합니다.</small>
  </article>
</body>
</html>
```
### 코드 목적
한 요소에 여러 선택자가 동시에 맞을 때 최종 색이 어떻게 결정되는지, 상속과 작성 순서까지 한 번에 확인한다.
### 코드 흐름
1. `body`에 기본 글자색을 지정한다.
2. 제목에는 타입, 후손, 클래스, ID 규칙을 차례로 겹친다.
3. 문단에는 구체성이 같은 규칙을 두 번 작성한다.
4. 직접 규칙이 없는 `small`은 부모 쪽 값을 상속받는다.
### 예상 렌더링
```text
제목: 보라색(rebeccapurple)
문단: 짙은 회색(#222)
작은 안내: 기본 회색(#444)
```
### 결과 해석
제목은 ID 선택자 `#today`가 타입, 후손, 클래스 규칙보다 구체적이어서 보라색이 된다.
문단은 두 규칙의 구체성이 같으므로 뒤에 작성된 `#222`가 적용된다.
`small`은 직접 색이 없어서 `body`의 `#444`를 상속받는다.
### 실무 연결
컴포넌트의 색이 예상과 다를 때 개발자 도구에서 취소선 처리된 선언을 보면 어떤 규칙이 경쟁에서 밀렸는지 알 수 있다.
선택자를 무작정 더 길게 만들기보다 공통 클래스와 변형 클래스를 분리하면 우선순위 경쟁을 줄일 수 있다.

## 헷갈리기 쉬운 포인트
| 헷갈리는 개념 | 차이 |
|---|---|
| 클래스 vs ID | 클래스는 반복 가능한 스타일 묶음, ID는 문서 안의 고유 요소 식별 |
| `li.active` vs `li .active` | 앞은 클래스가 붙은 `li` 자체, 뒤는 `li` 내부의 별도 후손 |
| 상속 vs 캐스케이드 | 상속은 부모 값 전달, 캐스케이드는 모든 후보 중 최종값 결정 |
| 구체성 vs 작성 순서 | 먼저 구체성을 비교하고, 같을 때 뒤의 규칙이 우선 |
| 내부 스타일 vs 외부 스타일 | 한 문서 안에서 관리 vs 여러 문서가 공통 규칙을 공유 |

- [ ] 구체성과 작성 순서로 최종 스타일을 예측할 수 있다.
### 복습 질문 및 답변
**Q1. 기본 — 클래스 선택자는 어떻게 표기하며 언제 적합한가?**

<details>
<summary>답</summary>

점과 이름을 붙인 `.card`처럼 표기한다. 같은 디자인을 여러 요소에서 반복하거나 한 요소에 여러 역할을 조합할 때 적합하다.

</details>

**Q2. 이해 확인 — 부모의 글자색이 자식에게 보이는데 자식의 테두리는 생기지 않는 이유는?**

<details>
<summary>답</summary>

글자색은 기본적으로 상속되는 속성이지만 테두리는 각 요소의 박스에 직접 지정하는 속성이어서 기본 상속 대상이 아니기 때문이다.

</details>

**Q3. 응용 — 특정 제목의 색이 바뀌지 않을 때 어떤 순서로 원인을 찾으면 좋은가?**

<details>
<summary>답</summary>

선택자가 실제 요소와 맞는지 확인하고, 인라인 선언 여부, ID·클래스·타입의 구체성, 같은 구체성에서의 작성 순서를 차례로 확인한다.

</details>
