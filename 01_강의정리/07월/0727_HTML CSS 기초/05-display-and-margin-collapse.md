# display와 마진 병합 — 요소의 자리 잡는 방식을 읽는 법

> 태그를 나란히 놓았는데 줄이 바뀌거나, 여백 두 개를 더했는데 예상보다 좁게 보일 때가 있습니다. 이 현상은 브라우저가 요소의 표시 방식과 세로 마진을 계산하는 규칙을 알면 예측할 수 있습니다.

`block` · `inline` · `inline-block` · `display` · `margin-collapse`

## 핵심요약
- 블록 요소는 새 줄에서 시작하고, 인라인 요소는 글의 흐름 안에서 이어진다.
- `display`는 태그의 기본 표시 방식을 레이아웃 목적에 맞게 바꾼다.
- `inline-block`은 같은 줄 배치와 너비·높이 지정을 함께 사용할 때 유용하다.
- 세로 방향으로 맞닿은 블록 마진은 더해지지 않고 하나의 마진으로 병합될 수 있다.
- 여백이 예상과 다르면 요소의 표시 방식, 맞닿은 경계, 부모의 경계 유무를 순서대로 확인한다.

## 1. 블록과 인라인의 흐름
### 1) 정의
블록 요소는 일반 흐름에서 한 줄의 자리를 차지하며 다음 요소를 아래 줄로 보냅니다.
`div`, `p`, `section`처럼 문서의 구역이나 문단을 만드는 요소가 대표적입니다.

인라인 요소는 문장 속 단어처럼 콘텐츠 너비만큼만 차지하며 같은 줄에 이어집니다.
`a`, `span`, `strong`처럼 텍스트 일부에 의미나 기능을 더하는 요소가 대표적입니다.

### 2) 왜 필요한가
레이아웃은 단순히 좌표를 지정하는 일이 아니라 요소가 원래 흐름에서 어떤 자리를 차지하는지 이해하는 일입니다.
이 차이를 모르면 인라인 링크에 `width`를 주고도 크기가 바뀌지 않거나, 블록 문단이 자동으로 줄을 바꾸는 이유를 설명하기 어렵습니다.
### 3) 핵심 흐름 재구성
브라우저는 먼저 각 요소의 `display` 계산값을 확인합니다.
그다음 블록이면 세로 흐름에 상자를 만들고, 인라인이면 현재 줄의 인라인 흐름에 콘텐츠를 놓습니다.

```text
요소 확인
  ├─ display: block  → 새 줄에서 시작 → 가로·세로 크기 지정 가능
  ├─ display: inline → 현재 줄에 이어짐 → 가로·세로 크기 지정에 제약
  └─ inline-block    → 현재 줄에 이어짐 → 상자 크기 지정 가능
```

### 4) 쉬운 예시
블록은 책장의 선반과 비슷합니다. 선반 하나가 가로 공간을 차지하므로 다음 선반은 아래에 놓입니다.
인라인은 한 줄에 붙이는 라벨과 비슷합니다. 라벨의 글자 길이만큼만 자리를 차지하고 다음 라벨이 옆에 붙습니다.
### 5) 코드 예시

```html
<p class="notice">오늘 읽을 분량</p>
<a class="tag" href="#">HTML</a>
<a class="tag" href="#">CSS</a>
```

```css
.notice {
  width: 240px;
  background: #eef2ff;
}
.tag {
  width: 90px;
  background: #fff4cc;
}
```

`p`의 너비는 적용되지만 기본 인라인인 `a`의 너비는 기대한 상자 너비로 작동하지 않습니다.

### 6) 헷갈리는 점
인라인 요소에 좌우 `padding`이나 `margin`은 보일 수 있지만, 위아래 공간이 주변 줄 높이와 직관적으로 맞지 않을 수 있습니다.
버튼처럼 명확한 상자를 만들 목적이라면 인라인의 기본 동작에 기대지 말고 표시 방식을 명시하는 편이 안전합니다.
### 7) 한 줄 정리
> 블록은 구역의 흐름을, 인라인은 문장 속 콘텐츠의 흐름을 만든다.

## 2. display 전환과 inline-block
### 1) 정의
`display`는 요소가 레이아웃에 참여하는 방식을 지정하는 CSS 속성입니다.

`block`과 `inline`으로 성격을 바꿀 수 있고, `inline-block`으로 두 방식의 장점을 조합할 수 있습니다.

### 2) 왜 필요한가
HTML 태그는 의미에 맞게 선택하고, 보이는 배치는 CSS로 조절하는 것이 좋습니다.
링크라는 의미를 유지하면서 메뉴 버튼처럼 크기를 주고 싶다면 태그를 `div`로 바꾸기보다 링크에 `display: inline-block`을 적용할 수 있습니다.
### 3) 핵심 흐름 재구성
표시 방식 변경은 태그의 의미를 바꾸지 않습니다.
`a`를 블록으로 표시해도 여전히 링크이며, `p`를 인라인으로 표시해도 문단이라는 의미는 남습니다.

따라서 먼저 의미에 맞는 태그를 고르고, 그다음 필요한 상자 동작을 `display`로 결정합니다.
### 4) 쉬운 예시
책갈피 링크 세 개를 한 줄에 놓되 모두 같은 크기로 만들고 싶다고 가정해 봅시다.
인라인만 사용하면 같은 줄에는 놓이지만 너비와 높이 제어가 어렵습니다.
블록만 사용하면 크기는 정하기 쉽지만 하나씩 줄이 바뀝니다.
`inline-block`은 한 줄 배치와 상자 크기 지정을 동시에 해결합니다.

### 5) 코드 예시

```html
<nav class="topics">
  <a href="#html">구조</a>
  <a href="#css">스타일</a>
  <a href="#layout">배치</a>
</nav>
```

```css
.topics a {
  display: inline-block;
  width: 88px;
  padding: 10px 0;
  text-align: center;
  border: 1px solid #8b94a7;
}
```

세 링크는 같은 줄에 놓이고 각각 `88px` 너비의 클릭 영역을 가집니다.
### 6) 헷갈리는 점
`display: none`은 요소를 투명하게 만드는 것이 아니라 레이아웃 자리까지 제거합니다.

또한 `inline-block` 요소 사이에는 HTML의 공백 문자가 작은 간격으로 보일 수 있습니다.
### 7) 한 줄 정리
> `inline-block`은 의미 있는 인라인 요소를 크기 조절 가능한 상자로 보여 주는 연결 고리다.

## 3. 세로 마진 병합
### 1) 정의
마진 병합은 일반 흐름의 블록 요소들이 세로 방향으로 맞닿을 때 여러 마진이 하나처럼 계산되는 현상입니다.
대표적으로 인접한 형제의 아래·위 마진과, 경계가 없는 부모와 첫 자식의 위 마진에서 나타납니다.
### 2) 왜 필요한가
문단과 제목마다 세로 여백을 지정해도 간격이 무한히 누적되지 않도록 브라우저가 문서 흐름을 정돈해 줍니다.
하지만 상자 배치를 픽셀 단위로 예상할 때는 병합 규칙이 뜻밖의 이동처럼 느껴질 수 있으므로 원리를 알아야 합니다.
### 3) 핵심 흐름 재구성
형제 요소의 `margin-bottom: 24px`과 `margin-top: 16px`이 맞닿으면 보통 간격은 `40px`이 아니라 큰 값인 `24px`이 됩니다.
부모의 위쪽에 `border`, `padding`, 인라인 내용이 없고 첫 자식의 위 마진이 경계에 맞닿으면 자식 마진이 부모 바깥쪽에서 보일 수 있습니다.

```text
형제 A의 아래 마진 24px
          ↓ 맞닿음
형제 B의 위 마진 16px
          ↓ 병합
실제 세로 간격 24px
```

### 4) 쉬운 예시
두 사람이 같은 복도에서 서로 `24m`, `16m` 떨어지겠다고 말해도 출발 경계가 같다면 거리는 두 값을 합친 것이 아니라 더 먼 기준 하나로 정해지는 것과 비슷합니다.
### 5) 코드 예시

```html
<section class="shelf">
  <h2>이번 달 기록</h2>
  <p>읽은 책을 짧게 정리합니다.</p>
</section>
```

```css
.shelf h2 { margin-bottom: 24px; }
.shelf p  { margin-top: 16px; }
```

두 요소 사이 간격은 일반적인 양수 마진 조건에서 `24px`로 보입니다.
### 6) 헷갈리는 점
가로 마진은 같은 방식으로 병합되지 않습니다.
또 `padding-top: 1px`이나 `border-top`처럼 부모와 자식의 마진이 직접 맞닿지 않게 하는 경계가 있으면 부모·자식 병합이 끊어집니다.
간격 제어만을 위해 무조건 작은 테두리를 숨겨 넣기보다, 부모의 `padding`으로 내부 여백을 표현하는 편이 의도가 분명합니다.
### 7) 한 줄 정리
> 마진 병합은 일반 흐름의 블록들이 맞닿은 세로 여백을 하나의 간격으로 정리하는 규칙이다.

## 코드로 보기 — 같은 줄의 메뉴와 예측 가능한 섹션 여백

```html
<section class="reading-section">
  <h2>주제별 기록</h2>
  <nav class="filter">
    <a href="#all">전체</a>
    <a href="#essay">에세이</a>
    <a href="#tech">기술</a>
  </nav>
</section>
```

```css
.reading-section {
  padding-top: 24px;
  border-bottom: 1px solid #d9deea;
}
.reading-section h2 {
  margin: 0 0 16px;
}
.filter a {
  display: inline-block;
  width: 80px;
  padding: 8px 0;
  text-align: center;
  background: #eef2ff;
}
```

### 코드 목적
링크를 같은 줄의 일정한 버튼으로 만들고, 부모의 내부 여백을 명시해 첫 자식 마진이 바깥으로 빠져나가는 혼란을 줄입니다.
### 코드 흐름
1. 의미에 맞게 메뉴 링크를 `a`로 작성한다.
2. 링크를 `inline-block`으로 바꿔 너비와 안쪽 여백을 적용한다.
3. 제목의 기본 마진을 명시적인 아래 마진으로 정리한다.
4. 섹션 위쪽 공간은 부모의 `padding-top`으로 만든다.
### 예상 렌더링

```text
주제별 기록
[  전체  ] [ 에세이 ] [  기술  ]
──────────────────────────────
```

### 실행 결과 해석
세 링크는 각각 `80px` 너비로 같은 줄에 배치됩니다. 섹션의 위쪽 `24px`은 부모 내부 여백이므로 첫 자식 마진 병합 여부에 흔들리지 않습니다.
### 실무 연결
탭 메뉴, 범주 필터, 작은 도구 모음처럼 한 줄에 놓이는 클릭 요소를 만들 때 이 조합을 사용할 수 있습니다.

## 직접 해보기
1. 인라인 링크에 너비와 높이를 주면서 같은 줄 배치를 유지하려면 어떤 표시 방식이 적합한가요?
2. 첫 형제의 아래 마진이 `18px`, 다음 형제의 위 마진이 `30px`일 때 일반적인 양수 마진 병합 결과는 얼마인가요?
3. 카드 섹션의 첫 제목이 부모 바깥쪽을 밀어내는 현상을 줄이려면 여백 책임을 어디에 두는 것이 명확한가요?
<details>
<summary>정답 보기</summary>

1. `display: inline-block`이 적합합니다. 같은 줄 흐름을 유지하면서 상자의 너비·높이·안쪽 여백을 제어할 수 있습니다.
2. `30px`입니다. 맞닿은 두 양수 세로 마진은 합산되지 않고 큰 값이 실제 간격이 됩니다.
3. 부모의 `padding-top`에 내부 여백 책임을 두는 방법이 명확합니다. 부모와 첫 자식의 마진이 직접 맞닿지 않아 결과도 예측하기 쉽습니다.
</details>

## 헷갈리기 쉬운 포인트
| 헷갈리는 개념 | 차이 |
|---|---|
| `block` vs `inline` | 새 줄에서 상자를 만드는 방식과 문장 흐름에 이어지는 방식의 차이 |
| `inline` vs `inline-block` | 둘 다 같은 줄에 놓이지만 후자는 너비·높이를 상자처럼 지정할 수 있음 |
| 형제 마진 vs 부모·자식 마진 | 형제는 맞닿은 위·아래 마진이 병합되고, 부모·자식은 경계가 없을 때 첫 자식 마진이 바깥으로 이어질 수 있음 |
| `margin` vs `padding` | 요소 바깥 간격과 요소 내부의 콘텐츠·테두리 사이 간격 |

<summary>답</summary>

아닙니다. 표시 방식만 블록으로 바뀌며 클릭해서 이동하는 링크의 의미와 기능은 유지됩니다.
</details>

<summary>답</summary>

일반 흐름에서 맞닿은 세로 마진은 병합될 수 있기 때문입니다. 두 양수 값이 맞닿으면 보통 큰 값 하나가 간격이 됩니다.
</details>
**Q3. 표시 방식과 여백 문제를 디버깅할 때 어떤 순서로 보면 좋을까요?**
<details>
<summary>답</summary>

먼저 개발자 도구에서 계산된 `display`를 확인하고, 다음으로 박스 모델의 마진 값을 봅니다. 마지막으로 형제 또는 부모·자식 경계가 직접 맞닿는지 확인하면 원인을 좁힐 수 있습니다.
</details>

## 한 줄 정리
> 요소의 자리는 `display`가 결정하고, 블록 사이의 세로 간격은 마진 병합 규칙까지 함께 봐야 정확히 예측할 수 있다.
