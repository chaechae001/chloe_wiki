# float와 clear — 떠 있는 요소 뒤의 흐름을 복구하기

> `float`는 요소 하나만 옆으로 옮기는 속성이 아니라 주변 콘텐츠가 흐르는 방식까지 바꿉니다. 그래서 배치 결과를 읽을 때는 떠 있는 상자와 일반 흐름에 남은 상자를 함께 살펴야 합니다.

`float` · `clear` · `normal-flow` · `clearfix` · `reset`

## 핵심요약
- `float`는 요소를 왼쪽이나 오른쪽에 붙이고 뒤따르는 인라인 콘텐츠가 그 둘레로 흐르게 한다.
- 떠 있는 요소는 일반 블록 흐름에서 빠지므로 부모 높이나 다음 요소의 위치가 예상과 달라질 수 있다.
- `clear`는 앞선 float 옆에 요소가 올라오는 것을 막고 필요한 아래쪽 위치로 이동시킨다.
- 기본 `margin`, 목록 기호, 링크 장식은 초기화 범위를 의식해서 정리한다.
- 레이아웃 붕괴를 막으려면 float의 시작과 끝, 부모 높이, 너비 합계를 함께 검토한다.

## 1. float와 주변 요소의 흐름
### 1) 정의
`float`는 선택한 상자를 컨테이너의 왼쪽 또는 오른쪽으로 이동시키고, 뒤따르는 인라인 콘텐츠가 남은 공간을 따라 흐르게 하는 속성입니다.

원래는 이미지 옆으로 글이 감싸 흐르는 편집 효과를 만들기 위해 사용되었습니다.
### 2) 왜 필요한가
이미지와 설명을 나란히 보여 주거나, 오래된 레이아웃에서 여러 박스를 가로로 배치한 구조를 이해하려면 float의 흐름을 알아야 합니다.
기존 코드 유지보수에서는 `float: left`와 `float: right`를 자주 만나므로, 단순한 좌우 정렬 속성으로만 이해하면 다음 요소가 겹치는 원인을 찾기 어렵습니다.
### 3) 핵심 흐름 재구성
브라우저는 float 상자를 가능한 한 왼쪽이나 오른쪽으로 옮깁니다.
그 상자는 문서에서 사라지는 것이 아니라 다른 콘텐츠가 피해서 흘러야 할 장애물처럼 남습니다.
뒤따르는 텍스트는 남은 가로 폭을 사용하지만, 일반 블록 상자의 배경이나 부모 높이 계산은 직관과 다르게 보일 수 있습니다.

```text
컨테이너
┌──────────┬─────────────────┐
│ float 상자│ 텍스트가 남은 폭을 │
│          │ 따라 여러 줄 흐름  │
└──────────┴─────────────────┘
```

### 4) 쉬운 예시
신문 기사에서 작은 사진을 왼쪽에 놓고 본문이 사진 오른쪽과 아래쪽을 따라 이어지는 모습을 떠올리면 됩니다.
사진은 왼쪽으로 부유하지만, 글은 사진이 차지한 영역을 피해서 흐릅니다.
### 5) 코드 예시

```html
<article class="note">
  <div class="cover">표지</div>
  <p>짧은 감상은 표지 옆에서 시작해 남은 너비를 따라 흐릅니다.</p>
</article>
```

```css
.cover {
  float: left;
  width: 96px;
  height: 128px;
  margin-right: 16px;
  background: #dce6ff;
}
```

문단의 첫 줄은 표지 오른쪽에서 시작하고, 글이 길어지면 표지 아래쪽의 전체 너비를 다시 사용합니다.
### 6) 헷갈리는 점
`float: left`는 상자들을 무조건 한 줄에 맞추는 명령이 아닙니다.

가용 너비가 부족하면 다음 float 상자는 아래로 내려가며, 각 상자의 실제 점유 폭에는 너비뿐 아니라 패딩·테두리·마진도 포함될 수 있습니다.
### 7) 한 줄 정리
> float는 상자를 한쪽에 붙이고 주변 콘텐츠의 흐름을 그 상자 둘레로 바꾼다.

## 2. clear와 레이아웃 붕괴 예방
### 1) 정의
`clear`는 요소의 어느 쪽에 앞선 float가 존재하는 것을 허용하지 않을지 지정합니다.

`clear: left`, `clear: right`, `clear: both`가 있으며, `both`는 좌우 float의 영향을 모두 피합니다.

### 2) 왜 필요한가
떠 있는 열 다음에 오는 하단 영역이 열 옆으로 올라오거나 겹쳐 보이는 현상을 막아야 합니다.
또 자식이 모두 float이면 부모가 일반 흐름에서 자식 높이를 충분히 감싸지 못하는 것처럼 보일 수 있어 별도의 포함 전략이 필요합니다.
### 3) 핵심 흐름 재구성
`clear`가 있는 요소는 지정된 방향의 float 아래로 내려갈 때까지 위치를 조정합니다.

따라서 좌우 열 뒤의 `footer`에 `clear: both`를 주면 두 열이 끝난 뒤부터 하단이 시작됩니다.
부모가 float 자식을 감싸게 하려면 `flow-root` 같은 새 블록 서식 문맥을 만드는 방법도 사용할 수 있습니다.

```css
.columns {
  display: flow-root;
}
.page-footer {
  clear: both;
}
```

### 4) 쉬운 예시
두 대의 보트가 강 좌우를 지나가고 있다고 생각해 봅시다.
다음 다리가 `clear: both`라면 어느 보트 옆에도 놓이지 않고 두 보트가 지난 아래쪽에서 시작합니다.
### 5) 코드 예시

```html
<main class="columns">
  <aside class="left-panel">목차</aside>
  <section class="content">본문</section>
</main>
<footer class="page-footer">읽기 기록 끝</footer>
```

```css
.left-panel {
  float: left;
  width: 28%;
}
.content {
  float: right;
  width: 68%;
}
.columns {
  display: flow-root;
}
.page-footer {
  clear: both;
}
```

두 열의 너비 합계는 `96%`이므로 남은 `4%`를 간격으로 활용할 수 있습니다.
### 6) 헷갈리는 점
`clear`는 앞선 요소의 `float`를 취소하지 않습니다. clear가 적용된 자기 자신의 시작 위치를 아래로 옮길 뿐입니다.

또 `overflow: hidden`으로 부모 높이를 복구하는 오래된 기법은 넘치는 콘텐츠를 잘라낼 수 있으므로 목적을 확인해야 합니다.
### 7) 한 줄 정리
> clear는 float를 제거하는 속성이 아니라 다음 요소가 float 옆에 놓이지 않도록 흐름을 재개하는 속성이다.

## 3. 기본 여백 초기화와 너비 계산
### 1) 정의
브라우저는 읽기 쉬운 기본 화면을 위해 `body`, 제목, 문단, 목록 등에 기본 마진이나 패딩을 적용합니다.
초기화는 이 기본값을 프로젝트의 디자인 규칙에 맞게 명시적으로 바꾸는 작업입니다.
### 2) 왜 필요한가
상단이 화면 가장자리에 닿지 않거나 목록 앞에 기호가 남는 이유가 작성한 CSS가 아니라 브라우저 기본 스타일일 수 있습니다.
레이아웃 기준점을 통일하면 float 열의 너비 합계와 컨테이너 위치를 더 쉽게 계산할 수 있습니다.
### 3) 핵심 흐름 재구성
작은 예제에서는 `box-sizing`, `body` 여백, 목록 스타일, 링크 장식 정도만 선택적으로 초기화해도 충분합니다.
모든 요소의 마진과 패딩을 무조건 `0`으로 만들면 제목과 문단 사이의 의미 있는 기본 간격까지 사라지므로 필요한 값을 다시 설계해야 합니다.
### 4) 쉬운 예시
새 공책의 줄 간격을 모두 지우는 것보다, 표지 여백과 목록 기호처럼 현재 설계에 방해되는 부분만 정리하는 방식이 유지보수에 유리합니다.
### 5) 코드 예시

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
body {
  margin: 0;
}
ul {
  margin: 0;
  padding: 0;
  list-style: none;
}
a {
  color: inherit;
  text-decoration: none;
}
```

`box-sizing: border-box`를 적용하면 선언한 너비 안에 패딩과 테두리가 포함되어 열 너비 합계를 계산하기 쉬워집니다.

### 6) 헷갈리는 점
초기화는 브라우저 오류를 고치는 과정이 아닙니다. 기본 스타일도 정상적인 출발값이며, 프로젝트가 다른 출발값을 선택하는 것입니다.
### 7) 한 줄 정리
> 초기화는 모든 스타일을 없애는 일이 아니라 레이아웃 계산의 공통 기준을 세우는 일이다.

## 코드로 보기 — 좌우 열과 안전한 하단 흐름

```html
<div class="layout">
  <main class="layout-body">
    <aside class="index">이번 주 목록</aside>
    <section class="records">독서 기록 두 편</section>
  </main>
  <footer class="footer">다음 기록은 금요일에 추가</footer>
</div>
```

```css
* { box-sizing: border-box; }
body { margin: 0; }
.layout {
  width: 720px;
  margin: 0 auto;
}
.layout-body {
  display: flow-root;
  padding: 24px 0;
}
.index {
  float: left;
  width: 180px;
  min-height: 160px;
  background: #eef2ff;
}
.records {
  float: right;
  width: 516px;
  min-height: 160px;
  background: #fff7e6;
}
.footer {
  clear: both;
  padding: 20px;
  background: #27324a;
  color: white;
}
```

### 코드 목적
고정 너비 컨테이너 안에 좌우 열을 배치하고, 부모 높이와 하단 시작 위치를 안정적으로 유지합니다.
### 코드 흐름
1. `border-box`와 `body` 마진 초기화로 계산 기준을 맞춘다.
2. 전체 컨테이너를 `margin: 0 auto`로 가운데 정렬한다.
3. 왼쪽과 오른쪽 열을 각각 float한다.
4. 부모에 `display: flow-root`를 주어 두 열을 감싸게 한다.
5. 하단에 `clear: both`를 두어 float 이후 흐름을 명시한다.
### 예상 렌더링

```text
┌──────────────┬────────────────────────────┐
│ 이번 주 목록 │ 독서 기록 두 편              │
│    180px     │            516px           │
└──────────────┴────────────────────────────┘
│ 다음 기록은 금요일에 추가                   │
└───────────────────────────────────────────┘
```

### 실행 결과 해석
전체 너비 `720px` 안에서 두 열 `180px + 516px`은 `696px`을 차지하고 `24px`의 여유를 남깁니다. 하단은 좌우 열 옆으로 올라오지 않고 두 열 아래에서 전체 너비로 이어집니다.
### 실무 연결
오래된 관리자 화면이나 이메일 템플릿처럼 float 기반 구조를 유지해야 할 때, 영향 범위를 컨테이너 안에 가두고 다음 구역을 안전하게 시작하는 패턴으로 활용할 수 있습니다.

## 헷갈리기 쉬운 포인트
| 헷갈리는 개념 | 차이 |
|---|---|
| `float` vs 일반 흐름 | float 상자는 한쪽으로 이동하고 주변 콘텐츠가 둘레로 흐르지만 일반 블록은 위에서 아래로 쌓임 |
| `clear` vs float 해제 | clear는 자기 위치를 float 아래로 옮기며 앞선 요소의 float 선언 자체를 바꾸지 않음 |
| `clear: left` vs `clear: both` | 왼쪽 float만 피하는 것과 좌우 float를 모두 피하는 것의 차이 |
| 전체 초기화 vs 선택적 초기화 | 모든 기본 간격을 지우는 방식과 필요한 기본값만 프로젝트 규칙으로 바꾸는 방식 |

<details>
<summary>답</summary>

해당 요소의 좌우에 앞선 float가 남지 않는 지점까지 시작 위치를 내리기 때문입니다. 그래서 하단이 열 옆이 아니라 열 아래에 배치됩니다.
</details>
**Q3. float 레이아웃이 깨졌을 때 어떤 순서로 확인하면 좋을까요?**
<details>
<summary>답</summary>

먼저 컨테이너와 열의 실제 너비 합계를 확인하고, 다음으로 각 요소의 float 방향을 봅니다. 이어서 부모가 float 자식을 포함하는지, 다음 구역에 clear가 필요한지, 기본 마진이 남았는지를 확인합니다.
</details>

## 한 줄 정리
> float 레이아웃은 떠 있는 상자의 방향만 보는 것이 아니라 주변 흐름, 부모의 포함 관계, clear로 다시 시작할 지점까지 함께 설계해야 한다.
