# CSS 박스 모델 — 보이는 크기와 여백을 정확히 계산하기
> 화면의 모든 요소는 내용만 있는 점이 아니라 네 겹의 사각형으로 공간을 차지한다.
> 박스 모델을 이해하면 “너비를 맞췄는데 왜 넘치지?” 같은 레이아웃 문제를 숫자로 설명하고 고칠 수 있다.

`content` · `padding` · `border` · `margin` · `box-sizing`
## 핵심요약
- 박스 모델은 안쪽부터 `content → padding → border → margin` 순으로 요소의 공간을 설명한다.
- `width`와 `height`는 기본 `content-box`에서 내용 영역의 크기만 지정한다.
- 실제 보이는 너비는 내용 너비에 좌우 패딩과 좌우 테두리를 더해 계산한다.
- `padding`은 테두리 안쪽, `margin`은 테두리 바깥쪽 여백이며 배경은 마진까지 칠해지지 않는다.
- 네 방향 축약형은 위쪽부터 시계 방향으로 읽고, `box-sizing: border-box`는 선언한 크기 안에 패딩과 테두리를 포함한다.
---
## 1. content·padding·border·margin
### 1) 정의
브라우저는 대부분의 HTML 요소를 사각형 박스로 계산한다.
가장 안쪽에는 텍스트나 이미지가 놓이는 `content`, 그 바깥에는 `padding`, `border`, `margin`이 차례로 둘러싼다.
```text
margin
└─ border
   └─ padding
      └─ content
```
### 2) 왜 필요한가
버튼의 글자와 테두리가 너무 붙거나, 카드 두 개가 서로 달라붙거나, 정해진 칸보다 요소가 넓어지는 문제는 모두 박스의 어느 층을 조절할지 판단해야 해결할 수 있다.
### 3) 핵심 흐름
| 영역 | 위치 | 역할 | 배경색이 보이는가 |
|---|---|---|---|
| `content` | 가장 안쪽 | 실제 내용이 놓이는 공간 | 예 |
| `padding` | 내용과 테두리 사이 | 내부 숨 쉴 공간 | 예 |
| `border` | 패딩 바깥 | 박스의 경계 | 자체 색으로 표시 |
| `margin` | 테두리 바깥 | 다른 요소와의 거리 | 아니요 |

패딩을 늘리면 내용과 테두리 사이가 넓어지고, 마진을 늘리면 요소 전체가 이웃과 멀어진다.
둘 다 “여백”이지만 기준선과 배경 처리, 크기 계산에서 역할이 다르다.
### 4) 쉬운 예시
액자를 떠올리면 사진이 `content`, 사진 주변의 매트지가 `padding`, 액자 틀이 `border`, 벽의 다른 액자와 떨어진 간격이 `margin`이다.
### 5) 코드 예시
```html
<article class="message-card">
  <h2>배송 안내</h2>
  <p>주문한 물품이 출발했습니다.</p>
</article>
```
```css
.message-card {
  width: 240px;
  padding: 20px;
  border: 4px solid #4f46e5;
  margin: 24px;
  background-color: #eef2ff;
}
```
### 6) 헷갈리는 점
- 배경색은 기본적으로 내용과 패딩 영역에 칠해지지만 마진에는 칠해지지 않는다.
- 마진은 요소 자체의 시각적 표면이 아니라 주변과의 거리다.
- 테두리 두께도 실제 화면에서 박스가 차지하는 크기에 포함된다.
### 7) 한 줄 정리
> 박스 모델은 내용, 내부 여백, 경계, 외부 간격을 서로 다른 층으로 나누어 다루는 공간 규칙이다.
---
## 2. width·height와 실제 박스 크기
### 1) 정의
`width`와 `height`는 요소의 가로와 세로 크기를 지정한다.
기본값인 `box-sizing: content-box`에서는 이 값이 전체 박스가 아니라 `content` 영역만 뜻한다.
### 2) 왜 필요한가
가로 300px로 지정한 카드가 실제로 300px보다 넓어지는 이유를 알아야 열 너비, 컨테이너, 버튼 크기를 정확히 맞출 수 있다.
### 3) 핵심 흐름
`content-box`에서 실제 보이는 너비와 높이는 다음처럼 계산한다.
```text
보이는 너비 = width + padding-left + padding-right + border-left + border-right
보이는 높이 = height + padding-top + padding-bottom + border-top + border-bottom
```
마진은 보이는 박스의 표면에는 포함되지 않지만 주변에서 요구하는 총 자리에는 더해진다.
```text
가로 점유 폭 = 보이는 너비 + margin-left + margin-right
```
### 4) 쉬운 예시
내용 너비가 240px이고 좌우 패딩이 각각 20px, 좌우 테두리가 각각 4px이라면 보이는 너비는 `240 + 20 + 20 + 4 + 4 = 288px`이다.
좌우 마진이 24px씩이면 주변 배치에서 필요한 가로 폭은 `288 + 24 + 24 = 336px`이다.
### 5) 코드 예시
```html
<div class="content-box">content-box</div>
<div class="border-box">border-box</div>
```
```css
.content-box,
.border-box {
  width: 240px;
  padding: 20px;
  border: 4px solid #333;
  margin-bottom: 12px;
}

.content-box { box-sizing: content-box; }
.border-box { box-sizing: border-box; }
```
`content-box`의 보이는 너비는 288px이고, `border-box`의 보이는 너비는 선언한 240px다.
후자는 240px 안에서 패딩과 테두리를 먼저 확보하고 남은 공간을 내용 영역으로 사용한다.
### 6) 헷갈리는 점
- `border-box`가 패딩과 테두리를 없애는 것은 아니다. 선언한 크기 안에 포함해 계산할 뿐이다.
- `%` 너비에 패딩을 더하면 기본 계산에서 부모 폭을 넘을 수 있다.
- 높이를 고정하면 내용이 길 때 넘침이 생길 수 있어 카드 본문에는 자동 높이가 더 안전한 경우가 많다.
### 7) 한 줄 정리
> `content-box`는 선언값이 내용 크기이고, `border-box`는 선언값이 테두리까지 포함한 보이는 크기다.

## 3. 네 방향 속성과 축약형
### 1) 정의
`margin`과 `padding`은 `-top`, `-right`, `-bottom`, `-left`로 한 방향씩 지정하거나 한 줄 축약형으로 작성할 수 있다.
### 2) 왜 필요한가
카드 안쪽의 위아래 간격과 좌우 간격을 다르게 주거나, 특정 방향만 이웃과 떨어뜨릴 때 방향 규칙을 알아야 한다.
축약형을 정확히 읽으면 짧은 코드로도 의도가 분명한 레이아웃을 만들 수 있다.
### 3) 핵심 흐름
| 값 개수 | 해석 | 예 |
|---|---|---|
| 1개 | 네 방향 모두 | `padding: 16px;` |
| 2개 | 위아래 / 좌우 | `padding: 12px 20px;` |
| 3개 | 위 / 좌우 / 아래 | `margin: 8px 16px 24px;` |
| 4개 | 위 / 오른쪽 / 아래 / 왼쪽 | `margin: 8px 12px 16px 20px;` |

네 값은 위에서 시작해 시계 방향으로 돈다고 기억하면 된다.
### 4) 쉬운 예시
`padding: 10px 24px;`은 위아래에는 10px, 좌우에는 24px의 공간을 두라는 뜻이다.
텍스트 버튼은 좌우 여백을 더 넓게 두는 경우가 많아 이 형태가 자주 쓰인다.
### 5) 코드 예시
```css
.action-button {
  padding: 10px 24px;
  margin: 0 8px 16px 0;
  border: 2px solid #0f766e;
}
```
위 코드는 버튼 안쪽은 세로 10px·가로 24px, 바깥쪽은 오른쪽 8px·아래 16px을 둔다.
### 6) 헷갈리는 점
- 네 값의 마지막은 오른쪽이 아니라 왼쪽이다.
- `border` 축약형은 방향 순서가 아니라 두께, 선 모양, 색을 한 번에 적는 다른 종류의 축약이다.
- 축약형을 다시 선언하면 이전에 개별 방향으로 지정한 값까지 함께 덮을 수 있다.
### 7) 한 줄 정리
> 네 방향 축약형은 위에서 시작해 시계 방향으로 읽고, 값 개수에 따라 서로 마주 보는 방향을 묶는다.

## 4. 테두리와 배경으로 박스 확인하기
### 1) 정의
`border`는 박스의 경계를 시각화하고, `background` 계열 속성은 내용과 패딩 영역의 바탕을 꾸민다.
### 2) 왜 필요한가
박스 모델을 배울 때 테두리와 배경을 켜면 각 영역이 어디까지인지 눈으로 확인할 수 있다.
실제 UI에서도 카드 구분, 상태 강조, 클릭 영역 표현에 같은 속성을 쓴다.
### 3) 핵심 흐름
테두리는 `border-width`, `border-style`, `border-color`로 나누어 쓰거나 `border: 2px solid #333;`처럼 합칠 수 있다.
배경은 색상, 이미지, 반복 여부, 위치를 각각 지정할 수 있으며 색상만으로도 박스 범위를 점검하기 충분하다.
### 4) 쉬운 예시
중요 공지 카드는 옅은 배경색과 진한 왼쪽 테두리를 주면 내용 영역을 명확히 구분하면서 상태도 전달할 수 있다.
### 5) 코드 예시
```css
.alert {
  padding: 16px 20px;
  border-left: 6px solid #dc2626;
  background-color: #fef2f2;
  color: #7f1d1d;
}
```
### 6) 헷갈리는 점
- `border` 축약형 값 사이에는 쉼표를 쓰지 않는다.
- `border-style`이 없으면 두께와 색을 지정해도 테두리가 보이지 않을 수 있다.
- 배경 이미지는 콘텐츠를 대체하지 않으므로 의미 있는 정보는 HTML 텍스트로도 전달해야 한다.
### 7) 한 줄 정리
> 테두리와 배경은 장식뿐 아니라 박스의 경계와 내부 영역을 확인하는 시각적 도구다.
---
## 코드로 보기 — 계산 가능한 알림 카드 만들기
```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>박스 모델 계산</title>
  <style>
    * { box-sizing: border-box; }
    body { margin: 0; font-family: Arial, sans-serif; }
    .notice {
      width: 320px;
      padding: 16px 24px;
      border: 3px solid #2563eb;
      margin: 20px;
      background-color: #eff6ff;
    }
    .notice h2 { margin: 0 0 8px; }
    .notice p { margin: 0; }
  </style>
</head>
<body>
  <section class="notice">
    <h2>점검 안내</h2>
    <p>예정된 시간 동안 일부 기능이 잠시 멈춥니다.</p>
  </section>
</body>
</html>
```
### 코드 목적
`border-box`를 사용해 카드의 보이는 너비를 320px로 고정하고, 패딩과 테두리, 마진이 각각 어떤 공간을 담당하는지 확인한다.
### 코드 흐름
1. 모든 요소에 `box-sizing: border-box`를 적용한다.
2. 카드 너비를 320px로 정한다.
3. 좌우 패딩 24px과 테두리 3px을 같은 너비 안에 포함한다.
4. 바깥쪽에는 마진 20px을 두어 화면 가장자리와 거리를 만든다.
### 예상 렌더링
```text
카드의 테두리 바깥 기준 보이는 너비: 320px
왼쪽과 오른쪽의 바깥 간격: 각각 20px
내용 영역의 계산 너비: 320 - 48 - 6 = 266px
화면에서 요구하는 가로 자리: 320 + 40 = 360px
```
### 결과 해석
패딩 48px과 테두리 6px이 320px 안에 포함되므로 내용 영역은 266px이 된다.
마진은 박스 너비에 포함되지 않아 좌우 20px을 합친 전체 점유 폭은 360px이다.
### 실무 연결
디자인 시안의 카드 너비를 그대로 구현하거나 반응형 열에서 요소가 삐져나오는 문제를 막을 때 `border-box`가 유용하다.
테두리와 패딩이 자주 바뀌는 버튼, 입력창, 카드 컴포넌트에도 같은 계산 규칙을 적용할 수 있다.

## 헷갈리기 쉬운 포인트
| 헷갈리는 개념 | 차이 |
|---|---|
| padding vs margin | 테두리 안쪽 여백 vs 테두리 바깥쪽 간격 |
| content-box vs border-box | 선언한 크기가 내용만 의미 vs 패딩과 테두리까지 포함 |
| 보이는 너비 vs 점유 폭 | 테두리까지의 크기 vs 좌우 마진까지 더한 배치 공간 |
| `border` vs `background` | 경계선을 그림 vs 내용과 패딩 영역의 바탕을 꾸밈 |
| 2값 축약 vs 4값 축약 | 위아래·좌우 묶음 vs 위·오른쪽·아래·왼쪽 개별 지정 |
