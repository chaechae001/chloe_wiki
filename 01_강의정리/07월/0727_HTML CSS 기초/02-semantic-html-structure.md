# 시맨틱 HTML 구조 — 태그 이름으로 문서의 지도를 그리기

> 브라우저는 태그를 화면에 그리지만, 사람과 검색 도구와 보조 기술은 태그가 담은 의미까지 읽습니다.
> 제목 계층과 영역의 역할을 분명히 하면 꾸미기 전에도 이해되는 문서가 됩니다.

`문서 골격` · `제목 계층` · `목록` · `시맨틱 태그` · `div`
## 핵심요약

- HTML 문서는 선언, `html`, `head`, `body`가 감싸는 기본 골격에서 시작한다.
- 제목은 글자 크기가 아니라 내용의 상하 관계를 나타내도록 단계적으로 사용한다.
- 문단·목록·링크·이미지는 콘텐츠의 목적에 맞는 태그를 선택한다.
- `header`, `nav`, `main`, `article`, `footer`는 영역의 역할을 이름으로 전달한다.
- `div`는 의미가 정해지지 않은 묶음이 필요할 때 사용하는 일반 컨테이너다.
## 1. HTML 문서의 기본 골격
### 1) 정의

HTML 문서의 골격은 브라우저가 문서의 종류, 설정 정보, 화면 콘텐츠를 구분하도록 만드는 최상위 구조입니다.

`<!doctype html>`은 현대 HTML 문서임을 알리고, `html`은 전체 문서를 감쌉니다.

`head`에는 문자 인코딩과 탭 제목 같은 문서 정보가 들어가고, `body`에는 사용자가 읽고 조작할 내용이 들어갑니다.

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>작은 정원 안내</title>
</head>
<body><h1>작은 정원 안내</h1><p>계절별로 돌보는 방법을 기록합니다.</p></body>
</html>
```
### 2) 왜 필요한가

브라우저는 불완전한 HTML도 어느 정도 보정하지만, 보정 결과를 개발자가 정확히 예측하기는 어렵습니다. 기본 골격을 갖추면 문서가 어떤 언어인지, 문자를 어떻게 해석할지, 작은 화면에서 폭을 어떻게 계산할지 분명해집니다.
또한 탭 제목은 여러 페이지를 열었을 때 문서를 구분하고 검색 결과의 맥락을 제공하는 중요한 정보입니다.
### 3) 핵심 흐름 재구성

문서 뼈대를 작성할 때는 바깥에서 안쪽으로 생각하면 쉽습니다.

1. 문서 형식을 선언한다.
2. `html`에 문서의 주 언어를 적는다.
3. `head`에 문자 인코딩, 화면 폭, 제목을 기록한다.
4. `body`에 실제 콘텐츠를 배치한다.
5. 모든 요소의 열고 닫는 관계를 들여쓰기로 확인한다.

`meta charset`은 가능한 한 `head` 앞부분에 둡니다.

문자 해석 기준을 일찍 알려 주면 한글을 비롯한 다양한 문자가 안정적으로 표시됩니다.
### 4) 쉬운 예시

문서를 택배 상자에 비유해 봅시다. 상자 바깥의 운송 표시는 문서 선언, 송장 정보는 `head`, 상자 안의 실제 물건은 `body`와 비슷합니다.
송장만 있고 물건이 없거나, 물건 설명을 송장 칸에 넣으면 내용을 찾기 어려워집니다.
### 5) 코드 예시

잘못된 중첩은 태그를 닫는 순서가 여는 순서와 어긋날 때 생깁니다.

```html
<!-- 올바른 중첩: 나중에 연 요소를 먼저 닫는다 -->
<p>오늘의 <strong>핵심 알림</strong>입니다.</p>
```

브라우저 화면에는 "핵심 알림" 부분이 강조된 한 문단으로 보입니다.
### 6) 헷갈리는 점

`head`와 `header`는 이름이 비슷하지만 역할이 전혀 다릅니다.

`head`는 화면에 직접 보이지 않는 문서 설정 영역이고, `header`는 페이지나 콘텐츠 영역의 머리말입니다.

또한 `title`은 브라우저 탭 제목이며, 본문에서 보이는 대표 제목은 `h1`로 작성합니다.
### 7) 한 줄 정리

> 문서 골격은 브라우저가 설정 정보와 실제 콘텐츠를 안정적으로 구분하도록 만드는 출발점이다.
## 2. 제목·문단·목록·링크·이미지
### 1) 정의

HTML의 기본 콘텐츠 태그는 텍스트와 미디어가 문서에서 맡는 역할을 표현합니다.

`h1`부터 `h6`까지는 제목 단계, `p`는 문단, `ol`과 `ul`은 목록, `a`는 이동, `img`는 이미지를 나타냅니다.

`li`는 목록의 각 항목이며 `ol`이나 `ul` 안에서 사용합니다.
### 2) 왜 필요한가

모든 내용을 `div`와 글자 크기로만 표현하면 사람 눈에는 제목처럼 보여도 문서 구조에는 제목이 존재하지 않습니다. 의미에 맞는 태그를 사용하면 키보드 탐색, 화면 낭독, 검색 색인, 유지보수에서 콘텐츠 관계를 이해하기 쉬워집니다.
특히 제목 계층은 긴 문서의 목차 역할을 합니다.
### 3) 핵심 흐름 재구성

콘텐츠 태그를 고르는 기준은 모양이 아니라 목적입니다.

- 문서 전체의 주제는 `h1`으로 시작한다.
- 큰 장의 하위 주제는 `h2`, 그 안의 세부 주제는 `h3`처럼 한 단계씩 내려간다.
- 하나의 생각 단위는 `p`로 묶는다.
- 순서가 결과에 영향을 주면 `ol`, 순서가 중요하지 않으면 `ul`을 쓴다.
- 다른 위치로 이동시키는 콘텐츠는 `a`로 만든다.
- 의미 있는 이미지에는 목적에 맞는 `alt`를 제공한다.

제목 번호는 기본 글자 크기를 고르는 도구가 아닙니다. 크기는 CSS로 바꿀 수 있지만 제목의 단계는 문서 구조에 남습니다.
### 4) 쉬운 예시

요리법에서 "재료"와 "조리 순서"는 모두 목록이지만 성격이 다릅니다. 재료는 순서를 바꾸어도 의미가 유지되므로 `ul`이 자연스럽습니다.
조리 순서는 앞뒤를 바꾸면 결과가 달라지므로 `ol`이 적합합니다.
### 5) 코드 예시

```html
<article>
  <h2>허브차 만들기</h2>
  <p>따뜻한 물과 허브 잎으로 향긋한 차를 만듭니다.</p>
  <h3>준비물</h3>
  <ul>
    <li>말린 허브 잎</li><li>따뜻한 물</li>
  </ul>
  <h3>순서</h3>
  <ol>
    <li>컵에 허브 잎을 넣습니다.</li><li>물을 붓고 잠시 기다립니다.</li>
  </ol>
  <a href="/guides/tea">다른 차 만드는 법 보기</a>
</article>
```

예상 렌더링은 하나의 `h2` 아래에 두 개의 `h3`가 있고, 글머리 목록과 번호 목록이 차례로 나타나는 모습입니다.
### 6) 헷갈리는 점

링크와 버튼은 모두 클릭할 수 있지만 목적이 다릅니다. 다른 문서나 위치로 이동하면 링크가 맞고, 현재 화면에서 저장·열기·상태 변경 같은 행동을 실행하면 버튼이 맞습니다.
이미지의 `alt`는 파일의 생김새를 기계적으로 나열하기보다 현재 문맥에서 이미지가 전달하는 의미를 적습니다.
### 7) 한 줄 정리

> 콘텐츠 태그는 보이는 모양이 아니라 문서에서 맡은 역할을 기준으로 선택한다.
## 3. 시맨틱 영역과 `div`
### 1) 정의

시맨틱 태그는 요소의 역할을 이름으로 드러내는 HTML 요소입니다.

`header`는 머리말, `nav`는 주요 탐색 링크, `main`은 페이지의 핵심 콘텐츠, `article`은 독립적으로 이해되는 글, `footer`는 꼬리말을 뜻합니다.

`div`는 정해진 의미 없이 요소를 묶는 일반 컨테이너입니다.
### 2) 왜 필요한가

페이지의 모든 영역이 `div`라면 코드만 보고 어느 부분이 탐색이고 어느 부분이 본문인지 알기 어렵습니다. 역할을 드러내는 태그는 개발자에게 구조를 설명하고, 보조 기술에는 빠르게 이동할 수 있는 영역 정보를 제공합니다.
문서가 커질수록 이 차이는 탐색과 수정 속도에 직접 영향을 줍니다.
### 3) 핵심 흐름 재구성

페이지 영역을 나눌 때는 다음 질문을 순서대로 던질 수 있습니다.

1. 사이트나 현재 글의 소개 영역인가? 그렇다면 `header`를 검토한다.
2. 주요 이동 링크의 묶음인가? 그렇다면 `nav`를 검토한다.
3. 이 페이지에서 하나뿐인 중심 내용인가? 그렇다면 `main`에 둔다.
4. 다른 문맥에서도 독립적으로 읽힐 글인가? 그렇다면 `article`을 검토한다.
5. 작성 정보나 관련 정책 같은 마무리 영역인가? 그렇다면 `footer`를 검토한다.
6. 특별한 의미 없이 스타일이나 배치를 위한 묶음인가? 그때 `div`를 사용한다.

시맨틱 태그는 위치만으로 정하지 않습니다. 화면 상단에 있다고 무조건 `header`가 아니고, 화면 하단에 있다고 모든 요소가 `footer`인 것도 아닙니다.
### 4) 쉬운 예시

도서관의 안내 표지를 떠올려 봅시다. "안내 데스크", "열람실", "자료 검색"이라는 표지는 공간의 역할을 알려 줍니다.
모든 방에 "공간 1", "공간 2"라고만 적어 둔 상태가 `div`만으로 만든 구조와 비슷합니다.
### 5) 코드 예시

```html
<body>
  <header>
    <a href="/">동네 기록관</a>
    <nav aria-label="주요 메뉴"><ul><li><a href="/stories">이야기</a></li><li><a href="/events">행사</a></li></ul></nav>
  </header>
  <main>
    <article>
      <header><h1>오래된 나무의 계절</h1><p>한 그루의 변화를 기록한 글입니다.</p></header>
      <p>봄이 오면 가장 먼저 작은 잎이 돋습니다.</p>
    </article>
  </main>
  <footer><p>콘텐츠 이용 안내</p></footer>
</body>
```

이 예시에서 `header`는 두 번 등장하지만 각각 페이지 전체와 `article`의 머리말을 맡습니다. 태그는 한 번만 써야 하는 장식 위치가 아니라 자신이 속한 콘텐츠의 역할을 나타냅니다.
### 6) 헷갈리는 점

`article`은 단순히 본문 안의 네모 상자를 뜻하지 않습니다.

목록에서 따로 공유할 수 있는 소식, 게시물, 리뷰처럼 독립성이 있는 콘텐츠에 적합합니다. 의미 있는 태그가 떠오르지 않는다고 억지로 이름을 붙이기보다는 `div`를 쓰는 편이 정확합니다.
### 7) 한 줄 정리

> 시맨틱 태그는 영역의 역할을 설명하고, `div`는 별도의 의미가 없는 묶음을 책임진다.
## 코드로 보기 — 한 페이지 소개 문서 완성하기

```html
<!doctype html>
<html lang="ko">
<head><meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1"><title>우리 동네 산책</title></head>
<body>
  <header>
    <p><a href="/">우리 동네 산책</a></p>
    <nav aria-label="주요 메뉴"><ul><li><a href="/routes">산책로</a></li><li><a href="/notices">안내</a></li></ul></nav>
  </header>
  <main>
    <article>
      <h1>비 오는 날의 짧은 코스</h1>
      <p>지붕이 있는 길을 중심으로 걷는 방법을 소개합니다.</p>
      <img src="images/covered-path.webp" alt="지붕 아래로 이어지는 보행로">
      <h2>준비할 것</h2>
      <ul><li>미끄럽지 않은 신발</li><li>작은 우산</li></ul>
    </article>
  </main>
  <footer><p><a href="/policy">콘텐츠 이용 안내</a></p></footer>
</body>
</html>
```
### 코드 목적

문서 골격, 제목 계층, 탐색 목록, 독립 콘텐츠, 이미지 대안, 꼬리말을 하나의 의미 있는 페이지로 조합합니다.
### 코드 흐름

1. `head`에서 문자와 화면 폭과 탭 제목을 설정한다.
2. 페이지 `header`에 사이트 이름과 주요 탐색을 둔다.
3. `main` 안의 `article`이 현재 페이지의 핵심 글을 담는다.
4. `h1` 아래에서 `h2`로 세부 주제를 나눈다.
5. `footer`에 본문과 구분되는 보조 링크를 둔다.
### 예상 렌더링 및 실행 결과

```text
우리 동네 산책
• 산책로  • 안내
비 오는 날의 짧은 코스
지붕이 있는 길을 중심으로 걷는 방법을 소개합니다.
[보행로 이미지] 준비할 것
• 미끄럽지 않은 신발  • 작은 우산
콘텐츠 이용 안내
```
### 결과 해석

위에서 아래로 사이트 탐색, 핵심 글, 보조 정보가 자연스럽게 이어집니다. CSS가 없어도 제목과 목록의 기본 표시 덕분에 콘텐츠 구조를 파악할 수 있습니다.
이미지를 볼 수 없는 환경에서는 대체 텍스트가 장면의 핵심 의미를 대신합니다.
### 실무 연결

블로그 글, 공지 상세, 상품 소개처럼 한 페이지에 중심 콘텐츠가 있는 화면의 기초 구조로 활용할 수 있습니다. 코드 리뷰에서는 태그 이름만 읽고도 영역의 책임을 빠르게 확인할 수 있습니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| `head` vs `header` | `head`는 문서 설정, `header`는 화면 콘텐츠의 머리말 |
| `title` vs `h1` | `title`은 탭과 문서 이름, `h1`은 본문의 대표 제목 |
| `ol` vs `ul` | 순서가 의미에 영향을 주면 `ol`, 그렇지 않으면 `ul` |
| `a` vs `button` | 다른 위치로 이동하면 `a`, 현재 화면에서 행동을 실행하면 `button` |
| `article` vs `div` | 독립적인 콘텐츠면 `article`, 의미 없는 묶음이면 `div` |
| `header` vs `footer` | 콘텐츠를 소개하는 머리말 vs 콘텐츠를 마무리하는 꼬리말 |

### 복습 질문 및 답변

**Q1. 제목 태그는 왜 글자 크기 기준으로 고르면 안 되나요?**
<details>
<summary>답</summary>

제목 숫자는 문서의 계층을 전달하기 때문입니다. 모양은 CSS로 바꿀 수 있지만 잘못된 제목 단계는 문서 목차와 탐색 순서를 왜곡합니다.
</details>

**Q2. `nav` 안의 메뉴를 목록으로 작성하면 어떤 장점이 있나요?**
<details>
<summary>답</summary>

여러 링크가 같은 목적의 항목 집합이라는 관계가 드러납니다. 사용자는 메뉴 개수와 각 항목을 구조적으로 이해할 수 있고 스타일도 목록 단위로 관리하기 쉽습니다.
</details>

**Q3. 시각적으로 같은 상자 두 개라도 하나는 `article`, 하나는 `div`가 될 수 있는 이유는 무엇인가요?**
<details>
<summary>답</summary>

태그 선택은 모양이 아니라 콘텐츠 역할로 결정하기 때문입니다. 독립적으로 읽히고 공유될 글은 `article`, 레이아웃을 위한 단순 묶음은 `div`가 알맞습니다.
</details>
