# K-Means와 Elbow Method — 정답 없이 몇 개로 나눌까

> 레이블이 없는 데이터를 "비슷한 것끼리" 묶는 가장 대표적인 방법이 K-Means입니다. 이 글은 중심을 옮겨 가며 수렴하는 원리와, 몇 개로 나눌지(K)를 Inertia 곡선의 팔꿈치로 정하는 방법을 정리합니다.

`K-Means` · `중심(centroid)` · `Inertia` · `Elbow Method` · `Hard Clustering`

## 핵심요약

- K-Means는 K개의 중심을 정하고 "할당 → 중심 재계산"을 반복해 데이터를 K개 그룹으로 나누는 알고리즘이다.
- 각 점은 오직 하나의 클러스터에만 속한다(Hard Clustering).
- Inertia는 각 점과 자기 클러스터 중심 사이 거리 제곱의 합으로, 군집이 얼마나 빽빽한지를 나타낸다.
- Inertia는 K가 커질수록 무조건 줄어들기 때문에, "덜 줄어들기 시작하는 꺾임(Elbow)" 지점을 최적 K 후보로 본다.
- K-Means는 K를 미리 정해야 하고, 구형(둥근) 군집을 가정하며, 이상치와 초기값에 민감하다는 한계가 있다.

## 1. K-Means 알고리즘

### 1) 정의

K-Means는 데이터를 미리 정한 K개의 그룹으로 나누는 군집화(Clustering) 알고리즘입니다. 각 그룹에는 대표점인 **중심(centroid)** 이 하나씩 있고, 모든 점은 자기와 가장 가까운 중심의 그룹에 속합니다. 정답 레이블을 전혀 쓰지 않고 오직 점들 사이의 거리만으로 구조를 찾는 대표적인 비지도학습 방법입니다.

### 2) 왜 필요한가

현실 데이터는 대부분 정답이 붙어 있지 않습니다. 고객 목록, 로그 기록, 센서 측정값에는 "이 사람은 몇 번 그룹"이라는 라벨이 없습니다. 이럴 때 K-Means는 비슷한 것끼리 자동으로 묶어 줍니다. 고객 세분화, 문서 주제 묶기, 이미지 색 압축처럼 "정답은 없지만 그룹을 만들어야 하는" 상황에서 가장 먼저 꺼내는 도구입니다.

### 3) 핵심 흐름 재구성

K-Means는 아래 네 단계를 반복합니다.

```text
1. 초기화 : K개 중심을 무작위(또는 개선된 방식)로 배치한다.
2. 할당   : 각 점을 가장 가까운 중심의 클러스터에 넣는다.
3. 갱신   : 각 클러스터에 속한 점들의 평균 위치로 중심을 옮긴다.
4. 반복   : 중심이 거의 안 움직일 때까지 2~3을 되풀이한다(수렴).
```

여기서 최소화하려는 목표를 수식으로 쓰면 다음과 같습니다.

$$
J = \sum_{k=1}^{K} \sum_{x \in C_k} \lVert x - \mu_k \rVert^2
$$

이 식은 "각 점이 자기 클러스터의 중심 $\mu_k$ 에서 얼마나 떨어져 있는지를 제곱해서 전부 더한 값"입니다. 이 값이 작을수록 같은 그룹 안의 점들이 서로 가깝게 모여 있다는 뜻이고, K-Means는 이 값을 줄이는 방향으로 중심을 계속 옮깁니다. 이 목표값이 바로 뒤에서 다룰 **Inertia** 입니다.

### 4) 쉬운 예시

넓은 강당에 사람들이 흩어져 있고, 커피차 3대를 어디에 세울지 정한다고 해봅시다. 처음엔 아무 데나 세운 뒤(초기화), 각 사람은 가장 가까운 커피차로 갑니다(할당). 그다음 각 커피차는 자기에게 온 사람들의 한가운데로 자리를 옮깁니다(갱신). 이걸 반복하면 커피차 위치가 더 이상 안 바뀌는 순간이 오는데, 그때가 수렴입니다. 커피차가 곧 중심이고, 각 줄이 하나의 클러스터입니다.

### 5) 코드 예시

스케일링된 데이터에 K를 2부터 10까지 넣어 가며 Inertia를 모읍니다.

```python
from sklearn.cluster import KMeans

inertias = []
for k in range(2, 11):
    km = KMeans(n_clusters=k, random_state=42, n_init=10)
    km.fit(X_scaled)          # 정답 레이블 없이 특성만 사용
    inertias.append(km.inertia_)
```

`n_init=10`은 초기 중심을 10번 다르게 잡아 그중 가장 좋은 결과를 고른다는 뜻으로, 초기값에 따라 결과가 흔들리는 문제를 완화합니다.

### 6) 헷갈리는 점

"K-Means가 알아서 그룹 개수를 찾아 준다"는 오해가 흔합니다. K-Means는 **K를 사람이 미리 정해 줘야** 작동합니다. 몇 개로 나눌지는 다음 절의 Elbow Method나 [타당성 지표](05-clustering-validity.md)로 따로 판단해야 합니다.

### 7) 한 줄 정리

> K-Means는 중심을 옮겨 가며 "가까운 것끼리" 묶는 알고리즘이며, 각 점은 하나의 그룹에만 속한다.

## 2. Elbow Method와 최적 K

### 1) 정의

**Inertia** 는 각 점과 자기 클러스터 중심 사이 거리 제곱의 합입니다. 값이 작을수록 군집이 빽빽하게 뭉쳐 있다는 뜻입니다. **Elbow Method** 는 K를 바꿔 가며 Inertia를 그린 뒤, 그래프가 팔꿈치처럼 꺾이는 지점을 최적 K 후보로 삼는 방법입니다.

### 2) 왜 필요한가

Inertia는 K가 커질수록 무조건 작아집니다. 극단적으로 점 개수만큼 클러스터를 만들면 Inertia는 0이 됩니다. 그래서 "Inertia가 가장 작은 K"를 고르면 항상 가장 큰 K가 뽑히는 함정에 빠집니다. Elbow Method는 "K를 하나 더 늘렸을 때 얻는 이득이 급격히 줄어드는 지점"을 찾아, 복잡도와 성능 사이의 균형점을 잡아 줍니다.

### 3) 핵심 흐름 재구성

K를 늘릴 때마다 Inertia가 얼마나 줄어드는지(감소폭)를 봅니다. 처음에는 클러스터를 하나 더 주면 Inertia가 크게 떨어지지만, 어느 순간부터는 늘려도 찔끔찔끔밖에 안 줄어듭니다. 그 "크게 떨어지다가 완만해지는" 꺾임이 팔꿈치이고, 그 K가 데이터를 설명하는 데 충분한 그룹 수라는 신호입니다.

### 4) 쉬운 예시

가방에 짐을 나눠 담는다고 해봅시다. 가방 1개에서 2개로 늘리면 훨씬 편해지고, 2개에서 3개도 꽤 낫습니다. 그런데 5개에서 6개로 늘리는 건 큰 차이가 없습니다. "확 편해지다가 별 차이 없어지는" 그 지점이 적당한 가방 수이고, Elbow가 찾는 것이 바로 이 지점입니다.

### 5) 코드 예시

K별 Inertia와 그 감소폭을 함께 출력해 꺾임을 눈으로 확인합니다.

```python
prev = None
for k, inertia in zip(range(2, 11), inertias):
    drop = '' if prev is None else f'  (감소폭 {prev - inertia:.1f})'
    print(f'K={k:2d}  inertia={inertia:.1f}{drop}')
    prev = inertia
```

```text
K= 2  inertia=565.7
K= 3  inertia=379.4  (감소폭 186.3)
K= 4  inertia=300.4  (감소폭  79.0)
K= 5  inertia=232.6  (감소폭  67.8)
K= 6  inertia=204.4  (감소폭  28.2)
K= 7  inertia=187.0  (감소폭  17.4)
K= 8  inertia=171.0  (감소폭  16.0)
```

### 6) 헷갈리는 점

"Elbow는 항상 딱 떨어지는 하나의 정답을 준다"고 생각하기 쉽지만, 실제로는 꺾임이 애매할 때가 많습니다. Elbow는 어디까지나 **후보**를 좁혀 주는 도구이고, 최종 결정은 [Silhouette·Dunn 같은 타당성 지표](05-clustering-validity.md)와 도메인 지식을 함께 봐야 합니다.

### 7) 한 줄 정리

> Elbow Method는 "K를 더 늘려도 이득이 줄어드는 꺾임"을 찾아 적절한 클러스터 수를 정하는 방법이다.

## 코드로 보기 — K=3으로 최종 군집화

```python
from sklearn.cluster import KMeans
import numpy as np

kmeans = KMeans(n_clusters=3, random_state=42, n_init=10)
cluster_labels = kmeans.fit_predict(X_scaled)   # 각 점에 그룹 번호 부여

unique, counts = np.unique(cluster_labels, return_counts=True)
for u, c in zip(unique, counts):
    print(f'Cluster {u}: {c}개')
```

```text
Cluster 0: 87개
Cluster 1: 123개
Cluster 2: 132개
```

### 코드 목적

Elbow에서 좁혀진 K=3으로 실제 군집을 만들고, 각 그룹에 몇 개 점이 들어갔는지 확인합니다.

### 코드 흐름

1. `n_clusters=3`으로 K-Means를 만든다.
2. `fit_predict`로 학습과 동시에 각 점의 그룹 번호를 받는다.
3. 그룹별 개수를 세어 분포를 본다.

### 실행 결과 해석

세 그룹의 크기가 87, 123, 132로 비교적 고르게 나뉘었습니다. 한 그룹에 몰리지 않고 어느 정도 균형 있게 갈라졌다는 것은, 데이터 안에 실제로 구분되는 덩어리가 존재할 가능성을 보여 줍니다. 다만 이 숫자만으로 "잘 나눴다"고 단정할 수는 없습니다. Inertia가 K=2에서 3으로 갈 때 186.3만큼(가장 큰 폭) 줄고 이후 감소폭이 79 → 68 → 28로 급격히 완만해지므로, K=3 부근이 팔꿈치라는 근거가 됩니다. 실제로 이 군집이 의미 있는지는 [타당성 지표](05-clustering-validity.md)와 [숨겨둔 정답과의 대조](07-full-pipeline-and-evaluation.md)로 검증합니다.

### 실무 연결

고객 세분화가 대표 사례입니다. 구매 금액·방문 빈도 같은 특성으로 고객을 K개 그룹으로 묶으면, 각 그룹에 맞는 마케팅 전략을 세울 수 있습니다. 이때 "몇 개 그룹으로 나눌까"를 Elbow로 정하고, 그룹 크기가 지나치게 한쪽으로 쏠리지 않는지 이 코드처럼 확인합니다.

## 직접 해보기

1. K-Means에서 각 점은 몇 개의 클러스터에 속할 수 있나요? 이런 방식을 무엇이라고 부르나요?
2. Inertia가 `K=2일 때 565.7`, `K=3일 때 379.4`, `K=4일 때 300.4`입니다. 2→3 감소폭과 3→4 감소폭을 계산하고, 어느 구간에서 꺾임이 더 뚜렷한지 말해 보세요.
3. 온라인 쇼핑몰에서 고객을 성향별로 묶어 쿠폰 전략을 짜려 합니다. K를 정할 때 Inertia가 가장 작은 K를 그대로 고르면 안 되는 이유는 무엇인가요?

<details>
<summary>정답 보기</summary>

1. 하나의 클러스터에만 속합니다. 이렇게 각 점이 오직 한 그룹에만 배정되는 방식을 Hard Clustering이라고 합니다.
2. 2→3 감소폭은 565.7 − 379.4 = 186.3, 3→4 감소폭은 379.4 − 300.4 = 79.0입니다. 2→3 구간의 감소폭이 훨씬 커서 이 부근에서 꺾임이 더 뚜렷하며, K=3이 팔꿈치 후보가 됩니다.
3. Inertia는 K가 커질수록 무조건 줄어들어, 극단적으로 점 개수만큼 클러스터를 만들면 0이 되기 때문입니다. 따라서 "가장 작은 Inertia"를 고르면 항상 가장 큰 K가 뽑혀 의미가 없습니다. 감소폭이 완만해지는 Elbow 지점을 봐야 합니다.

</details>

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| Inertia vs 좋은 군집 | Inertia는 K가 크면 무조건 작아지므로, 낮다고 좋은 게 아니라 꺾임(Elbow)을 봐야 함 |
| 할당 단계 vs 갱신 단계 | 점을 가까운 중심에 배정하는 것이 할당, 중심을 점들의 평균으로 옮기는 것이 갱신 |
| K-Means vs KNN | K-Means는 정답 없이 그룹을 만드는 군집화, KNN은 정답을 이웃 투표로 맞히는 분류 |
| 차원 축소 Elbow vs 군집 Elbow | 이름은 같지만 하나는 PC 개수 선택, 하나는 클러스터 수 선택 |
