# PCA와 스케일링 — 정보를 지키며 차원을 줄이는 법

> 특성이 많아지면 데이터는 눈으로 볼 수도, 다루기도 어려워집니다. PCA는 정보(분산)를 최대한 지키면서 차원을 줄이는 도구입니다. 그리고 그 앞에는 왜 항상 StandardScaler가 필요한지, 실제 수치로 확인합니다.

`차원의 저주` · `PCA` · `주성분` · `StandardScaler` · `설명분산`

## 핵심요약

- 차원의 저주란 특성이 많아질수록 데이터가 공간에 흩어져 거리·밀도 개념이 흐려지는 현상이다.
- PCA는 분산이 가장 큰 방향을 새 축(주성분)으로 잡아, 정보 손실을 최소화하며 차원을 줄이는 선형 기법이다.
- 스케일이 큰 변수(예: 몸무게 수천 g)가 작은 변수(부리 깊이 수 mm)를 압도하므로, PCA 전에는 StandardScaler가 필수다.
- 펭귄 데이터에서 스케일링 후 PC1은 분산의 68.8%, PC2는 19.3%를 설명해 두 축만으로 88.2%를 담는다.
- 누적 설명분산이 일정 기준(흔히 90%)을 넘는 지점에서 유지할 주성분 개수를 정한다.

## 1. 차원의 저주와 차원 축소

### 1) 정의

**차원의 저주(Curse of Dimensionality)** 는 특성(열)의 개수가 늘어날수록 데이터가 넓은 공간에 듬성듬성 흩어져, 점들 사이 거리가 다 비슷해지고 "가깝다/멀다"의 의미가 약해지는 현상입니다. 거리를 기반으로 하는 클러스터링·최근접 이웃 같은 알고리즘이 고차원에서 잘 작동하지 않는 근본 원인입니다.

**차원 축소(Dimensionality Reduction)** 는 이 문제를 줄이기 위해, 정보를 최대한 보존하면서 특성 개수를 낮추는 작업입니다.

### 2) 왜 필요한가

- **시각화**: 사람은 4차원 이상을 눈으로 볼 수 없습니다. 4개 특성을 2개로 줄여야 산점도로 확인할 수 있습니다.
- **계산·성능**: 특성이 적으면 학습이 빠르고, 불필요한 노이즈 축을 버려 과적합도 줄어듭니다.
- **군집 품질**: 거리 개념이 살아 있는 낮은 차원에서 클러스터링이 더 안정적으로 작동합니다.

### 3) 핵심 흐름 재구성

PCA의 아이디어는 "정보 = 분산"이라는 관점에서 출발합니다. 데이터가 가장 넓게 퍼진 방향(분산이 큰 방향)에 가장 중요한 정보가 담겨 있다고 보고, 그 방향을 새 축으로 삼습니다.

- **PC1(제1주성분)**: 데이터의 분산이 가장 큰 방향
- **PC2(제2주성분)**: PC1에 수직이면서 그다음으로 분산이 큰 방향
- 이런 식으로 서로 직교하는 축을 차례로 찾고, 앞쪽 몇 개만 남기면 정보 손실을 최소화하며 차원이 줄어듭니다.

### 4) 쉬운 예시

책장에 꽂힌 책을 사진 한 장으로 찍는다고 합시다. 어느 각도에서 찍어야 책들이 가장 잘 구분될까요? 책들이 가장 넓게 퍼져 보이는 방향에서 찍으면 겹침이 적어 잘 구분됩니다. PCA가 하는 일이 바로 이 "가장 잘 퍼져 보이는 촬영 각도"를 수학적으로 찾아 주는 것입니다.

### 5) 코드 예시

전체 4개 주성분의 설명분산을 확인합니다.

```python
from sklearn.decomposition import PCA
import numpy as np

pca_full = PCA(random_state=42)
pca_full.fit(X_scaled)   # 반드시 스케일링된 데이터

ev = pca_full.explained_variance_ratio_
print('각 PC 설명분산:', ev.round(4))
print('누적:', np.cumsum(ev).round(4))
```

```text
각 PC 설명분산: [0.6884 0.1931 0.0913 0.0271]
누적:         [0.6884 0.8816 0.9729 1.0000]
```

### 실행 결과 해석

PC1 하나가 전체 분산의 **68.8%** 를, PC2가 **19.3%** 를 설명합니다. 둘을 합치면 **88.2%** 로, 4개였던 특성을 2개 축으로 줄여도 원래 정보의 약 88%를 지킬 수 있다는 뜻입니다. PC3·PC4는 각각 9.1%, 2.7%로 기여가 작아, 버려도 손실이 크지 않습니다. 이 수치가 "2차원으로 압축해도 괜찮다"는 결정의 근거가 됩니다.

### 6) 헷갈리는 점

주성분은 원래 특성 중 하나를 "고르는" 것이 아니라, 여러 특성을 조합해 만든 **새로운 축**입니다. PC1은 부리 길이·깊이·날개·몸무게가 특정 비율로 섞인 방향이지, "부리 길이 그 자체"가 아닙니다.

### 7) 한 줄 정리

> PCA는 분산이 큰 방향을 새 축으로 잡아, 정보 손실을 최소화하며 특성 개수를 줄이는 선형 차원 축소 기법이다.

## 2. 왜 StandardScaler가 필수인가

### 1) 정의

**StandardScaler** 는 각 특성을 평균 0, 표준편차 1로 바꾸는 전처리입니다. 값에서 그 특성의 평균을 빼고 표준편차로 나눕니다.

$$z = \frac{x - \mu}{\sigma}$$

이 식은 "각 값이 평균에서 표준편차 몇 배만큼 떨어져 있는가"로 바꾸는 것으로, 단위가 다른 특성들을 같은 척도 위에 올려놓습니다.

### 2) 왜 필요한가

PCA는 분산이 큰 방향을 찾는데, **분산의 크기는 단위에 좌우**됩니다. 펭귄 데이터에서 몸무게(`body_mass_g`)는 수천 단위(2700~6300)이고 부리 깊이(`bill_depth_mm`)는 10~20 정도입니다. 스케일을 맞추지 않으면 몸무게의 수치 자체가 워낙 커서 분산도 압도적으로 크고, PCA는 "몸무게 방향"을 거의 그대로 PC1으로 뽑아 버립니다. 다른 특성의 정보는 묻힙니다.

즉 스케일링을 빼먹으면, **가장 정보가 많은 축이 아니라 단지 단위가 큰 축**을 주성분으로 착각하게 됩니다. 이것은 거리를 쓰는 K-Means·GMM에서도 똑같이 문제가 됩니다.

### 3) 핵심 흐름 재구성

`describe()`로 보면 스케일 차이가 한눈에 드러납니다.

```text
        bill_length  bill_depth  flipper_length  body_mass
mean          43.92       17.15          200.92    4201.75
std            5.46        1.97           14.06     801.95
```

몸무게의 표준편차(801.95)는 부리 깊이(1.97)의 400배가 넘습니다. 스케일링은 이 네 특성을 모두 표준편차 1로 맞춰, 어느 하나가 분산을 독점하지 못하게 합니다.

### 4) 쉬운 예시

키(cm)와 몸무게(kg)로 사람을 비교한다고 합시다. 키를 mm로 바꾸면 숫자가 10배로 커져, 실제로는 몸무게가 중요한 상황인데도 "키 차이"만 부풀려 보입니다. 단위를 통일(표준화)하지 않으면 단위 선택이 결과를 좌우해 버립니다.

### 5) 코드 예시

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X.values)

print('스케일링 후 평균(≈0):', X_scaled.mean(axis=0).round(4))
print('스케일링 후 표준편차(≈1):', X_scaled.std(axis=0).round(4))
```

```text
스케일링 후 평균(≈0): [ 0. -0. -0.  0.]
스케일링 후 표준편차(≈1): [1.0015 1.0015 1.0015 1.0015]
```

### 코드 목적

네 특성을 모두 평균 0, 표준편차 1로 맞춰, PCA·K-Means·GMM이 단위가 아니라 실제 패턴을 보도록 만드는 것입니다.

### 코드 흐름

1. `StandardScaler`를 만든다.
2. 특성 행렬에 `fit_transform`을 적용해 표준화한다.
3. 변환 후 평균과 표준편차를 확인해 정상 작동을 검증한다.

### 실행 결과 해석

모든 특성의 평균이 0, 표준편차가 약 1(1.0015)로 맞춰졌습니다. 표준편차가 정확히 1이 아니라 1.0015인 것은 표본 표준편차 계산 방식(자유도 보정)에 따른 아주 작은 차이일 뿐입니다. 이제 몸무게가 분산을 독점하는 문제가 사라져, 이후 모든 분석이 `X_scaled` 위에서 공정하게 진행됩니다.

### 실무 연결

거리·분산을 쓰는 알고리즘(PCA, K-Means, GMM, KNN, SVM 등)에서는 스케일링이 성능을 좌우하는 필수 단계입니다. 반대로 트리 기반 모델(랜덤포레스트 등)은 스케일에 둔감해 생략해도 됩니다. "이 알고리즘이 거리를 쓰는가"가 스케일링 필요성의 판단 기준입니다.

### 6) 헷갈리는 점

스케일링은 반드시 학습 데이터 기준으로 `fit`해야 합니다. 지도학습이라면 test 데이터에 `fit`을 다시 하면 안 되고, train에서 배운 평균·표준편차로 `transform`만 합니다. 이번처럼 전체를 비지도로 다룰 때도 원칙은 같습니다.

### 7) 한 줄 정리

> 스케일이 큰 변수 하나가 주성분과 거리를 독점하는 것을 막기 위해, PCA·거리 기반 알고리즘 앞에는 StandardScaler가 필수다.

## 코드로 보기 — 누적 설명분산으로 차원 정하기

```python
import numpy as np
from sklearn.decomposition import PCA

pca_full = PCA(random_state=42).fit(X_scaled)
ev = pca_full.explained_variance_ratio_
cum = np.cumsum(ev)

for i, (e, c) in enumerate(zip(ev, cum), start=1):
    print(f'PC{i}: 개별 {e:.1%}  누적 {c:.1%}')
```

```text
PC1: 개별 68.8%  누적 68.8%
PC2: 개별 19.3%  누적 88.2%
PC3: 개별 9.1%   누적 97.3%
PC4: 개별 2.7%   누적 100.0%
```

### 코드 목적

각 주성분의 기여도와 누적 곡선을 함께 보고, "몇 개의 주성분까지 남길지"를 데이터 기반으로 정합니다.

### 코드 흐름

1. 전체 주성분에 대해 PCA를 적합한다.
2. 개별 설명분산과 누적 설명분산을 계산한다.
3. 누적이 목표 기준(예: 90%)을 넘는 지점을 찾는다.

### 실행 결과 해석

누적 곡선은 PC2에서 88.2%, PC3에서 97.3%에 도달합니다. 90% 기준을 엄격히 지키려면 PC3까지, 시각화가 목적이면 88%로도 충분한 PC2까지 남깁니다. 곡선이 완만해지기 시작하는 "꺾임(Elbow)" 지점 이후의 주성분은 추가해도 정보 이득이 작습니다. 참고로 이 차원 축소의 Elbow는 [K-Means의 Elbow](04-kmeans-and-elbow.md)와 이름만 같고 목적이 다릅니다. 하나는 "주성분 개수", 다른 하나는 "군집 개수"를 정하는 도구입니다.

### 실무 연결

수백 개 특성을 가진 데이터에서 누적 설명분산 90~95% 기준으로 차원을 줄이면, 정보 대부분을 지키면서 계산량과 노이즈를 크게 낮출 수 있습니다. 이미지·텍스트 임베딩의 전처리, 시각화용 축소에 널리 쓰입니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 주성분 vs 원래 특성 | 원래 특성 중 하나를 고르는 게 아니라, 여러 특성을 섞어 만든 새 축이 주성분 |
| 설명분산 vs 누적 설명분산 | 개별 주성분의 기여도가 설명분산, PC1부터 차례로 더한 합이 누적 설명분산 |
| 스케일링 함 vs 안 함 | 안 하면 단위 큰 변수가 주성분을 독점, 하면 모든 특성이 공정하게 반영 |
| 차원 축소 Elbow vs 군집 Elbow | 앞은 주성분 개수를 정하는 곡선, 뒤는 군집 개수(K)를 정하는 곡선 |
