# PyTorch로 MLP 학습시키기 — 가중치를 사람이 정하지 않는다

> 앞에서는 XOR을 푸는 가중치를 사람이 손으로 넣었습니다. 문제는 현실의 데이터에는 정답 구조를 알려 줄 사람이 없다는 것입니다. 이 글은 기계가 스스로 가중치를 찾아가는 과정을 자동미분, 손실 함수, 학습 루프 네 줄로 나눠서 따라갑니다.

`Autograd` · `nn.Module` · `BCE Loss` · `역전파` · `zero_grad`

## 핵심요약

- PyTorch의 텐서는 값과 함께 계산 이력을 기억하며, 이를 이용해 미분값을 자동으로 계산하는 기능이 Autograd다.
- 모델을 `nn.Module` 상속 클래스로 만들면 층과 파라미터가 자동 등록되어 학습·저장·평가 전환을 프레임워크에 맡길 수 있다.
- `nn.Linear(2,2)` + Sigmoid → `nn.Linear(2,1)` + Sigmoid 구조에 BCE 손실을 붙이면 XOR을 학습으로 풀 수 있다.
- 학습 루프는 순전파 → 손실 계산 → 역전파 → 가중치 갱신의 반복이며, 매 반복 앞에서 `zero_grad()`로 기울기를 비워야 한다.
- 3,000 에포크 학습 결과 Loss는 0.0023에서 0.0001까지 줄고 정확도는 전 구간 100%였으며, 학습된 가중치는 절댓값이 9~19에 이르는 큰 값이었다.

## 1. 텐서와 자동미분(Autograd)

### 1) 정의

텐서(Tensor)는 숫자를 담는 다차원 배열입니다. 넘파이 배열과 비슷하지만 결정적인 차이가 하나 있습니다. PyTorch 텐서는 **자기가 어떤 계산을 거쳐 만들어졌는지를 기억**합니다. 이 계산 이력을 따라 거꾸로 미분값을 계산해 주는 기능이 자동미분(Autograd)입니다.

### 2) 왜 필요한가

가중치를 자동으로 고치려면 "이 가중치를 조금 키우면 오차가 늘어나는가, 줄어드는가"를 알아야 합니다. 이 정보가 바로 미분값(기울기, gradient)입니다. 층이 두세 개만 되어도 미분식을 손으로 전개하는 것은 현실적으로 불가능합니다. Autograd는 이 계산을 대신해 주고, 덕분에 우리는 모델 구조와 손실 함수만 정의하면 됩니다.

### 3) 핵심 흐름 재구성

흐름은 세 단계입니다.

```text
1. 순전파 중 계산 그래프가 자동으로 그려진다   (x → z → loss)
2. loss.backward() 를 부르면 그래프를 거꾸로 훑는다
3. 각 파라미터의 .grad 자리에 미분값이 채워진다
```

미분의 핵심 규칙은 연쇄 법칙입니다.

$$
\frac{\partial \mathcal{L}}{\partial w} = \frac{\partial \mathcal{L}}{\partial y}\cdot\frac{\partial y}{\partial z}\cdot\frac{\partial z}{\partial w}
$$

이 식은 "손실이 가중치에 얼마나 민감한지"를 구할 때, 출력 → 활성화 전 값 → 가중치 순으로 영향력을 차례차례 곱해 나간다는 뜻입니다. 이렇게 출력 쪽에서 입력 쪽으로 거슬러 오며 기울기를 전파하는 과정이 역전파(Backpropagation)입니다.

여기서 앞 글의 Step 함수를 왜 학습에 쓸 수 없었는지도 설명됩니다. Step 함수는 거의 모든 지점에서 기울기가 0이라 위 곱셈이 0이 되어 버립니다. 그래서 학습용 모델에서는 미분 가능한 Sigmoid를 씁니다.

### 4) 쉬운 예시

산에서 안개 속에 갇혀 아래로 내려가야 하는 상황을 떠올려 보면 됩니다. 전체 지도를 볼 수는 없지만, 발밑의 경사만은 느낄 수 있습니다. 가장 가파르게 내려가는 방향으로 한 걸음씩 옮기면 결국 골짜기에 닿습니다. 여기서 발밑 경사가 기울기이고, 그 경사를 알려 주는 장치가 Autograd입니다.

### 5) 코드 예시

가장 작은 예로, $y = 3w^2$ 에서 $w=2$ 일 때의 기울기를 확인해 봅니다.

```python
import torch

w = torch.tensor(2.0, requires_grad=True)   # 미분 대상으로 표시
y = 3 * w ** 2                              # 계산 이력이 함께 기록됨

y.backward()                                # 이력을 거꾸로 훑으며 미분
print('w의 기울기:', w.grad.item())          # dy/dw = 6w = 12
```

```text
w의 기울기: 12.0
```

### 6) 헷갈리는 점

`requires_grad=True`가 붙은 텐서만 추적 대상입니다. `nn.Linear` 같은 층의 가중치는 자동으로 이 표시가 붙지만, 우리가 직접 만든 데이터 텐서는 붙지 않습니다. 또 평가 단계처럼 학습이 필요 없는 구간에서는 `torch.no_grad()`로 감싸 불필요한 계산 그래프 생성을 막습니다.

### 7) 한 줄 정리

> Autograd는 계산 이력을 거꾸로 훑어 "가중치를 어느 방향으로 움직여야 오차가 줄어드는지"를 자동으로 알려 주는 기능이다.

## 2. 모델을 `nn.Module` 상속 클래스로 만들기

### 1) 정의

PyTorch의 모든 신경망 부품은 `nn.Module`을 상속합니다. `__init__`에서 사용할 층을 속성으로 선언하고, `forward`에서 데이터가 흐르는 순서를 적으면 모델 하나가 완성됩니다.

### 2) 왜 필요한가

단순히 함수로 짜도 계산은 됩니다. 하지만 `nn.Module`을 상속하면 프레임워크가 여러 가지를 대신 처리해 줍니다.

- `__init__`에 선언한 층의 가중치와 편향이 **자동으로 학습 대상 목록에 등록**됩니다. 그래서 `model.parameters()` 한 줄로 옵티마이저에 전부 넘길 수 있습니다.
- 모델을 통째로 저장하고 불러오는 기능, 학습 모드와 평가 모드 전환이 그대로 따라옵니다.
- 작은 모듈을 큰 모듈 안에 부품처럼 끼워 넣을 수 있어, 층이 수십 개인 모델도 같은 문법으로 조립됩니다.

즉 상속은 문법 장식이 아니라 "이 객체는 학습 가능한 부품입니다"라고 프레임워크에 알리는 등록 절차입니다.

### 3) 핵심 흐름 재구성

XOR을 풀 모델의 구조는 다음과 같습니다.

```text
입력 (batch, 2)
  → nn.Linear(2, 2) → Sigmoid  → 은닉 표현 (batch, 2)
  → nn.Linear(2, 1) → Sigmoid  → 출력 확률 (batch, 1)
```

$$
h = \sigma(W_1 x + b_1), \qquad \hat{y} = \sigma(W_2 h + b_2)
$$

여기서 시그모이드는 다음과 같습니다.

$$
\sigma(z) = \frac{1}{1 + e^{-z}}
$$

이 식은 어떤 실수든 0과 1 사이로 눌러 담는 함수입니다. $z$가 크면 1에 가까워지고, 작으면 0에 가까워지며, $z=0$ 이면 정확히 0.5입니다. 출력이 0~1이라 확률처럼 읽을 수 있고, 어디서나 미분이 가능해 역전파가 통합니다.

앞 글의 수동 조합과 구조가 같다는 점에 주목할 만합니다. 은닉 노드 두 개, 출력 노드 한 개로 완전히 동일하고, 다른 것은 가중치를 사람이 넣느냐 기계가 찾느냐뿐입니다.

### 4) 쉬운 예시

가구 조립에 비유하면, `nn.Module` 상속은 부품에 규격 나사 구멍을 뚫어 두는 일입니다. 규격을 지키면 어떤 부품이든 같은 방식으로 끼워지고, 나중에 부품 하나를 교체해도 나머지 조립 방식은 그대로입니다. 규격을 무시하고 만든 부품은 혼자서는 잘 돌아가도 다른 부품과 연결할 때마다 매번 새로 손봐야 합니다.

### 5) 코드 예시

```python
import torch.nn as nn

class LearnableXOR(nn.Module):
    def __init__(self):
        super().__init__()                  # 부모의 등록 절차를 먼저 실행
        self.hidden = nn.Linear(2, 2)       # 은닉층: 가중치 (2,2), 편향 (2,)
        self.output = nn.Linear(2, 1)       # 출력층: 가중치 (1,2), 편향 (1,)
        self.act = nn.Sigmoid()

    def forward(self, x):
        h = self.act(self.hidden(x))        # 은닉 표현
        return self.act(self.output(h))     # 0~1 확률

model = LearnableXOR()
print('학습 대상 파라미터 수:', sum(p.numel() for p in model.parameters()))
```

```text
학습 대상 파라미터 수: 9
```

### 6) 헷갈리는 점

`super().__init__()`을 빠뜨리면 층을 선언해도 파라미터가 등록되지 않아 학습이 되지 않습니다. 또 모델을 실행할 때는 `model.forward(x)`가 아니라 `model(x)`로 호출합니다. 그래야 PyTorch가 내부에서 필요한 사전·사후 처리를 함께 수행합니다.

### 7) 한 줄 정리

> `nn.Module` 상속은 "이 객체 안의 층들을 학습 대상으로 관리해 달라"고 프레임워크에 등록하는 절차다.

## 3. BCE 손실 함수 — 얼마나 틀렸는지 재는 자

### 1) 정의

이진 분류에서 예측 확률과 실제 정답의 차이를 재는 표준 지표가 이진 교차 엔트로피(Binary Cross Entropy)입니다.

$$
\mathcal{L} = -\big[\,y\log\hat{y} + (1-y)\log(1-\hat{y})\,\big]
$$

정답 $y$가 1이면 앞항만 남아 $-\log\hat{y}$가 되고, 0이면 뒷항만 남아 $-\log(1-\hat{y})$가 됩니다. 즉 **정답 쪽 확률에만 로그를 씌워 벌점을 매기는 식**입니다.

### 2) 왜 필요한가

학습은 "줄여야 할 숫자 하나"가 있어야 시작됩니다. 그 숫자가 손실입니다. 그런데 아무 숫자나 되는 것은 아닙니다. 오차의 절댓값을 쓰면 확신에 찬 오답과 애매한 오답의 벌점 차이가 크지 않아 학습이 느립니다. BCE는 로그를 쓰기 때문에 확신에 찬 오답에 훨씬 무거운 벌점을 줍니다.

### 3) 핵심 흐름 재구성

작은 숫자로 확인해 보면 성격이 바로 보입니다. 정답이 1일 때의 손실은 다음과 같습니다.

| 예측 확률 $\hat{y}$ | 손실 $-\log\hat{y}$ | 해석 |
|---|---|---|
| 0.99 | 0.01 | 거의 맞혔으니 벌점 거의 없음 |
| 0.50 | 0.69 | 반반 찍은 수준 |
| 0.10 | 2.30 | 틀린 쪽에 기울었으니 큰 벌점 |
| 0.01 | 4.61 | 확신에 차서 틀렸으니 아주 큰 벌점 |

확률이 0에 가까워질수록 로그값이 급격히 커집니다. 이 급격함이 모델을 정답 방향으로 강하게 밀어 줍니다.

### 4) 쉬운 예시

일기예보에 비유할 수 있습니다. "비 올 확률 50%"라고 했는데 비가 오면 크게 욕먹지 않습니다. 하지만 "비 올 확률 1%"라고 자신 있게 말했는데 폭우가 쏟아지면 신뢰를 크게 잃습니다. BCE는 이 감각을 그대로 수식으로 옮긴 것입니다.

### 5) 코드 예시

```python
import torch, torch.nn as nn

criterion = nn.BCELoss()
target = torch.tensor([[1.0]])

for p in [0.99, 0.5, 0.1, 0.01]:
    loss = criterion(torch.tensor([[p]]), target)
    print(f'예측 {p:>5} → 손실 {loss.item():.4f}')
```

```text
예측  0.99 → 손실 0.0101
예측   0.5 → 손실 0.6931
예측   0.1 → 손실 2.3026
예측  0.01 → 손실 4.6052
```

### 6) 헷갈리는 점

`nn.BCELoss()`는 입력이 이미 0~1 확률이라고 가정합니다. 그래서 모델 마지막에 Sigmoid가 반드시 있어야 합니다. Sigmoid를 빼고 싶다면 `nn.BCEWithLogitsLoss()`를 쓰면 되는데, 이 경우 Sigmoid를 두 번 적용하지 않도록 주의해야 합니다.

### 7) 한 줄 정리

> BCE는 정답 쪽 확률에 로그 벌점을 매겨, 확신에 찬 오답일수록 더 강하게 교정하는 이진 분류용 손실 함수다.

## 4. 학습 루프 4단계와 `zero_grad()`

### 1) 정의

학습은 다음 네 단계를 수천 번 반복하는 일입니다.

```text
1) 순전파      pred = model(inputs)        현재 가중치로 예측한다
2) 손실 계산   loss = criterion(pred, y)   얼마나 틀렸는지 잰다
3) 역전파      loss.backward()             각 가중치의 기울기를 구한다
4) 가중치 갱신 optimizer.step()            기울기 반대 방향으로 한 걸음
```

그리고 이 네 단계 **앞에** `optimizer.zero_grad()`가 붙습니다.

### 2) 왜 필요한가

PyTorch는 `backward()`를 부를 때 기울기를 덮어쓰지 않고 **기존 값에 더합니다**. 여러 배치의 기울기를 모아 한 번에 갱신하는 상황을 지원하기 위한 설계입니다. 그런데 일반적인 학습에서는 이 누적이 그대로 버그가 됩니다. 지우지 않으면 1,000번째 반복의 기울기가 앞선 999번의 기울기를 모두 더한 값이 되어, 걸음이 터무니없이 커지고 학습이 발산합니다.

### 3) 핵심 흐름 재구성

가중치 갱신 규칙 자체는 한 줄입니다.

$$
w \leftarrow w - \eta \frac{\partial \mathcal{L}}{\partial w}
$$

이 식은 "손실이 커지는 방향의 반대로, 학습률 $\eta$만큼의 보폭으로 가중치를 옮긴다"는 뜻입니다. 기울기가 양수면 그 가중치를 줄이고, 음수면 늘립니다. 학습률이 너무 크면 골짜기를 뛰어넘고, 너무 작으면 도착 전에 반복이 끝납니다.

옵티마이저로는 학습률을 파라미터별로 조절해 주는 Adam을 학습률 0.1로 사용했습니다.

### 4) 쉬운 예시

체중계에 비유하면 `zero_grad()`는 영점 조절입니다. 저울 위에 이전 물건을 그대로 둔 채 새 물건을 올리면 무게가 합쳐져 나옵니다. 매번 재기 전에 0으로 맞춰야 이번 물건의 무게가 나옵니다.

### 5) 코드 예시

```python
import torch.optim as optim

criterion = nn.BCELoss()
optimizer = optim.Adam(model.parameters(), lr=0.1)

for epoch in range(3000):
    optimizer.zero_grad()               # 이전 기울기 비우기
    pred = model(inputs)                # 1) 순전파
    loss = criterion(pred, targets)     # 2) 손실 계산
    loss.backward()                     # 3) 역전파
    optimizer.step()                    # 4) 가중치 갱신
```

### 6) 헷갈리는 점

에포크(epoch)는 "전체 데이터를 한 번 다 훑은 횟수"입니다. XOR처럼 데이터가 4건뿐이면 한 에포크가 곧 한 번의 갱신이지만, 데이터가 수만 건이면 한 에포크 안에서 배치 단위로 여러 번 갱신이 일어납니다. 에포크 수와 갱신 횟수는 같은 말이 아닙니다.

### 7) 한 줄 정리

> 학습 루프는 예측·측정·기울기 계산·갱신의 반복이며, 기울기가 누적되지 않도록 매 반복 앞에서 반드시 초기화해야 한다.

## 코드로 보기 — XOR을 학습으로 푸는 전체 흐름

```python
import torch, torch.nn as nn, torch.optim as optim

torch.manual_seed(42)
inputs = torch.tensor([[0., 0.], [0., 1.], [1., 0.], [1., 1.]])
targets = torch.tensor([[0.], [1.], [1.], [0.]])

model = LearnableXOR()
criterion = nn.BCELoss()
optimizer = optim.Adam(model.parameters(), lr=0.1)

for epoch in range(3000):
    optimizer.zero_grad()
    pred = model(inputs)
    loss = criterion(pred, targets)
    loss.backward()
    optimizer.step()

    if (epoch + 1) % 500 == 0:
        acc = ((pred >= 0.5).float() == targets).float().mean()
        print(f'Epoch {epoch+1:4d} | Loss={loss.item():.4f} | Acc={acc:.0%}')

print('\n은닉층 weight:\n', model.hidden.weight.data)
print('은닉층 bias:\n', model.hidden.bias.data)
print('출력층 weight:\n', model.output.weight.data)
```

### 코드 목적

사람이 NAND와 OR을 설계해 넣는 대신, 무작위로 초기화된 가중치에서 출발해 오차만 보고 XOR을 푸는 가중치에 도달할 수 있는지 확인합니다.

### 코드 흐름

1. 은닉 2노드, 출력 1노드짜리 모델을 만들고 파라미터를 무작위로 초기화한다.
2. BCE 손실과 Adam 옵티마이저를 연결한다.
3. 3,000 에포크 동안 순전파 → 손실 → 역전파 → 갱신을 반복한다.
4. 최종 예측 확률과 학습된 가중치를 꺼내 해석한다.

### 실행 결과 해석

**Loss가 0.0023 → 0.0008 → 0.0004 → 0.0002 → 0.0001로 줄어듭니다.** 감소 폭에 주목할 만합니다. 500에서 1,000 에포크 사이에 0.0015가 줄었지만, 2,500에서 3,000 사이에는 거의 변화가 없습니다. 이미 정답에 충분히 가까워져 기울기 자체가 작아졌기 때문입니다. 골짜기 바닥에 가까워질수록 경사가 완만해져 걸음이 짧아지는 것과 같습니다.

**정확도는 500 에포크 시점에 이미 100%** 입니다. 정확도는 0.5를 기준으로 자르는 지표라, 확률이 0.51이든 0.99이든 똑같이 1로 셉니다. 그래서 정확도가 100%에 도달한 뒤에도 Loss는 계속 줄어듭니다. 정확도는 "맞혔는가"를 보고, Loss는 "얼마나 확신하며 맞혔는가"를 봅니다. 두 지표를 함께 봐야 학습 상태가 제대로 보입니다.

**학습된 가중치의 절댓값이 유난히 큽니다.** 은닉층은 -8.9와 -10.8 근처, 출력층은 18.8과 -19.0입니다. 처음 무작위 초기값이 보통 -1에서 1 사이인 것을 생각하면 열 배 넘게 커진 셈입니다. 이유는 Sigmoid의 모양에 있습니다. 확률을 0.000이나 1.000처럼 극단으로 밀어붙이려면 시그모이드에 들어가는 값 $z$가 아주 크거나 아주 작아야 합니다. $\sigma(z)$가 0.999가 되려면 $z$가 대략 7 이상이어야 합니다. XOR처럼 정답이 확실한 문제에서 손실을 계속 줄이면, 모델은 확신을 키우기 위해 가중치를 계속 키웁니다.

**기계가 찾은 조합은 사람이 짠 것과 달랐습니다.** 학습된 값을 넣고 은닉 노드가 무엇을 계산하는지 따져 보면 이렇습니다.

| 입력 (A, B) | 은닉 노드 1 = $\sigma(-8.92A - 8.94B + 13.27)$ | 은닉 노드 2 = $\sigma(-10.78A - 10.89B + 5.02)$ |
|---|---|---|
| (0, 0) | ≈ 1.00 | ≈ 0.99 |
| (0, 1) | ≈ 0.99 | ≈ 0.00 |
| (1, 0) | ≈ 0.99 | ≈ 0.00 |
| (1, 1) | ≈ 0.01 | ≈ 0.00 |

은닉 노드 1은 `1,1,1,0` 패턴이니 NAND이고, 은닉 노드 2는 `1,0,0,0` 패턴이니 NOR입니다. 출력층 가중치가 `[18.79, -19.03]`이라는 것은 "1번이 켜지고 2번이 꺼졌을 때만 1을 내라"는 뜻입니다. NOR이 꺼졌다는 건 OR이 켜졌다는 말과 같으므로, 결국 기계가 찾은 규칙도 **NAND와 OR을 AND로 묶은 것**이었습니다. 출발점은 무작위였지만 도착점은 사람이 손으로 설계한 구조와 논리적으로 같았습니다.

**결정 경계의 모양은 두 방식이 다릅니다.** 수동 조합은 Step 함수를 썼기 때문에 경계가 각지게 꺾인 직선들의 조합으로 나타나고, 0과 1 사이에 중간 지대가 없습니다. 학습된 모델은 Sigmoid를 썼기 때문에 경계가 부드러운 곡선이고, 0에서 1로 넘어가는 구간이 그라데이션처럼 이어집니다. 이 흐릿한 구간은 모델이 확신하지 못하는 영역을 뜻하며, 실무에서는 여기가 곧 "사람이 한 번 더 확인해야 할 구간"이 됩니다.

### 실무 연결

여기서 익힌 다섯 줄짜리 학습 루프는 이미지 분류든 추천 모델이든 대규모 언어 모델이든 구조가 같습니다. 달라지는 것은 데이터의 크기, 층의 깊이, 손실 함수의 종류뿐입니다. Loss 곡선을 보며 학습률을 조절하고, 정확도와 Loss를 함께 보며 과적합을 판단하고, 확률이 애매한 구간을 골라 사람에게 넘기는 판단은 모든 실무 프로젝트에서 그대로 반복됩니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 순전파 vs 역전파 | 입력에서 출력으로 값을 계산하면 순전파, 출력에서 입력으로 기울기를 되돌리면 역전파 |
| `loss.backward()` vs `optimizer.step()` | 기울기를 계산만 하는 것이 backward, 그 기울기로 가중치를 실제로 바꾸는 것이 step |
| Step 함수 vs Sigmoid | 기울기가 0이라 학습 불가한 Step, 미분 가능해 학습 가능한 Sigmoid |
| Loss vs Accuracy | 확신의 정도까지 재는 것이 Loss, 맞고 틀림만 세는 것이 Accuracy |
| 수동 조합 MLP vs 학습된 MLP | 각진 직선 경계에 중간 지대가 없는 수동 조합, 부드러운 곡선 경계에 확률 그라데이션이 있는 학습 모델 |
| 에포크 vs 갱신 횟수 | 전체 데이터를 한 번 훑은 것이 에포크, 배치마다 일어나는 것이 갱신 |
