# 싱글 스레드와 이벤트 루프

자바스크립트는 한 번에 하나의 코드만 실행합니다. 그런데도 클릭을 받고 타이머를 기다리며 네트워크 응답까지 처리할 수 있는 이유는 실행 환경과 이벤트 루프가 일을 나눠 맡기 때문입니다.

## 핵심 키워드

싱글 스레드 · 호출 스택 · 실행 환경 · 이벤트 루프 · 블로킹

## 핵심 요약

- 자바스크립트 엔진은 호출 스택에서 한 번에 하나의 작업을 실행합니다.
- 타이머와 이벤트 감시는 브라우저나 Node.js 같은 실행 환경이 담당합니다.
- 이벤트 루프는 호출 스택이 비었는지 확인하고 대기 중인 콜백의 실행을 조정합니다.
- 오래 걸리는 동기 코드는 이벤트 루프가 콜백을 전달할 기회를 막습니다.

## 1. 호출 스택과 싱글 스레드

함수를 호출하면 호출 스택에 실행 맥락이 쌓이고, 함수가 끝나면 제거됩니다. 마지막에 들어온 함수가 먼저 끝나는 LIFO 구조입니다.

```javascript
function formatName(name) {
  return name.trim().toUpperCase();
}

function printUser(name) {
  console.log(formatName(name));
}

printUser(" mina ");
```

`전역 → printUser → formatName` 순서로 쌓인 뒤 역순으로 빠집니다. 스택의 맨 위 함수만 현재 실행되므로 동시에 두 자바스크립트 함수가 실행되는 것은 아닙니다.

> 한 줄 정리: 싱글 스레드는 “작업이 하나뿐”이 아니라 “자바스크립트 실행 통로가 하나”라는 뜻입니다.

## 2. 실행 환경과 역할 분담

```text
자바스크립트 엔진: 함수와 표현식 실행
실행 환경: 타이머, 네트워크, DOM 이벤트 등의 기능 제공
큐: 실행 준비가 끝난 콜백 대기
이벤트 루프: 스택과 큐를 관찰해 실행 시점 조정
```

타이머를 등록하면 엔진이 시간을 세며 멈추는 것이 아닙니다. 실행 환경이 시간을 측정하고, 조건이 충족되면 콜백을 큐에 넣습니다. 이벤트 루프는 현재 스택이 비었을 때 큐의 작업을 스택으로 보냅니다.

## 3. 블로킹이 만드는 지연

```javascript
setTimeout(() => console.log("타이머 완료"), 10);

const startedAt = Date.now();
while (Date.now() - startedAt < 100) {
  // 호출 스택을 점유하는 무거운 동기 작업을 흉내 냅니다.
}

console.log("동기 작업 완료");
```

10ms 타이머가 먼저 준비되어도 반복문이 끝날 때까지 실행할 수 없습니다. 결과는 `동기 작업 완료` 다음에 `타이머 완료`입니다. 지정 시간은 콜백 준비 시점일 뿐, 스택이 비는 시점까지 보장하지 않습니다.

### 자주 헷갈리는 점

- 비동기 API를 사용해도 콜백 안의 무거운 계산은 여전히 호출 스택을 막습니다.
- 이벤트 루프는 코드를 병렬로 실행하는 스레드가 아니라 실행 순서를 조정하는 메커니즘입니다.
- `await`도 자바스크립트 전체를 멈추지 않고 해당 `async` 함수의 나머지만 미룹니다.

## 대표 코드: 작업을 작은 단위로 나누기

### 목적

큰 배열을 한 번에 처리하지 않고 작은 묶음으로 나눠 다른 태스크가 실행될 기회를 만듭니다.

```javascript
function processInChunks(items, chunkSize) {
  let index = 0;

  function runChunk() {
    const end = Math.min(index + chunkSize, items.length);

    while (index < end) {
      items[index] = items[index] * 2;
      index += 1;
    }

    if (index < items.length) {
      setTimeout(runChunk, 0);
    }
  }

  runChunk();
}
```

### 흐름

1. 한 번에 `chunkSize`개만 동기적으로 처리합니다.
2. 남은 데이터가 있으면 다음 묶음을 타이머로 예약합니다.
3. 묶음 사이에 브라우저가 다른 태스크를 처리할 틈이 생깁니다.

### 결과와 실무 활용

긴 목록 가공이나 대량 렌더링에서 응답성을 개선하는 기본 아이디어입니다. CPU 계산 자체를 병렬화해야 한다면 Web Worker 같은 별도 수단이 필요합니다.

## 비교: 동기 대기 vs 비동기 예약

| 구분 | 동기 대기 | 비동기 예약 |
|---|---|---|
| 현재 함수 | 완료까지 점유 | 예약 후 계속 진행 |
| 다른 작업 | 실행 기회 없음 | 스택이 비면 실행 가능 |
| 대표 예 | 긴 반복문, 무거운 계산 | 타이머, 네트워크, 이벤트 |
| 주의점 | UI 멈춤 | 완료 시점과 오류 흐름 관리 |

### Q1. 자바스크립트가 싱글 스레드인데 비동기 작업이 가능한 이유는?

<details>
<summary>답</summary>

</details>

### Q2. 이벤트 루프가 콜백을 실행할 수 있는 기본 조건은?

<details>
<summary>답</summary>

현재 동기 코드가 끝나 호출 스택이 비어 있어야 합니다.

</details>

### Q3. 비동기 콜백 내부의 긴 계산도 안전할까?

<details>
<summary>답</summary>

</details>
