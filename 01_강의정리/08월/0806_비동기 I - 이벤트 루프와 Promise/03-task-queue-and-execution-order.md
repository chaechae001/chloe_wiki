# 태스크 큐와 실행 순서

비동기 코드를 읽을 때는 줄의 위치보다 “어느 큐에서 언제 준비되는가”를 추적해야 합니다. 타이머가 먼저 작성되어도 동기 코드보다 나중에 출력되는 이유가 여기에 있습니다.

## 핵심 키워드

태스크 · 태스크 큐 · FIFO · 실행 순서 · run-to-completion

## 핵심 요약

- 현재 자바스크립트 태스크는 중간에 끊기지 않고 끝까지 실행됩니다.
- 타이머와 이벤트 콜백은 준비가 끝나면 태스크 큐에서 대기합니다.
- 이벤트 루프는 호출 스택이 빈 뒤 다음 작업을 선택합니다.
- 같은 종류의 준비된 작업은 일반적으로 큐의 선입선출 순서를 따르지만, 타이머 준비 시점은 달라질 수 있습니다.

## 1. 출력 순서를 예측하는 절차

```text
1. 모든 동기 코드와 함수 호출을 먼저 추적한다.
2. 비동기 API는 실행하지 말고 “등록” 표시를 한다.
3. 현재 호출 스택이 빌 때까지 동기 결과를 적는다.
4. 준비된 큐와 우선순위를 확인한다.
5. 큐에서 꺼낸 콜백 내부도 다시 같은 방식으로 추적한다.
```

```javascript
console.log("A");

setTimeout(() => {
  console.log("B");
}, 0);

console.log("C");
```

정답은 `A → C → B`입니다. `0ms`는 현재 코드보다 먼저 실행하라는 우선권이 아니라, 최소 대기 시간이 사실상 없다는 뜻입니다.

> 한 줄 정리: 비동기 콜백은 준비되었다고 바로 실행되지 않고, 호출 스택이 비기를 기다립니다.

## 2. 중첩 타이머와 기준 시점

```javascript
setTimeout(() => {
  console.log("첫 번째");

  setTimeout(() => {
    console.log("두 번째");
  }, 100);
}, 100);
```

두 번째 타이머는 프로그램 시작 시점이 아니라 첫 번째 콜백이 실행된 시점에 등록됩니다. 반면 타이머 두 개를 바깥에서 동시에 등록하면 각 지연 시간은 같은 등록 구간을 기준으로 계산됩니다.

### 자주 헷갈리는 점

- 콜백 안에서 타이머를 등록하면 지연 시간은 그 콜백 실행 시점부터 계산됩니다.
- 짧은 지연 시간이 항상 먼저 실행된다는 보장은 없습니다. 등록 시점, 최소 지연, 스택 점유가 모두 영향을 줍니다.
- FIFO는 큐에 들어온 뒤의 순서이며, 큐에 들어오는 시점까지 같다는 뜻은 아닙니다.

## 대표 코드: 단계별 재시도

### 목적

실패한 작업을 일정 시간 후 다시 시도하되 중첩 호출의 기준 시점을 명확히 합니다.

```javascript
function retry(task, delays, index = 0) {
  const succeeded = task();

  if (succeeded || index >= delays.length) {
    return;
  }

  setTimeout(() => {
    retry(task, delays, index + 1);
  }, delays[index]);
}
```

### 흐름

1. 작업을 동기적으로 한 번 시도합니다.
2. 실패했고 남은 지연값이 있으면 다음 재시도를 예약합니다.
3. 타이머 콜백이 실행된 시점에 다음 시도가 시작됩니다.

### 결과와 실무 활용

연결 확인이나 상태 폴링의 기초 구조입니다. 실제 비동기 실패를 다룰 때는 Promise 기반 재시도와 최대 횟수, 취소, 오류 기록을 함께 설계합니다.

## 연습 문제

다음 코드의 출력 순서를 예측해 보세요.

```javascript
console.log("start");
setTimeout(() => console.log("timer-1"), 0);
setTimeout(() => console.log("timer-2"), 0);
console.log("end");
```

<details>
<summary>답</summary>

일반적인 실행 순서는 `start → end → timer-1 → timer-2`입니다. 동기 코드가 먼저 끝나고, 같은 구간에서 등록되어 준비된 타이머 콜백은 큐 순서대로 실행됩니다.

</details>

## 비교: 동시에 등록 vs 콜백 안에서 등록

| 구분 | 동시에 등록 | 중첩 등록 |
|---|---|---|
| 지연 기준 | 비슷한 등록 시점 | 앞 콜백이 실행된 시점 |
| 구조 | 들여쓰기가 얕음 | 순서 의도가 분명함 |
| 변경 영향 | 누적 시간 재계산 가능 | 앞 단계 완료 후 다음 예약 |
| 적합한 상황 | 독립된 예약 | 단계별 순차 진행 |

## 복습 질문 및 답변

### Q1. 태스크 큐에 콜백이 들어가면 바로 실행되는가?

<details>
<summary>답</summary>

아닙니다. 현재 호출 스택이 비고 이벤트 루프가 그 태스크를 선택할 때 실행됩니다.

</details>

### Q2. 타이머 지연 시간은 무엇을 보장하는가?

<details>
<summary>답</summary>

콜백이 그 시간보다 일찍 실행되지 않는 최소 지연만 의미합니다. 정확한 실행 시각은 보장하지 않습니다.

</details>

### Q3. FIFO인데 짧은 타이머가 항상 먼저가 아닌 이유는?

<details>
<summary>답</summary>

FIFO는 준비되어 같은 큐에 들어온 작업의 순서 규칙입니다. 각 타이머가 준비되어 큐에 들어오는 시점은 등록 시각과 지연값에 따라 달라집니다.

</details>
