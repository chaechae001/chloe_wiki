# React 프로덕션 빌드

> 배포는 개발 서버를 외부에 여는 일이 아니라 재현 가능한 프로덕션 산출물을 만들고 검증하는 과정입니다.

`Production Build` · `Bundling` · `Environment Variable` · `Static Asset` · `SPA Fallback`

## 핵심요약

- 프로덕션 빌드는 코드를 최적화된 정적 산출물로 변환합니다.
- 하나의 패키지 관리자와 lockfile로 의존성을 재현합니다.
- 빌드 전에 테스트, lint, 환경 변수와 API 주소를 검증합니다.
- 빌드 폴더는 웹서버가 정적 파일로 제공하며 개발 서버와 목적이 다릅니다.
- SPA의 직접 경로 접근을 위해 진입 HTML fallback이 필요합니다.

## 1. 빌드 전 준비

1. 저장소 상태와 배포할 커밋을 확정합니다.
2. lockfile을 기준으로 의존성을 재현 가능하게 설치합니다.
3. 테스트와 정적 검사를 실행합니다.
4. 프로덕션 환경 변수와 API Origin을 검토합니다.
5. 빌드 명령을 실행하고 오류·경고를 확인합니다.
6. 산출물을 로컬 정적 서버에서 미리 검증합니다.

두 종류의 lockfile이 함께 있으면 도구에 따라 다른 의존성 버전이 설치될 수 있습니다. 팀에서 선택한 패키지 관리자 하나를 사용합니다.

## 2. 빌드 결과 이해하기

```json
{
  "scripts": {
    "test": "vitest run",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

```bash
npm ci
npm test
npm run build
npm run preview
```

### 코드 목적

lockfile과 동일한 의존성을 설치하고 테스트를 통과한 코드만 빌드해 로컬에서 프로덕션 결과를 확인합니다.

### 코드 흐름과 결과 해석

설치 실패는 의존성 재현 문제, 테스트 실패는 동작 계약 문제, 빌드 실패는 타입·import·환경 설정 문제로 나눠 볼 수 있습니다. Preview에서 새로고침, 정적 자원 경로와 API 연결까지 확인합니다.

### 실무 연결

CI에서도 같은 순서를 실행하면 개발자 PC와 배포 서버의 차이를 줄입니다. 빌드 산출물에는 소스용 비밀값을 넣지 않으며 프런트 환경 변수는 사용자에게 노출될 수 있다고 가정합니다.

## 3. 정적 자원과 라우팅

웹서버는 HTML, JavaScript, CSS와 이미지에 올바른 content type과 캐시 헤더를 적용합니다. 해시가 붙은 파일은 길게 캐시하고 진입 HTML은 새 배포를 반영할 수 있도록 별도 정책을 둡니다. `/products/1` 같은 앱 경로는 파일이 없을 때 진입 HTML을 반환해야 합니다.

3. 프런트 환경 변수에 비밀 키를 넣으면 안 되는 이유를 설명하세요.

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| 개발 서버 vs 프로덕션 웹서버 | 빠른 개발·HMR 목적 vs 최적화 산출물 안정적 제공 |
| `npm install` vs `npm ci` | lockfile 갱신 가능 vs lockfile 기준 재현 설치 |
| 소스 환경 변수 vs 서버 비밀 | 번들에 포함될 수 있음 vs 서버에서만 보호 |

### 복습 질문 및 답변

**Q1. 로컬 개발 화면이 동작해도 빌드가 실패할 수 있는 이유는?**

<details>
<summary>답</summary>

프로덕션 최적화 과정에서 잘못된 import, 타입 오류, 대소문자 경로, 누락 환경 변수가 드러날 수 있습니다.

</details>

**Q2. 해시가 붙은 정적 파일을 오래 캐시할 수 있는 이유는?**

<details>
<summary>답</summary>

내용이 바뀌면 파일명 해시도 바뀌어 새 URL로 배포되기 때문입니다.

</details>

**Q3. 빌드 산출물만으로 SSR을 제공할 수 있는가?**

<details>
<summary>답</summary>

일반적인 CSR 정적 산출물만으로는 요청별 서버 렌더링이 없으며 SSR을 위한 서버 런타임과 코드가 별도로 필요합니다.

</details>
