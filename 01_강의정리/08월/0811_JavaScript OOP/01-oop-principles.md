# 객체 지향 프로그래밍의 핵심 원리

객체 지향 프로그래밍은 코드를 기능 목록으로만 보지 않고, 상태와 행동을 가진 객체들의 협력으로 바라보는 방법입니다.

## 핵심 키워드

`OOP` · `객체` · `추상화` · `캡슐화` · `상속` · `다형성`

## 핵심 요약

- 객체는 관련된 데이터와 동작을 한 단위로 묶습니다.
- 추상화는 문제 해결에 필요한 특징만 모델에 남깁니다.
- 캡슐화는 내부 상태를 보호하고 안전한 사용 통로를 제공합니다.
- 상속은 공통 기능을 재사용하고, 다형성은 같은 호출에 서로 다른 동작을 가능하게 합니다.

## 1. 객체로 프로그램 바라보기

객체 지향 프로그래밍(Object-Oriented Programming)은 프로그램을 객체 단위로 나누고 객체 사이의 상호작용으로 기능을 구현하는 방식입니다. 객체는 **상태**를 나타내는 프로퍼티와 **행동**을 나타내는 메서드를 함께 가집니다.

```javascript
const counter = {
  value: 0,
  increase() {
    this.value += 1;
  },
};

counter.increase();
console.log(counter.value); // 1
```

숫자와 증가 로직이 같은 객체에 있으므로 상태를 누가 바꾸는지 추적하기 쉽습니다. 규모가 커질수록 책임이 분명한 객체는 변경 범위를 줄여 줍니다.

## 2. OOP의 네 가지 특성

| 특성 | 쉬운 의미 | 해결하는 문제 |
|---|---|---|
| 추상화 | 필요한 공통 특징만 모델로 표현 | 복잡한 현실을 코드로 다루기 어려움 |
| 캡슐화 | 상태와 동작을 묶고 내부 접근을 제한 | 아무 코드나 상태를 깨뜨리는 문제 |
| 상속 | 기존 클래스의 기능을 이어받아 확장 | 공통 코드의 반복 |
| 다형성 | 같은 메서드 호출이 객체에 따라 다르게 동작 | 종류별 조건문이 늘어나는 문제 |

네 특성은 반드시 모두 적용해야 하는 체크리스트가 아닙니다. 문제에 맞는 책임과 경계를 설계하기 위한 관점입니다.

## 3. 추상화의 두 방향

여러 구체적인 대상에서 공통 특징을 뽑아 클래스를 만드는 것이 구체에서 추상으로 가는 과정입니다. 반대로 클래스에 실제 값을 넣어 객체를 생성하는 것은 추상에서 구체로 가는 과정입니다.

예를 들어 알림을 모델링할 때 핵심이 수신자와 메시지 전송이라면 색상이나 화면 위치는 제외할 수 있습니다. 무엇을 빼느냐도 설계 결정입니다.

## 대표 코드: 알림 객체의 책임 설계

### 목적

알림에 필요한 상태와 동작만 한 객체에 모읍니다.

```javascript
class Notification {
  constructor(receiver, message) {
    this.receiver = receiver;
    this.message = message;
    this.sent = false;
  }

  send() {
    this.sent = true;
    return `${this.receiver}에게 전송 완료`;
  }
}

const notice = new Notification("사용자", "점검이 완료되었습니다.");
console.log(notice.send());
console.log(notice.sent); // true
```

### 코드 흐름과 결과

1. 클래스가 알림에 필요한 상태와 동작을 정의합니다.
2. 생성 시 수신자와 메시지를 객체 상태로 저장합니다.
3. `send()`가 전송 상태를 변경하고 결과를 반환합니다.
4. 호출자는 내부 구현보다 공개된 행동에 집중합니다.

### 실무 연결

장바구니, 주문, 회원, 알림처럼 데이터와 규칙이 함께 변하는 영역을 객체로 나누면 기능 추가와 테스트가 쉬워집니다.

## 헷갈리기 쉬운 포인트

| 비교 | 차이 |
|---|---|
| 객체 지향 vs 클래스 문법 | 객체 지향은 설계 관점이고 클래스는 이를 표현하는 한 가지 문법입니다. |
| 추상화 vs 캡슐화 | 추상화는 무엇을 모델링할지 고르고, 캡슐화는 내부를 어떻게 보호할지 정합니다. |
| 상속 vs 다형성 | 상속은 관계와 재사용, 다형성은 같은 호출의 다양한 동작에 초점이 있습니다. |
