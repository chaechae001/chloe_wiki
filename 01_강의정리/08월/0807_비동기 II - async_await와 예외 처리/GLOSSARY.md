# 용어집

## async 함수

선언 앞에 `async`를 붙인 함수입니다. 어떤 값을 반환하든 호출자에게는 Promise가 전달되며, 함수 내부에서 던진 예외는 rejected Promise가 됩니다.

## await

Promise가 정착될 때까지 현재 `async` 함수의 나머지 실행을 미루는 연산자입니다. 성공하면 값을 꺼내고 실패하면 예외를 발생시킵니다.

## 순차 실행

앞 작업이 끝난 뒤 다음 작업을 시작하는 방식입니다. 앞 결과가 다음 작업의 입력일 때 필요합니다.

## 병렬 시작

서로 독립적인 여러 비동기 작업을 먼저 시작한 뒤 함께 기다리는 방식입니다. 자바스크립트 코드가 동시에 실행된다는 의미보다, 대기 시간이 겹치도록 예약한다는 의미에 가깝습니다.

## Promise.all

여러 Promise가 모두 성공할 때까지 기다리고 입력 순서대로 결과 배열을 만드는 메서드입니다. 하나라도 실패하면 반환 Promise가 거부됩니다.

## 예외(Exception)

정상 실행 흐름을 벗어난 오류 상황입니다. `throw`로 직접 발생시킬 수 있고, 잘못된 JSON 파싱처럼 실행 중 자동으로 발생할 수도 있습니다.

## 오류 전파

현재 위치에서 처리하지 않은 오류가 호출자나 Promise 체인의 다음 실패 처리기로 전달되는 과정입니다.

## try 블록

오류가 발생할 가능성이 있는 코드를 실행하는 영역입니다. 발생한 예외는 연결된 `catch`로 전달됩니다.

## catch 블록

`try` 영역에서 발생한 오류를 받아 복구, 기록, 사용자 안내 같은 대응을 수행합니다.

## finally 블록

성공과 실패에 관계없이 마지막에 실행되는 영역입니다. 로딩 상태 해제나 자원 정리처럼 공통 마무리에 적합합니다.

## throw

오류를 명시적으로 발생시키는 문법입니다. 보통 `throw new Error(message)` 형태로 사용해 의미 있는 오류 정보를 전달합니다.

## 직렬화(Serialization)

객체 같은 메모리 데이터를 저장하거나 전송하기 쉬운 문자열 형식으로 바꾸는 과정입니다. JavaScript에서는 `JSON.stringify`가 대표적입니다.

## 역직렬화(Deserialization)

문자열로 전달된 데이터를 다시 프로그램이 다룰 수 있는 객체로 복원하는 과정입니다. `JSON.parse`는 형식이 잘못되면 예외를 던집니다.

## 디바운싱(Debouncing)

짧은 시간에 이벤트가 연속 발생하면 이전 예약을 취소하고, 이벤트가 멈춘 뒤 마지막 호출만 실행하는 제어 방식입니다.

## 쓰로틀링(Throttling)

이벤트가 계속 발생해도 정해진 시간 구간마다 최대 한 번만 처리하도록 호출 빈도를 제한하는 방식입니다.

## 비동기 이터레이션

반복 과정에서 Promise 완료를 기다리며 데이터를 처리하는 흐름입니다. 순차 처리에는 `for...of`와 `await`, 병렬 처리에는 `map`과 `Promise.all`을 자주 사용합니다.

## 정리 작업(Cleanup)

로딩 표시 해제, 연결 종료, 타이머 취소처럼 주 작업이 끝난 뒤 반드시 수행해야 하는 마무리 동작입니다.
