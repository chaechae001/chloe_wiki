# 이벤트 루프와 작업 큐

Node.js가 입출력을 효율적으로 다루는 이유는 콜 스택이 비었을 때 준비된 작업을 올려 실행하는 이벤트 루프에 있습니다.

**핵심 키워드:** 콜 스택, 이벤트 루프, 타이머, 마이크로태스크, I/O

## 핵심 내용

- 동기 JavaScript는 콜 스택에서 위에서 아래로 실행됩니다.
- 비동기 작업은 등록된 뒤 런타임과 운영체제가 진행하고, 완료 시 실행할 콜백이 대기합니다.
- 이벤트 루프는 실행 가능한 콜백을 단계와 우선순위 규칙에 따라 콜 스택으로 보냅니다.
- Promise 후속 작업 같은 마이크로태스크는 일반 타이머 콜백보다 먼저 처리되는 경우가 많습니다.
- 긴 동기 코드나 끝없는 마이크로태스크는 이벤트 루프 진행을 막을 수 있습니다.

## 실행 요소

| 요소 | 역할 |
|---|---|
| Call Stack | 현재 실행 중인 JavaScript 함수 관리 |
| Runtime APIs | 타이머, 파일, 네트워크 작업 등록 |
| Task Queues | 실행 준비가 된 콜백 대기 |
| Microtask Queue | Promise 후속 작업 등 높은 우선순위 작업 대기 |
| Event Loop | 실행 시점과 단계 조정 |

## 출력 순서 관찰

```javascript
console.log("A");

setTimeout(() => console.log("timer"), 0);
Promise.resolve().then(() => console.log("promise"));

console.log("B");
```

일반적으로 `A`, `B`, `promise`, `timer` 순서가 됩니다.

- **목적:** 동기 코드, 마이크로태스크, 타이머의 상대적 실행 순서를 관찰합니다.
- **흐름:** 동기 로그 → 타이머 등록 → Promise 작업 등록 → 동기 로그 → 마이크로태스크 → 타이머입니다.
- **결과:** 지연 시간이 0이어도 타이머가 즉시 콜 스택을 가로채지 못함을 확인합니다.
- **실무 포인트:** 정확한 세부 순서는 실행 환경과 이벤트 루프 단계에 영향을 받으므로 단순한 “큐 하나” 모델로 모든 경우를 일반화하지 않습니다.

## Node.js 이벤트 루프 이해하기

Node.js 이벤트 루프에는 타이머와 I/O 콜백 등 여러 단계가 있습니다. 각 단계 사이에서 마이크로태스크가 처리될 수 있고, Node.js 고유 예약 큐도 존재합니다. 초보 단계에서는 “현재 동기 코드가 끝난 뒤 준비된 작업이 규칙에 따라 실행된다”는 원칙을 먼저 잡는 것이 중요합니다.

## 이벤트 루프를 막는 코드

```javascript
const startedAt = Date.now();
while (Date.now() - startedAt < 2000) {
  // 메인 스레드를 오래 점유하는 동기 작업
}
```

이 동안 타이머와 요청 콜백이 준비되어도 JavaScript를 실행할 수 없습니다. 큰 계산을 작은 작업으로 나누거나 다른 실행 단위로 옮기는 설계가 필요합니다.

## 실습

1. 동기 로그, Promise, 타이머의 출력 순서를 예측하고 실행하세요.
2. 긴 동기 반복문이 요청 처리에 미치는 영향을 설명하세요.
3. 독립된 파일 읽기 두 개를 병렬로 시작하도록 작성하세요.

<details>
<summary>답</summary>

동기 로그가 먼저 끝나고 일반적으로 Promise 후속 작업이 타이머보다 먼저 실행됩니다. 긴 반복문은 콜 스택을 점유해 다른 콜백을 지연시킵니다. 독립 파일 읽기는 `Promise.all`로 함께 시작할 수 있습니다.

</details>

## 복습 질문 및 답변

### Q1. `setTimeout(fn, 0)`은 fn을 즉시 실행하나요?

<details>
<summary>답</summary>

아닙니다. 최소 지연 후 실행 가능한 상태가 되며, 현재 콜 스택과 우선 처리 작업이 끝나야 콜백이 실행됩니다.

</details>

### Q2. 비동기 작업의 콜백도 JavaScript 메인 스레드에서 실행되나요?

<details>
<summary>답</summary>

일반적인 콜백 JavaScript는 메인 콜 스택에서 실행됩니다. 실제 입출력 처리는 런타임과 운영체제 등에 위임될 수 있습니다.

</details>

### Q3. 마이크로태스크가 너무 많아도 문제가 되나요?

<details>
<summary>답</summary>

계속 마이크로태스크를 생성하면 다른 이벤트 루프 단계가 실행될 기회를 늦춰 타이머나 I/O 처리가 지연될 수 있습니다.

</details>

## 요약

이벤트 루프는 한 JavaScript 콜 스택과 여러 비동기 실행 자원을 연결합니다. 동기 코드, 마이크로태스크와 일반 콜백의 관계를 알면 출력 순서와 응답 지연을 설명할 수 있습니다.
