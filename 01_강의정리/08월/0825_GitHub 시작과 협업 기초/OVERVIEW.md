# GitHub 시작과 협업 기초

Git의 로컬 버전 관리부터 GitHub 저장소 설정, 브랜치 전략, Pull Request와 병합까지 한 흐름으로 학습합니다.

## 학습 목표

- Git과 GitHub의 역할을 구분합니다.
- 안전한 저장소를 만들고 로컬·원격 이력을 동기화합니다.
- Issue, 브랜치, Pull Request와 Review를 연결합니다.
- 팀 상황에 맞는 브랜치와 병합 전략을 선택합니다.
- 충돌과 비밀정보 노출 같은 협업 위험에 대응합니다.

## 전체 흐름

```text
저장소 준비 → 최신 기준 동기화 → 작업 브랜치 생성
→ 작은 커밋 → 테스트 → 원격 푸시 → Pull Request
→ Review와 자동 검사 → 병합 → 브랜치 정리
```

## 최종 점검

- [ ] 커밋과 푸시의 차이를 설명할 수 있다.
- [ ] 공개 저장소에 비밀정보를 넣지 않는다.
- [ ] 작업마다 짧은 브랜치와 명확한 PR을 만든다.
- [ ] 병합 방식이 이력에 미치는 영향을 이해한다.
- [ ] 충돌 해결 후 테스트하고 팀 정책에 따라 병합한다.
