# Pull Request 협업 흐름

좋은 Pull Request는 코드를 합치기 위한 버튼이 아니라 변경을 작게 설명하고 검증하는 작업 기록입니다.

**핵심 키워드:** 작업 동기화, 변경 범위, 테스트, Pull Request, 코드 리뷰

## 핵심 내용

- 작업 전 기준 브랜치를 최신화하면 불필요한 충돌을 줄일 수 있습니다.
- 하나의 브랜치는 하나의 목적에 집중해야 리뷰가 쉬워집니다.
- 커밋은 작고 실행 가능한 단위로 나누며 메시지에 의도를 기록합니다.
- PR에는 변경 이유, 핵심 내용, 검증 방법과 영향 범위를 적습니다.
- 리뷰 반영 후 자동 검사와 승인을 확인하고 팀 규칙에 맞게 병합합니다.

## 표준 작업 순서

```bash
git switch main
git pull --ff-only
git switch -c feature/search-filter
# 수정
git diff
git add src/search.js
git commit -m "feat: 검색 결과 필터 추가"
git push -u origin feature/search-filter
```

- **목적:** 최신 기준에서 독립된 변경을 만들고 원격에 게시합니다.
- **흐름:** 동기화 → 브랜치 → 수정 → 차이 검토 → 선택 스테이징 → 커밋 → 푸시입니다.
- **결과:** GitHub에서 기준 브랜치를 대상으로 PR을 만들 수 있습니다.
- **실무 포인트:** 관계없는 포맷 변경과 기능 변경을 한 PR에 섞지 않습니다.

## 좋은 PR 본문

| 항목 | 작성 내용 |
|---|---|
| 배경 | 왜 변경이 필요한가 |
| 변경 | 무엇을 어떻게 바꿨는가 |
| 검증 | 어떤 테스트를 실행했는가 |
| 영향 | 호환성, 배포, 데이터 영향은 무엇인가 |
| 연결 | 관련 Issue와 후속 작업은 무엇인가 |

화면 변화가 있다면 필요한 범위의 캡처를, API 변화가 있다면 요청·응답 예시를 추가합니다. 자동 검사를 통과했다는 사실만으로 요구사항 검토가 끝나는 것은 아닙니다.

## 리뷰 반영

리뷰 의견을 이해한 뒤 새 커밋으로 수정하거나, 아직 공유되지 않은 로컬 커밋만 정리합니다. 이미 다른 사람이 사용 중인 브랜치의 이력을 임의로 재작성하고 강제 푸시하면 협업자의 작업이 끊길 수 있습니다.

## 실습

1. 검색 필터 기능 PR의 배경과 검증 방법을 작성하세요.
2. 기능 수정과 전역 포맷 변경을 어떻게 나눌지 설명하세요.
3. 리뷰 요청 전 자체 점검 항목을 다섯 개 작성하세요.

<details>
<summary>답</summary>

예: 요구사항 충족, 테스트 통과, 디버그 코드 제거, 비밀정보 미포함, 변경 파일·PR 본문 확인. 전역 포맷 변경은 기능 PR과 별도 커밋 또는 별도 PR로 분리합니다.

## 체크리스트

- [ ] 최신 기준 브랜치에서 작업을 시작했다.
- [ ] 브랜치와 PR이 하나의 목적에 집중한다.
- [ ] 커밋 전 diff와 스테이징 범위를 확인했다.
- [ ] 테스트 결과와 영향 범위를 PR에 적었다.
- [ ] 자동 검사와 필요한 승인을 확인했다.

## 복습 질문 및 답변

### Q1. PR이 작을수록 좋은 이유는 무엇인가요?

<details>
<summary>답</summary>

변경 의도를 이해하고 결함을 찾기 쉬우며, 문제 발생 시 되돌리거나 수정할 범위도 작아집니다.

</details>

### Q2. 자동 테스트를 통과하면 리뷰가 필요 없나요?

<details>
<summary>답</summary>

필요합니다. 자동 테스트는 정의된 조건을 검사하지만 요구사항의 적절성, 설계, 가독성, 놓친 위험까지 모두 판단하지는 못합니다.

</details>

### Q3. 리뷰 중에 관계없는 문제를 발견하면 어떻게 하나요?

<details>
<summary>답</summary>

현재 PR의 필수 수정인지 판단하고, 범위를 벗어나면 별도 Issue나 후속 PR로 분리해 현재 변경의 초점을 유지합니다.

</details>

## 요약

PR 품질은 변경 크기, 설명, 검증과 리뷰 대화에서 결정됩니다. 최신 기준에서 작은 브랜치를 만들고, 근거가 남는 검토를 거쳐 병합하세요.
