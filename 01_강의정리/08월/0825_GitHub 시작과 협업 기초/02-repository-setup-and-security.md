# 저장소 설정과 보안

좋은 저장소는 코드를 올리기 전에 공개 범위, 기본 문서, 제외 파일과 라이선스를 명확히 정합니다.

**핵심 키워드:** 저장소, 공개 범위, README, .gitignore, 비밀정보

## 핵심 내용

- 저장소 이름은 프로젝트의 목적을 짧고 일관되게 드러내야 합니다.
- 공개 저장소는 누구나 볼 수 있으므로 비밀정보와 개인정보를 절대 커밋하지 않습니다.
- `README.md`는 목적, 실행 방법, 구조, 기여 방법을 안내하는 첫 문서입니다.
- `.gitignore`는 생성물, 의존성, 로컬 설정처럼 추적하지 않을 파일을 정의합니다.
- 라이선스는 다른 사람이 코드를 사용할 수 있는 조건을 명시합니다.

## 저장소 생성 전 결정사항

소유자와 저장소 이름, 공개 여부, 기본 브랜치, 초기 파일을 먼저 결정합니다. 공개 저장소는 포트폴리오와 오픈소스에 적합하지만 코드와 이력이 모두 노출됩니다. 비공개 저장소도 초대받은 사용자의 권한을 최소한으로 관리해야 합니다.

| 항목 | 포함하는 경우 | 주의점 |
|---|---|---|
| README | 프로젝트 설명을 즉시 제공 | 실제 실행 방법과 일치시킴 |
| .gitignore | 불필요한 파일 추적 방지 | 이미 추적된 파일에는 자동 적용되지 않음 |
| License | 사용·수정·배포 조건 명시 | 프로젝트 의도에 맞는 조건 선택 |
| 공개 저장소 | 결과 공유가 쉬움 | 비밀정보와 내부 자료 노출 금지 |

## 안전한 초기화

```bash
git init
git status
git add README.md .gitignore LICENSE
git commit -m "chore: 저장소 초기 설정"
```

- **목적:** 저장소의 기본 정책을 첫 커밋에 명확히 기록합니다.
- **흐름:** 초기화 → 추적 대상 검토 → 기본 파일 스테이징 → 커밋입니다.
- **결과:** 협업자가 저장소의 용도와 제외 규칙을 처음부터 확인할 수 있습니다.
- **실무 포인트:** `.env`, API 키, 인증서, 개인 데이터는 커밋 전에 반드시 제외합니다.

## 비밀정보가 커밋되었다면

파일을 삭제하는 것만으로는 과거 커밋에서 사라지지 않습니다. 먼저 노출된 키를 폐기·재발급하고, 필요하면 이력 정리 절차를 팀과 협의합니다. 이력 재작성은 다른 사람의 로컬 기록과 충돌할 수 있으므로 혼자 강제 푸시하지 않습니다.

```gitignore
node_modules/
.env
.env.*
dist/
coverage/
*.log
```

## 실습

1. 프런트엔드 프로젝트에 필요한 `.gitignore` 항목을 작성하세요.
2. README에 목적, 설치, 실행, 폴더 구조 항목을 만드세요.
3. 공개 저장소에 올리면 안 되는 파일 세 가지를 적으세요.

<details>
<summary>답</summary>

예: `.env`, 개인 인증서, 사용자 데이터 덤프는 공개 저장소에 올리면 안 됩니다. `.gitignore`에는 `node_modules/`, `.env*`, `dist/`, 로그 등을 포함할 수 있습니다.

</details>

## 복습 질문 및 답변

### Q1. `.gitignore`에 파일을 추가하면 이미 커밋된 파일도 사라지나요?

<details>
<summary>답</summary>

아닙니다. `.gitignore`는 아직 추적하지 않는 파일에 적용됩니다. 이미 추적한 파일은 별도로 추적 대상에서 제거해야 합니다.

</details>

### Q2. 비밀 키를 삭제하고 다시 커밋하면 충분한가요?

<details>
<summary>답</summary>

충분하지 않습니다. 과거 이력에 남을 수 있으므로 키를 즉시 폐기·재발급하고 이력 정리가 필요한지 판단해야 합니다.

</details>

### Q3. README의 가장 중요한 역할은 무엇인가요?

<details>
<summary>답</summary>

처음 방문한 사람이 프로젝트의 목적과 실행 방법, 주요 구조를 빠르게 이해하도록 돕는 것입니다.

</details>

## 요약

저장소의 품질은 코드뿐 아니라 공개 범위, 문서, 제외 규칙, 라이선스와 비밀정보 관리에서 결정됩니다. 커밋 전에 노출 가능성을 점검하는 것이 가장 효과적인 보안 습관입니다.
