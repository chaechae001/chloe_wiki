# GitHub 협업 도구

원격 저장소는 파일 보관함이 아니라 작업을 제안하고 토론하며 결정의 근거를 남기는 협업 공간입니다.

**핵심 키워드:** Collaborator, Issue, Pull Request, Review, Wiki

## 핵심 내용

- Collaborator 권한은 필요한 사람에게 필요한 범위만 부여합니다.
- Issue는 버그, 개선, 질문 같은 작업의 배경과 완료 조건을 기록합니다.
- Pull Request는 브랜치 변경을 기준 브랜치에 반영해 달라는 검토 요청입니다.
- Review는 코드 품질뿐 아니라 요구사항, 테스트, 보안과 유지보수성을 확인합니다.
- Wiki나 문서는 반복해서 참고할 팀 지식을 저장합니다.

## 협업 도구의 역할

| 도구 | 질문 | 대표 결과 |
|---|---|---|
| Issue | 무엇을 왜 해야 하는가? | 작업 범위와 완료 조건 |
| Branch | 어디에서 독립적으로 작업할까? | 격리된 커밋 이력 |
| Pull Request | 이 변경을 합쳐도 되는가? | 리뷰와 병합 결정 |
| Wiki/문서 | 팀이 반복해서 알아야 할 것은? | 규칙과 운영 지식 |

## 권한과 초대

저장소 소유자는 협업자를 초대하고 역할을 지정할 수 있습니다. 모든 사람에게 관리 권한을 주기보다 읽기, 이슈 관리, 쓰기, 유지보수, 관리 중 실제 업무에 필요한 최소 권한을 선택하는 것이 안전합니다. 협업이 끝나면 접근 권한도 정리합니다.

## Issue에서 PR까지

```text
Issue 작성 → 담당자·범위 합의 → 작업 브랜치 생성
→ 작은 커밋 → 테스트 → Pull Request → Review → Merge
```

- **목적:** 코드 변경과 그 배경을 연결합니다.
- **흐름:** 문제 정의부터 구현, 검토, 병합까지 추적합니다.
- **결과:** 나중에 왜 변경했는지 이슈와 PR에서 확인할 수 있습니다.
- **실무 포인트:** PR 본문에는 변경 이유, 주요 내용, 검증 방법, 영향 범위를 포함합니다.

## 좋은 리뷰 대화

사람이 아니라 코드와 요구사항에 집중합니다. “잘못됨”보다 “이 입력이 비어 있을 때 예외가 발생할 수 있으니 기본값을 두는 것은 어떨까요?”처럼 근거와 대안을 함께 제시합니다. 반드시 수정해야 하는 항목과 제안을 구분하면 의사결정이 빨라집니다.

## 실습

1. 버그 Issue에 재현 절차와 완료 조건을 작성하세요.
2. PR 템플릿에 필요한 항목 네 가지를 정리하세요.
3. 팀 문서로 남길 내용과 Issue로 관리할 내용을 구분하세요.

<details>
<summary>답</summary>

PR 템플릿 예: 변경 이유, 주요 변경, 테스트 방법, 영향 범위. 반복되는 규칙은 문서에, 종료 가능한 작업은 Issue에 두는 것이 적합합니다.

</details>

- [ ] 협업자에게 최소 권한을 부여한다.
- [ ] Issue에 배경과 완료 조건을 기록한다.
- [ ] PR에 변경 이유와 검증 방법을 적는다.
- [ ] 리뷰 의견에 근거와 대안을 담는다.

## 복습 질문 및 답변

### Q1. Pull Request는 단순히 코드를 올리는 기능인가요?

<details>
<summary>답</summary>

아닙니다. 특정 브랜치의 변경을 다른 브랜치에 병합하기 전에 설명, 자동 검사, 리뷰와 의사결정을 모으는 협업 단위입니다.

</details>

### Q2. Issue와 Wiki의 차이는 무엇인가요?

<details>
<summary>답</summary>

Issue는 완료 가능한 개별 작업이나 문제를 추적하고, Wiki나 문서는 장기간 반복해서 참고할 지식을 정리합니다.

</details>

### Q3. 모든 협업자에게 관리자 권한을 주면 편하지 않나요?

<details>
<summary>답</summary>

편할 수 있지만 실수나 계정 침해의 영향이 커집니다. 업무 수행에 필요한 최소 권한만 부여하는 것이 안전합니다.

</details>

## 요약

Issue는 일을 정의하고, 브랜치는 작업을 격리하며, PR과 Review는 변경을 검증합니다. 권한과 기록을 함께 관리해야 저장소가 신뢰할 수 있는 협업 공간이 됩니다.
