# 클라이언트·서버와 HTTP 통신

웹 서비스는 화면과 서버가 메시지를 주고받는 구조에서 시작합니다. 통신의 방향과 규칙을 이해하면 API 코드가 단순한 암기 대상이 아니라 읽을 수 있는 흐름이 됩니다.

## 핵심 키워드

`클라이언트` · `서버` · `요청` · `응답` · `HTTP` · `무상태`

## 핵심 요약

- 클라이언트는 서비스를 요청하고 서버는 요청을 처리해 응답합니다.
- 프론트엔드와 백엔드는 HTTP라는 공통 규칙으로 협력합니다.
- HTTP 요청은 서로 독립적인 무상태 통신을 기본으로 합니다.
- 한 번의 통신은 요청과 응답이 짝을 이룰 때 완성됩니다.

## 1. 요청과 응답

### 정의와 필요성

클라이언트는 브라우저처럼 서비스를 사용하는 쪽이고, 서버는 데이터와 기능을 제공하는 쪽입니다. 클라이언트가 원하는 작업을 요청하면 서버는 필요한 로직이나 데이터 조회를 수행한 뒤 결과를 응답합니다.

```text
브라우저 ── 요청: 할 일 목록 조회 ──> 서버 ── 조회 ──> 저장소
브라우저 <─ 응답: JSON 목록 ─────── 서버 <─ 결과 ─── 저장소
```

역할을 나누면 화면과 데이터 처리를 독립적으로 변경할 수 있습니다. 여러 종류의 클라이언트가 같은 서버 기능을 재사용하기도 쉬워집니다.

### 프론트엔드와 백엔드

| 구분 | 주된 책임 | 대표 작업 |
|---|---|---|
| 프론트엔드 | 사용자 입력과 화면 표현 | 버튼 이벤트, 요청 전송, DOM 갱신 |
| 백엔드 | 요청 해석과 데이터 처리 | 검증, 비즈니스 로직, 데이터 저장 |

둘은 서로의 내부 구현을 몰라도 약속된 주소, 메서드, 데이터 형식을 지키면 통신할 수 있습니다.

## 2. 프로토콜과 HTTP

프로토콜은 데이터를 어떤 형식과 순서로 주고받을지 정한 규칙입니다. 웹에서는 HTTP가 요청과 응답 메시지의 구조를 정의합니다.

HTTP의 중요한 특징은 다음과 같습니다.

- **무상태**: 각 요청은 독립적입니다. 서버는 앞선 요청의 문맥을 자동으로 기억하지 않습니다.
- **요청·응답 구조**: 클라이언트가 요청해야 서버가 해당 응답을 보냅니다.
- **다양한 표현 전송**: HTML, JSON, 이미지 등 여러 형식의 데이터를 전달할 수 있습니다.

로그인이 유지되는 것처럼 보이는 서비스는 쿠키나 토큰처럼 상태를 식별할 정보를 요청에 함께 보냅니다. 이는 HTTP 자체가 이전 요청을 기억해서가 아닙니다.

## 대표 코드: 통신 흐름을 함수로 표현하기

### 목적

클라이언트가 서버 함수에 요청 정보를 전달하고 응답을 받는 최소 흐름을 확인합니다.

```javascript
function server(request) {
  if (request.method === "GET" && request.path === "/tasks") {
    return {
      status: 200,
      body: [{ id: 1, title: "HTTP 흐름 복습" }],
    };
  }

  return { status: 404, body: { message: "자원을 찾을 수 없습니다." } };
}

const response = server({ method: "GET", path: "/tasks" });
console.log(response.status); // 200
console.log(response.body[0].title); // HTTP 흐름 복습
```

### 코드 흐름과 결과

1. 클라이언트 역할의 코드가 메서드와 경로를 요청으로 만듭니다.
2. 서버 역할의 함수가 두 값을 기준으로 처리할 기능을 선택합니다.
3. 서버가 상태와 데이터를 응답 객체에 담습니다.
4. 클라이언트는 상태를 확인한 뒤 본문을 사용합니다.

실제 네트워크 통신은 아니지만 요청의 입력과 응답의 출력을 분리해서 생각하는 연습이 됩니다.

### 실무 연결

화면 오류를 진단할 때는 먼저 요청이 전송됐는지, 서버가 어떤 상태를 반환했는지, 응답 데이터가 예상한 구조인지 순서대로 확인합니다.

## 직접 해보기

`POST /tasks` 요청일 때 상태 `201`과 새 할 일 객체를 반환하도록 `server` 함수에 분기를 추가해 보세요.

<details>
<summary>답</summary>

```javascript
if (request.method === "POST" && request.path === "/tasks") {
  return {
    status: 201,
    body: { id: 2, title: request.body.title },
  };
}
```

`POST`와 경로를 함께 확인해야 같은 경로의 조회 요청과 구분할 수 있습니다.

</details>

## 헷갈리기 쉬운 차이점

| 비교 | 차이 |
|---|---|
| 클라이언트 vs 서버 | 클라이언트는 기능을 요청하고 서버는 기능을 제공하고 결과를 반환합니다. |
| 프로토콜 vs API | 프로토콜은 통신 규칙이고 API는 프로그램이 사용할 수 있도록 공개한 기능의 접점입니다. |
| 무상태 vs 로그인 유지 | HTTP는 요청을 기억하지 않으며 로그인 문맥은 쿠키·토큰 같은 별도 정보로 전달합니다. |
