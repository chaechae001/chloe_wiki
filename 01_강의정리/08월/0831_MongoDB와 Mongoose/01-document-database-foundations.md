# 문서형 데이터베이스 기초

MongoDB는 행과 테이블 대신 JSON과 비슷한 문서로 데이터를 저장해 애플리케이션 객체 구조를 자연스럽게 표현합니다.

**핵심 키워드:** NoSQL, Document DB, BSON, 유연한 스키마, 데이터 모델링

## 핵심 내용

- MongoDB는 문서형 NoSQL 데이터베이스입니다.
- 문서는 JSON과 비슷하지만 실제 저장에는 더 다양한 타입을 지원하는 BSON을 사용합니다.
- 관련 데이터를 한 문서에 포함하거나 다른 문서를 참조하는 방식으로 관계를 표현합니다.
- 유연한 스키마는 구조가 없어도 된다는 뜻이 아니라 변화 규칙을 애플리케이션이 관리해야 한다는 뜻입니다.
- 데이터 모델은 읽기 패턴, 갱신 빈도, 크기 증가와 일관성 요구에 맞춰 설계합니다.

## 관계형 데이터베이스와 비교

| 관점 | 관계형 데이터베이스 | MongoDB |
|---|---|---|
| 기본 단위 | 행과 테이블 | 문서와 컬렉션 |
| 구조 | 명시적 스키마와 관계 | 문서별 유연한 필드 |
| 관계 처리 | JOIN 중심 | 포함 또는 참조 |
| 확장 설계 | 정규화와 트랜잭션 중심 | 접근 패턴과 분산 고려 |

어느 한쪽이 항상 우월하지 않습니다. 복잡한 관계와 강한 제약이 핵심이면 관계형 모델이, 계층형 데이터와 빠른 구조 변화가 중요하면 문서형 모델이 유리할 수 있습니다.

## BSON 문서 예시

```javascript
{
  _id: ObjectId("..."),
  title: "MongoDB 모델링",
  tags: ["database", "nosql"],
  author: {
    name: "Kim",
    level: 2
  },
  publishedAt: new Date()
}
```

- **목적:** 게시글과 작은 작성자 요약을 하나의 문서로 표현합니다.
- **흐름:** 필드 정의 → 중첩 객체와 배열 구성 → MongoDB 컬렉션 저장입니다.
- **결과:** 한 번의 문서 조회로 자주 함께 사용하는 데이터를 얻을 수 있습니다.
- **실무 포인트:** 계속 증가하는 배열을 무제한으로 한 문서에 포함하면 문서 크기와 갱신 비용이 커질 수 있습니다.

## 포함과 참조

| 방식 | 적합한 상황 | 주의점 |
|---|---|---|
| 포함 | 함께 읽고 함께 바뀌는 작은 데이터 | 중복과 문서 성장 |
| 참조 | 독립 수명주기, 큰 관계, 여러 곳에서 공유 | 추가 조회와 일관성 |

읽기 요청 한 번을 줄이기 위해 모든 관계를 포함하거나, 관계형 설계처럼 모든 데이터를 분리하지 않습니다. 실제 쿼리 패턴을 기준으로 균형을 잡습니다.

## 복습 질문 및 답변

### Q1. MongoDB 문서는 JSON 파일과 완전히 같은가요?

<details>
<summary>답</summary>

형태는 비슷하지만 MongoDB는 BSON으로 저장해 ObjectId, Date와 같은 JSON보다 다양한 데이터 타입을 지원합니다.

</details>

### Q2. NoSQL은 관계를 표현할 수 없나요?

<details>
<summary>답</summary>

표현할 수 있습니다. 관련 데이터를 문서에 포함하거나 다른 문서의 식별자를 참조하는 방식으로 모델링합니다.

</details>

### Q3. 포함 방식이 항상 조회 성능에 유리한가요?

<details>
<summary>답</summary>

항상 그렇지는 않습니다. 문서가 지나치게 커지거나 자주 중복 갱신되면 저장 비용과 일관성 관리가 더 어려워질 수 있습니다.

</details>

## 요약

MongoDB는 BSON 문서를 중심으로 데이터를 모델링합니다. 유연성을 활용하되 실제 읽기·쓰기 패턴과 데이터 성장, 일관성을 고려해 포함과 참조를 선택해야 합니다.
