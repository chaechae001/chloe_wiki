# 호이스팅과 TDZ

> 선언보다 앞에서 이름이 보이는 현상은 코드가 이동해서가 아니라, 실행 전에 선언 정보를 먼저 준비하기 때문에 생깁니다.

`hoisting` · `var` · `let` · `const` · `TDZ`

## 핵심요약

- 호이스팅은 평가 단계에서 선언 정보가 실행보다 먼저 환경에 등록되어 나타나는 현상입니다.
- `var`는 등록과 함께 `undefined`로 초기화되어 선언 전 참조 결과가 `undefined`입니다.
- `let`과 `const`도 등록되지만 선언문 실행 전까지 초기화되지 않아 참조하면 오류가 발생합니다.
- 등록 후 초기화 전까지 접근할 수 없는 구간을 TDZ라고 합니다.
- 함수 선언문과 함수 표현식은 평가 단계에서 준비되는 수준이 달라 선언 전 호출 결과가 다릅니다.

## 1. 변수 호이스팅과 TDZ

### 1) 정의

호이스팅은 스코프의 선언이 코드 실행 전에 환경 레코드에 등록되어 선언문보다 앞에서도 엔진이 식별자의 존재를 알고 있는 동작입니다. TDZ는 `let`과 `const`가 등록됐지만 초기화되지 않아 접근할 수 없는 구간입니다.

### 2) 왜 필요한가

선언 전 참조가 `undefined`인지 `ReferenceError`인지 예측하고, 초기화 순서와 스코프 버그를 정확히 찾기 위해 필요합니다.

### 3) 핵심 흐름 재구성

```text
var:   환경 등록 + undefined 초기화 → 선언문에서 값 할당
let:   환경 등록 → TDZ → 선언문에서 초기화
const: 환경 등록 → TDZ → 선언문에서 반드시 초기화
```

### 4) 쉬운 예시

좌석표에 이름과 임시 번호까지 적힌 경우가 `var`, 이름은 등록됐지만 좌석 배정 전이라 접근할 수 없는 경우가 `let`·`const`와 비슷합니다.

### 5) 코드 예시

```javascript
console.log(oldValue); // undefined
var oldValue = 10;

// console.log(newValue); // ReferenceError
let newValue = 20;
```

두 선언 모두 평가되지만 초기화 시점이 다릅니다.

### 6) 헷갈리는 점

`let`과 `const`가 호이스팅되지 않는 것이 아닙니다. 등록은 되었지만 TDZ 때문에 초기화 전에 접근할 수 없는 것입니다.

### 7) 한 줄 정리

> 호이스팅의 핵심은 선언 등록 시점이고, TDZ의 핵심은 초기화 전 접근 금지입니다.

## 2. 함수 선언문과 함수 표현식

### 1) 정의

함수 선언문은 평가 단계에서 함수 객체까지 준비됩니다. 함수 표현식은 변수 선언 규칙을 따르며 실제 함수 값은 해당 할당문이 실행될 때 저장됩니다.

### 2) 왜 필요한가

함수 정의보다 앞에서 호출할 수 있는지와 오류가 발생하는 이유를 구분할 수 있습니다.

### 3) 핵심 흐름 재구성

```javascript
greet(); // 정상 실행

function greet() {
  console.log("hello");
}
```

```javascript
// introduce(); // ReferenceError
const introduce = function () {
  console.log("hi");
};
```

### 4) 쉬운 예시

함수 선언문은 영업 전에 완성된 레시피가 준비된 상태이고, 함수 표현식은 빈 보관함만 예약한 뒤 실행 중에 레시피를 넣는 상태와 같습니다.

### 5) 코드 예시

```javascript
console.log(makeLabel("A")); // item-A

function makeLabel(value) {
  return `item-${value}`;
}

const makeCode = (value) => `code-${value}`;
console.log(makeCode("B")); // code-B
```

### 6) 헷갈리는 점

화살표 함수인지 일반 함수 표현식인지보다 어느 변수 선언에 언제 할당되는지가 선언 전 호출 가능 여부를 결정합니다.

### 7) 한 줄 정리

> 함수 선언문은 평가 때 함수까지 준비되고, 함수 표현식은 실행 중 할당된 뒤에 사용할 수 있습니다.

## 코드로 보기 — 초기화 순서가 드러나는 구성

```javascript
function createSummary(items) {
  const count = items.length;
  const message = formatCount(count);
  return message;
}

function formatCount(count) {
  return `총 ${count}개`;
}

console.log(createSummary(["a", "b", "c"])); // 총 3개
```

### 코드 목적

함수 선언은 평가 단계에 준비하되, 변수는 사용 전에 선언하고 초기화하는 읽기 쉬운 순서를 구성합니다.

### 코드 흐름

1. 평가 단계에서 두 함수 선언을 준비합니다.
2. `createSummary` 호출 환경에서 `count`를 초기화합니다.
3. 초기화된 값을 `formatCount`에 전달합니다.
4. 완성된 문자열을 반환합니다.

### 실행 결과 해석

배열 길이 3이 먼저 계산된 뒤 문자열로 변환되어 `총 3개`가 출력됩니다. TDZ에 있는 변수를 미리 읽는 구간이 없습니다.

### 실무 연결

모듈 초기화, 설정 객체 생성, 의존성 순서를 정리할 때 선언과 사용 순서를 명확히 하면 순환 참조와 초기화 오류를 줄일 수 있습니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 등록 vs 초기화 | 등록은 이름을 환경에 기록하는 일, 초기화는 처음 참조 가능한 값을 부여하는 일입니다. |
| `var` vs `let`·`const` | 모두 등록되지만 `var`만 즉시 `undefined`로 초기화됩니다. |
| 함수 선언문 vs 함수 표현식 | 선언문은 평가 때 함수가 준비되고 표현식은 변수 할당이 실행된 뒤 함수 값이 생깁니다. |
