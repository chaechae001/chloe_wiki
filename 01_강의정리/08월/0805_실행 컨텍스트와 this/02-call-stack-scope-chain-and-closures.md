# 콜 스택과 스코프 체인

> 함수 호출 순서와 변수 검색 순서는 서로 다른 길을 따르지만, 실행 중에는 함께 작동합니다.

`call stack` · `LIFO` · `scope chain` · `lexical scope` · `closure`

## 핵심요약

- 콜 스택은 실행 컨텍스트를 나중에 들어온 것부터 먼저 제거하는 LIFO 구조로 관리합니다.
- 스택 최상단의 실행 컨텍스트가 현재 실행 중인 코드입니다.
- 스코프 체인은 현재 렉시컬 환경에서 바깥 환경으로 식별자를 탐색합니다.
- 함수가 호출된 위치가 아니라 정의된 위치가 상위 렉시컬 환경을 결정합니다.
- 클로저는 함수가 정의 당시의 바깥 변수를 계속 참조할 수 있는 성질입니다.

## 1. 콜 스택

### 1) 정의

콜 스택은 전역 코드와 함수 호출의 실행 컨텍스트를 쌓아 두고, 가장 최근에 호출된 함수부터 실행을 끝내는 구조입니다.

### 2) 왜 필요한가

함수 안에서 다른 함수를 호출하면 엔진은 현재 함수로 다시 돌아올 위치와 아직 끝나지 않은 실행 상태를 기억해야 합니다.

### 3) 핵심 흐름 재구성

```javascript
function prepare() {
  validate();
}

function validate() {
  console.log("검증");
}

prepare();
```

```text
전역 → prepare 추가 → validate 추가
                    → validate 제거 → prepare 제거 → 전역
```

### 4) 쉬운 예시

서류 위에 새 서류를 계속 올려두고 가장 위의 서류부터 처리해야 아래 업무로 돌아갈 수 있는 상황과 비슷합니다.

### 5) 코드 예시

```javascript
function first() {
  console.log("first:start");
  second();
  console.log("first:end");
}

function second() {
  console.log("second");
}

first();
```

출력 순서는 `first:start`, `second`, `first:end`입니다. `second`가 끝나야 `first`의 남은 줄로 돌아옵니다.

### 6) 헷갈리는 점

콜 스택 아래에 있는 실행 컨텍스트가 곧 상위 스코프라는 뜻은 아닙니다. 호출 관계와 렉시컬 상위 관계는 일치할 수도 있지만 서로 다른 규칙입니다.

### 7) 한 줄 정리

> 콜 스택은 지금 실행할 함수와 실행이 끝난 뒤 돌아갈 순서를 관리합니다.

## 2. 스코프 체인과 클로저

### 1) 정의

스코프 체인은 식별자를 현재 렉시컬 환경부터 바깥 환경으로 찾는 연결입니다. 클로저는 함수가 이 연결을 통해 정의된 바깥 환경의 변수를 계속 사용하는 성질입니다.

### 2) 왜 필요한가

안쪽 함수가 매번 필요한 값을 인자로 모두 받지 않아도 바깥 함수의 설정과 상태를 안전하게 활용할 수 있습니다.

### 3) 핵심 흐름 재구성

```javascript
function createCounter(start) {
  let count = start;

  return function increase() {
    count += 1;
    return count;
  };
}

const next = createCounter(10);
console.log(next()); // 11
console.log(next()); // 12
```

`createCounter` 호출은 끝났지만 반환된 `increase`가 바깥의 `count`를 참조하므로 상태가 유지됩니다.

### 4) 쉬운 예시

가게가 문을 닫아도 단골 카드가 그 가게의 적립 정보를 계속 기억하는 것과 비슷합니다.

### 5) 코드 예시

```javascript
function makeMultiplier(factor) {
  return (value) => value * factor;
}

const double = makeMultiplier(2);
const triple = makeMultiplier(3);

console.log(double(5)); // 10
console.log(triple(5)); // 15
```

각 반환 함수는 서로 다른 호출 환경의 `factor`를 기억합니다.

### 6) 헷갈리는 점

클로저는 특별한 문법이 아닙니다. 함수와 렉시컬 스코프가 결합되어 자연스럽게 생기는 동작입니다.

### 7) 한 줄 정리

> 스코프 체인은 이름을 찾는 길이고, 클로저는 그 길을 통해 바깥 상태를 계속 사용하는 함수의 성질입니다.

## 코드로 보기 — 호출 순서와 변수 검색 분리하기

```javascript
const label = "global";

function run(callback) {
  const label = "run";
  callback();
}

function report() {
  console.log(label);
}

run(report); // global
```

### 코드 목적

`report`가 `run` 안에서 호출되더라도 변수 검색은 정의 위치를 따른다는 점을 확인합니다.

### 코드 흐름

1. 전역 컨텍스트 위에 `run` 컨텍스트가 쌓입니다.
2. `run`이 `report`를 호출해 `report` 컨텍스트가 최상단에 놓입니다.
3. `report`의 렉시컬 상위는 호출자인 `run`이 아니라 정의 위치인 전역입니다.
4. 전역의 `label`을 찾아 출력합니다.

### 실행 결과 해석

콜 스택에는 `run`이 아래에 있지만 결과는 `run`이 아니라 `global`입니다. 호출 순서와 변수 검색 경로가 다르기 때문입니다.

### 실무 연결

콜백, 모듈 함수, 이벤트 핸들러가 어떤 설정값을 읽는지 추적할 때 호출자와 정의 위치를 분리해 보면 버그를 찾기 쉽습니다.

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 콜 스택 vs 스코프 체인 | 콜 스택은 실행 순서, 스코프 체인은 식별자 검색 경로를 관리합니다. |
| 호출 위치 vs 정의 위치 | 호출 위치는 스택을 바꾸고, 정의 위치는 렉시컬 상위 환경을 결정합니다. |
| 지역 변수 vs 클로저 상태 | 보통 지역 변수는 호출 종료 후 접근할 수 없지만 참조 중인 클로저가 있으면 유지될 수 있습니다. |
