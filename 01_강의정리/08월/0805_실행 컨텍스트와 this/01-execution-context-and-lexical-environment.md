# 실행 컨텍스트와 렉시컬 환경

> 코드를 실행한다는 것은 문장을 위에서 아래로 읽는 일만이 아니라, 실행에 필요한 이름과 연결 정보를 먼저 준비하는 일입니다.

`execution context` · `lexical environment` · `environment record` · `code evaluation` · `code execution`

## 핵심요약

- JavaScript 엔진은 스코프의 코드를 실행하기 전에 실행 컨텍스트를 준비합니다.
- 평가 단계에서는 선언을 환경에 등록하고, 실행 단계에서는 표현식을 계산하고 값을 갱신합니다.
- 렉시컬 환경은 현재 스코프의 식별자 기록과 바깥 환경으로 향하는 참조로 구성됩니다.
- 전역·함수·블록은 필요한 시점에 서로 다른 환경을 만들 수 있습니다.
- 실행 컨텍스트를 알면 스코프, 호이스팅, `this`를 하나의 실행 모델로 설명할 수 있습니다.

## 1. 실행 컨텍스트

### 1) 정의

실행 컨텍스트는 JavaScript 엔진이 현재 코드를 평가하고 실행하는 데 필요한 정보를 관리하는 단위입니다. 변수와 함수의 선언, 상위 스코프, `this`, 매개변수 같은 정보가 이 실행 과정에 연결됩니다.

### 2) 왜 필요한가

함수를 여러 번 호출하면 각 호출은 서로 다른 매개변수와 지역 변수를 가져야 합니다. 실행 컨텍스트는 호출마다 독립적인 실행 상태를 만들어 값이 섞이지 않게 합니다.

### 3) 핵심 흐름 재구성

```text
스코프 실행 직전
  → 코드 평가
  → 선언 정보 등록
  → 코드 실행
  → 값 계산과 갱신
  → 실행 종료
```

평가와 실행을 나누어 생각하면 “왜 선언보다 앞에서 이름을 알고 있는가?” 같은 질문에 답할 수 있습니다.

### 4) 쉬운 예시

요리를 시작하기 전에 조리대에 재료 이름과 도구 위치를 먼저 정리하는 상황과 비슷합니다. 준비표가 평가 단계라면 실제로 재료를 썰고 조리하는 과정은 실행 단계입니다.

### 5) 코드 예시

```javascript
const rate = 0.1;

function calculateTotal(price) {
  const fee = price * rate;
  return price + fee;
}

console.log(calculateTotal(20000)); // 22000
```

전역 환경에는 `rate`와 `calculateTotal`이, 함수 호출 환경에는 `price`와 `fee`가 관리됩니다.

### 6) 헷갈리는 점

실행 컨텍스트는 소스 코드에 직접 보이는 객체가 아닙니다. 엔진의 내부 실행 모델이며 개발자는 디버거의 호출 스택과 스코프 정보를 통해 간접적으로 관찰합니다.

### 7) 한 줄 정리

> 실행 컨텍스트는 한 번의 코드 실행에 필요한 상태와 연결 정보를 관리하는 작업 공간입니다.

## 2. 렉시컬 환경

### 1) 정의

렉시컬 환경은 현재 스코프의 식별자를 기록하는 환경 레코드와 상위 렉시컬 환경을 가리키는 참조로 구성됩니다.

```text
렉시컬 환경
├─ Environment Record: 현재 스코프의 이름과 값
└─ Outer Reference: 바깥 렉시컬 환경으로 가는 연결
```

### 2) 왜 필요한가

코드가 어떤 변수를 읽어야 하는지 결정하려면 현재 스코프의 이름 목록과 바깥으로 이어지는 검색 경로가 필요합니다.

### 3) 핵심 흐름 재구성

```javascript
const category = "book";

if (category === "book") {
  const discount = 2000;
  console.log(category, discount);
}
```

블록 환경은 `discount`를 기록하고 바깥 전역 환경을 참조합니다. 그래서 블록 안에서 `category`를 읽을 수 있지만, 블록 밖에서는 `discount`를 읽을 수 없습니다.

### 4) 쉬운 예시

내 서랍에 물건이 없으면 옆 사무실의 공용 수납장을 확인하도록 연결된 안내표가 있는 것과 같습니다.

### 5) 코드 예시

```javascript
const prefix = "ORDER";

function makeId(number) {
  const padded = String(number).padStart(4, "0");
  return `${prefix}-${padded}`;
}

console.log(makeId(27)); // ORDER-0027
```

`makeId` 환경에는 `prefix`가 없으므로 바깥 환경에서 찾습니다.

### 6) 헷갈리는 점

현재 스코프에서 같은 이름을 찾으면 검색을 멈춥니다. 안쪽 변수가 바깥 변수를 가리는 현상을 섀도잉이라고 합니다.

### 7) 한 줄 정리

> 렉시컬 환경은 현재 이름을 기록하고 바깥 이름을 찾을 경로를 연결합니다.

## 코드로 보기 — 호출마다 독립된 환경

```javascript
const serviceFee = 500;

function createReceipt(item, price) {
  const total = price + serviceFee;
  return `${item}: ${total}원`;
}

console.log(createReceipt("노트", 3000));
console.log(createReceipt("펜", 1500));
```

### 코드 목적

같은 함수가 여러 번 호출되어도 매개변수와 지역 변수가 호출별로 독립적으로 관리되는지 확인합니다.

### 코드 흐름

1. 전역 환경에 서비스 수수료와 함수 선언을 준비합니다.
2. 첫 호출 환경에 `item`, `price`, `total`을 기록합니다.
3. 첫 호출이 끝난 뒤 두 번째 호출을 위한 새 환경을 만듭니다.
4. 각 호출은 전역의 `serviceFee`를 같은 검색 경로로 참조합니다.

### 실행 결과 해석

첫 호출은 `노트: 3500원`, 두 번째 호출은 `펜: 2000원`을 출력합니다. 두 호출의 지역값은 서로 섞이지 않습니다.

### 실무 연결

요청마다 다른 입력을 처리하는 API 함수, 사용자별 계산 로직, 이벤트 핸들러의 지역 상태를 추적할 때 같은 모델을 사용할 수 있습니다.

<summary>정답 보기</summary>

1. 평가 단계는 선언 정보를 환경에 등록하고, 실행 단계는 표현식을 계산하며 변수 값을 초기화하거나 갱신합니다.
2. 현재 환경 레코드부터 확인하고 없으면 외부 렉시컬 환경 참조를 따라 바깥쪽으로 이동합니다.
3. 함수 호출마다 별도의 실행 컨텍스트와 함수 렉시컬 환경이 만들어지기 때문입니다.

</details>

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 평가 vs 실행 | 평가는 선언과 환경을 준비하고, 실행은 실제 계산과 값 변경을 수행합니다. |
| 실행 컨텍스트 vs 렉시컬 환경 | 실행 컨텍스트는 전체 실행 단위이고, 렉시컬 환경은 식별자와 상위 환경 연결을 관리하는 핵심 구성입니다. |
| 블록 환경 vs 함수 환경 | 블록은 `let`·`const`의 범위를, 함수 환경은 호출의 매개변수·지역 변수·`this` 등을 관리합니다. |

## 한 줄 정리

> JavaScript는 환경을 먼저 만들고 코드를 실행하며, 렉시컬 환경은 현재 이름과 바깥 이름을 잇는 검색 지도를 제공합니다.
