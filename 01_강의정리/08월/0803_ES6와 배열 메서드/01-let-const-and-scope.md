# `let`·`const`와 스코프

> 변수 선언은 값을 저장하는 문법이 아니라, 값이 어디까지 보이고 얼마나 바뀔 수 있는지를 정하는 설계입니다.

`let` · `const` · `block scope` · `scope chain` · `lexical scope`

## 핵심요약

- `let`은 재할당할 수 있고 `const`는 다른 값으로 재할당할 수 없습니다.
- 두 키워드는 같은 블록 안에서 중복 선언할 수 없습니다.
- `const`로 선언한 객체의 내부 프로퍼티는 변경할 수 있습니다.
- JavaScript는 함수를 정의한 위치를 기준으로 상위 스코프를 결정합니다.
- 식별자는 현재 스코프에서 시작해 바깥쪽으로 탐색합니다.

## 1. `let`과 `const`를 선택하는 기준

### 1) 정의

`let`은 값의 교체가 필요한 변수를, `const`는 변수와 값의 연결을 유지할 이름을 선언합니다. 둘 다 중괄호 `{}`가 만든 블록을 유효 범위로 사용합니다.

### 2) 왜 필요한가

값이 바뀌어야 하는지 코드에 드러내면 의도하지 않은 재할당을 줄일 수 있습니다. 반복문의 카운터처럼 변화가 필요한 값에는 `let`, 설정값이나 배열 참조처럼 연결을 유지할 값에는 `const`가 적합합니다.

### 3) 핵심 흐름 재구성

```javascript
const taxRate = 0.1;
let total = 0;

total = 12000 + 8000;
console.log(total * (1 + taxRate)); // 22000
```

기본적으로 `const`로 시작하고 실제 재할당이 필요할 때만 `let`으로 바꾸면 변경 지점이 분명해집니다.

### 4) 쉬운 예시

사물함 번호는 고정된 연결이므로 `const`, 사물함 안에 적어 두는 오늘의 대여 수량은 계속 바뀌므로 `let`이라고 생각할 수 있습니다.

### 5) 코드 예시

```javascript
const user = { name: "Mina", score: 70 };
user.score = 80; // 객체 내부 변경은 가능

// user = { name: "Jin", score: 90 }; // 재할당은 불가능
```

`const`가 객체를 얼리는 것은 아닙니다. 변수에 다른 객체를 다시 연결하지 못하게 할 뿐입니다.

### 6) 헷갈리는 점

`const`는 “절대 변하지 않는 값”보다 “변수가 가리키는 대상을 다시 바꾸지 않음”에 가깝습니다. 내부 변경까지 막으려면 별도의 불변성 전략이 필요합니다.

### 7) 한 줄 정리

> `const`를 기본값으로 삼고, 변수 자체를 다시 할당해야 할 때만 `let`을 사용합니다.

## 2. 블록 스코프와 스코프 체인

### 1) 정의

스코프는 식별자를 참조할 수 있는 범위입니다. `let`과 `const`는 함수뿐 아니라 `if`, `for` 같은 블록 안에서도 지역 범위를 만듭니다.

### 2) 왜 필요한가

필요한 범위 안에서만 변수를 보이게 하면 이름 충돌과 예기치 않은 변경을 줄일 수 있습니다.

### 3) 핵심 흐름 재구성

```javascript
const label = "global";

function outer() {
  const label = "outer";

  function inner() {
    console.log(label);
  }

  inner();
}

outer(); // outer
```

`inner()`는 현재 범위에 `label`이 없으므로 정의된 바깥 범위인 `outer()`에서 찾습니다. 호출 위치가 아니라 정의 위치가 기준인 규칙을 렉시컬 스코프라고 합니다.

### 4) 쉬운 예시

책상 서랍에서 물건을 찾을 때 내 서랍부터 확인하고, 없으면 같은 방의 수납장, 그다음 공용 창고를 확인하는 과정이 스코프 체인과 비슷합니다.

### 5) 코드 예시

```javascript
if (true) {
  let message = "inside";
  console.log(message);
}

// console.log(message); // ReferenceError
```

### 6) 헷갈리는 점

같은 이름의 변수가 안쪽에 있으면 바깥 변수를 가립니다. 이를 섀도잉이라고 하며, 코드가 길어지면 어느 값을 읽는지 혼동하기 쉽습니다.

### 7) 한 줄 정리

> 식별자는 현재 스코프에서 바깥쪽으로만 탐색하며 안쪽 스코프는 탐색하지 않습니다.

## 코드로 보기 — 블록별 상태 계산

```javascript
const basePrice = 10000;
let finalPrice = basePrice;

if (basePrice >= 10000) {
  const discount = 1000;
  finalPrice -= discount;
}

console.log(finalPrice); // 9000
```

### 코드 목적

변경되는 결과와 블록 안에서만 필요한 임시값을 서로 다른 선언으로 표현합니다.

### 코드 흐름

1. 기준 가격은 `const`로 선언합니다.
2. 변경될 최종 가격은 `let`으로 선언합니다.
3. 할인값은 조건 블록 안에서만 사용합니다.
4. 블록 밖에서 최종 결과를 출력합니다.

### 실행 결과 해석

`finalPrice`는 재할당되어 9000이 되고, `discount`는 조건 블록 밖에서는 접근할 수 없습니다.

### 실무 연결

함수 내부 계산값, 반복문의 인덱스, 조건별 임시 상태를 좁은 스코프에 두면 서비스 코드의 변경 범위를 추적하기 쉬워집니다.

## 직접 해보기

1. 재할당이 없는 배열 변수에는 `let`과 `const` 중 무엇이 더 적절한가요?
2. `if` 블록 안의 `let` 변수를 밖에서 출력하면 어떻게 되나요?
3. 주문 상태가 여러 단계에서 바뀌는 코드라면 어떤 값만 `let`으로 두어야 할까요?

<details>
<summary>정답 보기</summary>

1. 배열 참조를 다시 바꾸지 않는다면 `const`가 적절합니다.
2. 블록 밖에서는 식별자를 찾을 수 없어 `ReferenceError`가 발생합니다.
3. 실제로 단계마다 재할당되는 상태값만 `let`으로 두고 설정·입력 참조는 `const`로 유지합니다.

</details>

## 헷갈리기 쉬운 포인트

| 헷갈리는 개념 | 차이 |
|---|---|
| 재할당 vs 내부 변경 | 변수에 새 값을 연결하는 것과 객체·배열 내부를 바꾸는 것은 다릅니다. |
| 함수 스코프 vs 블록 스코프 | 함수 전체가 범위인지 중괄호 블록 하나가 범위인지 다릅니다. |
| 호출 위치 vs 정의 위치 | JavaScript의 상위 스코프는 함수가 정의된 위치로 결정됩니다. |

**Q1. `const`는 객체 내부까지 변경하지 못하게 하나요?**

<details>
<summary>답</summary>

아닙니다. 변수에 다른 객체를 재할당하지 못하게 하지만 기존 객체의 프로퍼티 변경은 가능합니다.

</details>

**Q2. 안쪽 함수가 같은 이름의 변수를 찾는 순서는 무엇인가요?**

<details>
<summary>답</summary>

현재 함수의 스코프부터 확인하고 없으면 함수가 정의된 바깥쪽 스코프를 차례로 탐색합니다.

</details>

**Q3. 모든 변수를 `let`으로 선언하면 어떤 단점이 있나요?**

<details>
<summary>답</summary>

바뀌지 않아야 할 값도 재할당할 수 있어 변경 의도를 파악하기 어렵고 실수로 값을 교체할 가능성이 커집니다.

</details>
