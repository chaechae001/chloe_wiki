# 가상화와 하이퍼바이저

> 가상화는 한 대의 물리 서버를 여러 독립 환경처럼 나누어 자원 활용률과 배포 속도를 높입니다.

`virtualization` · `hypervisor` · `virtual machine` · `guest OS` · `resource isolation`

## 핵심요약

- 가상화는 물리 자원을 논리 자원으로 추상화합니다.
- VM은 할당된 CPU·메모리·스토리지와 Guest OS를 가진 독립 실행 환경입니다.
- 하이퍼바이저는 VM을 생성하고 자원 접근을 중재합니다.
- Type 1은 하드웨어 위에서, Type 2는 Host OS 위에서 동작합니다.
- 자원 격리와 할당 정책이 잘못되면 한 VM의 부하가 다른 VM에 영향을 줄 수 있습니다.

## 1. 가상화가 필요한 이유

물리 서버마다 하나의 애플리케이션만 배치하면 남는 CPU와 메모리가 많아질 수 있습니다. 가상화는 하나의 큰 자원 풀을 여러 VM에 나누어 배치해 사용률을 높이고, 환경별 OS와 애플리케이션을 분리합니다.

```text
Physical CPU / RAM / Storage
          ↓ abstraction
VM A          VM B          VM C
Guest OS      Guest OS      Guest OS
App           App           App
```

<details>
<summary>답</summary>

VM은 단순한 폴더가 아닙니다. 가상 하드웨어와 운영체제를 포함하고, 하이퍼바이저가 실제 하드웨어 사용을 중재하는 실행 환경입니다.

</details>

## 2. 하이퍼바이저

하이퍼바이저는 여러 VM이 물리 CPU, 메모리, 네트워크, 디스크를 나누어 사용하게 하는 관리 계층입니다. Virtual Machine Monitor 또는 VMM이라고도 합니다.

| 구분 | 구조 | 특징 |
|---|---|---|
| Type 1 | Hardware → Hypervisor → VM | 서버 환경에 적합하고 중간 Host OS가 없습니다. |
| Type 2 | Hardware → Host OS → Hypervisor → VM | 개인 개발·테스트에 편리하지만 Host OS 영향을 받습니다. |

## 3. 전가상화와 반가상화

- **전가상화**는 Guest OS가 실제 하드웨어처럼 보이는 가상 환경에서 실행되도록 하이퍼바이저가 요청을 중재합니다.
- **반가상화**는 Guest OS가 가상화 환경을 인식하고 하이퍼바이저와 협력하도록 구성합니다.

현대 환경에서는 하드웨어 가속과 드라이버 최적화가 결합되므로 이름만 외우기보다 Guest OS가 자원을 요청하고 하이퍼바이저가 이를 물리 자원에 연결한다는 흐름을 이해하는 것이 중요합니다.

## 4. 자원 할당과 격리

VM을 만들 때 vCPU, 메모리, 디스크, 네트워크를 할당합니다. 관리 계층은 자원을 중복 예약하지 않도록 추적하고 VM 종료 시 회수합니다.

```text
요청 → 용량·정책 확인 → VM 생성 → 자원 연결 → 사용 → 회수
```

격리는 보안과 안정성의 기초지만 절대적이지 않습니다. CPU 경합, 스토리지 I/O 병목, 잘못된 네트워크 규칙은 여러 VM에 영향을 줄 수 있으므로 모니터링과 제한 정책이 필요합니다.

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| Host OS vs Guest OS | 물리 장비를 직접 제어하는 OS와 VM 내부의 OS입니다. |
| 물리 서버 vs VM | 실제 장비와 그 장비 자원을 논리적으로 분리한 환경입니다. |
| 격리 vs 무영향 | 경계를 나누는 것과 공유 자원 경합이 전혀 없는 것은 다릅니다. |

### 복습 질문 및 답변

**Q1. 하이퍼바이저가 하는 핵심 일은 무엇인가요?**

<details>
<summary>답</summary>

VM을 생성·실행하고 각 VM의 자원 요청을 물리 하드웨어에 연결하며 격리와 할당을 관리합니다.

</details>

**Q2. VM마다 운영체제가 필요한가요?**

<details>
<summary>답</summary>

일반적인 VM은 각자 Guest OS를 가집니다. 이 점이 Host OS 커널을 공유하는 컨테이너와 다른 핵심입니다.

</details>

**Q3. 자원을 많이 나누기만 하면 효율적인가요?**

<details>
<summary>답</summary>

과도하게 나누면 CPU·메모리·I/O 경합과 성능 변동이 커집니다. 실제 사용량과 서비스 중요도에 맞춰 할당해야 합니다.

</details>

## 한 줄 정리

> 가상화는 하이퍼바이저를 통해 물리 자원을 여러 독립 VM에 안전하고 유연하게 배분하는 기술입니다.
