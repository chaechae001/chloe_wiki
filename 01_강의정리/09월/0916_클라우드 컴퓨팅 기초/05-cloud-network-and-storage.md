# 클라우드 네트워크와 스토리지

> 컴퓨팅 자원만 만들어서는 서비스가 되지 않습니다. 요청이 오갈 경로와 데이터가 머물 방식을 함께 설계해야 합니다.

`virtual network` · `subnet` · `routing` · `object storage` · `block storage`

## 핵심요약

- 가상 네트워크는 클라우드 자원의 주소와 통신 경계를 논리적으로 분리합니다.
- 라우팅과 접근 규칙은 어떤 트래픽이 어디로 이동할지 결정합니다.
- 오브젝트·블록·파일 스토리지는 데이터 접근 방식과 용도가 다릅니다.
- 저장 방식은 데이터 형태보다 애플리케이션의 접근 패턴으로 선택합니다.
- 네트워크와 스토리지는 성능·보안·비용을 동시에 좌우합니다.

## 1. 가상 네트워크

가상 네트워크는 물리 케이블을 직접 바꾸지 않고 주소 공간, 서브넷, 라우팅, 접근 규칙을 소프트웨어로 정의합니다. 서로 다른 서비스 계층을 분리하고 필요한 통신만 허용하는 것이 목적입니다.

```text
Internet
   ↓
Public subnet: gateway / web
   ↓ allowed traffic only
Private subnet: API / database
```

서브넷을 나누는 것만으로 보안이 완성되지는 않습니다. 라우팅과 방화벽 규칙, 계정 권한, 애플리케이션 인증을 함께 설정해야 합니다.

## 2. 주소·라우팅·접근 제어

- **IP 주소**는 자원을 식별합니다.
- **서브넷**은 주소 공간과 관리 경계를 나눕니다.
- **라우터**는 목적지에 따라 패킷의 다음 경로를 정합니다.
- **접근 규칙**은 허용할 출발지, 목적지, 포트를 제한합니다.

외부 사용자가 접근해야 하는 웹 계층과 외부 노출이 필요 없는 데이터베이스를 같은 방식으로 배치하면 공격 표면이 커집니다. 최소 공개 원칙을 적용해 필요한 진입점만 엽니다.

## 3. 세 가지 저장 방식

| 방식 | 접근 단위 | 대표 용도 | 특징 |
|---|---|---|---|
| Object | 객체와 메타데이터 | 이미지, 영상, 백업, 모델 파일 | 대규모 확장과 HTTP API에 적합 |
| Block | 고정 크기 블록 | VM 디스크, 데이터베이스 볼륨 | 낮은 지연과 파일시스템 구성에 적합 |
| File | 파일·디렉터리 | 공유 폴더, 공동 작업 파일 | 계층 구조와 여러 클라이언트 공유 |

“정형 데이터면 블록, 비정형이면 오브젝트”처럼 단순 분류하기보다 읽기·쓰기 방식, 공유 범위, 지연 시간, 일관성 요구를 함께 봅니다.

## 4. AI 서비스 예시

- 학습 데이터와 모델 아티팩트는 오브젝트 스토리지에 둡니다.
- 추론 서버의 운영체제와 임시 작업 공간은 블록 스토리지를 사용합니다.
- 여러 작업자가 같은 POSIX 경로를 써야 하면 파일 스토리지를 검토합니다.
- 외부 API는 공개 진입점을 사용하지만 모델 서버와 데이터 계층은 사설 네트워크에 둡니다.

## 5. 성능과 비용

스토리지는 용량뿐 아니라 요청 횟수, 처리량, 지연 시간, 데이터 전송으로 과금될 수 있습니다. 네트워크도 외부 전송과 리전 간 전송이 비용에 영향을 줍니다.

따라서 데이터와 컴퓨팅을 가깝게 배치하고, 자주 쓰지 않는 데이터에는 보관 계층과 수명 주기 정책을 적용합니다.

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| Object vs File | API로 객체를 다루는 방식과 디렉터리 경로로 파일을 공유하는 방식입니다. |
| Block vs File | 원시 디스크 블록과 파일시스템이 제공하는 파일 인터페이스입니다. |
| Public IP vs 공개 서비스 | 주소 보유와 실제 접근 규칙·애플리케이션 공개 여부는 다릅니다. |

</details>
