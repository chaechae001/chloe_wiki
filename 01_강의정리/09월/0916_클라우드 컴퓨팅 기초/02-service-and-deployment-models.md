# 서비스 모델과 배포 모델

> SaaS·PaaS·IaaS는 “누가 어디까지 관리하는가”, Public·Private·Hybrid는 “어디에 어떻게 배치하는가”를 설명합니다.

`SaaS` · `PaaS` · `IaaS` · `public cloud` · `hybrid cloud`

## 핵심요약

- SaaS, PaaS, IaaS는 서비스 제공자와 사용자의 관리 책임 경계를 나눕니다.
- 아래 계층을 더 많이 맡길수록 운영 부담은 줄지만 제어 범위도 줄어듭니다.
- Public, Private, Hybrid는 자원의 소유·접근·연결 방식을 구분합니다.
- Multi Cloud는 여러 제공자를 함께 쓰는 전략이며 Hybrid Cloud와 기준이 다릅니다.
- 모델 선택은 기술 유행보다 보안, 통제, 속도, 인력 조건으로 결정합니다.

## 1. SaaS·PaaS·IaaS

| 모델 | 제공자가 주로 관리 | 사용자가 집중하는 것 | 대표 상황 |
|---|---|---|---|
| SaaS | 애플리케이션부터 인프라까지 | 계정, 데이터, 사용 설정 | 협업 도구 사용 |
| PaaS | 실행 환경, 미들웨어, 인프라 | 애플리케이션과 데이터 | 웹 API 배포 |
| IaaS | 서버, 네트워크, 가상화 | OS부터 애플리케이션까지 | 세밀한 서버 구성 |

아래로 갈수록 사용자가 관리할 영역이 넓어지고 자유도도 커집니다. 위로 갈수록 빠르게 사용할 수 있지만 플랫폼이 허용하는 범위 안에서 설계해야 합니다.

<details>
<summary>답</summary>

PaaS가 IaaS보다 항상 우수한 것은 아닙니다. 운영 인력이 적고 빠른 배포가 중요하면 PaaS가 유리하고, OS 수준 제어와 특수 구성이 필요하면 IaaS가 적합할 수 있습니다.

</details>

## 2. 공동 책임의 관점

관리 책임을 제공자에게 맡겨도 사용자의 책임이 사라지지는 않습니다. SaaS에서도 계정 권한과 입력 데이터는 사용자가 관리하고, IaaS에서는 운영체제 패치와 방화벽 설정까지 더 많은 책임을 집니다.

```text
관리 편의성  SaaS ← PaaS ← IaaS  세밀한 제어
사용자 책임  적음  →      →       많음
```

## 3. Public·Private·Hybrid Cloud

| 배포 모델 | 핵심 특징 | 적합한 상황 | 주의점 |
|---|---|---|---|
| Public | 외부 제공자의 공유 기반 사용 | 빠른 시작과 탄력 확장 | 권한·비용·규제 검토 |
| Private | 조직 전용 환경 | 강한 통제와 맞춤 구성 | 구축·운영 부담 |
| Hybrid | Public과 Private 연결 | 민감 데이터와 탄력 자원 분리 | 연결·정책 복잡도 |

Hybrid Cloud는 두 환경을 단순히 보유하는 데서 끝나지 않습니다. 데이터와 요청이 어느 환경을 오갈지, 인증과 모니터링을 어떻게 통합할지 설계해야 합니다.

## 4. Multi Cloud

Multi Cloud는 둘 이상의 클라우드 제공자를 함께 사용하는 전략입니다. 특정 서비스의 장점을 조합하거나 공급자 집중 위험을 줄일 수 있지만, 서로 다른 권한·네트워크·모니터링 체계를 관리해야 합니다.

Hybrid는 **배포 환경의 결합**, Multi Cloud는 **제공자 수와 분산 전략**에 초점이 있습니다. 한 시스템이 두 특성을 동시에 가질 수도 있습니다.

## 5. 선택 질문

1. 운영체제 수준의 제어가 필요한가?
2. 팀이 인프라 패치와 장애 대응을 맡을 수 있는가?
3. 민감 데이터가 특정 환경에 머물러야 하는가?
4. 서비스 출시 속도와 이식성 중 무엇이 더 중요한가?
5. 여러 제공자를 쓸 때 복잡도를 감당할 수 있는가?

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| PaaS vs IaaS | 실행 플랫폼까지 위임하는지, 인프라만 빌리는지의 차이입니다. |
| Hybrid vs Multi Cloud | 환경 종류의 결합과 여러 제공자 사용 전략의 차이입니다. |
| 책임 이전 vs 책임 공유 | 일부 운영을 맡겨도 계정·데이터·설정 책임은 남습니다. |

### 복습 질문 및 답변

**Q1. SaaS를 쓰면 보안을 모두 제공자가 책임지나요?**

<details>
<summary>답</summary>

아닙니다. 서비스 자체 보안은 제공자가 많이 담당하지만 계정, 권한, 공유 범위, 입력 데이터는 사용자가 관리해야 합니다.

</details>

**Q2. PaaS의 핵심 장점은 무엇인가요?**

<details>
<summary>답</summary>

운영체제와 실행 환경 관리 부담을 줄여 애플리케이션 개발과 배포에 집중할 수 있다는 점입니다.

</details>

**Q3. 여러 클라우드를 쓰면 자동으로 장애에 강해지나요?**

<details>
<summary>답</summary>

아닙니다. 데이터 복제, 트래픽 전환, 일관된 배포와 검증 절차를 실제로 설계해야 장애 대응 효과가 생깁니다.

</details>

## 한 줄 정리

> 서비스 모델은 관리 책임을, 배포 모델은 자원을 놓고 연결하는 방식을 결정합니다.
