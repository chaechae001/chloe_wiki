# 프로비저닝·보안·비용 운영

> 콘솔에서 VM 하나를 만드는 과정에도 권한, 이미지, 사양, 네트워크, 스토리지, 모니터링이라는 운영 결정이 들어 있습니다.

`provisioning` · `configuration` · `IAM` · `monitoring` · `cost governance`

## 핵심요약

- 프로비저닝은 자원을 생성해 실제 사용 가능한 상태로 준비하는 과정입니다.
- 이미지·사양·네트워크·스토리지·권한을 일관되게 설정해야 합니다.
- 콘솔의 수동 작업은 학습에 유용하지만 반복 운영에는 자동화가 필요합니다.
- 보안은 계정, 네트워크, 이미지, 데이터, 로그 전 계층에 적용합니다.
- 비용은 생성 시점보다 사용·변경·폐기 전 과정에서 관리합니다.

## 1. VM 프로비저닝 흐름

1. 프로젝트와 리전을 선택합니다.
2. 운영체제 이미지를 선택합니다.
3. CPU·메모리·GPU 등 인스턴스 사양을 정합니다.
4. 네트워크와 접근 규칙을 연결합니다.
5. 루트 디스크와 추가 스토리지를 구성합니다.
6. 키 또는 역할 기반 접근을 설정합니다.
7. 생성 후 상태·로그·비용 태그를 확인합니다.

<details>
<summary>답</summary>

“인스턴스 생성 완료”는 서비스 준비 완료와 같지 않습니다. 패치, 애플리케이션 배포, 상태 확인, 백업, 모니터링까지 준비되어야 운영 가능한 상태입니다.

</details>

## 2. 선언적 자동화

콘솔 작업을 반복하면 설정 누락과 환경 차이가 생깁니다. 운영에서는 원하는 상태를 코드나 템플릿으로 선언하고 검토·재현하는 방식을 사용합니다.

```yaml
server:
  image: hardened-linux
  size: small
  network: private-app
  tags:
    owner: api-team
    environment: staging
```

이 예시는 특정 공급자 문법이 아니라 “무엇을 만들지”를 기록하는 원리를 보여줍니다. 실제 비밀 값은 템플릿에 직접 넣지 않습니다.

## 3. 보안 체크포인트

| 계층 | 점검 질문 |
|---|---|
| Identity | 장기 관리자 키 대신 역할과 최소 권한을 쓰는가? |
| Network | 필요한 출발지와 포트만 허용하는가? |
| Image | 최신 패치와 신뢰할 수 있는 출처인가? |
| Data | 저장·전송 암호화와 백업 정책이 있는가? |
| Logging | 변경과 접근 기록을 추적할 수 있는가? |

클라우드 제공자의 데이터 센터 보안 기능이 강해도 사용자의 공개 설정이나 과도한 권한까지 자동으로 막아 주지는 않습니다.

## 4. 모니터링과 장애 대응

최소한 CPU, 메모리, 디스크, 네트워크, 애플리케이션 오류율과 응답 시간을 관찰합니다. 경보는 단순 임계치뿐 아니라 실제 사용자 영향과 연결해야 합니다.

```text
Metric / Log / Trace
        ↓
Detect → Alert → Diagnose → Recover → Review
```

## 5. 비용 거버넌스

- 자원마다 소유자·프로젝트·환경 태그를 붙입니다.
- 개발 환경은 사용 시간 외에 자동 중지합니다.
- 사용률과 사양을 비교해 과대 할당을 줄입니다.
- 오래된 스냅샷과 미연결 디스크를 정리합니다.
- 예산과 이상 비용 경보를 설정합니다.
- 데이터 전송과 로그 보관 비용도 함께 확인합니다.

오래된 시장 점유율이나 장비 가격표는 현재 의사결정의 직접 근거로 쓰기 어렵습니다. 숫자의 절대값보다 클라우드가 초기 구매를 사용량 기반 지출로 바꾸고, 그만큼 지속적인 비용 통제가 필요하다는 구조를 이해해야 합니다.

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| Provisioning vs Configuration | 자원을 준비하는 과정과 내부 소프트웨어 상태를 설정하는 과정입니다. |
| 가용성 vs 백업 | 서비스를 계속 제공하는 능력과 데이터를 복구할 사본을 보존하는 일입니다. |
| 사용량 기반 vs 자동 절감 | 쓴 만큼 내는 과금과 낭비가 자동으로 사라지는 것은 다릅니다. |

### 복습 질문 및 답변

**Q1. 콘솔로 만든 자원도 기록이 필요하나요?**

<details>
<summary>답</summary>

필요합니다. 소유자·목적·설정 근거가 없으면 재현과 변경 검토, 비용 추적이 어려워집니다.

</details>

**Q2. 백업이 있으면 고가용성이 보장되나요?**

<details>
<summary>답</summary>

아닙니다. 백업은 복구 수단이고, 고가용성은 중복 구성과 자동 전환 등으로 중단 시간을 줄이는 설계입니다.

</details>

**Q3. 비용 경보만 있으면 비용 최적화가 끝나나요?**

<details>
<summary>답</summary>

경보는 이상을 알릴 뿐입니다. 소유자 확인, 원인 분석, 사양 조정, 종료·보존 정책을 실행해야 실제 최적화가 됩니다.

</details>

## 한 줄 정리

> 클라우드 운영은 자원을 빠르게 만드는 능력보다 안전하게 반복하고 관찰하며 제때 회수하는 능력에서 완성됩니다.
