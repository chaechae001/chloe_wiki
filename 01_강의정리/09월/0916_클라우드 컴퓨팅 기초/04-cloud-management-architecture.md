# 클라우드 관리 아키텍처

> 클라우드의 편리함은 서버 자체보다 요청을 정책에 따라 검증하고 자원을 조립하는 관리 계층에서 나옵니다.

`cloud manager` · `control plane` · `image` · `IAM` · `resource lifecycle`

## 핵심요약

- Cloud Manager는 자원 조회, 할당, VM 생성, 회수를 조정합니다.
- 컴퓨팅·이미지·네트워크·사용자·데이터 관리가 함께 동작합니다.
- 이미지는 반복 가능한 VM 생성을 위한 운영체제와 초기 상태의 템플릿입니다.
- 사용자 권한은 가능한 최소 범위로 분리합니다.
- 자원의 생성부터 폐기까지 상태와 소유자를 추적해야 합니다.

## 1. 관리 계층의 역할

사용자가 VM을 요청하면 관리 계층은 단순히 전원을 켜지 않습니다. 요청자의 권한, 남은 용량, 이미지, 네트워크, 저장소 정책을 확인한 뒤 여러 시스템에 작업을 분배합니다.

```text
User / API
    ↓ request
Cloud Manager
    ├─ Compute scheduler
    ├─ Image catalog
    ├─ Network manager
    ├─ Identity & access
    └─ Storage manager
```

## 2. 리소스 관리

리소스 관리자는 CPU, 메모리, GPU, 스토리지, 네트워크의 총량과 사용량을 추적합니다. VM 생성 시 적합한 물리 서버를 선택하고, 종료 시 자원을 회수합니다.

좋은 스케줄링은 단순히 빈 공간을 찾는 일을 넘어 다음을 고려합니다.

- 필요한 GPU나 CPU 종류
- 장애 영역과 가용성 조건
- 데이터와 가까운 위치
- 사용자별 할당량
- 특정 서버로 부하가 몰리지 않는 배치

## 3. 이미지 관리

이미지는 운영체제와 기본 설정을 담은 재사용 가능한 템플릿입니다. 매번 OS를 처음부터 설치하는 대신 검증된 이미지로 같은 환경을 빠르게 만듭니다.

| 항목 | 역할 | 관리 포인트 |
|---|---|---|
| Base image | 표준 OS 제공 | 보안 패치와 출처 |
| Custom image | 조직 설정 포함 | 버전과 변경 이력 |
| Snapshot | 특정 시점 상태 보존 | 일관성과 보관 기간 |

오래된 이미지로 새 VM을 만들면 이미 알려진 취약점이 반복 배포될 수 있으므로 버전과 폐기 정책이 필요합니다.

## 4. 사용자와 권한 관리

권한 관리는 “누가 어떤 자원에 어떤 행동을 할 수 있는가”를 결정합니다. 관리자와 일반 사용자의 범위를 분리하고, 역할 기반 권한과 감사 로그를 사용합니다.

```text
Identity → Role → Permission → Resource action → Audit log
```

## 5. 자원 생명주기

1. 요청과 승인
2. 생성과 초기화
3. 사용량·상태 모니터링
4. 크기 변경과 패치
5. 백업·스냅샷
6. 종료와 자원 회수

생성 자동화만 있고 폐기 자동화가 없으면 유휴 자원과 오래된 이미지가 쌓입니다. 모든 자원에는 소유자, 목적, 환경, 만료 예정일 같은 태그를 붙이는 것이 좋습니다.

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| Image vs Snapshot | 반복 배포용 템플릿과 특정 자원의 시점 상태입니다. |
| 인증 vs 권한 | 사용자가 누구인지 확인하는 일과 허용 행동을 결정하는 일입니다. |
| 생성 vs 프로비저닝 | 객체를 만드는 일과 사용 가능한 전체 환경을 준비하는 과정입니다. |
