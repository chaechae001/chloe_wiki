# Route 53과 DNS 라우팅

> DNS는 사람이 읽는 이름을 주소로 바꾸는 기능을 넘어, 캐시와 정책으로 사용자를 적절한 서비스 끝점에 연결합니다.

`Route 53` · `DNS` · `hosted zone` · `record` · `TTL`

## 핵심요약

- DNS는 계층형 이름 체계를 따라 도메인을 주소나 다른 이름으로 해석합니다.
- Route 53은 도메인 등록, 호스팅 영역, 레코드와 상태 확인을 제공합니다.
- 퍼블릭 호스팅 영역과 프라이빗 호스팅 영역은 조회 범위가 다릅니다.
- 레코드 유형은 반환하려는 값의 의미에 맞게 선택합니다.
- TTL과 라우팅 정책은 변경 전파 속도와 조회 부하를 함께 결정합니다.

## 1. DNS 조회 흐름

브라우저가 이름을 조회하면 로컬 캐시와 재귀 해석기를 확인하고, 필요하면 루트·최상위 도메인·권한 있는 네임서버의 위임 정보를 따라 최종 레코드를 얻습니다.

<details>
<summary>답</summary>

DNS가 웹 요청 내용을 처리하는 것은 아닙니다. 요청을 보낼 대상 주소나 이름을 찾은 뒤 실제 HTTP 연결은 별도로 이루어집니다.

</details>

## 2. 호스팅 영역과 레코드

- 퍼블릭 호스팅 영역은 인터넷에서 조회할 이름을 관리합니다.
- 프라이빗 호스팅 영역은 연결된 VPC 내부에서만 조회할 이름을 관리합니다.
- 레코드는 이름, 유형, 값, TTL과 라우팅 정책을 정의합니다.

## 3. 주요 레코드

| 유형 | 의미 | 사용 예 |
|---|---|---|
| A | 이름을 IPv4 주소로 연결 | 서버 주소 |
| AAAA | 이름을 IPv6 주소로 연결 | IPv6 서비스 |
| CNAME | 이름을 다른 이름으로 연결 | 별칭 서브도메인 |
| Alias | AWS 리소스에 대한 Route 53 별칭 | 로드 밸런서·CDN |

## 4. TTL

TTL이 길면 재조회가 줄지만 변경된 주소가 늦게 반영될 수 있습니다. 마이그레이션 전에는 TTL을 미리 낮추고, 안정화 후 다시 늘리는 식으로 계획합니다.

## 5. 라우팅 정책

단순, 가중치, 지연 시간, 지리 위치와 장애 조치 정책을 서비스 목표에 맞게 선택합니다. 정책은 애플리케이션의 실제 가용성을 대신하지 않으므로 상태 확인과 대상 서비스의 복구 구조가 함께 필요합니다.

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| 호스팅 영역 vs 도메인 등록 | DNS 레코드 관리 범위와 이름 소유권 등록입니다. |
| A vs CNAME | 주소를 반환하는 레코드와 다른 이름을 가리키는 레코드입니다. |
| DNS 라우팅 vs 네트워크 라우팅 | 이름 조회 결과 선택과 패킷 전달 경로 선택입니다. |

### 복습 질문 및 답변

**Q1. DNS 레코드를 바꾸면 모든 사용자가 즉시 새 주소를 보나요?**

<details>
<summary>답</summary>

</details>

**Q2. 프라이빗 호스팅 영역은 인터넷에서 조회할 수 있나요?**

</details>

**Q3. 장애 조치 DNS만 있으면 무중단이 보장되나요?**

<details>
<summary>답</summary>

</details>
