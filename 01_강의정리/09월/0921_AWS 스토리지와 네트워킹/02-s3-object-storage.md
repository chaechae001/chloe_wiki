# S3 오브젝트 스토리지

> S3는 서버에 연결하는 디스크가 아니라, 버킷 안의 객체를 API로 저장하고 조회하는 확장형 데이터 저장소입니다.

`S3` · `object` · `bucket` · `storage class` · `lifecycle`

## 핵심요약

- S3는 객체와 메타데이터를 키로 식별하는 오브젝트 스토리지입니다.
- 버킷은 Region에 속하고 객체는 버킷 안의 고유한 키로 접근합니다.
- 저장 등급은 접근 빈도, 복구 시간과 최소 보관 비용을 함께 봅니다.
- 버전 관리·수명주기·복제를 사용해 데이터 보호와 비용을 조절합니다.
- 공개 접근 대신 최소 권한과 암호화, 접근 로그를 기본으로 설계합니다.

## 1. 객체와 버킷

객체는 데이터 본문, 키와 메타데이터로 구성됩니다. 디렉터리처럼 보이는 경로는 실제 파일 시스템 폴더가 아니라 키 이름의 접두사입니다.

<details>
<summary>답</summary>

S3는 운영체제가 디스크처럼 마운트해 블록을 수정하는 저장소가 아닙니다. HTTP 기반 API로 객체 전체를 저장하고 가져오는 방식이 중심입니다.

</details>

## 2. 블록·파일·객체 비교

| 유형 | 접근 단위 | 잘 맞는 상황 |
|---|---|---|
| 블록 | 디스크 블록 | 데이터베이스 볼륨, 부팅 디스크 |
| 파일 | 경로와 파일 | 여러 서버의 공유 디렉터리 |
| 객체 | 키와 API | 이미지, 백업, 로그, 데이터 레이크 |

## 3. 저장 등급

자주 읽는 데이터는 즉시 접근 가능한 등급이 자연스럽고, 드문 접근이나 아카이브는 저장 비용을 낮출 수 있습니다. 대신 검색 비용, 최소 보관 기간과 복원 시간을 함께 고려해야 합니다.

## 4. 데이터 보호

- 버전 관리로 덮어쓰기와 삭제 전 버전을 보존합니다.
- 수명주기로 오래된 객체를 저비용 등급으로 이동하거나 만료합니다.
- 복제로 다른 위치에 사본을 둘 수 있습니다.
- 기본 암호화와 전송 암호화를 적용합니다.
- 버킷 정책과 역할로 필요한 주체만 허용합니다.

## 5. 웹 콘텐츠와 데이터 레이크

정적 자산은 S3에 저장하고 CDN을 앞에 두어 빠르게 전달할 수 있습니다. 분석 환경에서는 원본·정제·결과 데이터를 접두사와 메타데이터로 구분해 데이터 레이크의 저장 계층으로 사용할 수 있습니다.

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| 객체 키 vs 파일 경로 | API 식별자와 파일 시스템의 계층 경로입니다. |
| 내구성 vs 가용성 | 데이터를 잃지 않을 가능성과 요청에 응답할 가능성입니다. |
| 버전 관리 vs 백업 | 같은 버킷의 과거 객체와 독립 복구 사본·절차입니다. |

### 복습 질문 및 답변

**Q1. S3 객체의 일부 블록만 디스크처럼 수정할 수 있나요?**

<details>
<summary>답</summary>

일반적인 사용 모델은 객체 단위 저장과 조회입니다. 잦은 부분 수정이 필요하면 다른 저장 구조가 더 적합한지 검토합니다.

</details>

**Q2. 가장 저렴한 저장 등급이 항상 최선인가요?**

<details>
<summary>답</summary>

아닙니다. 복원 지연, 요청·검색 비용과 최소 보관 기간 때문에 전체 비용과 서비스 요구가 오히려 나빠질 수 있습니다.

</details>

**Q3. S3 정적 웹 자산을 직접 공개해야 하나요?**

<details>
<summary>답</summary>

버킷은 비공개로 유지하고 CDN이 제한된 권한으로 원본에 접근하게 구성하면 노출 범위를 줄일 수 있습니다.

</details>

## 한 줄 정리

> S3는 객체를 API로 저장하며 접근 패턴에 맞는 저장 등급과 수명주기, 최소 권한을 함께 설계합니다.
