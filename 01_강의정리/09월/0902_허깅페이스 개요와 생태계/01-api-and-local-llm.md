# LLM API와 로컬 추론 선택

LLM을 서비스에 붙이는 방법은 외부 API 호출과 직접 모델을 실행하는 방식으로 나뉩니다. 정답은 하나가 아니라 데이터 민감도, 비용, 지연 시간과 운영 역량에 따라 달라집니다.

**핵심 키워드:** LLM API, local inference, latency, privacy, total cost

## 핵심 내용

- API는 빠르게 시작할 수 있지만 요청 데이터가 외부 경계를 통과하고 사용량 비용이 발생합니다.
- 로컬 추론은 데이터와 실행 환경을 통제하기 쉽지만 GPU·메모리와 운영 인력이 필요합니다.
- “오픈 모델을 쓴다”와 “안전하다”는 같은 말이 아닙니다. 배포 설정과 접근 통제가 별도로 필요합니다.
- 실제 선택 전 작은 대표 데이터로 품질, 속도와 비용을 함께 측정합니다.

## 처리 흐름

```python
def choose_runtime(is_sensitive, requests_per_day, ops_ready):
    if is_sensitive and ops_ready:
        return "self-hosted candidate"
    if requests_per_day < 1_000:
        return "managed API candidate"
    return "benchmark both options"
```

이 코드는 자동 결론이 아니라 검토 순서를 보여주는 예시입니다. 규제, 모델 라이선스, 장애 대응과 품질 기준을 추가해야 합니다.

## 헷갈리기 쉬운 포인트

| 비교 | 핵심 차이 |
|---|---|
| API vs 로컬 추론 | 공급자가 운영하는 엔드포인트 사용 vs 조직이 실행 환경을 관리 |
| 오픈 가중치 vs 오픈소스 | 가중치 공개 여부 vs 코드·데이터·라이선스를 포함한 더 넓은 공개 범위 |
| 단가 vs 총비용 | 요청당 가격 vs 장비·인력·전력·장애 대응을 포함한 비용 |
