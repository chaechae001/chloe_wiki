# 오픈 LLM과 자원 계획

오픈 모델은 선택권을 넓혀 주지만, 모델 파일을 받는 것과 안정적으로 추론하는 것은 다른 문제입니다. 파라미터 수만 보지 말고 정밀도, 컨텍스트 길이와 동시 요청을 함께 계산해야 합니다.

**핵심 키워드:** parameter, VRAM, quantization, context length, license

## 필요한 자원

가중치 메모리의 거친 하한은 `파라미터 수 × 파라미터당 바이트`입니다. 예를 들어 7B 모델을 16비트로 저장하면 가중치만 약 14GB가 필요합니다. 실제 추론에는 KV cache, 런타임 버퍼와 프레임워크 오버헤드가 더해집니다.

```python
def weight_gib(parameters_billion, bits):
    bytes_required = parameters_billion * 1_000_000_000 * bits / 8
    return bytes_required / (1024 ** 3)

print(round(weight_gib(7, 16), 1))
```

예상 출력은 약 `13.0`GiB입니다. 이 값만으로 GPU를 고르면 실행 중 메모리 부족이 생길 수 있습니다.

## 모델 후보 검토

1. 해결할 작업과 언어를 정의합니다.
2. 라이선스의 사용·배포 제한을 확인합니다.
3. 모델 카드에서 학습 범위, 한계와 평가 조건을 읽습니다.
4. 실행 가능한 크기와 정밀도를 고릅니다.
5. 자체 데이터로 품질과 안전성을 측정합니다.

## 헷갈리기 쉬운 포인트

| 비교 | 핵심 차이 |
|---|---|
| 파라미터 수 vs 파일 크기 | 모델 규모 단위 vs 저장 정밀도·형식이 반영된 실제 용량 |
| 양자화 vs 압축 파일 | 계산 정밀도 축소 vs 전송을 위한 파일 크기 축소 |
| 컨텍스트 길이 vs 출력 길이 | 입력과 누적 문맥 범위 vs 새로 생성하는 토큰 범위 |
