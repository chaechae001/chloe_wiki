# 모델 카드와 평가 지표 해석

모델 카드는 모델의 사용 설명서이자 선택 근거입니다. 높은 점수 하나보다 어떤 데이터·조건·과업에서 측정했으며 어디에 쓰면 안 되는지를 함께 읽어야 합니다.

**핵심 키워드:** Model Card, metadata, benchmark, metric, limitation

## 모델 카드 읽기

1. 모델 목적과 지원 과업·언어를 확인합니다.
2. 학습 데이터와 기반 모델의 출처를 확인합니다.
3. 라이선스와 허용·제한 용도를 읽습니다.
4. 평가 데이터, 프롬프트 방식과 지표를 확인합니다.
5. 편향, 위험과 알려진 한계를 자체 사용 사례에 연결합니다.

YAML front matter에는 언어, 라이선스, 라이브러리와 과업 같은 검색 가능한 메타데이터가 들어갑니다. 본문은 수치만으로 표현하기 어려운 의도, 제한과 평가 맥락을 설명합니다.

```yaml
---
language: en
license: apache-2.0
pipeline_tag: text-classification
library_name: transformers
---
```

## 성능표 해석

Accuracy는 전체 정답 비율이지만 불균형 데이터에서는 오해를 줄 수 있습니다. Precision은 양성 예측의 신뢰도, Recall은 실제 양성을 찾은 비율, F1은 둘의 조화 평균입니다. 생성 모델 벤치마크도 과업, 샷 수, 프롬프트와 평가 코드가 같을 때만 직접 비교하기 쉽습니다.

## 헷갈리기 쉬운 포인트

| 비교 | 핵심 차이 |
|---|---|
| metadata vs 본문 | 필터 가능한 구조화 정보 vs 사용 맥락의 서술 |
| benchmark vs 실제 품질 | 표준 과제 결과 vs 내 데이터·사용자 환경의 결과 |
| 높은 평균 vs 안전한 배포 | 전체 성능 수치 vs 하위 집단·실패 비용까지 고려한 판단 |

## 직접 해보기

1. 모델 카드의 필수 섹션을 설계하세요.
2. 양성 사례가 1%인 탐지 문제의 지표를 고르세요.
3. 두 모델의 점수를 비교하기 전 확인할 조건을 적으세요.

<details>
<summary>정답 보기</summary>

1. 목적, 사용법, 데이터, 평가, 제한, 라이선스와 위험을 포함합니다.
2. Accuracy만 보지 말고 Precision, Recall, F1과 임계값별 비용을 봅니다.
3. 데이터셋 버전, 과업, 프롬프트, 샷 수, 평가 코드와 하드웨어 조건을 확인합니다.

</details>
