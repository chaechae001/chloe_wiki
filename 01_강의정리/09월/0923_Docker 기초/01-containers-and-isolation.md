# 컨테이너와 실행 환경 격리

> 같은 애플리케이션을 어디서 실행해도 같은 방식으로 움직이게 만드는 출발점은 실행 환경을 함께 다루는 데 있다.

`컨테이너` · `가상머신` · `namespace` · `cgroup` · `커널 공유`

## 핵심요약

- 컨테이너는 애플리케이션과 필요한 실행 환경을 격리된 단위로 묶는다.
- 가상머신은 각 인스턴스가 운영체제를 포함하지만, 컨테이너는 호스트 커널을 공유한다.
- namespace는 서로 보이는 자원을 분리하고, cgroup은 자원 사용량을 제한한다.

## 1. 환경 차이가 만드는 문제

### 정의와 필요성

개발 환경에서는 동작하지만 배포 환경에서 실패하는 일은 운영체제, 런타임, 라이브러리 버전, 설정의 차이에서 시작한다. 컨테이너는 앱을 실행하는 데 필요한 파일과 설정을 함께 포장해 이 차이를 줄인다.

### VM과 컨테이너

| 구분 | 가상머신 | 컨테이너 |
| --- | --- | --- |
| 격리 단위 | 하드웨어를 가상화한 컴퓨터 | 운영체제 위의 프로세스 환경 |
| 운영체제 | 인스턴스마다 별도 OS | 호스트 커널 공유 |
| 시작·용량 | 비교적 무겁고 느림 | 비교적 가볍고 빠름 |
| 적합한 상황 | 서로 다른 OS가 필요한 강한 격리 | 같은 계열 환경에서 빠른 배포 |

컨테이너가 VM을 완전히 대체하는 것은 아니다. 서로 다른 운영체제를 실행하거나 더 강한 경계가 필요한 경우에는 VM이 적합할 수 있다.

## 2. 컨테이너가 독립적으로 보이는 이유

### namespace: 보이는 범위를 분리하기

namespace는 프로세스 ID, 네트워크 인터페이스, 호스트명, 마운트 지점처럼 프로세스가 **보는 세계**를 분리한다. 그래서 서로 다른 컨테이너의 첫 프로세스가 각각 PID 1처럼 보일 수 있다.

### cgroup: 사용할 양을 제한하기

cgroup은 CPU, 메모리, I/O, 프로세스 수 같은 자원의 사용량을 통제한다. 특정 작업이 과도하게 자원을 사용해 다른 작업까지 멈추는 일을 완화한다.

```bash
# 예시: 실행할 때 메모리 상한을 함께 둔다.
docker run --memory 256m sample-api
```

이 값은 서비스의 실제 부하를 측정한 뒤 정해야 한다. 너무 작은 제한은 정상 요청도 실패하게 만들 수 있다.

### 복습 질문 및 답변

**Q1. 컨테이너가 커널까지 포함하지 않는 이유는 무엇인가요?**

<details>
<summary>답</summary>

호스트 커널을 공유하면 운영체제 전체를 반복해서 올리지 않아 이미지와 실행 단위를 더 작고 빠르게 만들 수 있다.

</details>

**Q2. namespace만으로 자원 폭주를 막을 수 있나요?**

<details>
<summary>답</summary>

아니다. namespace는 격리 범위를 정하고, CPU·메모리 사용량 제한은 cgroup 같은 자원 제어가 담당한다.

</details>

**Q3. 컨테이너가 있으면 보안 검토가 필요 없나요?**

<details>
<summary>답</summary>

아니다. 컨테이너도 권한, 이미지 출처, 비밀값, 네트워크 경계를 함께 관리해야 한다.

</details>

## 한 줄 정리

> 컨테이너는 커널을 공유하면서 실행 환경과 자원 경계를 분리해 배포 재현성을 높이는 방식이다.
