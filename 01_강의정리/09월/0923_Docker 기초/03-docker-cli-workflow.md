# Docker 기본 명령으로 만드는 실행 흐름

> Docker 명령은 외우는 목록이 아니라 이미지를 준비하고, 실행 상태를 관찰하고, 정리하는 하나의 작업 흐름이다.

`build` · `run` · `ps` · `exec` · `rm`

## 핵심요약

- `build`는 Dockerfile을 바탕으로 이미지를 만들고, `run`은 새 컨테이너를 만들어 실행한다.
- `ps`로 상태를 확인하고 `exec`로 실행 중인 컨테이너 안에서 진단 명령을 수행한다.
- 종료·삭제 절차와 포트 매핑을 이해해야 로컬 테스트가 안정적이다.

## 1. 가장 작은 실행 루프

```bash
docker build -t sample-web:dev .
docker run -d --name sample-web -p 8080:80 sample-web:dev
docker ps
docker exec sample-web sh -c "echo running"
docker stop sample-web
docker rm sample-web
```

`run`은 기존 컨테이너를 다시 시작하는 명령이 아니라 **새 컨테이너를 생성하고 실행**한다. 이름을 반복 사용하려면 기존 컨테이너를 먼저 정리해야 한다.

## 2. 자주 쓰는 옵션의 의도

| 옵션 | 의도 | 주의점 |
| --- | --- | --- |
| `-d` | 백그라운드 실행 | 로그와 상태를 별도로 확인해야 함 |
| `-p host:container` | 호스트와 컨테이너 포트 연결 | 애플리케이션이 실제로 해당 포트에서 수신해야 함 |
| `--name` | 식별하기 쉬운 이름 부여 | 같은 이름은 동시에 쓸 수 없음 |
| `--rm` | 종료 뒤 자동 삭제 | 종료 뒤 상태를 다시 살펴볼 수 없음 |
| `-it` | 대화형 터미널 연결 | 서비스 실행용보다는 셸 진단에 적합 |

## 3. run과 exec의 구분

`docker run`은 이미지에서 컨테이너를 새로 만든다. 반면 `docker exec`는 이미 실행 중인 컨테이너 안에서 추가 명령을 실행한다. 장애를 확인할 때는 먼저 `ps`로 대상의 상태를 확인하는 습관이 좋다.

## 직접 해보기

1. 실행 중인 컨테이너 목록을 보는 명령을 적어 보세요.
2. 브라우저에서 컨테이너 웹 서버에 접근하려면 어떤 옵션이 필요한지 답해 보세요.
3. 기존 컨테이너를 새로 만들지 않고 내부에서 명령을 실행할 때 쓸 명령을 적어 보세요.

<details>
<summary>정답 보기</summary>

1. `docker ps`이다. 종료된 컨테이너까지 보려면 `docker ps -a`를 사용한다.
2. `-p`로 호스트 포트와 컨테이너 포트를 매핑한다.
3. `docker exec`를 사용한다.

</details>

## 헷갈리기 쉬운 포인트

| 비교 | 핵심 차이 |
| --- | --- |
| run vs exec | 새 컨테이너 생성·실행 vs 실행 중 컨테이너에서 추가 명령 실행 |
| stop vs rm | 실행 중지 vs 컨테이너 객체 삭제 |

### 복습 질문 및 답변

**Q1. `docker ps`에 서비스가 보이지 않을 때 무엇을 확인하나요?**

<details>
<summary>답</summary>

`docker ps -a`로 종료 상태를 확인하고, 컨테이너 로그와 실행 명령의 오류를 함께 점검한다.

</details>

**Q2. `EXPOSE`만 쓰면 외부에서 접속되나요?**

<details>
<summary>답</summary>

아니다. EXPOSE는 이미지의 포트 의도를 표현한다. 호스트 접근에는 실행 시 포트 매핑이 필요하다.

</details>

**Q3. 테스트용 작업에 `--rm`이 유용한 이유는 무엇인가요?**

<details>
<summary>답</summary>

명령이 끝난 뒤 컨테이너를 자동으로 지워 불필요한 종료 컨테이너가 쌓이는 것을 줄인다.

</details>
