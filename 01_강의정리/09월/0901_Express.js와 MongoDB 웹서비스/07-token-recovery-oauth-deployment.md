# JWT, 계정 복구, OAuth와 배포 경계

인증 방식을 확장할수록 토큰 저장 위치, 만료와 폐기, 외부 공급자 신뢰 경계, 프록시 구성을 함께 설계해야 합니다.

**핵심 키워드:** JWT, cookie, password reset, OAuth, Nginx

## JWT와 쿠키

JWT는 헤더·페이로드·서명으로 구성되며, 일반적인 서명 JWT의 페이로드는 암호화되지 않습니다. 비밀 정보를 넣지 말고 짧은 만료, 발급자·대상 검증과 키 교체 정책을 둡니다. 쿠키에 저장한다면 `httpOnly`, `secure`, `sameSite`와 CSRF 방어가 필요합니다.

```javascript
res.cookie("access_token", token, {
  httpOnly: true,
  secure: process.env.NODE_ENV === "production",
  sameSite: "lax",
  maxAge: 15 * 60 * 1000,
});
```

로그아웃은 브라우저 쿠키를 제거하지만 이미 발급된 JWT 자체가 자동 폐기되는 것은 아닙니다. 짧은 수명, 회전 가능한 갱신 토큰이나 폐기 목록을 위험 수준에 맞게 설계합니다.

## 비밀번호 재설정

무작위 일회용 토큰을 발급하고 데이터베이스에는 토큰 원문 대신 해시와 짧은 만료 시간을 저장합니다. 응답은 계정 존재 여부를 드러내지 않게 통일하고, 사용 후 토큰을 즉시 무효화합니다. 메일 링크의 호스트는 요청 헤더를 그대로 신뢰하지 말고 설정값에서 구성합니다.

## OAuth 로그인

OAuth 공급자로 리다이렉트하기 전 `state`로 요청 위조를 방지하고, 콜백에서 공급자 식별자와 검증된 이메일을 기준으로 계정을 연결합니다. 액세스 토큰은 필요한 범위만 요청하고 안전한 저장·폐기 정책을 둡니다.

## Nginx 앞단

리버스 프록시는 TLS 종료, 정적 파일, 요청 크기 제한과 전달 헤더를 담당할 수 있습니다. Express의 `trust proxy`는 실제 프록시 구조에 맞게 제한적으로 설정해야 클라이언트 IP와 보안 쿠키 판단이 정확해집니다.

## 체크리스트

- [ ] JWT 페이로드에 비밀을 넣지 않는다.
- [ ] 토큰 만료·교체·폐기 정책을 둔다.
- [ ] 재설정 토큰은 일회용 해시로 저장한다.
- [ ] OAuth `state`와 최소 권한을 적용한다.
- [ ] 프록시 신뢰 범위와 TLS를 점검한다.

</details>
