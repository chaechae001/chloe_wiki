# OpenStack과 프라이빗 클라우드 제어 구조

> 프라이빗 클라우드는 서버를 모아 둔 공간이 아니라, 컴퓨팅·네트워크·스토리지를 API와 정책으로 제어하는 운영 시스템입니다.

`OpenStack` · `private cloud` · `control plane` · `API` · `resource provisioning`

## 핵심요약

- OpenStack은 데이터 센터의 컴퓨팅·네트워크·스토리지 자원을 통합 제어합니다.
- Control Plane은 사용자 요청을 인증하고 여러 서비스에 작업을 분배합니다.
- 대시보드와 CLI는 다르지만 결국 같은 API를 호출합니다.
- 메시지 큐와 데이터베이스는 분산 서비스의 상태와 명령을 연결합니다.
- 서비스 분리는 확장성을 높이는 대신 장애 추적과 운영 복잡도를 늘립니다.

## 1. 프라이빗 클라우드의 목적

조직이 직접 보유하거나 통제하는 인프라를 클라우드처럼 제공하려면 사용자가 서버 위치를 일일이 몰라도 VM, 네트워크, 볼륨을 요청할 수 있어야 합니다. OpenStack은 이 요청을 여러 서비스가 협력해 처리하도록 구성한 오픈소스 클라우드 플랫폼입니다.

```text
User → Dashboard / CLI / SDK → API → Control Plane → Compute / Network / Storage
```

프라이빗 클라우드는 단순한 사내 서버실과 다릅니다. 자원을 표준 API로 요청·할당·회수하고 사용자별 권한과 할당량을 관리해야 클라우드 운영 모델에 가까워집니다.

## 2. Control Plane

Control Plane은 원하는 상태를 결정하고 조정하는 영역입니다. VM 생성 요청이 들어오면 인증, 이미지 조회, 호스트 선택, 네트워크 연결, 스토리지 연결을 순서에 맞게 조율합니다.

| 구성 요소 | 역할 | 핵심 질문 |
|---|---|---|
| API | 요청 접수와 검증 | 어떤 작업을 원하는가? |
| Identity | 인증·권한 확인 | 누가 요청했는가? |
| Scheduler | 실행 위치 선택 | 어느 호스트가 적합한가? |
| Message Queue | 비동기 명령 전달 | 어떤 작업을 누가 처리할까? |
| Database | 상태와 메타데이터 저장 | 현재 자원 상태는 무엇인가? |

## 3. 요청이 처리되는 흐름

1. 사용자가 자격 증명으로 토큰을 얻습니다.
2. VM 사양과 이미지, 네트워크를 포함해 API를 호출합니다.
3. 권한과 할당량을 검증합니다.
4. 스케줄러가 적합한 컴퓨트 호스트를 고릅니다.
5. 네트워크·스토리지 서비스가 필요한 자원을 준비합니다.
6. 컴퓨트 서비스가 하이퍼바이저에 VM 생성을 요청합니다.
7. 상태를 갱신하고 사용자에게 결과를 반환합니다.

## 4. API 중심 설계

대시보드는 편리한 화면일 뿐, 자동화의 핵심은 API입니다. 동일한 요청을 코드로 재현할 수 있으면 개발·테스트·운영 환경 차이를 줄이고 대량 작업을 안전하게 반복할 수 있습니다.

```text
Dashboard ─┐
CLI ───────┼→ REST API → Cloud services
SDK ───────┘
```

## 5. 운영 관점

- Control Plane 장애와 실제 VM 실행 장애를 구분합니다.
- API, 메시지 큐, 데이터베이스의 지연을 함께 관찰합니다.
- 서비스 계정과 사용자 계정을 분리합니다.
- 사용자별 할당량으로 자원 독점을 방지합니다.
- 모든 변경을 감사 로그로 남깁니다.

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| Control Plane vs Data Plane | 상태를 결정·조정하는 영역과 실제 트래픽·작업이 흐르는 영역입니다. |
| Dashboard vs API | 사용자 화면과 자동화 가능한 서비스 계약입니다. |
| 서버 관리 vs 클라우드 관리 | 개별 장비 관리와 자원 풀·정책·사용자 단위 관리입니다. |
