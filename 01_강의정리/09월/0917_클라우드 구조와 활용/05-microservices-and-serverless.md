# 마이크로서비스와 Serverless

> 애플리케이션을 작게 나누는 것과 서버 운영을 플랫폼에 맡기는 것은 서로 다른 선택이며, 둘 다 경계와 운영 책임을 명확히 해야 효과가 있습니다.

`microservices` · `BaaS` · `FaaS` · `event driven` · `serverless`

## 핵심요약

- 마이크로서비스는 업무 능력을 기준으로 독립 배포 가능한 서비스로 나눕니다.
- 서비스 분리는 독립 확장성을 주지만 네트워크·데이터·관찰 복잡도를 높입니다.
- Serverless는 서버가 없는 것이 아니라 인프라 운영 책임을 제공자에게 더 많이 맡기는 모델입니다.
- BaaS는 완성된 백엔드 기능을, FaaS는 이벤트에 반응하는 함수를 제공합니다.
- 짧고 변동이 큰 이벤트 작업에 유리하지만 지속 부하와 긴 작업에는 비용과 제약을 따져야 합니다.

## 1. 모놀리식과 마이크로서비스

모놀리식 구조는 하나의 배포 단위 안에서 기능을 연결하므로 초기 개발과 로컬 테스트가 단순합니다. 마이크로서비스는 주문, 결제, 알림처럼 업무 경계를 나누어 각 서비스를 독립 배포하고 확장할 수 있게 합니다.

<details>
<summary>답</summary>

마이크로서비스는 서비스를 많이 만드는 것이 목적이 아닙니다. 변경 이유와 데이터 책임이 다른 기능을 독립적으로 운영할 필요가 있을 때 경계를 나누는 설계입니다.

</details>

## 2. 분리의 이점과 비용

| 관점 | 이점 | 추가 비용 |
|---|---|---|
| 배포 | 서비스별 독립 배포 | 버전 호환 관리 |
| 확장 | 병목 서비스만 확장 | 용량 계획 복잡도 |
| 장애 | 영향 범위 격리 가능 | 연쇄 실패 대응 |
| 데이터 | 책임과 소유권 명확화 | 분산 트랜잭션·일관성 |
| 운영 | 팀 자율성 | 로그·추적·모니터링 통합 |

## 3. Serverless의 두 축

- **BaaS**: 인증, 데이터베이스, 메시징처럼 이미 구현된 백엔드 기능을 API로 사용합니다.
- **FaaS**: 특정 이벤트가 발생할 때 짧은 코드를 실행하고 사용량에 따라 과금합니다.

```text
Event → Function → Managed service → Result
       scale out / scale in automatically
```

## 4. 이벤트 기반 실행 흐름

파일 업로드를 예로 들면 저장소 이벤트가 함수를 깨우고, 함수가 메타데이터를 추출해 데이터베이스에 기록한 뒤 후속 메시지를 발행할 수 있습니다. 각 단계는 재시도되어도 안전하도록 멱등성을 고려해야 합니다.

## 5. 선택 기준

- 요청이 드물거나 변화 폭이 큰가?
- 실행 시간이 짧고 상태를 외부 저장소로 분리할 수 있는가?
- 초기 실행 지연이 사용자 경험에 허용되는가?
- 플랫폼 종속성과 실행 제한을 감수할 수 있는가?
- 호출 수, 실행 시간, 데이터 전송을 합친 비용이 합리적인가?

## 직접 해보기

1. 이미지 업로드 후 썸네일을 만드는 기능에 적합한 실행 모델을 고르세요.
2. 하루 종일 일정한 고부하를 처리하는 작업에 FaaS를 적용하기 전 확인할 항목을 적으세요.
3. 주문과 결제를 별도 서비스로 나눌 때 데이터 일관성을 어떻게 다룰지 설명하세요.

<details>
<summary>정답 보기</summary>

1. 저장 이벤트로 시작하는 FaaS가 자연스럽고 결과 저장은 관리형 저장소를 이용할 수 있습니다.
2. 지속 실행 비용, 최대 실행 시간, 초기 실행 지연, 동시 실행 제한을 상시 실행 방식과 비교합니다.
3. 서비스별 데이터 소유권을 정하고 이벤트와 보상 처리로 단계별 상태를 추적하며 중복 요청에도 안전하게 설계합니다.

</details>

## 복습 질문 및 답변

### Q1. 마이크로서비스가 항상 모놀리식보다 좋은가요?

<details>
<summary>답</summary>

아닙니다. 독립 배포와 확장이 필요한 규모에서 가치가 커집니다. 작은 시스템에서는 네트워크 통신, 배포 자동화, 관찰 체계의 비용이 이점보다 클 수 있습니다.

</details>

### Q2. Serverless라는 이름이 서버가 없다는 뜻인가요?

<details>
<summary>답</summary>

실제 서버는 존재하지만 프로비저닝, 패치, 자동 확장 같은 운영 책임의 상당 부분을 클라우드 제공자가 맡는다는 뜻입니다.

</details>

### Q3. 이벤트 기반 함수에서 멱등성이 중요한 이유는 무엇인가요?

<details>
<summary>답</summary>

전송 실패나 시간 초과로 같은 이벤트가 다시 처리될 수 있기 때문입니다. 같은 요청을 여러 번 받아도 결과가 중복 생성되지 않도록 해야 안전합니다.

</details>
