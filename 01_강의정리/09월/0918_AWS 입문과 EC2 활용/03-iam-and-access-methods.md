# IAM과 AWS 접근 방식

> 클라우드 보안은 누가 로그인했는지보다, 어떤 주체가 어떤 자원에 어떤 행동을 할 수 있는지를 명확히 정의하는 데서 시작합니다.

`IAM` · `least privilege` · `policy` · `role` · `MFA`

## 핵심요약

- IAM은 신원 인증과 권한 부여를 분리해 관리합니다.
- 루트 사용은 최소화하고 일상 작업은 개별 신원으로 수행합니다.
- 정책은 Effect, Action, Resource, Condition으로 권한을 표현합니다.
- Role은 사용자나 서비스가 임시 자격 증명으로 권한을 맡는 방식입니다.
- Console, CLI, SDK는 접근 화면이 다르지만 모두 권한 검사를 거칩니다.

## 1. 인증과 권한 부여

인증은 “누구인가”를 확인하고, 권한 부여는 “무엇을 할 수 있는가”를 결정합니다. 로그인에 성공했더라도 요청한 작업의 정책이 허용되지 않으면 실행할 수 없습니다.

<details>
<summary>답</summary>

IAM은 계정 안의 신원과 권한을 중앙에서 관리합니다. 강한 인증만으로 충분하지 않고 각 주체에 필요한 최소 행동만 허용해야 합니다.

</details>

## 2. User, Group, Role

| 주체 | 목적 | 권장 사용 |
|---|---|---|
| Root | 계정 소유 수준 작업 | 꼭 필요한 계정 작업에만 제한 |
| User | 사람 또는 레거시 장기 신원 | 개별 추적이 필요한 경우 |
| Group | 여러 사용자의 권한 묶음 | 직무별 공통 권한 관리 |
| Role | 임시로 맡는 권한 집합 | 서비스 간 호출과 연합 로그인 |

서비스가 다른 AWS 자원에 접근할 때 장기 키를 파일에 넣기보다 Role을 연결해 짧은 수명의 자격 증명을 사용하는 것이 안전합니다.

## 3. 정책 구조

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:GetObject"],
    "Resource": ["arn:aws:s3:::example-learning-bucket/public/*"]
  }]
}
```

- `Effect`: 허용 또는 명시적 거부입니다.
- `Action`: 수행할 API 작업입니다.
- `Resource`: 작업 대상입니다.
- `Condition`: 시간, 네트워크, 태그 같은 추가 조건입니다.

## 4. 최소 권한과 MFA

최소 권한은 처음부터 넓은 권한을 주는 대신 업무에 필요한 작업과 자원만 허용하는 원칙입니다. 관리자급 신원과 중요한 작업에는 MFA를 적용하고, 사용하지 않는 신원과 권한을 주기적으로 정리합니다.

## 5. Console, CLI, SDK

Console은 탐색과 일회성 작업에 편리하고, CLI는 반복 명령과 스크립트에 적합하며, SDK는 애플리케이션 코드에서 API를 호출할 때 사용합니다. 접근 키나 비밀 값은 코드·문서·저장소에 기록하지 않고 안전한 자격 증명 공급 방식을 사용합니다.

2. 읽기 전용 사용자가 삭제를 수행하지 못하게 정책 범위를 설명하세요.
3. 반복 운영 작업을 자동화할 때 Console, CLI, SDK 중 선택 기준을 적으세요.

<details>
<summary>정답 보기</summary>

1. 서버에 필요한 읽기 권한만 가진 Role을 연결합니다.
2. 읽기 Action과 필요한 Resource만 허용하고 삭제 Action을 부여하지 않습니다.
3. 간단한 운영 스크립트는 CLI, 애플리케이션 로직과 통합할 작업은 SDK가 적합하며 Console은 확인과 탐색에 유용합니다.

</details>

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| 인증 vs 권한 부여 | 신원 확인과 허용 행동 판단입니다. |
| User vs Role | 장기 신원과 필요할 때 맡는 임시 권한입니다. |
| CLI vs SDK | 셸 명령 자동화와 프로그램 코드 통합입니다. |

### 복습 질문 및 답변

**Q1. Role은 서비스에만 사용할 수 있나요?**

<details>
<summary>답</summary>

아닙니다. AWS 서비스뿐 아니라 사용자, 외부 계정과 연합 신원도 신뢰 정책에 따라 Role을 맡을 수 있습니다.

</details>

**Q2. MFA가 있으면 넓은 관리자 권한을 계속 써도 되나요?**

<details>
<summary>답</summary>

아닙니다. MFA는 인증을 강화하지만 과도한 권한의 피해 범위를 줄이지는 못하므로 최소 권한을 함께 적용해야 합니다.

</details>

**Q3. 접근 키를 환경 변수에 넣으면 영구적으로 안전한가요?**

<details>
<summary>답</summary>

환경 변수도 노출될 수 있습니다. 가능하면 Role과 임시 자격 증명을 사용하고, 장기 키가 필요하면 안전한 저장·회전·감사 절차를 적용합니다.

</details>

## 한 줄 정리

> IAM은 신원별 최소 권한과 임시 자격 증명을 통해 AWS 요청의 허용 범위를 통제합니다.
