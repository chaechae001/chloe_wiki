# AWS 클라우드 기초와 웹 아키텍처

> 클라우드는 서버를 빌리는 서비스가 아니라, 컴퓨팅·네트워크·저장소를 필요할 때 조합하고 자동화하는 운영 방식입니다.

`AWS` · `cloud computing` · `IaaS` · `PaaS` · `SaaS`

## 핵심요약

- 클라우드는 자원을 API로 요청하고 사용량에 따라 확장·회수할 수 있게 합니다.
- 퍼블릭·프라이빗 클라우드는 소유와 운영 책임의 경계가 다릅니다.
- IaaS·PaaS·SaaS는 사용자가 직접 관리하는 범위가 다릅니다.
- 웹 서비스는 DNS, 네트워크, 컴퓨팅, 데이터베이스, 관찰 계층이 협력합니다.
- 서비스 선택은 편의성뿐 아니라 통제권, 비용, 보안 책임을 함께 비교해야 합니다.

## 1. 데이터 센터에서 클라우드로

직접 데이터 센터를 운영하면 서버 구매, 공간, 전력, 네트워크, 장애 대응과 용량 예측을 모두 책임져야 합니다. 클라우드는 이를 표준화된 서비스로 제공해 필요한 자원을 빠르게 만들고 반복 가능한 방식으로 관리하도록 돕습니다.

<details>
<summary>답</summary>

가상화는 한 물리 장비를 여러 논리 자원으로 나누는 기술이고, 클라우드는 그 자원을 네트워크와 API를 통해 요청·할당·측정·회수하는 운영 모델까지 포함합니다.

</details>

## 2. 배포 모델과 서비스 모델

| 구분 | 사용자가 주로 관리 | 제공자가 주로 관리 | 선택 포인트 |
|---|---|---|---|
| IaaS | 운영체제, 런타임, 애플리케이션 | 물리 장비와 가상화 | 높은 통제권 |
| PaaS | 애플리케이션과 데이터 | 실행 환경과 인프라 | 개발 속도 |
| SaaS | 사용자 설정과 데이터 사용 | 애플리케이션 전체 | 빠른 도입 |

퍼블릭 클라우드는 제공자의 공용 인프라를 논리적으로 분리해 사용하고, 프라이빗 클라우드는 조직이 전용 환경을 통제합니다. 실제 선택에서는 규제, 기존 시스템, 운영 역량과 비용을 함께 고려합니다.

## 3. 웹 애플리케이션의 기본 흐름

```text
Client → DNS → Load Balancer → Web/API → Database
                         └────→ Object storage
```

사용자 요청은 이름 해석과 네트워크 경로를 거쳐 컴퓨팅 자원에 도착합니다. 애플리케이션은 데이터베이스와 저장소를 사용하고, 로그·지표·알림은 전체 흐름을 관찰합니다.

## 4. 온디맨드와 탄력성

온디맨드는 필요한 시점에 자원을 요청하는 방식이고, 탄력성은 수요 변화에 맞춰 자원을 늘리고 줄이는 능력입니다. 둘은 초기 투자 부담을 줄이지만 사용하지 않는 자원을 방치하면 비용이 계속 발생할 수 있습니다.

## 5. 공동 책임

제공자가 데이터 센터와 기반 인프라를 보호하더라도 사용자는 계정 권한, 네트워크 규칙, 데이터 암호화, 운영체제 패치와 애플리케이션 취약점을 서비스 유형에 맞게 책임져야 합니다.

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| 가상화 vs 클라우드 | 자원 분할 기술과 그 자원을 서비스로 운영하는 모델입니다. |
| 확장성 vs 탄력성 | 커질 수 있는 능력과 수요에 맞춰 늘고 줄어드는 능력입니다. |
| IaaS vs PaaS | 운영체제까지 관리하는 방식과 실행 환경을 제공자에게 맡기는 방식입니다. |

### 복습 질문 및 답변

**Q1. 클라우드를 사용하면 운영 책임이 모두 사라지나요?**

<details>
<summary>답</summary>

아닙니다. 제공자는 기반 시설을 관리하지만 사용자는 계정, 설정, 데이터와 애플리케이션의 안전을 서비스 유형에 맞게 책임집니다.

</details>

**Q2. SaaS가 항상 가장 경제적인가요?**

<details>
<summary>답</summary>

도입은 빠르지만 사용자 수, 기능 제한, 데이터 이동과 장기 구독 비용을 함께 평가해야 합니다.

</details>

**Q3. 비용 최적화에서 가장 기본적인 습관은 무엇인가요?**

<details>
<summary>답</summary>

자원에 소유·환경 태그를 붙이고 사용량을 관찰하며 불필요한 자원을 종료하는 것입니다.

</details>
