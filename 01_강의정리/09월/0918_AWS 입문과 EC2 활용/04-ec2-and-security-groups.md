# EC2와 보안 그룹

> EC2를 안전하게 운영하려면 적절한 인스턴스를 고르는 것만큼, 누가 어떤 경로로 접근할 수 있는지를 제한하는 일이 중요합니다.

`EC2` · `AMI` · `instance type` · `Security Group` · `inbound`

## 핵심요약

- EC2는 운영체제와 실행 환경을 직접 제어하는 가상 머신 서비스입니다.
- AMI는 인스턴스를 반복 생성하기 위한 이미지 템플릿입니다.
- 인스턴스 유형은 CPU·메모리·스토리지·가속 자원의 조합입니다.
- 보안 그룹은 인스턴스 수준의 상태 저장형 가상 방화벽입니다.
- 관리 포트는 전체에 열지 않고 필요한 출발지와 경로만 허용합니다.

## 1. EC2와 인스턴스 유형

EC2는 IaaS 형태의 컴퓨팅 서비스입니다. 범용, 컴퓨팅 최적화, 메모리 최적화, 가속 컴퓨팅, 스토리지 최적화 등 워크로드 특성에 맞는 유형을 선택합니다.

<details>
<summary>답</summary>

인스턴스 크기를 크게 만드는 것이 항상 최선은 아닙니다. 병목이 CPU인지 메모리인지 저장소인지 측정하고 적절한 계열과 크기를 선택해야 비용 대비 성능이 좋아집니다.

</details>

## 2. AMI와 시작 구성

AMI는 운영체제, 소프트웨어와 설정을 담은 인스턴스 시작 템플릿입니다. 검증된 이미지를 버전으로 관리하면 같은 구성을 반복 배포하고 장애 시 빠르게 교체할 수 있습니다.

```text
Base image → Configure and validate → New image version → Multiple instances
```

이미지 안에는 비밀 값이나 환경별 설정을 넣지 않고 실행 시 안전한 구성 공급 방식을 사용합니다.

## 3. 보안 그룹

보안 그룹은 허용 규칙으로 수신과 발신 트래픽을 제어합니다. 연결 상태를 추적하므로 허용된 요청에 대한 응답 경로는 별도 반대 방향 규칙 없이 처리됩니다.

| 규칙 요소 | 질문 | 예시 원칙 |
|---|---|---|
| Protocol | 어떤 통신인가? | TCP 등 필요한 프로토콜만 |
| Port | 어느 서비스인가? | 웹·관리·데이터 계층 분리 |
| Source | 누가 접근하는가? | 사용자 대신 앞단 보안 그룹 참조 |
| Destination | 어디로 나가는가? | 필요한 서비스 경로만 |

## 4. 계층별 접근 설계

```text
Internet → Load Balancer SG → Application SG → Database SG
```

애플리케이션 인스턴스는 로드 밸런서에서 오는 트래픽만, 데이터베이스는 애플리케이션 계층에서 오는 트래픽만 허용합니다. 관리 접속은 제한된 운영 경로나 관리형 세션 기능을 사용합니다.

## 5. 운영 점검

- 사용하지 않는 규칙과 보안 그룹을 제거합니다.
- 넓은 출발지와 불필요한 포트를 정기적으로 검사합니다.
- 이미지와 운영체제 패치를 자동화합니다.
- 메트릭과 로그로 인스턴스 상태를 관찰합니다.
- 장애 복구는 수동 수정보다 교체 가능한 이미지 기반으로 설계합니다.

## 헷갈리기 쉬운 포인트

| A vs B | 차이 |
|---|---|
| AMI vs 인스턴스 | 시작 템플릿과 실제 실행 중인 가상 머신입니다. |
| 인바운드 vs 아웃바운드 | 들어오는 트래픽과 나가는 트래픽입니다. |
| 보안 그룹 vs IAM | 네트워크 연결 허용과 API 행동 권한입니다. |

### 복습 질문 및 답변

**Q1. 보안 그룹은 차단 규칙을 직접 작성하는 방화벽인가요?**

<details>
<summary>답</summary>

보안 그룹은 기본적으로 허용할 트래픽을 명시합니다. 명시되지 않은 트래픽은 허용되지 않습니다.

</details>

**Q2. 웹 서버와 데이터베이스에 같은 보안 그룹을 써도 되나요?**

<details>
<summary>답</summary>

가능하더라도 책임과 접근 범위를 분리하기 어렵습니다. 계층별로 보안 그룹을 나누고 그룹 간 참조로 필요한 흐름만 허용하는 편이 안전합니다.

</details>

**Q3. AMI만 있으면 데이터도 모두 복구되나요?**

<details>
<summary>답</summary>

AMI는 실행 환경 템플릿에 가깝습니다. 영구 데이터는 별도의 볼륨 스냅샷, 데이터베이스 백업과 복구 계획이 필요합니다.

</details>
